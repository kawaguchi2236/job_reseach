# CHAPTER 9｜情報の流れ（何の情報が、誰から誰へ渡るのか）

> 本ファイルは `03_company-structure.md` のモデル企業（株式会社サンエイ内装／内装仕上工事・従業員28名）を主語に、
> **建設業で扱われる情報を1つずつ名前を付けて**追いかけます。
> 「情報」という抽象語では終わらせず、**引合い情報／積算情報／出来高情報**のように具体的に命名します。
> ステップ名（S1〜S21）は `04_end-to-end-process.md` の定義を使います。
> 出典の詳細は `19_sources.md` を参照してください。

---

## 9-1 建設業の情報の流れが、他業界と決定的に違う3点

### 違い(1)：情報を作る場所と、使う場所が物理的に離れている

```
 ［製造業の工場］
   生産現場と管理部門が同じ敷地にある
   → 現場の状況が、その日のうちに管理側に伝わる

 ［建設業］
   本社・事務所 ←────── 数km〜数十km ──────▶ 工事現場（複数箇所）
   ★ 情報を持っている人（現場代理人・職長）は、現場にいる
   ★ 情報を使う人（経理・積算・経営者）は、本社にいる
```

> **【Typical】これが何を生むか**
> 現場代理人は日中ずっと現場にいます。
> そのため、本社への報告は現場から戻った後、または移動の合間になります。
> `01_overview.md` 1-7 特徴2で「日中は現場、夕方から書類」という働き方になりやすいと述べたのは、
> **情報の発生場所と処理場所が離れている**ことの帰結です【Inference】。

### 違い(2)：情報が「契約の線」に沿ってしか流れない

`06_people.md` 6-10 で見たとおり、建設業では**契約関係のない相手に直接情報を渡せません**。

```
  発注者 ◀────▶ 元請 ◀────▶ 1次下請 ◀────▶ 2次下請

  ★ 2次下請は、発注者に直接質問できない
  ★ 1次下請は、設計事務所に直接質問せず、元請を経由するのが基本【Typical】
  ★ 情報は必ず、契約の線に沿って上へ／下へ流れる
```

> **なぜそうなのか**：契約関係のない相手からの指示は、契約上の根拠を持ちません。
> 「設計事務所が直接そう言った」と言っても、元請との契約内容が変わったわけではないため、
> **費用も工期も動かせません**【Inference】。
> だから情報は必ず契約の線を通します。時間はかかりますが、これが建設業の骨格です。

### 違い(3)：情報が「証拠」としての役割を持つ

建設業では、多くの情報が**後から検証されることを前提に**作られます。

| 情報 | 何の証拠になるか |
|---|---|
| **工事写真** | 完成後に見えなくなる部分が、正しく施工されたことの証拠 |
| **作業日報** | 誰が何日働いたかの証拠（＝原価と出来高の根拠） |
| **打合せ記録** | 誰がいつ何を指示したかの証拠（＝追加工事の請求根拠） |
| **検査記録・是正記録** | 指摘が是正されたことの証拠 |
| **安全書類** | 誰がどの資格で現場にいたかの証拠（＝事故時の対応） |
| **マニフェスト** | 廃棄物が適正に処理されたことの証拠【Fact】 |

> **【Fact】法令上、保存が義務づけられている情報もあります。**
> 建設業法第40条の3により、建設業者は営業所ごとに営業に関する事項を記載した**帳簿**を備え、
> 保存しなければなりません（→ 9-11、`10_documents.md`、`15_rules-customs.md`）。

## 9-2 情報の全体像（1つの工事で流れる14の情報）

```
【受注前】
  ① 入札公告情報／引合い情報
        ↓
  ② 現地条件情報（現調情報）
        ↓
  ③ 図面・仕様情報（設計図書）
        ↓
  ④ 積算情報（数量拾い・歩掛・単価）
        ↓
  ⑤ 見積情報
        ↓
  ⑥ 契約情報

【着工準備〜施工中】
  ⑦ 実行予算情報
        ↓
  ⑧ 施工計画情報（施工計画・施工図）
        ↓
  ⑨ 工程情報
        ↓
  ⑩ 安全情報（安全書類・KY・指摘）
        ↓
  ⑪ 施工実績情報（作業日報・工事写真）
        ↓
  ⑫ 出来高情報

【完成〜入金】
  ⑬ 請求情報
        ↓
  ⑭ 入金情報

  ＋ 横断して流れるもの
     ・変更情報（設計変更・追加工事）
     ・品質情報（検査記録・是正記録）
     ・原価実績情報（次の積算情報にフィードバックされる）
```

> **【重要】最後の「原価実績情報 → 積算情報」が輪を閉じます。**
> 建設業は1件ごとに違うものを造るため、**実績を積み上げなければ次の見積の精度が上がりません**。
> 情報の流れは直線ではなく、**循環**しています（→ 9-12）。

## 9-3 各情報の詳細（誰が作り／誰が使い／どこに保管され／次に何に変わるか）

> **媒体（紙・Excel・システム・クラウド等）は企業により大きく異なります【Varies】。**
> 本資料では媒体を決めつけず、「どこに保管されるか」は保管の**場所と責任者**として記述します。

---

### ① 入札公告情報／引合い情報

| 項目 | 内容 |
|---|---|
| **何の情報か** | 「この工事の見積を出してほしい」という依頼、または「この公共工事を発注する」という公告 |
| **誰が作るか** | **元請の工事部・購買部**（下請の場合）／**発注機関**（公共工事の場合）／**発注者・ビル管理会社**（直請けの場合） |
| **中身** | 工事名、工事場所、工期、見積範囲、見積提出期限、添付図面の一覧、現場説明会の有無 |
| **誰が受け取るか** | ①営業機能、代表取締役、③工事管理機能（現場代理人が直接受けることも多い）【Typical】 |
| **誰が使うか** | 代表取締役（S2 受け・不受けの判断）、②積算・見積機能 |
| **どこに保管されるか** | **引合い台帳**（案件番号・発注者・元請名・工事名・見積期限・担当を記録）。管理責任は①営業機能【Varies】 |
| **次に何に変わるか** | 受注すれば **⑥契約情報** へ。辞退すれば失注記録へ |
| **頻度** | **案件発生時** |

> **なぜ台帳に記録するのか**
> 建設業では引合いが同時並行で複数走ります。
> 「どの案件がどの段階か」を見失うと、**見積提出期限を逃して失注します**【Typical】。

> **【Fact】見積期間には法定の下限があります。**
> 注文者は、受注予定者が見積りを行うために必要な期間を設けなければならず、
> 工事1件の予定価格が **500万円未満は1日以上／500万円以上5,000万円未満は10日以上／
> 5,000万円以上は15日以上**と定められています（建設業法第20条、同施行令第6条／出典：国土交通省）。

> **公共工事の場合**：入札情報は発注機関のホームページ等で公告されます。
> 参加するには事前に**入札参加資格**の登録が必要です【Fact】（→ `02_industry-structure.md` 11-6）。

---

### ② 現地条件情報（現調情報）

| 項目 | 内容 |
|---|---|
| **何の情報か** | 現場に実際に行って確認した、**図面には書かれていない条件** |
| **誰が作るか** | ③工事管理機能（現場代理人）、②積算・見積機能 |
| **中身** | 既存の状態（下地、天井内、床レベル、壁の垂直）、搬入経路、置き場、作業可能時間、電源・水、近隣・入居者、廃材搬出経路、駐車 |
| **誰が使うか** | ②積算・見積機能（S4 積算）、③工事管理機能（S9 施工計画） |
| **どこに保管されるか** | **現地調査報告書＋現場写真＋実測寸法メモ**。案件フォルダに案件番号で保管【Varies】 |
| **次に何に変わるか** | **④積算情報** の前提になる。受注後は **⑧施工計画情報** の前提にもなる |
| **頻度** | **案件発生時** |

> **【最重要】この情報が原価の大半を左右する**
> `04_end-to-end-process.md` S3 で述べたとおり、
> 同じ100㎡のクロス張りでも、エレベーターが使えない8階と、台車で入れる1階では必要な人工が違います。
> **現地条件情報は「図面に書かれていない原価要因」を言語化した情報**です【Inference】。

> **なぜ写真を撮るのか**：後の価格折衝（S6）や追加工事の協議（S15）で、
> **「図面と現況が違う」ことの根拠**になるためです。
> `04_end-to-end-process.md` 4-5 の【Example】で、現調写真を根拠に価格交渉を行ったのはこの理由です。

### ③ 図面・仕様情報（設計図書）

| 項目 | 内容 |
|---|---|
| **何の情報か** | 何を、どこに、どんな材料で、どう作るかを表した情報 |
| **誰が作るか** | **設計事務所**（意匠・構造・設備）、ゼネコンの設計部門 |
| **中身** | 意匠図（平面図・天井伏図・展開図・断面図）、構造図、設備図、**仕上表**、**仕様書**、特記仕様書 |
| **誰が受け取るか** | 元請 → 自社（③工事管理機能、②積算・見積機能） |
| **誰が使うか** | ②積算（数量拾い）、③工事管理（施工図作成・施工指示）、④現場作業（施工） |
| **どこに保管されるか** | 案件フォルダ。**版（バージョン）の管理が必須**【Typical】 |
| **次に何に変わるか** | **④積算情報**、**⑧施工計画情報（施工図）** へ |
| **頻度** | **案件発生時**。ただし**設計変更のたびに改訂版が出る**【Typical】 |

> **【最重要】図面には「版」がある**
> 建設の図面は、設計の進行・変更に伴って何度も改訂されます。
> **古い版で施工すると、すべてやり直し（手戻り）になります**【Typical】。
>
> ```
>  ［典型的な失敗の構造】
>    第1版で施工図を作成 → 第2版が出たことに気づかない
>    → 第1版どおりに施工 → 検査で「図面と違う」と指摘 → やり直し
> ```
> だから現場では「**最新版はどれか**」の確認が日常的な業務になります。

> **仕上表（しあげひょう）**
> → 部屋ごとに、床・壁・天井・巾木に何を使うかを一覧にした表。
> → 実務例：「会議室A：床＝タイルカーペット○○、壁＝ビニルクロス△△、天井＝岩綿吸音板」
> → **なぜ重要か**：内装工事の積算は、この表がないと始まりません。

> **質疑応答書（しつぎおうとうしょ）**
> → 図面や仕様で分からない点を、書面で質問し、回答をもらう記録のこと。
> → 実務例：「この壁の下地ピッチの指定がありませんが、@455でよいですか」→ 回答が返る。
> → **なぜ書面にするのか**：口頭の回答は後から「そうは言っていない」となり得ます。
>   **書面の回答が、施工の根拠になります**【Typical】。
> → **経路**：自社 → 元請 → 設計事務所 → （必要に応じて発注者）→ 逆順で回答が戻る（→ 9-6）。

### ④ 積算情報（数量拾い・歩掛・単価）

| 項目 | 内容 |
|---|---|
| **何の情報か** | 図面から拾った数量と、それに掛ける単価・歩掛 |
| **誰が作るか** | ②積算・見積機能 |
| **中身** | **数量拾い表**（材料数量・労務数量）、**歩掛**（1単位あたり何人工か）、材料単価、労務単価、運搬・仮設・廃棄の数量、現場経費 |
| **誰が使うか** | ②積算・見積機能（S5 見積）、③工事管理機能（S8 実行予算、S11 発注数量） |
| **どこに保管されるか** | 案件フォルダ。**歩掛は会社の共有資産として蓄積される**【Typical】 |
| **次に何に変わるか** | **⑤見積情報** → **⑦実行予算情報** → **発注数量**（S11） |
| **頻度** | **案件発生時** |

> **歩掛（ぶがかり）は会社の中核情報**
> → 一定の作業量をこなすのに必要な手間（人工）や材料の標準量のこと。
> → 実務例：「クロス張りは1人1日あたり60㎡」という歩掛があれば、300㎡なら5人工と即座に計算できる。
> → **歩掛の精度が、その会社の見積精度そのもの**です【Typical】。
> → **どこから来るか**：**過去の工事の実績**（⑪施工実績情報 → 原価実績情報）から更新されます。
>   これが 9-12 の循環の中心です。

> **【重要】拾い出しの情報は、後で何度も使われる**
> ```
>   数量拾い表 ──▶ ⑤見積情報（元請に出す金額の根拠）
>              ──▶ ⑦実行予算情報（現場が使ってよい金額）
>              ──▶ 材料の発注数量（S11）
>              ──▶ 労務手配の人工数（S12）
>              ──▶ ⑫出来高情報の分母（全体数量）
> ```
> **1つの積算情報が、工事の最後まで使われ続けます**【Inference】。

### ⑤ 見積情報

| 項目 | 内容 |
|---|---|
| **何の情報か** | 自社がこの工事をいくらで請けるかという提示 |
| **誰が作るか** | ②積算・見積機能。**承認は代表取締役**（→ `06_people.md` 6-7） |
| **中身** | **見積書**（総額）、**見積内訳書**（工種・数量・単価・金額）、**見積条件書**（含む範囲／含まない範囲）、見積有効期限、工期 |
| **誰が受け取るか** | 元請の購買部・工事部／発注者 |
| **誰が使うか** | 元請（他社見積との比較、査定）、自社（S6 価格折衝、S8 実行予算の出発点） |
| **どこに保管されるか** | 案件フォルダ。**提出した版を必ず控えとして残す**【Typical】 |
| **次に何に変わるか** | **⑥契約情報** へ（金額が確定する） |
| **頻度** | **案件発生時**（1案件で複数回改訂されることが一般的）【Typical】 |

> **【最重要】見積条件書は「契約の範囲を定める情報」**
> 「この見積に既存壁の解体は含まれているのか」「残材処分は誰の負担か」
> 「夜間作業の割増は含まれているのか」——
> これらを書いていないと、着工後に「入っているはずだ」「入っていない」の争いになります【Typical】。

> **【Fact】2025年（令和7年）12月12日に完全施行された改正建設業法**により、
> **建設工事の見積書に記載すべき事項、および入札金額の内訳書に記載すべき事項が明確化**されました。
> また、**著しく低い労務費等による見積り・契約が禁止**されています
> （出典：国土交通省報道発表資料）。

### ⑥ 契約情報

| 項目 | 内容 |
|---|---|
| **何の情報か** | 金額・工期・条件が確定したという情報 |
| **誰が作るか** | 元請（注文書）／自社（注文請書）。直請けの場合は請負契約書 |
| **中身** | 工事名、工事場所、請負金額、工期（着手・完成）、支払条件（締日・支払日・手形の有無）、契約の範囲、変更時の取扱い、契約不適合責任の範囲 |
| **誰が使うか** | ②積算（S8 実行予算）、③工事管理（工期の前提）、⑦経理・財務（請求・入金の管理）、⑧人事総務（契約書の保管） |
| **どこに保管されるか** | **契約書ファイル**。管理責任は⑧人事・総務機能または⑦経理・財務機能【Varies】 |
| **次に何に変わるか** | **⑦実行予算情報**、**⑬請求情報**（請求の根拠）へ |
| **頻度** | **受注時** |

> **【Fact】建設業法第19条の書面交付義務**
> 請負契約の当事者は、工事内容、請負代金の額、着工・完成の時期、前金払・出来高部分払の定め、
> 設計変更時の取扱い、不可抗力時の取扱い等を書面に記載し、
> **署名または記名押印して相互に交付**しなければなりません（出典：国土交通省）。
> **注文書・注文請書による方式でも、これらの事項を満たす必要があります**【Fact】。

> **【Fact】電子契約について**：国土交通省は
> 「電磁的措置による建設工事の請負契約の締結に係るガイドライン」（最終改正 2025年9月30日）を示しており、
> 一定の要件を満たす電子的方法による契約締結が認められています。
> ただし、**どの方式を採るかは企業により異なります**【Varies】。

### ⑦ 実行予算情報

| 項目 | 内容 |
|---|---|
| **何の情報か** | **この現場で使ってよい原価の上限**（費目別） |
| **誰が作るか** | ②積算・見積機能＋③工事管理機能。**承認は代表取締役** |
| **中身** | 材料費・労務費・外注費・現場経費の費目別予算、目標粗利 |
| **誰が使うか** | ③工事管理機能（**日々の原価管理の基準**）、⑥資材調達・外注管理機能（発注の上限）、⑦経理・財務機能（工事別原価との対比） |
| **どこに保管されるか** | 工事番号ごとの工事ファイル。⑦経理・財務機能が対比に使う |
| **次に何に変わるか** | 発注金額の上限（S11、S12）→ 原価実績との対比（S20） |
| **頻度** | **受注時**（工事の途中で見直す場合もある）【Varies】 |

> **【重要】この情報が現場に渡らないと何が起きるか**
> 現場代理人は「いくらまで使ってよいか」を知らずに発注することになります。
> 原価の超過に気づくのが工事完了後になります【Inference】。
> `03_company-structure.md` 3-6 で「②積算 → ③工事管理の実行予算の受け渡しが最も詰まりやすい接点」と
> 述べたのは、この情報の受け渡しのことです。

---

### ⑧ 施工計画情報（施工計画書・施工図）

| 項目 | 内容 |
|---|---|
| **何の情報か** | どんな手順・工法・材料・体制で工事を進めるか／実際に施工できるレベルまで詳細化した図面 |
| **誰が作るか** | ③工事管理機能（現場代理人 兼 主任技術者） |
| **中身** | **施工計画書**（使用材料のメーカー・品番、下地のピッチ、施工手順、品質管理の方法、作業員の体制、安全対策）／**施工図**（下地の割付、開口部の補強、他業者との取り合い） |
| **誰が承認するか** | **元請（および工事監理者）**。自社だけでは決められない【Typical】 |
| **誰が使うか** | ④現場作業機能（施工の指示書になる）、⑥資材調達（発注の根拠）、⑤安全品質（検査の基準） |
| **どこに保管されるか** | 現場事務所＋本社の工事ファイル。**承認印のある版を保管** |
| **次に何に変わるか** | 施工の実行（S13）→ 変更があれば**竣工図**（S18）へ |
| **頻度** | **受注時**（着工前）。変更のつど改訂【Typical】 |

> **なぜ着工前に承認をもらうのか**
> 着工後に「その材料は認めていない」「その工法では不可」となると、**すべてやり直し**になります。
> **着工前に合意しておくための情報**です【Inference】。

> **施工図（せこうず）**
> → 設計図をもとに、実際に施工できるレベルまで詳細化した図面。
> → 実務例：設計図には「軽量鉄骨下地 t=15 ボード2重張り」としか書かれていない壁について、
>   下地の割付、開口部の補強、他業者の配管・配線との取り合いまで描き込む。
> → **なぜ必要か**：設計図のままでは、現場で「ここはどう納めるのか」が決まらないためです。

### ⑨ 工程情報

| 項目 | 内容 |
|---|---|
| **何の情報か** | いつ、どの作業を、どこまで進めるか |
| **誰が作るか** | **元請**（全体工程表）／自社（自社工種の詳細工程） |
| **中身** | **全体工程表**（元請が作る、全工種の日程）、**週間工程表**、自社の作業工程、他業者との取り合いの予定 |
| **誰が使うか** | ③工事管理（進捗管理）、④現場作業（作業の段取り）、⑥資材調達（搬入日・労務手配日の決定） |
| **どこに保管されるか** | 現場事務所（掲示されることが多い）＋本社 |
| **次に何に変わるか** | **搬入計画**（S11）、**労務手配表**（S12）、**⑫出来高情報**の基準 |
| **頻度** | 全体工程は**受注時**に受領。週間工程の見直しは**週次**【Typical】。日々の進捗確認は**日次** |

> **【最重要】下請は工程を自分では決められない**
> `04_end-to-end-process.md` 4-2 のとおり、下請の場合、
> **元請の全体工程表の中に自社の作業期間が割り当てられます**【Typical】。
>
> ```
>  前工程が遅れる → 自社の作業開始日が押す
>                 → しかし後ろの工程（他業者）は動かない
>                 → 同じ作業を短い日数でこなす必要が生じる
>                 → 応援を入れる（＝原価が増える）
> ```
> **工程情報の変化が、そのまま原価の変化になります**【Inference】。

### ⑩ 安全情報

| 項目 | 内容 |
|---|---|
| **何の情報か** | 誰が現場にいるか／どんな危険があるか／どう対策するか |
| **誰が作るか** | ⑤安全・品質管理機能、③工事管理機能、④現場作業（職長）、⑧人事総務（資格・保険の情報） |
| **中身** | **グリーンファイル（安全書類）**＝作業員名簿、再下請負通知書、持込機械等使用届、有資格者名簿、保険加入状況、工事安全衛生計画書／**KY記録**／**新規入場者教育の記録**／**安全パトロールの指摘と是正**／災害報告 |
| **誰が使うか** | **元請**（施工体制台帳の作成、現場の安全管理）、自社（作業前の確認）、労働基準監督署（事故発生時）【Fact】 |
| **どこに保管されるか** | 現場事務所（元請が保管）＋自社の控え |
| **次に何に変わるか** | 元請の**施工体制台帳・施工体系図**へ【Fact】。事故発生時は災害報告へ |
| **頻度** | **受注時**（着工前）＋**作業員・協力会社が変わるたびに更新**【Typical】。KYは**日次**。パトロールの頻度は現場により異なる【Varies】 |

> **なぜこれだけの情報が必要なのか**
> 建設現場では**複数の会社の作業員が同時に働きます**（→ `06_people.md` 6-1）。
> 事故が起きたとき「誰の会社の、誰が、どの資格で、何の作業をしていたか」が分からないと、
> 救護も原因究明も責任の所在の確定もできません。
> **安全情報は、現場にいる全員を事前に把握しておくための情報**です【Inference】。

> **【Fact】施工体制台帳**：発注者から直接工事を請け負った特定建設業者は、
> その工事について締結した**下請契約の総額が5,000万円以上（建築一式工事は8,000万円以上）**になる場合、
> 施工体制台帳と施工体系図を作成しなければなりません
> （建設業法第24条の8。金額は2025年2月1日改正後／出典：国土交通省）。
> **下請は、その材料となる情報（自社と再下請の情報）を提供する義務**があります。

### ⑪ 施工実績情報（作業日報・工事写真）

| 項目 | 内容 |
|---|---|
| **何の情報か** | **実際に何が行われたか**の記録 |
| **誰が作るか** | ④現場作業機能（職長）、③工事管理機能（現場代理人） |
| **中身** | **作業日報**（誰が何人、何をどこまで進めたか、天候、使用機械）／**工事写真**（施工前・施工中・施工後）／**打合せ記録**／**是正記録** |
| **誰が使うか** | ③工事管理（進捗・原価の把握）、⑦経理・財務（**工事別原価の配賦**）、⑤安全品質（品質の証明）、元請・発注者（提出物） |
| **どこに保管されるか** | 現場→本社の工事ファイル。工事写真は**工事写真台帳**として整理される |
| **次に何に変わるか** | **⑫出来高情報**の根拠／**原価実績情報**／引渡し時の提出書類（S18） |
| **頻度** | **日次** |

> **【最重要】作業日報は「作業の記録」であり「原価の記録」でもある**
> `08_money.md` 8-8 のとおり、自社職人の給与は月額で支払われるため、
> **「誰がどの現場で何日働いたか」を作業日報で記録しないと、現場ごとの原価に配分できません**【Typical】。
>
> ```
>   作業日報 ──▶ 進捗の把握（工程管理）
>            ──▶ 投入人工の把握（原価管理）
>            ──▶ 出来高の根拠（請求）
>            ──▶ 実績歩掛の更新（次回見積）
> ```
> **1枚の日報が4つの用途に使われます**【Inference】。

### ⑫ 出来高情報

| 項目 | 内容 |
|---|---|
| **何の情報か** | 締日時点で、工事がどこまで進んでいるかを**金額で表した**情報 |
| **誰が作るか** | ③工事管理機能（現場代理人） |
| **中身** | **出来高報告書**、出来高内訳書（工種別の施工済み数量と金額）、出来高率（%） |
| **誰が使うか** | **元請（査定する）**、⑦経理・財務機能（請求の根拠） |
| **どこに保管されるか** | 工事ファイル。**査定後の確定値を保管する**（申請値と査定値の両方） |
| **次に何に変わるか** | **⑬請求情報** へ |
| **頻度** | **月次**（元請・発注者の締日に合わせる）【Typical】 |

> **【重要】申請した出来高と、査定された出来高は違うことがある**
> 下請が「70%進んだ」と報告しても、元請が現場を見て「60%」と査定すれば、
> その月に請求できるのは60%分です【Typical】。
> **だから出来高の根拠（施工済み数量、工事写真、作業日報）を示せる状態にしておくことが実務上重要**です。
>
> ```
>  ⑪施工実績情報（日報・写真・数量）──▶ ⑫出来高情報の根拠になる
> ```
> **日々の記録が、月次の請求額を決めます**【Inference】。

### ⑬ 請求情報

| 項目 | 内容 |
|---|---|
| **何の情報か** | 「いくら支払ってください」という請求 |
| **誰が作るか** | ⑦経理・財務機能（根拠は③工事管理機能から） |
| **中身** | **請求書**（工事名、請求金額、消費税、振込先、支払期日）、請求内訳 |
| **誰が受け取るか** | 元請の経理／発注者 |
| **誰が使うか** | 元請（支払処理）、自社（**完成工事未収入金**の管理） |
| **どこに保管されるか** | 経理の請求書控えファイル。売掛金台帳と対応づけて管理 |
| **次に何に変わるか** | **⑭入金情報** へ |
| **頻度** | **請求時**（出来高請求は**月次**、完成請求は**納品時**）【Typical】 |

> **【Typical】請求情報を出すために必要な前提**
> ```
>   ⑥契約情報（契約金額）
>      ＋ 変更契約（S15 で承認された追加分）
>      ＋ ⑫出来高情報（査定済み）
>      ＋ 完成引渡しの事実（S18）
>   ────────────────────────
>   ＝ 請求できる金額
> ```
> **どれか1つが欠けると請求できません。**
> 特に**変更契約を交わしていない追加工事は請求できません**（→ `04_end-to-end-process.md` S15）。

### ⑭ 入金情報

| 項目 | 内容 |
|---|---|
| **何の情報か** | 実際にいくら入金されたか |
| **誰が作るか** | 銀行（入金明細）→ ⑦経理・財務機能が記録 |
| **中身** | 入金日、入金額、振込元、手形の場合は期日 |
| **誰が使うか** | ⑦経理・財務機能（**消し込み**）、代表取締役（資金繰り） |
| **どこに保管されるか** | 入金記録・売掛金台帳 |
| **次に何に変わるか** | 資金繰り情報／**工事別原価の確定**（S20） |
| **頻度** | **入金時** |

> **消し込み（けしこみ）**
> → 請求した金額と入金された金額を照合し、一致したものを「回収済み」として消す作業のこと。
> → 実務例：780万円を請求し、778万円が入金された → 差額2万円の理由（振込手数料か、査定減か、相殺か）を確認する。
> → **なぜ必要か**：`08_money.md` 8-16 のとおり、
>   建設業では請求額と入金額が一致しないことがあります【Typical】。
>   差額を放置すると、回収漏れが後から発覚しても請求できなくなることがあります。

### ＋ 変更情報（設計変更・追加工事）

| 項目 | 内容 |
|---|---|
| **何の情報か** | 当初の契約から何がどう変わったか |
| **誰が作るか** | 発注者・設計者（指示）／③工事管理機能（現場での発見の報告）／②積算（金額の算出） |
| **中身** | 変更指示の記録、変更図面、**変更見積書**、**変更契約書または変更注文書・注文請書** |
| **誰が使うか** | 元請・発注者（承認）、③工事管理（施工）、⑦経理・財務（請求金額の更新） |
| **どこに保管されるか** | 工事ファイル。**当初契約と変更契約をセットで保管** |
| **次に何に変わるか** | **⑬請求情報**（請求できる金額が増える） |
| **頻度** | **案件発生時** |

> **【最重要】記録がないと請求できない**
> ```
>  ［典型的な失敗の構造］
>    現場で口頭の指示を受ける
>      → 工期が迫っているので先に施工する
>      → 書面を交わさない
>      → 後から「それは当初の契約範囲に含まれている」と言われる
>      → 請求できない
> ```
> **【Fact】建設業法第19条第2項**は、請負契約の内容を変更するときは、
> **変更の内容を書面に記載し、署名または記名押印して相互に交付しなければならない**としています。
> つまり**変更も書面で行うのが法律上の建て付け**です（出典：国土交通省）。

> **【Typical】実務での基本動作**
> 1. 変更の指示は、口頭で受けても**記録（メール・打合せ記録・工事日報）に残す**
> 2. 数量と金額の増減を出し、**変更見積を提出する**
> 3. **承認を得てから施工する**（緊急でやむを得ず先行する場合も、記録は必ず残す）

## 9-5 現場と本社が離れていることで何が起きるか

> 本資料は評価や提言を行いません。以下は**業務上の因果関係**の説明です。

### 情報が滞る典型的な箇所

| 情報 | どこで滞りやすいか | 滞ると何が起きるか |
|---|---|---|
| **⑦実行予算情報** | ②積算 → ③工事管理（現場） | 現場が「いくらまで使ってよいか」を知らずに発注する |
| **⑪施工実績情報**（日報） | ④現場作業 → ③工事管理 → ⑦経理 | 工事別原価の集計が遅れる。実行予算との差に気づくのが遅れる |
| **⑫出来高情報** | ③工事管理（現場） → ⑦経理 | **締日に間に合わず、その月の請求ができない → 入金が1か月遅れる** |
| **＋変更情報** | 現場で発生 → 本社へ | 書面を交わさないまま施工が進み、後から請求できなくなる |
| **③図面・仕様情報**（改訂版） | 元請 → 現場 → 協力会社 | 古い版で施工し、手戻りが発生する |
| **⑩安全情報**（作業員の変更） | 協力会社 → 自社 → 元請 | 書類が揃わず、**作業員が現場に入場できない** |

### なぜ滞るのか（構造的な理由）【Inference】

```
  ① 情報を持っている人（現場代理人・職長）が、現場にいる
  ② その人は同時に2〜4現場を掛け持っている【Typical】
  ③ 日中は施工管理・安全管理・他業者との調整に時間を使う
  ④ 書類の作成は、現場を離れた後になる
  ⑤ 本社の締日（給与計算、請求、支払）は待ってくれない
```

> **【Typical】だから建設業では「締日前後に書類が集中する」という業務の波が生まれます。**
> 詳細は `13_periodic-work.md` で扱います。

### 現場に入らないと分からない情報がある

| 情報 | なぜ現場でないと分からないか |
|---|---|
| 実際の進捗（出来高） | 図面では分からない。**目で見て数えるしかない** |
| 前工程の遅れ | 他業者の状況は、現場に行かないと分からない |
| 品質の状態 | 仕上げてしまうと下地は見えなくなる |
| 危険な状態 | 足場のぐらつき、整理整頓の状態は写真では伝わりにくい |
| 図面と現況の食い違い | 解体してみて初めて分かることがある |

## 9-6 情報が流れる経路（誰を経由するか）

### 下請から上へ（質問・報告・請求）

```
  自社の職長
     ↓
  自社の現場代理人
     ↓
  元請の現場所長
     ↓
  工事監理者（設計事務所）  ※技術的な事項
     ↓
  発注者
```

### 上から下へ（指示・承認・図面）

```
  発注者
     ↓
  工事監理者／元請の現場所長
     ↓
  自社の現場代理人
     ↓
  自社の職長 ／ 協力会社の職長
     ↓
  職人
```

> **【Typical】往復に時間がかかる**
> `06_people.md` 6-10 の【Example】では、追加工事の承認に
> 「職長 → 現場代理人 → 現場所長 → 設計事務所 → 発注者」と5人を経由し、
> 承認は逆順で戻ってきました。
> **この往復が、工程が動く主な原因の一つになります**【Inference】。

### 例外的に直接やり取りすることもある【Varies】

現場の実務では、効率のために業者同士が直接話すこともあります【Typical】。
ただし、**工程や費用が動く話は元請を通す**のが基本とされています。
理由は 9-1 違い(2) のとおり、**契約関係のない相手の指示には契約上の根拠がない**ためです。

## 9-7 【最重要】工事写真が果たす役割 ― なぜ撮るのか

### 建設業では「完成すると見えなくなる部分」が大量にある

> **隠蔽部（いんぺいぶ）**
> → 完成すると目視で確認できなくなる部分のこと。
> → 実務例：天井裏の下地、壁の中の配線・配管、床下の設備、コンクリートの中の鉄筋、
>   ボードの下の防火措置。

```
 ［施工中］                     ［完成後］
   軽量鉄骨の下地が見える    →    ボードとクロスで覆われ、見えない
   配線・配管が見える        →    天井材で覆われ、見えない
   防火区画の貫通処理が見える →    見えない
```

> **完成した状態を見ても、中がどうなっているかは分かりません。**
> 壊さない限り確認できません。

### だから写真が「証拠」になる

| 写真が証明すること | 具体例 |
|---|---|
| **指定された材料を使ったこと** | 材料の刻印・ラベルを写し込む |
| **指定された寸法・ピッチで施工したこと** | スケール（定規）を当てて撮る |
| **必要な補強・処理をしたこと** | 開口部の補強、防火措置 |
| **既存の状態がどうだったか** | 施工前の状態（＝追加工事の根拠にもなる） |
| **是正が完了したこと** | 指摘箇所の是正前・是正後 |

### 工事写真の撮り方の考え方【Typical】

```
 ［必ず撮る3点セット］
   ① 施工前 ── 着手前の状態
   ② 施工中 ── 完成後に見えなくなる部分（★最重要）
   ③ 施工後 ── 仕上がった状態

 ［写し込むもの］
   ・黒板（工事名、工種、施工箇所、施工内容、日付）
   ・スケール（寸法が分かるように）
   ・全体が分かる引きの写真＋詳細が分かる寄りの写真
```

> **なぜ黒板を写し込むのか**
> 写真だけでは「どの現場の、どこの、いつの写真か」が分かりません。
> **後から検証できる情報を、写真そのものに埋め込む**ためです【Inference】。

### 【Fact】公共工事では写真管理が契約上の要求事項になる

公共工事では、**写真管理基準**が定められ、
撮影頻度・撮影箇所・提出方法が契約上の要求事項として指定されます【Typical】。
民間工事では、元請・発注者によって要求の程度が大きく異なります【Varies】。

### 写真情報の行き先

```
  工事写真（撮影）
     ↓
  工事写真台帳（整理・分類）
     ↓
  ┌────────────┬──────────────┬─────────────┐
  ▼            ▼              ▼             ▼
 出来高の根拠  品質の証明    追加工事の根拠  引渡し時の提出物
 （S14）      （S17）       （S15）        （S18）
```

> **【Typical】写真の整理が実務上の負担になる理由**
> 1つの現場で数百〜数千枚の写真を撮ることがあります。
> **撮るだけでは使えず、「どこの、何の写真か」を分類して初めて台帳になります**。
> `09-5` で「情報が滞る」と述べた箇所の1つがここです。

## 9-8 社外に出す情報と、社内だけの情報

これを区別しないと、**出してはいけない情報を出してしまう**ことがあります。

| 区分 | 情報 | 誰に出すか |
|---|---|---|
| **社外に出す（元請・発注者へ）** | 見積書、見積内訳書、注文請書、施工計画書、工程表、施工図、**グリーンファイル**、作業日報（提出を求められる場合）、工事写真、出来高報告書、検査記録、是正報告、完成引渡書、竣工図、請求書 | 元請／発注者 |
| **社外に出す（行政へ）** | 建設業許可の申請・変更届、決算変更届、経営事項審査の申請書類、労働保険・社会保険の届出、災害報告【Fact】 | 許可行政庁、労働基準監督署、年金事務所 |
| **社外に出す（協力会社へ）** | 注文書、工程表、施工図、作業指示、安全指示 | 協力会社・一人親方 |
| **社内だけ（原則として出さない）** | **実行予算書**、**原価積上げ表**、**歩掛**、工事別原価の実績、仕入単価、協力会社への発注単価、資金繰り表、給与情報 | — |

> **【最重要】実行予算と見積内訳は別物**
> ```
>   見積内訳書（社外に出す）：元請に提出する。工種・数量・単価・金額
>   実行予算書（社内だけ）  ：自社がいくらで作るつもりかの内訳。★利益の中身が分かる
> ```
> **実行予算書を社外に出すと、自社の原価構造と利益率が相手に分かります**【Inference】。
> 建設業の実務で「見積書の内訳はどこまで出すか」が論点になるのは、この境界の問題です。

> **【Fact】ただし、見積書に記載すべき事項は法令上明確化されています。**
> 2025年12月完全施行の改正建設業法により、
> **建設工事の見積書に記載すべき事項が明確化**されました（出典：国土交通省）。
> 「何を出すか」は、企業の判断だけでなく法令にも関わります。
> 詳細は `15_rules-customs.md` で扱います。

## 9-9 情報の「版」と「更新」の管理

建設業では、**同じ名前の書類が何度も改訂されます**。

| 情報 | 改訂される理由 | 古い版を使うとどうなるか |
|---|---|---|
| **設計図** | 設計変更、施主要望、法規対応 | **手戻り**（施工したものをやり直す） |
| **施工図** | 他業者との取り合いの調整 | 納まらない。作り直し |
| **工程表** | 前工程の遅れ、天候、変更工事 | 職人を手配した日に仕事がない（**手待ち**） |
| **見積書** | 条件変更、価格折衝 | 古い金額で契約してしまう |
| **作業員名簿** | 作業員の入退場 | **現場に入場できない**【Typical】 |

> **【Typical】実務での基本動作**
> - 版数・改訂日を明記する
> - 最新版がどれかを、現場と協力会社に確実に伝える
> - 古い版は差し替える（または「旧版」と明示する）
>
> （本資料は改善策を扱いません。版管理が必要になる業務上の理由として理解してください。）

## 9-10 媒体について【Varies】

> **本資料では、情報の媒体（紙・Excel・専用システム・クラウド・チャット等）を決めつけません。**

## 9-11 【Fact】情報の保存に関する法令上の義務

建設業では、一定の情報の保存が法令で義務づけられています。

| 情報 | 保存期間 | 根拠 |
|---|---|---|
| **帳簿**（営業に関する事項を記載したもの）とその添付書類 | **5年間**。ただし**発注者と締結した住宅を新築する建設工事に係るものは10年間** | 建設業法**第40条の3**、同施行規則第26条・第28条【Fact】 |
| **営業に関する図書**（完成図、発注者との打合せ記録、施工体系図） | **引渡しから10年間**。**発注者から直接建設工事を請け負った場合**が対象 | 建設業法第40条の3、同施行規則第28条【Fact】 |
| **産業廃棄物管理票（マニフェスト）の写し** | **交付した日から5年間** | 廃棄物処理法【Fact】（出典：環境省） |

（建設業法関係の出典：国土交通省。制度の詳細は必ずその時点の公式情報で確認してください）

> **【重要】なぜ保存義務があるのか**
> 建設工事の目的物は長期間使われ続けます。
> 後から不具合が見つかったとき、**誰がどう施工したかを検証する必要がある**ためです【Inference】。
> だから「営業に関する図書」の保存期間は10年と長く設定されています。

> **モデル企業（下請中心）の場合**【Example】
> 「営業に関する図書」の10年保存は、**発注者から直接請け負った場合**が対象です。
> モデル企業は売上の約30%が直請けのため、その部分が該当します。
> 一方、**帳簿の5年保存はすべての建設業者が対象**です【Fact】。

> その他、労働安全衛生関係の記録、税務関係の帳簿書類にもそれぞれ保存期間の定めがあります。
> 詳細は `10_documents.md` `15_rules-customs.md` で扱います。

## 9-12 情報は循環している ― 積算情報のフィードバック

### 建設業の情報の最大の特徴

> **1つの工事で得た実績が、次の工事の見積の精度を決めます。**

```
 ［1件目の工事］
   ④積算情報（歩掛：クロス張り 1人1日60㎡と仮定）
      ↓
   ⑤見積情報 → ⑥契約情報 → ⑦実行予算情報
      ↓
   ⑪施工実績情報（実際は 1人1日52㎡だった）
      ↓
   原価実績情報（労務費が予算超過。理由は搬入条件）
      ↓
 ★ ④積算情報を更新（このビル形状・この搬入条件なら 52㎡/人日）

 ［2件目の工事］
   更新された歩掛で積算 → 見積の精度が上がる
```

### なぜこの循環が重要なのか

| 理由 | 説明 |
|---|---|
| **1件ごとに条件が違う** | 標準原価が使いにくい。実績の蓄積でしか精度が上がらない【Typical】 |
| **契約時に金額が確定する** | 受注後の原価上振れは原則として自社負担（`04_end-to-end-process.md` S4） |
| **歩掛は公開されていない** | 各社が自社の実績から作る。**会社固有の資産**になる【Inference】 |

> **【Typical】この循環が切れると何が起きるか**
> 実績原価を集計しない、または集計しても積算に戻さないと、
> **何年たっても見積の精度が上がりません**。
> `04_end-to-end-process.md` S20 で「なぜ振り返るのか」と述べたのは、この循環のことです。

## 9-13 【Example】1工事の情報の流れを追跡する

> ⚠️ **以下はすべて説明用の架空の事例です。実在する工事・企業ではありません。**
> `04_end-to-end-process.md` 4-5 の案件（○○ビル5階テナント内装工事）を、
> **情報の視点**で追い直します。

| 時期 | 情報の動き | 情報の名前 |
|---|---|---|
| 着工8週前 | 元請G社の工事部から見積依頼＋図面一式がメールで届く → 営業Nが**引合い台帳**に登録 | **①引合い情報** |
| 着工8週前 | 「技術者が空く」「G社は支払条件が明確」という社内情報を持ち寄り、社長Sが見積作成を決定 | 受注判断情報 |
| 着工7週前 | 現場代理人Aと積算Bが現地へ。解体量が図面より多い／EVに寸法制約あり／置き場あり を確認し、**写真と実測寸法**を記録 | **②現地条件情報** |
| 着工7週前 | 元請から平面図・天井伏図・仕上表・展開図・仕様書を受領。**版数を確認** | **③図面・仕様情報** |
| 着工6週前 | 積算Bが**数量拾い表**を作成（間仕切り180㎡、クロス620㎡、カーペット340㎡、必要人工110人工） | **④積算情報** |
| 着工5週前 | 原価に一般管理費・利益を乗せ、**見積書・内訳書・見積条件書**を提出（1,620万円） | **⑤見積情報** |
| 着工4週前 | 元請の査定1,450万円 → Aが**現調写真**を根拠に解体量増を説明 → 1,500万円で合意 | ②が⑤の根拠として再利用される |
| 着工3週前 | **注文書**を受領し、**注文請書**を返送。工事番号を採番し**工事台帳**に登録 | **⑥契約情報** |
| 着工3週前 | 積算Bと A が**実行予算書**を作成（原価1,275万円／粗利225万円）。社長Sが承認 | **⑦実行予算情報**（社内限り） |
| 着工2週前 | **施工計画書・工程表・施工図**を作成し、元請と工事監理者の承認を取得 | **⑧施工計画情報** |
| 着工2週前 | 元請の**全体工程表**を受領。自社の作業期間を確認 | **⑨工程情報** |
| 着工2週前 | 総務Yから有資格者名簿・保険加入状況を受領。協力会社から作業員名簿等を回収し、**グリーンファイル**を元請に提出 | **⑩安全情報** |
| 着工1週前 | 数量拾い表と工程表から**材料発注書**と**搬入計画**を作成。協力会社へ**注文書**を発行 | ④＋⑨から派生 |
| 着工日〜 | 毎日：**作業日報**（誰が何人、どこまで）、**工事写真**（施工前／隠蔽部／施工後）、**KY記録** | **⑪施工実績情報**／**⑩安全情報** |
| 着工2週後 | 壁内に図面にない配管を発見 → **写真**を撮り即日元請へ報告 → **変更見積（18万円）** → **変更注文書**を受領してから施工 | **＋変更情報** |
| 着工4週後（月末） | 施工済み数量を集計し**出来高報告書**（55%＝825万円）を提出 → 元請が査定し**52%＝780万円**で確定 | **⑫出来高情報** |
| 着工5週後 | 経理Eが**請求書**（780万円）を提出 | **⑬請求情報** |
| 着工7週後 | Aと安全Mが**自主検査記録**を作成。**是正リスト11か所** → 2日で是正 | **＋品質情報** |
| 着工8週後 | 元請検査（指摘4か所）→ 施主検査（指摘1か所）→ **是正完了報告（写真付き）** | **＋品質情報** |
| 着工8週後 | **完成引渡書・竣工図・工事写真・材料の証明書**を提出 | 引渡し情報 |
| 着工8週後 | 契約1,500万円＋変更18万円＝1,518万円から既請求780万円を控除し、**738万円を請求** | **⑬請求情報** |
| 着工12週後 | 780万円が入金 → **消し込み** | **⑭入金情報** |
| 工事完了後 | 実行予算と実績を突合（原価1,275万円 → 1,305万円）。差の理由を特定 | **＋原価実績情報** |
| 工事完了後 | **「このビル形状・この搬入条件なら軽鉄・ボードは何人工」**という実績歩掛を積算Bへ申し送り | **④積算情報へ循環** ★ |

### この追跡から分かること

| 分かること | 内容 |
|---|---|
| **1. 情報は形を変えながら最後まで使われる** | ②現調情報は、S5 見積の根拠になり、S6 折衝の根拠になり、S9 施工計画の前提にもなった |
| **2. 写真が3回役に立った** | ①現調時（見積の根拠）②変更発生時（追加工事の根拠）③是正完了時（品質の証明） |
| **3. 日次の情報が月次の請求額を決める** | 作業日報と数量の記録がなければ、出来高報告に根拠を持たせられない |
| **4. 最後に情報が④へ戻る** | 原価実績情報が次の積算情報になる。**これが建設業の情報の輪** |

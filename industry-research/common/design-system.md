# design-system.md — スライド設計と画像生成の共通デザインシステム

全業界の `17_slides.md` / `18_image-prompts.md` はこのファイルに従うこと。
**業界ごとに画像のテイストがバラバラになることを防ぐ**のがこのファイルの目的です。

---

## PART 1. PowerPoint スライド設計

### 1-1. 原則

- **1スライド＝1メッセージ。** 1枚に2つの主張を載せない。
- 目安 **30〜45枚**。必要なら45枚を超えてよい。
  **情報を削って30枚に収めるより、初心者が理解できることを優先する。**
- 調査結果をそのまま流し込まない。スライドは「調査の要約」ではなく「理解の設計」。

### 1-2. 可読性の優先順位

本文を文章だらけにしないこと。表現手段は上から優先して選ぶ。

```
1. 図       （構造・関係・流れ）
2. フロー   （順序があるもの）
3. 表       （項目が並列で比較できるもの）
4. カード   （3〜6個の要素の並置）
5. 箇条書き （上記で表せないもの）
6. 長文     （最後の手段）
```

詳細説明はスライド本文に詰め込まず、**スピーカーノート**に回してよい。

### 1-3. 推奨スライド構成（業界ごとに最適化すること）

```
 1. 表紙
 2. この資料で分かること
 3. 3分で分かる○○業界
 4. ○○業界は社会のどこにいる？
 5. 業界分類
 6. 主な企業タイプ
 7. 顧客は誰？
 8. 何を売っている？（売上の源泉）
 9. 業界プレイヤーマップ
10. 商流
11. バリューチェーン
12. 典型的な中小企業（モデル企業）
13. 組織・部署（機能マップ）
14. 全社業務フロー（受注〜入金）
15. ヒトの流れ
16. モノの流れ
17. カネの流れ
18. 情報の流れ
19〜. 部署別（各部署につき 役割／業務フロー／業務一覧・頻度／IN-OUT／関係部署／帳票・情報）
  〜. 部署間連携
  〜. 帳票一覧
  〜. システム一覧
  〜. お金の仕組み（売上・コスト・利益・キャッシュの時間差）
  〜. 定期業務
  〜. KPI
  〜. 業界ルール（法規制・許認可・資格）
  〜. 商習慣
  〜. 用語集
  〜. 初心者が間違えやすいポイント
  〜. 全体まとめ
```

業界の実態に合わせて順序・枚数を変えてよい。ただし §1-2 の思想は変えない。

### 1-4. スライド原稿の出力形式（この形式を厳守）

````markdown
## Slide 14：受注から入金までの全体像

### このスライドで伝えたいこと
（1文。このスライドの唯一のメッセージ）

### タイトル
（スライドに実際に載せる短いタイトル）

### サブタイトル
（無い場合は「なし」）

### 本文
（スライドに載せる要素。箇条書き／表／カードの中身を具体的に。長文にしない）

### 図表
（このスライドに置く図や表の内容を具体的に記述。画像を使う場合は IMAGE-014 と対応付ける）

### 初心者向け補足
（スピーカーノート想定。ここは文章で厚く書いてよい）

### 出典
- （短縮表記。無い場合は「なし（一般的な業務知識）」）

### 画像
必要 / 不要

### 画像種類
業務フロー / インフォグラフィック / イラスト / 概念図 / 関係図 / プロセス図 等
````

## PART 2. 画像生成プロンプト

### 2-1. 画像を作る判断基準

**すべてのスライドに画像を入れてはいけない。** 次の場合のみ推奨する。

- 文章だけでは構造が理解しづらい
- 商流 / バリューチェーン / 業務フロー
- モノの流れ / カネの流れ / 情報の流れ
- 部署間関係 / 会社全体像 / 業界構造
- 工程 / 空間配置

**単純な表のほうが分かりやすい場合は画像を作らない。**
1業界あたりの画像点数は概ね 10〜15 点を目安とする。

### 2-2. 画像プロンプトの出力形式（この形式を厳守）

````markdown
# IMAGE-014

## 使用スライド
Slide 14

## 画像の目的
（この画像で初心者に何を理解させるか。1〜2文）

## 推奨配置
（例：スライド中央〜右側、横幅70%）

## アスペクト比
16:9

## ChatGPT画像生成プロンプト

（ここに、そのままコピー＆ペーストできる完全な日本語プロンプト。
 A〜J の全要素を含んだ、数百字規模の完成プロンプト。
 「○○の画像を作って」のような短いプロンプトは禁止）

## PowerPoint上で追加する要素
- タイトル
- 出典
- 補足説明

## 画像内に含めないもの
- 長文
- 出典
- 注釈
````

### 2-3. プロンプトに必ず含める10要素（A〜J）

| | 要素 | 内容 |
|---|---|---|
| A | **目的** | 何を理解させる画像か |
| B | **表現形式** | インフォグラフィック／フロー図／アイソメトリック図／鳥瞰図／概念図／プロセス図／関係図 |
| C | **キャンバス** | PowerPoint用・横長16:9・1920×1080相当・高解像度 |
| D | **デザイン** | §2-4 の共通デザイン文（毎回そのまま入れる） |
| E | **レイアウト** | 「左から右へ5段階」「上段に情報・下段にモノ」等、配置を具体的に指定 |
| F | **表示要素** | 描くものを列挙 |
| G | **テキスト** | 画像内に入れる日本語ラベルを明示。文字数は最小限 |
| H | **アイコン** | 人物・会社・工場・トラック・書類・お金・データ等、必要なものを指定 |
| I | **色** | §2-5 のカラールール |
| J | **禁止事項** | §2-6 の禁止リスト |

### 2-4. 共通デザイン文（全画像のプロンプトにこのまま埋め込む）

> モダンでプロフェッショナルな、日本企業向けビジネス資料のデザイン。clean / minimal / sophisticated。
> フラットデザインを基調に、ごく控えめな奥行き（subtle depth）のみ与える。過度な3D表現は避ける。
> 余白を十分に取り、情報階層を明確にする。コンサルティングファームの資料のように整理された構成。
> 白〜ごく薄いグレーの背景。角丸のカード。細く均一な線。控えめな影。
> 人物アイコン・建物アイコン・設備アイコンはすべて同一テイストのシンプルなピクトグラムで統一。
> 矢印はすべて同一デザイン。日本語ラベルは正確で自然な日本語。
> 初心者が一目で関係性を理解できるレイアウト。高解像度でPowerPointに自然に馴染むこと。

### 2-5. カラールール

- 背景：白〜ごく薄いグレー
- 基本色：ネイビー／ブルー
- アクセントカラーは**2色以内**に限定
- 高コントラスト（ビジネス用途・プロジェクタ投影を想定）
- **色だけに意味を依存させない。** 必ずラベル・アイコン・線種を併用する

### 2-6. 禁止事項（全画像プロンプトに明記）

- 写実的すぎる画像 / 写真風
- 不要な装飾 / 派手なグラデーション
- 文字だらけ / 小さすぎる文字
- 意味不明なアイコン
- 不自然な日本語（誤字・機械翻訳調）
- 余計なタイトル / ウォーターマーク / ロゴ
- 架空の企業名
- PowerPointに不要な背景装飾

## PART 3. 4つの流れの表現ルール（全業界・全画像で統一）

同じ資料内で表現ルールを変えないこと。

| 流れ | アイコン | 線・矢印 | 色の役割 |
|---|---|---|---|
| **ヒト** | 人物ピクトグラム | 細い実線の関係線（矢印なし、または双方向） | ネイビー |
| **モノ** | 箱・材料・製品・トラック | **太い実線の矢印** | ブルー |
| **カネ** | ￥マーク・請求書・硬貨 | **実線矢印（やや太め・カネ専用の形状）** | アクセント色1（例：グリーン系） |
| **情報** | 書類・データ・画面 | **点線の矢印** | アクセント色2（例：オレンジ系） |

図の中に複数の流れが混在する場合は、
**上段＝情報の流れ／下段＝モノの流れ** のように段で分けると初心者に分かりやすい。
凡例（レジェンド）を必ず画像内に小さく入れること。

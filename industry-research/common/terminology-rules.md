# terminology-rules.md — 用語・表記の共通ルール

全業界の全ファイルで、この表記に従うこと。

---

## 1. 専門用語の書き方

必ず **専門用語 → 日本語で簡単に説明 → 実務例** の順。初出時は必ずこの3点セットを書く。

```
BOM（部品表）
→ 製品を1つ作るのに必要な部品・材料の一覧表のこと。
→ 実務例：「椅子1脚＝脚4本・座面1枚・ネジ12本」のように、何がいくつ要るかを登録しておき、
   受注数を掛け算して必要な材料量を計算するのに使う。
```

初出以降は略称のみでよいが、`16_glossary.md` に必ず収録すること。

---

## 2. 用語集の形式（`16_glossary.md`）

| 用語 | 正式名称 | 簡単な意味 | 実務ではどう使う？ |
|---|---|---|---|

- 「辞書的な定義」だけで終わらせない。**実務上どう使われるか**を必ず書く。
- 初心者が資料を読んで詰まりそうな用語を網羅する（目安：1業界あたり60語以上）。
- 業界固有語だけでなく、**商取引・会計の基本語**（与信、掛売、締め日、売掛金、
  買掛金、粗利、リードタイム 等）も収録する。

---

## 3. 「初心者が間違えやすいこと」（`16_glossary.md` 後半）

似た言葉・混同しやすい概念を、業界ごとに整理する。各項目は
**「何と何が違うのか」＋「なぜ混同するのか」＋「実務でどう効いてくるのか」** まで書く。

全業界で共通して扱うべき基本（業界の実態に合わせて言い換える）：

```
売上 ≠ 入金        （売上が立ってもお金はまだ入っていない）
受注 ≠ 売上        （注文をもらった時点ではまだ売上にならない）
発注 ≠ 仕入計上    （注文しただけでは仕入にならない）
在庫 ≠ すべて完成品（原材料・仕掛品・完成品は別物）
粗利 ≠ 利益        （粗利から販管費を引いて初めて営業利益）
見積 ≠ 契約        （見積を出しただけでは仕事は確定していない）
```

これに**業界固有の混同しやすいペア**を必ず追加すること。
例：建設業なら「請負 ≠ 派遣」「元請 ≠ 発注者」、
物流業なら「運送 ≠ 倉庫」「実運送 ≠ 利用運送」など。

---

## 4. 表記統一

| 項目 | ルール |
|---|---|
| 見出し | Markdown の `#`〜`####` を使う。深さは4階層まで |
| 数字 | 半角。桁区切りカンマを使う（1,000個） |
| 単位 | 「円」「名」「個」「時間」等、日本語単位を優先 |
| 年度 | 西暦を基本とし、必要に応じて和暦を括弧書き（2024年〈令和6年〉） |
| 企業名 | 架空例では「A社」「X工業」等の記号的名称を使い、実在企業名を架空例に使わない |
| 部署名 | 「営業機能（一般的な名称：営業部、業務部 等）」の形で、機能→名称の順 |
| 確度タグ | `【Fact】【Typical】【Example】【Varies】【Inference】` を本文中に埋め込む |
| 出典 | 本文中は `（出典：資料名／発行元）` の短縮表記。詳細は `19_sources.md` |

---

## 5. 禁止表現

- 「〜すべきである」「〜が課題である」「〜を改善できる」等の**提案・評価表現**
  （本資料は理解のための資料であり、提案資料ではない）
- 「効率が悪い」「アナログである」等の**価値判断**
- 「必ず〜である」「すべての企業が〜」等の**根拠のない断定**
  （`【Varies】`を使うか、範囲を限定して書く）
- 「最近では〜」「近年〜」のみで年を示さない表現（年度を明記する）

## 11-2. ① 会計ソフト — この業界の中心的な道具

### 何のための道具か

**仕訳を1件ずつ記録し、それを自動的に元帳・試算表・決算書の形に集計する道具です。**

```
   仕訳を入力      →   総勘定元帳     →   試算表        →   決算書
   （1件ずつ）          （科目ごと）        （残高一覧）        （1年の結果）
        │                   │                  │                  │
        └───────────────────┴──────────────────┴──────────────────┘
                       **すべて同じデータから自動的に作られる**
```

> **なぜこの道具が中心なのか**
> 【Inference】この業界の月次業務（`04_end-to-end-process.md` B）は、
> **仕訳の入力から試算表の作成までが一本の流れ**になっています。
> その流れの全部が、この道具の中で起きます。
> `10_documents.md` の帳票のうち、仕訳帳・総勘定元帳・試算表・決算書は、
> **すべて会計ソフトが出力するもの**です。

### 何ができる道具か

| 機能 | 何のためか | どの業務で使うか |
|---|---|---|
| 仕訳の入力 | 取引を記録する | `05_departments.md` ②-2〜②-6 |
| 勘定科目の設定 | 顧問先の事業に合った科目を使う | ②-10（新規顧問先の初期設定） |
| 総勘定元帳の出力 | 科目別に取引を追う | ②-8（残高照合） |
| **試算表・推移表の出力** | 期の途中の状況を見る | ①-5（試算表の確認） |
| 補助元帳（取引先別） | 売掛・買掛を相手先別に管理する | ②-8 |
| 固定資産の管理・減価償却の計算 | 固定資産ごとの償却額を出す | ③-1（決算整理） |
| 決算書の出力 | 貸借対照表・損益計算書を作る | ③-3 |
| 期首残高の引継ぎ・繰越処理 | 前期の残高を当期に引き継ぐ | ③-2 |

### 実務上どういう形があるか（並べて書きます。評価はしません）

| 形 | どういうものか |
|---|---|
| **事務所のパソコンに入れて使う** | 【Typical】事務所内のパソコンにソフトを入れ、事務所内で入力する |
| **サーバに置いて所内で共有する**【Varies】 | 複数の職員が同じデータを見られるようにする |
| **インターネット経由で使う**【Varies】 | 事務所の外からも同じデータを見られる形 |
| **顧客が自社で入力し、事務所が点検する**【Varies】 | `05_departments.md` ②-9。この場合、②記帳代行・入力機能の作業が「入力」から「点検」に変わる |
| **顧客が使っているソフトと、事務所のソフトが違う**【Varies】 | データの受渡しの方法が問題になる |

> **★「顧客が自社で入力している」場合の違い**
> 【Inference】事務所が入力するのではなく、**入力済みのデータを点検する**ことになります。
> 作業の中身が変わるため、`05_departments.md` は ②-9 を独立した業務として立てています。
> 【Varies】どちらの形かは顧問先ごとに異なり、**同じ事務所の中で混在することも一般的です。**
> （※どちらが良いという評価はしません。）

## 11-3. ② 申告書作成ソフト

### 何のための道具か

**会計データ（決算書）から税額を計算し、制度が定める申告書の様式に数値を落とす道具です。**

> **なぜ会計ソフトと別なのか**
> 【Inference】会計上の利益と、税金の計算上の所得は一致しません
> （`03_company-structure.md` 3-4 ③）。
> 決算書から申告書へは、**変換の作業**が必要です。
> また、申告書は**別表（べっぴょう）**と呼ばれる複数の様式で構成され、
> それぞれの数値が相互に連動します。この連動の計算を行うのがこの道具です。
> ※**具体的な税務上の判断・処理方法には、本資料は立ち入りません。**

### 何ができる道具か

| 機能 | 何のためか |
|---|---|
| 決算書データの取込み | 会計ソフトの数値を引き継ぐ |
| **税額の計算** | 制度に従って税額を算出する |
| **様式への反映** | 申告書の定められた様式に数値を配置する |
| 別表間の連動計算 | 様式どうしで整合が取れるようにする |
| 地方税の申告書の作成 | 都道府県・市町村ごとの様式に対応する |
| 消費税の申告書の作成 | 【Fact】消費税法第45条第1項の申告のため |
| 所得税の確定申告書の作成 | 【Fact】所得税法第120条第1項の申告のため |
| 勘定科目内訳明細書・事業概況説明書の作成 | 申告書に添付する書類を作る |
| 電子申告データの作成 | ③へ渡すデータを作る |

（`05_departments.md` ③-6〜③-12 に対応）

### ★税制改正への対応が、この道具の前提になっている

【Inference】税制は改正されます。
改正されれば、**税額の計算方法も、申告書の様式も変わります。**
事務所が自力で様式を作り直すことはできません。

したがって、
- **保守・更新の契約が、業務の前提**になります（`08_money.md` 8-5 ③）。
- **更新の時期が、業務のスケジュールに影響します**【Varies】。
- ソフトウェアベンダーが、事務所の社外関係者として登場します（`06_people.md` 6-2 ⑥）。

## 11-4. ③ 電子申告の仕組み（e-Tax／eLTAX）

### 何のための道具か

**作成した申告書を、国税・地方税の官公署に対して電子的に提出するための仕組みです。**

| 名称 | 対象 | 提出先 |
|---|---|---|
| **e-Tax** | 国税（法人税・所得税・消費税 等） | 税務署（国税庁） |
| **eLTAX** | 地方税（法人都道府県民税・法人市町村民税・事業税・給与支払報告書 等） | 都道府県・市町村 |

> **★国税と地方税で仕組みが分かれています**
> 【Inference】1つの法人の申告でも、**国に出すものと、都道府県・市町村に出すものがあります。**
> `04_end-to-end-process.md` C の全体像に「法人税・消費税・地方税」が並んでいるのは、このためです。

### この仕組みが返してくるもの

| 返ってくるもの | 何か | なぜ重要か |
|---|---|---|
| **受信通知** | 提出が受け付けられたことの記録（受付日時・受付番号） | 【Inference】送信した「つもり」と受け付けられたことは別。**期限内に提出したことを示す記録**になる（`10_documents.md` 13） |
| エラーの通知 | 形式の誤りなどで受け付けられなかった場合 | 【Inference】**期限の直前に出ると、修正の時間が要る** |

### 誰が操作するのか

**【Fact】税理士法第30条（税務代理の権限の明示）**

> 「税理士は、税務代理をする場合においては、財務省令で定めるところにより、
> その権限を有することを証する書面を税務官公署に提出しなければならない。」
> （出典：税理士法／e-Gov法令検索）

**【Fact】税理士法第33条第1項（署名の義務）**

> 「税理士又は税理士法人が税務代理をする場合において、租税に関する申告書等を作成して税務官公署に
> 提出するときは、当該税務代理に係る税理士は、当該申告書等に署名しなければならない。…」
> （出典：税理士法／e-Gov法令検索）

`05_departments.md` ④-4「電子申告の送信と受信通知の確認」は、
**④チェック・レビュー機能（有資格者）の業務**として置かれています。

### 道具として必要なもの

| もの | 何のためか |
|---|---|
| **電子証明書**【Varies】 | 送信者が誰であるかを示すため |
| ICカードリーダ【Varies】 | 電子証明書を読み取るため（証明書の形式による） |
| 利用者識別番号等 | 各仕組みの利用者を識別するため |

（`05_departments.md` ③N「電子証明書（ICカードリーダを使う場合を含む）【Varies】」）

## 11-5. ④ 給与計算ソフト【Varies】

### 何のための道具か

**従業員ごとの給与の額・控除の額・源泉所得税の額を計算する道具です。**

| 機能 | 何のためか |
|---|---|
| 支給額の計算 | 基本給・手当・残業代を集計する |
| 社会保険料の控除の計算 | 健康保険・厚生年金・雇用保険の本人負担分を差し引く |
| **源泉所得税の計算** | 【Fact】所得税法第183条第1項「その支払の際、その給与等について所得税を徴収し、その徴収の日の属する月の翌月十日までに、これを国に納付しなければならない。」（出典：所得税法／e-Gov法令検索） |
| 支給明細の出力 | 従業員に渡す |
| **年末調整の計算** | 1年間の所得税を精算する |
| 賃金台帳の出力 | 記録として残す |

### 誰が使うのか【Varies】

| 形 | どういうものか |
|---|---|
| **顧客が自社で計算する** | 【Typical】事務所は仕訳の元になる資料（支給明細等）を受け取るだけ |
| **税理士事務所が受託する**【Varies】 | 事務所が計算し、顧客に結果を渡す |
| **社会保険労務士事務所が受託する**【Varies】 | 【Typical】社労士事務所では、給与計算を受託しているかどうかで月次の業務量が大きく変わる（`03_company-structure.md` 3-3） |
| **事務所自身の職員の給与計算に使う** | `05_departments.md` ⑥-8 |

> **★給与計算は、税と労働保険の両方に関わります**
> 【Inference】源泉所得税は税の話（【Fact】所得税法第183条第1項）、
> 社会保険・労働保険は社労士の扱う領域です。
> だから同じ給与データが、税理士事務所と社労士事務所の両方に流れることがあります
> （`06_people.md` 6-7 の6〜7月）。

## 11-6. ⑤ 顧客管理・進捗管理システム【Varies】

### 何のための道具か

**「どの顧問先の、どの作業が、どこまで進んだか」を一覧で見るための道具です。**

> **なぜこの道具が必要になるのか**
> 【Example】X会計事務所には顧問先が120件あります。
> 【Inference】1件ずつの状況を記憶で管理することはできません。
> とくにこの業界では、**期限が顧問先ごとに違います**（決算月が違うため）。
> 「今どの件が危ないか」を見る手段が必要になります。

### 何を見る道具か

| 見るもの | なぜ見るか | 対応するKPI（`14_kpi.md`／本セットの `pro_14`） |
|---|---|---|
| **顧問先ごとの決算月・申告期限** | 期限は動かない（【Fact】法人税法第74条第1項ほか） | 申告期限の遵守率 |
| **資料の受領状況**（何月分が来ているか） | `09_information.md` 9-8 のとおり、ここが詰まると全部止まる | 資料の回収率・遅延件数【Varies】 |
| **入力の完了状況** | 試算表が出せるかどうかが決まる | 入力完了率 |
| **チェック待ちの件数** | 有資格者のところに何件たまっているか | ④での滞留件数 |
| **担当者ごとの担当件数** | 負荷の偏りを見る | 担当者1人あたり顧問先数 |
| 契約内容（顧問料・決算料） | 請求の元になる | — |

### 実務上どういう形があるか【Varies】

| 形 | どういうものか |
|---|---|
| **専用のシステムを使う** | 顧客情報と進捗を一元的に管理する |
| **会計ソフトに付属する機能を使う**【Varies】 | 会計ソフトの側で進捗を管理できる場合がある |
| **表計算ソフトで一覧を作る**【Typical】 | 顧問先名・決算月・進捗の列を作り、所内で共有する |
| **ホワイトボードや紙の一覧で管理する**【Varies】 | 事務所内に掲示する形 |

> **※どの形が良いという評価はしません。**
> 【Inference】共通しているのは、**「どの件が、どこまで進んだか」を一覧にして、
> 所内の誰もが見られる状態にしている**という点です。
> 形は事務所により異なります【Varies】。

## 11-7. ⑥ 資料の授受の仕組み【Varies】

### 何のための道具か

**顧客と資料・データをやり取りするための道具です。**

### 実務にはどういう形があるか（並べて書きます）

| 形 | どういうものか | 何が動くか |
|---|---|---|
| **担当者が訪問して紙を預かる** | 【Typical】月次の訪問時に受け取る | **紙が移動する**（`07_goods.md` 7-7） |
| **顧客が来所して渡す** | 顧問先が事務所に持ってくる | 紙が移動する |
| **郵送・宅配** | 紙を送る | 紙が移動する |
| **電子メールに添付する**【Varies】 | データを送る | データが動く |
| **共有フォルダ・クラウドの仕組みに置く**【Varies】 | 顧客がデータを置き、事務所が取りに行く | データが動く |
| **証憑の読み取りの仕組みを使う**【Varies】 | 紙をスキャンして画像・データにする | データが動く。**原本は顧客の手元に残る場合がある** |
| **金融機関のデータ連携**【Varies】 | 通帳の入出金データを直接取り込む | 通帳のコピーを預からない形になる |

（`05_departments.md` ②M「証憑の電子化・読み取りの仕組み」「金融機関のデータ連携」
「ファイル共有・受け渡しの仕組み」）

### ★紙の資料で受け渡している顧問先もあります（価値判断抜きの記述）

【Varies】受渡しの形は、**顧問先ごとに異なります。**

- 【Typical】紙の領収書を箱にまとめて持ってくる顧問先があります。
- 【Typical】通帳のコピーを毎月郵送する顧問先があります。
- 【Typical】データで送ってくる顧問先があります。
- 【Varies】**同じ事務所の中で、顧問先ごとに形が違うことも一般的です。**

> **なぜ形が統一されないのか（構造の説明です。評価ではありません）**
> 【Inference】受渡しの形を決めているのは、主に**顧客側の事情**です。
> 顧客が使っている道具、顧客の担当者の慣れ、顧客の事業の形によって変わります。
> `06_people.md` 6-2 ② のとおり、**顧客は事務所の業務プロセスの一部に組み込まれています。**
> 事務所が一方的に形を決められる部分ではありません。
>
> **本資料は、どの形が良い・悪いとは書きません。**
> **紙で運用していることを「遅れている」とも書きません**（`common/methodology.md` §5）。

### 形が変わっても消えない論点

| 論点 | 紙のとき | データのとき |
|---|---|---|
| 何を受け取ったかの記録 | **預り証** | 受信の記録・ファイル一覧【Varies】 |
| 抜けが無いかの確認 | 枚数・月・口座を数える | 同じく月・口座・件数を照合する |
| **秘密の管理** | 施錠書庫 | アクセスの管理 |
| **根拠となる義務** | 【Fact】税理士法第38条／民法第644条 | **同じ**（`09_information.md` 9-5） |

> **★道具が変わっても、義務は変わりません。**

## 11-8. ⑦ 事務所自身の会計・請求管理

### 何のための道具か

**事務所自身の請求・入金・経費・給与を管理する道具です。**

> **★他人の経理を見ている事務所でも、自分の経理は別に必要です**
> （`03_company-structure.md` 3-4 ⑥）

| 機能 | 何のためか | 対応する業務 |
|---|---|---|
| **顧問契約の登録・報酬マスタ** | 毎月いくら請求するかの元を持つ | `05_departments.md` ⑥-1 |
| **請求書の発行**（月次） | 【Example】120件分の顧問料を毎月請求する | ⑥-2 |
| 決算料・スポット報酬の請求 | 発生のつど請求する | ⑥-3 |
| **入金の確認・消込** | 誰から入って、誰から入っていないかを見る | ⑥-4 |
| 未入金の一覧 | 督促の対象を把握する | ⑥-5 |
| 事務所自身の記帳・決算 | 事務所も納税者である | ⑥-6／⑥-7 |
| 職員の給与計算・年末調整 | 事務所も使用者である | ⑥-8 |

> **★「120件に毎月請求する」という作業量**
> 【Inference】顧問料は毎月発生します（`08_money.md` 8-1 ①）。
> 【Example】120件の顧問先があれば、**毎月120件の請求と、120件の入金確認**が発生します。
> これは事務所の売上の大小にかかわらず、件数に比例して発生する作業です。

## 11-9. ⑧ スケジュール管理・グループウェア

### 何のための道具か

**誰がいつどこにいるか、誰が何を抱えているかを、所内で共有するための道具です。**

| 何を共有するか | なぜ必要か |
|---|---|
| **訪問の予定** | 【Typical】担当者は月次で顧問先を訪問する。事務所に電話が来たとき、誰がどこにいるか分からないと対応できない |
| **期限の一覧** | 【Fact】期限は制度で決まっている（法人税法第74条第1項ほか）。顧問先ごとに決算月が違う |
| **所内の連絡** | 税制改正・法改正の共有（`06_people.md` 6-1 ⑥） |
| **不在・休暇の予定** | 【Inference】繁忙期の人の配置を決めるため |

### 実務上どういう形があるか【Varies】

| 形 | どういうものか |
|---|---|
| グループウェア | 予定表・掲示板・ファイル共有をまとめて使う |
| 表計算ソフトの一覧【Typical】 | 月間の予定を1枚の表にする |
| ホワイトボード【Varies】 | 事務所内に掲示する |
| 電子メール・チャット【Varies】 | 所内の連絡に使う |

（`05_departments.md` ①M「グループウェア・スケジュール共有」）

## 11-10. 道具どうしのつながり（データはどこからどこへ流れるか）

```
  顧客の資料（紙／データ）
        │
        ▼
  ┌────────────┐
  │ ① 会計ソフト  │  仕訳 → 総勘定元帳 → 試算表 → 決算書
  └──────┬─────┘
         │ 決算書のデータ
         ▼
  ┌────────────┐
  │ ② 申告書作成  │  税額計算 → 申告書の様式 → 申告データ
  └──────┬─────┘
         │ 申告データ
         ▼
  ┌────────────┐      送信      ┌──────────────┐
  │ ③ 電子申告    │───────────▶│ e-Tax／eLTAX   │
  │              │◀───────────│                │
  └────────────┘   受信通知    └──────────────┘

  ┌────────────┐  給与データ  ┌────────────┐
  │ ④ 給与計算    │───────────▶│ ① 会計ソフト  │（給与の仕訳）
  └────────────┘             └────────────┘
         │ 源泉徴収の情報
         ▼
    納付書・年末調整（③へ／顧客へ）

  ┌────────────┐
  │ ⑤ 進捗管理    │◀── ①②③の状況を人が入力する場合が多い【Varies】
  └────────────┘

  ┌────────────┐
  │ ⑦ 事務所会計  │◀── 顧問契約の情報（`09_information.md` ③契約情報）
  └────────────┘
```

### つながりの中で、つなぎ目が人手になる場所【Varies】

| つなぎ目 | どうつながるか |
|---|---|
| 顧客の資料 → ①会計ソフト | 【Varies】人が入力する形／読み取りの仕組みを使う形／顧客が入力する形 |
| ①会計ソフト → ②申告書作成ソフト | 【Varies】同じ提供元の製品なら連動する場合がある。別ならデータの受渡しが必要 |
| ②申告書作成 → ③電子申告 | 【Typical】申告データとして受け渡される |
| ①②③の状況 → ⑤進捗管理 | 【Varies】人が入力する形が一般的 |

> **※本資料は、つなぎ目を減らすべきだ、といった提案をしません。**
> 【Inference】**つなぎ目がどこにあるかを知ること**が、業務の流れを理解するうえで必要だから書いています。

## 11-11. 社労士事務所で使われる道具（【Example】Y社会保険労務士事務所）

**★扱う手続が違うため、道具も違います。**

| システム種別 | 何のための道具か |
|---|---|
| **社会保険・労働保険の手続ソフト** | 資格取得届・喪失届・算定基礎届などの様式を作る |
| **電子申請の仕組み** | 年金事務所・労働基準監督署・ハローワークへ電子的に届け出る【Varies】 |
| **給与計算ソフト** | 【Typical】受託している場合の中心的な道具 |
| **勤怠管理の仕組み**【Varies】 | 顧客の勤怠データを受け取る／確認する |
| **就業規則の作成支援**【Varies】 | 規程の作成に使う |
| 顧客管理・進捗管理【Varies】 | 顧問先ごとの手続の進捗を見る |
| 事務所自身の会計・請求管理 | 事務所の経理 |

> **★提出先が違えば、仕組みも違います**
> 税理士事務所：**e-Tax（国税）／eLTAX（地方税）**
> 社労士事務所：**年金事務所・労働基準監督署・ハローワークへの電子申請**【Varies】
>
> 【Inference】根拠となる法律が違うため（`06_people.md` 6-3）、
> 提出先も、様式も、期限も、使う道具も別々になります。

## 11-12. 道具が使えなくなると何が起きるか（構造の記述）

> **※これは「備えるべきだ」という提案ではありません。**
> **道具と業務の依存関係を示すための記述です。**

| 止まるもの | 何が起きるか | なぜ |
|---|---|---|
| **会計ソフト** | 仕訳の入力・試算表の作成が止まる | 【Inference】月次業務の中心の道具のため |
| **申告書作成ソフト**（更新されない） | 当年の様式の申告書が作れない | 【Inference】税制改正で様式・計算が変わるため |
| **電子申告の仕組み** | 申告の送信ができない | 【Fact】期限は動かない（法人税法第74条第1項ほか） |
| **進捗管理** | どの件がどこまで進んだか分からなくなる | 【Example】120件を記憶では管理できない |
| **事務所会計・請求管理** | 請求・入金確認ができない | 【Example】毎月120件の請求が発生する |

> **★期限が動かないことが、道具への依存を強くしています**
> 【Inference】他の業界なら「今日できなければ明日やる」で済む場面があります。
> この業界では、**期限のある業務については、それができません**
> （【Fact】法人税法第74条第1項、所得税法第120条第1項、消費税法第45条第1項）。

## 11-13. まとめ：この章で押さえるべき6点

1. **道具は8種類で整理できる**——①会計ソフト ②申告書作成ソフト ③電子申告の仕組み（e-Tax／eLTAX）
   ④給与計算ソフト【Varies】 ⑤顧客管理・進捗管理【Varies】 ⑥資料の授受の仕組み【Varies】
   ⑦事務所自身の会計・請求管理 ⑧スケジュール管理。
2. **中心は会計ソフト。** 仕訳帳・総勘定元帳・試算表・決算書は、すべてこの道具から出力される。
3. **申告書作成ソフトは、税制改正への対応（更新）が業務の前提になっている。**
   更新が無ければ当年の様式の申告書が作れない。
4. **電子申告は有資格者の業務として置かれている。**
   【Fact】税理士法第30条・第33条第1項。**受信通知が期限内提出の記録**になる。
5. **資料の授受の形は顧問先ごとに異なる。紙の受渡しも、データの受渡しもある。**【Varies】
   **形を決めているのは主に顧客側の事情であり、本資料はどちらが良いとも書かない。**
6. **道具が変わっても、守秘義務と預り物の管理の義務は変わらない。**
   【Fact】税理士法第38条／民法第644条・第646条第1項。

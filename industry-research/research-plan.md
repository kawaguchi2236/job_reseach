# research-plan.md — 実行計画

作成日：2026-09-16

## 1. 前提（ユーザー確認済み）

- **対象業界数：12**（プロンプト例示の12業界すべて）
- **深度：フル仕様**（1業界あたり20ファイル＋スライド原稿＋画像プロンプト＋出典＋QA）
- 対象：**日本国内の中小企業**
- 目的：**業界・業務理解の教科書**（DX/AI/システム提案は対象外）

## 2. 合理的前提として置いた設計判断（ユーザー確認なしで決定）

| 論点 | 決定 | 理由 |
|---|---|---|
| フォルダ構成 | プロンプト §47 の推奨構造をそのまま採用 | 指定どおり |
| 業界フォルダ名 | 英語スネークケース単語（manufacturing 等） | パス互換性・可搬性 |
| 実行単位 | 4業界×3バッチ | 一度に12業界並列は重複調査と品質低下を招く |
| 1業界あたりのエージェント数 | 6（基盤1／本体2／表現1／QA1／予備1） | 依存関係のある部分を直列、独立部分を並列に |
| 画像点数 | 1業界あたり10〜15点 | 全スライドに画像を付けない方針（§34） |
| 用語集の規模 | 1業界60語以上 | 「業界関係者と会話できる」水準の下限として設定 |
| スライド枚数 | 35〜50枚 | 目安30〜45枚＋「削るより理解優先」の方針 |

## 4. バッチ構成

| バッチ | 業界 | 狙い |
|---|---|---|
| **Batch 1** | 製造業・建設業・卸売業・小売業 | モノと商流が明快な基幹4業界。ここでフォーマットを確立 |
| **Batch 2** | 運輸物流・飲食・宿泊・不動産 | オペレーション／店舗／仲介型。モノの流れの扱いが異なる群 |
| **Batch 3** | 医療・介護福祉・情報通信・専門サービス | 制度・報酬体系・無形役務が中心の群 |

## 5. 1業界あたりの実行フェーズ（依存関係）

```
Phase A  基盤エージェント（1体）
         01_overview / 02_industry-structure / 03_company-structure / 04_end-to-end-process
         ＋ 19_sources（初版）
         → ここで「モデル企業」と「全社フロー」を確定させ、以降の全ファイルの土台にする
                │
                ├─────────────┬─────────────
                ▼             ▼
Phase B-1  部署別エージェント   Phase B-2  横断エージェント
         05_departments      06_people / 07_goods / 08_money / 09_information
         （A〜O 15項目・      10_documents / 11_systems / 12_business-model
          業務一覧表・        13_periodic-work / 14_kpi / 15_rules-customs
          部署間連携）         16_glossary
                └─────────────┬─────────────
                              ▼
Phase C  表現エージェント（1体）
         17_slides / 18_image-prompts（01〜16 をすべて読んでから設計）
                              ▼
Phase D  QAエージェント（1体・別視点）
         20_qa（ファクトチェック／矛盾検出／不足検出）＋ 19_sources 最終化
```

- Phase A は直列（後続がモデル企業に依存するため）
- Phase B-1 / B-2 は並列
- 1バッチ（4業界）では Phase A で4体、Phase B で8体、Phase C で4体、Phase D で4体を並列実行

## 6. 重複調査の回避（トークン節約）

- 全業界共通の基礎知識（商取引の基本、締め支払い、会計の基本、中小企業の定義、
  4つの流れの考え方）は `common/` に集約し、各エージェントはそれを**読む**だけで再調査しない。
- 各エージェントは**担当ファイルのみ**を書く。他業界のフォルダには一切触れない。
- 出典は業界フォルダ内 `19_sources.md` に集約し、共通出典（中小企業白書等）は
  `common/` 側に置いて各業界から参照する。

## 7. 品質確認方法（QA）

Phase D の QA エージェントは、調査エージェントとは**別の視点**で以下をチェックする。

- 根拠のない断定がないか
- 大企業特有の業務を「中小企業一般」としていないか
- 業界固有と会社固有を混同していないか
- 古い制度・古い年度の統計を使っていないか
- 数値に年度と出典があるか
- 業務フローに欠落がないか
- 部署間で矛盾がないか（A部署のアウトプット＝B部署のインプットになっているか）
- インプット／アウトプットの不整合がないか
- カネの流れに矛盾がないか
- 専門用語の誤用がないか
- 初心者に説明不足な箇所がないか
- **対象外（DX・AI・提案・評価）が混入していないか** ← 最重要チェック
- 完成条件（methodology §12）の34項目がすべて存在するか
- 最終品質基準10問（methodology §13）に答えられるか

QA結果は `20_qa.md` に、指摘と修正状況を対で記録する。

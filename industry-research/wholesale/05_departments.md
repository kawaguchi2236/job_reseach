## 5-0. この章の読み方

### 5-0-1. 15項目（A〜O）とは何か

| 記号 | 項目 | 何を読み取るための項目か |
|---|---|---|
| **A** | 部署・機能名 | 一般的に何と呼ばれているか。会社が変わっても通じる言い方 |
| **B** | 存在目的 | 「何のためにこの仕事があるのか」。これが分かると個々の業務の理由が分かる |
| **C** | 担当者 | どんな役職・担当がいるか |
| **D** | 主な業務一覧 | この機能がやっている仕事を漏れなく並べたもの |
| **E** | **業務詳細** | **この章の心臓部。** Dの各業務を7つの観点で分解したもの |
| **F** | 業務頻度 | いつ・どのくらいの頻度で起きるか |
| **G** | インプット | 仕事を始めるために必要なもの（前工程から受け取るもの） |
| **H** | アウトプット | 仕事の結果できあがるもの（後工程へ渡すもの） |
| **I** | 関係部署 | 社内で誰とやり取りするか |
| **J** | 社外関係者 | 社外で誰とやり取りするか |
| **K** | 使用帳票 | 紙・電子を問わず、扱う書類 |
| **L** | 使用データ | 扱う情報の種類 |
| **M** | 使用システム | どんな種類の仕組みを使うか（商品名の列挙が目的ではありません） |
| **N** | 使用設備・道具 | 物理的な道具・設備 |
| **O** | 見ている数字・KPI | この機能が日常的に追いかけている数字 |

**E（業務詳細）の7つの観点**

```
 ① 何をきっかけに始まるか  … トリガー。これがないと業務は始まらない
 ② 誰が行うか              … 実行者
 ③ 何を確認するか          … 手を動かす前に見るもの
 ④ 何をするか              … 実際の作業
 ⑤ 何を判断するか          … 人が決めなければならないこと
 ⑥ 誰と連携するか          … 1人で完結しない相手
 ⑦ 最終的に何が出来上がるか … 成果物。次の誰かのインプットになる
```

そして各業務に **「なぜこの業務が必要なのか」** を必ず添えます。
作業手順だけを覚えても、なぜそれをするのかが分からないと、
例外が起きたときに何を優先すべきか判断できないからです。【Inference】

### 5-0-2. 大前提 ——「部署」ではなく「機能」で読む

中小卸売業では、次のことが同時に成り立ちます。

> - **その仕事（機能）は必ず存在する**
> - **その仕事だけを担当する独立した「○○部」が存在するとは限らない**
> - **1人が複数の機能を兼務しているのが普通**

そのため、以下の各節の冒頭には必ず
**「独立した○○部があるとは限らない」**という注記を置いています。
「A社には在庫管理部がないから在庫管理をしていない」ということはありません。
**誰かが必ずやっています。** その誰かを探すのが、会社を理解する第一歩です。【Typical】

### 5-0-3. 頻度の書き方

頻度は本プロジェクト共通の語彙のみを使います。

```
 常時 / 日次 / 週次 / 月次 / 四半期 / 半期 / 年次
 案件発生時 / 問い合わせ時 / 受注時 / 発注時 / 納品時 / 請求時 / 入金時
 トラブル発生時 / 法定・契約上のタイミング / その他
```

「毎週月曜日に行う」のような、根拠のない曜日・日付レベルの具体化はしていません。
実際のタイミングは会社ごとに異なるためです【Varies】。

### 5-0-4. 業種による違いの扱い

卸売業は扱う商品によって仕事の中身が大きく変わります。
そのため各機能の末尾に **「業種による違い（Level 2）」** の節を置き、
**食品卸／建材卸／機械・工具卸／医薬品卸／アパレル卸** の5業種で
どこがどう変わるかを示しています。

特に差が大きいのは次の3点です。【Typical】

| 差が大きい論点 | どの業種で顕著か |
|---|---|
| **賞味期限・使用期限の管理** | 食品卸・医薬品卸では必須。機械・工具卸ではほぼ不要 |
| **ロット（製造単位）の追跡** | 医薬品卸では法令上の要請。食品卸でも回収対応のために必要 |
| **規制・許認可への対応** | 医薬品卸（薬機法）・食品卸（食品衛生法・酒税法）で重い |

## 5-1. 営業機能

---

### A. 部署・機能名

| 項目 | 内容 |
|---|---|
| **機能名（本資料の呼び方）** | 営業機能 |
| **一般的な部署名** | 営業部、営業課、販売部、営業一課／二課、外商部 |
| **担当者の一般的な呼び方** | 営業、営業担当、セールス、**ルートセールス**、外勤、ルートマン、MS（医薬品卸の場合） |
| **モデル企業での呼称** | 営業部（12名） |

> **【Varies】** 独立した営業部があるとは限りません。
> 従業員10名以下の卸売会社では、**社長と数名の営業担当だけ**という形が珍しくありません。
> それでも「得意先を訪問して注文と情報を取ってくる」という**営業機能そのものは必ず存在します**。
> 逆に、営業担当が配送も集金も兼ねる（`03_company-structure.md` §3-3-1 参照）ことも多くあります。

**用語**
**ルートセールス**
→ **決まった得意先を、決まった周期で繰り返し訪問する営業のやり方**のこと。
　「ルート（route＝道すじ）」を回るように、同じ相手を定期的に訪ねます。
→ 実務例：営業担当が「月曜はこの5軒、火曜はこの6軒」というように訪問先を組み、
　毎週または隔週で同じ得意先を回る。新しい客を探すのではなく、
　**既にある取引を維持し、少しずつ増やす**のが仕事の中心になります。

**用語**
**新規開拓（しんきかいたく）**
→ まだ取引のない相手に働きかけて、新しく取引を始めること。
→ 実務例：新しく開店する飲食店に営業をかけ、食材の取引口座を開いてもらう。

---

### B. 存在目的

> **得意先を訪問して注文を取り、同時に「売場・現場で何が起きているか」という情報を持ち帰る。**
> 注文が来なければ、仕入も、在庫も、物流も、請求も、何ひとつ始まりません。
> 営業機能は、**会社の活動全体の入口**です。

もう少し丁寧に言うと、営業機能には3つの役割があります。【Typical】

| 役割 | 内容 | なぜ必要か |
|---|---|---|
| **① 売る** | 注文を取る、新しい商品を採用してもらう、新規の取引先を開く | これがないと売上が立たない |
| **② つなぐ** | 得意先の要望を社内に伝え、社内の事情（欠品・納期・価格）を得意先に伝える | 卸売業の取引は継続的であり、日々の調整が途切れると関係が壊れる |
| **③ 見てくる** | 売場の状況、競合の動き、得意先の経営状況を見て帰る | 仕入判断・与信判断の材料は、現場にしかない |

> **【Inference】** ③を軽視すると、「注文は取れているのに得意先が急に倒産した」
> 「他社に棚を取られていたことに気づかなかった」という事態が起きます。
> 卸売業の営業が**足で稼ぐ仕事**と言われるのは、この情報収集の比重が大きいためです。

---

### C. 担当者

| 役職・担当 | 主な役割 |
|---|---|
| **営業部長** | 営業全体の統括、予算の配分と進捗管理、重要得意先の担当（中小企業では自分も得意先を持つ**プレイングマネージャー**が普通）【Typical】 |
| **営業担当（ルートセールス）** | 割り当てられた得意先を定期訪問し、受注・提案・回収・クレーム対応を行う |
| **チームリーダー／主任** | 業態別（量販チーム、業務用チーム等）のとりまとめ |
| **新規開拓担当** | 新しい得意先を開く役割。専任を置かず全員が兼ねる会社も多い【Varies】 |
| **社長・役員** | 主要得意先の経営層との折衝、取引条件の最終決定 |

> **【Example】** モデル企業A食品商事の営業部12名の内訳
> ・営業部長 1名（プレイングマネージャー。大口得意先3社を自分で担当）
> ・量販チーム 4名（食品スーパー約25社を担当）
> ・業務用チーム 5名（飲食店・給食施設約230社を担当）
> ・新規・地域チーム 2名（個人商店・酒販店の維持と新規開拓）
> 営業1人あたりの担当得意先は約32社。

### E. 業務詳細

---

#### E-1. ルートセールス（既存得意先の定期訪問）

| 観点 | 内容 |
|---|---|
| **① きっかけ** | あらかじめ組んである訪問計画（訪問ルート・訪問周期）。得意先からの呼び出し。前回訪問時の宿題 |
| **② 誰が** | 営業担当（得意先ごとに担当が固定されているのが一般的）【Typical】 |
| **③ 何を確認するか** | 前回の宿題（見積回答、サンプル手配、クレームの結果）／自社商品の売場の状態／在庫の残り／得意先の担当者が変わっていないか／請求・入金の状況 |
| **④ 何をするか** | 訪問し、担当者（店長、バイヤー、料理長、資材担当など）と面談する。売場・厨房・倉庫を見る。注文を聞く。新商品・販促の話をする。宿題を持ち帰る |
| **⑤ 何を判断するか** | 今日この得意先で一番話すべきことは何か／提案するタイミングか、聞くタイミングか／気になる兆候（支払いの渋り、他社商品の増加、来客数の減少）があるか |
| **⑥ 誰と連携するか** | 受注・業務機能（持ち帰った注文の入力依頼）／仕入・調達機能（新商品・価格の相談）／与信・債権管理機能（気になる情報の報告）／物流・倉庫機能（納品時間・置き場所の調整） |
| **⑦ 出来上がるもの** | **受注情報**、訪問記録（営業日報）、得意先情報の更新、宿題リスト |

**なぜこの業務が必要なのか**

卸売業の取引は、1回売って終わりではなく**毎日・毎週続きます**。
続く取引だからこそ、放っておくと少しずつ他社に置き換えられていきます。
得意先の側から見れば、「うちに来る卸は1社ではない」のが普通だからです。【Typical】

また、得意先は**注文を全部言ってくれるわけではありません**。
売場を見て「この商品、棚が空いていますね」と気づいて初めて注文になるものがあります。
これが「訪問しないと売上が落ちる」と言われる理由です。【Inference】

> **【Example】**（説明用の架空例）
> 営業担当がB飲食店を訪問すると、厨房の棚に置かれていた自社の業務用ソースが、
> 別メーカーの商品に変わっていた。料理長に聞くと「先週切らしてしまい、
> 近くの業務用スーパーで買った」とのこと。
> 営業は発注周期を見直す提案をし、次回から在庫が少なくなる前に声をかけることを約束した。
> **訪問していなければ、この置き換わりに気づかないまま失注していた可能性がある。**

---

#### E-2. 売場・在庫の確認と補充提案

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 定期訪問時。得意先からの「何が足りないか見てほしい」という依頼 |
| **② 誰が** | 営業担当 |
| **③ 何を確認するか** | 棚のどこが空いているか（**欠品棚**）／在庫が積み上がっている商品はないか（売れ残り）／自社商品と他社商品の並び方／販促物（POP、のぼり）が掲示されているか／賞味期限が近い商品が売場に残っていないか |
| **④ 何をするか** | 売場・バックヤード・厨房の在庫を目で見て数える。不足分を補充数量として提案する。得意先の担当者に確認して注文にする |
| **⑤ 何を判断するか** | 何をいくつ補充すべきか（前回訪問からの販売ペースから逆算）／売れていない商品をどうするか（売価変更の提案か、いったん取扱をやめるか）／得意先に無理な在庫を持たせていないか |
| **⑥ 誰と連携するか** | 受注・業務機能（注文の入力）／在庫管理機能（自社在庫の残数確認）／仕入・調達機能（売れ行きの情報共有） |
| **⑦ 出来上がるもの** | 補充の**受注情報**、売場の状況記録、滞留している得意先在庫の情報 |

**なぜこの業務が必要なのか**

得意先（特に小規模な飲食店・個人商店）は、**発注を専門にする担当者がいません**。
店主が調理や接客の合間に発注しているため、切らしてから気づくことが起こります。
卸売業者が売場を見て補充を提案するのは、**得意先の発注業務の一部を肩代わりしている**
ことになります。これが `01_overview.md` で扱った「情報提供機能」の実際の姿です。【Typical】

同時に、得意先に在庫を持たせすぎると、次の注文が止まります。
**適量を提案することが、結果として自社の継続的な売上につながります。**【Inference】

---

#### E-3. 商品提案（新商品の導入提案）

| 観点 | 内容 |
|---|---|
| **① きっかけ** | メーカーの新商品発表／仕入・調達機能（バイヤー）からの推奨商品の連絡／得意先からの「何か新しいものはないか」という要望／季節の切り替わり |
| **② 誰が** | 営業担当（提案）／仕入・調達機能（商品情報・価格の提供）／メーカー担当者（同行する場合） |
| **③ 何を確認するか** | 商品の規格（内容量、入数、荷姿、温度帯、賞味期限日数）／仕切価格と想定売価／メーカーの販促支援（サンプル、什器、リベート）／得意先が既に扱っている競合商品／得意先の客層に合うか |
| **④ 何をするか** | 商品カタログ・規格書・サンプルを持って訪問する。商品の特徴と、その得意先にとっての使いどころを説明する。試食・試用を依頼する。採用された場合は初回発注数量を決める |
| **⑤ 何を判断するか** | この得意先に合う商品か／今提案すべきか（次の棚替えのタイミングを待つか）／既存商品を置き換える提案か、追加の提案か／初回はいくつ入れるのが適量か |
| **⑥ 誰と連携するか** | 仕入・調達機能（商品情報、価格、在庫確保）／受注・業務機能（商品マスタ・価格マスタの登録依頼）／品質・衛生管理機能（規格書・表示内容の確認） |
| **⑦ 出来上がるもの** | 提案資料、サンプルの提供記録、（採用時）**新商品の初回受注**、商品マスタ登録の依頼 |

**なぜこの業務が必要なのか**

卸売業者の取扱商品は、放っておくと**古い商品ばかりになります**。
メーカーは毎年新商品を出し、消費者の好みは変わります。
新しい商品を売場に入れ続けなければ、得意先の売場が古くなり、
その結果として得意先の売上が落ち、最終的に自社の売上も落ちます。【Inference】

また、卸売業者にとって新商品の提案は**粗利を確保する手段**でもあります。
定番商品は価格が知れ渡っており値引き圧力が強い一方、
新商品は比較対象が少ないため、相対的に粗利を確保しやすい傾向があります。【Typical】

---

#### E-4. 棚割提案・売場づくりの提案

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 得意先の棚替え（売場のレイアウト変更）の時期／新店舗の開店／得意先からの相談／メーカーからの棚割提案の持ち込み |
| **② 誰が** | 営業担当／メーカーの営業担当（資料作成の支援）／仕入・調達機能（商品構成の助言） |
| **③ 何を確認するか** | 現在の売場の寸法・段数・フェース数（商品が正面に何個並んでいるか）／各商品の販売実績／得意先の売場方針／競合店の売場 |
| **④ 何をするか** | 「どの商品を、どの位置に、いくつ並べるか」の案（**棚割表**）を作って提案する。採用されれば、切り替え日に合わせて商品を手配し、必要なら店頭での陳列作業も手伝う |
| **⑤ 何を判断するか** | 何を残し、何を落とすか／自社の取扱商品をどこに配置するか／得意先の売上を伸ばす提案になっているか（自社商品を押し込むだけの提案になっていないか） |
| **⑥ 誰と連携するか** | 仕入・調達機能（棚割に必要な商品の在庫確保）／受注・業務機能（切替時の受注・納品段取り）／物流・倉庫機能（切替日に合わせた納品） |
| **⑦ 出来上がるもの** | **棚割表（棚割提案書）**、切替時の受注情報、（旧商品の）返品・引取の取り決め |

**用語**
**棚割（たなわり）**
→ 小売店の棚の、**どの位置にどの商品を何個並べるか**を決めた計画のこと。
　「棚割表」という図で表します。
→ 実務例：「調味料の棚、上から2段目の左3フェースを自社の醤油にしてもらった」。
　棚の位置と面積が、そのまま売れる量に直結するため、卸・メーカーにとって重要な交渉事になります。

**用語**
**フェース**
→ 商品が売場の正面（消費者から見える面）に何個並んでいるかの数。
→ 実務例：「2フェース」＝同じ商品が横に2個並んでいる状態。

**なぜこの業務が必要なのか**

得意先（特に中小のスーパーや個人商店）は、**売場づくりの専門知識を持つ人員が限られています**。
一方、卸売業者は同じ商品を何十軒もの店に納めているため、
「どう並べるとどう売れたか」の情報が自然に集まります。
その情報を提案の形で戻すことが、`01_overview.md` の「情報提供機能」の中身です。【Typical】

> **【Varies】** 棚割提案がどれだけ重要かは業種によって大きく異なります。
> 食品卸・日用品卸では中心的な業務のひとつですが、
> 建材卸・機械工具卸では「棚」そのものが存在しない取引が多く、
> 代わりに**現場での使い方の提案**が同じ役割を果たします。

#### E-5. 売価の決定と価格交渉【卸売業の核心】

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 新規取引の開始／新商品の導入／得意先からの値下げ要請／仕入価格の改定（メーカーの価格改定）／特売の引合／競合他社の価格提示 |
| **② 誰が** | 営業担当（一次交渉）／営業部長（一定金額・一定値引率を超える場合の承認）／仕入・調達機能（仕入価格と粗利の確認）／社長（大口・重要案件の最終決定）【Varies】 |
| **③ 何を確認するか** | **その商品の仕切価格（自社の仕入価格）**／現在その得意先に出している売価／他の得意先に出している売価との整合／目標粗利率／リベートの有無と条件／数量と継続性／競合他社の提示価格 |
| **④ 何をするか** | 粗利を計算したうえで提示価格を決める。得意先と交渉する。社内の承認が必要な水準なら上長・商品部に相談する。合意したら価格マスタへの登録を依頼する |
| **⑤ 何を判断するか** | いくらで出すか／値下げを受けるか、断るか／数量とセットで条件を出すか（「50ケース以上ならこの価格」）／粗利が薄くても受けるべき取引か（他商品との抱き合わせ、棚の確保、新規取引の足がかり）／**他の得意先に知られたときに説明できる価格か** |
| **⑥ 誰と連携するか** | 仕入・調達機能（仕切価格の確認、メーカーへの特別価格の依頼）／受注・業務機能（価格マスタへの登録）／経理・財務機能（粗利実績の確認）／経営機能（重要案件の判断） |
| **⑦ 出来上がるもの** | **得意先別・商品別の売価**、見積書、価格マスタ登録の依頼、（合意内容の）記録 |

**なぜこの業務が必要なのか ——「同じ商品でも得意先ごとに価格が違う」**

ここが卸売業を理解するうえで**最も重要な点のひとつ**です。【Typical】

卸売業では、**まったく同じ商品でも、得意先によって売る価格が違います。**

```
 【同じ商品（醤油1Lケース）の売価の違い】【Example】（説明用の架空例）

  自社の仕入価格（仕切価格）      2,400円
       │
       ├─ Bスーパー（月100ケース買う）      2,650円   粗利 250円（約9.4%）
       ├─ C飲食店（月5ケース買う）          2,850円   粗利 450円（約15.8%）
       ├─ D個人商店（月2ケース買う）        2,950円   粗利 550円（約18.6%）
       └─ E同業卸（月300ケース買う）        2,520円   粗利 120円（約4.8%）
```

**なぜ違うのか**【Typical】

| 理由 | 説明 |
|---|---|
| **数量が違う** | まとめて買う相手ほど1件あたりの手間が減るため、価格を下げやすい |
| **配送の手間が違う** | 1か所に大量に届けるのと、少量を何軒にも届けるのではコストが違う |
| **支払条件が違う** | 現金で早く払う相手と、サイトの長い手形で払う相手では、資金の負担が違う |
| **取引の歴史が違う** | 長年の取引の積み重ねで決まっている価格がある |
| **競合との関係が違う** | 他社が食い込もうとしている得意先には、守るための価格を出すことがある |

**この仕組みが生む実務上の帰結**

1. **価格マスタが膨大になる**
   得意先380社 × 商品4,500SKU の組み合わせすべてに価格があるわけではありませんが、
   実際に取引のある組み合わせだけでも数万件の価格データが存在します。【Example】
   これを登録・保守するのが受注・業務機能の仕事です（後述 §5-2）。

2. **価格が外に漏れると問題になる**
   得意先Dが「Bスーパーは2,650円で買っているらしい」と知ると、
   「うちにも同じ価格で出せ」という交渉になります。
   そのため、**どの得意先にいくらで出しているかは社内でも慎重に扱われます**。【Typical】

3. **粗利率は商品ではなく「得意先×商品」で決まる**
   「この商品の粗利率は10%」という言い方は、卸売業では正確ではありません。
   同じ商品でも得意先によって粗利率が違うからです。【Inference】

> **【Fact】** なお、メーカーが卸売業者に対して「この価格で売れ」と販売価格を拘束する行為は、
> **再販売価格維持行為**として、原則として不公正な取引方法に該当し違法とされています
> （出典：流通・取引慣行に関する独占禁止法上の指針／公正取引委員会）。
> メーカーが「希望小売価格」「建値」を**示すこと**と、その価格で売るよう**拘束すること**は別です。
> （詳細は `02_industry-structure.md` §11-6-1 および `15_rules-customs.md` で扱います）

#### E-6. 販促提案（特売・企画の提案と実行支援）

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 得意先の販促計画（チラシ、催事、セール）／メーカーの販促企画の案内／季節行事（年末年始、行楽期、鍋物の季節など）／仕入・調達機能からの在庫処分の要請 |
| **② 誰が** | 営業担当／仕入・調達機能（価格と数量の確保）／メーカー担当者（同行・販促費の提供） |
| **③ 何を確認するか** | 得意先の販促スケジュール／特売に必要な数量と納品日／特売用の仕切価格をメーカーから引き出せるか／自社の在庫と入荷予定／販促物（POP、試食品）の手配可否 |
| **④ 何をするか** | 特売の企画を提案する。数量・価格・納品日を詰める。社内（商品部）に数量確保を依頼する。当日の売場応援・試食販売を行うこともある |
| **⑤ 何を判断するか** | 数量を確保できるか（欠品したら得意先の販促そのものが失敗する）／特売価格で粗利が残るか／販促費・リベートを含めた採算はどうか／売れ残った場合に誰が負担するか |
| **⑥ 誰と連携するか** | 仕入・調達機能（特売仕切の交渉、まとめ発注）／在庫管理機能（引当の確保）／物流・倉庫機能（大量納品の段取り、納品時間）／受注・業務機能（特売価格の登録） |
| **⑦ 出来上がるもの** | 特売の企画書、特売の**受注情報**、特売価格の登録依頼、販促物の手配記録 |

**なぜこの業務が必要なのか**

特売は、**普段の何倍もの数量が一度に動く仕事**です。【Typical】
得意先にとっては集客の手段であり、卸売業者にとっては
「まとめて仕入れることで仕切価格を下げられる」機会でもあります。

同時に、**失敗したときの影響が大きい仕事**でもあります。
チラシに載った商品が納品されなければ、得意先は店頭で客に謝ることになります。
そのため、特売の受注は「数量の確保」が受注そのものより重い意味を持ちます。【Inference】

> **【Example】**（`04_end-to-end-process.md` §4-4 の例と同じ構造）
> Bスーパーの「鍋つゆ処分特売」で200ケースの引合。
> 自社在庫は33ケースしかないため、メーカーへ170ケースを追加発注。
> 100ケース以上の一括発注により特売仕切が適用され、仕入単価が下がった。
> **「大量に売る話」と「大量に仕入れる話」が同時に動く**のが特売の特徴です。

#### E-7. 受注の聞き取りと社内への引き継ぎ

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 訪問時に得意先から口頭で注文を受ける／携帯電話に直接注文の連絡が入る |
| **② 誰が** | 営業担当 |
| **③ 何を確認するか** | 商品名の特定（類似商品と取り違えていないか）／数量の単位（ケースか、ボールか、バラか）／希望納品日と時間帯／納品先（本店か、支店か、センターか）／適用する価格（特売価格か通常価格か） |
| **④ 何をするか** | 注文内容をメモまたは携帯端末に記録する。その場で在庫を確認する場合は内勤に電話する。帰社後（または移動中に）内勤へ引き継ぐ。会社によっては営業自身が端末から入力する【Varies】 |
| **⑤ 何を判断するか** | その場で受けてよい注文か（与信、納期、数量の面で）／内勤に急いで伝えるべきか（当日の受注締切に間に合うか）／在庫を確認してから返事すべきか |
| **⑥ 誰と連携するか** | 受注・業務機能（注文の入力）／在庫管理機能（在庫確認） |
| **⑦ 出来上がるもの** | **注文の記録**（受注メモ、端末入力データ）、内勤への引き継ぎ |

**なぜこの業務が必要なのか**

営業が受けた注文は、**そのままでは出荷できません。**
販売管理システムに入力されて初めて、在庫が引き当てられ、
ピッキングリストが出て、納品書が作られ、請求の対象になります。

ここで引き継ぎが漏れると、**得意先は「注文した」と思っているのに商品が届かない**
という、卸売業で最も信用を失う事態が起きます。【Typical】

**ここで起きやすい間違い**【Typical】
- **ケースとバラの取り違え**：「醤油10」が10ケースなのか10本なのか
- **類似商品の取り違え**：「濃口醤油1L」と「濃口醤油1L（減塩）」
- **納品日の取り違え**：「あした」が翌日なのか翌営業日なのか
- **受注締切に間に合わない**：帰社してから伝えたのでは、当日出荷に乗らない

#### E-8. 欠品連絡・代替提案・納期調整の得意先対応

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 受注・業務機能からの欠品連絡（S3の引当不足）／仕入先からの入荷遅延の連絡／メーカーの生産終了・出荷調整の通知 |
| **② 誰が** | 営業担当（得意先との交渉）／受注・業務機能（欠品の発見と情報提供）／仕入・調達機能（代替品・緊急調達の手配） |
| **③ 何を確認するか** | 何が、いくつ足りないのか／入荷予定はいつか／代わりになる商品が自社にあるか（同等品、別メーカー品、別規格品）／得意先がその商品をいつまでに必要としているか（チラシ掲載品か、通常の補充か） |
| **④ 何をするか** | 得意先に連絡し、状況を正直に伝える。対応案（代替品・分納・後日納品・キャンセル）を提示し、相談する。合意した内容を内勤に戻す |
| **⑤ 何を判断するか** | どの対応案から提示するか／代替品の価格をどうするか（同額にするか）／緊急発注のコストを負担してでも納めるべき取引か／謝罪と説明をどの立場の人間が行うべきか（担当者か、上長か） |
| **⑥ 誰と連携するか** | 受注・業務機能（受注データの修正）／仕入・調達機能（緊急発注、代替品の手配）／物流・倉庫機能（分納・追加配送の段取り）／営業部長・経営機能（重大な欠品の場合） |
| **⑦ 出来上がるもの** | 欠品連絡の記録、**変更後の受注内容**、代替品の受注、（必要時）緊急発注の依頼 |

**なぜこの業務が必要なのか**

欠品は「売り損なった」だけでは終わりません。
**得意先の売場に穴が開き、得意先の売上も失われます。**
飲食店であれば、その日出せないメニューが出ます。【Typical】

そのため、欠品対応で問われるのは**「早く伝えたか」**と**「代案を持っていったか」**です。
納品予定の当日に何も言わずに商品が届かないのと、
前日に連絡して代替品を提案するのとでは、得意先が受ける影響がまったく違います。【Inference】

#### E-9. クレームの一次対応

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 得意先からの連絡（品違い、数量違い、破損、期限不足、品質異常、納品遅れ、請求金額の相違） |
| **② 誰が** | 営業担当（一次受付）／内容により品質・衛生管理機能、物流・倉庫機能、仕入・調達機能、経理・財務機能へ引き継ぐ |
| **③ 何を確認するか** | 何が起きたのか（事実）／いつ納品したものか／商品名・ロット・数量／現物は残っているか／得意先がすでに販売・使用してしまったか／得意先が求めている対応は何か |
| **④ 何をするか** | まず相手の話を最後まで聞き、事実を記録する。現物を確認しに行く（または回収する）。社内の該当部署に調査を依頼する。原因と対応を得意先に回答する。再発防止の内容を伝える |
| **⑤ 何を判断するか** | 原因はどこにあるか（自社の出荷ミス／輸送中の事故／仕入先の製造段階／得意先側の取扱い）／どこまで自社が負担するか／緊急性はどれくらいか（**品質異常の場合は同じロットが他の得意先にも出ている可能性がある**）／上長・経営機能に即座に報告すべき事案か |
| **⑥ 誰と連携するか** | 物流・倉庫機能（出荷記録の確認）／受注・業務機能（受注内容と伝票の確認）／仕入・調達機能（仕入先への申し入れ）／品質・衛生管理機能（品質異常時の調査・回収判断）／経理・財務機能（値引き・赤伝の処理）／経営機能（重大案件） |
| **⑦ 出来上がるもの** | **クレーム記録**、原因の特定結果、対応内容（再納品・返品受入・値引き・代替品）、（該当時）仕入先への報告、再発防止の記録 |

**なぜこの業務が必要なのか**

クレームは、**得意先が「まだ取引を続ける気がある」から言ってくる**ものです。
何も言わずに取引を減らされるほうが、卸売業者にとっては深刻です。【Inference】

さらに重要なのは、**品質異常のクレームは1件で終わらない可能性がある**ことです。
同じロットの商品は、他の得意先にも出荷されています。
そのため、営業が受けた1本の電話が、**回収（リコール）の起点**になることがあります。
「どのロットをどの得意先に何個出したか」をたどれる記録（トレーサビリティ）が
日常的に求められるのは、このためです。【Typical】

> **【Varies】** クレームの一次対応を誰がするかは会社によって異なります。
> 営業が受ける場合、内勤（受注担当）が受ける場合、
> 専用の窓口を置く場合がありますが、
> **中小卸売業では、得意先との接点である営業が最初に受けることが多くあります**。

#### E-10. 返品の受付と可否判断

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 得意先からの返品の申し出（誤発注、売れ残り、期限接近、破損、誤出荷） |
| **② 誰が** | 営業担当（受付・一次判断）／営業部長・経営機能（金額が大きい場合、契約外の返品の場合）／受注・業務機能（伝票処理）／物流・倉庫機能（現物の回収） |
| **③ 何を確認するか** | 返品理由／いつ納品したものか／現物の状態（未開封か、期限はどれだけ残っているか、外装は無傷か）／契約上の返品条件（返品可の取引か）／自社の在庫に戻せるか |
| **④ 何をするか** | 返品理由を聞き、現物を確認する。受けるかどうかを判断する。受ける場合は回収の段取りを組む（次回配送便で引き取るなど）。内勤に返品伝票（赤伝）の起票を依頼する |
| **⑤ 何を判断するか** | 返品を受けるか、断るか／全額戻すか、一部負担にするか／在庫に戻せるか、廃棄・値下げ処分にするか／誰の責任か（自社／得意先／仕入先／運送会社）／仕入先に返品交渉できる案件か |
| **⑥ 誰と連携するか** | 受注・業務機能（返品伝票の起票）／物流・倉庫機能（回収・現物の受入・検品）／在庫管理機能（在庫への戻し入れ／除外）／経理・財務機能（請求金額の調整）／仕入・調達機能（仕入先への返品） |
| **⑦ 出来上がるもの** | 返品の受付記録、**返品伝票（赤伝）の起票依頼**、回収の指示、（該当時）仕入先への返品連絡 |

**用語**
**赤伝（あかでん）／赤伝票**
→ 売上や仕入を**マイナスで計上する伝票**のこと。返品や値引きの処理に使います。
→ 実務例：10ケース納品したうち2ケースが返品されたら、2ケース分の赤伝を起こす。
　請求時には10ケース分の売上から2ケース分が差し引かれる。

**なぜこの業務が必要なのか**

返品は、**売上・在庫・請求・入金消込・仕入のすべてに同時に影響します。**【Typical】
営業が「いいですよ」と口頭で受けただけで伝票処理が漏れると、次のことが起きます。

```
 赤伝を起こし忘れると…

  ① 請求書には返品前の金額が載る → 得意先が「話が違う」と言う → 入金が止まる
  ② 帳簿在庫は減ったままなのに現物は倉庫に戻っている → 棚卸で差異が出る
  ③ 仕入先に返品できる商品だった場合、期限を過ぎて交渉できなくなる
```

つまり、**営業の1つの口頭了解が、経理と倉庫の両方に波及します。**
だから返品は「受けるかどうか」と同じくらい「伝票を確実に回すこと」が重要になります。【Inference】

> **【Fact】** 返品をめぐっては、独占禁止法上の論点もあります。
> 公正取引委員会の「大規模小売業者による納入業者との取引における特定の不公正な取引方法」
> （平成17年5月13日公正取引委員会告示第11号。通称「大規模小売業告示」）は、
> 大規模小売業者が納入業者に対して行う**不当な返品**を禁止しています
> （出典：大規模小売業者による納入業者との取引における特定の不公正な取引方法／公正取引委員会）。
> 卸売業者は大規模小売業者に対して「納入業者」の立場になることがある一方、
> 自社が仕入先に対して行う返品については**優越的地位の濫用**が問題となり得る立場にもあります。【Inference】
> （詳細は `15_rules-customs.md` で扱います）

#### E-11. 新規開拓（見込み客の発掘から口座開設まで）

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 新規出店・開業の情報（新しい飲食店、新店舗の建設）／既存得意先や取引先からの紹介／展示会・商談会での接触／メーカーからの引合の紹介／問い合わせ |
| **② 誰が** | 営業担当／営業部長（同行）／社長（規模が大きい相手の場合）／与信・債権管理機能（審査）／経営機能（取引開始の最終判断） |
| **③ 何を確認するか** | 相手の業態・規模・立地／必要な商品と量／現在どこから仕入れているか／配送できる範囲か（自社便のルートに乗るか）／希望する取引条件（締め日、支払方法）／**相手の信用状態** |
| **④ 何をするか** | 訪問して話を聞く。取扱商品を提案し、見積を出す。条件が折り合えば与信審査を依頼する。審査が通れば取引基本契約を交わし、得意先マスタに登録してもらい、初回納品につなげる |
| **⑤ 何を判断するか** | 取引する価値があるか（金額、継続性、配送効率）／配送ルートに無理なく組み込めるか／提示できる価格で粗利が残るか／**与信上、掛売にしてよい相手か（前払・現金取引にすべきか）** |
| **⑥ 誰と連携するか** | 与信・債権管理機能（信用調査、与信限度額の設定）／経営機能（取引開始の承認）／受注・業務機能（得意先マスタの新規登録、価格登録）／物流・倉庫機能（配送ルートへの組み込み）／仕入・調達機能（必要商品の手当て） |
| **⑦ 出来上がるもの** | 商談記録、見積書、**与信審査の依頼**、（成約時）取引基本契約書、**新しい取引口座（得意先マスタ）**、初回受注 |

**用語**
**取引口座（こうざ）を開く**
→ 「この会社と取引する」という社内登録を行うこと。銀行口座とは別物です。
→ 実務例：「A社にうちの口座を開けてもらった」＝A社と取引を始められるようになった。

**なぜこの業務が必要なのか**

既存の得意先は、**必ず少しずつ減っていきます。**
店の閉店、経営者の高齢化・廃業、他社への切り替え、得意先自身の倒産。【Typical】
新規開拓をしなければ、取引先数は減る一方になります。

一方で、新規開拓は**与信リスクを新たに背負う行為**でもあります。
新しい相手は取引実績がないため、支払能力の判断材料が少ない。
だから卸売業の新規開拓は、**「売れるか」と「回収できるか」を必ずセットで見ます**。【Typical】
ここが、現金でその場で決済される小売業との決定的な違いです。

#### E-12. メーカーとの同行訪問

| 観点 | 内容 |
|---|---|
| **① きっかけ** | メーカーの新商品発売／メーカーからの同行依頼／大口の商談・特売の提案／得意先からの技術的・専門的な質問／クレームの謝罪と説明 |
| **② 誰が** | 営業担当＋メーカーの営業担当（営業所長、地区担当など）／案件により営業部長・社長も同席 |
| **③ 何を確認するか** | 誰に会うか（得意先のどの立場の人か）／その日の目的（導入依頼か、価格交渉か、謝罪か）／メーカーが出せる条件（販促費、リベート、サンプル、什器）／自社の立場（特約店か、二次卸か） |
| **④ 何をするか** | メーカー担当者と事前に打ち合わせる。一緒に得意先を訪問する。メーカーが商品説明・技術説明を行い、卸売業者が価格・納品・在庫の話をする。訪問後にメーカーと結果を共有する |
| **⑤ 何を判断するか** | 同行が有効な相手か／メーカーにどこまで価格の話をさせるか（**卸の売価はメーカーに知らせたくない場合がある**）／得意先の要望のうち、メーカーに持ち帰ってもらうものはどれか |
| **⑥ 誰と連携するか** | 仕入・調達機能（メーカーとの窓口、条件の確認）／経営機能（重要な商談）／受注・業務機能（商談後の受注・価格登録） |
| **⑦ 出来上がるもの** | 商談記録、（成約時）新商品の採用・特売の合意、メーカーへのフィードバック、メーカーとの関係の維持 |

**なぜこの業務が必要なのか**

卸売業者は**商品を作っていません。**
そのため、商品の詳細（原材料、製法、規格、安全性、使い方）については、
メーカーのほうが深い情報を持っています。【Typical】

得意先が知りたいことが商品そのものの専門的な内容である場合、
メーカー担当者に同行してもらうほうが、話が早く、正確に伝わります。

同時に、同行訪問はメーカー側にも意味があります。
メーカーは全国に営業所を置いていても、**小さな飲食店や個人商店1軒1軒を訪問する体制は持てません**。
卸売業者に同行することで、自社商品が実際にどう扱われているかを見ることができます。
つまり同行訪問は、**卸売業者とメーカーが互いの不足を補い合う仕組み**です。【Inference】

> **【Varies】** 同行訪問の頻度と重要度は業種によって異なります。
> 機械・工具卸ではメーカーの技術者が同行して仕様を詰めることが多く、
> 医薬品卸ではメーカー（製薬会社）の担当者と医療機関を訪問する形があります。
> 食品卸では、新商品導入時・特売提案時の同行が中心になります。

#### E-13. 売掛金の回収督促・集金

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 経理・財務機能／与信・債権管理機能からの未入金の連絡（S21の消込で残ったもの）／支払予定日を過ぎても入金がない／得意先から支払延期の申し出があった／現金集金の取り決めがある得意先の訪問日 |
| **② 誰が** | 営業担当（実際の連絡・訪問）／与信・債権管理機能（未入金の把握と依頼）／営業部長・経営機能（長期化・高額の場合） |
| **③ 何を確認するか** | いつの請求のいくらが残っているか／過去にも遅れたことがあるか（**年齢表**の確認）／差額の原因が事務的なものか（返品の反映漏れ、値引きの認識違い、振込手数料の負担、一部入金）／得意先の様子に変化はないか（在庫が減っている、人が辞めている、他社の出入りが止まっている） |
| **④ 何をするか** | 得意先に連絡し、事情を聞く。事務的な行き違いなら内容を確認して経理に戻す。資金繰りの問題なら支払予定を取り付ける。現金集金の場合は訪問して受け取り、**領収書**を発行する |
| **⑤ 何を判断するか** | 単なる事務処理の遅れか、資金繰りの悪化か／このまま出荷を続けてよいか／与信限度額を下げるべきか／上長・経理・経営に上げるべき段階か |
| **⑥ 誰と連携するか** | 与信・債権管理機能（未入金情報の受領、与信見直しの相談）／経理・財務機能（消込、差額の処理）／受注・業務機能（出荷停止の反映）／経営機能（取引継続の判断） |
| **⑦ 出来上がるもの** | **督促の記録**、支払予定の取り付け、（現金集金時）領収書と入金、与信見直しの材料、（必要時）出荷停止の依頼 |

**用語**
**年齢表（ねんれいひょう）／売掛金年齢表**
→ 売掛金を「発生してから何日経っているか」で区分した一覧表のこと。
→ 実務例：「30日以内」「31〜60日」「61〜90日」「91日超」のように分けて表示する。
　**古い売掛金ほど回収が難しくなる**ため、どこに古い残高があるかを一目で見るために使います。

**なぜこの業務が必要なのか ——「売ったら終わり」ではない**

掛売が前提の卸売業では、**回収できなければ売上は損失に変わります。**【Typical】

```
 【回収できなかった場合に何が起きるか】【Example】（説明用の架空例）

  売上 100万円、原価 92万円、粗利 8万円 の取引が回収できなかった場合

   ・失うのは「粗利8万円」ではなく、仕入代金として実際に払った「92万円」
   ・この92万円を粗利8万円の取引で取り返すには、同じ取引を11.5回成立させる必要がある
     （92万円 ÷ 8万円 ＝ 11.5）
```

粗利率の薄い卸売業では、**1件の貸倒れを取り返すのに何倍もの売上が必要**になります。
これが「卸売業では回収が売ること以上に重要」と言われる理由です。【Inference】

**なぜ営業が督促するのか**

経理は「いくら残っているか」は分かりますが、
「なぜ払えないのか」「この会社は大丈夫なのか」は分かりません。
それを知っているのは、**毎週その店に行っている営業**です。【Typical】

一方で、営業は「売る側」であるため督促を言い出しにくい立場でもあります。
そのため実務では、**経理が把握して営業に依頼する**形が多く取られます。
この経理と営業の情報のやり取りが、貸倒れを防ぐ実務上の要になります。【Typical】

#### E-14. 得意先情報の収集と社内共有（与信情報を含む）

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 定期訪問（常に）／得意先の様子の変化に気づいたとき／同業者・仕入先からの噂・情報／新聞・業界紙の記事／与信・債権管理機能からの照会 |
| **② 誰が** | 営業担当／営業部長（とりまとめ） |
| **③ 何を確認するか** | 経営者・キーパーソンの交代／店舗の改装・新設・閉鎖／従業員の入れ替わりの激しさ／在庫の減り方（仕入れを絞っている兆候）／他社の出入り／支払いの態度の変化／業界内の噂 |
| **④ 何をするか** | 訪問時に見聞きしたことを記録する。特に支払能力に関わる兆候は、その日のうちに与信・債権管理機能へ伝える。競合や売れ筋の情報は商品部（仕入・調達機能）へ伝える |
| **⑤ 何を判断するか** | 報告すべき情報か、単なる噂か／急いで伝えるべきか／出荷を止めるほどの話か |
| **⑥ 誰と連携するか** | 与信・債権管理機能（信用不安の兆候）／仕入・調達機能（売れ筋・競合・価格の情報）／経営機能（重要な情報）／受注・業務機能（納品条件・担当者変更などの実務情報） |
| **⑦ 出来上がるもの** | 営業日報・訪問記録、**与信情報の報告**、市場情報（売れ筋・競合の動き・価格動向） |

**なぜこの業務が必要なのか**

**倒産の兆候は、決算書よりも先に現場に現れます。**【Typical】

決算書が手に入るのは年に1回で、しかも数か月遅れです。
一方、営業は毎週その店に行っています。
「急に仕入れを絞り始めた」「別の卸の車が来なくなった」「従業員が辞めていく」
といった変化は、**訪問している人間にしか見えません**。【Inference】

同じ理由で、商品の売れ行きの変化も現場に先に現れます。
「この商品の動きが急に良くなった」という情報が早く商品部に伝われば、
在庫を確保して欠品を避けることができます。

だから営業の情報収集は、「ついでにやること」ではなく、
**与信管理と仕入判断の材料を作る独立した業務**として位置づけられます。【Inference】

#### E-15. 売上・粗利の予算管理と実績報告

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 期初の予算策定／月次・週次の締めのタイミング／営業会議 |
| **② 誰が** | 営業担当（自分の担当分）／営業部長（部全体のとりまとめ）／経理・財務機能（数字の提供）／経営機能（予算の決定） |
| **③ 何を確認するか** | 自分の担当得意先の売上・粗利の実績／予算に対する達成率／前年同月との比較／粗利率が落ちている得意先・商品はないか／売上が落ちている得意先はないか（その理由は何か） |
| **④ 何をするか** | 実績を確認し、差の原因を調べる。不足分をどこで取り返すかの計画を立てる。会議で報告する。粗利率が悪化している取引について価格の見直しを検討する |
| **⑤ 何を判断するか** | 売上減の原因は一時的なものか、構造的なものか（得意先の不振か、他社に取られたか）／どの得意先に注力するか／価格改定を申し入れるべき取引はどれか |
| **⑥ 誰と連携するか** | 経理・財務機能（売上・粗利データ）／仕入・調達機能（仕入価格の見直し相談）／経営機能（予算・方針） |
| **⑦ 出来上がるもの** | 実績報告、予算との差異の分析、**注力先・価格見直し先のリスト** |

**なぜこの業務が必要なのか**

卸売業では、**売上が伸びても利益が伸びるとは限りません。**【Typical】
値引きして数量を増やせば売上は伸びますが、粗利率は下がります。
極端な場合、売上が増えているのに粗利額が減ることさえあります。

```
 【売上が増えて粗利が減る例】【Example】（説明用の架空例）

  前年：売上 1,000万円 × 粗利率 12% ＝ 粗利 120万円
  今年：売上 1,200万円 × 粗利率  9% ＝ 粗利 108万円

  → 売上は20%増えたが、粗利は12万円減っている
```

そのため卸売業の営業は、**売上高だけでなく粗利額・粗利率を必ずセットで見ます**。
これが `03_company-structure.md` §3-1-3 で述べた
「会社の実力は売上高ではなく粗利額で比べる」という見方の実務上の現れです。【Inference】

#### E-16. 取引条件の交渉（配送条件・締め日・支払方法）

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 新規取引の開始時／契約更新の時期／得意先からの条件変更の申し出／自社のコスト構造の変化（配送費、人件費）／与信・債権管理機能からの条件見直し要請 |
| **② 誰が** | 営業担当（一次交渉）／営業部長・経営機能（決定）／与信・債権管理機能（支払条件の妥当性）／物流・倉庫機能（配送条件の可否） |
| **③ 何を確認するか** | 現在の条件（締め日、支払サイト、支払方法、最低配送金額、配送頻度、時間指定）／その条件で採算が取れているか／他の得意先との条件のバランス／得意先の要望の背景 |
| **④ 何をするか** | 条件を整理して提示する。交渉する。合意内容を契約書・覚書にする。社内（経理、物流、業務）に変更内容を周知し、マスタを更新してもらう |
| **⑤ 何を判断するか** | 条件を変更すべきか／支払サイトの延長要請を受けるか（**資金繰りに直結する**）／少額配送を続けるか、最低金額を設けるか／時間指定に応じられるか |
| **⑥ 誰と連携するか** | 経理・財務機能（締め日・支払条件の実務、資金繰りへの影響）／与信・債権管理機能（条件変更のリスク）／物流・倉庫機能（配送条件の実現可否）／受注・業務機能（得意先マスタの条件更新）／経営機能（最終判断） |
| **⑦ 出来上がるもの** | 改定後の取引条件、契約書・覚書、**得意先マスタの更新依頼** |

**なぜこの業務が必要なのか**

取引条件は、**価格と同じくらい利益を左右します。**【Typical】

```
 【支払サイトが延びるとどうなるか】【Example】（説明用の架空例）

  月商500万円の得意先が「月末締め翌月末払い」から「月末締め翌々月末払い」に変更を要請

  → 立て替える期間が30日延びる
  → 常に約500万円分、多く資金を寝かせることになる
  → 商品代金の仕入支払は変わらないため、その分の資金を自社で用意する必要がある
```

つまり、**1円も値引きしていないのに、条件変更だけで資金負担が増える**ことがあります。
卸売業で「条件交渉」が重視されるのは、このためです。【Inference】

#### E-17. 得意先マスタの変更依頼

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 得意先の住所・屋号・電話番号の変更／納品先の追加・廃止（新店舗の開店、閉店）／担当者の交代／請求書の送付先・送付方法の変更／取引条件の変更 |
| **② 誰が** | 営業担当（変更内容の把握と依頼）／受注・業務機能（実際の登録作業） |
| **③ 何を確認するか** | 変更内容が正確か（正式な社名・住所か）／いつから適用するか／請求・配送のどちらに影響するか／既に入っている受注に影響しないか |
| **④ 何をするか** | 変更内容を書面・依頼票にまとめ、受注・業務機能へ渡す。登録後に内容を確認する |
| **⑤ 何を判断するか** | いつ切り替えるか（月の途中か、締め日の切れ目か）／請求先と納品先を分ける必要があるか |
| **⑥ 誰と連携するか** | 受注・業務機能（マスタ登録）／物流・倉庫機能（配送ルート・納品先の変更）／経理・財務機能（請求先の変更） |
| **⑦ 出来上がるもの** | **マスタ変更依頼票**、更新された得意先マスタ |

**なぜこの業務が必要なのか**

得意先マスタは、**受注・配送・請求のすべての出発点**です。
住所が古いままだと商品が届かず、請求先が古いままだと請求書が届かず、
請求書が届かなければ入金されません。【Inference】

小さな変更に見えますが、**変更のタイミングを間違えると締め処理が狂います**。
たとえば締め日の途中で請求先を変えると、1か月分の売上が2つの請求先に割れてしまいます。
そのため、変更は締め日の切れ目に合わせるのが一般的です。【Typical】

### O. 見ている数字・KPI

| 数字 | 意味 | なぜ見るのか |
|---|---|---|
| **売上高（担当得意先別・商品別）** | いくら売ったか | 最も基本的な実績 |
| **粗利額・粗利率** | 売上から仕入原価を引いた金額と、その売上に対する比率 | **卸売業では売上より重要**。値引きの影響が直接現れる |
| 予算達成率 | 予算に対してどこまで届いているか | 期中の進捗管理 |
| 前年同月比 | 前年の同じ月と比べてどうか | 季節性を除いて増減を見る |
| **得意先数（取引社数）・稼働得意先数** | 実際に取引のある得意先が何社あるか | 取引先の減少に早く気づくため |
| **新規口座開設数** | 新しく取引を始めた先の数 | 減っていく得意先を補えているか |
| 訪問件数・訪問頻度 | 何軒回ったか | 活動量の把握 |
| **欠品件数・欠品率** | 注文に対して出せなかった件数の割合 | 得意先の信用に直結する |
| **返品額・返品率** | 納品額に対する返品の割合 | 提案の精度、出荷の正確さを反映する |
| **売掛金残高・回収率・回収サイト** | 未回収の金額とその古さ | 回収できなければ売上は損失になる |
| **与信使用率** | 与信限度額に対して現在どれだけ使っているか | 出荷停止に至る前に気づくため |
| 新商品導入件数 | 新しい商品を何品採用してもらったか | 品揃えの更新度合い |
| 1件あたり受注金額（客単価） | 1回の注文の平均金額 | 配送効率・採算に直結する |

> **【Inference】** 卸売業の営業が「売上高」だけを見ないのは、
> 売上高は値引きしても増やせるからです。
> 粗利額・欠品率・回収率をあわせて見ることで、
> 「**利益が残り、約束が守られ、代金が回収された売上**」かどうかが分かります。

### 業種による違い（Level 2）——営業機能

| 比較軸 | **食品卸** | **建材卸** | **機械・工具卸** | **医薬品卸** | **アパレル卸** |
|---|---|---|---|---|---|
| **訪問の主目的** | 売場の確認と補充提案。ルートセールスの比重が最も大きい | 工務店・現場への訪問。**工事の進捗に合わせた納材の打ち合わせ** | **型番の特定**と技術的な相談への対応 | 医療機関・薬局への訪問。**医薬品の情報提供**の比重が高い | 展示会・展示受注が商談の中心。シーズン前に**まとめて受注** |
| **提案の中身** | 新商品、棚割、特売、メニュー提案 | 工法・規格・納期・現場搬入の段取り | 仕様・互換品・代替品・工具の使い方 | 採用品目、在庫の適正化、供給情報 | 色・サイズの展開、シーズンの品揃え |
| **価格交渉の性格** | 得意先ごとの継続的な価格。特売のつど交渉 | **案件（物件）ごとの見積**。同じ商品でも現場ごとに価格が変わる | 定番品は価格表、特注・大型品は都度見積 | **公的な価格制度の枠組みの中**での価格交渉【Fact】 | シーズン単位の価格。売れ残りの負担の分担が交渉点 |
| **受注の形** | 日次の繰り返し受注。電話・FAX・EDIが中心 | **案件ごとの見積→注文**。現場から直接電話が来ることも多い | 型番指定の都度受注＋定番消耗品の補充受注 | 日次の補充受注＋緊急発注（急配） | シーズン前の**先行受注（展示会受注）**＋期中追加 |
| **クレームの性格** | 期限不足、品違い、品質異常（**回収に発展しうる**） | 寸法違い、数量不足、納期遅れ（**工事が止まる**） | 型番違い、互換性の相違 | **品質・ロットに関わる事象は法令上の対応が必要**【Fact】 | 色・サイズの相違、納期遅れ（**シーズンを外すと売れない**） |
| **回収の性格** | 小口の得意先が多く、件数が多い | **工事代金の入金に連動**するため、支払が長期化しやすい【Typical】 | 事業者相手が中心 | 医療機関相手。支払サイトが長い取引がある【Varies】 | 小売店の売上に連動しやすい |

> **【Fact】** 医薬品卸の価格交渉については、厚生労働省の
> 「医療用医薬品の流通改善に向けて流通関係者が遵守すべきガイドライン」
> （平成30年1月23日施行、令和8年3月4日改訂）が、
> 割戻し（リベート）の整理・縮小や、一次売差マイナス（納入価が仕切価よりも低い状況）の
> 改善などについて示しています
> （出典：医療用医薬品の流通改善に向けて流通関係者が遵守すべきガイドライン／厚生労働省）。

> **【Typical】** 建材卸の営業は、**得意先の事務所だけでなく工事現場にも行きます。**
> 「いつ、どの工程で、何が必要になるか」を現場で確認し、
> 搬入の段取り（クレーンが必要か、道が狭くないか、置き場所があるか）まで決めます。
> 食品卸の「売場を見る」が、建材卸では「現場を見る」に置き換わります。

## 5-2. 受注・業務機能（内勤）

---

### A. 部署・機能名

| 項目 | 内容 |
|---|---|
| **機能名（本資料の呼び方）** | 受注・業務機能 |
| **一般的な部署名** | 業務部、業務課、営業事務、受注センター、受注課、内勤、事務、管理部 |
| **担当者の一般的な呼び方** | 内勤、業務、営業事務、受注担当、オペレーター、マスタ担当 |
| **モデル企業での呼称** | 業務部（6名。業務部長1名、受注担当4名、価格・マスタ管理1名） |

> **【Varies】** 独立した業務部があるとは限りません。
> 小規模な卸売会社では、**社長の配偶者や事務員1〜2名**が受注入力と請求を兼ねている形が
> 珍しくありません。それでも「注文を正確にデータにして、出荷と請求につなげる」という
> **受注・業務機能そのものは必ず存在します**。
> 逆に、大量受注を扱う会社では「受注センター」として独立させ、
> 電話受注の専門オペレーターを置くこともあります。

**用語**
**内勤（ないきん）**
→ 社内（事務所）で仕事をする担当者のこと。社外を回る**外勤（営業）**と対になる言葉です。
→ 実務例：「その件は内勤に聞いてください」＝伝票や在庫のことは事務所の担当者が分かる。

---

### B. 存在目的

> **得意先からの注文を、間違いなく「出荷できるデータ」と「請求できるデータ」に変換する。**
> ここで間違えると、誤出荷・誤請求として後工程のすべてに波及します。

もう少し丁寧に言うと、受注・業務機能は**3つの変換**を行っています。【Inference】

```
 ① バラバラな形で来る注文 → 統一されたデータ
    （電話の口頭、FAXの手書き、EDIの電子データ、メールの文章、営業のメモ）

 ② 「欲しい」という要望 → 「出せる」という約束
    （在庫を引き当て、与信を確認し、納期を回答して、初めて約束になる）

 ③ 出荷した事実 → 請求できる金額
    （正しい得意先別売価が当たっていなければ、請求できない）
```

> **【Typical】** この機能の価値は「正確さ」と「速さ」にあります。
> 受注締切の時刻までに、その日の全注文を漏れなく正確にデータ化しなければ、
> 倉庫は動けず、配送便は出発できず、翌朝の納品が間に合いません。

### E. 業務詳細

---

#### E-1. 電話での受注受付と入力

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 得意先からの電話。**朝の開店前と、受注締切前の時間帯に集中する**【Typical】 |
| **② 誰が** | 受注担当（内勤） |
| **③ 何を確認するか** | どの得意先からの電話か（納品先が複数ある場合はどの店か）／商品の特定（商品名・規格・メーカー）／数量と単位（ケース／ボール／バラ）／希望納品日と時間帯／特売価格の適用があるか |
| **④ 何をするか** | 注文を聞きながら、その場で販売管理システムに入力する。商品コードを検索し、価格マスタから売価が自動でセットされることを確認する。**聞き取った内容を復唱して確認する**。在庫が不安な商品はその場で引当可能在庫を見る |
| **⑤ 何を判断するか** | 聞き取った商品が本当にその商品か（**類似商品との取り違え**がないか）／単位は合っているか／希望納品日に間に合うか（受注締切に間に合っているか）／在庫があるか／その場で答えるか、折り返すか |
| **⑥ 誰と連携するか** | 在庫管理機能（在庫の確認）／営業機能（イレギュラーな注文、価格の相違）／仕入・調達機能（在庫がない商品の入荷予定確認） |
| **⑦ 出来上がるもの** | **受注データ（受注伝票）**、（欠品時）欠品の記録 |

**なぜこの業務が必要なのか**

卸売業の得意先には、**発注専門の担当者がいない相手が多くいます。**【Typical】
小さな飲食店の店主、個人商店の経営者は、営業の合間に電話をかけてきます。
そのため、電話受注は「注文を聞く」だけでなく、
**相手の言葉を正しい商品コードに翻訳する**仕事になります。

> **【Example】**（説明用の架空例）
> 飲食店から「いつもの醤油、3つ」という電話。
> 「いつもの」が何かを得意先マスタの購買履歴から特定し、
> 「濃口醤油1L×6本入り、3ケースでよろしいですか」と復唱して確認する。
> **「3つ」が3ケース（18本）なのか3本なのかで、金額も在庫も6倍違います。**

**ここで起きやすい間違い**【Typical】
- **単位の取り違え**（ケース／ボール／バラ）
- **類似商品の取り違え**（規格違い、減塩・無添加などのバリエーション違い）
- **納品先の取り違え**（本店と支店、店舗とセンター）
- **納品日の取り違え**（「あした」が翌日か翌営業日か）
- **口頭の聞き間違い**（「7」と「1」、「いち」と「しち」）

#### E-2. FAXでの受注受付と入力

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 得意先から送信されたFAX注文書。**前夜から早朝にかけて届いたものを、朝一番にまとめて処理する**【Typical】 |
| **② 誰が** | 受注担当（内勤） |
| **③ 何を確認するか** | 送信元の得意先／手書き文字が判読できるか／商品名・数量・単位／希望納品日／前回送信分との重複がないか（**同じFAXが2回届いていないか**）／訂正や二重線の意味 |
| **④ 何をするか** | 届いたFAXを得意先別・納品日別に仕分ける。1枚ずつ販売管理システムに入力する。判読できない箇所は得意先に電話で確認する。入力済みのFAXには処理済みの印を付け、原本を保管する |
| **⑤ 何を判断するか** | 手書きの数量・商品名の読み取りが正しいか／不明箇所を確認するか、推測で入力しないか／重複注文ではないか／締切に間に合う枚数か |
| **⑥ 誰と連携するか** | 営業機能（判読不能・内容が不自然な場合の確認）／得意先（社外。直接の確認） |
| **⑦ 出来上がるもの** | **受注データ**、処理済みFAX原本（保管）、確認記録 |

**なぜこの業務が必要なのか**

FAXは、**得意先が営業時間外でも注文を送れる手段**です。【Typical】
夜の営業が終わった飲食店、早朝に発注する店舗は、
電話が通じない時間に注文を出せます。

一方で、FAXは**手書きの文字を人が読み取って入力する**ため、
電話受注と同じかそれ以上に読み取りの判断が必要になります。
また、**受信した事実が自動で記録されない**ため、
「送ったのに届いていない」というトラブルが起きます。
そのため、受信したFAXの枚数管理と原本保管が実務上の重要な作業になります。【Inference】

> **【Varies】** FAX受注の比重は業種・得意先によって大きく異なります。
> 大手小売向けはEDIが中心である一方、
> 個人商店・飲食店向けでは電話とFAXが主要な受注手段として残っている場合があります。

#### E-3. EDI受注データの取込と確認

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 得意先（主に大手小売・チェーン店）の発注システムから、決められた時刻にデータが送信されてくる |
| **② 誰が** | システムが自動で取り込み、受注担当が結果を確認する |
| **③ 何を確認するか** | 取込件数が想定どおりか（**送信されていない店舗はないか**）／エラーになったデータはないか（商品コードの不一致、未登録商品、価格の不一致）／単価が自社の価格マスタと一致しているか／数量が異常に多くないか（**桁違いの発注**） |
| **④ 何をするか** | 取込結果を確認する。エラーデータを1件ずつ処理する（商品コードの対応付け、価格の修正、得意先への照会）。正常分はそのまま引当へ流す |
| **⑤ 何を判断するか** | エラーの原因は自社側か得意先側か／自社で修正してよいか、得意先に確認すべきか／数量が異常な注文をそのまま通してよいか／取込の時刻に間に合っているか |
| **⑥ 誰と連携するか** | 営業機能（得意先への照会）／仕入・調達機能（大量発注時の在庫手当て）／（社内外の）システム担当（取込エラーの調査） |
| **⑦ 出来上がるもの** | **受注データ**、エラー処理の記録、（該当時）得意先への照会記録 |

**用語**
**EDI（Electronic Data Interchange：電子データ交換）**
→ 発注・受注・出荷・請求などのデータを、**企業間でシステム同士が直接やり取りする仕組み**。
→ 実務例：スーパーの本部システムが発注データを送ると、卸のシステムに自動で受注データが入る。
　人が入力しないため入力ミスがなく、大量の注文を短時間で処理できる。

**なぜこの業務が必要なのか ——「自動なのに確認が要る理由」**

EDIは人が入力しないため、入力ミスは起きません。
しかし、**別の種類の問題が起きます。**【Typical】

| 起きること | なぜ起きるか |
|---|---|
| **商品コードが合わない** | 得意先の商品コードと自社の商品コードは別物。対応表（変換マスタ）が古いと紐づかない |
| **単価が合わない** | 得意先側の登録価格と自社の価格マスタがずれている。特売価格の適用期間の認識違い |
| **未登録商品が来る** | 得意先が新しく採用した商品がまだ自社に登録されていない |
| **データが届かない** | 通信の不具合、得意先側の送信漏れ。**「届いていない」ことに気づくのが難しい** |
| **桁違いの発注** | 得意先側の入力ミス（10ケースのつもりが100ケース） |

特に最後の2つは重大です。
**データが届いていないことに気づかなければ、その店舗には何も届きません。**
そのため、受注担当は「取込件数が想定どおりか」を必ず確認します。【Inference】

#### E-4. Web受発注・メールでの受注処理

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 得意先が自社のWeb受発注画面から注文を入力した／得意先からメールで注文書が届いた |
| **② 誰が** | 受注担当（内勤）。Web受発注の場合はデータが直接受注として登録される仕組みもある【Varies】 |
| **③ 何を確認するか** | 注文内容／添付ファイルの形式（注文書、表計算ファイル、写真）／過去の注文との重複／メール本文に書かれた特記事項（納品時間、置き場所、担当者への伝言） |
| **④ 何をするか** | 内容を確認し、システムに登録する（Web受発注の場合は登録内容を確認する）。特記事項を受注データの備考欄や出荷指示に反映する。受付の返信をする |
| **⑤ 何を判断するか** | メール本文の要望を誰に伝えるべきか（物流か、営業か）／注文として確定してよい内容か（相談段階のメールではないか） |
| **⑥ 誰と連携するか** | 物流・倉庫機能（納品時の特記事項）／営業機能（相談段階の案件） |
| **⑦ 出来上がるもの** | **受注データ**、受付の返信、特記事項の申し送り |

**なぜこの業務が必要なのか**

メールでの注文には、**注文以外の情報が混ざります。**【Typical】
「明日は搬入口が使えないので裏口に」「担当者が変わりました」「先週の請求書が届いていない」
といった内容が、注文と同じメールに書かれていることがあります。

これらを受注データに入力するだけでは、**該当する部署に届きません。**
そのため受注担当は、「注文として処理する部分」と
「他部署へ申し送る部分」を仕分ける判断をしています。【Inference】

---

#### E-5. 営業からの受注引き継ぎの入力

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 営業担当からの電話連絡、帰社後の受注メモの提出、モバイル端末からの送信 |
| **② 誰が** | 受注担当（内勤）／営業自身が入力する運用の場合は営業担当【Varies】 |
| **③ 何を確認するか** | 受注メモの記載内容（商品、数量、単位、納品日、納品先）／適用する価格（特売か通常か、営業が約束した特別価格か）／急ぎかどうか（当日締切に乗せる必要があるか） |
| **④ 何をするか** | メモの内容をシステムに入力する。不明点は営業に確認する。特別価格が約束されている場合は、価格の根拠（承認の有無）を確認して入力する |
| **⑤ 何を判断するか** | メモの内容で入力してよいか、確認が必要か／価格マスタと違う価格が指定されている場合、そのまま入力してよいか（**承認された価格か**）／当日出荷に間に合わせるか |
| **⑥ 誰と連携するか** | 営業機能（内容・価格の確認）／営業部長（価格の承認確認）／物流・倉庫機能（締切後の緊急対応） |
| **⑦ 出来上がるもの** | **受注データ**、（価格が特別な場合）価格の適用記録 |

**なぜこの業務が必要なのか**

営業が受けた注文は、**入力されるまで存在しないのと同じ**です。
在庫も引き当てられず、ピッキングリストにも載らず、請求もされません。【Inference】

ここで特に重要なのが**価格の確認**です。
営業が訪問先で「今回は特別に2,800円で」と約束した場合、
価格マスタの登録価格（たとえば2,950円）とは違う金額を入力することになります。
この差額がそのまま粗利の減少になるため、
**誰がその価格を承認したのかを確認する**のが内勤の役割になります。【Typical】

#### E-6. 在庫引当の確認

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 受注入力の完了（システムが自動で引当を実行する） |
| **② 誰が** | システムが自動で引当を行い、受注担当が結果を確認する |
| **③ 何を確認するか** | 引当可能在庫が受注数量を満たしたか／引当不足（欠品）になった明細はどれか／食品・医薬品では**賞味期限／使用期限とロット**も条件を満たすか（得意先の納品期限基準を満たす期限の在庫があるか）／先入先出のとおりに古いロットから引き当てられているか |
| **④ 何をするか** | 引当結果の一覧を確認する。引当不足のものを欠品リストとして抽出する。期限の条件で引当できなかったものを区別する（**在庫はあるが期限が足りない**というケース） |
| **⑤ 何を判断するか** | 欠品として営業に連絡すべきか／他の受注の引当を振り替えて調整できるか／入荷予定に間に合うか／期限違いの在庫でも得意先が了承する可能性があるか |
| **⑥ 誰と連携するか** | 在庫管理機能（実在庫の確認、引当の調整）／営業機能（欠品連絡）／仕入・調達機能（緊急発注、入荷予定の確認） |
| **⑦ 出来上がるもの** | **引当済の受注データ**、**引当不足リスト（欠品リスト）** |

**用語の整理（`04_end-to-end-process.md` §4-1 の再掲）**

| 用語 | 意味 |
|---|---|
| **総在庫（実在庫）** | 倉庫に実際に置いてある数量 |
| **引当済在庫** | すでに他の注文に割り当てられている数量 |
| **引当可能在庫（有効在庫・フリー在庫）** | 総在庫 − 引当済在庫。新しい注文に使える数量 |
| **入荷予定** | 発注済みでまだ届いていない数量 |

**なぜこの業務が必要なのか**

引当がないと、**同じ在庫を複数の注文に二重に約束してしまいます。**【Typical】

```
 【引当がない場合に起きること】【Example】（説明用の架空例）

  在庫：醤油 50ケース

  午前 10:00  B店から30ケースの注文 → 「在庫50あるから大丈夫」と受注
  午前 11:30  C店から35ケースの注文 → 「在庫50あるから大丈夫」と受注
                                        （B店分が引かれていない）
  → 合計65ケースの約束をしたが、在庫は50ケースしかない
  → 出荷段階で15ケース足りないことが判明する
```

引当は、**受注した瞬間にその在庫を「他の注文には使えない」状態にする**ことで、
この二重約束を防いでいます。

**食品卸・医薬品卸に特有の「期限つき引当」**【Typical】

食品卸では、在庫が数量としてあっても**引き当てられないことがあります。**
得意先ごとに「残りの賞味期間がこれだけ残っていなければ受け取らない」という
**納品期限**の基準があるためです。

> **【Fact】** 農林水産省は、食品業界における「**3分の1ルール**」を
> 「賞味期間を製造日から賞味期限までの3段階に分割し、最初の区間を納品期限、
> 次の区間を販売期限とする商慣習」と説明しています。
> また、納品期限を緩和する食品小売事業者の数は、令和4年度の240事業者から
> **令和5年10月末時点で297事業者**に増加したと公表されています
> （出典：商慣習見直しに取り組む食品製造・小売事業者の公表／農林水産省）。

つまり内勤の画面には、**「在庫あり・引当不可」**という状態が現れます。
「倉庫には商品があるのに、この得意先には出せない」という判断を、
毎日の受注処理の中で行っているのが食品卸の内勤です。【Inference】

#### E-7. 欠品の発見・連絡と代替提案

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 在庫引当（S3）で引当不足が出たとき／入荷予定が遅れる連絡が仕入・調達機能から入ったとき |
| **② 誰が** | 受注担当（発見と一次情報の整理）／営業機能（得意先との調整）／仕入・調達機能（代替品・緊急調達） |
| **③ 何を確認するか** | 何が、いくつ足りないか／入荷予定日と数量／代替できる商品が自社在庫にあるか（同等品、別メーカー品、別規格品、別入数）／他の受注に引き当て済の在庫を振り替えられるか／その得意先にとっての緊急度 |
| **④ 何をするか** | 欠品リストを整理し、商品ごとに対応案を作る。営業へ連絡する（商品名・不足数・入荷予定・代替案をセットで）。営業が得意先と調整した結果を受けて、受注データを修正する。緊急発注が必要なら仕入・調達機能へ依頼する |
| **⑤ 何を判断するか** | 営業に上げるべき欠品か、内勤の判断で処理してよい範囲か（例：入数違いの同一商品への振替）／どの得意先の引当を優先するか（**限られた在庫を誰に回すか**）／分納にするか、まとめて後日にするか |
| **⑥ 誰と連携するか** | 営業機能（得意先への連絡と交渉）／仕入・調達機能（緊急発注、入荷前倒しの交渉）／在庫管理機能（引当の振替）／物流・倉庫機能（分納・追加便の段取り） |
| **⑦ 出来上がるもの** | **欠品連絡**、代替案、**修正後の受注データ**、緊急発注の依頼、欠品の記録 |

**なぜこの業務が必要なのか**

欠品は、卸売業では**毎日一定量発生します。**【Typical】
4,500SKUを扱い、380社から注文が来れば、
すべてを完全に在庫で満たすことは現実的に起こりません。

重要なのは「欠品をゼロにする」ことではなく、
**「欠品に気づき、代案を添えて、早く伝える」**ことです。【Inference】

**「誰に在庫を回すか」という判断**

在庫が足りないとき、内勤は**限られた在庫をどの得意先に回すか**を判断する場面があります。

> **【Example】**（説明用の架空例）
> ある商品の引当可能在庫が20ケース。同じ日に3件の注文が入った。
> ・Bスーパー：チラシ掲載品として15ケース（欠品すると店頭で告知が必要になる）
> ・C飲食店：通常補充として10ケース（在庫に余裕があり、翌日でも支障がない）
> ・D商店：通常補充として5ケース
> → チラシ掲載のBスーパーを優先し、C飲食店には翌日納品を打診する、という調整を行う。

> **【Varies】** この優先順位の付け方は会社の方針によって異なります。
> 「先に注文が入った順」「取引金額の大きい順」「緊急度の高い順」など、
> 明文化されている会社もあれば、担当者の経験で判断している会社もあります。

#### E-8. 納期回答

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 得意先からの納期の問い合わせ／在庫のない商品（**都度仕入**の商品）の受注／欠品対応の中での照会 |
| **② 誰が** | 受注担当（内勤）／在庫のない商品は仕入・調達機能に確認したうえで回答 |
| **③ 何を確認するか** | 在庫があるか（あれば自社の配送スケジュールだけで決まる）／ない場合は仕入先の在庫と納期／自社の受注締切と配送コースの曜日／入荷してから出荷できるまでの社内の作業時間／得意先の希望納期 |
| **④ 何をするか** | 在庫・入荷予定・配送スケジュールを組み合わせて、**いつ届けられるか**を計算する。仕入先に納期を確認する。得意先（または営業）に回答する。回答した納期を受注データに記録する |
| **⑤ 何を判断するか** | 確実に守れる納期か（**余裕を見ずに回答すると守れない**）／仕入先の納期回答をそのまま伝えてよいか／急ぐ場合に別ルート（他の仕入先、他拠点、チャーター便）を使うか |
| **⑥ 誰と連携するか** | 仕入・調達機能（仕入先の納期確認、緊急手配）／在庫管理機能（入荷予定の確認）／物流・倉庫機能（配送便の空き、臨時便の可否）／営業機能（得意先への回答） |
| **⑦ 出来上がるもの** | **納期回答**、受注データへの納期の記録、（必要時）発注の依頼 |

**なぜこの業務が必要なのか**

**在庫のない商品では、納期回答が仕事の中心になります。**【Typical】

`04_end-to-end-process.md` §4-3 で扱った「都度仕入」のパターンでは、
受注してから仕入先に発注するため、**得意先にいつ届くかを答えられるのは自社だけ**です。
建材卸・機械工具卸では、この納期回答の正確さが取引の評価そのものになります。

納期回答で難しいのは、**自社で完結しない要素が混ざる**ことです。

```
 【納期を構成する要素】

  仕入先の在庫の有無  →  仕入先の出荷日  →  自社への入荷日
      →  自社での検品・入庫  →  自社の出荷日  →  配送日  →  得意先の納品日
      ※ このどこか1つが遅れれば、約束した納期は守れない
```

そのため納期回答には、**各段階の余裕をどれだけ見込むか**という判断が入ります。【Inference】

#### E-9. 与信チェック結果の確認と出荷保留対応

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 受注データの登録時にシステムが与信判定を行い、限度額超過の警告が出たとき |
| **② 誰が** | 受注担当（発見）／与信・債権管理機能（判断）／経営機能（承認） |
| **③ 何を確認するか** | 現在の売掛金残高／与信限度額／今回の受注金額／超過している金額／入金予定日（間もなく入金があるのか）／過去にも超過したことがあるか |
| **④ 何をするか** | 超過の内容を整理し、与信・債権管理機能へ回す。判断を待つ間、その受注の出荷を保留にする。承認されれば出荷指示に乗せ、保留が続く場合は営業に差し戻す |
| **⑤ 何を判断するか** | 出荷を止めるか、一時的に通すか（**これは内勤単独では判断しない**）／他の受注（同じ得意先の別明細）も止めるか／得意先にいつ・誰から連絡するか |
| **⑥ 誰と連携するか** | 与信・債権管理機能（判断の依頼）／経営機能（限度額の一時引き上げ等の承認）／営業機能（得意先への説明、入金の確認）／物流・倉庫機能（保留分を出荷させない） |
| **⑦ 出来上がるもの** | 与信超過の記録、**出荷保留または出荷可の判定**、（承認時）承認記録 |

**なぜこの業務が必要なのか**

与信限度額は、**設定するだけでは意味がありません。**
実際に受注のたびにチェックし、超過したら止める仕組みが動いていて初めて機能します。【Inference】

内勤がこの役割を担うのは、**受注データが必ず内勤を通るから**です。
受注のすべてが1か所を通るため、そこにチェックを置くのが確実になります。

> **【Varies】** 与信チェックをシステムで自動的に行うか、
> 経理担当が目視で確認するか、そもそも明示的な与信限度額を設けていないかは、
> 企業によって異なります（`04_end-to-end-process.md` S5 参照）。

> **【Typical】** ここで内勤が単独で判断しないのが重要な点です。
> 「出荷を止める」判断は得意先との関係に直結するため、
> 与信・債権管理機能または経営機能の判断を仰ぐ形になります。

#### E-10. 受注締切と出荷指示の確定

| 観点 | 内容 |
|---|---|
| **① きっかけ** | あらかじめ決められた**受注締切時刻**の到来 |
| **② 誰が** | 業務部長・受注担当 |
| **③ 何を確認するか** | 締切時点で未入力の注文が残っていないか（FAXの未処理分、EDIの未着分、営業からの引き継ぎ漏れ）／全明細が引当済か／与信保留のものが混ざっていないか／配送コース別の物量が車両に収まるか |
| **④ 何をするか** | 当日出荷分を締める。配送コース別・得意先別に出荷指示を確定する。締切後に入った注文を翌日分として登録する。出荷指示データを物流・倉庫機能へ渡す |
| **⑤ 何を判断するか** | 締切後に入った注文を当日分に入れるか、翌日に回すか（**例外を認めるかどうかの判断**）／コースの積載が収まらない場合、どの納品を翌日に回すか／臨時便を出すか |
| **⑥ 誰と連携するか** | 物流・倉庫機能（物量と車両の調整、締切後の追加可否）／営業機能（翌日に回す場合の得意先への連絡）／与信・債権管理機能（保留分の最終確認） |
| **⑦ 出来上がるもの** | **確定した出荷指示データ**、配送コース別の出荷一覧、翌日出荷分の受注データ |

**用語**
**受注締切（じゅちゅうしめきり）**
→ 「この時刻までに入った注文は当日出荷（翌日納品）する」という時刻の取り決め。
→ 実務例：「当日15時締め、翌日午前納品」。15時1分に入った注文は翌々日納品になる。

**なぜこの業務が必要なのか ——「締切は物流から逆算されている」**

締切は、事務の都合で決めているのではありません。
**倉庫の作業時間と配送便の出発時刻から逆算して決まっています。**【Inference】

```
 【締切が決まる仕組み】

  翌朝7時に得意先へ納品したい
       ↑
  そのためには当日5時30分に配送車が出発する必要がある
       ↑
  そのためには前日18時までに積込を終える必要がある
       ↑
  そのためには前日15時30分からピッキング・検品を始める必要がある
       ↑
  そのためには前日15時に受注を締めてピッキングリストを出す必要がある
       ↑
  →  受注締切は15時
```

締切を1時間延ばせば、この全工程が1時間後ろにずれます。
だから「もう少しだけ受けてほしい」という得意先の要望に応えるかどうかは、
**倉庫と配送の物理的な制約との相談**になります。【Typical】

> **【Varies】** 受注締切の回数と時刻は企業により異なります。
> 1日1回の会社もあれば、午前・午後の2回締める会社、
> 配送コースごとに別々の締切を設けている会社もあります。

#### E-11. ピッキングリスト・納品書の出力

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 出荷指示の確定（E-10） |
| **② 誰が** | 受注担当・伝票担当 |
| **③ 何を確認するか** | 出力対象が確定分だけになっているか／保留分・翌日分が混ざっていないか／納品書の様式が得意先ごとの指定に合っているか（**得意先指定の伝票を使う取引がある**）／枚数が揃っているか |
| **④ 何をするか** | ピッキングリストを出力する（倉庫のロケーション順に並ぶよう設定されている）。納品書・物品受領書を出力する。得意先別・配送コース別に仕分けて物流・倉庫機能へ渡す |
| **⑤ 何を判断するか** | 再出力が必要な状態か（用紙ずれ、印字不良）／変更が入った分の差し替えをどう扱うか（**古いリストが現場に残ると誤出荷になる**） |
| **⑥ 誰と連携するか** | 物流・倉庫機能（リストと伝票の引き渡し）／営業機能（変更が入った場合の連絡） |
| **⑦ 出来上がるもの** | **ピッキングリスト**、**納品書**、**物品受領書**、配送コース別の出荷一覧 |

**用語**
**ピッキングリスト**
→ 倉庫で商品を集めるための作業指示書。「どの棚から、どの商品を、何個取るか」が並んでいます。
→ 実務例：倉庫の棚の並び順に商品が並んだリストを見ながら、台車で回って商品を集める。
　**棚の順番に並んでいないと、倉庫内を何度も往復することになります。**

**用語**
**物品受領書（ぶっぴんじゅりょうしょ）**
→ 得意先が「注文どおりのものを受け取った」と確認して、署名または押印する書類。
　納品書と複写になっていることが多くあります。
→ 実務例：ドライバーが納品時に受領印をもらい、持ち帰って会社に提出する。
　**これが「確かに納めた」という証拠**になり、請求の根拠になります。

**なぜこの業務が必要なのか**

ピッキングリストと納品書は、**データを現場が使える形にしたもの**です。【Inference】

- **ピッキングリスト**は、倉庫の作業者への指示書
- **納品書**は、得意先への「何を届けたか」の通知書
- **物品受領書**は、「確かに届けた」という証拠

3つとも同じ受注データから作られますが、**読む相手が違うため形が違います**。

ここで注意が必要なのが、**出力後に受注が変更された場合**です。
古いピッキングリストが倉庫に残っていると、変更前の数量で集品されてしまいます。
そのため、変更時は必ず古いリストを回収してから差し替えます。【Typical】

#### E-12. 伝票発行（納品書・物品受領書・売上伝票）

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 出荷指示の確定／納品完了後の売上計上／得意先からの伝票再発行の依頼 |
| **② 誰が** | 受注担当・伝票担当 |
| **③ 何を確認するか** | 得意先ごとの伝票様式の指定（**得意先が指定する統一伝票を使う取引がある**）／消費税の表示（税率、税込／税抜の別）／請求先と納品先が違う場合の記載／必要な控えの枚数 |
| **④ 何をするか** | 伝票を発行する。控えを保管する。得意先指定の伝票がある場合は専用用紙に印字する。納品後、受領印のある受領書を回収して保管する |
| **⑤ 何を判断するか** | 様式が得意先の要求に合っているか／数量変更があった場合、どの時点の伝票を正とするか |
| **⑥ 誰と連携するか** | 物流・倉庫機能（伝票の同梱・貼付）／経理・財務機能（売上計上、請求の根拠）／営業機能（得意先からの伝票に関する要望） |
| **⑦ 出来上がるもの** | **納品書**、**物品受領書**、**売上伝票**、伝票の控え（保管） |

**なぜこの業務が必要なのか**

伝票は、**取引があったことの証拠**です。【Typical】
「何を、いくつ、いくらで、いつ、誰に納めたか」が書かれた紙（またはデータ）がなければ、
請求もできず、返品の処理もできず、クレームの検証もできません。

> **【Fact】** 消費税の仕入税額控除の方式として、
> 令和5年（2023年）10月1日から**適格請求書等保存方式（インボイス制度）**が開始されています
> （出典：インボイス制度の概要／国税庁）。
> また、見積書・契約書・請求書・領収書などを電子データでやり取りした場合、
> 令和6年（2024年）1月から、そのデータを**電子データのまま保存すること**が必要とされています
> （出典：令和6年1月スタート 令和5年度の税制改正により見直された電子帳簿等保存制度の内容と中小企業の対応策／財務省（広報誌「ファイナンス」令和6年8月号））。
> 卸売業では取引件数・伝票枚数が多いため、これらの保存要件への対応は
> 受注・業務機能と経理・財務機能が分担して行うことになります。【Inference】
> （制度の詳細は `10_documents.md` `15_rules-customs.md` で扱います）

#### E-13. 受注の変更・キャンセルの処理

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 得意先からの変更・取消の連絡／営業からの変更依頼／欠品対応に伴う数量変更／配送の都合による納品日変更 |
| **② 誰が** | 受注担当（内勤） |
| **③ 何を確認するか** | **現在その受注がどの段階にあるか**（入力済／引当済／出荷指示済／ピッキング中／出荷済／納品済）／変更が間に合う段階か／変更後の在庫引当がどうなるか |
| **④ 何をするか** | 段階に応じた処理を行う。入力済・引当済の段階なら受注データを直接修正する。出荷指示済ならピッキングリストの差し替えと倉庫への連絡を行う。出荷済・納品済なら**返品処理（赤伝）**に切り替える |
| **⑤ 何を判断するか** | まだ変更できる段階か／倉庫の作業を止めてでも変更するか／出荷後であれば返品扱いにするか、次回で調整するか／キャンセルに伴う在庫（特別に仕入れた商品）をどうするか |
| **⑥ 誰と連携するか** | 物流・倉庫機能（作業中の変更、リストの差し替え）／営業機能（得意先への確認）／仕入・調達機能（特別手配品のキャンセル）／在庫管理機能（引当の解除） |
| **⑦ 出来上がるもの** | **修正後の受注データ**、差し替えたピッキングリスト・納品書、（出荷後の場合）返品伝票 |

**なぜこの業務が必要なのか**

変更対応の難しさは、**受注が「どの段階まで進んでいるか」で処理がまったく変わる**点にあります。【Typical】

```
 【受注の段階と、変更の可否】

  受注入力済      → データを直すだけ。影響は小さい
  引当済          → 引当を解除して数量を変える。他の注文への影響を確認する
  出荷指示済      → ピッキングリストと納品書の差し替えが必要。倉庫に連絡が要る
  ピッキング中    → 作業を止める必要がある。集品済の商品を棚に戻す
  出荷済（車上）  → 原則として変更できない。納品を止めるか、返品扱いにする
  納品済          → 返品処理（赤伝）になる
```

つまり、**同じ「1ケース減らしてほしい」という依頼でも、
時刻が1時間違うだけで作業量が何倍にもなります。**【Inference】
これが、受注締切が厳しく運用される理由のひとつでもあります。

#### E-14. 返品処理（赤伝の起票）

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 営業機能からの返品受付の連絡／物流・倉庫機能からの返品現物の受入報告／誤出荷の判明 |
| **② 誰が** | 受注担当・伝票担当 |
| **③ 何を確認するか** | 元の売上伝票（いつ、いくらで、何ケース納品したか）／返品数量／返品理由と責任の所在／現物が倉庫に戻っているか／在庫に戻せる状態か／仕入先へ返品する案件か |
| **④ 何をするか** | 返品伝票（赤伝）を起票し、売上をマイナスで計上する。在庫に戻せるものは在庫を戻す入力を行う。戻せないものは在庫から除外する処理を行う。仕入先返品の場合は仕入・調達機能へ引き継ぐ |
| **⑤ 何を判断するか** | 元の売上のどの明細に対する返品か（**同じ商品を複数回納品している場合、どの納品分か**）／単価をいくらで戻すか（納品時の単価で戻す）／在庫に戻すか、除外するか／どの月の売上から引くか（**締めをまたぐ場合**） |
| **⑥ 誰と連携するか** | 営業機能（返品の内容確認）／物流・倉庫機能（現物の受入・検品）／在庫管理機能（在庫数の修正）／経理・財務機能（請求金額への反映）／仕入・調達機能（仕入先返品） |
| **⑦ 出来上がるもの** | **返品伝票（赤伝）**、修正された売上データ、修正された在庫データ、（該当時）仕入先返品の依頼 |

**なぜこの業務が必要なのか**

返品処理は、**卸売業の伝票処理の中で最も間違えやすい作業のひとつ**です。【Typical】
理由は、1件の返品が**5つのものに同時に影響する**からです。

```
 【1件の返品が影響するもの】

   返品 ─┬─▶ 売上     （マイナス計上する）
         ├─▶ 在庫     （戻すか、除外するか）
         ├─▶ 請求金額 （締めまでに反映されないと請求が合わない）
         ├─▶ 粗利     （原価も一緒に戻す必要がある）
         └─▶ 仕入     （仕入先へ返品する場合は買掛金も変わる）
```

どれか1つでも漏れると、**後の工程で必ず問題として表面化します**。

| 漏れたもの | いつ、どう表面化するか |
|---|---|
| 売上のマイナス計上 | 請求時。得意先が「返品分が引かれていない」と言う → 入金が止まる |
| 在庫の戻し入れ | 棚卸時。「帳簿より現物が多い」という差異になる |
| 在庫からの除外 | 棚卸時。「帳簿より現物が少ない」という差異になる |
| 仕入先への返品 | 交渉期限を過ぎ、返品を受けてもらえなくなる |

#### E-15. 得意先マスタの登録と保守

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 新規取引の開始（与信審査の完了）／営業機能からのマスタ変更依頼／得意先の住所・屋号・担当者・納品先・取引条件の変更／取引の終了 |
| **② 誰が** | マスタ担当（受注・業務機能）／内容により与信・債権管理機能・経理・財務機能の確認を経る |
| **③ 何を確認するか** | 正式な商号・住所・電話番号／請求先と納品先の区分／**取引条件（締め日、支払方法、支払サイト）**／配送コース／与信限度額／適格請求書発行事業者の登録番号【Fact】／担当営業の割り当て |
| **④ 何をするか** | 得意先マスタに登録・更新する。納品先（出荷先）を必要な数だけ登録する。取引条件を登録する。与信限度額を登録する。登録内容を依頼元に確認してもらう |
| **⑤ 何を判断するか** | いつから適用するか（**締め日の切れ目に合わせるか**）／請求先と納品先を分ける必要があるか／同じ会社の別店舗を1コードにするか、店舗ごとに分けるか／休止・取引終了の扱い（コードを消すか、休止にするか） |
| **⑥ 誰と連携するか** | 営業機能（依頼元）／与信・債権管理機能（与信限度額）／経理・財務機能（締め日・請求先）／物流・倉庫機能（配送コース・納品先） |
| **⑦ 出来上がるもの** | **登録・更新された得意先マスタ**、登録完了の連絡 |

**なぜこの業務が必要なのか**

得意先マスタは、**受注・出荷・請求のすべての前提**です。
ここが間違っていると、以下がすべて狂います。【Inference】

```
 得意先マスタの誤り ──┬─▶ 配送先が違う     → 商品が届かない
                      ├─▶ 締め日が違う     → 請求月がずれる
                      ├─▶ 請求先が違う     → 請求書が届かない → 入金されない
                      ├─▶ 与信限度額が空欄 → 与信チェックが働かない
                      └─▶ 配送コースが違う → 配車計画が崩れる
```

**なぜ「いつから適用するか」が重要なのか**

締め日の途中で請求先を変えると、**1か月分の売上が2つの請求先に割れます**。
得意先側も自社側も、どちらに請求するのが正しいか分からなくなります。
そのため、取引条件に関わる変更は締め日の切れ目に合わせるのが一般的です。【Typical】

> **【Fact】** 適格請求書（インボイス）を交付するためには、
> 税務署長に申請して**適格請求書発行事業者**の登録を受ける必要があり、
> 登録された事業者には**登録番号**が通知されます
> （出典：インボイス制度の概要／国税庁）。
> 卸売業では仕入先・得意先ともに数百社規模になるため、
> 取引先の登録状況をマスタで管理する必要が生じます。【Inference】

#### E-16. 商品マスタの登録と保守

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 新商品の取扱開始／仕入先からの商品情報（規格書、JANコード）の受領／規格変更（内容量・パッケージの変更）／取扱終了（廃番） |
| **② 誰が** | マスタ担当（受注・業務機能）／仕入・調達機能（商品情報の提供）／品質・衛生管理機能（規格書・表示内容の確認） |
| **③ 何を確認するか** | 商品コード／商品名（正式名称と略称）／**JANコード**／メーカー名／規格・内容量／**入数（1ケースに何個入りか）**／荷姿（ケース、ボール、バラ）／**温度帯（常温・冷蔵・冷凍）**／**賞味期限日数**／仕入先／仕切価格／標準売価／保管ロケーション／（該当時）ロット管理の要否 |
| **④ 何をするか** | 商品マスタに登録する。ケース入数・バラ単位の換算を設定する。温度帯と保管場所を登録する。既存商品の規格変更の場合は、切替時期と旧商品の扱いを決める |
| **⑤ 何を判断するか** | 旧商品と別コードにするか、同じコードで規格だけ変えるか（**在庫が混在する期間の扱い**）／いつから登録を有効にするか／廃番商品のコードをどう扱うか（削除するか、休止にするか） |
| **⑥ 誰と連携するか** | 仕入・調達機能（商品情報、仕切価格）／品質・衛生管理機能（規格書、表示、アレルゲン情報）／物流・倉庫機能（ロケーション、保管条件）／在庫管理機能（発注点・安全在庫の設定）／営業機能（売価の設定） |
| **⑦ 出来上がるもの** | **登録された商品マスタ**、新商品の取扱開始の社内周知 |

**用語**
**JANコード（ジャンコード）**
→ 商品に付いているバーコードの番号。**日本国内の商品を識別する共通の番号**です。
→ 実務例：レジやハンディターミナルでバーコードを読むと、この番号から商品が特定される。
　卸売業では、検品・棚卸・EDIでの商品の突き合わせに使います。

**用語**
**入数（いりすう）**
→ 1つの箱（ケース）に商品が何個入っているか。
→ 実務例：「醤油1L、6本入り」なら入数は6。
　**入数を間違えると、注文数量も在庫数も請求金額もすべてずれます。**

**なぜこの業務が必要なのか**

商品マスタは、**在庫・受注・出荷・請求のすべての単位を決めています**。【Inference】

> **【Example】**（説明用の架空例）
> ある商品の入数が「6本入り」から「12本入り」に変更された。
> このとき商品マスタを更新しないと、次のことが起きる。
> ・受注：「10ケース」の注文で、旧入数のまま60本と計算される（実際は120本）
> ・在庫：ケース数は合っているが、本数ベースの在庫が合わなくなる
> ・請求：ケース単価が変わっているのに旧単価で請求してしまう
> 規格変更は、**現物の切り替わりとマスタの切り替わりを合わせる**必要があります。

**なぜ「旧商品と新商品の扱い」が判断を要するのか**

パッケージ変更・規格変更が起きると、**倉庫には旧商品と新商品が同時に存在する期間**があります。
これを同じ商品コードで管理すると、どちらが出荷されるかを指定できません。
別コードにすると、旧商品を売り切るまで両方を管理することになります。
どちらを選ぶかは、切替期間の長さと在庫量によって判断されます。【Varies】

#### E-17. 価格マスタ（得意先別売価）の登録と保守

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 営業機能からの売価決定の連絡／新規取引の開始／新商品の導入／**特売価格の設定**／仕入価格の改定に伴う売価の見直し／得意先との価格交渉の妥結 |
| **② 誰が** | マスタ担当（受注・業務機能）／営業機能（価格の決定）／仕入・調達機能（仕切価格の提供）／営業部長・経営機能（一定水準を超える価格の承認）【Varies】 |
| **③ 何を確認するか** | どの得意先の、どの商品の、いくらか／**適用開始日と終了日**（特売価格には期間がある）／承認されている価格か／仕切価格に対して粗利が確保されているか／他の得意先の価格との整合 |
| **④ 何をするか** | 価格マスタに登録する。特売価格は期間を指定して登録する。適用開始前の受注に誤って新価格が当たらないよう、日付を確認する。登録後に営業へ完了を連絡する |
| **⑤ 何を判断するか** | 承認が必要な価格水準か（**仕切価格を下回っていないか**）／期間指定が正しいか／通常価格に戻すタイミングをどうするか／同じ商品の他の得意先への影響があるか |
| **⑥ 誰と連携するか** | 営業機能（価格の決定内容）／仕入・調達機能（仕切価格、特売仕切の適用期間）／経理・財務機能（粗利の確認）／経営機能（重要な価格の承認） |
| **⑦ 出来上がるもの** | **登録・更新された価格マスタ（得意先別売価）**、特売価格の期間設定、登録完了の連絡 |

**なぜこの業務が必要なのか ——「価格マスタが卸売業の心臓部である理由」**

`05_departments.md` §5-1 E-5 で述べたとおり、
卸売業では**同じ商品でも得意先ごとに売価が違います**。【Typical】

この価格が正しく登録されていないと、次のことが起きます。

| 登録の誤り | 何が起きるか |
|---|---|
| **売価が高すぎる** | 得意先が請求書を見て「話が違う」と言う。信用を失い、入金が遅れる |
| **売価が安すぎる** | 気づかないまま粗利が減り続ける。**誰も指摘しないため長期間続くことがある** |
| **特売価格の期間が切れていない** | 特売が終わっても安い価格で出し続けてしまう |
| **特売価格の登録漏れ** | 特売のはずが通常価格で請求される。得意先からの指摘で発覚する |
| **仕切価格を下回る売価** | 売れば売るほど損をする（**逆ザヤ**） |

**用語**
**逆ザヤ（ぎゃくざや）**
→ 売る価格が仕入価格を下回っている状態。売るたびに損が出ます。
→ 実務例：仕入2,400円の商品を2,350円で売っている状態。
　価格改定で仕入値が上がったのに売価を据え置いた場合などに起こり得ます。

> **【Fact】** 医薬品卸売業では、これに近い状態を**一次売差マイナス**と呼びます。
> 厚生労働省のガイドラインは、一次売差マイナスを
> 「納入価が仕切価よりも低い状況」と注記しています
> （出典：医療用医薬品の流通改善に向けて流通関係者が遵守すべきガイドライン／厚生労働省）。
> この状態では商品単体の粗利がマイナスになり、
> 割戻し（リベート）で補う構造になります。【Inference】

**登録件数の多さ**

> **【Example】**（説明用の架空例）
> モデル企業A食品商事は、得意先380社・取扱4,500SKU。
> すべての組み合わせに価格があるわけではないが、
> 実際に取引のある組み合わせだけでも数万件の価格データが存在する。
> ここに毎月、特売価格の登録と解除、価格改定、新商品の価格登録が加わる。
> **専任のマスタ担当を置く会社があるのは、この作業量のためです。**【Inference】

#### E-18. 売上データの確定と経理への引き渡し

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 納品完了（受領書の回収、検収データの受信）／日次の売上確定処理／締め日の到来 |
| **② 誰が** | 受注担当・業務部長／経理・財務機能（受け取り側） |
| **③ 何を確認するか** | 出荷したものがすべて売上になっているか／納品できなかったもの（積み残し、持ち帰り）が売上に含まれていないか／返品伝票・値引き伝票が反映されているか／受領書が全件回収されているか／得意先の検収データと自社の売上が一致しているか |
| **④ 何をするか** | 出荷実績・納品実績を売上データとして確定する。受領書を確認し、差異があるものを調査する。確定した売上データを経理・財務機能へ引き渡す |
| **⑤ 何を判断するか** | 売上をいつ計上するか（**出荷基準か、納品基準か、検収基準か**）／受領書が戻っていないものをどう扱うか／得意先との数量差異をどちらに合わせるか |
| **⑥ 誰と連携するか** | 物流・倉庫機能（出荷実績、受領書の回収）／営業機能（差異の確認）／経理・財務機能（売上の計上、請求） |
| **⑦ 出来上がるもの** | **確定した売上データ**、差異の一覧、受領書（保管） |

**なぜこの業務が必要なのか**

**「出荷した」と「売上になった」は同じではありません。**【Typical】

```
 【売上計上のタイミング（取引条件によって異なる）】【Varies】

  出荷基準       … 自社が出荷した時点で売上とする
  納品基準（着荷基準）… 得意先に届いた時点で売上とする
  検収基準       … 得意先が検収した時点で売上とする
```

どの基準を採るかによって、**月末をまたぐ取引の売上計上月が変わります**。
3月31日に出荷して4月1日に納品した取引は、
出荷基準なら3月の売上、納品基準なら4月の売上になります。【Inference】

また、**出荷したが売上にならないもの**も存在します。
得意先が不在で持ち帰った、数量違いで一部を持ち帰った、
納品先の受入時間に間に合わなかった、といった場合です。
これらを売上から除く処理をしないと、請求金額が実際の納品と合わなくなります。【Typical】

#### E-19. 得意先からの問い合わせ対応（納期照会・在庫照会・伝票再発行）

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 得意先からの電話・メールでの問い合わせ |
| **② 誰が** | 受注担当（内勤） |
| **③ 何を確認するか** | 何についての問い合わせか（納期、在庫、価格、伝票、請求金額）／該当する受注・出荷・請求のデータ／営業担当が既に対応していないか |
| **④ 何をするか** | システムで該当データを調べて回答する。伝票の再発行・再送付を行う。自分で判断できない内容は営業・経理・物流へ引き継ぐ |
| **⑤ 何を判断するか** | その場で答えられるか、確認してから折り返すか／自分の判断で答えてよい内容か（**価格・与信・クレームは営業や上長の判断が要る**）／誰に引き継ぐべきか |
| **⑥ 誰と連携するか** | 営業機能（価格・取引条件・クレーム）／物流・倉庫機能（配送状況）／経理・財務機能（請求・入金）／仕入・調達機能（入荷予定） |
| **⑦ 出来上がるもの** | 回答、再発行した伝票、（引き継いだ場合）担当部署への申し送り |

**なぜこの業務が必要なのか**

内勤は、**得意先にとって「いつでもつながる窓口」**です。【Typical】
営業担当は外出しているため、日中に電話しても捕まりません。
「注文した商品はいつ届くのか」「請求書をなくしたので再発行してほしい」といった
日常的な問い合わせは、内勤が受けることになります。

この問い合わせ対応の質が、そのまま**得意先から見た卸売業者の印象**になります。
「あそこに電話すればすぐ分かる」という状態を作ることが、
営業活動を側面から支えることになります。【Inference】

#### E-20. 定型的な補充発注の代行【Varies】

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 在庫が発注点を下回った（システムが発注候補として抽出）／仕入・調達機能からの依頼／定番商品の定例発注のタイミング |
| **② 誰が** | 受注担当（内勤）／判断が必要な部分は仕入・調達機能（バイヤー） |
| **③ 何を確認するか** | 発注候補リストの内容／発注点と現在の在庫／入荷予定に重複がないか／最低発注単位（ロット）／バイヤーが決めた発注ルール（この商品は自動で発注してよい、この商品は都度相談） |
| **④ 何をするか** | 定型的な補充発注を仕入先へ送信する（EDI、FAX、Web発注画面）。発注データを登録し、入荷予定を作る |
| **⑤ 何を判断するか** | ルールどおりに発注してよいか／異常な数量になっていないか／バイヤーに確認すべき案件か（特売の予定がある、価格改定が近い、終売が決まっている） |
| **⑥ 誰と連携するか** | 仕入・調達機能（発注方針、例外の判断）／在庫管理機能（発注点・安全在庫の設定）／物流・倉庫機能（入荷予定の連絡） |
| **⑦ 出来上がるもの** | **発注データ**、入荷予定データ |

**なぜこの業務が必要なのか（そして、なぜ【Varies】なのか）**

定番商品の補充発注は、**判断の余地が小さい作業**です。【Typical】
「在庫が発注点を切ったから、決められた数量を発注する」という機械的な処理であれば、
バイヤーが1件ずつ判断しなくても回ります。

そのため会社によっては、**判断が必要な発注（新商品、特売、価格交渉を伴うもの）をバイヤーが、
定型的な補充発注を内勤が**という分担を取ります。

> **【Varies】** この分担は会社によって大きく異なります。
> すべての発注をバイヤーが行う会社、在庫管理担当が行う会社、
> 内勤が代行する会社があります。
> 重要なのは「発注という機能は必ず存在する」ことであり、
> 誰が実行するかは組織の作り方次第です。

**用語**
**統一伝票（とういつでんぴょう）**
→ 業界や取引先グループで**様式を統一した納品伝票**のこと。
　卸売業者は、得意先ごとに違う伝票を使うより、統一された様式を使うほうが処理しやすくなります。
→ 実務例：「この得意先は指定の統一伝票で納品する決まりなので、専用用紙に印字する」。
　**得意先ごとに専用用紙をセットして印刷する作業が発生します。**【Typical】

### 業種による違い（Level 2）——受注・業務機能

| 比較軸 | **食品卸** | **建材卸** | **機械・工具卸** | **医薬品卸** | **アパレル卸** |
|---|---|---|---|---|---|
| **受注の性格** | **日次の大量受注処理**。1日に数千明細を処理することもある | **案件（物件）単位**の見積・受注管理。1件が長期にわたる | **型番指定の都度受注**＋定番消耗品の補充受注 | 日次の補充受注＋**緊急発注（急配）**への即応 | **シーズン前の先行受注**が中心。期中は追加受注 |
| **引当で見るもの** | 数量＋**賞味期限＋ロット**（納品期限基準を満たすか）【Fact】 | 数量＋**寸法・規格**（同じ品名でも長さ・厚みが違う） | 数量＋**型番の正確な一致**（互換品との区別） | 数量＋**使用期限＋ロット**（法令上の追跡が必要）【Fact】 | 数量＋**色・サイズ（SKU展開が非常に細かい）** |
| **納期回答の重さ** | 在庫販売が中心のため、当日〜翌日で完結することが多い | **非常に重い。** 工事工程に直結し、遅れると現場が止まる | **重い。** 特注品・機械本体は仕入先の生産次第 | 重い。緊急配送への対応が求められる | シーズンの投入時期を外せない |
| **マスタの難しさ** | SKU数が多い。パッケージ変更・規格変更が頻繁 | **寸法・規格の組み合わせが膨大**。同じ商品名で何十通りもある | **型番が数万〜数十万点**。廃番・後継品の対応付けが必要 | 薬価・規格・包装単位の管理。**制度改定のたびに一斉更新**【Typical】 | **色 × サイズ**の展開で1型が数十SKUになる |
| **伝票の特徴** | 得意先指定の統一伝票を使う取引が多い | **納品先が工事現場**のため、現場名・現場住所の管理が必要 | 型番・仕様の記載が長くなる | 法令に基づく記録の保存が必要【Fact】 | 色・サイズ別の明細で伝票が長くなる |
| **期限管理** | **必須。** 3分の1ルール等の納品期限基準を引当条件に組み込む【Fact】 | 原則として不要（一部の接着剤・塗料等を除く） | 原則として不要 | **必須。** ロットと使用期限の記録が法令上求められる【Fact】 | 不要（ただしシーズンという実質的な期限がある） |

> **【Fact】** 医薬品卸売業では、医薬品、医療機器等の品質、有効性及び安全性の確保等に関する法律
> （医薬品医療機器等法。通称「薬機法」）**第24条第1項**に基づく**卸売販売業の許可**が必要であり、
> 同法**第35条第1項**により、卸売販売業者は**営業所ごとに薬剤師を置き、
> その営業所を管理させなければならない**とされています
> （ただし卸売販売業者自身が薬剤師であって、自らその営業所を管理するときを除く）
> （出典：卸売販売業の許可／滋賀県、【医薬品医療機器等法】卸売販売業許可申請／千葉県）。

## 5-3. 仕入・調達機能（バイヤー）

---

### A. 部署・機能名

| 項目 | 内容 |
|---|---|
| **機能名（本資料の呼び方）** | 仕入・調達機能 |
| **一般的な部署名** | 商品部、仕入部、購買部、調達部、商品課、バイイング部門 |
| **担当者の一般的な呼び方** | **バイヤー**、仕入担当、商品担当、マーチャンダイザー（MD）、購買担当 |
| **モデル企業での呼称** | 商品部（3名。商品部長1名、バイヤー2名。常温／低温で分担） |

> **【Varies】** 独立した商品部があるとは限りません。
> 小規模な卸売会社では、**社長自身がバイヤーを兼ねている**ことが非常に多くあります。
> 「何をいくらで仕入れるか」は会社の利益を直接左右する判断であり、
> 中小企業ではこれを経営者が手放さない傾向があります【Typical】。
> また、営業担当が自分の担当商品の仕入も行う（営業とバイヤーの兼務）形もあります。

**用語**
**バイヤー**
→ **何を・どこから・いくらで・どれだけ仕入れるかを決める担当者**のこと。
→ 実務例：「調味料のバイヤーが、メーカーと来期の仕切価格を交渉している」。
　卸売業では、バイヤーが決めた仕入価格が粗利の出発点になるため、
　**会社の利益に最も直接的な影響を与える役割のひとつ**とされています【Typical】。

**用語**
**マーチャンダイザー（MD）**
→ 品揃え全体（どんな商品をどう組み合わせて売るか）を計画する役割。
　バイヤーと同義で使われることもあれば、バイヤーより広い企画の役割を指すこともあります【Varies】。

---

### B. 存在目的

> **「何を・どこから・いくらで・どれだけ仕入れるか」を決める。**
> 仕入価格が粗利の出発点であり、仕入量が在庫と資金を左右します。

卸売業は商品を作りません。**仕入れたものを売るだけ**です。
したがって、利益の源泉は次の2つしかありません。【Inference】

```
 卸売業の粗利 ＝ （売価 − 仕入価格）× 数量  ＋  リベート

   ① 売価を上げる   → 営業機能の仕事（ただし競争があり簡単には上がらない）
   ② 仕入価格を下げる → 仕入・調達機能の仕事
   ③ リベートを取る  → 仕入・調達機能の仕事
```

> **【Inference】** 卸売業の粗利率は相対的に薄いため、
> 仕入価格が1%下がることの利益への影響は、売上が1%増えることよりも大きくなります。
> これが「バイヤーは会社の利益を左右する」と言われる理由です。

さらに、仕入・調達機能には**もうひとつの重い責任**があります。

> **仕入れすぎれば在庫と資金が寝る。仕入れが足りなければ欠品して信用を失う。**
> この2つの間でバランスを取るのが、在庫を持つ卸売業の宿命です。【Typical】

---

### C. 担当者

| 役職・担当 | 主な役割 |
|---|---|
| **商品部長／仕入部長** | 商品構成（品揃え）全体の方針、主要仕入先との交渉、リベート条件の決定、在庫金額の管理 |
| **バイヤー（商品担当）** | 担当カテゴリーの商品選定、発注、価格交渉、販促企画、在庫の適正化 |
| **発注担当（事務）** | 定型的な補充発注の実行、入荷予定の管理【Varies】 |
| **社長・役員** | 主要メーカーとの取引条件の最終決定、特約店契約の締結 |

> **【Example】** モデル企業A食品商事の商品部3名の内訳
> ・商品部長 1名（主要メーカー約15社との交渉、リベート管理、品揃え方針、食品表示の確認を兼務）
> ・バイヤー 2名（常温商品担当1名、冷蔵・冷凍商品担当1名）
> バイヤー1人あたり約1,500SKUを見ている計算になる。

> **【Inference】** 1人で1,000点以上の商品の価格・在庫・販促を見るため、
> すべての商品を同じ深さで見ることは物理的にできません。
> そのため実務では、**売上・粗利の大きい商品に時間を割き、
> 残りは発注点にもとづく定型処理に任せる**という濃淡が付けられます。

#### E-1. 発注点・安全在庫にもとづく補充発注

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 在庫が**発注点**を下回った（システムが発注候補として抽出）／定例の発注サイクルの到来／在庫データの日次確認 |
| **② 誰が** | バイヤー（判断）／システム（候補の抽出）／受注・業務機能や在庫管理機能が代行する場合もある【Varies】 |
| **③ 何を確認するか** | 引当可能在庫と入荷予定／直近の出荷実績（売れるペースが変わっていないか）／これから予定されている特売・販促の数量／仕入先の**調達リードタイム**／**最低発注単位（MOQ）**／仕入先の休業日・締切時刻／賞味期限の残り（食品の場合） |
| **④ 何をするか** | 発注候補リストを確認する。数量を決める（システムの推奨数量をそのまま使う／特売や季節要因を加味して増減する）。仕入先へ発注する |
| **⑤ 何を判断するか** | 発注するか、見送るか（もうすぐ終売になる商品、次の特売で安く仕入れられる商品は見送ることがある）／いくつ発注するか／最低発注単位との兼ね合いをどうするか（**5ケース欲しいが10ケース単位でしか買えない場合にどうするか**）／まとめ買いで単価を下げるか、小刻みに買って在庫を抑えるか |
| **⑥ 誰と連携するか** | 在庫管理機能（在庫数・発注点の設定）／営業機能（今後の販売見込み、特売の予定）／受注・業務機能（欠品情報）／物流・倉庫機能（入荷予定の連絡、保管スペースの確認）／経理・財務機能（資金繰りへの影響） |
| **⑦ 出来上がるもの** | **発注データ（注文書）**、**入荷予定データ** |

**用語（`04_end-to-end-process.md` §4-1 の再掲）**
**発注点（はっちゅうてん）**
→ 「在庫がこの数まで減ったら発注する」という基準の数量。
→ 実務例：ある調味料は1日平均10ケース売れる。発注してから届くまで3日かかる。
　3日分＝30ケース。これに安全在庫20ケースを足して、発注点を50ケースに設定する。

**用語**
**調達リードタイム**
→ 発注してから商品が自社に届くまでの日数。
→ 実務例：「この仕入先は発注から3営業日で届く」「輸入品は発注から45日かかる」。
　**リードタイムが長いほど、先を読んで発注しなければならず、読み違いのリスクが大きくなります。**

**用語**
**最低発注単位（MOQ：Minimum Order Quantity）**
→ 仕入先が受け付ける最小の発注数量。
→ 実務例：「この商品は10ケース単位でしか発注できない」。
　5ケースしか必要なくても10ケース仕入れることになり、余剰在庫の原因になります。

**なぜこの業務が必要なのか**

在庫がゼロになってから発注したのでは、**届くまでの間に必ず欠品します。**【Typical】

```
 【発注点の考え方】

 在庫数
   ▲
   │╲
   │ ╲                                    ← 毎日少しずつ売れて減っていく
   │  ╲
   │───╲──────────────── 発注点      ← ここを切ったら発注する
   │    ╲          ▲
   │     ╲         │ 調達リードタイム（発注してから届くまで）
   │      ╲        │
   │───────╲─────┴─────── 安全在庫  ← この線より下に行かないようにする
   │        ╲    ／
   │         ╲  ／  ← 入荷して在庫が回復
   └──────────────────────────▶ 時間
```

**なぜ人の判断が必要なのか**

発注点を切ったら自動で発注する、という仕組みだけでは足りません。
理由は、**発注点は「これまでどおり売れる」という前提で計算されているから**です。【Inference】

| 前提が崩れる場面 | バイヤーが加える判断 |
|---|---|
| 来月に大きな特売がある | 通常の発注量では足りない。先に多めに仕込む |
| 競合商品が値下げされた | 売れ行きが落ちる可能性。発注量を抑える |
| メーカーが値上げを発表した | 値上げ前にまとめて仕入れるか検討する |
| 商品が終売になると連絡が来た | 発注を止め、在庫を売り切る計画に切り替える |
| 季節が終わる | 発注を止める。残った在庫の処分を考える |

> **【Varies】** 発注点・安全在庫の設定方法（計算式を使うか、担当者の経験で決めるか、
> 商品ごとに設定するか）は企業により大きく異なります。

#### E-2. 都度発注（受注対応の発注）・直送手配

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 在庫を持たない商品の受注が入った／大ロットの注文で在庫では賄えない／得意先の指定で特定の商品を取り寄せる必要がある／直送の依頼 |
| **② 誰が** | バイヤー／受注・業務機能（納期回答の依頼元） |
| **③ 何を確認するか** | 仕入先の在庫と納期／仕入価格（都度の見積が必要な商品もある）／得意先の希望納期に間に合うか／自社倉庫を経由するか直送にするか／直送の場合の納品先住所・納品日時・荷受けの条件 |
| **④ 何をするか** | 仕入先に在庫と納期を確認する。見積を取る。発注する。直送の場合は納品先・納品日を指定して発注する。納期を受注・業務機能へ回答する |
| **⑤ 何を判断するか** | どの仕入先から買うか（同じ商品を複数から買える場合、価格と納期を比べる）／倉庫を経由するか直送にするか／急ぐ場合に送料を負担してでも早い便を使うか |
| **⑥ 誰と連携するか** | 受注・業務機能（納期回答）／営業機能（得意先との納期調整）／物流・倉庫機能（入荷予定、直送の場合は入荷しないことの共有）／経理・財務機能（直送時の仕入・売上の計上） |
| **⑦ 出来上がるもの** | **発注データ**、入荷予定データ（倉庫経由の場合）、**直送指示**、納期回答 |

**用語**
**直送（ちょくそう）**
→ 商品の現物が、**メーカー（仕入先）から得意先へ直接届く**こと。
　伝票（商流）は卸売業者を通りますが、現物は卸売業者の倉庫を通りません。
→ 実務例：「大型の業務用冷凍庫は、メーカーから飲食店へ直送してもらう」。
　**卸売業者の倉庫に入らないため、入荷検品も保管もピッキングも発生しません。**

**なぜこの業務が必要なのか**

すべての商品を在庫で持つことはできません。【Typical】

| 在庫を持たない商品の例 | 理由 |
|---|---|
| 取扱頻度が低い商品 | 持っても回転せず、資金が寝る |
| 大型・重量物 | 保管スペースを大きく取る |
| 特注品・別注品 | その注文にしか使えない |
| 高額品 | 在庫として持つと資金負担が大きい |
| 期限が極端に短い商品 | 在庫のまま期限切れになる |

これらは**受注してから仕入れる（都度仕入）**形になります。
`04_end-to-end-process.md` §4-3 の「パターンB：都度仕入」がこれにあたります。

**直送を選ぶ理由と、選ばない理由**【Typical】

```
 【直送を選ぶ場合】
  ・大型で自社倉庫に入らない
  ・数量が多く、倉庫を経由すると二度手間になる
  ・納品先が自社の配送エリア外
  ・急いでおり、倉庫経由では間に合わない

 【直送を選ばない場合】
  ・納品先が複数に分かれており、小口配送になってしまう
  ・他の商品と一緒に配送したほうが効率的
  ・自社で検品してから納品したい（品質の確認が必要）
  ・得意先が納品時間を指定しており、メーカーの配送では合わない
```

> **【Example】**（`04_end-to-end-process.md` §4-4 の例）
> Bスーパー4店舗への鍋つゆ200ケースの納品で、A社は直送を選ばなかった。
> 1店舗あたり40〜60ケースであり、メーカーから4店舗へ直送すると小口配送になり、
> かつ醤油・味噌など他の商品と一緒に配送できないためです。

#### E-3. 新商品の発掘と仕入交渉（取扱の決定）

| 観点 | 内容 |
|---|---|
| **① きっかけ** | メーカーからの新商品案内／展示会・商談会での接触／営業機能からの「得意先がこの商品を欲しがっている」という要望／競合が扱っている商品の情報／既存商品の終売に伴う代替の必要 |
| **② 誰が** | バイヤー／商品部長（採用の決定）／社長（重要な商品・大きな取引の場合） |
| **③ 何を確認するか** | 商品の規格（内容量、入数、荷姿、温度帯、賞味期限日数）／**仕切価格と想定できる売価、そこから出る粗利**／最低発注単位と調達リードタイム／メーカーの販促支援（サンプル、什器、販促費、リベート）／類似商品との重複／**売れる見込み**（既存得意先の何社が採用しそうか） |
| **④ 何をするか** | メーカーと商談する。サンプルと規格書を入手する。価格と条件を交渉する。営業機能に売れ行きの見込みを確認する。取扱を決めたら初回の仕入数量を決め、商品マスタの登録を依頼する |
| **⑤ 何を判断するか** | 取り扱うか、見送るか／初回いくつ仕入れるか（**売れなければ在庫になる**）／既存商品を落として入れ替えるか、追加するか／在庫を持つ商品にするか、都度仕入にするか／独占的に扱えるか（他の卸も扱うのか） |
| **⑥ 誰と連携するか** | 営業機能（売れ行きの見込み、得意先の反応）／受注・業務機能（商品マスタ・価格マスタの登録）／品質・衛生管理機能（規格書・表示・アレルゲンの確認）／物流・倉庫機能（保管条件・保管スペース）／在庫管理機能（発注点の設定）／経営機能（重要な採用の判断） |
| **⑦ 出来上がるもの** | **取扱決定（採用の可否）**、仕切価格の合意、**商品マスタ登録の依頼**、初回発注、商品情報（規格書、JAN、サンプル）の社内展開 |

**なぜこの業務が必要なのか**

卸売業の品揃えは、**放っておくと古くなります。**【Inference】
メーカーは毎年新商品を出し、既存商品は終売になっていきます。
新しい商品を入れ続けなければ、取扱商品が減り、得意先の要望に応えられなくなります。

一方で、**新商品には必ず在庫リスクが伴います。**
売れる保証がない商品を仕入れるため、売れなければそのまま滞留在庫になります。
そのためバイヤーは、「売れそうか」だけでなく
「売れなかったときにどうするか」（返品できるか、値下げで処分できるか）まで含めて判断します。【Typical】

> **【Typical】** 中小卸売業では、新商品の採用を決める前に
> **営業担当に「この商品、お宅の得意先で何社くらい採用しそうか」と確認する**ことが多くあります。
> バイヤーには売場が見えないため、営業の感触が初回発注数量の根拠になります。

#### E-4. 仕入価格（仕切価格）の交渉

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 新商品の取扱開始／年度・期の変わり目の定期交渉／メーカーからの価格改定（値上げ）の申し入れ／得意先から値下げを求められ、原価を下げる必要が生じた／仕入数量が大きく変わった／特売の引合 |
| **② 誰が** | バイヤー（日常の交渉）／商品部長（主要商品・大口の交渉）／社長（重要メーカーとの交渉、特約店契約に関わる交渉） |
| **③ 何を確認するか** | 現在の仕切価格／**自社の仕入数量の実績と見込み**（交渉の材料になる）／他の仕入ルートの価格（同じ商品を一次卸からも買える場合）／メーカーの建値と市場の実勢価格／リベートを含めた実質的な仕入価格／得意先に出している売価と、そこから出る粗利 |
| **④ 何をするか** | メーカー・一次卸と交渉する。数量を提示して価格を引き出す。リベートとの組み合わせを詰める。合意した価格を受注・業務機能へ伝え、マスタに登録してもらう |
| **⑤ 何を判断するか** | どこまで粘るか／価格を下げる代わりに数量を約束してよいか（**約束した数量が売れなければ在庫になる**）／リベートで受けるか、仕切価格そのものを下げてもらうか／仕入先を変えるか |
| **⑥ 誰と連携するか** | 営業機能（売価との整合、数量の見込み）／受注・業務機能（仕切価格・売価のマスタ更新）／経理・財務機能（仕入計上単価、粗利の確認）／経営機能（重要な条件の決定） |
| **⑦ 出来上がるもの** | **合意した仕切価格**、価格改定の通知、マスタ更新の依頼、（該当時）数量の約束 |

**用語（`02_industry-structure.md` §11-6-1 の再掲）**
**仕切価格（しきりかかく／仕切価）**
→ **メーカーが卸売業者に売る価格**、あるいは**卸売業者が得意先に売る価格**のこと。
　立場によって「仕入側から見た仕切」「販売側から見た仕切」の両方の使い方をします。
→ 実務例：「A社からの仕切は2,400円、うちからB商店への仕切は2,700円」。

**なぜこの業務が必要なのか**

```
 【仕入価格1%の重み】【Example】（説明用の架空例）

  年間仕入高 35億円の会社で、仕入価格が平均1%下がったとすると

    35億円 × 1% ＝ 3,500万円

  → 同じ金額の粗利を売上増で作ろうとすると、粗利率10%なら
     3億5,000万円の売上増が必要になる
```

**仕入価格の交渉は、売上を増やすよりも直接的に利益に効きます。**【Inference】
だから中小卸売業では、社長自身が主要メーカーとの価格交渉に出てくることが多いのです。

**「リベートで受けるか、仕切で受けるか」という判断**

同じ金額を引き出すにも、2つの受け取り方があります。【Typical】

| 受け方 | 見え方 | 実務上の違い |
|---|---|---|
| **仕切価格を下げてもらう** | 商品ごとの粗利にすぐ表れる | 売価の設定がしやすい。得意先への価格提示に反映できる |
| **リベートで後から受ける** | 商品ごとの粗利には表れない | 期末にまとめて利益になる。**達成しないともらえない条件が付くことがある** |

> **【Fact】** 厚生労働省の「医療用医薬品の流通改善に向けて流通関係者が遵守すべきガイドライン」
> （平成30年1月23日施行、令和8年3月4日改訂）では、
> 「**割戻し（リベート）は卸機能の適切な評価に基づくものとし、割戻し、アローアンスのうち
> 仕切価に反映可能なものについては仕切価へ反映した上で、整理・縮小を行う**」ことなどが示されています
> （出典：医療用医薬品の流通改善に向けて流通関係者が遵守すべきガイドライン／厚生労働省）。

#### E-5. リベート・販売奨励金の交渉と管理

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 年度・期の初めの条件交渉／新商品の導入時／特売・販促の実施時／期間の区切り（四半期・半期・年次）での精算／メーカーからのリベート制度の案内 |
| **② 誰が** | バイヤー・商品部長（交渉）／経理・財務機能（計上・入金確認）／社長（重要な条件の決定） |
| **③ 何を確認するか** | **リベートの種類と条件**（何を達成すれば、いくらもらえるのか）／対象期間／対象商品／達成基準（仕入高か、販売数量か、新商品の導入店数か）／現在の達成状況／支払方法（現金入金か、買掛金との相殺か） |
| **④ 何をするか** | メーカーと条件を交渉し、書面で確認する。期中は達成状況を追う。達成が危うい場合は営業機能と販売の強化を相談する。期末に実績を集計してメーカーと金額を確認し、精算を受ける |
| **⑤ 何を判断するか** | 条件を受け入れるか（**達成できない条件を受けても意味がない**）／達成のために追加の仕入をするか（在庫になるリスクを取るか）／どの期間の利益として計上するか／リベートを見込んで売価を下げてよいか |
| **⑥ 誰と連携するか** | 営業機能（販売の強化、得意先への販促）／経理・財務機能（リベートの計上、入金・相殺の確認）／経営機能（条件の承認）／受注・業務機能（対象商品の販売実績の集計） |
| **⑦ 出来上がるもの** | **リベート条件の合意（覚書）**、達成状況の管理資料、**リベート精算の資料**、リベート収入の計上依頼 |

**用語（`02_industry-structure.md` §11-6-2 の再掲）**
**リベート**
→ 商品の売買代金とは**別に**、一定期間後に仕入先から卸売業者へ
　（または卸売業者から得意先へ）支払われる金銭のこと。「販売奨励金」「割戻し」とも呼びます。
→ 実務例：「今期の仕入高が1億円を超えたので、メーカーから2%のリベートが支払われた」。

**リベートの代表的な種類**【Typical】

| 種類 | 支払いの条件 |
|---|---|
| 数量リベート・累進リベート | 一定期間の仕入高・販売数量が基準を超えた場合 |
| 販売促進リベート | 特売・陳列・新商品導入など、販促活動への協力に対して |
| 決済リベート | 早期に支払った場合、現金決済した場合 |
| 目標達成リベート | あらかじめ設定された目標を達成した場合 |

**なぜこの業務が必要なのか ——「商品別粗利では利益が分からない」**

リベートは商品ごとの粗利には表れず、**期間がたってからまとめて入ってきます。**【Typical】
そのため、次の状態が起こり得ます。

```
 【商品別粗利と、最終的な利益の乖離】【Example】（説明用の架空例）

  ある商品の商品別粗利         年間 200万円（粗利率 4%）
  期末に受け取ったリベート     年間 150万円
  ─────────────────────────────
  実質的な利益                 年間 350万円（実質粗利率 7%）

  → 商品別粗利だけを見ると「この商品は儲かっていない」と見えるが、
     リベートを含めると別の姿になる
```

この乖離があるため、バイヤーは**「リベートを含めた実質的な仕入価格」**を常に頭に置いています。
同時に、この乖離が**卸売業の利益管理を難しくする一因**にもなっています。【Inference】

**期末に達成を追いかける状況**

リベートには「期間の仕入高が○円を超えたら」という条件が付くことがあります。
期末が近づいて達成が微妙な場合、**追加で仕入れて達成する**という選択肢が生まれます。
しかしそれは在庫を増やす行為でもあり、資金を寝かせることになります。
ここが、バイヤーが判断を迫られる場面のひとつです。【Typical】

> **【Fact】** 公正取引委員会の指針では、リベートは
> 「**仕切価格とは区別されて取引先に制度的に又は個別の取引ごとに支払われる金銭**」と説明されています。
> また、**リベートの供与自体が直ちに独占禁止法上問題となるものではない**としつつ、
> 供与の方法によっては取引先事業者の事業活動を制限することとなり問題となる場合があるとされ、
> **供与の基準を明確にし、取引の相手方に示すことが望ましい**とされています
> （出典：流通・取引慣行に関する独占禁止法上の指針／公正取引委員会）。

#### E-6. 欠品時の代替調達・緊急発注

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 受注・業務機能からの欠品連絡／営業機能からの緊急の依頼／仕入先からの入荷遅延・出荷調整の通知／予想外の大量受注 |
| **② 誰が** | バイヤー |
| **③ 何を確認するか** | 不足数量と必要な期日／通常の仕入先の在庫・出荷可能日／**別ルートで手に入るか**（他のメーカー、一次卸、同業の卸、他の拠点）／代替できる商品があるか（同等品、別規格、別メーカー）／緊急手配にかかる追加コスト（送料、割高な仕入価格） |
| **④ 何をするか** | 通常の仕入先に出荷の前倒しを依頼する。難しければ別ルートを当たる。代替品の提案を営業へ返す。手配できたら納期を受注・業務機能へ伝える |
| **⑤ 何を判断するか** | どこまでコストをかけて手配するか（**送料が粗利を上回ることがある**）／代替品で対応するか／分納にするか／断るか／同業の卸から融通してもらうか |
| **⑥ 誰と連携するか** | 受注・業務機能（納期の回答、受注データの修正）／営業機能（得意先との調整、代替品の了承取り付け）／物流・倉庫機能（緊急入荷の受入、臨時の配送）／在庫管理機能（他の受注の引当の振替） |
| **⑦ 出来上がるもの** | **緊急発注**、代替品の手配、納期回答、（該当時）他ルートからの調達 |

**用語**
**横持ち（よこもち）**
→ 同業の卸売業者どうしで、在庫を融通し合うこと。
→ 実務例：「近隣のD卸に電話して、醤油を10ケース分けてもらった」。
　自社に在庫がなく、メーカーからの入荷も間に合わないときの手段です【Varies】。

**なぜこの業務が必要なのか**

欠品対応は、**卸売業の信用に直結します。**【Typical】
特に、得意先がチラシに載せている商品、飲食店の看板メニューに使う食材が欠品すると、
得意先の営業そのものに影響します。

一方で、緊急調達は**採算を度外視することがある**業務でもあります。

> **【Example】**（説明用の架空例）
> 粗利300円／ケースの商品を10ケース緊急手配するのに、
> チャーター便の運賃が15,000円かかる場合、
> その取引の粗利3,000円に対して15,000円のコストがかかる。
> **この1件だけを見れば損失だが、得意先との関係を守るために実施することがある。**

こうした判断は、**その取引単体の採算ではなく、取引全体の継続性**を踏まえて行われます。【Inference】

#### E-7. メーカーの販促情報の入手と社内展開

| 観点 | 内容 |
|---|---|
| **① きっかけ** | メーカー担当者の訪問／メーカーからの案内（新商品、キャンペーン、テレビ広告の開始、増量企画）／展示会・商談会／業界紙・専門誌 |
| **② 誰が** | バイヤー・商品部長 |
| **③ 何を確認するか** | 企画の内容と期間／対象商品／メーカーが提供する支援（販促費、什器、POP、サンプル、リベート）／**卸売業者に求められる条件**（一定数量の仕入、陳列の実施、導入店数）／広告の投下時期（**テレビ広告が始まると売れ行きが変わる**） |
| **④ 何をするか** | 情報を整理して営業機能へ展開する。企画に乗るかどうかを判断する。乗る場合は必要数量を仕込む。販促物を手配する |
| **⑤ 何を判断するか** | 企画に乗るか／どれだけ仕込むか（**広告に合わせて売れると読んで仕入れ、読み違えれば在庫になる**）／どの得意先に提案してもらうか |
| **⑥ 誰と連携するか** | 営業機能（得意先への展開、販促物の配布）／在庫管理機能（数量の確保）／物流・倉庫機能（販促物の保管、什器の配送）／受注・業務機能（企画価格の登録） |
| **⑦ 出来上がるもの** | **販促情報の社内展開資料**、企画への参加の可否、仕込みの発注、販促物の手配 |

**なぜこの業務が必要なのか**

**メーカーの広告と、卸売業者の在庫は連動していなければなりません。**【Inference】

テレビ広告が始まると、消費者が店頭でその商品を探します。
小売店は注文を増やし、その注文は卸売業者に来ます。
このとき卸売業者に在庫がなければ、**広告が打たれているのに商品が棚にない**という状況が生まれ、
得意先からもメーカーからも指摘を受けることになります。

逆に、広告に合わせて仕入れたのに売れ行きが伸びなければ、そのまま在庫になります。
**販促情報を早く正確に入手し、どれだけ仕込むかを決めること**が、
バイヤーの読みの部分になります。【Typical】

#### E-8. 季節商品・特売の仕込み（先行仕入）

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 季節の到来に向けた準備時期（暑くなる前、鍋物の季節の前、年末年始、行楽期）／営業機能からの特売の引合／得意先の販促計画の共有／メーカーからの季節企画の案内 |
| **② 誰が** | バイヤー・商品部長／営業機能（数量の見込みの提供） |
| **③ 何を確認するか** | 前年同時期の販売実績／今年の得意先の販促計画／メーカーの生産・出荷スケジュール（**季節商品は生産期間が限られる**）／まとめ発注による仕切価格の優遇条件／**倉庫の保管スペース**／賞味期限（シーズンが終わったときにどれだけ残るか） |
| **④ 何をするか** | 必要数量を見積もる。メーカーと数量・価格・納期を交渉する。まとめて発注する。入荷に合わせて倉庫のスペースを確保してもらう。シーズン中の追加発注の可否を確認しておく |
| **⑤ 何を判断するか** | いくつ仕込むか（**ここが最も難しい判断**）／まとめ買いで単価を下げるか、小刻みに買って残りを抑えるか／シーズン終了後に残った場合の処分方法（値下げ、返品交渉、翌年持ち越し）／保管スペースが確保できるか |
| **⑥ 誰と連携するか** | 営業機能（販売見込み、得意先の計画）／物流・倉庫機能（保管スペース、入荷の受入体制）／在庫管理機能（期限管理）／経理・財務機能（**大量仕入に伴う資金繰り**）／経営機能（大きな仕込みの承認） |
| **⑦ 出来上がるもの** | **先行発注**、シーズンの在庫計画、保管スペースの確保依頼、（該当時）特売価格の設定 |

**なぜこの業務が必要なのか ——「読み違えたときの影響が最も大きい業務」**

季節商品には、**売れる期間が決まっている**という特徴があります。【Typical】

```
 【季節商品の仕込みが難しい理由】

  ① 生産期間が限られる     → シーズン中に追加発注しても作ってもらえないことがある
  ② シーズンを過ぎると売れない → 残った在庫は値下げするか廃棄するしかない
  ③ まとめ買いで単価が下がる   → たくさん買いたい誘惑がある
  ④ 保管スペースを圧迫する     → 他の商品の保管に影響する
  ⑤ 資金が先に出ていく         → 売れて入金されるのは数か月後
```

> **【Example】**（説明用の架空例）
> 鍋つゆを1,000ケース仕込んだ。仕切価格は通常より150円安い。
> ・900ケース売れた場合：仕入の割安分で135,000円の利益上積み
> ・600ケース売れた場合：残り400ケースは翌シーズンまで保管するか、値下げ処分になる
> 　賞味期限が翌シーズンまで持たなければ、廃棄の可能性もある
>
> **同じ「安く買えた」という条件でも、売れた量によって結果が正反対になります。**

この判断のために、バイヤーは**前年実績と営業の見込みを突き合わせます**。
どちらも確実ではないため、最終的には経験にもとづく判断が入ります。【Typical】

#### E-9. 在庫の適正化判断

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 在庫データの定期確認／在庫金額が計画を超えた／滞留在庫・期限接近在庫のリストが上がってきた／経理・財務機能からの在庫圧縮の要請／棚卸の結果 |
| **② 誰が** | バイヤー・商品部長／在庫管理機能（データの抽出）／経営機能（方針） |
| **③ 何を確認するか** | **商品別の在庫回転**（どれだけの期間で在庫が入れ替わっているか）／動きのない在庫（**デッドストック**）／期限が近い在庫／在庫金額の総額と、資金への影響／発注点・安全在庫の設定が現状と合っているか／仕入先ごとの最低発注単位 |
| **④ 何をするか** | 在庫を分類する（よく動く／あまり動かない／まったく動かない）。動かない在庫について処置を決める（値下げ販売、特売への投入、仕入先への返品交渉、廃棄）。発注点・安全在庫を見直す。発注を止める商品を決める |
| **⑤ 何を判断するか** | どの商品の在庫を減らすか／値下げしてでも売るか、持ち続けるか／仕入先に返品交渉できるか／取扱そのものをやめるか／発注点を上げるか下げるか |
| **⑥ 誰と連携するか** | 在庫管理機能（データ、滞留リスト）／営業機能（売り切るための販売努力）／経理・財務機能（在庫金額、評価損・廃棄損の計上）／物流・倉庫機能（保管スペース、廃棄の実務）／経営機能（大きな処分の判断） |
| **⑦ 出来上がるもの** | **在庫の処置方針**、発注点・安全在庫の見直し、値下げ・返品交渉・廃棄の指示、在庫計画 |

**用語**
**在庫回転率・在庫回転日数**
→ 在庫が何日で入れ替わるかを表す数字。
→ 実務例：「在庫回転日数30日」＝今ある在庫は、平均すると30日分の販売量にあたる。
　**日数が長いほど、資金が長く寝ていることになります。**

**用語**
**デッドストック（不動在庫・死蔵在庫）**
→ まったく動かなくなった在庫のこと。
→ 実務例：「3年前に仕入れた商品が、倉庫の奥に20ケース残っている」。
　**帳簿上は資産だが、実際には売れる見込みがない**という状態です。

**なぜこの業務が必要なのか ——「在庫は資産であり、同時に資金である」**

在庫は帳簿上は**資産**ですが、実態は**現金が形を変えたもの**です。【Inference】

```
 【在庫が資金を固定する仕組み】

  現金 ──仕入──▶ 在庫 ──販売──▶ 売掛金 ──入金──▶ 現金
                   ▲
                   └─ ここに留まっている間、その分の現金は使えない
```

在庫が増えるほど、手元の現金は減ります。
にもかかわらず、在庫を減らしすぎれば欠品が増えます。
**この綱引きの真ん中に立っているのがバイヤー**です。【Typical】

| 在庫が多すぎると | 在庫が少なすぎると |
|---|---|
| 資金が寝る（借入が必要になることもある） | 欠品が増える |
| 保管スペースを圧迫する | 得意先の信用を失う |
| 期限切れ・劣化のリスクが増える | 緊急調達のコストがかかる |
| 廃棄・値下げの損失が出る | まとめ買いによる仕入単価の引き下げができない |
| 棚卸の作業量が増える | 営業が提案しにくくなる |

#### E-10. 仕入先の選定・評価・新規開拓

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 新しい商品カテゴリーを扱うことになった／既存の仕入先の条件が合わなくなった／欠品・納期遅れが続いている／展示会・商談会での接触／メーカーからの直接取引の申し入れ |
| **② 誰が** | バイヤー・商品部長／社長（重要な取引先の決定） |
| **③ 何を確認するか** | 取扱商品の幅と価格／納期と欠品の状況／最低発注単位と配送条件／支払条件（締め日、支払サイト、支払方法）／リベートの有無／**直接取引（一次卸）になれるか、一次卸経由（二次卸）になるか**／相手の信用状態 |
| **④ 何をするか** | 商談する。条件を比較する。試験的に取引を始める。取引実績を見て評価する。既存の仕入先との関係を整理する |
| **⑤ 何を判断するか** | どの仕入先から買うか／同じ商品を複数のルートから買えるようにしておくか（**1社に依存するリスク**）／直接取引を目指すか／既存の仕入先を切り替えるか |
| **⑥ 誰と連携するか** | 経理・財務機能（支払条件、仕入先マスタの登録）／物流・倉庫機能（納品条件、荷姿）／営業機能（商品の売れ行きの見込み）／経営機能（重要な取引先の決定） |
| **⑦ 出来上がるもの** | **仕入先の決定**、取引条件の合意、仕入先マスタの登録依頼、（該当時）取引基本契約書 |

**なぜこの業務が必要なのか**

**1社の仕入先に依存すると、その1社の都合で自社の商売が止まります。**【Inference】

| 依存によるリスク | 具体的に起きること |
|---|---|
| その仕入先が欠品した | 自社も欠品する。代替ルートがない |
| 値上げを申し入れられた | 断れない。他から買えないため |
| 取引を止められた | その商品カテゴリー全体を失う |
| 仕入先が倒産した | 商品が入らなくなる。前払金があれば損失になる |

一方で、複数の仕入先から買うと、1社あたりの仕入額が分散し、
**まとめ買いによる価格の優遇やリベートの条件を満たしにくくなります**。【Typical】
この「集約するか、分散するか」の判断も仕入・調達機能の仕事です。

#### E-11. 特約店・代理店契約の維持と交渉

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 契約の更新時期／メーカーからの条件変更の申し入れ／販売実績が契約上の目標に届いていない／新たに特約店になる商談／テリトリー（販売エリア）に関する協議 |
| **② 誰が** | 商品部長・社長（契約に関わるため経営判断） |
| **③ 何を確認するか** | 契約の内容（**販売エリア、取扱商品の範囲、販売目標、価格条件、リベート条件、期間**）／自社の販売実績が目標に対してどうか／メーカーが自社に期待している役割／同じエリアの他の特約店の状況 |
| **④ 何をするか** | 実績を整理してメーカーと協議する。条件を交渉する。契約を更新する。社内に条件を周知する |
| **⑤ 何を判断するか** | 契約を続けるか／目標をどこまで約束するか（**達成できない目標を約束すると、後で条件が悪化する**）／エリアの拡大・縮小を受け入れるか／他メーカーの競合商品を扱ってよい契約か |
| **⑥ 誰と連携するか** | 営業機能（実績、販売の見込み）／経営機能（契約の締結）／経理・財務機能（リベートの精算、支払条件） |
| **⑦ 出来上がるもの** | **更新された特約店契約・代理店契約**、販売目標の合意、条件の社内周知 |

**用語（`02_industry-structure.md` §11-2-3 の再掲）**
**特約店・代理店契約**
→ メーカーと卸売業者の間で結ばれる、**継続的な取引の枠組みを定めた契約**。
　「この商品を、このエリアで、この条件で扱う」という取り決めをします。
→ 実務例：「当社はX調味料の県内特約店です」。
　特約店になると、メーカーから直接仕入れられる（一次卸になる）ことが多くなります。

> **【Varies】** 「特約店」「代理店」「販売店」「特約卸」といった名称と、
> その実態（どこまでの権利・義務があるか）は業界・メーカーによって異なります。
> **名称だけで内容を判断せず、契約の中身を確認する必要があります。**

**なぜこの業務が必要なのか**

特約店契約は、**卸売業者の商売の土台**です。【Typical】

```
 【特約店であることの意味】【Example】（説明用の架空例）

  特約店の場合（一次卸）
    メーカー ──仕切 2,400円──▶ 自社 ──2,700円──▶ 得意先
                                          粗利 300円

  特約店でない場合（二次卸）
    メーカー ──▶ 一次卸 ──仕切 2,550円──▶ 自社 ──2,700円──▶ 得意先
                                                     粗利 150円
```

同じ商品を同じ価格で売っても、**仕入ルートが1段違うだけで粗利が変わります**。
そのため、主力商品について特約店の地位を維持することは、
中小卸売業にとって利益の確保に直結します。【Inference】

同時に、特約店には**義務**も伴います。
販売目標、エリアでの販売活動、在庫の保有、販促への協力などです。
これらを果たせなければ、契約の見直しを申し入れられることがあります。【Typical】

#### E-12. 商品の終売・廃番への対応

| 観点 | 内容 |
|---|---|
| **① きっかけ** | メーカーからの終売・生産終了の通知／規格変更（パッケージ変更、内容量変更）の通知／原材料の調達難による供給停止 |
| **② 誰が** | バイヤー |
| **③ 何を確認するか** | いつまで注文できるか（**最終発注期限**）／自社の在庫と、これから売れる見込み／後継商品があるか／得意先のうち何社がその商品を定期的に買っているか／すでに受けている受注に影響するか |
| **④ 何をするか** | 営業機能に終売を伝える。最終発注の数量を決める（**売り切れる量だけ買う**）。後継商品への切り替えを提案してもらう。在庫を売り切る計画を立てる。商品マスタの廃番処理を依頼する |
| **⑤ 何を判断するか** | 最後にいくつ買うか（**買いすぎれば在庫、買わなすぎれば得意先が困る**）／後継商品に切り替えるか、他メーカー品に切り替えるか／残った在庫をどう処分するか |
| **⑥ 誰と連携するか** | 営業機能（得意先への説明、切替提案）／受注・業務機能（商品マスタの廃番処理、後継品の登録）／在庫管理機能（在庫の売り切り計画）／物流・倉庫機能（ロケーションの整理） |
| **⑦ 出来上がるもの** | 終売の社内周知、**最終発注**、後継商品への切替計画、商品マスタの廃番処理依頼 |

**なぜこの業務が必要なのか**

終売は、**予告なく在庫リスクが発生する場面**です。【Typical】

「もう作らない」と言われた商品は、最後に買えるだけ買うか、売り切って終わりにするかを選びます。
買いすぎれば**二度と補充できない在庫**として残り、
買わなすぎれば得意先が「急に買えなくなった」と困ります。

特に、その商品を定期的に使っている飲食店・給食施設にとっては、
**メニューやレシピを変えなければならない問題**になります。
だから終売の情報は、早く正確に営業へ伝える必要があります。【Inference】

#### E-13. 仕入先との納期・入荷トラブル対応

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 物流・倉庫機能からの入荷不備の連絡（数量違い、品違い、破損、期限不足）／仕入先からの納期遅延の連絡／入荷予定日に商品が届かない |
| **② 誰が** | バイヤー |
| **③ 何を確認するか** | 発注データと納品書と現物の差異／仕入先側の原因（生産の遅れ、輸送の問題、受注処理のミス）／自社側の原因（発注内容の誤り）／その商品にひもづく受注があるか（**得意先への納品に影響するか**）／代替の手段 |
| **④ 何をするか** | 仕入先に連絡し、事実を確認する。不足分の再手配を依頼する。不良品・期限不足品の返送または値引きを交渉する。得意先への納品に影響する場合は受注・業務機能と営業機能へ連絡する |
| **⑤ 何を判断するか** | 受け入れるか、返送するか（**期限が基準に満たない商品を受け入れると、出荷できない在庫になる**）／値引きを受けて受け入れるか／再手配が間に合うか／別ルートで調達するか |
| **⑥ 誰と連携するか** | 物流・倉庫機能（入荷検品の結果、返送の実務）／受注・業務機能（納期の再回答、引当の調整）／営業機能（得意先への説明）／経理・財務機能（仕入計上の修正、値引きの処理） |
| **⑦ 出来上がるもの** | 仕入先への申し入れの記録、再手配の発注、**返品・値引きの合意**、修正された入荷予定 |

**なぜこの業務が必要なのか**

**入荷段階で見逃した問題は、出荷段階で必ず大きくなって戻ってきます。**【Inference】

```
 【入荷で見逃した場合の波及】

  期限の短い商品を受け入れてしまった
      ▼
  在庫として登録される（数量上は問題なし）
      ▼
  受注時に引当できない（得意先の納品期限基準を満たさない）
      ▼
  「在庫はあるのに出せない」状態の在庫が滞留する
      ▼
  最終的に値下げ処分または廃棄
```

そのため、バイヤーは入荷不備の連絡を受けたとき、
**「今受け入れると、その在庫は本当に売れるのか」**を判断します。
数量が合っているかだけでなく、**出荷できる状態か**を見るのがこの業務です。【Typical】

#### E-14. 商品情報（規格書・JAN・入数）の入手と社内提供

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 新商品の取扱開始／規格変更／得意先からの商品情報の要求（**大手小売は取引開始時に商品規格書の提出を求めることがある**）／品質・衛生管理上の確認の必要 |
| **② 誰が** | バイヤー／品質・衛生管理機能（内容の確認） |
| **③ 何を確認するか** | **商品規格書**の内容（原材料、アレルゲン、栄養成分、製造者、保存方法、賞味期限）／JANコード／入数・荷姿・外装サイズ・重量／温度帯／表示内容が法令に適合しているか |
| **④ 何をするか** | メーカーから規格書・商品情報を入手する。受注・業務機能へ渡してマスタ登録してもらう。営業機能・品質衛生管理機能へ共有する。得意先から求められた場合は提出する |
| **⑤ 何を判断するか** | 情報が揃っているか（**不足があると得意先に提出できず、取引が始まらないことがある**）／表示内容に問題がないか／保管条件を自社の倉庫で満たせるか |
| **⑥ 誰と連携するか** | 受注・業務機能（商品マスタ登録）／品質・衛生管理機能（規格・表示の確認）／営業機能（得意先への提出）／物流・倉庫機能（保管条件、荷姿の確認） |
| **⑦ 出来上がるもの** | **商品規格書**、商品情報一式、マスタ登録用の情報、（該当時）得意先への提出資料 |

**用語**
**商品規格書（しょうひんきかくしょ）**
→ その商品の中身を詳しく書いた書類。
　原材料、アレルゲン、栄養成分、製造者、保存方法、賞味期限などが記載されます。
→ 実務例：スーパーが新しい商品を採用するとき、
　「この商品の規格書を出してください」と卸売業者に求めます。
　卸売業者はメーカーから入手して提出します。
　**卸売業者は商品を作っていないため、自分では作れない書類です。**

**なぜこの業務が必要なのか**

**卸売業者は商品を作っていないのに、商品の内容について説明を求められます。**【Typical】

得意先（特に大手小売・給食施設・病院）は、
自分たちが販売・提供する商品の中身を把握する必要があります。
しかし得意先はメーカーと直接の取引がないため、**卸売業者に聞くしかありません**。

そのため卸売業者は、**メーカーと得意先の間で情報を中継する役割**を担います。
これが `01_overview.md` の「情報提供機能」の、書類の面での現れです。【Inference】

> **【Fact】** 食品については、食品表示法にもとづく表示の制度があり、
> 食品卸売業では、取り扱う商品の表示内容が法令に適合していることの確認が必要になります。
> また、食品衛生法に基づく営業許可・営業届出の制度が令和3年（2021年）6月1日から施行され、
> 原則としてすべての食品等事業者が**HACCPに沿った衛生管理**に取り組むこととされています
> （出典：改正食品衛生法の概要、HACCP手引書等について／農林水産省、
> HACCPに沿った衛生管理の制度化／東京都保健医療局）。
> （詳細は §5-10 品質・衛生管理機能 および `15_rules-customs.md` で扱います）

#### E-15. 仕入価格改定への対応（値上げの受入と売価への反映）

| 観点 | 内容 |
|---|---|
| **① きっかけ** | メーカーからの価格改定（値上げ）の通知／原材料価格・輸送費・為替の変動／包装資材の変更 |
| **② 誰が** | バイヤー・商品部長（交渉と判断）／営業機能（得意先への価格転嫁）／経営機能（方針） |
| **③ 何を確認するか** | 改定の内容（対象商品、改定率、実施日）／改定前に仕入れられる期限と数量／自社の在庫（**旧価格の在庫がどれだけあるか**）／得意先に出している売価と、改定後の粗利／同じ商品の他の仕入ルートの価格 |
| **④ 何をするか** | メーカーと改定内容を協議する（改定幅、実施時期の調整）。改定前の仕入（**駆け込み仕入**）をどうするか決める。営業機能に情報を渡し、得意先への価格改定の申し入れを準備してもらう。改定日に合わせてマスタを更新してもらう |
| **⑤ 何を判断するか** | 改定を受け入れるか、交渉するか／改定前にまとめて仕入れるか（**在庫リスクと引き換えに旧価格で確保する**）／売価にいつから転嫁するか／転嫁できない得意先の粗利減をどう扱うか |
| **⑥ 誰と連携するか** | 営業機能（得意先への価格改定の申し入れ）／受注・業務機能（仕切価格・売価マスタの更新）／経理・財務機能（在庫の評価、粗利への影響）／経営機能（方針の決定）／在庫管理機能（旧価格在庫の管理） |
| **⑦ 出来上がるもの** | 改定後の仕切価格、**売価改定の方針**、マスタ更新の依頼、（該当時）改定前のまとめ発注 |

**なぜこの業務が必要なのか ——「仕入が上がっても売価はすぐには上がらない」**

価格改定は、卸売業の粗利に**時間差で効いてきます。**【Typical】

```
 【時間差が生む粗利の圧迫】【Example】（説明用の架空例）

  4月1日  メーカーが仕切価格を 2,400円 → 2,520円 に改定（5%上昇）
  4月1日  自社の仕入はこの日から2,520円になる
  4月〜   得意先への価格改定を申し入れる。しかし交渉には時間がかかる
  6月1日  得意先の売価を 2,700円 → 2,820円 に改定（合意）

  → 4月・5月の2か月間は、仕入だけが上がって売価が据え置き
     粗利 300円 → 180円 に減少（4割減）
```

この2か月間の粗利の目減りは、**誰も悪くないのに発生します**。
そのため、価格改定への対応では
**「いつから売価に反映できるか」を早く見通すこと**が実務上の焦点になります。【Inference】

**駆け込み仕入という判断**

改定前に大量に仕入れておけば、旧価格の在庫で当面をしのげます。
しかしそれは在庫と資金を増やす行為でもあります。
**どれだけ仕込むかは、値上げ幅と在庫リスクの比較**になります。【Typical】

#### E-16. 仕入実績・粗利の管理と報告

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 月次・四半期の締め／リベートの精算時期／経営会議／在庫金額の確認 |
| **② 誰が** | バイヤー・商品部長／経理・財務機能（数字の提供） |
| **③ 何を確認するか** | 仕入先別・商品カテゴリー別の仕入高／**商品別・カテゴリー別の粗利額と粗利率**／リベートの達成状況と見込み／在庫金額と在庫回転／値下げ・廃棄による損失 |
| **④ 何をするか** | 実績を集計する。計画との差を分析する。リベートの達成見込みを確認する。粗利率が悪化しているカテゴリーの原因を調べる。経営機能に報告する |
| **⑤ 何を判断するか** | 粗利率の低下は仕入価格の問題か、売価の問題か／仕入先との条件交渉が必要か／在庫が計画より多い場合、発注を抑えるか／リベート達成のために追加仕入をするか |
| **⑥ 誰と連携するか** | 経理・財務機能（仕入・粗利・在庫のデータ）／営業機能（売価の状況）／経営機能（報告と方針の確認） |
| **⑦ 出来上がるもの** | 仕入実績の報告、**粗利の分析**、リベート見込み、在庫状況の報告、次期の仕入方針 |

**なぜこの業務が必要なのか**

`04_end-to-end-process.md` §4-2 S25 で触れたとおり、
**リベートは商品ごとの粗利には表れません。**

そのため、卸売業の利益を正しく見るには、
**「商品別粗利」と「リベートを含めた最終的な利益」の2段構え**で見る必要があります。【Typical】

```
 【卸売業の利益の見方（2段階）】

  第1段階：商品別粗利  ＝ 売上 − 仕入原価
           → 日々の取引で見える利益。営業とバイヤーが日常的に見る

  第2段階：最終的な利益 ＝ 商品別粗利 ＋ リベート − 販売促進費 − 廃棄・値下げ損
           → 期間の締め・精算を経て確定する利益。商品部長と経理が見る
```

第1段階だけを見て「この商品は儲かっていない」と判断できないのは、このためです。【Inference】

#### E-17. 商品構成（品揃え）の見直し

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 期・年度の切り替わり／取扱商品数が増えすぎた／滞留在庫が増えた／新しい商品カテゴリーへの参入／得意先の業態の変化 |
| **② 誰が** | 商品部長・バイヤー／経営機能（方針）／営業機能（現場の要望） |
| **③ 何を確認するか** | 商品別・カテゴリー別の販売実績と粗利／**取扱はあるがほとんど売れていない商品（死に筋）**／似た商品が重複していないか／得意先の要望に応えられていないカテゴリーはないか／在庫回転／保管スペースの使われ方 |
| **④ 何をするか** | 商品を分類する（主力／準主力／少量／取扱中止候補）。取扱をやめる商品を決める。新しく加えるカテゴリーを決める。営業機能と調整して得意先への影響を確認する |
| **⑤ 何を判断するか** | 取扱をやめるか（**1社でも定期的に買っている得意先がいれば、やめると迷惑がかかる**）／似た商品を1つに集約するか／新カテゴリーに参入するか（在庫・保管・知識の準備が必要） |
| **⑥ 誰と連携するか** | 営業機能（得意先への影響、要望）／在庫管理機能（在庫の整理）／物流・倉庫機能（ロケーションの再編）／受注・業務機能（マスタの整理）／経営機能（方針） |
| **⑦ 出来上がるもの** | **商品構成の方針**、取扱中止商品のリスト、新規カテゴリーの計画、マスタ整理の依頼 |

**なぜこの業務が必要なのか**

卸売業の強みは**品揃え**です（`01_overview.md` の「取り揃え機能」）。
しかし、品揃えは増やせば増やすほど良いわけではありません。【Inference】

| 品揃えを増やすと | 品揃えを絞ると |
|---|---|
| 得意先の要望に応えやすくなる | 在庫と保管スペースが軽くなる |
| 「あそこなら何でもある」という評価につながる | 1商品あたりの仕入量が増え、価格交渉がしやすくなる |
| **在庫・保管スペース・管理の手間が増える** | **「あの商品がない」と言われ、他社に注文が流れる** |
| **1商品あたりの仕入量が減り、価格交渉力が落ちる** | 得意先の要望に応えられない場面が増える |

このバランスを取るのが商品構成の見直しです。
特に難しいのは、**「ほとんど売れないが、1社だけが定期的に買っている商品」**の扱いです。
取扱をやめればその得意先が困り、続ければ在庫として残り続けます。【Typical】

#### E-18. 仕入先への返品交渉

| 観点 | 内容 |
|---|---|
| **① きっかけ** | 入荷時の不良・期限不足／得意先からの返品のうち、商品自体に問題があるもの／終売・規格変更に伴う旧商品の在庫／季節商品の売れ残り／販促企画の残品 |
| **② 誰が** | バイヤー／商品部長（金額が大きい場合） |
| **③ 何を確認するか** | 返品の理由と責任の所在／契約・商慣行上、返品を受けてもらえる条件か／現物の状態（未開封か、期限はどれだけ残っているか、外装は無傷か）／数量と金額／返送にかかる送料の負担 |
| **④ 何をするか** | 仕入先に相談する。返品を受けてもらえるか、値引きで処理するか、引き取れないかを交渉する。合意したら返送の手配をする。仕入の赤伝処理を経理へ依頼する |
| **⑤ 何を判断するか** | 返品交渉をするか、自社で処分するか／返送の送料をかけても見合うか／今後の取引関係への影響をどう考えるか |
| **⑥ 誰と連携するか** | 物流・倉庫機能（返送する現物の準備、出荷）／経理・財務機能（仕入の赤伝、買掛金の調整）／在庫管理機能（在庫からの除外）／営業機能（得意先からの返品の背景） |
| **⑦ 出来上がるもの** | **仕入先への返品の合意**、返送の手配、仕入の赤伝処理依頼、（不成立時）自社処分の決定 |

**なぜこの業務が必要なのか**

仕入先への返品は、**自社の損失を減らす手段**です。【Inference】
自社で廃棄すれば全額が損失になりますが、
仕入先が引き取ってくれれば、その分の損失は発生しません。

ただし、**返品は自動的に受け入れられるものではありません。**
仕入先にとっても返品は損失であり、受け入れるかどうかは交渉になります。
そして、この交渉は**取引関係の中で行われる**ため、
「今回は受けてもらったが、次は難しい」という蓄積が生じます。【Typical】

> **【Fact】** 返品については独占禁止法上の論点があります。
> 公正取引委員会の「大規模小売業者による納入業者との取引における特定の不公正な取引方法」
> （大規模小売業告示）は、大規模小売業者が納入業者に行う**不当な返品**を禁じています
> （出典：大規模小売業者による納入業者との取引における特定の不公正な取引方法／公正取引委員会）。
> 卸売業者は、**仕入先に対しては「買い手」の立場**になるため、
> 自社が行う返品について**優越的地位の濫用**が問題となり得る立場にもあります。【Inference】

### O. 見ている数字・KPI

| 数字 | 意味 | なぜ見るのか |
|---|---|---|
| **仕入高（仕入先別・カテゴリー別）** | いくら仕入れたか | リベートの達成基準になることが多い |
| **仕入価格（仕切価格）の水準と推移** | 1商品あたりいくらで仕入れているか | 粗利の出発点 |
| **粗利額・粗利率（商品別・カテゴリー別・仕入先別）** | 仕入と売りの差 | 利益の源泉。**卸売業で最も重視される数字のひとつ** |
| **リベート額・リベート率・達成率** | 仕入高に対するリベートの割合と、条件の達成状況 | 商品別粗利に表れない利益 |
| **在庫金額** | 在庫として寝ている資金の額 | 資金繰りに直結する |
| **在庫回転率・在庫回転日数** | 在庫が何日で入れ替わるか | 在庫が多すぎないかの判断 |
| **欠品率・品切れ件数** | 注文に応えられなかった割合 | 仕入判断の結果が現れる |
| **滞留在庫金額・デッドストック金額** | 動いていない在庫の額 | 将来の損失の予備軍 |
| **廃棄額・値下げ損失額** | 処分によって失った金額 | 仕入の読み違いの結果 |
| **取扱SKU数** | 扱っている商品の点数 | 品揃えの広さと管理負荷 |
| **仕入先数・仕入先別の構成比** | 何社から、どの割合で買っているか | 1社への依存度 |
| **納期遵守率（仕入先の）** | 仕入先が約束どおり納品した割合 | 仕入先の評価 |

### 業種による違い（Level 2）——仕入・調達機能

| 比較軸 | **食品卸** | **建材卸** | **機械・工具卸** | **医薬品卸** | **アパレル卸** |
|---|---|---|---|---|---|
| **発注の性格** | **期限と回転を見た日次の補充発注**が中心 | 定番は在庫補充、**特注建材は案件ごとの都度手配** | 定番消耗品は在庫補充、**機械本体は都度手配・受注生産** | 日次の補充発注＋緊急対応 | **シーズン前の先行仕入**が中心。期中は追加生産（追加投入） |
| **在庫リスクの性格** | **賞味期限切れ**。期限を過ぎれば価値がゼロになる | 長期保管が可能だが、**規格・仕様が変わると売れなくなる** | 型番の陳腐化・後継品への切り替え | 使用期限。**法令に基づく管理が必要**【Fact】 | **流行と季節**。シーズンを外すと大幅な値下げが必要 |
| **価格交渉の枠組み** | 建値・仕切価格・リベートの組み合わせ | **案件ごとの見積**。同じ商品でも物件により価格が動く | メーカーの価格表を基準にした掛率交渉が一般的【Typical】 | **公的な価格制度の枠組みの中**での交渉【Fact】 | シーズン単位の価格。**売れ残りの負担の分担**が交渉点 |
| **リベートの重み** | 大きい。数量・販促・目標達成の各種リベートがある | **【Varies】** 案件型の取引では個別の値引きの形を取ることが多い | メーカーごとの制度による【Varies】 | **ガイドラインで整理・縮小が示されている**【Fact】 | シーズン末の値引き負担（値引き補填）の形を取ることがある【Varies】 |
| **仕入先との関係** | メーカー特約店＋一次卸・商社の併用 | メーカー・商社経由。**代理店の指定が強い**【Typical】 | **メーカーごとに代理店・特約店が指定される**【Typical】 | 製薬企業との取引。制度の枠組みが強い | メーカー・商社・OEM（自社企画品）の併用【Varies】 |
| **期限・規制への対応** | **賞味期限・食品表示法・HACCP**【Fact】 | 規格・認定品の確認 | 仕様・安全基準の確認 | **薬機法に基づく管理。営業所ごとに薬剤師の配置**【Fact】 | 家庭用品品質表示法に基づく表示【Typical】 |

> **【Typical】** 建材卸・機械工具卸のバイヤーは、**同じ商品でも案件ごとに価格を取りに行きます。**
> 「この物件のために、この数量を、この納期で」という条件をメーカーに提示し、
> その案件限りの価格（**物件価格・スポット価格**）を引き出します。
> 食品卸のように「年間の仕切価格を決めておいて、あとはその価格で回す」形とは
> 交渉のリズムが異なります。

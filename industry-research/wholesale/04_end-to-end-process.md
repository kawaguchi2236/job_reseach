## 4-1. 先に押さえておく重要概念

この章を読む前に、次の5つの用語を理解しておくと全体がつながります。

### ① 在庫引当（ざいこひきあて）

**やさしい説明**
注文を受けたとき、**倉庫にある在庫の一部を「この注文用」として押さえること**。
まだ現物は動きませんが、データ上は「他の注文には使えない」状態になります。

**なぜするのか**
同じ商品に複数の注文が入ったとき、先に受けた注文分が他の注文に取られてしまうのを防ぐためです。
引当がないと、「受注したのに出荷する段になったら在庫がなかった」という事態が起きます。

**用語の整理**

| 用語 | 意味 |
|---|---|
| **総在庫（実在庫）** | 倉庫に実際に置いてある数量 |
| **引当済在庫** | すでに他の注文に割り当てられている数量 |
| **引当可能在庫（有効在庫・フリー在庫）** | 総在庫 − 引当済在庫。新しい注文に使える数量 |
| **入荷予定** | 発注済みでまだ届いていない数量 |

**実務例【Example】**
> 醤油の総在庫が100ケース。うち30ケースはすでに明日の出荷分として引き当てられている。
> 新しい注文が来たとき、使えるのは残り70ケース。

### ② 欠品（けっぴん）と欠品対応

**やさしい説明**
注文された数量に対して引当可能在庫が足りない状態。

**対応の選択肢**【Typical】

| 対応 | 内容 | どんな時に選ぶか |
|---|---|---|
| 代替品の提案 | 同等の他メーカー品・別規格品を提案する | 得意先が代替を受け入れる場合 |
| 分納（ぶんのう） | 在庫がある分だけ先に納品し、残りは後日 | 一部でも早く欲しい場合 |
| 緊急発注（急配） | 仕入先に緊急で手配し、間に合わせる | 納期に余裕がある／仕入先が対応できる場合 |
| 他倉庫からの移動 | 別拠点の在庫を回す（拠点が複数ある場合） | 移動時間が納期に間に合う場合 |
| 次回納品での充当 | 次の定期納品時にまとめて納める | 緊急性が低い場合 |
| 受注のキャンセル | 注文自体を取り消してもらう | いずれも不可能な場合 |

> **【Varies】** どの対応を選ぶかは、商品・得意先・納期・その会社の方針によって大きく異なります。

### ③ 発注点（はっちゅうてん）と安全在庫

**やさしい説明**
- **発注点** … 「在庫がこの数まで減ったら発注する」という基準の数量。
- **安全在庫** … 予想外に注文が増えたり入荷が遅れたりしたときのための、余裕分の在庫。

**なぜ必要か**
在庫がゼロになってから発注したのでは、届くまでの間に必ず欠品します。
「届くまでにかかる日数（調達リードタイム）の間に売れる分」＋「余裕分」を
切ったら発注する、という考え方です。

```
 在庫数
   ▲
   │╲
   │ ╲                                    ← 毎日少しずつ売れて減っていく
   │  ╲
   │───╲──────────────── 発注点      ← ここを切ったら発注する
   │    ╲          ▲
   │     ╲         │ 調達リードタイム（発注してから届くまで）
   │      ╲        │
   │───────╲─────┴─────── 安全在庫  ← この線より下に行かないようにする
   │        ╲    ／
   │         ╲  ／  ← 入荷して在庫が回復
   └──────────────────────────▶ 時間
```

**実務例【Example】**
> ある調味料は1日平均10ケース売れる。発注してから届くまで3日かかる。
> 3日分＝30ケース。これに安全在庫20ケースを足して、発注点を50ケースに設定する。
> 在庫が50ケースを切ったら、自動的に発注リストに上がる。

> **【Varies】** 発注点・安全在庫の設定方法（計算式を使うか、担当者の経験で決めるか、
> 商品ごとに設定するか）は企業により大きく異なります。

### ④ 与信限度額（よしんげんどがく）

**やさしい説明**
「この得意先に対して、**代金未回収の状態でいくらまで商品を渡してよいか**」の上限額。

**なぜ必要か**
掛売では、商品を渡してから代金が入るまで時間差があります。
その間に得意先が倒産すれば、商品も代金も戻ってきません（**貸倒れ**）。
渡しっぱなしの金額に上限を設けることで、万一のときの損失を限定します。

**実務例【Example】**
> B商店の与信限度額は300万円。現在の売掛金残高は250万円。
> ここに80万円の注文が入ると合計330万円になり限度額を超えるため、
> システムが警告を出し、出荷前に経理・経営の承認が必要になる。

### ⑤ 締め日（しめび）・請求・消込

**やさしい説明**
- **締め日** … 「いつからいつまでの取引を1回分としてまとめるか」を区切る日。
- **請求** … 締めた分の合計金額を得意先に通知すること。
- **消込（けしこみ）** … 入金された金額を、どの請求（どの売掛金）に対応するかを突き合わせて
  「回収済み」にする作業。

**なぜ消込が必要か**
入金は「B商店から980,000円」という形でまとめて振り込まれます。
これがどの月のどの請求に対する入金なのかを突き合わせないと、
「どの売掛金がまだ残っているのか」が分からなくなるためです。

## 4-2. ステップ別の詳細

> 表記ルール：各ステップは
> **【誰が】【何を受け取るか（インプット）】【何をするか】【何を判断するか】【何を作るか（アウトプット）】
> 【次に誰へ渡すか】【頻度】** の形で整理します。
> 頻度は methodology §5 の語彙（常時／日次／週次／月次／四半期／半期／年次／案件発生時／
> 問い合わせ時／受注時／発注時／納品時／請求時／入金時／トラブル発生時／法定・契約上のタイミング）を使います。

---

### 【事前の準備】取引が始まる前

#### S0-1. 引合・商談

| 項目 | 内容 |
|---|---|
| **誰が** | 営業機能（営業担当）／重要案件は経営機能（社長）も同席 |
| **受け取るもの** | 見込み客からの問い合わせ、紹介、既存得意先からの新規要望 |
| **何をするか** | 相手の業態・規模・必要な商品・必要な量・希望納品条件を聞く。取扱商品を提案する |
| **何を判断するか** | 自社の商圏・配送体制・品揃えで対応できるか。採算が取れるか |
| **作るもの** | 商談記録、提案資料、見積書 |
| **次に渡す先** | 与信・債権管理機能（取引開始の可否を判断してもらうため） |
| **頻度** | 問い合わせ時／案件発生時 |

**なぜするのか**
卸売業の取引は一度始まると継続します。最初に条件を詰めておかないと、
配送コストが合わない・支払条件が厳しすぎるといった問題を長期間抱えることになります。【Inference】

#### S0-2. 与信審査・取引口座開設

| 項目 | 内容 |
|---|---|
| **誰が** | 与信・債権管理機能（経理担当が兼務）／最終判断は経営機能 |
| **受け取るもの** | 商談記録、相手先の会社概要、決算書（入手できる場合）、信用調査報告 |
| **何をするか** | 信用調査会社の報告を取得する。決算内容・業歴・経営者の状況を確認する。取引条件（締め日・支払方法・支払サイト）を決める。与信限度額を設定する |
| **何を判断するか** | 取引してよいか。与信限度額をいくらにするか。前払・現金取引にすべきか。保証（連帯保証・担保・取引信用保険）を求めるか |
| **作るもの** | 与信限度額の設定記録、取引基本契約書、取引口座（得意先マスタ） |
| **次に渡す先** | 受注・業務機能（得意先マスタに登録して受注できる状態にするため）、営業機能（条件を伝えるため） |
| **頻度** | 案件発生時（新規取引時）／年次または半期（既存先の定期見直し） |

**用語**
**取引口座（こうざ）**
→ 「この会社と取引する」という社内登録のこと。銀行口座とは別物です。
→ 実務例：「A社にうちの口座を開けてもらった」＝A社と取引を始められるようになった。

**なぜするのか**
掛売を前提とする卸売業では、**商品を渡した後に代金が入らないリスク**が常にあります。
取引開始前に相手の支払能力を確認しておかないと、売れば売るほど損をする事態になります。【Inference】

#### S0-3. 商品登録・価格登録

| 項目 | 内容 |
|---|---|
| **誰が** | 受注・業務機能（マスタ管理担当）／価格は仕入・調達機能と営業機能が決定 |
| **受け取るもの** | 仕入先からの商品情報（規格書、JANコード、荷姿、入数、仕切価格）、営業からの売価決定内容 |
| **何をするか** | 商品マスタに商品コード・商品名・入数・荷姿・温度帯・賞味期限日数などを登録する。得意先別の売価を価格マスタに登録する |
| **何を判断するか** | 登録内容に誤りがないか。得意先別・商品別の売価が粗利を確保できているか |
| **作るもの** | 商品マスタ、価格マスタ、得意先別売価表 |
| **次に渡す先** | 受注・業務機能（受注入力で使う）、物流・倉庫機能（保管・ピッキングで使う） |
| **頻度** | 案件発生時（新商品導入時、価格改定時）／日次（日常的な登録作業） |

**なぜするのか**
卸売業では**同じ商品でも得意先ごとに売価が違う**のが普通です。
この対応関係をマスタに正しく登録しておかないと、受注のたびに価格を調べることになり、
請求金額の誤りにもつながります。【Typical】

### 【売る側の流れ】受注〜納品

#### S1. 受注

| 項目 | 内容 |
|---|---|
| **誰が** | 受注・業務機能（内勤）／訪問時は営業機能 |
| **受け取るもの** | 得意先からの注文（電話、FAX、メール、Web受発注画面、EDI、営業の訪問時の聞き取り、モバイル端末入力） |
| **何をするか** | 注文内容（商品・数量・希望納品日・納品先）を聞き取る／受け取る。不明点を確認する |
| **何を判断するか** | 商品の特定が正しいか（同じような名前の別商品ではないか）。数量の単位が正しいか（ケースかバラか）。希望納品日に間に合うか |
| **作るもの** | 注文の記録（受注メモ、FAX原本、EDIデータ） |
| **次に渡す先** | 受注・業務機能（自分自身。次のS2へ） |
| **頻度** | 日次（毎日、受注締切時刻まで継続的に発生）／受注時 |

**用語**
**EDI（Electronic Data Interchange：電子データ交換）**
→ 発注・受注・出荷・請求などのデータを、**企業間でシステム同士が直接やり取りする仕組み**。
→ 実務例：スーパーの本部システムが発注データを送ると、卸のシステムに自動で受注データが入る。
　人が入力しないため、入力ミスがなく、大量の注文を短時間で処理できる。

**ここで起きやすい間違い**【Typical】
- **ケースとバラの取り違え**：「醤油10」が10ケースなのか10本なのか。
- **類似商品の取り違え**：「濃口醤油1L」と「濃口醤油1L（減塩）」。
- **納品日の取り違え**：「あした」が翌日なのか翌営業日なのか。

#### S2. 受注入力

| 項目 | 内容 |
|---|---|
| **誰が** | 受注・業務機能（内勤の受注担当）／EDIの場合はシステムが自動取込 |
| **受け取るもの** | S1の注文記録 |
| **何をするか** | 販売管理システムに、得意先コード・商品コード・数量・納品日・納品先を入力する。価格マスタから売価が自動セットされることを確認する |
| **何を判断するか** | 入力内容が注文と一致しているか。売価が正しいか（特売価格の適用漏れはないか）。単位（ケース／ボール／バラ）が正しいか |
| **作るもの** | **受注データ**（受注伝票） |
| **次に渡す先** | 受注・業務機能（次のS3へ） |
| **頻度** | 日次（受注締切時刻まで随時） |

**用語**
**販売管理システム**
→ 受注・出荷・売上・請求・入金の情報を一元的に記録する仕組み。
　多くの卸売業では、これに在庫管理・仕入管理の機能が組み合わさっています。
→ 実務例：受注を入力すると、在庫が自動で引き当てられ、納品書が印刷され、
　月末に締めると請求書が出力される。
（システムの詳細は `11_systems.md` で扱います）

#### S3. 在庫引当

| 項目 | 内容 |
|---|---|
| **誰が** | 受注・業務機能（システムが自動で行い、担当者が結果を確認） |
| **受け取るもの** | S2の受注データ、在庫データ |
| **何をするか** | 受注数量に対して引当可能在庫を割り当てる。食品・医薬品では**賞味期限／使用期限とロット**も併せて引き当てる（古いものから出す＝**先入先出**） |
| **何を判断するか** | 引当可能在庫が足りているか。得意先の**納品期限**（食品の3分の1ルール等）を満たす期限の在庫があるか |
| **作るもの** | **引当済の受注データ**、引当不足リスト（欠品リスト） |
| **次に渡す先** | 在庫が足りる場合 → S5（与信チェック）／足りない場合 → S4（欠品対応） |
| **頻度** | 日次（受注のつど、自動） |

**用語**
**先入先出（さきいれさきだし／FIFO）**
→ 先に入荷したものから先に出荷すること。
→ 実務例：同じ商品でも賞味期限が近いロットから出荷する。
　これを守らないと、倉庫の奥に期限切れ間近の在庫が残ってしまう。

**用語**
**ロット**
→ 同じ条件でまとめて製造された商品のかたまり。製造日や製造番号で識別します。
→ 実務例：「ロット番号241105の缶詰を50ケース出荷した」。
　商品に問題が見つかったとき、**どのロットをどこに出したか**をたどるために記録します（**トレーサビリティ**）。

#### S4. 欠品対応

| 項目 | 内容 |
|---|---|
| **誰が** | 受注・業務機能（内勤）→ 営業機能（得意先との調整）→ 必要に応じて仕入・調達機能 |
| **受け取るもの** | S3の引当不足リスト |
| **何をするか** | 不足数量と入荷予定を確認する。営業へ連絡する。営業が得意先に状況を伝え、対応（代替品・分納・後日納品・キャンセル）を相談する。緊急発注が必要ならバイヤーへ依頼する |
| **何を判断するか** | 代替品を提案できるか。分納で了承が得られるか。緊急発注して間に合うか。他の得意先への引当を振り替えるべきか |
| **作るもの** | 欠品連絡の記録、変更後の受注データ、緊急発注の依頼 |
| **次に渡す先** | 受注・業務機能（受注データの修正）、仕入・調達機能（緊急発注）、営業機能（得意先への説明） |
| **頻度** | 日次（毎日一定量発生する）／トラブル発生時（大量欠品時） |

**なぜ重要か**
欠品は「売り損なった」だけでは終わりません。
得意先の売場に穴が開き、得意先の売上も失われます。
そのため欠品対応は、**卸売業の信用に直結する仕事**とされています。【Typical】

#### S5. 与信チェック

| 項目 | 内容 |
|---|---|
| **誰が** | 受注・業務機能（システムが自動判定）／超過時は与信・債権管理機能と経営機能 |
| **受け取るもの** | 引当済の受注データ、得意先の売掛金残高、与信限度額 |
| **何をするか** | 「現在の売掛金残高 ＋ 今回の受注金額」が与信限度額を超えないか確認する。超える場合は出荷を保留し、承認を求める |
| **何を判断するか** | 出荷してよいか。限度額を一時的に引き上げるか。先に入金してもらうか。取引を止めるか |
| **作るもの** | 出荷可否の判定結果、与信超過の承認記録 |
| **次に渡す先** | 受注・業務機能（S6へ）／保留の場合は営業機能へ差し戻し |
| **頻度** | 日次（受注のつど、自動）／トラブル発生時（超過時の個別判断） |

> **【Varies】** 与信チェックをシステムで自動的に行うか、経理担当が目視で確認するか、
> そもそも明示的な与信限度額を設けていないかは、企業によって異なります。

#### S6. 出荷指示の確定（受注締切）

| 項目 | 内容 |
|---|---|
| **誰が** | 受注・業務機能（業務部長・受注担当） |
| **受け取るもの** | 引当済・与信チェック済の受注データ |
| **何をするか** | 決められた**受注締切時刻**で当日出荷分を締める。配送コース別・得意先別に出荷指示を確定する。**ピッキングリスト**と**納品書**を出力する |
| **何を判断するか** | 締切後に入った注文を当日分に入れるか翌日分に回すか。配送コースごとの積載量が収まるか |
| **作るもの** | **出荷指示データ**、**ピッキングリスト**、**納品書**、配送コース別の出荷一覧 |
| **次に渡す先** | 物流・倉庫機能 |
| **頻度** | 日次（受注締切時刻に1回、または午前・午後の2回など）【Varies】 |

**用語**
**ピッキングリスト**
→ 倉庫で商品を集めるための作業指示書。「どの棚から、どの商品を、何個取るか」が並んでいます。
→ 実務例：倉庫の棚の並び順に商品が並んだリストを見ながら、台車で回って商品を集める。

**用語**
**受注締切（じゅちゅうしめきり）**
→ 「この時刻までに入った注文は当日出荷（翌日納品）する」という時刻の取り決め。
→ 実務例：「当日15時締め、翌日午前納品」。15時1分に入った注文は翌々日納品になる。

**なぜ締切が必要か**
倉庫の作業と配送便の出発時刻は決まっています。
注文をいつまでも受け付けていると、ピッキングも仕分けも積込も終わりません。
**締切は、物流の物理的な制約から逆算して決められています。**【Inference】

#### S7. ピッキング

| 項目 | 内容 |
|---|---|
| **誰が** | 物流・倉庫機能（ピッキング担当） |
| **受け取るもの** | ピッキングリスト（または携帯端末の指示） |
| **何をするか** | 指示された棚（ロケーション）から、指示された商品を指示された数だけ取り出す。ケース単位とバラ単位を区別して取る |
| **何を判断するか** | 商品が指示どおりか。数量が合っているか。賞味期限・ロットが指示どおりか。商品に破損・汚れがないか |
| **作るもの** | 得意先別に集められた商品、ピッキング完了の記録 |
| **次に渡す先** | 物流・倉庫機能（S8へ） |
| **頻度** | 日次 |

**用語**
**ロケーション**
→ 倉庫内の保管場所を表す住所のようなもの。「A-03-2」のように番地で管理します。
→ 実務例：商品マスタに「この商品はA-03-2」と登録しておけば、
　誰でも同じ場所から取り出せる。逆に登録が実際とずれていると、商品が見つからない。

**用語**
**トータルピッキング／シングルピッキング**
→ **トータルピッキング**＝全得意先分の同じ商品をまとめて取り、後で得意先別に分ける方式。
　**シングルピッキング**＝得意先1件ずつ、その得意先の商品だけを集める方式。
→ 実務例：小口・多品種の得意先が多い食品卸では、
　トータルピッキング＋仕分けの組み合わせが使われることがあります【Varies】。

#### S8. 仕分け・出荷検品

| 項目 | 内容 |
|---|---|
| **誰が** | 物流・倉庫機能（出荷検品担当） |
| **受け取るもの** | ピッキング済の商品、納品書、出荷指示データ |
| **何をするか** | 得意先別・配送コース別に商品を仕分ける。納品書と現物を突き合わせて検品する（バーコード照合を行う場合もある）。温度帯別に梱包・箱詰めする。納品書を同梱または貼付する |
| **何を判断するか** | 品違い・数量違いがないか。破損がないか。温度帯の混載が不適切でないか |
| **作るもの** | **出荷可能な状態の荷物**、出荷検品の記録、**送り状**（路線便を使う場合） |
| **次に渡す先** | 物流・倉庫機能（S9へ） |
| **頻度** | 日次 |

**なぜ検品するのか**
誤出荷は、得意先での商品不足・返品処理・再配送・請求訂正を連鎖的に引き起こします。
**出荷前の1回の確認で、その後の何倍もの手間を防いでいます。**【Inference】

#### S9. 積込・配送

| 項目 | 内容 |
|---|---|
| **誰が** | 物流・倉庫機能（配送ドライバー、積込担当）／外部委託の場合は物流会社 |
| **受け取るもの** | 出荷可能な荷物、配送コース表、納品書 |
| **何をするか** | 配送コースの**回る順番の逆**に積み込む（最後に降ろす荷物を先に積む）。温度帯を守って積む。出発する。指定の時間帯に納品先へ向かう |
| **何を判断するか** | 積載量が車両に収まるか。冷蔵・冷凍品の温度が保たれているか。時間指定に間に合うルートか |
| **作るもの** | 配送実績、運行記録 |
| **次に渡す先** | 得意先（S10へ） |
| **頻度** | 日次 |

> **【Varies】** 自社便で配送するか、路線便（複数の荷主の荷物をまとめて運ぶ定期便）に委託するか、
> チャーター便（貸切）を使うかは、距離・数量・緊急度によって使い分けられます。

#### S10. 納品・検収

| 項目 | 内容 |
|---|---|
| **誰が** | 配送ドライバー（納品）／得意先の担当者（検収） |
| **受け取るもの** | 商品、納品書 |
| **何をするか** | 指定された場所（店舗のバックヤード、物流センターの荷受場、工事現場、病院の資材室など）に荷降ろしする。得意先が納品書と現物を照合する |
| **何を判断するか** | （得意先側）注文どおりの商品・数量・期限か。破損はないか |
| **作るもの** | **受領書**（または検収データ）、納品完了の記録 |
| **次に渡す先** | 受注・業務機能／経理・財務機能（売上確定と請求の根拠にするため） |
| **頻度** | 日次／納品時 |

**用語**
**検収（けんしゅう）**
→ 得意先が「注文どおりのものを受け取った」と確認すること。
→ 実務例：受領印をもらう、検収データを受信する。
　**検収されて初めて売上が確定する**取引条件が多くあります【Typical】。

**ここが重要**
> **売上をいつ計上するか**は、取引条件によって異なります。【Varies】
> - **出荷基準** … 自社が出荷した時点で売上とする
> - **納品基準（着荷基準）** … 得意先に届いた時点で売上とする
> - **検収基準** … 得意先が検収した時点で売上とする
>
> どの基準を採るかで、月末をまたぐ取引の売上計上月が変わります。
> （会計上の扱いは `08_money.md` `12_business-model.md` で扱います）

### 【買う側の流れ】発注〜入庫

> ここからは「売る」のと**並行して常に走っている**流れです。
> 在庫は出ていくだけでは尽きるので、補充し続けなければなりません。

#### S11. 発注点・安全在庫の判定

| 項目 | 内容 |
|---|---|
| **誰が** | 仕入・調達機能（バイヤー）／在庫管理機能。システムが候補を自動抽出する場合が多い |
| **受け取るもの** | 在庫データ、出荷実績、入荷予定、販促・特売の計画、営業からの販売見込み |
| **何をするか** | 引当可能在庫と入荷予定を見て、発注点を下回った商品を抽出する。特売・季節要因を加味して発注数量を調整する |
| **何を判断するか** | 発注するか、見送るか。いくつ発注するか。最低発注単位（ロット）との兼ね合いをどうするか |
| **作るもの** | **発注候補リスト**、発注数量の案 |
| **次に渡す先** | 仕入・調達機能（S12へ） |
| **頻度** | 日次（日々の補充判定）／週次・月次（定番商品の見直し）／案件発生時（特売・季節商品） |

**用語**
**最低発注単位（MOQ：Minimum Order Quantity）**
→ 仕入先が受け付ける最小の発注数量。
→ 実務例：「この商品は10ケース単位でしか発注できない」。
　5ケースしか必要なくても10ケース仕入れることになり、余剰在庫の原因になります。

#### S12. 発注

| 項目 | 内容 |
|---|---|
| **誰が** | 仕入・調達機能（バイヤー）／定型的な補充は受注・業務機能が代行する場合もある |
| **受け取るもの** | 発注候補リスト、S4からの緊急発注依頼、都度仕入の受注情報 |
| **何をするか** | 仕入先へ発注する（EDI、FAX、メール、Web発注画面、電話）。納期を確認する。直送の場合は納品先・納品日を指定する |
| **何を判断するか** | 仕入先をどこにするか（同じ商品を複数から仕入れられる場合）。仕入価格は妥当か。納期は間に合うか。倉庫に入れるか直送にするか |
| **作るもの** | **発注データ（注文書）**、入荷予定データ |
| **次に渡す先** | 仕入先／物流・倉庫機能（入荷予定の連絡）／受注・業務機能（納期回答のため） |
| **頻度** | 日次（補充発注）／受注時（都度仕入）／トラブル発生時（緊急発注） |

#### S13. 入荷・検品

| 項目 | 内容 |
|---|---|
| **誰が** | 物流・倉庫機能（入荷担当） |
| **受け取るもの** | 仕入先からの商品、仕入先の納品書、自社の発注データ（入荷予定） |
| **何をするか** | 荷降ろしする。発注データと納品書と現物を突き合わせる。数量・商品・賞味期限・ロット・破損の有無を確認する |
| **何を判断するか** | 発注どおりか。期限は十分に残っているか（自社の納品期限基準を満たすか）。破損・汚損はないか。受け入れるか返送するか |
| **作るもの** | **入荷実績データ**、検品記録、不一致があれば**受入不備の連絡** |
| **次に渡す先** | 在庫管理機能（S14へ）、仕入・調達機能（不備があった場合） |
| **頻度** | 日次／発注時に対応する入荷時 |

**なぜ入荷検品が重要か**
ここで見逃した不良・期限不足・数量違いは、**自社の在庫として登録され、
得意先に出荷されてから発覚します。**
そうなると、得意先でのクレーム → 返品 → 再納品 → 仕入先への交渉、と手間が数倍になります。【Inference】

#### S14. 入庫・ロケーション登録

| 項目 | 内容 |
|---|---|
| **誰が** | 物流・倉庫機能（入荷担当）／在庫管理機能 |
| **受け取るもの** | 検品済の商品、入荷実績データ |
| **何をするか** | 温度帯別・商品別に所定のロケーションへ格納する。在庫データを更新する。賞味期限・ロットを在庫情報に紐づける。先入先出ができるように配置する |
| **何を判断するか** | どのロケーションに置くか（回転が速い商品は取りやすい場所へ）。既存在庫と新しい在庫の前後関係をどうするか |
| **作るもの** | **更新された在庫データ**（引当可能在庫が増える）、ロケーション情報 |
| **次に渡す先** | 受注・業務機能（引当に使える在庫になる）、仕入・調達機能（入荷完了の確認） |
| **頻度** | 日次 |

#### S15. 仕入計上（買掛金の発生）

| 項目 | 内容 |
|---|---|
| **誰が** | 経理・財務機能（買掛担当）／入荷データを元にシステムが自動計上する場合が多い |
| **受け取るもの** | 入荷実績データ、仕入先の納品書 |
| **何をするか** | 仕入を計上する。**買掛金**（仕入先に支払うべき債務）を発生させる |
| **何を判断するか** | 仕入単価が契約どおりか。数量が入荷実績と一致するか |
| **作るもの** | **仕入データ**、**買掛金の残高** |
| **次に渡す先** | 経理・財務機能（S23の仕入締めへ） |
| **頻度** | 日次／納品時 |

**用語**
**買掛金（かいかけきん）**
→ 商品を仕入れたが、まだ支払っていない代金。**会社の債務（負債）**です。
→ 実務例：「今月の買掛金残高は3億円。来月末に支払う」。

> **【重要な区別】** **発注 ≠ 仕入計上**。
> 注文しただけでは仕入にはなりません。**商品が届いて検収した時点**で仕入になります。
> （この区別は `16_glossary.md` の「初心者が間違えやすいこと」でも扱います）

### 【例外処理】

#### S16. 返品処理

| 項目 | 内容 |
|---|---|
| **誰が** | 営業機能（受付・判断）→ 受注・業務機能（伝票処理）→ 物流・倉庫機能（現物の受入） |
| **受け取るもの** | 得意先からの返品の申し出、返品された現物 |
| **何をするか** | 返品理由を確認する（誤出荷、破損、期限接近、売れ残り、誤発注）。返品を受けるか判断する。現物を回収する。**返品伝票**を起こし、売上を取り消す（**赤伝**）。在庫に戻せるものは戻し、戻せないものは廃棄・値下げ処分する。仕入先都合の場合は仕入先へ返品する |
| **何を判断するか** | 返品を受けるか、受ける場合の条件（全額戻すか、一部負担か）。在庫に戻せるか（期限・状態）。誰の責任か（自社／得意先／仕入先／運送会社） |
| **作るもの** | **返品伝票（赤伝）**、在庫の更新、仕入先への返品連絡 |
| **次に渡す先** | 経理・財務機能（請求金額の調整）、在庫管理機能（在庫数の修正）、仕入・調達機能（仕入先返品） |
| **頻度** | トラブル発生時／納品時（納品直後の返品）／月次（季節商品のシーズン終了時等）【Varies】 |

**用語**
**赤伝（あかでん）／赤伝票**
→ 売上や仕入を**マイナスで計上する伝票**のこと。返品や値引きの処理に使います。
　（プラスの伝票を「黒伝」と呼ぶことがあります）
→ 実務例：10ケース納品したうち2ケースが返品されたら、2ケース分の赤伝を起こす。
　請求時には、10ケース分の売上から2ケース分が差し引かれる。

**なぜ返品処理が難しいのか**【Inference】
返品は、**売上・在庫・請求・入金消込・仕入**のすべてに同時に影響します。
処理が漏れると「請求額が得意先の認識と合わない」「帳簿在庫と実在庫がずれる」という形で、
後の工程（S21の消込、S26の棚卸）で必ず問題として表面化します。

#### S17. クレーム対応

| 項目 | 内容 |
|---|---|
| **誰が** | 営業機能（一次受付）／内容により品質・衛生管理機能、物流・倉庫機能、仕入・調達機能 |
| **受け取るもの** | 得意先からのクレーム（品違い、数量違い、破損、期限不足、品質異常、納品遅れ） |
| **何をするか** | 事実を確認する。原因がどこにあるか調べる（自社の出荷ミス／輸送中の事故／仕入先の製造段階）。対応を決める（再納品、返品受入、値引き、代替品）。再発防止の記録を残す |
| **何を判断するか** | 誰の責任か。どこまで負担するか。仕入先に申し入れるべきか。回収が必要な事案か |
| **作るもの** | クレーム記録、対応結果、（該当時）仕入先への報告 |
| **次に渡す先** | 該当する機能すべて／重大な場合は経営機能へ |
| **頻度** | トラブル発生時 |

> **【Typical】** 食品・医薬品では、品質異常のクレームが**回収（リコール）**につながる可能性があるため、
> 「どのロットをどの得意先に何個出荷したか」を即座にたどれる記録（トレーサビリティ）が
> 日常的に求められます。

---

### 【カネの流れ】締め〜入金・支払

#### S18. 売上の締め

| 項目 | 内容 |
|---|---|
| **誰が** | 経理・財務機能（売掛担当）／受注・業務機能が売上データを確定 |
| **受け取るもの** | 期間中の売上データ（出荷・納品実績）、返品伝票、値引き伝票 |
| **何をするか** | 得意先ごとに決められた**締め日**で、その期間の売上を集計する。返品・値引きを反映する。得意先の検収データと自社の売上を突き合わせる（**請求差異の確認**） |
| **何を判断するか** | 締め対象に漏れ・重複がないか。得意先の認識と金額が一致しているか |
| **作るもの** | **締め後の売上集計**、得意先別の請求予定額 |
| **次に渡す先** | 経理・財務機能（S19へ） |
| **頻度** | 月次（得意先ごとの締め日）／法定・契約上のタイミング |

> **【Typical】** 締め日は得意先ごとに異なることが多く、
> 「月末締め」「20日締め」「10日締め」「15日・月末の2回締め」などが混在します。
> そのため経理は、月内に何度も締め処理を行うことになります。

#### S19. 請求書の発行・送付

| 項目 | 内容 |
|---|---|
| **誰が** | 経理・財務機能（売掛担当） |
| **受け取るもの** | 締め後の売上集計 |
| **何をするか** | **請求書**を作成する。消費税額を正しく記載する。得意先へ送付する（郵送、電子送付、Web明細、得意先のシステムへのデータ送信）。営業が持参する場合もある |
| **何を判断するか** | 金額・明細が正しいか。得意先が求める様式・送付方法に合っているか |
| **作るもの** | **請求書**、請求データ、**売掛金の確定** |
| **次に渡す先** | 得意先／与信・債権管理機能（残高管理のため） |
| **頻度** | 月次（締め日の後）／請求時 |

**用語**
**売掛金（うりかけきん）**
→ 商品を売ったが、まだ回収していない代金。**会社の債権（資産）**です。
→ 実務例：「B商店に対する売掛金は250万円」。

> **【重要な区別】** **売上 ≠ 入金**。
> 請求書を出した時点では、まだ1円も入っていません。
> 売上が立ってから実際に現金になるまでには、締めと支払サイトの分だけ時間がかかります。

#### S20. 入金

| 項目 | 内容 |
|---|---|
| **誰が** | 得意先（支払）／経理・財務機能（確認） |
| **受け取るもの** | 銀行振込、手形、でんさい（電子記録債権）、現金（集金の場合） |
| **何をするか** | 得意先の支払日に入金される。経理が銀行の入出金明細を確認する |
| **何を判断するか** | 予定どおり入金されたか。金額は請求額と一致するか |
| **作るもの** | 入金明細 |
| **次に渡す先** | 経理・財務機能（S21へ） |
| **頻度** | 月次（得意先の支払日）／入金時 |

#### S21. 入金消込

| 項目 | 内容 |
|---|---|
| **誰が** | 経理・財務機能（売掛担当） |
| **受け取るもの** | 入金明細、請求データ、売掛金残高 |
| **何をするか** | どの入金がどの請求に対応するかを突き合わせ、売掛金を減らす（**消込**）。差額がある場合は原因を特定する |
| **何を判断するか** | 請求額と入金額が一致するか。差額の原因は何か（返品の反映漏れ、値引きの認識違い、振込手数料の負担、一部入金、リベートとの相殺） |
| **作るもの** | **消込済の売掛金残高**、差異の一覧 |
| **次に渡す先** | 与信・債権管理機能（未回収の管理）／営業機能（差異の確認依頼） |
| **頻度** | 日次（入金があった日）／月次（締め後のまとめ処理）／入金時 |

**なぜ消込が大変なのか**【Typical】
- 1回の振込に複数の請求分がまとまっている
- 得意先が一部だけ支払ってくる（**一部入金**）
- 振込名義が会社名と違う（店舗名・代表者名で振り込まれる）
- 返品や値引きの認識が得意先と自社でずれている
- 振込手数料を差し引いて振り込まれる

#### S22. 督促・与信見直し

| 項目 | 内容 |
|---|---|
| **誰が** | 与信・債権管理機能（経理担当）→ 営業機能（実際の連絡）→ 経営機能（重大時） |
| **受け取るもの** | 消込後の未回収リスト（**年齢表**：どれだけ古い売掛金が残っているか） |
| **何をするか** | 未入金の得意先に連絡し、事情を確認する。支払予定を取り付ける。入金遅延が続く場合は与信限度額を下げる、出荷を止める、担保・保証を求める |
| **何を判断するか** | 単なる事務処理の遅れか、資金繰りの悪化か。取引を継続するか。出荷を止めるか。法的手続きに進むか |
| **作るもの** | 督促記録、**与信限度額の変更**、出荷停止の指示 |
| **次に渡す先** | 営業機能・受注業務機能（出荷停止の反映）、経営機能（重大案件の報告） |
| **頻度** | 月次（入金確認後）／トラブル発生時 |

> **【Typical】** 営業担当は「売る側」であるため督促を言い出しにくく、
> 経理が把握して営業に依頼する形をとることが多くあります。
> 一方、得意先の状況を最もよく知っているのは営業であるため、
> **経理と営業の情報のやり取りが、貸倒れを防ぐ実務上の要**になります。

#### S23. 仕入の締め

| 項目 | 内容 |
|---|---|
| **誰が** | 経理・財務機能（買掛担当） |
| **受け取るもの** | 期間中の仕入データ、仕入先からの請求書、仕入先返品の伝票 |
| **何をするか** | 仕入先ごとの締め日で仕入を集計する。仕入先の請求書と自社の仕入計上額を突き合わせる（**買掛照合**） |
| **何を判断するか** | 金額が一致するか。差額があればその原因（単価違い、数量違い、返品の反映漏れ、リベートの扱い） |
| **作るもの** | **確定した買掛金残高**、差異の照会 |
| **次に渡す先** | 経理・財務機能（S24へ）、仕入・調達機能（差異の確認依頼） |
| **頻度** | 月次（仕入先ごとの締め日）／法定・契約上のタイミング |

#### S24. 支払（買掛金の決済）

| 項目 | 内容 |
|---|---|
| **誰が** | 経理・財務機能（買掛担当・経理部長）／最終承認は経営機能 |
| **受け取るもの** | 確定した買掛金残高、支払予定表、資金繰り表 |
| **何をするか** | 支払日に、銀行振込・手形・でんさいなどで支払う。支払前に資金残高を確認し、不足する場合は借入や入金予定を調整する |
| **何を判断するか** | 支払資金が足りるか。支払順序をどうするか。借入が必要か |
| **作るもの** | 支払実績、**買掛金の消滅**、資金繰りの実績 |
| **次に渡す先** | 仕入先／経営機能（資金状況の報告） |
| **頻度** | 月次（支払日）／法定・契約上のタイミング |

#### S25. リベート精算

| 項目 | 内容 |
|---|---|
| **誰が** | 仕入・調達機能（バイヤー・商品部長）／経理・財務機能（計上・入金確認） |
| **受け取るもの** | 仕入先との取り決め（リベート条件）、期間の仕入実績・販売実績 |
| **何をするか** | 条件の達成状況を確認する。仕入先と金額を確認・合意する。入金または買掛金との相殺を受ける。得意先へ支払うリベートがある場合は同様に精算する |
| **何を判断するか** | 条件を達成しているか。計算根拠が合意内容と一致するか。いつの期間の利益として計上するか |
| **作るもの** | リベートの精算資料、**リベート収入の計上**（または販売促進費の計上） |
| **次に渡す先** | 経理・財務機能（損益への反映）、経営機能（実績報告） |
| **頻度** | 四半期／半期／年次／月次（契約による）【Varies】 |

> **【Inference】** リベートは商品ごとの粗利には表れないため、
> リベートを含めない段階の利益（商品別粗利）と、
> リベートを含めた後の利益（最終的な利益）が乖離します。
> この乖離をどう管理するかが、卸売業の利益管理の難しさの一因になっています。

### 【定期的に行うこと】

#### S26. 棚卸（たなおろし）

| 項目 | 内容 |
|---|---|
| **誰が** | 物流・倉庫機能（実地カウント）／在庫管理機能・経理・財務機能（照合・評価） |
| **受け取るもの** | 帳簿在庫データ |
| **何をするか** | 倉庫の商品を実際に数える（**実地棚卸**）。帳簿在庫と突き合わせる。差異があれば原因を調べ、帳簿を修正する（**棚卸差異の処理**） |
| **何を判断するか** | 差異の原因は何か（入出庫の記録漏れ、誤出荷、破損の未処理、盗難、数え間違い）。在庫の評価をどうするか（期限切れ・不良在庫の評価減） |
| **作るもの** | **実地棚卸表**、棚卸差異の記録、修正後の在庫データ、在庫金額（決算資料） |
| **次に渡す先** | 経理・財務機能（決算処理）、経営機能（在庫状況の報告） |
| **頻度** | 月次（簡易な循環棚卸）／半期・年次（全品目の実地棚卸）【Varies】 |

**なぜ棚卸が必要か**
帳簿上の在庫と実際の在庫は、日々の作業の中で必ずずれていきます。
在庫金額は決算における利益計算に直結するため、
**実際の数量を確認して帳簿を合わせる**作業が不可欠です。【Typical】

#### S27. 滞留在庫・期限接近在庫の処置

| 項目 | 内容 |
|---|---|
| **誰が** | 在庫管理機能・仕入・調達機能（抽出と方針決定）／営業機能（販売努力） |
| **受け取るもの** | 在庫データ（動きのない在庫、期限が近い在庫の一覧） |
| **何をするか** | 動きのない在庫・期限が近い在庫を抽出する。値下げして売る、特売に投入する、仕入先に返品交渉する、廃棄するなどの処置を決める |
| **何を判断するか** | まだ売れるか。値下げしてでも売るか。廃棄するか。仕入先に相談できるか |
| **作るもの** | 滞留在庫リスト、処置の記録、（廃棄の場合）**廃棄損の計上** |
| **次に渡す先** | 営業機能（販売）、経理・財務機能（評価損・廃棄損の計上） |
| **頻度** | 週次・月次（抽出）／随時（処置） |

#### S28. 取引条件の見直し

| 項目 | 内容 |
|---|---|
| **誰が** | 経営機能・仕入・調達機能（仕入条件）／経営機能・営業機能（販売条件） |
| **受け取るもの** | 得意先別・商品別の採算資料、仕入先との契約内容、市況・原価の変動情報 |
| **何をするか** | 仕入先と仕入価格・リベート条件・支払条件を交渉する。得意先と売価・配送条件・支払条件を交渉する |
| **何を判断するか** | 条件を変更すべきか。取引を継続するか。価格改定を申し入れるか |
| **作るもの** | 改定後の価格、契約書の更新、価格マスタの更新指示 |
| **頻度** | 年次・半期（定期見直し）／案件発生時（原価変動時、契約更新時）【Varies】 |

## 4-3. 【重要】2つの供給パターン ——「在庫販売」と「都度仕入」

卸売業の受注処理には、**まったく異なる2つのパターン**があります。
どちらも同じ会社の中に共存しているのが普通です。【Typical】

### 4-3-1. 比較表

| 比較軸 | **パターンA：在庫販売（在庫から出す）** | **パターンB：都度仕入（受注のたびに仕入れる）** |
|---|---|---|
| どんな商品か | 定番品、回転の速い商品、多数の得意先が買う商品 | 特注品、大ロット品、取扱頻度の低い商品、大型品 |
| 在庫を持つか | **持つ** | **持たない** |
| 受注から納品まで | **短い**（当日〜翌日） | **長い**（仕入先の納期に依存） |
| 在庫リスク | **負う**（売れ残りリスク） | **ほぼ負わない** |
| 資金負担 | 在庫に資金が固定される | 在庫には固定されない（買掛と売掛の差だけ） |
| 欠品リスク | 在庫があれば欠品しない | 仕入先の在庫・生産次第で欠品しうる |
| 粗利 | 事前にまとめ買いすることで仕入単価を下げられる | 都度の仕入単価になる |
| 主な業種 | 食品卸（定番品）、消耗品、日用品 | 建材卸（特注建材）、機械卸（機械本体）、アパレル卸（別注品） |

### 4-3-2. フローの違い

```
■ パターンA：在庫販売

  得意先 ─受注─▶ 【S2受注入力】 ─▶ 【S3在庫引当】
                                        │（在庫あり）
                                        ▼
                                  【S6出荷指示】─▶【S7ピッキング】─▶【S9配送】─▶【S10納品】

  （並行して、別のサイクルで）
  【S11発注点判定】─▶【S12発注】─▶【S13入荷検品】─▶【S14入庫】
     ※ 受注とは無関係に、在庫を減らさないために回り続けている


■ パターンB：都度仕入

  得意先 ─引合─▶ 【見積】 ─▶ 得意先の発注 ─▶ 【S2受注入力】
                                                    │
                                                    ▼
                                             【S12発注】（仕入先へ）
                                                    │
                                                    ▼
                                        【納期回答】─▶ 得意先へ連絡
                                                    │
                          ┌─────────────┴──────────────┐
                          ▼（自社倉庫経由）                    ▼（直送）
                   【S13入荷検品】                       メーカーが得意先へ直送
                          │                                    │
                   【S14入庫】                          【得意先が検収】
                          │                                    │
                   【S7ピッキング】                     【出荷実績データを受領】
                          │                                    │
                   【S9配送】─▶【S10納品】             【売上・仕入を同時計上】
```

### 4-3-3. 実務上のポイント【Typical】

| ポイント | 説明 |
|---|---|
| 同じ会社に両方ある | 「定番の調味料は在庫販売、季節限定のギフトは都度仕入」のように商品によって使い分ける |
| 都度仕入では納期回答が命 | 在庫がないため、「いつ届くか」を仕入先に確認して得意先に伝えるのが仕事の中心になる |
| 都度仕入は粗利が見えやすい | 1件の受注に1件の仕入が対応するため、案件ごとの粗利が明確に計算できる |
| 在庫販売は粗利が見えにくい | 仕入時期・仕入単価が異なる在庫が混ざるため、1件の売上に対する原価は計算方法（総平均法、移動平均法、先入先出法など）に依存する |
| 在庫販売は「持つ判断」が利益を決める | 何をどれだけ在庫として持つかの判断が、欠品と滞留の両方を左右する |

## 4-4. 【Example】1件の受注を最初から最後まで追跡する

> **【Example】** 以下はすべて**説明用の架空の例**です。実在の企業・取引ではなく、
> 記載した金額・日付・数量も実データではありません。
> 日付は「1件の受注がどう流れるか」を示すための仮の設定です。

### 登場人物

| 登場人物 | 説明 |
|---|---|
| **A食品商事株式会社** | 本資料のモデル企業（架空）。食品専門卸、従業員45名 |
| **Bスーパー** | A社の得意先（架空）。県内に4店舗を持つ食品スーパー。**20日締め・翌月末払い**、与信限度額500万円 |
| **C食品工業** | A社の仕入先（架空）。調味料メーカー。A社は**C食品の地域特約店（一次卸）** |
| **D物産** | A社の仕入先（架空）。全国規模の食品卸。A社はここから多くの商品を**二次卸**として仕入れる |

### タイムライン

---

#### 【Day 1（3月10日）午前】営業訪問 ——S0-1の続き／情報の入手

**誰が**：A社営業部・営業担当（Bスーパー担当）
Bスーパーの本店を訪問。売場を確認し、バイヤーと面談。

> Bスーパーのバイヤー：「4月の第1週に『鍋つゆ処分特売』をやりたい。
> C食品の鍋つゆ1Lを、4店舗合計で200ケース。単価はいくらになる？」

**営業の判断**：通常売価は1ケース3,600円。特売なので数量が大きい。
社に持ち帰って仕切価格と在庫を確認することにする。

**作るもの**：商談記録（特売の引合情報）
**次に渡す先**：仕入・調達機能（商品部）、受注・業務機能
**頻度**：案件発生時

---

#### 【Day 1 午後】社内での価格・在庫確認

**誰が**：A社商品部・バイヤー ＋ 営業担当

**確認したこと**
- 現在の在庫：鍋つゆ1L = 45ケース（うち引当済12ケース、引当可能33ケース）
- 賞味期限：在庫分は7月末。Bスーパーの納品期限基準（残存3分の2以上）を満たす
- C食品からの仕切価格：1ケース3,100円
- C食品の納期：発注から3営業日
- C食品の特売対応：100ケース以上の一括発注なら、仕切価格を1ケース2,950円に引き下げる条件あり

**判断**
- 200ケースのうち、在庫33ケースを充当し、**不足167ケースをC食品へ発注**する
- ただし発注は10ケース単位なので、**170ケース発注**する（余る3ケースは通常在庫に回す）
- 170ケース発注により特売仕切2,950円が適用される
- Bスーパーへの売価は **1ケース3,250円** とする

**粗利の試算【Example】**

```
 売上   ：200ケース × 3,250円 ＝ 650,000円

 原価   ：在庫分  33ケース × 3,100円 ＝ 102,300円
          新規分 167ケース × 2,950円 ＝ 492,650円
                                 計  ＝ 594,950円

 粗利   ：650,000 − 594,950 ＝ 55,050円（粗利率 約8.5%）
```

> **注**：上記の金額はすべて説明のための架空の数値です。
> 実際の仕切価格・売価・粗利率は、商品・取引先・時期によって大きく異なります【Varies】。

**作るもの**：見積内容、発注の方針
**次に渡す先**：営業機能（得意先へ回答）、仕入・調達機能（発注）

## この章のまとめ

1. 卸売業のEnd-to-Endは、**受注 → 引当 → 出荷 → 納品 → 締め → 請求 → 入金 → 消込** という
   「売る側の線」と、**発注点判定 → 発注 → 入荷 → 入庫 → 仕入計上 → 支払** という
   「買う側の線」の**2本が並行して走っている**。
2. その2本をつないでいるのが**在庫**。だから在庫データの正確さがすべての工程に効く。
3. 卸売業固有の要素は、**在庫引当・欠品対応・与信限度・締め日・売掛金の消込・返品（赤伝）・
   直送・発注点／安全在庫**。
4. 供給の仕方には **在庫販売** と **都度仕入** の2パターンがあり、同じ会社に共存している。
5. 商品を渡してから代金が入るまでには**数十日の時間差**があり、
   **支払いのほうが先に来ることがある**。これが卸売業の資金繰りの構造。

# 11_systems.md — システム（今の仕事を理解するための道具として）

**対象**：日本国内の中小製造業
**前提**：`09_information.md`（情報の流れ）／`10_documents.md`（帳票）を読んでいること
**最終更新**：2026-09-16

> ### ⚠️ このファイルの位置づけ（厳守事項）
>
> 本ファイルは、**製造業の仕事を理解するために必要な範囲で、
> 業界で一般的に使われているシステムの「カテゴリ」を説明する**ものです。
>
> **次のことは一切書きません。**
> - システムの導入提案、乗り換えの提案
> - 良し悪しの評価、「あったほうがよい」「なくても困らない」といった判断
> - 特定の製品・ベンダーの推奨
> - デジタル化・自動化に関する論評
>
> 書くのは次のことだけです。
> **「それは何を管理する道具か／誰が使うか／どの業務で使うか／どんな情報が入り、どんな情報が出るか」**
>
> なぜこの方針かというと、システムの名前を知らないと、
> 「販売管理に入力しておいて」「生産管理から出した」といった会話が理解できないためです。
> **システムは、`09_information.md` で見た情報が置かれている「場所」**として理解してください。

## 11-1. 全体像：どの情報がどのシステムに置かれるか

```
【情報とシステムの対応（中小製造業の一般的な姿）】【Typical】

  ＜顧客＞                                                    ＜仕入先・外注先＞
     │                                                              ▲
     │ 注文・納入指示                                                │ 発注
     ▼                                                              │
 ┌──────────────┐                                    ┌──────────────┐
 │  EDI / 顧客の      │                                    │  EDI（あれば） │
 │  購買システム       │                                    └──────────────┘
 └───────┬──────┘                                              ▲
         │ 受注情報                                                │
         ▼                                                        │
 ┌───────────────────────────────────────────────────┐
 │           生産管理システム                                        │
 │  受注 → 生産計画 → 材料所要量 → 製造指示 → 進捗 → 実績 → 在庫      │
 └───┬───────────┬──────────────┬───────────────┬──────┘
     │           │              │               │
     │ 図面・工程  │ 実績工数      │ 在庫数         │ 出荷実績
     ▼           ▼              ▼               ▼
 ┌────────┐ ┌────────┐ ┌──────────┐ ┌──────────────┐
 │ CAD/CAM  │ │ 原価管理  │ │ 在庫管理  │ │ 販売管理システム  │
 │ CAE      │ │ システム  │ │ システム  │ │ 受注→売上→請求→入金│
 └────────┘ └───┬────┘ └──────────┘ └───────┬──────┘
                  │                                  │
                  └─────────────┬────────────────┘
                                ▼
                        ┌──────────────┐
                        │  会計ソフト      │
                        │ 仕訳・試算表・決算│
                        └──────────────┘
                                ▲
       ┌────────────────────────┼────────────────────────┐
       │                        │                        │
 ┌──────────┐        ┌──────────────┐      ┌──────────────┐
 │ 勤怠管理    │ ────▶ │ 給与計算システム │      │ ISO文書管理     │
 └──────────┘        └──────────────┘      └──────────────┘
```

> **【Typical】中小製造業の実態**
> 上の図のすべてが独立したシステムとして存在するとは限りません。
> 【Typical】次のような形が広く見られます。
> - 生産管理と販売管理が1つのパッケージになっている
> - 在庫管理が生産管理の一機能になっている
> - 原価管理を表計算ソフトで行っている
> - 会計は税理士事務所のソフトで処理している
> - 一部の業務が紙と表計算ソフトで運用されている
>
> 【Fact】中小企業のITツール利用状況について、中小企業庁は中小企業白書等で調査結果を公表しています。
> 【Varies】どのシステムをどこまで使っているかは企業により大きく異なるため、
> 本資料では「どの企業も○○を使っている」という断定はしません。

## 11-2. 生産管理システム

| 項目 | 内容 |
|---|---|
| **何を管理する道具か** | 「いつ・何を・どれだけ作るか」と「今どこまで進んだか」を管理する道具 |
| **誰が使うか** | ② 受注・生産管理機能（中心）、⑤ 製造機能、④ 調達機能、① 営業機能 |
| **どの業務で使うか** | ⑤受注登録 → ⑥生産計画 → ⑦材料手配の指示 → ⑧受入 → ⑨製造指示 → 進捗管理 → 実績収集（`04_end-to-end-process.md` のステップ） |
| **どんな情報が入るか** | 受注情報（品番・数量・納期・単価）、部品表（BOM）、工程情報（工程の順序・標準時間）、在庫情報、設備の能力情報、作業日報の実績、入荷実績 |
| **どんな情報が出るか** | 生産計画表、製造指示書、現品票、材料所要量（何をいつまでに何個買うか）、進捗状況、受注残、負荷状況、在庫数 |

### 中で行われている計算の考え方

> **用語：MRP（エムアールピー／資材所要量計画）**
> → Material Requirements Planning の略。
>   「何を、いつまでに、いくつ手配すればよいか」を計算する考え方です。
> → **計算の流れ**：
>   1. 受注情報から「製品を何個、いつまでに作るか」を決める
>   2. **BOM（部品表）**を掛け算して「部品・材料が何個必要か」を出す
>   3. **在庫**を引いて「不足分」を出す
>   4. **調達期間（リードタイム）**を逆算して「いつ発注すればよいか」を出す
> → 実務例：ブラケット1,000個を5月26日までに作る
>    → BOMより、本体板1,000枚＋補強板2,000枚が必要
>    → 在庫が本体板200枚あるので、不足は800枚
>    → 鋼板の調達期間が7日なので、製造着手の5月7日から逆算して5月1日までに入荷、
>      つまり4月22日には発注する必要がある
> → **なぜこの計算が要るのか**：【Typical】品目数が多くなると、
>    「何をいつ発注すればよいか」を人が頭の中で計算しきれなくなるためです。

> **用語：MES（エムイーエス／製造実行システム）**
> → Manufacturing Execution System の略。
>   工場の現場で、作業の指示・実績の収集・設備の稼働状況の把握を行う仕組み。
> → 実務例：作業者が端末で作業の開始・終了を入力すると、実績工数が自動的に記録される。
> → 【Varies】MESという形で独立して導入されているかどうかは企業により異なります。
>    中小製造業では、生産管理システムの一機能として扱われたり、作業日報（紙）で代替されたりします。

> **用語：かんばん方式・製番管理・MRP（計画のやり方の違い）**
> → 製造業で生産の指示を出す考え方には複数あり、生産形態によって使い分けられます。
>
> | 方式 | 考え方 | 【Typical】向く生産形態 |
> |---|---|---|
> | **製番管理**（オーダー別管理） | 1つの注文（製番）ごとに、材料から完成まで紐づけて管理する | 個別受注生産。一品物、機械製造 |
> | **MRP** | 計画（需要）から必要量を計算して手配する | 繰返生産、部品点数の多い製品 |
> | **かんばん方式** | 使った分だけ後から補充する | 繰返生産、需要が安定している製品 |
>
> → 【Varies】どれを使うかは製品と取引形態によって決まり、1社の中で併用されることもあります。

## 11-3. 販売管理システム

| 項目 | 内容 |
|---|---|
| **何を管理する道具か** | 「誰に、何を、いくらで売り、いくら請求し、いくら入金されたか」を管理する道具 |
| **誰が使うか** | ① 営業機能、⑨ 経理・財務機能、② 受注・生産管理機能 |
| **どの業務で使うか** | ④見積提出 → ⑤受注 → ⑬納品 → ⑭検収 → ⑮請求 → ⑯入金（`04_end-to-end-process.md` のステップ） |
| **どんな情報が入るか** | 顧客情報（住所・締め日・支払条件・与信限度）、見積情報、受注情報、単価情報、出荷実績、検収情報、入金情報 |
| **どんな情報が出るか** | 見積書、注文請書、納品書、請求書、売掛金残高、未入金リスト、売上集計（顧客別・製品別・月別）、受注残 |

> **生産管理システムとの違い**
> 【Typical】両者は同じ「受注情報」を扱いますが、見ている角度が違います。
>
> | | 生産管理システム | 販売管理システム |
> |---|---|---|
> | 関心 | **作れるか、間に合うか** | **いくらで売って、いくら回収するか** |
> | 単位 | 品番・数量・工程・時間 | 顧客・金額・締め日 |
> | 主に使う機能 | ② 生産管理、⑤ 製造 | ① 営業、⑨ 経理 |
>
> 【Varies】中小製造業では、この2つが1つのパッケージにまとまっていることも多くあります。

> **用語：与信限度（よしんげんど）**
> → その顧客に対して、代金未回収のまま許容できる金額の上限。
> → 実務例：ある顧客の与信限度を500万円と設定しておき、売掛金残高がそれに近づいたら
>    新規の受注や出荷を保留にして、社長に確認する。
> → **なぜ設定するのか**：`08_money.md` 8-5 のとおり、顧客が倒産すれば売掛金は回収できません。
>    1社に対する未回収額が膨らむほど、その損失が会社の存続に関わる規模になります。

## 11-4. 会計ソフト（財務会計システム）

| 項目 | 内容 |
|---|---|
| **何を管理する道具か** | 会社のお金の出入りを記録し、決算書を作るための道具 |
| **誰が使うか** | ⑨ 経理・財務機能、税理士事務所、社長 |
| **どの業務で使うか** | 日々の仕訳（記帳）、月次試算表の作成、決算、税務申告 |
| **どんな情報が入るか** | 売上（販売管理から）、仕入（購買から）、経費の支払、給与（給与計算から）、入金・出金（銀行の記録）、在庫金額（棚卸表から）、減価償却費 |
| **どんな情報が出るか** | 仕訳帳、総勘定元帳、月次試算表、貸借対照表、損益計算書、製造原価報告書、消費税の集計 |

> **用語：仕訳（しわけ）**
> → お金や資産の動きを、決められた勘定科目（売上、仕入、現金、売掛金など）に振り分けて記録すること。
>   簿記の基本単位です。
> → 実務例：A社への売上800,000円が確定したとき、
>    「（借方）売掛金 800,000 ／（貸方）売上 800,000」と記録します。
>    その後入金されたとき、「（借方）普通預金 800,000 ／（貸方）売掛金 800,000」と記録します。
> → **なぜ2つに分けて書くのか**：お金の動きには必ず「増える側」と「減る側（または原因）」があるためです。
>    この形式を**複式簿記**といいます。

> **【Typical】中小製造業での使われ方**
> 【Typical】中小製造業では、会計処理の一部または全部を税理士事務所に委託していることが多く見られます
> （`03_company-structure.md` 3-3）。
> その場合、日々の記帳を自社で行い、月次のチェックと決算を税理士が行う、という分担が一般的です【Varies】。

## 11-5. 原価管理システム（原価計算）

| 項目 | 内容 |
|---|---|
| **何を管理する道具か** | 「その製品を作るのに、実際いくらかかったか」を計算する道具 |
| **誰が使うか** | ⑨ 経理・財務機能、① 営業機能、② 生産管理機能、社長 |
| **どの業務で使うか** | ③見積（予定原価）、製造後の実績原価の集計、見積と実績の比較、単価改定の検討 |
| **どんな情報が入るか** | 材料の使用実績（何をどれだけ使ったか）、作業日報の実績工数、チャージレート（賃率）、外注費、経費の配賦基準 |
| **どんな情報が出るか** | 受注番号別・製品別の実績原価、見積原価との差額、製品別の粗利、赤字案件の一覧 |

> **原価計算の2つの場面**
>
> | | **見積原価**（予定原価） | **実績原価** |
> |---|---|---|
> | いつ計算するか | 作る**前**（③見積のステップ） | 作った**後**（製造完了後・月次） |
> | 何に使うか | 見積金額を決める | 見積どおりだったかを確認する |
> | データの元 | 過去の実績、標準時間、材料単価の見積り | 作業日報、材料の払出記録、外注の請求 |
>
> 【Inference】この2つを比較することが、**見積の精度を上げる唯一の方法**です。
> `09_information.md` 9-2 ⑨ で述べた「見積 → 製造 → 実績 → 次の見積」のループの、
> 計算部分を担うのがこの道具です。

> **【Varies】中小製造業での実態**
> 【Typical】独立した原価管理システムを持つ企業もあれば、
> 生産管理システムの一機能として原価を集計する企業、
> 表計算ソフトで受注番号ごとに集計する企業もあります。
> 【Varies】どこまで細かく原価を追うか（受注番号ごとか、製品ごとか、月単位の全体か）は企業により異なります。

## 11-6. 在庫管理システム

| 項目 | 内容 |
|---|---|
| **何を管理する道具か** | 「今、何が、どこに、いくつあるか」を管理する道具 |
| **誰が使うか** | ④ 調達機能、⑦ 出荷・物流機能、② 生産管理機能 |
| **どの業務で使うか** | ⑦材料手配（在庫を確認してから発注）、⑧受入（入庫）、⑨製造（出庫）、⑫出荷、棚卸 |
| **どんな情報が入るか** | 入庫（受入実績）、出庫（製造への払出）、返品、棚卸の結果、置き場所（ロケーション） |
| **どんな情報が出るか** | 品目別の在庫数、在庫金額、置き場所、入出庫の履歴、滞留在庫（長期間動いていないもの）、発注点を下回った品目 |

> **用語：発注点（はっちゅうてん）**
> → 「在庫がこの数を下回ったら発注する」と決めておく基準の数量。
> → 実務例：ボルトM6の発注点を500本と決めておき、在庫が500本を切ったら1,000本発注する。
> → **なぜ必要か**：【Typical】毎日すべての品目の在庫を確認するのは現実的でないため、
>    「この数になったら動く」という基準を決めておきます。
>    定番の材料や消耗品でよく使われる考え方です。

> **【Typical】在庫データと現物が合わなくなる理由**
> | 理由 | 説明 |
> |---|---|
> | 出庫の記録漏れ | 急ぎの仕事で、材料を取って使ったが記録していない |
> | 不良による消費 | 不良が出て余分に材料を使ったが、その分が記録されていない |
> | 端材の扱い | 端材を使える在庫とみなすかどうかの基準が曖昧 |
> | 置き場所の相違 | 別の場所に置かれていて「無い」と判断された |
> | 数え間違い | 大量の小物部品の計数誤差 |
>
> 【Typical】このため、**棚卸**によって定期的に現物と帳簿を合わせる作業が必要になります（`07_goods.md` 7-9）。

## 11-7. 設計・技術系のシステム（CAD／CAM／CAE）

### CAD（キャド）

| 項目 | 内容 |
|---|---|
| **何を管理する道具か** | 図面を作成・編集・保管する道具。Computer Aided Design（コンピュータ支援設計）の略 |
| **誰が使うか** | ③ 生産技術機能、設計機能（自社設計を行う場合）。受託加工型では**顧客が使い、自社は受け取って見る側**になることが多い【Typical】 |
| **どの業務で使うか** | ②仕様確認・図面受領、③見積（形状の確認）、⑨製造（加工形状の確認）、治具の設計 |
| **どんな情報が入るか** | 形状、寸法、公差、材質の指定 |
| **どんな情報が出るか** | 図面データ（2D／3D）、展開図（板金を平らに開いた形）、CAMへ渡す形状データ、印刷用の図面 |

> **2次元CADと3次元CADの違い**
> | | 2次元CAD（2D） | 3次元CAD（3D） |
> |---|---|---|
> | 扱うもの | 平面の図面（正面図・側面図・上面図） | 立体のモデル |
> | 【Typical】用途 | 図面そのもののやり取り | 形状の確認、干渉チェック、CAM・CAEへの受け渡し |
> | 【Varies】受託加工での実態 | 顧客からPDFや紙で受け取ることも多い | 顧客から3Dデータで受け取ることもある |
>
> 【Typical】受託加工の現場では、**顧客がどの形式で図面を渡してくるかに合わせる**ことになります。
> 顧客ごとに形式が異なることもあります【Varies】。

### CAM（キャム）

| 項目 | 内容 |
|---|---|
| **何を管理する道具か** | 図面データから、工作機械を動かすためのプログラムを作る道具。Computer Aided Manufacturing（コンピュータ支援製造）の略 |
| **誰が使うか** | ③ 生産技術機能、⑤ 製造機能（機械加工・レーザー加工の担当者） |
| **どの業務で使うか** | ⑥生産計画の前提となる工程準備、⑨製造（加工） |
| **どんな情報が入るか** | 図面データ（CADから）、使用する工具、加工条件（回転数・送り速度）、材料の形状 |
| **どんな情報が出るか** | **NCプログラム**（工作機械への動作指令）、加工時間の見積り、工具の経路 |

> **用語：NC／CNC（エヌシー／シーエヌシー）**
> → Numerical Control（数値制御）の略。工作機械を数値の指令で自動的に動かす仕組み。
>   CNC は Computer Numerical Control。
> → 実務例：「NC旋盤」「マシニングセンタ」は、プログラムに従って自動的に刃物を動かして加工する機械です。
> → **なぜCAMが要るのか**：【Typical】複雑な形状の加工プログラムを、
>    人が数値で1行ずつ書くのは現実的でないためです。
>    【Varies】単純な形状であれば、機械の操作パネルで直接入力することもあります。

> **【Typical】ネスティング（板取り）**
> → 板金加工では、1枚の鋼板から複数の部品を切り出すため、
>   「どう並べれば無駄が少ないか」を決める作業が発生します。これを**ネスティング（板取り）**といいます。
> → **なぜ重要か**：`04_end-to-end-process.md` ③ で出てきた**歩留まり**に直結します。
>   歩留まりが80％か90％かで、材料費が10％以上変わります。

### CAE（シーエーイー）

| 項目 | 内容 |
|---|---|
| **何を管理する道具か** | 作る前に、コンピュータ上で強度・変形・熱・流れなどを計算して確かめる道具。Computer Aided Engineering の略 |
| **誰が使うか** | 設計機能（自社設計を行う場合）、③ 生産技術機能 |
| **どの業務で使うか** | 設計、試作の前の検討、金型の設計（樹脂の流れの解析など） |
| **どんな情報が入るか** | 3D形状、材料の物性、荷重・温度などの条件 |
| **どんな情報が出るか** | 応力・変形・温度分布などの解析結果 |
| **【Varies】中小での実態** | 【Varies】自社設計を行う企業や、金型・樹脂成形を扱う企業で使われることがある。受託加工（顧客図面どおりに作る）では使わないことが多い |

## 11-8. 人事・労務系のシステム

### 勤怠管理システム

| 項目 | 内容 |
|---|---|
| **何を管理する道具か** | 誰が、いつ出勤し、何時間働き、いつ休んだかを記録する道具 |
| **誰が使うか** | ⑩ 人事・総務機能、⑤ 製造機能（工場長）、各従業員 |
| **どの業務で使うか** | 日々の出退勤記録、残業時間の管理、休暇の管理、給与計算の前処理 |
| **どんな情報が入るか** | 出勤・退勤の時刻、休憩、休暇申請、残業申請 |
| **どんな情報が出るか** | 月次の労働時間集計、残業時間、有給休暇の残日数、給与計算へ渡すデータ |

> **【Fact】なぜ労働時間の記録が必要か**
> 労働基準法では、法定労働時間を超えて労働させるには労使協定（36協定）の締結と労働基準監督署への届出が必要で、
> 36協定で定められる時間外労働の限度時間は原則として**1か月45時間・1年360時間**とされています。
> また、36協定に基づき労働させる場合でも、1か月の時間外労働と休日労働の合計は100時間未満、
> 2〜6か月間の1か月あたりの平均は80時間以下としなければなりません（出典：時間外労働の上限規制／厚生労働省）。
> 【Fact】労働基準法第108条に基づく賃金台帳には、労働日数・労働時間数などの記載が求められます
> （出典：労働基準法／e-Gov法令検索）。
> 【Inference】したがって、労働時間の記録は給与計算のためだけでなく、法令上の要請に対応するためにも必要になります。

### 給与計算システム

| 項目 | 内容 |
|---|---|
| **何を管理する道具か** | 給与・賞与の金額を計算し、支給と控除を記録する道具 |
| **誰が使うか** | ⑩ 人事・総務機能、⑨ 経理・財務機能、社会保険労務士 |
| **どの業務で使うか** | 月次の給与計算、賞与計算、年末調整、社会保険料の計算、住民税の処理 |
| **どんな情報が入るか** | 勤怠データ（労働時間・残業・休暇）、基本給・手当の設定、扶養情報、社会保険料率、税率 |
| **どんな情報が出るか** | 給与明細、**賃金台帳**、振込データ、社会保険・税の納付額、会計ソフトへ渡す仕訳データ |

> 【Typical】中小製造業では、給与計算を社会保険労務士に委託している企業も多く見られます【Varies】。

## 11-9. 企業間をつなぐ仕組み（EDI）

| 項目 | 内容 |
|---|---|
| **何を管理する道具か** | 顧客・仕入先と、注文・出荷・請求などの情報を、決められた形式のデータで直接やり取りする仕組み。Electronic Data Interchange の略 |
| **誰が使うか** | ① 営業機能、② 受注・生産管理機能、⑦ 出荷・物流機能、⑨ 経理・財務機能 |
| **どの業務で使うか** | ⑤受注（注文・納入指示の受信）、⑬納品（出荷データの送信）、⑭検収・⑮請求（検収データ・支払通知の受信） |
| **どんな情報が入るか** | 顧客からの発注データ、内示（フォーキャスト）、納入指示、検収データ、支払通知 |
| **どんな情報が出るか** | 出荷予定データ、出荷実績データ、請求データ |

> **なぜEDIが使われるのか**
> 【Typical】取引件数が多く、納入指示が頻繁に変わる取引（自動車部品の繰返生産など）では、
> 紙の注文書を1件ずつやり取りしていては間に合いません。
> 【Example】1日に複数回、数量が変更される納入指示が届く取引では、データで直接受け取る必要が生じます。
>
> 【Varies】EDIを使うかどうかは、**顧客の要求と取引量によって決まります**。
> 顧客ごとに異なる形式・異なる画面を求められることもあり、
> 取引先が多い中小製造業では複数の仕組みを併用することもあります【Typical】。

> **用語：Web-EDI**
> → 専用の通信回線ではなく、Webブラウザを通じて発注情報を受け取る形式。
> → 実務例：顧客の指定するWebサイトにログインして、その日の発注内容を確認し、印刷または取り込む。
> → 【Varies】顧客により、専用回線・Web・メール・FAXなど形式はさまざまです。

## 11-10. ISO文書管理・品質関連の仕組み【Varies】

| 項目 | 内容 |
|---|---|
| **何を管理する道具か** | ISO 9001 等のマネジメントシステムで必要な文書と記録を、版・保管場所・保存期間とともに管理する仕組み |
| **誰が使うか** | ⑥ 品質保証機能（ISO事務局）、全機能、審査機関 |
| **どの業務で使うか** | 文書の制定・改訂・配付・回収、記録の保管、内部監査、マネジメントレビュー、審査対応 |
| **どんな情報が入るか** | 品質マニュアル、手順書、作業標準書、QC工程表、各種記録（検査記録・教育記録・内部監査記録） |
| **どんな情報が出るか** | 有効な文書の一覧（どの版が最新か）、記録の保管場所、審査への提出資料 |

> **【Fact】なぜ文書の版管理が要求されるのか**
> ISO 9001 では、文書化した情報の管理として、必要なときに必要な場所で入手できること、
> 適切に保護されること、および**廃止された文書化した情報の誤使用の防止**が要求されています（箇条7.5.3）。
> 【Typical】製造業では、旧版の図面や作業標準書が現場に残っていると、
> それに従って作られた製品がすべて不適合になるため、この管理が実務上の要点になります。

> **【Fact】ISO 9001 の改訂について**
> ISO 9001 は2015年版が長く使われてきましたが、改訂版が2026年9月頃に発行される予定です。
> 国際認定機関フォーラム（IAF）から、次期規格への移行期間は国際規格の発行から3年間と発表されています
> （出典：日本規格協会（JSA）ISO 9001改訂動向）。
> 【Varies】認証を取得している企業では、この移行への対応が発生します。
> 詳細は `15_rules-customs.md` を参照。

> 【Varies】文書管理を紙のファイルで行う企業、共有フォルダで行う企業、専用の仕組みを使う企業があります。
> 認証を取得していない企業では、この仕組み自体が存在しません。

## 11-12. 表計算ソフトと紙の併用について【Typical】

> **⚠️ ここでも評価・提案は行いません。実態の記述のみです。**

【Typical】中小製造業では、業務システムと、表計算ソフト、紙の帳票が併存しているのが一般的です。
業界の会話を理解するうえで、この実態を知っておく必要があります。

| 【Typical】よく見られる組み合わせの例 | 説明 |
|---|---|
| 受注・請求はシステム、生産計画は表計算ソフト | 計画は日々変更されるため、自社の運用に合わせて自由に組み替えられる形が使われることがある |
| 製造指示書・現品票は紙、実績は集計して入力 | 工場では手袋・油・粉じんの環境があり、紙が現物と一緒に動く |
| 進捗はホワイトボードで共有 | 全員が同時に見られ、その場で書き換えられる |
| 原価集計は表計算ソフト | 自社の原価の考え方に合わせて計算式を組む |
| 会計は税理士事務所のソフト | 記帳の一部または全部を委託している |

> **【Inference】なぜこうなるのか（構造的な説明）**
> 1. **業務のやり方が企業ごとに違う**：製造業の仕事は、持っている設備・扱う製品・顧客の要求によって異なります。
>    このため、既製のシステムがそのまま自社の運用に合うとは限りません。
> 2. **顧客ごとに要求が違う**：顧客ごとに納入指示の形式、成績書の様式、請求の方法が異なります。
> 3. **工場と事務所で環境が違う**：`09_information.md` 9-4 のとおり、扱いやすい媒体が場所によって異なります。
>
> **本資料はこの実態に評価を加えません。** 業界の人との会話では、
> 「システムに入っている情報」と「表計算や紙で管理している情報」が混在している前提で話が進む、
> ということを理解しておくことが実務的に有用です。

## 11-13. 業種によってシステムはどう変わるか【Varies】

| 業種 | 【Typical】固有のシステム・仕組み |
|---|---|
| **食品製造** | 【Typical】**賞味期限・消費期限の管理**が在庫管理に組み込まれる。**ロットトレースの仕組み**（原材料ロットと製品ロットの紐づけ）。【Fact】HACCPに沿った衛生管理では重要管理点の監視記録が求められる（出典：厚生労働省）ため、温度等の記録の仕組みが使われる。食品表示の作成、配合（レシピ）管理、栄養成分計算 |
| **金属加工** | 本ファイルの基本形。CAD／CAM（板金では**ネスティング**）、生産管理、原価管理 |
| **機械製造** | **設計（3D CAD）とBOMの連携**が中核。部品点数が多く、設計変更が部品表に波及するため、**設計部品表と製造部品表の管理**が論点になる。プロジェクト（案件）ごとの工数・原価管理。据付・保守の履歴管理 |
| **電気機器** | **回路設計のCAD（EDA）**、基板実装のプログラム（マウンターデータ）、部品表（BOM）と部品在庫の連携。部品の調達リードタイムが長いため、**所要量計算（MRP）の比重が大きい** |
| **化学・プラスチック** | **配合（レシピ）管理**、バッチ製造記録、成分・物性の試験データ管理。**SDS（安全データシート）の作成・管理**。【Fact】化学物質の届出（化審法の一般化学物質の数量届出など）に対応する数量集計（出典：化学物質の審査及び製造等の規制に関する法律／e-Gov法令検索） |
| **印刷** | **DTP（デスクトップパブリッシング）**による版下作成、**面付け・製版**の処理、色管理（カラーマネジメント）、校正のやり取りの記録。用紙の手配と在庫管理 |

## 11-14. このファイルのまとめ

1. システムは、`09_information.md` で見た**情報が置かれている場所**として理解する。
2. **生産管理システム**は「いつ何をどれだけ作るか」と「今どこまで進んだか」を管理する。MRP（必要な材料と時期の計算）が中核にある。
3. **販売管理システム**は「誰にいくらで売って、いくら回収したか」を管理する。生産管理と同じ受注情報を、別の角度から見ている。
4. **原価管理**は「見積原価と実績原価を比べる」ための道具であり、見積の精度を支える。
5. **CAD／CAM** は図面と加工プログラムの道具。受託加工では、顧客がどの形式で図面を渡してくるかに合わせることになる。
6. **EDI** は顧客・仕入先と直接データをやり取りする仕組みで、使うかどうかは**顧客の要求と取引量**で決まる。
7. 中小製造業では、業務システム・表計算ソフト・紙が併存するのが一般的である。本資料はこれに評価を加えない。
8. どのシステムをどこまで使っているかは**企業により大きく異なる**ため、「どの企業も○○を使っている」という前提は持たない。

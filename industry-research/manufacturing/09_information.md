# 09_information.md — 情報の流れ（何の情報が、誰から誰へ渡るか）

**対象**：日本国内の中小製造業
**前提**：`04_end-to-end-process.md`（17ステップ）／`06_people.md`（ヒト）／`07_goods.md`（モノ）／`08_money.md`（カネ）を読んでいること
**最終更新**：2026-09-16

> **このファイルの方針：「情報」という抽象語で終わらせません。**
>
> 「情報を共有する」「情報が重要だ」と言っても、何も理解できません。
> 製造業の現場を流れているのは、**名前を付けられる具体的な情報**です。
>
> ```
> 問い合わせ情報 → 仕様情報 → 図面情報 → 見積情報 → 受注情報 → 計画情報
>   → 製造指示情報 → 実績情報 → 検査情報 → 出荷情報 → 請求情報 → 入金情報
> ```
>
> このファイルでは、これらを1つずつ取り上げ、
> **「誰が作り／誰が使い／どこに保管され／次に何に変わるか」**を明示します。

---

## 9-1. 情報の流れの全体像

### 12の情報が連鎖する

```
【顧客】                                                            【自社】

 問い合わせ                      ①問い合わせ情報
  ─────────────────────────────▶  ① 営業機能
                                        │
 図面・仕様書                    ②仕様情報 ③図面情報
  ─────────────────────────────▶  ① 営業 → ③ 生産技術
                                        │
                                  ④見積情報（原価情報を含む）
                                  ③ 生産技術＋④ 調達 → ① 営業
  ◀─────────────────────────────  見積書
 注文書                          ⑤受注情報
  ─────────────────────────────▶  ① 営業 → ② 生産管理
                                        │
                                  ⑥計画情報（生産計画・材料所要量）
                                  ② 生産管理
                                    ├──────────────▶ ⑦発注情報 → ④ 調達 → 仕入先・外注先
                                    │
                                  ⑧製造指示情報
                                  ② 生産管理 → ⑤ 製造
                                        │
                                  ⑨実績情報（作業日報・進捗）
                                  ⑤ 製造 → ② 生産管理／⑨ 経理
                                        │
                                  ⑩検査情報
                                  ⑥ 品質保証
                                        │
                                  ⑪出荷情報
                                  ② 生産管理 → ⑦ 出荷・物流
  ◀─────────────────────────────  納品書・検査成績書
 検収                            ⑫検収情報
  ─────────────────────────────▶  ⑨ 経理
                                        │
                                  ⑬請求情報
                                  ⑨ 経理
  ◀─────────────────────────────  請求書
 支払                            ⑭入金情報
  ─────────────────────────────▶  ⑨ 経理 → 社長
```

### 情報の流れを理解する3つの原則

> **原則1：【Typical】情報は、前の情報を材料にして次の情報が作られる**
> 見積情報は、仕様情報と図面情報がないと作れません。
> 受注情報は、見積情報と注文書がないと作れません。
> 生産計画情報は、受注情報と負荷情報がないと作れません。
> **前の情報が間違っていれば、後ろの情報はすべて間違います。**

> **原則2：【Typical】情報は途中で「形」を変えるが、中身はつながっている**
> 【Example】顧客が言った「1,000個、5月26日に欲しい」という**問い合わせ情報**は、
> → 見積書に書かれた「数量1,000／納期5月26日」という**見積情報**になり、
> → 注文書を経て「受注番号 X-2604-118／数量1,000／納期5/26」という**受注情報**になり、
> → 「5/7 切断着手、5/22 検査完了」という**計画情報**になり、
> → 製造指示書の「切断 1,020個」という**製造指示情報**になり、
> → 作業日報の「良品1,018個」という**実績情報**になり、
> → 納品書の「1,000個」という**出荷情報**になり、
> → 請求書の「800,000円」という**請求情報**になります。
> **同じ1件の注文が、12回ほど姿を変えて会社の中を通り抜けます。**

> **原則3：【Typical】情報は「モノ」と並走する**
> `07_goods.md` で見たとおり、工場では現品票という形で、モノに情報が貼り付いて動きます。
> **モノだけが動いて情報が動かないと、そのモノは正体不明になります。**
> **情報だけが動いてモノが動かないと、帳簿と現物が合わなくなります。**

## 9-2. 各情報の詳細

以下、12の主要な情報について、
**［何の情報か］［誰が作るか］［誰が使うか］［どこに保管されるか］［次に何に変わるか］［途切れると何が起きるか］**
を整理します。

---

### ① 問い合わせ情報（引合い情報）

| 項目 | 内容 |
|---|---|
| **何の情報か** | 顧客が「これを作れるか」「いくらか」「いつできるか」と聞いてきた内容。顧客名、担当者名、品名、想定数量、希望納期、用途、図面の有無 |
| **誰が作るか** | ① 営業機能（顧客からの連絡を受けて記録する） |
| **誰が使うか** | ① 営業（対応可否の判断）、③ 生産技術（見積依頼を受ける）、社長（新規顧客の与信判断） |
| **【Varies】どこに保管されるか** | 引合い台帳、案件管理の記録。媒体は企業により異なる |
| **次に何に変わるか** | → ② 仕様情報 ／ ④ 見積情報 ／（失注時）失注理由の記録 |
| **頻度** | **問い合わせ時**（モデル企業では【Example】月200〜300件） |

> **なぜこの情報を記録するのか**
> 【Typical】理由は3つあります。
> 1. **対応の抜けを防ぐため**：電話で聞いただけだと、忙しいときに忘れます。顧客は返事を待っています。
> 2. **失注の理由を後から振り返るため**：価格で負けたのか、納期で負けたのか、技術的にできなかったのかが分かると、
>    次に同種の引合いが来たときの判断材料になります。
> 3. **見積工数をかけるかどうかを判断するため**：【Typical】見積1件には工程設計と原価計算の時間がかかります。
>    すべてに同じ手間をかけることはできないため、入口で仕分けをします。

> **この情報が途切れると**
> 【Inference】顧客からの問い合わせに返事をしないまま時間が経ち、失注します。
> また、「言った・言わない」が生じます。

---

### ② 仕様情報

| 項目 | 内容 |
|---|---|
| **何の情報か** | 「何を、どう作るのか」を確定させた内容。材質、寸法、公差、表面処理、溶接の要求、外観の要求、検査項目、成績書の要否、梱包・荷姿、納入場所と回数、支給材の有無 |
| **誰が作るか** | ① 営業機能（顧客に確認して確定させる）＋③ 生産技術機能（技術的な確認） |
| **誰が使うか** | ③ 生産技術（工程設計）、④ 調達（材料手配）、⑤ 製造（作業内容）、⑥ 品質保証（検査基準）、⑦ 出荷・物流（梱包・納入） |
| **【Varies】どこに保管されるか** | 仕様書、仕様確認メモ、見積依頼書、案件ファイル。媒体は企業により異なる |
| **次に何に変わるか** | → ④ 見積情報 → ⑧ 製造指示情報 → ⑩ 検査情報 |
| **頻度** | **案件発生時** |

> **なぜこの情報が特に重要なのか**
> 【Typical】図面だけでは決まらないことが多くあります（`04_end-to-end-process.md` ② 参照）。
> 【Example】「板厚3mmのSUS304」と書かれていても、表面の仕上げ（ヘアライン・鏡面・素地）、
> 溶接跡を残してよいか、角のバリをどこまで取るかは図面に書かれていないことがあります。
> **仕様情報は「図面に書かれていないことを埋める情報」**であり、
> ここが曖昧なまま製造すると、納品後に「これでは受け取れない」となって作り直しになります。

> **この情報が途切れると**
> 【Typical】営業担当が顧客と口頭で決めた内容が製造現場に伝わらず、図面どおりに作ったのに不合格になります。
> 逆に、現場が気を利かせて仕様外の処理をすると、費用が増えるだけでなく顧客の想定と違うものになります。

---

### ③ 図面情報

| 項目 | 内容 |
|---|---|
| **何の情報か** | 製品の形状・寸法・公差・材質・表面処理を図で示したもの。**図面番号**と**改訂（リビジョン）番号**を持つ |
| **誰が作るか** | 【Typical】**顧客**（受託加工型の場合）／自社の設計機能（自社製品型・機械製造の場合） |
| **誰が使うか** | ③ 生産技術（工程設計、NCプログラム作成）、④ 調達（材料の指定）、⑤ 製造（加工）、⑥ 品質保証（検査基準）、外注先 |
| **【Varies】どこに保管されるか** | 図面ファイル、図面管理の仕組み。紙・PDF・CADデータの併存が一般的【Typical】 |
| **次に何に変わるか** | → 工程表、NCプログラム、検査基準、外注先への支給図面 |
| **頻度** | **案件発生時**／**仕様変更時** |

> **用語：図面の改訂（リビジョン／Rev.）**
> → 図面が変更されたとき、番号やアルファベットで版を管理すること。
>   「AB-2041 Rev.B」なら、AB-2041という図面の2回目の版（A→B）という意味です。
> → 実務例：顧客の設計変更により穴の位置が2mm移動し、Rev.B から Rev.C になる。
> → **なぜ版の管理が重要なのか**：
>   【Typical】古い版の図面で作ってしまうと、全数が不良になります。
>   工場の中に Rev.B と Rev.C の図面が混在していると、どちらで作ればよいか分かりません。
>   このため、**古い版の図面を工場から確実に回収・破棄する**という運用が行われます。
>   【Fact】ISO 9001 では、文書化した情報の管理として、版の管理と、
>   廃止された文書化した情報の誤使用防止が要求されています（箇条7.5.3）。

> **この情報が途切れると**
> 【Typical】古い版で製造してしまい、全数が作り直しになります。
> また、外注先に旧版の図面を渡してしまえば、外注先で作られたものも不良になります。

---

### ④ 見積情報（原価情報を含む）

| 項目 | 内容 |
|---|---|
| **何の情報か** | 「いくらで、いつまでに作れるか」の算定結果。**2層**ある：（a）**社外に出す見積情報**＝見積金額・納期・有効期限・条件、（b）**社内に残る原価情報**＝材料費・加工時間・工程・チャージレート・外注費・段取り費の内訳 |
| **誰が作るか** | ③ 生産技術機能（工程設計と加工時間）＋④ 調達機能（材料単価・外注単価）＋① 営業機能（取りまとめと最終金額） |
| **誰が使うか** | 社長（承認）、① 営業（顧客への提示・価格交渉）、② 生産管理（納期回答の根拠）、⑨ 経理（後日の原価との比較） |
| **【Varies】どこに保管されるか** | 見積書控え、見積台帳、原価計算の記録 |
| **次に何に変わるか** | → ⑤ 受注情報（受注した場合）／失注記録（失注した場合）／リピート時の単価の基準 |
| **頻度** | **案件発生時**（モデル企業では【Example】年間約3,000件） |

> **【重要】原価情報は「社内に残す情報」**
> 【Typical】顧客に出す見積書には合計金額しか書きませんが、社内には内訳が残ります。
> この内訳がないと、後から次のことが分からなくなります。
> - なぜこの金額になったのか（顧客に説明できない）
> - 実績と比べて、見積が甘かったのかきつかったのか
> - 材料が値上がりしたとき、いくら単価を上げる必要があるのか
>
> 【Example】`04_end-to-end-process.md` 4-4 では、前回の実績工数と材料単価の変動を根拠に、
> 780円 → 808円という再計算を行っています。**過去の原価情報が残っているから、この計算ができます。**

> **この情報が途切れると**
> 【Inference】単価の根拠が説明できなくなり、価格交渉ができなくなります。
> 【Fact】なお取適法では、価格協議の求めに応じない、必要な説明を行わないなど一方的に代金を決めることが
> 禁止行為として定められています（取適法第5条第2項第4号。出典：e-Gov法令検索）。

### ⑤ 受注情報

| 項目 | 内容 |
|---|---|
| **何の情報か** | 確定した注文の内容。受注番号、顧客名、顧客の注文番号、品番、品名、図面番号と版、数量、単価、金額、納期、納入場所、支払条件 |
| **誰が作るか** | ① 営業機能（注文書を受領し、見積と照合）→ ② 受注・生産管理機能（受注として登録） |
| **誰が使うか** | ② 生産管理（生産計画の元）、④ 調達（材料所要量の元）、⑤ 製造（何を作るか）、⑥ 品質保証（検査対象）、⑦ 出荷・物流（出荷先・時期）、⑨ 経理（売上計上・請求の元） |
| **【Varies】どこに保管されるか** | 受注データ、受注台帳、注文書の原本 |
| **次に何に変わるか** | → ⑥ 計画情報 ／ **受注残**（まだ納めていない注文の残高） |
| **頻度** | **受注時**（モデル企業では【Example】年間約1,800件） |

> **【重要】受注情報は「会社の全機能が参照する情報」**
> 【Inference】上の「誰が使うか」を見ると、**ほぼ全機能が受注情報を使っています**。
> つまり、受注情報が間違って登録されると、間違いが会社全体に伝播します。
> 【Example】数量を1,000個のところ100個と登録すれば、材料が足りず、作る数も足りず、請求額も間違います。
> このため `04_end-to-end-process.md` ⑤ では、**注文書と見積の照合**が必須の作業として位置づけられています。

> **用語：受注残（じゅちゅうざん）**
> → 受注したが、まだ納品していない注文の残高（金額または数量）。
> → 実務例：4月に8,000万円受注し、4月中に6,000万円分を納品したら、受注残は2,000万円。
> → **なぜこの数字を見るのか**：受注残は「これから確実に売上になる仕事の量」を示します。
>    受注残が減っていれば、数か月後の売上が減ることが予測できます（`14_kpi.md` 参照）。

---

### ⑥ 計画情報（生産計画・材料所要量）

| 項目 | 内容 |
|---|---|
| **何の情報か** | 「いつ、どの設備で、何を、どれだけ作るか」。**2つの内容**を持つ：（a）**日程計画**＝工程ごとの着手日・完了日、（b）**材料所要量**＝何の材料が、いつまでに、何個必要か |
| **誰が作るか** | ② 受注・生産管理機能（相談：⑤ 製造機能の工場長・職長） |
| **誰が使うか** | ⑤ 製造（何をいつ作るか）、④ 調達（いつまでに材料を揃えるか）、① 営業（納期回答）、⑦ 出荷・物流（いつ出荷するか）、⑧ 設備保全（設備を止められる日） |
| **【Varies】どこに保管されるか** | 生産計画表、日程表、工程管理の記録 |
| **次に何に変わるか** | → ⑦ 発注情報 ／ ⑧ 製造指示情報 ／ ⑪ 出荷情報 |
| **頻度** | **週次**（計画の立て直し）＋**日次**（調整）＋**受注時**（新規受注の組み込み） |

> **計画情報を作るために必要な「入力情報」**
> 【Typical】生産計画は受注情報だけでは作れません。次の情報が揃って初めて作れます。
>
> | 必要な情報 | 誰が持っているか |
> |---|---|
> | 受注情報（何を、何個、いつまでに） | ① 営業 → ② 生産管理 |
> | **負荷情報**（各設備にすでに入っている仕事の量） | ② 生産管理 |
> | **能力情報**（各設備・作業者が働ける時間） | ⑤ 製造（工場長）＋⑩ 人事・総務（勤怠・出勤予定） |
> | **在庫情報**（材料が今いくつあるか） | ④ 調達＋⑦ 出荷・物流 |
> | **入荷予定情報**（材料がいつ届くか） | ④ 調達 |
> | **外注の空き情報**（外注先がいつ受けられるか） | ④ 調達＋外注先 |
> | **設備の状態情報**（故障・点検予定） | ⑧ 設備保全 |
> | **標準時間情報**（1個作るのに何分かかるか） | ③ 生産技術 |
>
> 【Inference】**生産管理機能が「すべての機能とつながるハブ」である理由が、ここに現れています**
> （`03_company-structure.md` 3-5）。計画を立てるには、会社中の情報を集める必要があるからです。

> **この情報が途切れると**
> 【Typical】材料の発注が遅れて納期に間に合わない、設備が重複して割り当てられる、
> 出荷の準備ができていない、といったことが起きます。

---

### ⑦ 発注情報

| 項目 | 内容 |
|---|---|
| **何の情報か** | 仕入先・外注先への注文内容。発注番号、品名、材質、寸法、数量、単価、金額、要求納期、納入場所、支払条件。外注の場合は加工内容と支給する品の情報 |
| **誰が作るか** | ④ 調達機能（依頼元：② 生産管理機能） |
| **誰が使うか** | 仕入先・外注先、⑦ 出荷・物流（入荷予定の把握）、② 生産管理（入荷予定日）、⑨ 経理（請求書照合・支払の根拠） |
| **【Varies】どこに保管されるか** | 注文書控え、発注台帳、**発注残**データ |
| **次に何に変わるか** | → 入荷実績 → 仕入計上 → 買掛金 → 支払 |
| **頻度** | **発注時**＋**週次**（定期発注品）＋**月次**（消耗品） |

> **【Fact】発注情報の明示は法令上の義務になり得ます**
> 取適法では、委託事業者の義務として「発注内容等を明示する義務」が定められており、
> 発注にあたり、給付の内容・代金の額・支払期日・支払方法等を書面または電子メール等の電磁的方法で
> 明示しなければならないとされています。
> また、取引完了後に給付内容・代金の額など取引の記録を作成し、**2年間保存**する義務があります
> （出典：取適法／e-Gov法令検索、公正取引委員会）。
> 【Typical】中小製造業は「受注側」であることが多いですが、**自社が外注先に発注するときは「発注側」になります**。
> このため、自社が取適法上の委託事業者にあたる場合は、上記の義務を負う可能性があります。

---

### ⑧ 製造指示情報

| 項目 | 内容 |
|---|---|
| **何の情報か** | 現場に「これを作りなさい」と伝える情報。受注番号、品番、品名、図面番号と版、材質、数量、工程の順序、各工程の着手予定日、使用する設備、使用する治具・NCプログラム、注意事項 |
| **誰が作るか** | ② 受注・生産管理機能（内容は ③ 生産技術機能が作った工程情報に基づく） |
| **誰が使うか** | ⑤ 製造機能（工場長、各職長、作業者）、⑥ 品質保証（検査のタイミング）、⑦ 出荷・物流（完成予定） |
| **【Varies】どこに保管されるか** | 製造指示書（作業指示書）、現品票、工程表。媒体は企業により異なる |
| **次に何に変わるか** | → ⑨ 実績情報（作業日報）／現品票への記入 |
| **頻度** | **日次**／**週次**／**受注時** |

> **製造指示情報に必ず含まれるもの**【Typical】
> | 要素 | なぜ必要か |
> |---|---|
> | **何を**（品番・品名・図面番号と版） | 作るものを特定するため。版が違えば別物になる |
> | **何個** | 不良見込みを含めて何個着手するかを決めるため |
> | **いつまでに** | 後工程・出荷に間に合わせるため |
> | **どの順番で**（工程順） | 順番を間違えると作れない（例：めっき後に穴あけをすると、めっきがはがれる） |
> | **どの設備で** | 設備によって精度・時間が違うため |
> | **何を使って**（治具・NCプログラム・金型） | 準備が要るため |
> | **注意事項** | 過去に不具合があった点、顧客の特別要求など |

> **この情報が途切れると**
> 【Typical】作業者は何を作ればよいか分からず、工場が止まります。
> 版の情報が抜ければ、旧版で作られます。順番の情報が抜ければ、後戻りできない失敗が起きます。

---

### ⑨ 実績情報

| 項目 | 内容 |
|---|---|
| **何の情報か** | 「実際にどうだったか」。**4種類**ある：（a）**作業実績**＝誰が、いつ、どの工程を、何分かけたか、（b）**数量実績**＝何個良品ができ、何個不良だったか、（c）**進捗実績**＝どの工程まで終わったか、（d）**材料消費実績**＝何をどれだけ使ったか |
| **誰が作るか** | ⑤ 製造機能（作業者が作業日報に記入、現品票に記入） |
| **誰が使うか** | ② 生産管理（進捗の把握、納期の判断）、⑨ 経理（原価計算）、③ 生産技術（標準時間の見直し）、① 営業（次回見積の根拠）、⑥ 品質保証（不良の傾向） |
| **【Varies】どこに保管されるか** | 作業日報、現品票、生産実績の記録 |
| **次に何に変わるか** | → **原価実績**（⑨ 経理が集計）／**進捗情報**（② 生産管理が使う）／**標準時間の見直し**（③ 生産技術）／**次回の見積情報** |
| **頻度** | **日次**（作業日報）／**常時**（現品票への記入） |

> **【重要】実績情報は「見積 → 実績 → 次の見積」というループの要**
> 【Inference】製造業では、見積の段階ではすべてが予測です。
> 「切断1.2分/個」というのは、過去の実績から推定した数字です。
> 実際に作ってみて4.2時間かかったという**実績情報**が記録されて初めて、
> 「見積どおりだったのか、甘かったのか」が分かります。
>
> ```
>   見積（予測） ──▶ 製造 ──▶ 実績情報 ──▶ 見積と実績の比較 ──▶ 次回の見積が正確になる
>       ▲                                                              │
>       └──────────────────────────────────────────────────────────────┘
> ```
>
> 【Typical】このループが回らないと、何年経っても見積の精度が上がらず、
> 「安く受けてしまった案件」に気づくのが遅れます。
> **作業日報は、単なる記録ではなく、原価と見積の基礎データ**です。

> **この情報が途切れると**
> 【Typical】3つのことが起きます。
> 1. 生産管理が進捗を把握できず、納期遅れに事前に気づけない
> 2. 原価計算ができず、その案件が儲かったのか分からない
> 3. 次回の見積の根拠がなくなる

### ⑩ 検査情報

| 項目 | 内容 |
|---|---|
| **何の情報か** | 「図面どおりにできているか」を確認した結果。**3種類**ある：（a）**受入検査の結果**＝材料が仕様どおりか、（b）**工程内検査の結果**＝加工途中の寸法・外観、（c）**最終検査の結果**＝出荷前の全項目。測定値、判定（合格／不合格）、検査日、検査者、使用した測定器 |
| **誰が作るか** | ⑥ 品質保証機能（検査員）＋⑤ 製造機能（作業者の自主検査） |
| **誰が使うか** | **顧客**（検査成績書として提出）、⑦ 出荷・物流（出荷可否）、⑤ 製造（手直しの指示）、② 生産管理（納期影響）、③ 生産技術（工程の見直し） |
| **【Varies】どこに保管されるか** | 検査記録、検査成績書の控え、不適合品報告書 |
| **次に何に変わるか** | → **検査成績書**（顧客提出）／**不適合情報**（不合格の場合）／**是正処置情報** |
| **頻度** | **納品時**（最終検査）／**常時**（工程内検査）／**納品時**（受入検査） |

> **なぜ検査情報を記録として残すのか**
> 【Typical】3つの理由があります。
> 1. **顧客に証明するため**：検査成績書は「当社で測定した結果、図面どおりでした」という証明書です。
>    顧客はこれを信頼して受け入れます。
> 2. **後から追跡するため**：納品後に不具合が判明したとき、「出荷時にはどうだったか」を確認できます。
>    【Fact】ISO 9001 では、監視・測定の結果の証拠として、文書化した情報を保持することが要求されています（箇条8.6、9.1.1）。
> 3. **傾向を知るため**：同じ寸法が繰り返し公差の端に寄っていれば、工程に何かが起きていることが分かります。

> **用語：不適合（ふてきごう）／不適合品報告書**
> → 不適合＝要求されている事項を満たしていない状態。
>   不適合品報告書＝不適合が発生したときに、何が、いつ、どこで、どれだけ発生し、どう処置したかを記録する帳票。
> → 実務例：曲げ角度が公差外の3個が発生。不適合品報告書に、発生工程・数量・原因の推定・処置（廃棄）を記録する。
> → **なぜ記録するのか**：同じ不適合が繰り返されていないかを見るため、
>    また不良による損失額を把握するためです。

### ⑪ 出荷情報

| 項目 | 内容 |
|---|---|
| **何の情報か** | 「いつ、どこへ、何を、いくつ届けるか」。納入先（会社名・工場名・受入口）、納入日時、品番、数量、荷姿、運送手段、納品書番号 |
| **誰が作るか** | ② 受注・生産管理機能（出荷指示）→ ⑦ 出荷・物流機能（納品書・送り状の作成） |
| **誰が使うか** | ⑦ 出荷・物流（梱包・手配）、運送会社、**顧客の受入担当**、⑨ 経理（売上計上の根拠）、① 営業（納入完了の確認） |
| **【Varies】どこに保管されるか** | 出荷指示、納品書控え（**受領印付き**）、送り状控え、出荷台帳 |
| **次に何に変わるか** | → ⑫ 検収情報 → ⑬ 請求情報 |
| **頻度** | **納品時**（モデル企業では【Example】1日10〜20件） |

> **なぜ受領印のある納品書控えが重要なのか**
> 【Typical】受領印のある納品書控えは、「たしかに納めた」ことを示す証拠書類です。
> 後日「届いていない」と言われた場合の唯一の裏付けになり、請求の根拠にもなります。
> 【Varies】電子化が進んだ企業では、システム上の受領データで代替される場合もあります。

---

### ⑫ 検収情報

| 項目 | 内容 |
|---|---|
| **何の情報か** | 顧客が「注文どおりのものを受け取った」と認めた記録。検収日、検収数量、検収金額、対応する注文番号 |
| **誰が作るか** | **顧客**（自社ではない） |
| **誰が使うか** | ⑨ 経理・財務機能（売上計上、請求額の確定）、② 生産管理（案件の完了確認）、① 営業 |
| **【Varies】どこに保管されるか** | 検収データ、検収明細、支払通知書 |
| **次に何に変わるか** | → **売上情報** → ⑬ 請求情報 → 売掛金 |
| **頻度** | **納品時**／【Varies】**月次**（まとめて検収する顧客もある） |

> **【重要】検収情報は「自社が作れない情報」**
> 【Inference】ここまでの情報は自社が作ってきましたが、**検収情報だけは顧客が作ります**。
> したがって、顧客から送られてこなければ自社は知りようがありません。
> 【Typical】このため、自社の出荷データと顧客の検収データを**突き合わせる（照合する）**作業が発生します。
> 【Example】自社は「5月に3,850,000円納品した」と認識していても、
> 顧客側は「検収は3,700,000円分、残り150,000円は6月検収」と認識していることがあります。
> この差異を放置すると、請求額と入金額が合わなくなります。
>
> 【Varies】顧客によっては「**支払通知書**」を先に送ってきて、その金額どおりに請求させる方式もあります
> （支払通知書方式、買掛計上方式）。この場合、検収情報は支払通知書の形で届きます。

---

### ⑬ 請求情報

| 項目 | 内容 |
|---|---|
| **何の情報か** | 顧客に「いくら払ってください」と伝える内容。請求番号、請求先、締め日、請求期間、明細（納品日・品番・数量・単価・金額）、小計、消費税、合計、支払期日、振込先 |
| **誰が作るか** | ⑨ 経理・財務機能 |
| **誰が使うか** | **顧客の経理・支払担当**、⑨ 経理（売掛金の管理）、社長（資金繰り） |
| **【Varies】どこに保管されるか** | 請求書控え、売掛金台帳、請求データ |
| **次に何に変わるか** | → **売掛金** → ⑭ 入金情報 → 消込 |
| **頻度** | **月次**（締め日の翌日〜数営業日以内）／**請求時** |

> **【Fact】請求書には法令上の記載要件があります**
> 消費税の仕入税額控除の適用を受けるための「適格請求書（インボイス）」制度が
> 2023年10月1日から開始されています。適格請求書には、
> 適格請求書発行事業者の氏名または名称および**登録番号**、取引年月日、取引内容（軽減税率対象品目である旨）、
> 税率ごとに区分して合計した対価の額および適用税率、税率ごとに区分した消費税額等、書類の交付を受ける事業者の氏名または名称
> の記載が必要です（出典：インボイス制度／国税庁）。
> 【Typical】このため、請求情報には「登録番号」という項目が加わっています。

### ⑭ 入金情報

| 項目 | 内容 |
|---|---|
| **何の情報か** | 実際にお金が振り込まれた記録。入金日、入金額、振込元、対応する請求番号 |
| **誰が作るか** | ⑨ 経理・財務機能（銀行口座の記録を確認して記録する） |
| **誰が使うか** | ⑨ 経理（消込、売掛金残高の更新）、社長（資金繰りの把握）、① 営業（未入金の確認） |
| **【Varies】どこに保管されるか** | 入金記録、売掛金台帳、消込記録、未入金リスト |
| **次に何に変わるか** | → **売掛金残高の更新** → **資金繰り表** → 社長への報告 |
| **頻度** | **入金時**（支払日）／**月次**（残高確認） |

> **なぜ請求額と入金額が合わないことがあるのか**【Typical】
> | 差異の原因 | 内容 |
> |---|---|
> | 振込手数料 | 顧客が手数料を差し引いて振り込む場合がある |
> | 検収のずれ | 自社の請求月と顧客の検収月が違う |
> | 値引き・調整 | 事前に合意した値引きが反映されている |
> | **相殺** | 有償支給材の代金が差し引かれている（8-5、`02_industry-structure.md` 11-3参照） |
> | 単価の相違 | 単価改定の適用時期の認識が違う |
>
> 【Typical】経理担当は、差額があれば原因を調べて処理します。これが「消込」の実務です。

## 9-3. 情報が途切れると何が起きるか

### なぜ情報伝達が製造業で決定的に重要なのか

【Inference】製造業では、**1つの仕事が10前後の機能を順番に通過します**（`06_people.md` 6-7）。
つまり、情報は**10回以上、人から人へ渡されます**。
1回の受け渡しで情報が欠けると、その先の全工程が誤った前提で動きます。

### 情報が途切れた場合に起きることの一覧【Typical】

| 途切れる箇所 | 起きること | 損失の大きさ |
|---|---|---|
| 顧客 → 営業（仕様情報） | 図面に書かれていない要求が伝わらず、納品後に「これでは受け取れない」となる | 全工程の費用＋作り直し |
| 営業 → 生産技術（数量情報） | 数量を前提に計算した単価が、実際の数量と合わず赤字になる | 差額×数量 |
| 営業 → 生産管理（納期情報） | 納期を過ぎてから気づく | 納期遅れ、顧客の生産停止 |
| 生産管理 → 調達（材料所要量） | 材料が間に合わず、製造に着手できない | 納期遅れ |
| 生産管理 → 製造（図面の版） | 旧版で作ってしまう | 全数作り直し |
| 製造 → 生産管理（不良の発生） | 納品数が足りないことに出荷直前に気づく | 納期遅れ、緊急対応費用 |
| 製造 → 経理（実績工数） | 原価が計算できず、儲かったか分からない。次の見積の根拠がない | 継続的な見積精度の低下 |
| 品質保証 → 出荷（検査結果） | 不合格品が出荷される | 顧客クレーム、信用の低下 |
| 出荷 → 経理（出荷実績） | 請求漏れが発生する | 請求額そのもの |
| 顧客 → 経理（検収情報） | 請求額と入金額が合わず、原因が分からない | 回収遅延 |
| 外注先 → 調達（進捗） | 外注から戻らないことに、納期直前に気づく | 納期遅れ |

> **【Typical】情報が途切れる典型的な状況**
> 情報は「悪意で隠される」より、次のような形で途切れることのほうが多く見られます。
> - **口頭で伝えたが、相手が忘れた／聞き間違えた**
> - **伝えるべき相手が分からなかった**（誰に言えばよいか決まっていない）
> - **担当者が休んでいて、代わりの人が知らなかった**（兼務による単点依存。`06_people.md` 6-6参照）
> - **忙しくて後回しにした**
> - **「言わなくても分かるだろう」と思った**
> - **異常を報告しづらい雰囲気があった**

## 9-4. 情報の媒体：口頭・紙・データ【Varies】

### 3つの媒体の性質

> **⚠️ このファイルでは、どの媒体を使うべきかという評価・推奨は行いません。**
> **中小製造業では複数の媒体が併用されるのが実態です【Typical】。**
> ここでは「それぞれの媒体がどういう性質を持つか」を、業務理解のために整理します。

| 媒体 | 【Typical】強み | 【Typical】制約 | 【Typical】よく使われる場面 |
|---|---|---|---|
| **口頭**（対面・電話） | 速い。前後の事情を含めて伝えられる。その場で質問して確認できる | 記録が残らない。同時に複数人へ伝えるのが難しい。時間が経つと双方の記憶が食い違う | 現場での当日の調整、緊急の連絡、異常の第一報、顧客との仕様の詰め |
| **紙**（帳票・図面・日報） | 工場内で扱いやすい（油・粉じん・手袋の環境でも使える）。その場で書き込める。現物に貼り付けられる | 1枚しかないため同時に複数人が見られない。集計に手間がかかる。保管場所が要る。遠隔では見られない | 現品票、作業日報、図面、検査記録、納品書、掲示 |
| **データ**（システム・表計算・メール） | 集計・検索ができる。複数人が同時に見られる。遠隔でも見られる。履歴が残る | 入力する手間がかかる。入力されるまで反映されない。工場の現場では端末の設置環境に制約がある | 受注登録、生産計画、在庫数、請求・入金、原価集計、顧客とのやり取り |

### 【Typical】1つの情報が複数の媒体を渡り歩く

【Example】1件の受注情報は、次のように媒体を変えながら会社の中を移動します。

```
 顧客の注文書（紙／PDF／EDIデータ）
      ↓ 営業担当が内容を確認
 受注データ（システム／表計算に入力）
      ↓ 生産管理担当が計画を立てる
 生産計画（システム／表計算／ホワイトボード）
      ↓ 現場へ指示
 製造指示書・現品票（紙）
      ↓ 現物に貼り付いて工程を移動
 作業日報（紙）
      ↓ 事務所で集計
 実績データ（システム／表計算）
      ↓ 締め日に集計
 請求書（紙／PDF／電子）
```

> **【Inference】なぜ媒体が変わるのか**
> 情報を使う場所の環境が違うためです。
> 事務所では画面で扱うのが扱いやすく、工場では手袋をしたまま扱える紙が扱いやすい、という事情があります。
> 【Varies】どこまでをどの媒体にするかは、企業の規模・設備・取引先の要求により大きく異なります。
> 本資料では特定の媒体を前提にせず、**「どの媒体であっても、その情報が必要な人に届いているか」**という観点で
> 情報の流れを理解してください。

### 【Typical】顧客とのやり取りで使われる媒体

| やり取りの内容 | 【Varies】よく使われる媒体 |
|---|---|
| 引合い・仕様の相談 | 電話、メール、対面 |
| 図面の授受 | メール添付（PDF・CADデータ）、紙、顧客の専用システム |
| 見積書の提出 | メール添付、紙（郵送・持参）、顧客の購買システム |
| 注文書の受領 | メール、紙（FAX・郵送）、**EDI**（後述）、顧客の購買システム |
| 納入指示（繰返生産） | EDI、かんばん、メール |
| 納品書 | 紙（現品に同梱）、電子 |
| 検収・支払通知 | 顧客のシステム、紙、メール |
| 請求書 | 紙（郵送）、電子（PDF・電子請求システム） |

> **用語：EDI（Electronic Data Interchange／電子データ交換）**
> → 企業と企業の間で、注文・出荷・請求などの情報を、決められた形式のデータで直接やり取りする仕組み。
> → 実務例：顧客の生産管理システムから発注データが自動的に送られ、自社の受注データとして取り込まれる。
>    注文書という紙を介さずに、注文の内容が伝わる。
> → **なぜ使われるのか**：【Typical】取引件数が多く、納入指示が頻繁に変わる取引（自動車部品の繰返生産など）では、
>    毎回紙でやり取りすると間に合わないためです。
> → 【Varies】EDIを使うかどうかは、顧客の要求と取引量によって決まります。
>    顧客ごとに異なる形式を求められることもあります。詳細は `11_systems.md` を参照。

## 9-5. 情報の保存期間【Fact】

製造業では、いくつかの情報について法令上の保存義務があります。

| 情報・書類 | 保存期間 | 根拠 |
|---|---|---|
| 取適法に基づく取引記録（給付内容・代金の額等） | **2年間** | 【Fact】取適法（委託事業者の義務②「書類等を作成・保存する義務」）。出典：取適法／e-Gov法令検索、公正取引委員会 |
| 帳簿および請求書等（消費税の仕入税額控除を受けるためのもの） | 【Fact】**7年間**（帳簿の閉鎖・請求書等の受領をした課税期間の末日の翌日から2か月を経過した日から7年間。ただし6年目・7年目はいずれか一方の保存でよい） | 消費税法（出典：国税庁 タックスアンサー No.6496「仕入税額控除をするための帳簿及び請求書等の保存」） |
| 労働者名簿、賃金台帳、雇入・解雇・災害補償・賃金その他労働関係の重要書類 | 【Fact】**5年間**（経過措置により**当分の間3年間**） | 労働基準法第109条（出典：厚生労働省） |
| 産業廃棄物管理票（マニフェスト）の写し | 【Fact】**5年間** | 廃棄物の処理及び清掃に関する法律第12条の3および関係省令（出典：e-Gov法令検索、各自治体の案内） |
| 品質記録（検査記録等） | 【Varies】法令ではなく**顧客との契約・ISO 9001の要求により決まる** | 【Fact】ISO 9001 では、文書化した情報の保持が要求されるが、保存期間は組織が決定する（箇条7.5） |

> 【Typical】顧客から「製品の納入後○年間、検査記録を保存すること」と求められることがあります。
> 【Varies】期間は業種・顧客により大きく異なり、自動車・航空・医療機器などでは長期の保存が求められる場合があります。
> 詳細は `15_rules-customs.md` を参照。

## 9-6. 業種によって情報の流れはどう変わるか【Varies】

| 業種 | 【Typical】情報の流れの特徴 |
|---|---|
| **食品製造** | 見込生産のため、上流に**需要予測情報・販売計画情報**が加わる。**原材料のロット情報**と製品の製造ロットを結び付ける記録（トレーサビリティ）が重要。【Fact】HACCPに沿った衛生管理では、危害要因の分析と重要管理点の**監視記録**が求められる（出典：厚生労働省）。**賞味期限・消費期限情報**が製品表示と在庫管理の両方に関わる |
| **金属加工** | 本ファイルの基本形。**図面情報の版管理**と**ミルシート（材料証明書）**によるトレーサビリティが要点 |
| **機械製造** | 受注後に**設計情報**が生まれる。部品点数が多いため**部品表（BOM）情報**が中核になる。据付・試運転の段階で**据付記録・立会い記録**という情報が加わり、これが検収の根拠になる |
| **電気機器** | **部品表（BOM）情報**と**部品の調達リードタイム情報**が計画の中心。【Fact】電気用品安全法の対象となる場合、届出・適合性検査の証明書の保存が義務（出典：電気用品安全法／e-Gov法令検索）。基板実装では部品のリール単位のロット情報が管理される |
| **化学・プラスチック** | **配合情報（レシピ）**が製造指示情報の中核。バッチごとの**製造記録**（温度・時間・投入量）が品質の証拠になる。【Fact】労働安全衛生法に基づき、リスクアセスメント対象物については**ラベル表示とSDS（安全データシート）の交付**が義務（出典：厚生労働省）。SDSは仕入先から受け取り、顧客へ渡す情報でもある |
| **印刷** | **校正情報**（顧客が内容を確認し修正を指示するやり取り）が業務の中心にあり、往復の記録が残される。**校了（顧客の最終承認）**がどの時点で成立したかが、刷り直しの責任の所在を決める |

## 9-7. このファイルのまとめ

1. 製造業を流れるのは「情報」という抽象物ではなく、**問い合わせ情報・仕様情報・図面情報・見積情報・受注情報・計画情報・発注情報・製造指示情報・実績情報・検査情報・出荷情報・検収情報・請求情報・入金情報**という名前を持った具体的な情報である。
2. 情報は**前の情報を材料にして次が作られる**。前が間違えば後ろはすべて間違う。
3. 1件の注文は、会社の中で**12回ほど姿を変えて**通り抜ける。
4. **生産計画情報**を作るには会社中の情報が必要であり、これが生産管理機能が中枢である理由。
5. **実績情報**は「見積 → 製造 → 実績 → 次の見積」というループの要であり、作業日報は原価と見積の基礎データ。
6. **検収情報だけは顧客が作る**ため、自社のデータと突き合わせる作業が必要になる。
7. 情報が途切れると、その先の全工程が誤った前提で動く。途切れ方は悪意より**口頭伝達の忘却・担当者不在・後回し**が多い。
8. 媒体（口頭・紙・データ）はそれぞれ性質が違い、**中小製造業では併用されるのが実態**。どの媒体が良いかではなく、必要な人に届いているかで理解する。

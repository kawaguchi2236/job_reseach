# 08_money.md — カネの流れ（情報通信業）

**対象**：日本国内の中小情報通信業（受託開発を主業とするソフトウェア会社）
**読み手**：情報通信業をまったく知らない人（会計の知識は前提にしません）
**前提**：`03_company-structure.md` で設定した**Xシステム株式会社**（従業員48名・技術者40名・年商4億5,000万円）【Example】
**最終更新**：2026-09-20

> このファイルは、`common/methodology.md` §6 の「4つの流れ」のうち**カネ**を扱います。
> **見積 → 契約 → 売上 → 人件費・外注費 → 請求 → 売掛金 → 入金 → 買掛金 → 支払 → 利益**の順に追い、
> 各段階の**時間差**を必ず示します。

## 8-0. この章の軸——請負と準委任では、お金の動き方が違う

### 最初に、この1点を押さえてください

> **請負は、検収がないと請求できません。**
> **準委任は、作業報告書への顧客の承認が請求の根拠になります。**

この2つの違いが、この業界のカネの流れのほぼすべてを説明します。

```
  【請負】
    契約 ──▶ 作業（数か月） ──▶ 納品 ──▶ ★検収 ──▶ 請求 ──▶ 入金
      │           │                        │
      │           └─ この間、人件費だけが出ていく
      │                                    │
      └─ 金額はここで固定される             └─ ここが通らないと1円も請求できない

  【準委任（SES・保守）】
    契約 ──▶ 1か月作業 ──▶ ★作業報告書に顧客が承認 ──▶ 請求 ──▶ 入金
                              │
                              └─ これを毎月繰り返す
```

### なぜこの違いが生まれるのか（条文の確認）

【Fact】**請負**
> **民法 第六百三十二条（請負）**
> 請負は、当事者の一方が**ある仕事を完成することを約し**、相手方がその**仕事の結果に対して**その報酬を支払うことを約することによって、その効力を生ずる。
> （出典：民法／e-Gov法令検索）

**条文の文言でいえば**、報酬は「**仕事の結果に対して**」支払われます。

【Fact】**準委任の報酬**
> **民法 第六百四十八条（受任者の報酬）**
> 受任者は、特約がなければ、委任者に対して報酬を請求することができない。
> ２　受任者は、報酬を受けるべき場合には、委任事務を履行した後でなければ、これを請求することができない。
> ただし、**期間によって報酬を定めたときは**、第六百二十四条第二項の規定を準用する。
> ３　受任者は、次に掲げる場合には、**既にした履行の割合に応じて**報酬を請求することができる。
> 　一　委任者の責めに帰することができない事由によって委任事務の履行をすることができなくなったとき。
> 　二　委任が履行の中途で終了したとき。
> （出典：民法／e-Gov法令検索）

**条文の文言でいえば**、第648条第2項ただし書は「**期間によって報酬を定めたとき**」の扱いを定めています。

【Fact】**準委任の報告義務**
> **民法 第六百四十五条（受任者による報告）**
> 受任者は、委任者の請求があるときは、いつでも委任事務の処理の状況を報告し、
> 委任が終了した後は、遅滞なくその経過及び結果を報告しなければならない。
> （出典：民法／e-Gov法令検索）

**実務上の意味（条文の説明ではなく、実務としてどうなるか）**
【Typical】月額いくらで契約するSESや保守は、第648条第2項ただし書の「期間によって報酬を定めたとき」にあたる形です。
そして、毎月の**作業報告書（稼働報告書）**は、第645条の報告義務を実務の形にしたものといえます。
04の4-3②が述べているとおり、**この書類に顧客の承認がないと請求できない**のが実務の運用です【Typical】。

> **★注意：これらは別々の条文です。**
> 民法第632条（請負）と第648条（委任の報酬）は、まったく別の条文です。
> **1つにまとめて「IT業界の請求はこう」と要約することはできません。**

## 8-1. カネの流れの全体像

### (1) 1本の線で見る

```
 ① 見積          ② 契約          ③ 作業           ④ 納品／作業報告
   金額の案       金額が確定       ★費用だけ発生      「渡した」ことの記録
                                    （人件費・外注費）
     │              │                │                   │
     └──────────────┴────────────────┴───────────────────┘
                                                          │
                                                          ▼
 ⑤ 検収／承認  ──▶ ⑥ 売上計上 ──▶ ⑦ 請求 ──▶ ⑧ 売掛金 ──▶ ⑨ 入金
   顧客が判定        帳簿に記録      請求書発行    未回収の債権    現金が増える
                     （現金は動かない）

 ＜同時に、逆向きにお金が出ていく＞

 ⑩ 給与（毎月）        ⑪ 協力会社への支払      ⑫ 家賃・ライセンス・採用費
   技術者の人件費        買掛金 → 支払             販管費
```

### (2) 入ってくるお金と、出ていくお金

| | 何か | いつ動くか |
|---|---|---|
| **入ってくる** | 受託開発の代金（請負） | **検収の1〜2か月後**【Varies】 |
| | SESの代金（準委任） | **毎月**（作業報告書の承認後） |
| | 保守料（準委任） | **毎月**（または四半期・年次）【Varies】 |
| **出ていく** | **技術者の給与・賞与・社会保険料** | **毎月**（仕事があってもなくても） |
| | 協力会社への外注費 | **月次**（受領日から60日以内。8-5） |
| | オフィス家賃 | 月次 |
| | ライセンス・クラウド利用料 | 月次／年次【Varies】 |
| | 採用費（求人媒体・人材紹介） | 発注時／採用時 |
| | 源泉所得税の納付 | **法定・契約上のタイミング**（徴収の日の属する月の翌月10日まで） |
| | 社会保険料の納付 | 月次 |

## 8-2. ★請負のカネの流れ——検収がないと請求できない

### (1) 時系列で見る

```
  【6月】契約締結        金額が確定する（この後は増えない）
     │                  ★この時点では売上でも入金でもない
     ▼
  【8月〜12月】作業      技術者の給与は毎月出ていく
     │                  協力会社への外注費も毎月出ていく
     │                  ★売上は1円も立たない
     ▼
  【1月14日】納品        納入物＋検収依頼書を渡す
     │                  ★まだ請求できない
     ▼
  【1月28日】検収合格    顧客が「合格」と判定し、検収合格書を交付
     │                  ★ここで初めて請求できる
     ▼
  【1月末】売上計上      帳簿に「売上1,224.5万円」と記録する
     │                  ★現金は1円も入っていない。売掛金が立つ
     ▼
  【1月末】請求書発行    月末締めで請求書を送る
     │
     ▼
  【2月末】入金          ★ここで初めて現金が増える
```

### (2) 各段階で「何が起きて」「何が起きていないか」

| 段階 | 起きること | **起きていないこと** |
|---|---|---|
| **契約（受注）** | 金額が確定する。作業を始められる | **売上ではない。入金でもない** |
| **作業中** | 費用（人件費・外注費）が発生する | **売上は立たない** |
| **納品** | 納入物を渡した記録が残る | **請求できない**（検収がまだ） |
| **検収合格** | 顧客が合格と判定する | — |
| **売上計上** | 帳簿に売上を記録する | **現金は増えない** |
| **請求** | 請求書を送る | **現金は増えない** |
| **入金** | **現金が増える** | — |

> **★「受注 ≠ 売上 ≠ 入金」**
> 04の4-4が示しているとおり、この3つは別の出来事です。
> ```
>  契約（受注）  →  作業  →  検収  →  請求  →  入金
>       │                      │               │
>       │                      └── 売上計上 ──┘
>       └─ この時点ではまだ売上ではない       └ ここで初めて現金が増える
> ```

### (3) 検収とは何か

**検収（けんしゅう）**
→ 顧客が、納めたものを検査して「合格」と判定すること。
→ 実務例：「検収が下りました」＝「顧客が合格と認めたので、請求書を出せます」という意味。
   **納めただけでは検収ではありません。**顧客が検査して判定するまでが検収です。

| 誰が行うか | **顧客**（社外）。自社は待つだけ |
|---|---|
| **何に基づいて判定するか** | 【Typical】**検査仕様書**（顧客が作る。合否の基準） |
| **どれくらいかかるか** | 【Varies】契約で定める。【Example】04の4-5では「納入後10営業日」 |
| **不合格だったら** | 修正して再度納品する。**その工数は自社負担**（請負のため） |

> **★検収期間が長いと、資金繰りに効きます**
> 【Example】検収期間が10営業日なら、納品から請求まで約2週間です。
> **20営業日なら約1か月**です。その分だけ入金が後ろにずれます。
> そのため、⑪契約・法務機能は契約時に検収期間を確認します（05の⑪-2）。

### (4) 【Example】請負の資金の出入りを、月ごとに追う

> **以下は説明用の架空の例です。実データではありません。**
> 04の4-5で追跡した案件（R社／契約金額1,250万円 → 変更後1,352万円）を、カネの側から見ます。

| 月 | 入ってくるお金 | 出ていくお金（この案件の分） | 累計の持ち出し |
|---|---:|---:|---:|
| 7月（要件定義） | 0 | 技術者2名分 約104万円 | △104万円 |
| 8月 | 0 | 技術者4名分 約208万円 | △312万円 |
| 9月 | **127.5万円**（契約1の入金） | 技術者4名＋協力会社1名 約266万円 | △450万円 |
| 10月 | 0 | 技術者4名＋協力会社1名 約266万円 | △716万円 |
| 11月 | 0 | 技術者4名＋協力会社1名 約266万円 | △982万円 |
| 12月 | 0 | 技術者4名＋協力会社2名 約324万円 | △1,306万円 |
| 1月（納品・検収） | 0 | 技術者2名分 約104万円 | △1,410万円 |
| **2月（入金）** | **1,224.5万円** | 0 | **△185万円** |

> **★12月末の時点で、この案件だけで約1,306万円を立て替えています。**
> 【Typical】これが、受託開発（請負）の資金の特徴です。
> **作業は数か月続くのに、入金は終わってからです。**
>
> 04の4-3①が述べているとおり、そのため規模の大きい案件では
> **着手金・中間金**を設定し、分割して請求する形をとることがあります【Typical】。

## 8-3. ★準委任（SES・保守）のカネの流れ——作業報告書の承認が請求の根拠

### (1) 時系列で見る

```
  【契約】            月額780,000円／精算幅140〜180時間【Example】
     │
     ▼
  【毎月1日〜末日】   技術者が常駐先で作業する
     │               ★この間も給与は出ていく（請負と同じ）
     ▼
  【月末〜翌月初】    ★作業報告書を作成 → 常駐先の主任担当者へ提出
     │
     ▼
  【顧客の承認】      ★ここが請求の根拠
     │
     ▼
  【月末】            売上計上（役務提供期間に応じて）
     │
     ▼
  【翌月初】          請求書発行
     │
     ▼
  【翌々月末】        入金【Varies】支払サイトによる
```

### (2) 請負との違いを並べる

| | **請負** | **準委任（SES・保守）** |
|---|---|---|
| 請求の根拠 | **検収合格書** | **作業報告書への顧客の承認** |
| 請求の周期 | 【Typical】検収後にまとめて／出来高で分割 | **毎月** |
| 売上計上 | **検収が完了した時点**（検収基準） | **役務を提供した期間ごと**（毎月） |
| 金額 | **契約時に固定** | 【Typical】精算幅の中は定額、外れた分は精算 |
| 工数が増えたら | **売上は増えず、原価だけ増える** | 【Typical】上限を超えた分は加算される |
| 立て替えの期間 | **数か月**（作業開始〜入金） | **1〜2か月**（作業した月〜入金） |
| 売上が止まる原因 | 次の案件が受注できない | **契約終了・要員交代** |

### (3) 精算幅（せいさんはば）

【Typical】SESの契約では、**1か月あたりの作業時間に上限と下限を決める**のが一般的です。

**精算幅（せいさんはば）**
→ 「この時間の範囲内なら、月額は定額」と決めた時間の幅のこと。「幅精算」「上下割れ」とも言う。
→ 実務例：「140〜180時間の精算幅です」＝
   「その月に140時間から180時間働けば、月額780,000円。それを外れたら精算します」という意味。

【Example】説明用の架空例（04の4-3②より）：
> **契約条件**：月額 780,000円（税抜）／精算幅 **140時間 〜 180時間**
> 　　　　　　　下限を下回った場合：不足1時間あたり 5,570円を控除
> 　　　　　　　上限を超えた場合　：超過1時間あたり 4,330円を加算
>
> | その月の稼働時間 | 請求額 | 計算 |
> |---:|---:|---|
> | 160時間 | 780,000円 | 精算幅の中なので定額 |
> | 132時間 | 735,440円 | 780,000 −（8時間 × 5,570円） |
> | 190時間 | 823,300円 | 780,000 +（10時間 × 4,330円） |

> **なぜ精算幅があるのか**
> 【Inference】月によって営業日数が違うため（例：20日の月と22日の月）、実際の稼働時間は毎月変動します。
> 1時間単位で毎月金額が変わると管理が煩雑になるため、
> **一定の幅の中は定額とし、幅を外れた分だけ精算する**という運用になっています。

> **★下限割れは売上が減ります**
> 【Typical】技術者が病気で休んだ月、年末年始や大型連休のある月は、下限を割ることがあります。
> **このとき請求額が減ります。**
> 一方、自社が払う給与は月給制であれば変わりません。**この月は粗利が薄くなります。**

### (4) 【Example】SESの資金の出入りを、月ごとに追う

> **以下は説明用の架空の例です。実データではありません。**

| 項目 | 金額【Example】 |
|---|---:|
| 顧客への請求（月額） | 780,000円 |
| その技術者の原価（給与＋社会保険料＋交通費） | 520,000円 |
| **1人あたりの月次の粗利** | **260,000円**（粗利率33.3%） |

| 月 | 作業 | 売上計上 | 請求 | 入金【Varies】 | 給与の支払 |
|---|---|---|---|---|---|
| 4月 | 4月分の作業 | 4月末 | 5月初 | **6月末** | 4月25日 |
| 5月 | 5月分の作業 | 5月末 | 6月初 | **7月末** | 5月25日 |
| 6月 | 6月分の作業 | 6月末 | 7月初 | **8月末** | 6月25日 |

> **★給与の支払が、入金より2か月先行しています。**
> 4月分の作業に対する入金は6月末ですが、**4月の給与は4月25日に払っています。**
> つまり、**常に2か月分の人件費を立て替えている**状態になります【Typical】。
>
> 【Example】モデル企業のSES14名分なら、520,000円 × 14名 × 2か月 = **約1,456万円**を、
> 常に立て替えている計算になります。

## 8-4. ★多重下請では、自社の入金より協力会社への支払が先に来る

### (1) この業界の資金繰りを難しくしている構造

【Typical】モデル企業は、元請SIerに対しては「受ける側」ですが、協力会社に対しては「**出す側**」です（06の6-2）。
このとき、お金の流れは次のようになります。

```
  エンドユーザー
      │ 支払
      ▼
  元請SIer（P社）
      │ 支払 ← ★Xシステムへの入金は、検収や作業報告の承認の 1〜2か月後
      ▼
  Xシステム ★ここ
      │ 支払 ← ★協力会社への支払は、受領日から60日以内
      ▼
  協力会社（T社）
      │ 支払
      ▼
  T社の技術者（給与）
```

### (2) 条文の確認——支払期日

【Fact】
> **製造委託等に係る中小受託事業者に対する代金の支払の遅延等の防止に関する法律（取適法） 第三条**
> 「製造委託等代金の支払期日は、委託事業者が中小受託事業者の給付の内容について**検査をするかどうかを問わず**、
> 委託事業者が中小受託事業者の給付を**受領した日**（略）から起算して、**六十日の期間内**において、
> かつ、できる限り短い期間内において、定められなければならない。」
> （出典：製造委託等に係る中小受託事業者に対する代金の支払の遅延等の防止に関する法律／e-Gov法令検索）

【Fact】同法第5条第1項は、委託事業者の遵守事項として次を挙げています。
> 「二　製造委託等代金をその**支払期日の経過後なお支払わない**こと（略）。
> 　三　中小受託事業者の責めに帰すべき理由がないのに、製造委託等代金の額を**減ずる**こと。」
> （出典：同法／e-Gov法令検索）

**実務上の意味（条文の説明ではなく、実務としてどうなるか）**
【Typical】「自社が顧客から入金されていないから、協力会社への支払も待ってもらう」という運用は、
この条文の枠外ということになります（05の⑩-7）。

> **★ただし、適用されるかどうかは別の基準で決まります**
> 【Fact】取適法が適用されるかどうかは、**委託の内容と、発注側・受注側の資本金または従業員数の組み合わせ**で決まります。
> 経済産業省のガイドラインは次のように述べています。
> > 「取適法の適用の有無を判断するに当たり、**請負契約であるか準委任契約であるかを峻別する必要はない**。
> > 取適法は、情報成果物作成委託、役務提供委託など委託の内容と資本金又は従業員数により判断される。」
> > （出典：情報サービス・ソフトウェア産業における中小受託適正取引等の推進のためのガイドライン／経済産業省）
>
> **したがって「IT業だから取適法の対象」とは言えません。**
> **取引ごとに、委託の内容と規模の組み合わせを確認することになります**（05の⑪-7、15で詳述）。

### (3) 3つの支払が、入金より先に来る

| 出ていくお金 | いつ出ていくか | 入金との関係 |
|---|---|---|
| **技術者の給与** | **毎月**（モデル企業では25日【Example】） | **入金を待たない。最も早い** |
| **社会保険料・源泉所得税** | 月次／法定・契約上のタイミング | 入金を待たない |
| **協力会社への支払** | 受領日から60日以内 | 【Typical】自社への入金より先になることがある |
| **オフィス家賃・ライセンス** | 月次 | 入金を待たない |

```
  【Example】時間軸で見る（説明用の架空例）

  4月     協力会社T社が作業（1名・58万円）
  4月25日 自社の技術者に給与を支払う           ← 出ていく
  5月末   T社から請求書を受け取る
  6月末   ★T社へ58万円を支払う                ← 出ていく
  6月末   ★元請P社から4月分のSES代金が入金    ← 入ってくる

  → 4月に作業した分のお金が入るのは6月末。
    その間に、自社の給与（4月・5月）とT社への支払が先に出ている。
```

> **★この構造が「黒字なのにお金がない」を生みます**
> 【Typical】帳簿上は利益が出ていても、**現金が手元にない**という状態が起きます。
> そのため、⑩経理・財務機能は**資金繰り表**を作り、今後の入出金の予定と現金残高の見通しを管理します
> （05の⑩-12。頻度：月次／週次【Varies】）。

### (4) 売掛金と買掛金

**売掛金（うりかけきん）**
→ 売上は立ったが、まだ入金されていない金額のこと。
→ 実務例：「売掛金が4,800万円あります」＝「請求済みだが、まだ受け取っていないお金が4,800万円ある」という意味。
   **回収できなければ、その分は損失になります。**

**買掛金（かいかけきん）**
→ 仕入や外注の費用が発生したが、まだ支払っていない金額のこと。
→ 実務例：「協力会社への買掛金が550万円あります」＝
   「作業はしてもらったが、まだ払っていないお金が550万円ある」という意味。

| | 売掛金 | 買掛金 |
|---|---|---|
| 何か | **受け取る予定のお金** | **支払う予定のお金** |
| この業界での発生源 | 検収後の請求／毎月の作業報告後の請求 | 協力会社への外注費 |
| 管理する書類 | 売掛金元帳・売掛金年齢表 | 買掛金元帳 |
| 【Example】モデル企業の規模感 | 【Varies】検収から入金まで1〜3か月分が滞留する（03の3-7） | 協力会社への1〜2か月分 |

> **★03の3-7が述べているとおり、この業界の会社は「貸借対照表が小さい」**
> 工場も在庫もないため、**資産の大半が「売掛金」と「現金」**になります。
> つまり、**資産のほとんどが「まだ受け取っていないお金」**という形をしています。

## 8-5. コスト構造——何にお金を使っているか

### (1) モデル企業の費用の全体像【Example】

> **以下はすべて説明用の設定値です。業界平均ではありません。**（03の3-2より）

| 項目 | 金額【Example】 | 売上比 | 性質 |
|---|---:|---:|---|
| **売上高** | **4億5,000万円** | 100.0% | |
| 外注費（協力会社へ支払った金額） | 6,600万円 | 14.7% | 発注した分だけ発生 |
| **労務費（技術者の人件費）** | **2億5,000万円** | **55.6%** | **仕事がなくても発生** |
| **売上総利益（粗利）** | **1億3,400万円** | 29.8% | |
| 販売費及び一般管理費 | 1億800万円 | 24.0% | 役員報酬、営業・管理部門の人件費、家賃、通信費、採用費、システム利用料など |
| **営業利益** | **2,600万円** | 5.8% | |

> **★費用の9割近くが人件費と外注費です**（03の3-7）。
> 材料費・物流費がありません。**売っているものが作業だから**です。

### (2) コストを1つずつ見る

#### ① 人件費（圧倒的最大）

| 何が含まれるか | 給与、賞与、**社会保険料の会社負担分**、通勤交通費 |
|---|---|
| **いつ発生するか** | **毎月。仕事があってもなくても** |
| **売上比【Example】** | 労務費 2億5,000万円 ÷ 売上4億5,000万円 = **55.6%** |
| **1人あたり【Example】** | 技術者1名あたり月52万円（03の3-5、05の5-15と同じ設定値） |
| **なぜ最大なのか** | **売っているものが人の作業時間だから**（07の7-0） |

> **★初心者が誤解しやすい点：人月単価 ≠ 技術者の給与**
> 【Example】モデル企業では、顧客への平均単価が月78万円、技術者1名の原価が月52万円です。

#### ② 協力会社への外注費

|---|---|
| **いつ発生するか** | 発注時（費用の計上）／受領日から60日以内（支払） |
| **売上比【Example】** | 6,600万円 ÷ 4億5,000万円 = **14.7%** |
| **【Example】単価** | 協力会社の技術者1名あたり月58万円（自社要員52万円より高い） |
| **なぜ使うのか** | ・自社の人が足りないとき<br>・案件を断ると取引先との関係が切れるとき<br>・専門的な技術が自社にないとき |

> **★外注を使うと粗利は薄くなります**
> 【Example】顧客への単価78万円、協力会社への支払58万円なら、粗利は**20万円**です。
> 自社要員なら78万円 − 52万円 = **26万円**です。
> **それでも外注を使うのは、断ると売上がゼロになるから**です（03の3-5）。

#### ③ オフィス家賃

## 8-6. ★待機（アイドル）が出ると、売上ゼロで人件費だけが出ていく

### (1) この業界特有の費用構造

**待機（たいき）**
→ 技術者が、どの案件にも割り当てられていない状態のこと。「アサイン待ち」「ベンチ」とも言う。
→ 実務例：「田中さんは今月末で案件が終わるので、来月から待機になります」。

```
  【案件に入っている技術者】
     売上：78万円／月  −  原価：52万円／月  =  粗利 +26万円

  【待機している技術者】
     売上： 0万円／月  −  原価：52万円／月  =  粗利 △52万円

  → 1名が1か月待機すると、案件に入っている場合と比べて
     26万円 + 52万円 = 78万円分、利益が違ってくる
```

### (2) 【Example】数字で見る（03の3-5と同じ設定）

> モデル企業（技術者40名、平均単価78万円）で、3名が1か月まるまる待機したとします。
>
> - **失われる売上**：78万円 × 3名 × 1か月 = **234万円**
> - **それでも発生する費用**：技術者3名分の人件費（1人あたり月52万円とすると）= **156万円**
>
> **年間の営業利益が2,600万円の会社にとって、これは小さな金額ではありません。**
> 3名が3か月待機すれば、営業利益の大半が消えます。

### (3) なぜ製造業と違うのか

| | 製造業 | 受託開発（IT） |
|---|---|---|
| 受注がないとき | 材料を仕入れなければ、変動費は発生しない | **人件費は毎月まるごと発生する** |
| 費用を減らすには | 仕入を止める（すぐできる） | **すぐには減らせない** |
| 能力を増やすには | 設備を買う（数か月〜数年） | 人を採用する（数か月〜1年）【Varies】 |

> **★だから営業と要員管理が連動します**
> 【Typical】03の3-5が述べているとおり、次のことが起きます。
> - 営業は「案件を取ってくる」だけでなく、「**いま空いている人に合う案件を探す**」ことを求められます。
> - 案件の終了時期を逆算して、**終わる1〜2か月前から次の案件を探し始めます**（頻度：常時）。
> - **単価が低くても、待機させるよりは入れたほうがまし**という判断が生じます。
>
> **本資料はこの判断の良し悪しを評価しません。** 費用の構造としてこうなる、ということを押さえてください。

## 8-7. ★プロジェクトが赤字化する仕組み

### (1) 構造を一文で言うと

> **請負契約では、契約金額は受注時点で決まっている。**
> **だから工数が超過しても売上は1円も増えない。増えるのは原価だけである。**（05の5-15）

```
  請負の利益 ＝ 契約金額 −（実績工数 × 原価単価）− 外注費 − その他の原価
                   ↑固定          ↑ここだけが動く
```

- **左側（契約金額）**は、⑥受注・契約締結の時点で確定します。
- **右側（実績工数）**は、作業が終わるまで確定しません。

**その差が、そのまま利益または赤字になります。**

### (2) 工数が超過する原因【Typical】

| 原因 | 誰が負担するか | 防ぎ方（実務でどう扱うか） |
|---|---|---|
| **見積が甘かった** | **自社** | 過去案件の実績工数を記録し、次の見積に反映する（05の③-11・②-3） |
| **要件が固まっていなかった** | **自社**（前提条件書に書いていなければ） | 前提条件書で範囲を線引きする（05の②-6） |
| **顧客の回答が遅れた** | 【Varies】記録があれば交渉の余地がある | 課題一覧に回答期限を書いて記録を残す（05の③-5） |
| **仕様変更** | **顧客**（変更管理書で合意できていれば） | 変更管理書を発行し、追加費用を請求する（05の③-8・①-8） |
| **不具合が多く出た** | **自社** | テストを前倒しする【Varies】 |
| **技術が未経験だった** | **自社** | ③実現性の確認で見極める（04の③） |

> **★同じ「工数超過」でも、誰が負担するかが変わります。**
> 分かれ目は**記録があるかどうか**です。
> - 仕様変更を**変更管理書**で合意していれば → 顧客に請求できる
> - 口頭で引き受けていれば → **自社負担**
> - 顧客の回答遅れを**課題一覧**に記録していれば → 交渉の余地がある
> - 記録していなければ → **自社負担**

### (3) 【Example】赤字化する過程を数字で追う（05の5-15より）

> **以下は説明用の架空の例です。実データではありません。**

**② 見積の段階**

| 項目 | 金額・工数 |
|---|---:|
| 見積工数 | 14.6人月（291.4人日） |
| 契約金額（税抜） | 1,200万円 |
| 想定原価（自社要員のみ、1人月52万円） | 759万円 |
| **見込み粗利** | **441万円**（粗利率36.8%） |

**③-4 設計工程が終わった時点**

| 工程 | 見積（人日） | 実績（人日） | 差 |
|---|---:|---:|---:|
| 要件定義 | 24.8 | 31.0 | **+6.2** |
| 設計 | 82.5 | 95.0 | **+12.5** |
| 小計（確定分） | 107.3 | 126.0 | **+18.7** |

**⑩-10 案件別損益の確定**

| 項目 | 金額 |
|---|---:|
| 売上（契約金額） | 1,200万円 |
| 自社要員の原価（15.5人月 × 52万円） | 806万円 |
| 外注費（協力会社3.0人月） | 174万円 |
| 経費（交通費・インフラ費用） | 15万円 |
| **原価計** | **995万円** |
| **粗利** | **205万円**（粗利率17.1%） |
| **見込みとの差** | **△236万円** |

> **★見積では441万円の粗利を見込んでいたのに、実際は205万円でした。**
> 売上は1円も変わっていません。**変わったのは原価だけ**です。

### (4) ★この構造が「毎日の工数入力」を必要にする理由

【Typical】赤字かどうかを知るには、**実績工数**が要ります。
しかし実績工数は、技術者本人が入力しないと存在しません。

| 情報 | どこにあるか | 持っている機能 |
|---|---|---|
| **契約金額**（固定された売上） | 契約書 | ⑪契約・法務 → ⑩経理・財務 |
| **実績工数**（動く原価の「量」） | **作業実績の入力** | ④開発 → ③PM |
| **原価単価**（工数を金額に変える係数） | 給与・人件費のデータ | ⑨人事・採用 → ⑩経理・財務 |

**この3つを掛け合わせないと、「いま黒字か赤字か」が出ません。**
PMは工数を持っていますが、各人の原価単価（給与）は通常見ていません。
経理は原価単価を持っていますが、現場の進捗は見ていません。
**だから月次で突き合わせます**（05の③-4と⑩-10）。

> **★工数の実績が記録されないと、赤字かどうかが分かりません。**
> これが、09（情報の流れ）でも繰り返し出てくる原則です。

### (5) 準委任では、この構造が変わる

| | **請負** | **準委任** |
|---|---|---|
| 売上 | **契約時に固定** | 作業時間に応じて毎月 |
| 工数が増えたら | **売上は増えず、原価だけ増える（赤字化）** | 【Typical】精算幅の範囲内は定額、超えた分は加算 |
| **利益を決めるもの** | **見積工数と実績工数の差** | **稼働率と、単価と原価の差** |
| PMが見るべき数字 | 工数の消化率・着地見込み | 稼働時間が精算幅に収まっているか |

> **つまり、同じ会社の中で2つの採算構造が並行しています。**
> 【Example】モデル企業では、売上の50%が請負、50%が準委任（SES35%＋保守15%）です（03の3-2）。

## 8-8. 売上をいつ計上するか（売上計上のタイミング）

**売上計上（うりあげけいじょう）**
→ 会計帳簿に「売上が発生した」と記録すること。**お金が入ってくることとは別**です。
→ 実務例：3月に検収が終われば、入金が5月でも**3月の売上**として記録する。
   このずれが「黒字なのにお金がない」状態を生む。

| 契約の形 | 【Typical】いつ売上にするか | 根拠となる考え方 |
|---|---|---|
| **請負** | **検収が完了した時点**（検収基準） | 仕事の完成に対して報酬を受け取る契約だから（民法632条） |
| **準委任（SES・保守）** | **役務を提供した期間ごと**（毎月） | 期間に応じて報酬を定めているから（民法648条第2項ただし書） |
| **準委任（成果完成型）** | 【Varies】成果の引渡し時 | 民法648条の2 |
| **SaaS利用料** | **利用期間に応じて毎月** | 契約期間にわたってサービスを提供するから |

> **【Varies】適用する会計基準によって扱いが異なります。**
> 上場企業や大会社では「収益認識に関する会計基準」に従い、**進捗度に応じて期間にわたって収益を認識する**扱いになる場合があります。
> 中小企業では、検収基準によることが一般的とされます【Typical】。
> **具体的にどの基準を適用するかは、会社の規模と監査の有無によって異なるため、
> 実務では顧問税理士・会計士に確認します。**

## 8-9. 毎月必ず出ていくお金

### (1) 給与と、それに伴う納付

| 何を | いつ | 誰が |
|---|---|---|
| **給与の支給** | 【Example】毎月25日 | ⑩経理・財務（計算）、⑨人事・採用（勤怠の集計） |
| **社会保険料の納付** | 月次 | ⑩経理・財務 |
| **源泉所得税の納付** | **法定・契約上のタイミング** | ⑩経理・財務 |

【Fact】
> **所得税法 第百八十三条第一項**
> 「居住者に対し国内において第二十八条第一項（給与所得）に規定する給与等（以下この章において「給与等」という。）の
> 支払をする者は、その支払の際、その給与等について所得税を徴収し、
> **その徴収の日の属する月の翌月十日までに、これを国に納付しなければならない**。」
> （出典：所得税法／e-Gov法令検索）

**実務上の意味**：給与から源泉徴収した所得税は、徴収した月の翌月10日までに納付することになります。
【Varies】納期の特例の適用を受けている場合は取り扱いが異なるため、実務では顧問税理士に確認します。

### (2) 月次の資金の流れ【Example】

> **以下は説明用の架空の例です。実データではありません。**
> モデル企業の1か月を単純化した形です。

| 日 | 出来事 | 金額の目安【Example】 |
|---|---|---:|
| 1日〜5日 | 前月分の作業報告書を回収し、顧客の承認を得る | — |
| 5日〜10日 | **請求書を作成・送付**（SES・保守・検収済みの請負） | 請求額 約3,750万円／月 |

## 8-11. この章のまとめ

### 情報通信業のカネの流れで押さえるべき10点

1. **請負は、検収がないと請求できない。**
   【Fact】民法第632条は、報酬が「仕事の結果に対して」支払われると定めています。

2. **準委任は、作業報告書への顧客の承認が請求の根拠になる。**
   【Fact】民法第645条が受任者の報告義務を、第648条第2項ただし書が「期間によって報酬を定めたとき」の扱いを定めています。
   **これらは別々の条文です。**

3. **売上計上のタイミングが違う。**
   請負は**検収基準**、準委任は**役務提供期間**ごと。【Varies】適用する会計基準によって扱いが異なります。

4. **受注 ≠ 売上 ≠ 入金。** この3つは別の出来事で、それぞれ数か月ずれます。

5. **請負では、作業期間中ずっと費用だけが出ていく。**
   【Example】1,352万円の案件で、12月末時点の立て替えは約1,306万円でした。

6. **多重下請では、自社の入金より協力会社への支払が先に来ることがある。**
   【Fact】取適法第3条は、支払期日を「受領した日から起算して六十日の期間内」と定めています。
   ただし**適用されるかどうかは、委託の内容と資本金・従業員数の組み合わせで決まります。**

7. **費用の9割近くが人件費と外注費。** 材料費は0円です。

8. **待機が出ると、売上ゼロで人件費だけが出ていく。**
   【Example】3名が1か月待機すると、売上234万円が消え、人件費156万円は出ていきます。

9. **請負の赤字は、見積工数と実績工数の差から生まれる。**
   契約金額は固定なので、**増えるのは原価だけ**です。

10. **工数の実績が記録されないと、赤字かどうかが分からない。**
    契約金額（契約書）・実績工数（技術者の入力）・原価単価（給与データ）の3つは、
    それぞれ別の場所にあります。**だから月次で突き合わせます。**

# 14_kpi.md — KPI・数字（情報通信業）

**対象**：日本国内の中小情報通信業（受託開発を主業とするソフトウェア会社）
**読み手**：情報通信業をまったく知らない人
**前提**：`03_company-structure.md` で設定した**Xシステム株式会社**（従業員48名・技術者40名・年商4億5,000万円）【Example】
**最終更新**：2026-09-20

## 14-0. このファイルの読み方（★先に読んでください）

### 数値の水準は示しません

> **★本ファイルは、「稼働率は何%が適切か」「人月単価はいくらか」といった水準を示しません。**

理由は次のとおりです。

| 項目 | なぜ水準を示さないか |
|---|---|
| **人月単価** | **公的な出典を確認できなかった**（19_sources.md §6）。<br>地域・技術分野・元請との関係・下請の階層によって大きく異なる【Varies】 |
| **稼働率** | **公的な出典を確認できなかった**（19_sources.md §6） |
| **離職率** | 【Varies】会社によって大きく異なる |
| **不具合件数** | 【Varies】システムの規模・種類によって大きく異なる |
| **粗利率** | 【Varies】契約形態・階層の位置・外注比率によって大きく異なる |

**本ファイルに出てくる具体的な金額・比率は、すべて説明用の架空の設定値【Example】です。**
**業界平均として引用しないでください。**

### では、何を書くのか

> **「どんな数字を見ているか」と「その数字が動くと何が起きるか」**を書きます。
> 数字そのものより、**数字と数字のつながり**を理解することが目的です。

### KPIとは

**KPI（ケーピーアイ）**
→ Key Performance Indicator の略。「この数字を見れば、仕事がうまくいっているかが分かる」という指標のこと。
→ 実務例：「今月のKPIは稼働率95%と粗利率30%です」＝
   「今月は、技術者の95%が案件に入っていて、売上の30%が粗利として残る状態を目指す」という意味。

## 14-1. ★この業界の数字の全体構造

### (1) 1本の式から、ほとんどの数字が導かれる

```
  売上 ＝ 技術者の人数 × 稼働率 × 平均単価 × 期間
           │             │         │
           │             │         └─ ⑤ 人月単価
           │             └─ ① 稼働率
           └─ ④ 要員数

  粗利 ＝ 売上 −（実績工数 × 原価単価）− 外注費
                  │
                  └─ ② 見積工数と実績工数の差（工数超過率）
                       → ③ プロジェクト別粗利
```

### (2) 数字のつながりを図で見る

```
  ┌────────────────────┐
  │ ⑦ 採用人数          │──▶ 技術者の人数が増える
  └────────────────────┘                │
  ┌────────────────────┐                ▼
  │ ⑧ 離職率【Varies】  │──▶ ┌────────────────────┐
  └────────────────────┘     │ ④ 要員数            │
                              └──────────┬─────────┘
                                         │
  ┌────────────────────┐                ▼
  │ ⑨ 受注残            │──▶ ┌────────────────────┐
  │（この先の仕事の量）  │     │ ① 稼働率            │◀── 待機人数
  └────────────────────┘     │（案件に入っている割合）│
                              └──────────┬─────────┘
                                         │
  ┌────────────────────┐                ▼
  │ ⑤ 人月単価【Varies】│──▶ ┌────────────────────┐
  │  ← ⑪ 直請けと下請の │     │      売  上          │
  │     比率が影響する   │     └──────────┬─────────┘
  └────────────────────┘                │
                                         ▼
  ┌────────────────────┐     ┌────────────────────┐
  │ ② 工数超過率        │──▶ │ ③ プロジェクト別粗利 │
  │（見積と実績の差）    │     └──────────┬─────────┘
  └────────────────────┘                │
         ▲                                ▼
         │                     ┌────────────────────┐
  ┌──────┴─────────┐          │  会社全体の粗利・利益 │
  │ ⑫ 不具合件数     │          └────────────────────┘
  │   【Varies】     │
  └──────────────────┘
```

## 14-2. ① 稼働率（★もっとも重要な数字）

### (1) 何を表す数字か

**稼働率（かどうりつ）**
→ 自社の技術者のうち、実際に「お金をもらえる仕事」に割り当てられている人の割合のこと。
　 「アサイン率」「要員稼働率」とも呼ぶ。
→ 実務例：「今月の稼働率は92%です」＝「40名のうち約37名は案件に入っているが、約3名は入っていない」という意味。

```
  稼働率 ＝ 案件に入っている技術者の人数 ÷ 技術者の総数
```

> **【Varies】計算の仕方は会社によって異なります。**
> - 人数で数えるか、時間で数えるか
> - 教育・研修の時間をどう扱うか
> - 社内作業（提案書の作成、社内ツールの整備）をどう扱うか
> **本資料は、どの計算方法が正しいかという評価は行いません。**

| 誰が見るか | 要員管理機能（営業部長）／社長／営業 |
|---|---|
| **どこで集計するか** | 稼働率の集計表（10の帳票30） |
| **頻度** | **常時**（監視）／**月次**（集計） |

### (2) ★稼働率が1%下がると、何が起きるか（初心者向け）

> **この説明が、この業界を理解するうえでもっとも重要です。**

#### ステップ1：1%とは何人分か

【Example】モデル企業は技術者40名です。

```
  40名 × 1% = 0.4名
```

**「0.4名」という中途半端な数は、実際には次のような状態を指します。**
- 1名が、1年のうち約5か月だけ待機している
- または、4名が、1年のうち約1.2か月ずつ待機している
- または、40名全員が、月に1日ずつ「どの案件にも入っていない日」がある

#### ステップ2：それがいくらの売上になるか

【Example】平均単価78万円／人月とすると：

```
  78万円 × 0.4名 × 12か月 = 374万円／年
```

**稼働率1%＝年374万円の売上**です【Example】。

#### ステップ3：その売上が消えると、利益はどうなるか

```
  売上が374万円減る
      ↓
  しかし、費用は減らない
      ↓
  なぜなら、技術者の人件費は「仕事があってもなくても発生する」から（12の12-5）
      ↓
  ★374万円が、そのまま利益から消える
```

**モデル企業の年間営業利益は2,600万円【Example】です。**

```
  稼働率 1%減 → 利益 374万円減（営業利益の 14.4%）
  稼働率 3%減 → 利益 1,122万円減（営業利益の 43.2%）
  稼働率 5%減 → 利益 1,870万円減（営業利益の 71.9%）
```

> **★製造業と比べると、この怖さが分かります**
>
> | | 製造業 | 受託開発（IT） |
> |---|---|---|
> | 受注が1%減ったら | 材料の仕入も1%減る → **利益への影響は小さい** |
> | 稼働率が1%減ったら | — | **人件費は変わらない → 売上の減少がそのまま利益の減少** |

#### ステップ4：だから、会社は何をするか

【Typical】03の3-5が述べているとおり、次のことが起きます。

| 打つ手 | 内容 |
|---|---|
| **終了の1〜2か月前から次を探す** | 終わってから探すと、確実に空白ができる（05の⑧-5） |
| **単価が低くても入れる** | 待機させるより、限界利益が大きいため（12の12-5） |
| **別の技術の案件に、立ち上がり期間を見込んで入れる** | すぐには戦力にならなくても、待機よりよい |
| **社内作業に充てる**【Varies】 | 教育、社内ツールの整備、提案資料の作成 |

### (3) ★ただし「上げればよい」数字ではない

【Typical】稼働率100%は、次のことを意味します（03の3-5）。

- 教育・研修の時間がない
- 新しい技術を試す時間がない
- **急な引き合いに応えられない**
- **誰かが辞めたとき、代わりが誰もいない**

> **本資料は「稼働率は何%が適切か」という評価は行いません。**
> 押さえるべきは、**この1つの数字が、売上・利益・採用・営業のすべてに同時につながっている**という構造です。

## 14-3. ④ 要員数・稼働人数・待機人数

### (1) 3つの数字の関係

```
  要員数（技術者の総数） ＝ 稼働人数 ＋ 待機人数 ＋ 社内作業の人数【Varies】
```

【Example】モデル企業の場合：

| 区分 | 人数【Example】 | 内容 |
|---|---:|---|
| **技術者の総数** | **40名** | PM4名・SE20名・PG13名・運用保守3名 |
| **稼働人数** | 38名 | 顧客の案件に入っている |
| **待機人数** | 2名 | どの案件にも入っていない |
| **稼働率** | **95%** | 38名 ÷ 40名 |

### (2) 誰が見るか、何のために見るか

| 数字 | 誰が見るか | 何を決めるために |
|---|---|---|
| **要員数** | 社長／要員管理機能 | **売上の上限**を知る（12の12-1） |
| **稼働人数** | 要員管理機能／営業 | 今月の売上を見積もる |
| **★待機人数** | 要員管理機能／営業／社長 | **すぐに手を打つべき人が何名いるか** |
| **待機の日数** | 要員管理機能 | 1名が10日待機と、10名が1日待機は、金額としては同じ |

**頻度**：**常時**（把握）／**週次**（空き状況表の更新）／**月次**（集計）

### (3) ★待機の「原因」も数字とセットで見る

【Typical】待機が出たとき、原因によって打つ手が変わります（05の⑧-4）。

| 原因 | 打つ手【Typical】 |
|---|---|
| **案件が終わったのに次がない** | 営業と一緒に案件を探す |
| **スキルが合わない** | 育成期間を見込んで別の技術の案件に入れる【Varies】 |
| **通える範囲に案件がない** | 【Varies】在宅可能な案件を探す／持ち帰り案件に入れる |
| **本人の事情**【Varies】 | 個別の対応 |

## 14-4. ② ★見積工数と実績工数の差（工数超過率）

### (1) 何を表す数字か

**工数超過率（こうすうちょうかりつ）**
→ 見積もった工数に対して、実際に何%多く（少なく）かかったかを示す数字。
→ 実務例：「あの案件、工数超過率27%でした」＝
   「14.6人月と見積もったのに、18.5人月かかった」という意味。

```
  工数超過率 ＝（実績工数 − 見積工数）÷ 見積工数
```

【Example】05の5-15の例（説明用の架空例）：

```
  見積工数 14.6人月
  実績工数 18.5人月
  工数超過率 ＝（18.5 − 14.6）÷ 14.6 ＝ +26.7%
```

### (2) なぜこの数字が利益そのものなのか

```
  請負の利益 ＝ 契約金額 −（実績工数 × 原価単価）− 外注費 − その他の原価
                   ↑固定          ↑ここだけが動く
```

**請負契約では、契約金額は受注時点で決まっています。**
**だから工数が超過しても売上は1円も増えません。増えるのは原価だけです。**

| 誰が見るか | PM（案件の途中）／経理（案件の終了後）／見積・提案機能（次の見積のため） |
|---|---|
| **どこで見るか** | 工数実績表（10の帳票16） |
| **頻度** | **日次**（入力）／**週次**（PMの確認）／**月次**（集計）／納品時（確定） |

### (3) ★案件の途中で見る「消化率」と「着地見込み」

【Typical】案件が終わってから超過率を知っても手遅れです。
そのため、PMは途中で次の2つを見ます。

**消化率（しょうかりつ）**
→ 見積もった工数のうち、いまどれだけ使ったかの割合。
→ 実務例：「工数消化率80%、進捗50%」＝
   **「予定の8割の時間を使ったのに、半分しか終わっていない」**という危険な状態。

**着地見込み（ちゃくちみこみ）**
→ このままいけば最終的に何人月になるか、という予測。
→ 実務例：「着地見込み15.5人月。0.9人月超過する見込みです」。

```
  【正常な状態】
     進捗 50%  ←→  工数消化率 50%   （つり合っている）

  【危険な状態】
     進捗 50%  ←→  工数消化率 80%   （★このままいくと大幅に超過する）
```

> **★この2つの数字は、別のものを測っています**（09の9-3）
>
> | | 進捗 | 工数消化率 |
> |---|---|---|
> | 何を表すか | **どこまで終わったか** | **どれだけ時間を使ったか** |
> | 誰が記録するか | PM（担当者の報告をまとめる） | **技術者本人**（工数入力） |
>
> **突き合わせて初めて、遅れが見えます。**

### (4) 超過の「原因」を分類する

【Typical】案件が終わったら、超過の原因を分類します（05の③-11）。
**誰が負担したかを記録することが、次の見積を直す材料になります。**

【Example】05の5-15の例（説明用の架空例）：

| 超過の原因 | 人月 | 誰が負担したか |
|---|---:|---|
| 顧客の業務が想定より複雑だった（見積の甘さ） | 1.2 | **自社** |
| 既存システムの資料が古く調査に時間がかかった | 0.7 | **自社**（前提条件書に記載がなかった） |
| 顧客の回答が遅れた | 0.6 | **自社**（記録はあるが交渉しなかった） |
| 仕様変更（変更管理書で合意済み） | 1.4 | **顧客**（別途150万円を請求） |
| **合計** | **3.9** | |

> **★同じ「超過」でも、誰が負担するかが変わります。**
> **分かれ目は、記録があるかどうかです**（09の9-4）。

## 14-5. ③ プロジェクト別粗利（案件別損益）

### (1) 何を表す数字か

```
  プロジェクト別粗利 ＝ 売上（契約金額）
                       −（実績工数 × 原価単価）   ← 自社要員の原価
                       − 外注費                   ← 協力会社への支払
                       − その他の原価             ← 交通費・インフラ費用など

  粗利率 ＝ 粗利 ÷ 売上
```

【Example】説明用の架空例（05の5-15より）：

| 項目 | 金額 |
|---|---:|
| 売上（契約金額） | 1,200万円 |
| 自社要員の原価（15.5人月 × 52万円） | 806万円 |
| 外注費（協力会社3.0人月） | 174万円 |
| 経費（交通費・インフラ費用） | 15万円 |
| **原価計** | **995万円** |
| **粗利** | **205万円**（粗利率17.1%） |
| **見込みとの差** | **△236万円**（見込み粗利は441万円・粗利率36.8%） |

### (2) なぜ「案件別」で見る必要があるのか

【Typical】会社全体の粗利率が29.8%【Example】でも、その中身は次のように分かれています。

```
  会社全体の粗利率 29.8%【Example】
        │
        ├── 案件A（請負・見積どおり）      粗利率 35%
        ├── 案件B（請負・工数超過）        粗利率 17%  ← ★ここが足を引っ張っている
        ├── SES（14名）                    粗利率 33%
        └── 保守（3名）                    粗利率 30%
```

**会社全体の数字だけを見ていると、どの案件が赤字かが分かりません。**

### (3) 3つのデータが必要

| 情報 | どこにあるか | 持っている機能 |
|---|---|---|
| **契約金額** | 契約書 | ⑪契約・法務 → ⑩経理 |
| **実績工数** | **技術者の入力** | ④開発 → ③PM |
| **原価単価** | 給与・人件費のデータ | ⑨人事・採用 → ⑩経理 |

> **この3つは別々の場所にあります。だから月次で突き合わせます**（09の9-3）。

| 誰が見るか | 社長／PM |
|---|---|
| **どこで見るか** | 案件別損益表（10の帳票31） |
| **頻度** | **月次** |

## 14-6. ⑤ 人月単価【Varies】

### (1) 何を表す数字か

**人月単価（にんげつたんか）**
→ 技術者1人が1か月作業することに対して顧客が支払う金額のこと。
→ **この単価は、技術者本人の給料ではない。会社の経費と利益が上乗せされている。**

### (2) ★水準は示しません

> **【Varies】具体的な金額は、地域・技術分野・元請との関係・下請の階層によって大きく異なります。**
> 【Fact】**本資料では、適切な公的出典を確認できなかったため、単価の水準を数値で示していません**
> （19_sources.md §6）。

### (3) 何と一緒に見るか

| 一緒に見る数字 | なぜ一緒に見るか |
|---|---|
| **原価単価**（その技術者の人件費） | **差が粗利になる**。単価が高くても原価が高ければ意味がない |
| **稼働率** | **稼働率 × 単価**で売上が決まる。単価が高くても稼働していなければ売上はゼロ |
| **階層の位置**（直請けか下請か） | 12の12-3のとおり、階層を下るごとに単価は減る |
| **役割**（PM／SE／PG） | 役割によって単価が分かれる |

【Example】モデル企業の設定値：

```
  顧客への単価  78万円／人月（平均）
  自社要員の原価 52万円／人月
  ───────────────────────────
  粗利          26万円／人月（粗利率33.3%）

  協力会社への支払 58万円／人月
  ───────────────────────────
  協力会社を使った場合の粗利 20万円／人月（粗利率25.6%）
```

### (4) 単価は、簡単には上がらない

| なぜ上がりにくいか【Typical】 |
|---|
| **契約期間中は変えられない**（SESは【Typical】3か月単位で更新される） |
| **顧客との交渉が必要**。理由（実績・スキルの向上）を示す必要がある |
| **階層の位置に制約される**（12の12-3） |
| **単価を上げると、契約を打ち切られる可能性がある**【Varies】 |

> **本資料は、単価交渉の是非やその方法を扱いません。** 構造として上がりにくい、という事実を示しています。

## 14-7. ⑥ 売上／技術者1人あたり

### (1) 何を表す数字か

```
  技術者1人あたり売上 ＝ 売上高 ÷ 技術者の人数
```

【Example】モデル企業：

```
  4億5,000万円 ÷ 40名 = 1,125万円／人・年
```

### (2) なぜこの数字を見るのか

【Typical】この数字は、**稼働率 × 単価の結果**を1つの数字にまとめたものです。

```
  技術者1人あたり売上 ＝ 稼働率 × 平均単価 × 12か月 ＋ 協力会社による売上の寄与
```

| この数字が下がる原因 | 対応する数字 |
|---|---|
| 稼働率が下がった | ① 稼働率 |
| 単価が下がった | ⑤ 人月単価 |
| 協力会社を使わなくなった | 外注費 |

> **★注意：協力会社の技術者の売上も含まれます**
> 【Example】モデル企業の売上4億5,000万円のうち、9,000万円は協力会社の技術者による売上です（03の3-2）。
> **自社技術者40名だけで4億5,000万円を作っているわけではありません。**
> **【Varies】** この数字を会社間で比較するときは、**外注をどれだけ使っているか**を揃えないと比較になりません。

### (3) 管理部門を含めた数字も見る【Varies】

```
  従業員1人あたり売上 ＝ 4億5,000万円 ÷ 48名 = 937.5万円／人・年
```

| 誰が見るか | 社長 |
|---|---|
| **頻度** | **月次**／**年次** |

## 14-8. ⑨ 受注残

### (1) 何を表す数字か

**受注残（じゅちゅうざん）**
→ すでに契約が決まっていて、**まだ売上になっていない**仕事の金額のこと。「受注残高」とも言う。
→ 実務例：「受注残が1億2,000万円あります」＝
   「契約は済んでいるが、まだ作業中・未検収の仕事が1億2,000万円分ある」という意味。

```
  受注残 ＝ 契約済みの金額 − すでに売上計上した金額
```

### (2) なぜこの数字が重要なのか

```
  受注残 ＝ 「この先、確実に立つ売上」
        ＝ 「この先、確実にふさがる要員」
```

| 受注残から分かること | 内容 |
|---|---|
| **この先の売上の見通し** | 契約済みなので、【Typical】ほぼ確実に売上になる |
| **この先の要員の見通し** | その仕事をする人がふさがる |
| **★受注残が減ってきたら** | **この先、待機が出る**という予告になる |

> **★受注残と稼働率のつながり**
> ```
>   受注残が減る
>        ↓
>   案件が終わったあと、次の仕事がない
>        ↓
>   ★稼働率が下がる
>        ↓
>   ★売上が減り、利益がそのまま減る
> ```
> **だから、受注残は「稼働率の先行指標」として見られます**【Typical】。

### (3) 受注見込み（売上予測）と一緒に見る

| | **受注残** | **受注見込み（パイプライン）** |
|---|---|---|
| 何か | **契約済み**で未売上の金額 | **まだ契約していない**引合いの金額 |
| 確実性 | 【Typical】高い | 【Varies】確度によって異なる |
| どこで管理するか | 販売管理／表計算 | **案件管理表**（10の帳票1） |

【Typical】案件管理表では、引合いを**確度別**に分類して集計します。

| 確度の分類の例【Varies】 | 内容 |
|---|---|
| A | 内示が出ている／ほぼ決まっている |
| B | 提案中。競合がいる |
| C | 引合いを受けたばかり |

> **【Varies】** 分類の仕方と、確度ごとの掛け目（Aは80%で見る、など）は会社によって異なります。

| 誰が見るか | 社長／営業部長／要員管理機能 |
|---|---|
| **頻度** | **月次** |

## 14-11. ⑦ 採用人数

### (1) 何を表す数字か

## 14-15. 数字のつながり——1つが動くと何が動くか

### (1) 稼働率が下がったとき

```
  稼働率が下がる
     ├──▶ 売上が減る（人件費は減らない）──▶ 利益が減る
     ├──▶ 待機人数が増える ──▶ 営業が案件を探す
     ├──▶ 受注残が減っていたことが原因かもしれない ──▶ 営業活動を見直す
     └──▶ 【Varies】採用を止める判断につながることもある
```

### (2) 工数超過率が上がったとき

```
  工数超過率が上がる
     ├──▶ プロジェクト別粗利が下がる ──▶ 会社全体の粗利率が下がる
     ├──▶ 協力会社の投入が増える ──▶ 外注費が増える ──▶ さらに粗利が下がる
     ├──▶ その要員が次の案件に移れない ──▶ ★次の案件のアサインがずれる
     └──▶ 振り返りで原因を分類 ──▶ 次の見積のバッファを見直す
```

### (3) 離職が出たとき

```
  技術者が1名退職する
     ├──▶ 常駐案件なら、交代要員の手配が必要 ──▶ 社内で出せなければ協力会社へ
     ├──▶ 引き継ぎ期間は2名分の人件費 ──▶ その案件の粗利が下がる
     ├──▶ 要員数が減る ──▶ 売上の上限が下がる
     └──▶ 採用が必要になる ──▶ 採用費が発生する
```

### (4) 受注残が減ったとき

```
  受注残が減る
     ├──▶ この先、案件が終わったあとの仕事がない
     ├──▶ ★1〜2か月後に稼働率が下がる（先行指標）
     └──▶ 営業活動を強める／単価を下げてでも受ける判断【Varies】
```

## 14-16. この章のまとめ

### 情報通信業のKPIで押さえるべき9点

1. **★稼働率がもっとも重要な数字。**
   **売上＝人数 × 稼働率 × 単価 × 期間**のうち、短期間で動かせるのは稼働率だけです。

2. **★稼働率1%は、【Example】モデル企業で年374万円の売上。**
   人件費は減らないので、**そのまま利益から消えます。**

3. **ただし、稼働率100%は「余力がゼロ」を意味する。**
   本資料は、適切な水準の評価を行いません。

4. **★見積工数と実績工数の差が、請負の利益そのもの。**
   契約金額は固定なので、超過分は原価だけが増えます。

5. **案件の途中では「工数消化率」と「進捗」を突き合わせる。**
   「進捗50%なのに工数消化率80%」が、危険を知らせる形です。

6. **プロジェクト別粗利を出すには、3つのデータが要る。**
   契約金額（契約書）・実績工数（技術者の入力）・原価単価（給与データ）。
   **別々の場所にあるため、月次で突き合わせます。**

7. **受注残は、稼働率の先行指標。**
   受注残が減ると、1〜2か月後に待機が出ます。

8. **採用人数は、離職率とセットで見る。**
   **純増数が、売上の上限を動かします。**

9. **★人月単価・稼働率・離職率・不具合件数の水準は示していない。**
   公的な出典を確認できなかったため（19_sources.md §6）、本資料では【Varies】としています。
   **本ファイルの数値はすべて説明用の架空の設定値【Example】です。**

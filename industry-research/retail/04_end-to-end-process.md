# 04_end-to-end-process.md — 小売業の全社End-to-End業務フロー

> 本ファイルは、`03_company-structure.md` で設定したモデル企業
> **X食品スーパー株式会社（4店舗／年商約30億円）** を舞台に、
> 「商品が入ってきて、売れて、仕入代金を払うまで」の全体の流れを追います。

---

## 4-0 【最初に】小売業のフローは「受注→納品→請求→入金」ではない

### 他業界との決定的な違い

多くのBtoB業界（製造業・卸売業・建設業など）の業務フローは、次の形をしています。

```
  引合 → 見積 → 受注 → 生産／手配 → 納品 → 検収 → 請求 → 入金
   ↑                                                      ↑
   お客さまから注文をもらってから動く                    お金は後日入る
```

**小売業はこの形をしていません。** 小売業の基本形はこうです。

```
  仕入（先にお金を払う約束をして商品を持つ） → 陳列（並べる）
                    → 販売（お客さまが選ぶ） → 即時決済（その場でお金を受け取る）
   ↑                                                      ↑
   お客さまが来る前に、売れるかどうか分からない商品を       お金はその場で入る
   自分の判断で仕入れて持っておく
```

### この違いが生む3つの帰結

| # | 小売業の特徴 | なぜそうなるか | 業務への影響 |
|---|---|---|---|
| 1 | **「受注」という工程が存在しない** | 注文を受けてから商品を用意するのではなく、先に商品を並べておく | 売上は「注文書」ではなく**レジの記録（POSデータ）**から生まれる |
| 2 | **「請求」「回収」という工程が（原則）存在しない** | その場で代金を受け取るため | 売掛金の管理・督促という業務が原則ない。代わりに**現金管理**と**キャッシュレス決済の入金管理**が発生する |
| 3 | **需要予測の責任が完全に小売側にある** | 誰が何を買いに来るか分からないまま仕入れる | **発注が最重要業務**になる。発注を誤れば、欠品（売り逃し）か過剰在庫（ロス）のどちらかが必ず起きる |

> **ここを理解しないと、小売業の会話についていけません。**
> 小売業の人が「**今日の数字**」と言うとき、それは「今日レジを通った金額」のことです。
> 製造業の人が「今月の受注」と言うのとは、指しているものがまったく違います。

### 小売業では2つのサイクルが同時に走っている

小売業のフローは、**1本の線ではなく2本の線**として理解する必要があります。
この2本は**起点は同じ（発注）ですが、時間軸がまったく違います。**

```
╔══════════════════════════════════════════════════════════════════════╗
║  A. モノと売上のサイクル  ── 早い（数日〜数週間で完結）                  ║
║     商品計画 → 発注 → 入荷 → 検品 → 検収 → 値付け → 陳列              ║
║       → 販売（レジ）→ ★即時入金★ → 補充 → 見切り → 廃棄 → 棚卸        ║
╚══════════════════════════════════════════════════════════════════════╝
                              ▲
                  同じ「発注」から枝分かれする
                              ▼
╔══════════════════════════════════════════════════════════════════════╗
║  B. 仕入と支払のサイクル  ── 遅い（1〜2か月かかる）                     ║
║     発注 → 入荷 → 仕入計上 → ★締め★ → 請求書照合 → 買掛金計上          ║
║       → ★支払★                                                       ║
╚══════════════════════════════════════════════════════════════════════╝
```

**この2本の時間差が、小売業のお金の流れの正体です。**（詳細は 4-3）

## 4-1 【サイクルA】商品が入ってきて売れるまで（モノと売上のサイクル）

### 全体図

```
 ┌──────────┐
 │ A-1 商品計画 │ 何を置くか・いくらで売るかを決める
 └──────────┘
        ▼
 ┌──────────┐
 │ A-2 発注    │ ★最重要工程★ いくつ仕入れるかを決める
 └──────────┘
        ▼
 ┌──────────┐   ┌──────────┐   ┌──────────┐
 │ A-3 入荷・荷受│→│ A-4 検品    │→│ A-5 検収    │ ここで仕入が確定する
 └──────────┘   └──────────┘   └──────────┘
        ▼
 ┌──────────┐   ┌──────────┐
 │ A-6 値付け   │→│ A-7 陳列    │ 売れる状態にする
 └──────────┘   └──────────┘
        ▼
 ┌──────────┐
 │ A-8 販売    │ ★レジ／即時決済★  ← ここで初めて売上が立つ
 └──────────┘
        ▼
 ┌──────────┐   ┌────────────┐   ┌──────────┐
 │ A-9 補充    │→│ A-10 売価変更・│→│ A-11 廃棄  │ 売り切る／処分する
 │            │   │    見切り     │   │    ロス処理 │
 └──────────┘   └────────────┘   └──────────┘
        ▼
 ┌────────────────┐   ┌──────────────┐
 │ A-12 レジ締め・売上金管理│→│ A-13 入金（銀行）│ その日のお金を確定させる
 └────────────────┘   └──────────────┘
        ▼
 ┌──────────┐
 │ A-14 棚卸   │ 実際の在庫を数え、帳簿と突き合わせる
 └──────────┘
```

### 各ステップの詳細

#### A-1 商品計画（品揃えと売価方針の決定）

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 新商品の案内を受けたとき／季節の切り替わり／定番の見直し時期／売れ行きが落ちた商品の入れ替え検討時 |
| **誰が行うか** | 商品調達機能（X社では**社長**）＋生鮮は各店の売場担当（部門チーフ） |
| **何を受け取るか（インプット）** | メーカー・卸売業者からの新商品案内、売上・粗利・在庫の実績データ、競合店の売価情報、季節・行事のカレンダー |
| **何を確認するか** | その商品は自店の客層に合うか／既存商品と重ならないか／仕入価格と想定売価で狙う粗利が取れるか／置く場所（棚・フェイス）があるか |
| **何をするか** | 取り扱う品目（SKU）を決める。仕入先を決める。**定番売価を決める（＝値入を決める）**。棚のどこに何フェイス置くかを決める |
| **何を判断するか** | 新規採用するか／既存品を外すか（カット）／売価をいくらにするか |
| **誰と連携するか** | 仕入先（卸・メーカー）、店長、売場担当 |
| **最終的に何ができあがるか** | **取扱商品リスト（マスタ）**、**定番売価**、**棚割（たなわり）** |
| **頻度** | 月次／季節の変わり目（＝その他）／案件発生時 `【Varies】` |

> **棚割（たなわり）**
> → 棚のどこに、どの商品を、何フェイス並べるかを決めた設計図のこと。
> → 実務例：「この3段目の左から、しょうゆA・しょうゆB・しょうゆC」と決めておくことで、
>   誰が補充しても同じ売場が再現されます。**棚割がないと、人が替わるたびに売場が変わってしまいます。**

> **値入（ねいれ）を決めるとはどういうことか**
> `【Example】`（説明用の架空例）仕入価格120円の豆腐に売価168円を付ければ、
> 値入額48円、値入率28.6％。この時点ではまだ「**予定**」です。
> 実際には一部が値下げ・廃棄になるため、最終的な粗利率はこれより低くなります（`01_overview.md` 1-5）。

#### A-2 発注 ★小売業で最も重要な工程★

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 発注サイクルの到来（仕入先ごとの発注締め時刻）／在庫が補充点を下回ったとき／特売の決定時／季節商戦の準備時 |
| **誰が行うか** | **売場担当（部門チーフ）**が部門ごとに行う。特売・大量仕入は商品調達機能（社長）が判断 |
| **何を受け取るか（インプット）** | 現在の在庫数、直近の販売実績、天気予報、曜日・行事、特売計画（チラシ内容）、仕入先の在庫・相場情報、前年同時期の実績 |
| **何を確認するか** | 今ある在庫で、次の納品まで持つか／売価と仕入価格から狙う粗利が取れるか／売場に置ききれる量か／賞味期限・消費期限内に売り切れる量か |
| **何をするか** | 発注端末・FAX・電話・Web発注等で、**品目ごとに数量を入力して送信**する `【Varies】` |
| **何を判断するか** | **いくつ発注するか。** 多ければロス、少なければ欠品。判断を誤ると必ずどちらかの損失が出る |
| **誰と連携するか** | 仕入先（卸売業者・メーカー・仲卸）、店長（大口の場合） |
| **最終的に何ができあがるか** | **発注データ（発注情報）**／発注書 |
| **頻度** | **日次**（生鮮・日配）／週次（グロサリー等）／発注時（季節品） `【Varies】`（品目・仕入先により異なる） |

> **なぜ発注が最重要なのか**
> `【Inference】` 小売業の粗利は、発注した瞬間にほぼ決まってしまうからです。
> - 発注が多すぎた → 値下げして売るか、捨てる → **粗利が減る**
> - 発注が少なすぎた → 売る商品がない → **売上そのものが立たない**
>
> 陳列や接客をどれだけ工夫しても、**発注量の誤りは取り返せません**。
> だから小売業では、パート・アルバイトではなく**正社員の部門チーフが発注を担う**のが
> 一般的です `【Typical】`。

> **定番発注と特売発注の違い**
>
> | | **定番発注** | **特売発注** |
> |---|---|---|
> | 目的 | 棚を切らさない（欠品させない） | 特売期間中に売る量を確保する |
> | 数量の決め方 | **売れた分を補充する**（実績ベース） | **これだけ売ると決めて確保する**（計画ベース） |
> | 判断者 | 売場担当 | 商品調達機能（社長）＋店長 |
> | 誤ったときのリスク | 欠品または棚の在庫過多 | **大量の売れ残り**（特売価格で大量に仕入れているため損失が大きい） |
> | 頻度 | 日次〜週次 | 特売企画ごと（＝発注時） |

#### A-3 入荷・荷受

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 納品トラックの到着（納品時） |
| **誰が行うか** | **バックヤード機能**（荷受担当）。小規模店では売場担当や店長が兼務 `【Typical】` |
| **何を受け取るか（インプット）** | 商品（現物）、**納品書（伝票）** |
| **何を確認するか** | 自店宛の荷か／便・仕入先は合っているか／外装に破損・汚損はないか／**冷蔵・冷凍品の温度**は適切か |
| **何をするか** | 荷受場で商品を受け取り、温度帯ごとに仮置きする（冷蔵品は速やかに冷蔵庫へ） |
| **何を判断するか** | その場で受け取れるか／破損があれば受け取らずに返すか |
| **誰と連携するか** | 配送ドライバー、仕入先 |
| **最終的に何ができあがるか** | 荷受済みの商品、納品書（未照合） |
| **頻度** | **日次**（複数便） `【Varies】` |

> `【Typical】` 冷蔵・冷凍品は、荷受から保管までの時間が品質に直結します。
> 「トラックが着いたらすぐに冷蔵庫へ入れる」という単純な作業が、
> **鮮度の維持＝ロスの削減**に直結している点が、小売業の現場の特徴です。

---

#### A-4 検品

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 荷受の完了（納品時） |
| **誰が行うか** | バックヤード機能（検品担当）／売場担当 |
| **何を受け取るか（インプット）** | 商品（現物）、納品書、発注データ |
| **何を確認するか** | **発注した品番・数量と、届いた現物が一致しているか**／賞味期限・消費期限は十分か／品質（傷み・変色・破損）は問題ないか／規格（サイズ・等級）は合っているか |
| **何をするか** | 伝票と現物を1品ずつ突き合わせる。差異があれば記録する |
| **何を判断するか** | 受け入れるか／**返品するか**／数量違いを仕入先に連絡するか |
| **誰と連携するか** | 仕入先（差異があった場合）、売場担当 |
| **最終的に何ができあがるか** | **検品結果**（差異リスト／返品伝票） |
| **頻度** | **日次**（納品の都度＝納品時） |

> **なぜ検品が必要なのか**
> `【Inference】` 検品を省略すると、**「届いていない商品の代金を払う」**ことになります。
> また、期限の短い商品を受け取ってしまうと、それはそのまま廃棄ロスになります。
> 検品は「商品を確認する作業」であると同時に、**支払金額を確定させる作業**でもあります。

---

#### A-5 検収（仕入の確定）

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 検品の完了（納品時） |
| **誰が行うか** | バックヤード機能／店長（責任者として確認） |
| **何を受け取るか（インプット）** | 検品結果、納品書 |
| **何を確認するか** | 最終的に受け入れる数量・金額／返品分が控除されているか |
| **何をするか** | 受け取りを確定させ、納品書に受領印等を押す。**仕入データとして登録**する |
| **何を判断するか** | この内容で仕入計上してよいか |
| **誰と連携するか** | 経理・財務機能（データが渡る）、仕入先 |
| **最終的に何ができあがるか** | **仕入計上データ（仕入情報）**、受領済み納品書 |
| **頻度** | **日次**（納品時） |

> ★ **ここがサイクルBの起点でもあります。**
> 検収した瞬間に、「この商品はX社のもの（買取仕入の場合）」になり、
> 同時に「この金額を仕入先に払う義務」が発生します。
> **モノを受け取ることと、支払義務が生まれることは同じ出来事です。**

> **初心者が間違えやすい点：発注 ≠ 仕入計上**
> 注文しただけでは仕入にはなりません。**モノを受け取って検収した時点**で仕入が立ちます。
> 発注した翌日にキャンセルすれば、仕入は発生しません。

---

#### A-6 値付け（プライスカードと値札）

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 検収の完了／売価の変更決定時 |
| **誰が行うか** | 売場担当（部門チーフ）。生鮮・惣菜は**加工・パック詰めと一体**で行う |
| **何を受け取るか（インプット）** | 検収済み商品、定番売価（A-1で決定）、特売売価（販促企画で決定）、仕入価格 |
| **何を確認するか** | 売価は決められたとおりか／**仕入価格が変わっていないか**（変わっていれば売価の見直しが要る）／競合店の売価 |
| **何をするか** | 値札・プライスカードを作成し、商品または棚に付ける。生鮮・惣菜は**計量してラベル（重量・単価・売価・消費期限）を発行**する |
| **何を判断するか** | 定番売価のままでよいか／仕入価格の変動を売価に反映するか |
| **誰と連携するか** | 商品調達機能（売価変更が必要な場合）、店長 |
| **最終的に何ができあがるか** | **値札・プライスカード付きの商品**、**売価情報** |
| **頻度** | **日次** |

> `【Typical】` 生鮮食品の値付けは、加工とセットで行われます。
> 例えば魚1匹を三枚におろして2パックに分ける場合、
> **その場で重量を量り、単価を掛けて売価を計算し、消費期限を印字したラベルを貼る**、
> という一連の作業になります。
> ここで「1パックあたりいくらにするか」を誤ると、**そのまま粗利がずれます**。

#### A-7 陳列（売場への展開）

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 値付けの完了／開店前の売場作り／特売初日の売場切り替え |
| **誰が行うか** | 売場担当、パート・アルバイト |
| **何を受け取るか（インプット）** | 値付け済みの商品、棚割、特売の売場計画、POP |
| **何を確認するか** | 棚割どおりの位置か／**先入先出（さきいれさきだし）**になっているか／前面に商品が並んでいるか／POPと売価が一致しているか |
| **何をするか** | 定番棚・エンド・平台に商品を並べる。POPを付ける。前出し（商品を手前に引き出す）をする |
| **何を判断するか** | どこにどれだけ積むか／売れ行きを見て場所を変えるか |
| **誰と連携するか** | 店長、販促・販売企画機能 |
| **最終的に何ができあがるか** | **販売可能な売場** |
| **頻度** | **日次**（開店前・随時）／特売の切り替え時 |

> **先入先出（さきいれさきだし）**
> → **先に入荷した（期限が近い）商品から先に売る**ように並べること。
> → 実務例：牛乳を補充するとき、新しい商品を奥に入れ、古い商品を手前に出します。
>   逆にすると古い商品が奥に残り続け、**期限切れ＝廃棄ロス**になります。
>   単純な作業に見えますが、これを徹底するかどうかでロス率が変わります `【Inference】`。

---

#### A-8 販売（レジ・即時決済）★売上が成立する瞬間★

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | お客さまがレジに来たとき（＝問い合わせ時／その他） |
| **誰が行うか** | **レジ・接客機能**（レジ担当。多くがパート・アルバイト） |
| **何を受け取るか（インプット）** | 商品（お客さまが選んだもの）、代金または決済手段（現金・カード・コード決済・電子マネー・商品券） |
| **何を確認するか** | 商品のバーコードが正しく読めたか／年齢確認が必要な商品（酒・たばこ）か／**受け取った金額**／ポイントカードの有無／クーポンの適用可否 |
| **何をするか** | 商品を登録し、合計金額を提示し、決済を処理し、**レシートを発行**して商品を渡す |
| **何を判断するか** | 決済手段ごとの処理／値引・返品の可否（判断が難しい場合は店長へ） |
| **誰と連携するか** | 店長（イレギュラー時）、決済事業者（システム上） |
| **最終的に何ができあがるか** | **売上データ（POSデータ）**、レシート、**現金または決済の記録** |
| **頻度** | **常時**（営業時間中） |

> **POS（ピーオーエス／Point of Sale：販売時点情報管理）**
> → レジで商品を登録した瞬間に、「何が・いつ・いくらで・何個売れたか」を記録する仕組みのこと。
> → 実務例：レジでバーコードを読むと、売上が計上されると同時に、
>   その商品の在庫が1減り、翌日の発注判断の材料になります。
>   **POSは「レジ」であると同時に「売上と在庫の記録装置」**です。

> ★ **他業界との最大の違いがここ。**
> 製造業・卸売業では、納品してから請求書を出し、翌月以降に入金されます。
> 小売業は**この瞬間に売上が立ち、同時に代金を受け取ります**。
> 「請求」「回収」「督促」という工程が、原則として存在しません。

##### 決済手段によって「いつ現金になるか」が違う

`【Typical】` 「即時決済」と言っても、**実際に会社の口座にお金が入るタイミングは決済手段で異なります。**
ここは初心者が必ず誤解する点です。

| 決済手段 | レジでの処理 | **実際に会社の口座に入るタイミング** | 手数料 |
|---|---|---|---|
| **現金** | その場で受け取る | **即時**（ただし銀行に預け入れるまで社内で保管する必要がある） | なし |
| **クレジットカード** | 端末で承認を取る | **後日**。カード会社から締めて入金される `【Varies】` | **決済手数料が引かれる** `【Varies】` |
| **電子マネー・コード決済** | 端末で処理 | **後日**。決済事業者から締めて入金される `【Varies】` | **決済手数料が引かれる** `【Varies】` |
| **商品券・ギフトカード** | 券を受け取る | **後日**。発行会社に請求して回収する `【Varies】` | 換金手数料が発生する場合がある `【Varies】` |

`【Fact】` 日本のキャッシュレス決済比率は2023年に39.3％に到達しました
（出典：キャッシュレス・ロードマップ2024／一般社団法人キャッシュレス推進協議会、2024年12月）。

`【Fact】` 食品スーパーの**現金以外の決済手段の導入率は95.6％**（2024年、業界推計値。
出典：2024年スーパーマーケット年次統計調査報告書）。

> `【Inference】` つまり現在の小売業では、
> **「売上は今日立つが、その一部のお金は数日〜1か月後にしか入ってこない」**状態が常態です。
> 「小売業は現金商売だから資金繰りが楽」という理解は、キャッシュレス比率の上昇により
> かつてより当てはまりにくくなっています。
> この入金タイムラグは `08_money.md` `12_business-model.md` で詳しく扱います。

#### A-10 売価変更・見切り（値下げ）

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 期限が迫ったとき／閉店が近づいたとき／売れ行きが計画を下回ったとき／シーズンが終わるとき／仕入価格が変わったとき |
| **誰が行うか** | 売場担当。値下げ幅の大きい判断は店長 `【Typical】` |
| **何を受け取るか（インプット）** | 残り在庫数、消費期限・賞味期限、残り営業時間、当日の客数の出方、部門の粗利進捗 |
| **何を確認するか** | この価格で売り切れるか／いつから何％引くか／部門の粗利への影響 |
| **何をするか** | 値下げシールを貼る／POSの売価を変更する／売場の表示を変える |
| **何を判断するか** | **「今いくら下げれば売り切れるか」。** 下げすぎれば粗利を失い、下げ足りなければ廃棄になる |
| **誰と連携するか** | 店長、レジ（変更後の売価が正しく通るか） |
| **最終的に何ができあがるか** | **売価変更情報**、**値下げロスの記録** |
| **頻度** | **日次**（惣菜・生鮮）／シーズン末（衣料・季節品）＝その他 |

> **見切り（みきり）**
> → 売れ残りそうな商品を、**期限内に売り切るために値下げする**こと。
> → 実務例：閉店2時間前に惣菜を3割引、1時間前に半額にする。
>   「値引き」と呼ぶこともありますが、実務では「見切る」「見切り品」という言い方をよくします。

> **なぜ見切るのか — 廃棄との比較**
> `【Example】`（説明用の架空例）原価400円・売価600円の弁当が1個残っている。
> - 半額300円で売る → 300円の現金が入る。粗利は▲100円（原価割れ）だが、**300円は回収できる**
> - 捨てる → 0円。**原価400円がまるごと損失**
>
> つまり見切りは「損を確定させる行為」ではなく、**「損を小さくする行為」**です。
> 一方で、見切りを早く始めすぎると、**定価で買うはずだった客まで値下げ品を待つ**ようになり、
> 全体の粗利が下がります `【Inference】`。
> **「いつから、いくら下げるか」が、惣菜・生鮮の粗利を左右する日々の判断**になります。

#### A-11 廃棄ロス処理

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 消費期限・賞味期限の到来／品質の劣化／破損 |
| **誰が行うか** | 売場担当、パート・アルバイト |
| **何を受け取るか（インプット）** | 期限切れ・品質不良の商品 |
| **何を確認するか** | 本当に販売できないか／**廃棄数量と金額** |
| **何をするか** | 売場から撤去し、**廃棄として登録（ロス計上）**し、廃棄物として処理する |
| **何を判断するか** | 廃棄するか／値下げで売り切るか（A-10に戻す判断） |
| **誰と連携するか** | 店長、経理・財務機能（ロス金額の集計）、廃棄物処理業者 |
| **最終的に何ができあがるか** | **廃棄ロスの記録（ロス情報）**、廃棄物 |
| **頻度** | **日次** |

> **なぜ廃棄を「登録」するのか**
> `【Inference】` 捨てるだけなら記録は要らないように見えますが、記録しないと次の3つができません。
> 1. **在庫数が合わなくなる**（帳簿上は残っているのに現物がない → 不明ロスに化ける）
> 2. **粗利が正しく計算できない**（なぜ粗利率が計画より低いのか分からなくなる）
> 3. **次の発注を直せない**（どの商品がいくつ余っているのか分からない）
>
> `【Fact】` 食品スーパーの商品カテゴリー別廃棄率（金額ベース、2024年）は
> 惣菜2.4％、水産2.2％、青果1.3％、畜産1.2％、日配品1.0％、一般食品0.6％、非食品0.4％
> （出典：2024年スーパーマーケット年次統計調査報告書）。

#### A-12 レジ締め・売上金管理（日次の締め）

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 閉店時／レジ担当者の交替時 |
| **誰が行うか** | レジ・接客機能（レジ担当）＋**店長（責任者として確認）** |
| **何を受け取るか（インプット）** | レジ内の現金、POSの売上記録、決済端末の記録、釣銭準備金の額 |
| **何を確認するか** | **POSが示す現金売上の金額と、レジ内の実際の現金が一致するか**／決済手段別の内訳／返品・取消の内容 |
| **何をするか** | レジを精算する。現金を数える。差異があれば原因を調べる。売上金と釣銭準備金を分け、金庫に保管する |
| **何を判断するか** | 差異の原因（釣銭の渡し間違い／登録ミス／未記録の入出金）／原因不明の場合の処理 |
| **誰と連携するか** | 店長、経理・財務機能 |
| **最終的に何ができあがるか** | **日報（売上報告）**、**現金過不足の記録**、金庫に保管された売上金 |
| **頻度** | **日次**（レジごと／閉店時） |

> **レジ締め（レジ精算）**
> → その日（またはその担当時間）のレジの記録と、実際の現金を突き合わせる作業のこと。
> → 実務例：POSが「本日の現金売上は85万円」と示し、レジの引き出しには釣銭準備金5万円＋
>   売上金が入っている。数えて85万円ちょうどなら一致、84万9,000円なら1,000円の不足です。

> **なぜ毎日締めるのか**
> `【Inference】` 現金は、誰の手を経たか記録が残らない資産です。
> 日をまたぐと、差異が出たときに**どの取引でずれたのかが追えなくなります**。
> **その日のうちに突き合わせる**ことで、原因の追跡範囲を1日分に限定できます。
> これが小売業で「日次の締め」が必須になる理由です。

> **現金管理が小売業特有の業務である理由**
> `【Typical】` BtoBの業界では、代金は振込で入るため、現物の現金を扱う場面はほとんどありません。
> 小売業は**毎日、多額の現金が物理的に店舗に存在する**業種です。したがって、
> - **釣銭準備金**を毎朝用意する（銀行から両替して確保する）
> - 売上金を金庫で保管する
> - 銀行へ入金（預け入れ）する、または集金を依頼する
> - 盗難・紛失に備えた管理ルールを定める
>
> といった、**現金そのものを扱う業務**が日次で発生します。

|---|---|
| **何をきっかけに始まるか** | レジ締めの完了／翌営業日の開店前 |
| **誰が行うか** | 店長または指名された担当者／経理・財務機能 |
| **何を受け取るか（インプット）** | 金庫の売上金、日報 |
| **何を確認するか** | 日報の金額と持ち出す現金が一致するか |
| **何をするか** | 銀行へ売上金を預け入れる（または夜間金庫・集金サービスを利用する） `【Varies】` |

#### A-14 棚卸（たなおろし）

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 決算期末／月次の締め／期中の定期実施 `【Varies】` |
| **誰が行うか** | 店長・売場担当・パート・アルバイト（全員で実施することが多い）`【Typical】` |
| **何を受け取るか（インプット）** | 帳簿上の在庫数（理論在庫）、棚卸表、カウント用の端末・用紙 |
| **何を確認するか** | **売場とバックヤードにある商品の実際の数量**（実在庫） |
| **何をするか** | 全商品を数える。数量と売価（または原価）を記録する。理論在庫と突き合わせる |
| **何を判断するか** | 差異の原因（記録漏れ・不明ロス）／在庫評価額の確定 |
| **誰と連携するか** | 経理・財務機能、税理士 `【Varies】` |
| **最終的に何ができあがるか** | **実在庫データ**、**在庫金額**、**不明ロスの金額** |
| **頻度** | **年次**（決算時は必須）／月次・四半期に実施する企業もある `【Varies】` |

> **棚卸をなぜするのか**
> `【Inference】` 2つの理由があります。
>
> **① 正しい粗利を計算するため。**
> 小売業の売上原価は、次の式で計算します。
> ```
> 売上原価 ＝ 期首在庫 ＋ 期中の仕入 − 期末在庫
> ```
> **期末在庫の金額が分からないと、売上原価が計算できず、粗利も利益も出せません。**
> 期末在庫を確定させる唯一の方法が、実際に数えること＝棚卸です。
>
> **② 不明ロスを把握するため。**
> 「帳簿では100個あるはずが、数えたら97個しかなかった」——この3個が不明ロスです。
> 万引き、レジの登録ミス、廃棄の登録漏れ、納品数量の誤りなどが原因ですが、
> **棚卸をしない限り、そもそも「合っていないこと」に気づけません。**

> **初心者が間違えやすい点：在庫 ≠ すべてが売れる商品**
> 棚卸で数えた在庫の中には、期限が迫ったもの、シーズンが終わったもの、
> 傷んで売り物にならないものも含まれます。
> **「在庫が○円ある」ことと「○円で売れる」ことは別**です。

## 4-2 【サイクルB】仕入先へ支払うまで（仕入と支払のサイクル）

サイクルAが「数日で一周する速い流れ」なのに対し、
サイクルBは**「1〜2か月かけて一周する遅い流れ」**です。

```
 ┌──────────┐
 │ B-1 発注    │ ← A-2と同じ出来事
 └──────────┘
        ▼
 ┌──────────┐
 │ B-2 入荷・検収│ ← A-3〜A-5と同じ出来事
 └──────────┘
        ▼
 ┌──────────┐
 │ B-3 仕入計上 │ 「払う義務」が会計上確定する
 └──────────┘
        ▼
 ┌──────────┐
 │ B-4 締め     │ ★1か月分（または半月分）を区切る★
 └──────────┘
        ▼
 ┌──────────────┐
 │ B-5 請求書の受領・照合 │ 請求額が正しいか突き合わせる
 └──────────────┘
        ▼
 ┌──────────┐
 │ B-6 買掛金計上│ 支払うべき金額が確定する
 └──────────┘
        ▼
 ┌──────────┐
 │ B-7 支払     │ ★実際にお金が出ていく★
 └──────────┘
```

### 各ステップの詳細

#### B-3 仕入計上

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 検収の完了（A-5） |
| **誰が行うか** | 店舗（検収データの登録）→ 経理・財務機能 |
| **何を受け取るか（インプット）** | 検収済みの納品書、仕入データ |
| **何を確認するか** | 品目・数量・単価・金額／仕入先ごとの計上区分 |
| **何をするか** | 仕入として会計上記録する。仕入先別に積み上げていく |
| **何を判断するか** | 買取仕入か・委託／消化仕入か（**消化仕入は売れた時点で計上**するため、ここでは計上しない） |
| **誰と連携するか** | 店舗、仕入先 |
| **最終的に何ができあがるか** | **仕入データ（仕入先別・日別）** |
| **頻度** | **日次**（納品時） |

#### B-4 締め（しめ）

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 仕入先との契約で定めた締め日の到来（＝法定・契約上のタイミング） |
| **誰が行うか** | 経理・財務機能／仕入先（仕入先側も同じ日で締める） |
| **何を受け取るか（インプット）** | 締め日までの仕入データ |
| **何を確認するか** | 締め日までの取引がすべて計上されているか／返品・値引が反映されているか |
| **何をするか** | 期間を区切り、仕入先ごとの取引金額を集計する |
| **何を判断するか** | 締め日をまたぐ取引の帰属（どちらの期間に入れるか） |
| **誰と連携するか** | 仕入先 |
| **最終的に何ができあがるか** | **締め後の仕入先別取引金額** |
| **頻度** | **月次**（月に1回が一般的。月2回以上の場合もある `【Varies】`） |

> **締め（しめ）**
> → 継続的な取引について、**一定期間の取引をまとめて1本の請求・支払にする**ための区切りのこと。
> → 実務例：毎日何回も納品を受けても、その都度お金を払うのは双方にとって手間です。
>   そこで「月末で区切って、その1か月分をまとめて請求する」と決めておきます。
>   この区切りの日を**締め日**といいます。

> **なぜ締めるのか**
> `【Inference】` 小売業は取引回数が極端に多い業種です。
> 1つの卸売業者から毎日納品を受ければ、月に30回近い取引になります。
> これを1件ずつ支払っていては、双方の事務負担が膨大になります。
> **締めは、多数の取引を1本にまとめるための仕組み**です。

#### B-5 請求書の受領・照合

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 仕入先からの請求書の到着（＝請求時） |
| **誰が行うか** | 経理・財務機能（X社では事務担当） |
| **何を受け取るか（インプット）** | **請求書**、自社の仕入データ（検収ベース） |
| **何を確認するか** | **請求金額と自社の仕入計上額が一致しているか**／単価は取り決めどおりか／返品・値引・リベート（販売奨励金）が反映されているか／期間（締め期間）は合っているか |
| **何をするか** | 請求書と自社データを1件ずつ突き合わせる。差異があれば仕入先に問い合わせる |
| **何を判断するか** | この金額で支払ってよいか／保留して確認するか |
| **誰と連携するか** | 仕入先、店舗（検収内容の確認） |
| **最終的に何ができあがるか** | **照合済みの請求書**、差異の問い合わせ記録 |
| **頻度** | **月次**（請求時） |

> **なぜ照合するのか**
> `【Inference】` 請求書の金額が常に正しいとは限りません。
> 返品したはずの商品が請求に含まれている、特売で下げたはずの単価が通常単価で計算されている、
> といったことは実務上起こり得ます。
> **A-4の検品が「モノの正しさ」を守る工程なら、B-5の照合は「金額の正しさ」を守る工程**です。
> この2つがあって初めて、払うべき金額だけを払うことができます。

#### B-6 買掛金計上

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 請求書の照合完了 |
| **誰が行うか** | 経理・財務機能 |
| **何を受け取るか（インプット）** | 照合済み請求書 |
| **何を確認するか** | 支払期日／支払方法（振込・手形等） `【Varies】` |
| **何をするか** | **買掛金**（仕入先に支払う義務のある金額）として記録し、支払予定に組み込む |
| **何を判断するか** | 支払期日と資金繰りの照合 |
| **誰と連携するか** | 社長（資金繰りの判断） |
| **最終的に何ができあがるか** | **買掛金残高**、**支払予定表** |
| **頻度** | **月次** |

> **買掛金（かいかけきん）**
> → 商品を仕入れたが、まだ代金を払っていない金額のこと。
> → 実務例：11月中に1,800万円分を仕入れ、支払いは12月末という場合、
>   11月末時点で1,800万円の買掛金があります。
>   **「商品はもう店にあり、売れているのに、まだ払っていないお金」**です。

#### B-7 支払

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 支払期日の到来（＝法定・契約上のタイミング） |
| **誰が行うか** | 経理・財務機能。実行の承認は社長 |
| **何を受け取るか（インプット）** | 支払予定表、口座残高、資金繰り表 |
| **何を確認するか** | **口座に十分な残高があるか**／振込先・金額は正しいか |
| **何をするか** | 銀行振込等で支払う `【Varies】` |
| **何を判断するか** | 資金が不足する場合の手当（借入・支払時期の相談など） |
| **誰と連携するか** | 仕入先、金融機関 |
| **最終的に何ができあがるか** | **支払記録**、買掛金の消込（残高が減る） |
| **頻度** | **月次**（法定・契約上のタイミング） |

## 4-3 【重要】キャッシュの時間差 — 小売業のお金の基本構造

### サイクルAとサイクルBを重ねて見る

```
   日数 →  1日目        5日目            30日目           60日目
           │            │                │                │
  【A】 仕入→陳列→販売→★入金（即日〜数日）★
           ●━━━━━━━━●
           商品を受け取る  売れてお金が入る

  【B】 仕入計上 ────────── 締め ────────── 請求書 ─── ★支払★
           ●───────────────●──────────────●──────────●
           払う義務が発生     期間を区切る    金額確定    お金が出ていく
```

### 小売業の基本構造：「先に入って、後から出ていく」

`【Typical】` 小売業では、多くの場合**お金は先に入り、支払いは後**になります。

- **入り**：商品が売れた日に（現金なら即日、キャッシュレスなら数日〜1か月後）入金される
- **出**：仕入代金は、締めてから請求書が来て、翌月以降に支払う

> `【Example】`（説明用の架空例）
> X社が11月10日に卸売業者Yから100万円分を仕入れ、11月中に全部売れたとする。
> - **売上（現金分）は11月中に手元に入る。**
> - **仕入代金100万円の支払いは、11月末締め・翌月末払いなら12月末。**
>
> つまり**約1か月半、商品の代金を払わないまま、売上代金だけが手元にある**状態になります。

`【Inference】` この構造は、小売業が比較的少ない運転資金で事業を回せる理由の一つです。
製造業のように「材料を買い、作り、納品し、翌々月に入金」という順序とは逆向きになっています。

### ただし「必ず楽」ではない — 逆転する条件

`【Typical】` 次の条件が重なると、この関係は逆転します。

| 逆転する要因 | 何が起きるか |
|---|---|
| **キャッシュレス比率の上昇** | 売上のうち即日現金になる部分が減り、**入金が支払いより後ろにずれる**ことがある |
| **在庫が増える** | 仕入れた分が売れずに残れば、**払う義務だけが先に立ち、入金は来ない** |
| **季節商戦の前倒し仕入** | 商戦前にまとめて仕入れると、**売れる前に支払期日が来る**ことがある |
| **新店の開店** | 開店時に大量の初期在庫を仕入れるため、**売上が立つ前に大きな仕入が発生する** |
| **法人向け掛売がある場合** | その部分は入金が後日になる |

> **したがって小売業の資金繰りは、「現金商売だから安心」ではなく、
> 「入金と支払のタイミングを合わせ続ける仕事」**として理解する必要があります。
> 詳細は `08_money.md` `12_business-model.md` で扱います。

## 4-4 【Example】1つの商品を追跡する — 入荷から売れて支払われるまで

> **以下はすべて説明用の架空の例です `【Example】`。実在の企業・商品ではありません。**

### 登場人物

- **X食品スーパー株式会社**（本資料のモデル企業。4店舗）
- **Y食品卸株式会社**（加工食品の卸売業者。X社の主要仕入先）
- **Z食品工業株式会社**（メーカー）
- 商品：「特選しょうゆ 1L」 仕入価格 180円／定番売価 258円（税抜）

### タイムライン

| 日付 | 誰が | 何をしたか | 何ができたか | 対応ステップ |
|---|---|---|---|---|
| **11月8日 14:00** | X社・第1店舗 グロサリー担当 | 棚の在庫が残り6本になっているのを確認。過去の実績から週に約24本売れると判断し、**24本（1ケース）を発注**。Y社の締め時刻は当日15時 | 発注データ | A-2／B-1 |
| **11月9日 08:30** | Y食品卸のドライバー | 第1店舗の荷受場に納品。X社バックヤード担当が受け取る | 商品＋納品書 | A-3 |
| **11月9日 08:45** | X社・バックヤード担当 | 納品書と現物を照合。「特選しょうゆ1L × 24本」一致。賞味期限も十分と確認 | 検品結果（差異なし） | A-4 |
| **11月9日 09:00** | X社・バックヤード担当／店長 | 受領印を押し、仕入データとして登録。**この瞬間に商品はX社のものになり、180円×24本＝4,320円を払う義務が発生** | 仕入計上データ | A-5／B-2・B-3 |
| **11月9日 09:30** | X社・グロサリー担当 | 定番売価258円のプライスカードを確認（変更なし）。棚に補充。**古い6本を手前、新しい24本を奥**に置く（先入先出） | 販売可能な売場 | A-6／A-7 |
| **11月9日〜15日** | X社・レジ担当 | お客さまがレジに持ってくるたびに登録・決済。1週間で**22本が258円で販売**。うち現金12本、キャッシュレス10本 | 売上データ・現金／決済記録 | A-8 |
| **毎日 閉店後** | X社・レジ担当／店長 | レジを締め、POSの現金売上と実際の現金を照合。金庫に保管 | 日報・現金 | A-12 |
| **毎日 翌朝** | X社・店長 | 前日の売上金を銀行に預け入れ | 入金記録 | A-13 |
| **11月16日** | X社・グロサリー担当 | 残り8本。次の発注サイクルで再び発注 | 発注データ | A-2（次周） |
| **11月30日** | X社・経理担当／Y社 | **Y社との取引を月末で締める。** 11月中のY社からの仕入合計は1,850,000円（しょうゆ24本の4,320円もこの中に含まれる） | 締め後の取引金額 | B-4 |
| **12月5日** | X社・経理担当 | Y社から請求書（1,850,000円）が届く。自社の仕入データと照合。返品2件分が正しく控除されていることを確認 | 照合済み請求書 | B-5 |
| **12月5日** | X社・経理担当 | **買掛金1,850,000円を計上**し、支払予定表に載せる | 買掛金残高・支払予定表 | B-6 |
| **12月末** | X社・社長／経理担当 | 口座残高を確認し、Y社へ1,850,000円を振込 | 支払記録 | B-7 |

### この例から読み取れること

| 観点 | 事実 |
|---|---|
| **商品が店にあった期間** | 11月9日〜15日（約1週間） |
| **売上が立った日** | 11月9日〜15日（売れた都度） |
| **現金が入った日** | 現金分は11月9日〜15日の各日。キャッシュレス分は決済事業者の入金サイクルに従い後日 `【Varies】` |
| **仕入代金を払った日** | **12月末** |
| **モノが現金に変わってから、仕入代金を払うまでの期間** | **約1か月半** |
| **この間、X社の手元にあるお金** | しょうゆの売上代金（258円×22本＝5,676円）は先に入り、仕入代金4,320円の支払いは後 |

> **粗利の確認**
> - 売上：258円 × 22本 ＝ 5,676円
> - 原価：180円 × 22本 ＝ 3,960円
> - 粗利：1,716円（粗利率 30.2％）
> - **残り2本は在庫として翌週に繰り越し**（まだ売上にも原価にもなっていない）
>
> ここで注意：**仕入れたのは24本だが、売上原価になるのは売れた22本分だけ**です。
> 残り2本の原価360円は「在庫」として資産に残ります。
> これが `A-14 棚卸` で数える対象であり、
> **売上原価 ＝ 期首在庫 ＋ 仕入 − 期末在庫** の式が必要になる理由です。

### 【Example】もし売れ残った場合（惣菜の例）

| 時刻 | 何が起きたか | 金額への影響 |
|---|---|---|
| 10:00 | 惣菜担当が弁当を20個仕込む。原価400円／個、売価600円／個（値入率33.3％） | 原価合計 8,000円 |
| 12:00〜18:00 | 14個が600円で売れた | 売上 8,400円 |
| 18:30 | 残り6個。閉店まで2時間。**3割引（420円）に見切る** | ─ |
| 19:30 | 4個が420円で売れた | 売上 1,680円 |
| 20:00 | 残り2個。**半額（300円）に見切る** | ─ |
| 20:45 | 1個が300円で売れた | 売上 300円 |
| 21:00（閉店） | **1個が売れ残り、消費期限のため廃棄** | 売上 0円 |
| **合計** | 売上 10,380円／原価 8,000円 | **粗利 2,380円（粗利率 22.9％）** |

> **値入率33.3％の計画に対し、実際の粗利率は22.9％**。
> 差の10.4ポイントが、値下げ（見切り）と廃棄というロスで失われました。
> `【Fact】` 実際の統計でも、惣菜の目標利益率は38.5％である一方、ロス率は10.6％です
> （2024年。出典：2024年スーパーマーケット年次統計調査報告書）。
> **「粗利率の高い部門ほどロス率も高い」という小売業の構造**が、この例に現れています。

### フローのステップ名（後続ファイルはこの名称を使うこと）

**サイクルA（モノと売上）**
`A-1 商品計画` → `A-2 発注` → `A-3 入荷・荷受` → `A-4 検品` → `A-5 検収` →
`A-6 値付け` → `A-7 陳列` → `A-8 販売（レジ・即時決済）` → `A-9 在庫補充` →
`A-10 売価変更・見切り` → `A-11 廃棄ロス処理` → `A-12 レジ締め・売上金管理` →
`A-13 売上金の入金` → `A-14 棚卸`

**サイクルB（仕入と支払）**
`B-1 発注` → `B-2 入荷・検収` → `B-3 仕入計上` → `B-4 締め` →
`B-5 請求書の受領・照合` → `B-6 買掛金計上` → `B-7 支払`

### 押さえるべき5点

1. 小売業は「受注→納品→請求→入金」ではなく、**「仕入→陳列→販売→即時決済」**。
2. **発注が最重要工程**。粗利は発注した瞬間にほぼ決まる。
3. **日次の締め（レジ締め・現金管理）**が毎日必ず発生する。これは他業界にない特徴。
4. **キャッシュレス決済には入金タイムラグと手数料がある。**「即時決済＝即時入金」ではない。
5. **サイクルA（数日）とサイクルB（1〜2か月）の時間差**が、小売業のお金の構造を作っている。

次は `05_departments.md`（部署別業務）と、`06`〜`16` の横断テーマへ進みます。

# 11_systems.md — 小売業のシステム

**対象**：日本国内の中小小売業
**前提**：`04_end-to-end-process.md`（A-1〜A-14／B-1〜B-7）、`09_information.md`（情報の流れ）、
`10_documents.md`（帳票）を読んでいること
**最終更新**：2026-09-16

---

> **このファイルの目的（重要）**
>
> 本ファイルは、**「今この業界で行われている仕事を理解するため」**にシステムを扱います。
> システムは、**業務を動かすための道具**として説明します。
>
> したがって本ファイルでは、次のことを**一切行いません**。
> - どのシステムが優れているか／劣っているかの評価
> - 導入の提案、入れ替えの提案、機能追加の提案
> - 「この業務は自動化できる」「ここは手作業が残っている」といった論評
> - 特定の製品名・ベンダー名の推奨
>
> `【Varies】` **中小小売業では、紙・表計算ソフト・システムが同時に使われているのが実態です。**
> 本資料はこれを事実として記述し、**良し悪しを評価しません。**
>
> **このファイルの読み方**
> システムは製品名で覚えるものではなく、**カテゴリ（何をするための道具か）**で理解します。
> 各カテゴリについて、次の5点を示します。
>
> 1. **何を管理するものか**
> 2. **誰が使うか**（`03_company-structure.md` の機能名①〜⑪で示す）
> 3. **どの業務で使うか**（`04_end-to-end-process.md` のステップ A-○／B-○ で示す）
> 4. **どんな情報が入るか**（インプット）
> 5. **どんな情報が出るか**（アウトプット）

## 11-1 全体像 — 小売業のシステムはどこに置かれているか

```
 ┌─────────────────── 本部 ───────────────────┐
 │  ・商品マスタ／売価マスタの管理                  │
 │  ・仕入価格・取引条件の管理                     │
 │  ・全店の売上・粗利の集計                       │
 │  ・会計ソフト、勤怠・給与                       │
 └────────────────────────────────────────────┘
          ▲ 売上・在庫のデータ       │ 商品・売価のデータ
          │                        ▼
 ┌─────────────────── 店舗 ───────────────────┐
 │  【売場】                                     │
 │    POSレジ ── キャッシュレス決済端末           │
 │    セルフレジ／セミセルフレジ 【Varies】        │
 │    電子棚札 【Varies】                        │
 │  【バックヤード】                              │
 │    発注端末（ハンディ）／発注用のPC            │
 │    電子秤・値付け機（生鮮・惣菜の加工場）        │
 │    事務所のPC（日報、シフト、売価変更）         │
 │  【店舗全体】                                  │
 │    防犯カメラ                                 │
 └────────────────────────────────────────────┘
          ▲ 発注データ              │ 納品予定・商品情報
          │                        ▼
 ┌────────────────── 社外 ────────────────────┐
 │  仕入先・卸売業者のシステム（発注の受け手）       │
 │  決済事業者（クレジット・電子マネー・コード決済）  │
 │  銀行                                        │
 └────────────────────────────────────────────┘
```

`【Inference】` 図から分かるとおり、小売業のシステムは **「売場で発生した事実を記録するもの」** と
**「次に何をするかを決めるために情報を渡すもの」** の2種類に大きく分かれます。
`09_information.md` 9-0 で説明した「情報の輪」を、機械の側から見たものがこの図です。

## 11-2 POS（販売時点情報管理）

> **POS（ピーオーエス／Point of Sale ＝ 販売時点情報管理）**
> → 商品が売れたその瞬間に、「何が・いつ・いくつ・いくらで売れたか」を記録する仕組みのこと。
> → 実務例：レジでバーコードを読み取ると、金額が計算されると同時に、
>   「14時32分に、この店で、この商品が1個、198円で売れた」という記録が残ります。
>
> **「レジ」と「POS」は同じものではありません。**
> レジ（キャッシュレジスター）は**お金を計算して預かる機械**です。
> POSは、それに加えて**「何が売れたか」を商品単位で記録する仕組み**です。
> 現在、小売店のレジの多くはPOSの機能を持っているため、
> 実務では「POSレジ」「レジ」と呼び分けずに使われることが多くあります。

| 項目 | 内容 |
|---|---|
| **何を管理するものか** | 販売の事実（商品別の販売数量・金額・時刻）、決済手段別の売上、レジ内の現金の理論額、返品・取消の記録 |
| **誰が使うか** | ⑨ レジ・接客機能（打つ人）／⑦ 店舗運営統括機能（締める人・数字を見る人）／⑧ 売場担当機能（売れ行きを見る人）／① 商品調達機能・社長（全店の数字を見る人）／④ 経理・財務機能 |
| **どの業務で使うか** | `A-8 販売（レジ・即時決済）`、`A-12 レジ締め・売上金管理`、`A-2 発注`（前日・前週の実績を見る）、`A-10 売価変更・見切り`、`A-14 棚卸` |
| **どんな情報が入るか** | 商品のバーコード（JANコード）、数量、**売価マスタから読み込まれた売価**、値引き・値下げの情報、決済手段、預り金、会員カード・ポイントカードの情報 `【Varies】` |
| **どんな情報が出るか** | レシート（お客さま向け）、**POS売上情報**（商品別・時間帯別・部門別）、レジ精算票・点検票、客数（レジ通過人数）、客単価、買上点数、**値下げ額・廃棄額**（登録した場合）、在庫の理論値 `【Varies】` |

> **なぜPOSが必要なのか**
> `09_information.md` 9-2 のとおり、**次に何をいくつ発注するかを決めるには、
> 「何がいくつ売れたか」が分からなければなりません。**
> レジが金額の合計だけを記録していると、「今日30万円売れた」は分かっても、
> **「豆腐が何丁売れたか」が分からない**ため、明日の豆腐の発注数を決められません。
> `【Typical】` 小売業でPOSが業務の中心にあるのは、
> **売った記録がそのまま仕入の判断材料になる**という構造があるからです。

### POSから出てくる情報が、どの業務に渡るか

| POSから出る情報 | 渡る先 | そこで何に使われるか |
|---|---|---|
| 商品別の販売数量 | ⑧ 売場担当機能 | `A-2 発注` の数量判断、`A-9 在庫補充` のタイミング |
| 時間帯別の売上・客数 | ⑦ 店舗運営統括機能 | シフトの人時配置（`13_periodic-work.md` 参照） |
| 部門別の売上・粗利 | ① 商品調達機能、社長 | 品揃えと売価の見直し（`A-1 商品計画`） |
| 決済手段別の売上 | ④ 経理・財務機能 | `A-12 レジ締め`、`A-13 売上金の入金`、入金予定の把握 |
| 値下げ額・廃棄額 | ⑦ 店舗運営統括機能、④ 経理・財務機能 | ロスの内訳把握（`14_kpi.md` 参照） |

## 11-3 発注システム・発注端末（EOS）

> **EOS（イーオーエス／Electronic Ordering System ＝ 電子発注システム）**
> → 発注の内容を、紙やFAXではなくデータで仕入先に送る仕組みのこと。
> → 実務例：売場でハンディ端末（手のひらサイズの携帯端末）のバーコードを読み、
>   数量を打ち込んで送信すると、その内容が仕入先のシステムに届きます。
>
> **発注端末（ハンディターミナル、ハンディ）**
> → 売場を歩きながら発注数量を入力するための携帯端末のこと。
> → 実務例：棚の前で「この商品はあと2個しかない」と見て、その場でバーコードを読んで
>   「10」と入力します。**売場を見ながら発注できる**ことが、この道具の要点です。

| 項目 | 内容 |
|---|---|
| **何を管理するものか** | 発注の内容（商品・数量・納品希望日）とその履歴、発注先（どの商品をどの仕入先に頼むか）、発注の締め時刻 |
| **誰が使うか** | ⑧ 売場担当機能（部門ごとに発注する人）／① 商品調達機能（本部でまとめて発注する場合）／⑦ 店舗運営統括機能（発注内容の確認） |
| **どの業務で使うか** | `A-2 発注`／`B-1 発注`、`A-3 入荷・荷受`・`A-4 検品`（発注内容との照合） |
| **どんな情報が入るか** | 商品コード、発注数量、納品希望日、店舗コード、担当者。あわせて**商品マスタ**（入数・発注単位・仕入価格）と、参考情報として**前回発注数・販売実績・在庫数** `【Varies】` |
| **どんな情報が出るか** | **発注データ**（仕入先へ送信）、発注控え、発注履歴、発注残（頼んだがまだ届いていない数量）`【Varies】` |

> **なぜ「発注単位」と「入数」が重要なのか**
> `【Typical】` 発注は1個単位ではなく、**ケース単位・ボール単位**で行うことが多くあります。
> 「1ケース＝24本」の飲料を「10」と入力したとき、それが10本なのか10ケース（240本）なのかで
> 入ってくる量が24倍変わります。
> 発注システムには**入数（1ケースに何個入っているか）と発注単位**が登録されており、
> これが正しくないと、発注した本人の意図と違う量が届きます。

### 発注の伝達手段は1つではない `【Varies】`

`09_information.md` 9-4 のとおり、発注情報の伝え方には幅があります。

| 手段 | 概要 |
|---|---|
| 発注端末（EOS） | ハンディ端末から仕入先のシステムへ送信 |
| Web発注 | 仕入先が用意したWebサイトに、PCやタブレットから入力 |
| FAX | 発注用紙に記入して送信 |
| 電話 | 口頭で伝え、控えを手元に残す |
| 対面 | 来店した仕入先の営業担当に直接伝える |

`【Varies】` **どの手段を使うかは、仕入先ごと・商品分野ごとに異なります。**
同じ店で「青果は市場の担当者に電話、日配はEOS、グロサリーはWeb発注」という組み合わせは
珍しくありません。**本資料はこの実態を評価しません。**

## 11-4 発注推奨機能（自動発注の支援）`【Varies】`

> **発注推奨（発注提案）**
> → 販売実績や在庫数をもとに、システムが「この商品はこれだけ発注してはどうか」という
>   数量の候補を提示する機能のこと。
> → 実務例：過去の販売数と今ある在庫から計算した数量が端末に表示され、
>   担当者がそれを見て、そのまま確定するか、数字を直すかを判断します。

| 項目 | 内容 |
|---|---|
| **何を管理するものか** | 発注数量の計算に使う条件（販売実績、在庫数、発注リードタイム、最低陳列量 など） |
| **誰が使うか** | ⑧ 売場担当機能、① 商品調達機能 |
| **どの業務で使うか** | `A-2 発注` |
| **どんな情報が入るか** | POS売上情報、在庫情報、商品マスタ（発注単位・リードタイム）、販促・特売の予定 `【Varies】` |
| **どんな情報が出るか** | 発注数量の候補（推奨値） |

`【Varies】` **この機能が使えるかどうか、また、どこまで使っているかは企業により大きく異なります。**
`【Typical】` 実務上、次のような事情から**最終的な数量は人が判断する**という運用が一般的です。

- 天候（雨の予報が出れば来店客数が落ち、鍋物の材料は寒波で動く）
- 地域の行事（近隣の学校行事・祭り・工事などで人の流れが変わる）
- 特売やチラシの予定（過去の実績には表れない需要が生まれる）
- 売場の見え方（同じ販売数でも、棚を埋めるために必要な量は変わる）

> **注意**
> 本資料は「人が判断すること」と「システムが計算すること」のどちらが優れているかを
> **一切評価しません。** ここで理解すべきは、**発注という業務には
> 数字だけでは決まらない要素が含まれている**という業務の性質です。

## 11-5 在庫管理（在庫の記録）

| 項目 | 内容 |
|---|---|
| **何を管理するものか** | 商品ごとの在庫数量（理論値）、入荷・販売・廃棄・値下げ・返品による在庫の増減、棚卸の結果 |
| **誰が使うか** | ⑧ 売場担当機能、⑩ バックヤード機能、④ 経理・財務機能、① 商品調達機能 |
| **どの業務で使うか** | `A-5 検収`（在庫が増える）、`A-8 販売`（在庫が減る）、`A-11 廃棄ロス処理`（在庫が減る）、`A-14 棚卸`（理論値と実際を合わせる） |
| **どんな情報が入るか** | 検収情報（入った数）、POS売上情報（出た数）、廃棄情報、返品情報、棚卸情報 |
| **どんな情報が出るか** | 在庫数量の一覧、**帳簿在庫と実地棚卸高の差＝不明ロス**、在庫金額、在庫回転率の計算材料 |

> **在庫管理の「精度」は、扱う商品により大きく違う `【Varies】`**
> `07_goods.md` で扱ったとおり、小売業の在庫には**個数を1つずつ追えるもの**と、
> **追いにくいもの**があります。
> - 追いやすい：パッケージ化された加工食品・日用品（バーコードで1点ずつ管理できる）
> - 追いにくい：**量り売りの生鮮、店内で加工する惣菜**（丸ごとの魚を切り身にすると、
>   元の1尾が複数の商品に変わり、歩留まりも一定ではない）
>
> `【Typical】` このため、中小小売業では**全商品の在庫をシステムで常時把握しているとは限りません。**
> 「グロサリーは数量で管理し、生鮮は金額だけで管理する」といった使い分けが行われます `【Varies】`。
> **本資料はこの実態を評価しません。**

## 11-6 電子秤・値付け機（生鮮・惣菜）

> **電子秤（でんしばかり）／計量値付け機（ラベルプリンタースケール）**
> → 商品を載せて重さを量り、その場で**価格を計算してラベル（値札）を印字する機械**のこと。
> → 実務例：切り身の魚をトレーに載せて秤に置くと、「100gあたり298円」の設定から
>   その1パックの価格が計算され、商品名・内容量・価格・消費期限・バーコードを印字した
>   ラベルが出てきます。

| 項目 | 内容 |
|---|---|
| **何を管理するものか** | 商品ごとの単価（100gあたりの価格など）、商品名、期限の設定、原材料・アレルゲンなどの表示内容 `【Varies】` |
| **誰が使うか** | ⑧ 売場担当機能（青果・鮮魚・畜産・惣菜の担当者） |
| **どの業務で使うか** | `A-6 値付け`、`A-10 売価変更・見切り`（値下げシールの発行） |
| **どんな情報が入るか** | 商品マスタ（商品名・単価・期限の日数・表示事項）、量った**重さ**、加工日 |
| **どんな情報が出るか** | **値札（ラベル）**：商品名、内容量、単価、売価（税込）、消費期限・賞味期限、バーコード |

> **なぜ生鮮・惣菜には専用の機械が必要なのか**
> `【Typical】` 生鮮食品は**1パックごとに重さが違う**ため、
> パッケージ化された商品のように「この商品＝198円」と決めておくことができません。
> **量って初めて価格が決まる**ため、その場でラベルを印字する必要があります。
>
> `【Fact】` また、この機械が印字するラベルは**法令上の表示**そのものでもあります。
> 精肉・鮮魚・惣菜などは計量法上の**特定商品**に該当し、内容量を示して販売するときは
> 政令で定める誤差（**量目公差**）を超えないように計量しなければなりません
> （出典：計量法第12条、特定商品の販売に係る計量に関する政令／e-Gov法令検索）。
> 取引・証明に使うはかりには検定を受けたものを使う必要があり、
> **2年に1回の定期検査**を受けることが定められています
> （出典：計量法第16条・第19条、計量法施行令第11条／e-Gov法令検索）。
> 詳細は `15_rules-customs.md` を参照してください。

## 11-7 キャッシュレス決済端末

> **キャッシュレス決済端末（決済端末、CAT端末、マルチ決済端末）**
> → クレジットカード・電子マネー・コード決済などの支払いを処理する機械のこと。
> → 実務例：お客さまがカードをかざすと、端末が決済事業者に照会し、
>   支払いが成立した記録がPOSに戻ってきます。

| 項目 | 内容 |
|---|---|
| **何を管理するものか** | 現金以外の支払いの受付と記録、決済手段ごとの売上 |
| **誰が使うか** | ⑨ レジ・接客機能、④ 経理・財務機能 |
| **どの業務で使うか** | `A-8 販売（レジ・即時決済）`、`A-12 レジ締め`、`A-13 売上金の入金` |
| **どんな情報が入るか** | 決済金額、カード・コードの情報、支払回数 |
| **どんな情報が出るか** | 決済の承認結果、決済控え（お客さま控え・店控え）、**決済手段別の売上集計**、決済事業者からの**入金明細**（後日） |

> **【重要】ここで発生する「入金のタイムラグ」と「手数料」**
> `08_money.md` 8-1 で詳しく扱ったとおり、**キャッシュレス決済は「即時決済」ですが
> 「即時入金」ではありません。**
> 売上が成立した瞬間に店にお金が入るのは現金だけで、キャッシュレス分は
> 決済事業者から**後日、手数料を引かれた金額**が振り込まれます。
> `【Fact】` 日本のキャッシュレス決済比率は39.3％（2023年）
> （出典：キャッシュレス・ロードマップ2024／一般社団法人キャッシュレス推進協議会）、
> 食品スーパーの現金以外の決済手段の導入率は95.6％（2024年）
> （出典：2024年スーパーマーケット年次統計調査報告書）。
> `【Varies】` 手数料率と入金サイクルは契約により異なるため、本資料では具体的な数値を示しません。

## 11-8 セルフレジ・セミセルフレジ `【Varies】`

> **セルフレジ**
> → お客さま自身が商品のバーコードを読み取り、支払いまで行うレジのこと。
>
> **セミセルフレジ（会計分離型）**
> → 商品の読み取りは店員が行い、**支払いだけをお客さまが別の精算機で行う**方式のこと。
> → 実務例：店員が「お会計は2番の精算機でお願いします」と案内し、
>   お客さまがその機械に現金を入れるかカードをかざします。

| 項目 | 内容 |
|---|---|
| **何を管理するものか** | 通常のPOSと同じ（販売の事実、決済） |
| **誰が使うか** | **お客さま**（操作する人）／⑨ レジ・接客機能（見守り・トラブル対応・年齢確認） |
| **どの業務で使うか** | `A-8 販売（レジ・即時決済）` |
| **どんな情報が入るか** | 商品のバーコード、数量、決済手段、預り金 |
| **どんな情報が出るか** | POS売上情報、レシート、精算機内の現金の記録 |

`【Varies】` **導入しているかどうかは企業・店舗により大きく異なります。**

`【Typical】` 業務理解の上で押さえるべき点は、**レジの仕組みが変わると
レジ担当者の仕事の中身も変わる**ことです。

- 現金を直接扱わない方式では、**釣銭の受け渡しがレジ担当者の手を離れる**
- そのぶん、**見守り・操作案内・トラブル対応**が仕事の中心になる
- `【Fact】` 酒類・たばこの販売では**年齢確認**が必要であり（`15_rules-customs.md` 参照）、
  お客さま自身が操作する方式でも、この確認は店側が行う必要がある

> **注意**：本資料は導入の是非・効果を**評価しません。**
> ここで理解すべきは「レジ業務の中身が方式によって変わる」という事実です。

## 11-9 ポイント・会員管理 `【Varies】`

| 項目 | 内容 |
|---|---|
| **何を管理するものか** | 会員（顧客）の登録情報、ポイントの付与と使用の履歴、購買履歴 |
| **誰が使うか** | ⑨ レジ・接客機能（カードの読み取り・問い合わせ対応）／② 販促・販売企画機能（販促の企画）／④ 経理・財務機能（ポイント引当の会計処理）`【Varies】` |
| **どの業務で使うか** | `A-8 販売`、`A-1 商品計画`（販促の企画） |
| **どんな情報が入るか** | 会員番号、購入日時・店舗、購入商品と金額、付与・使用ポイント |
| **どんな情報が出るか** | ポイント残高、購買履歴、**同じ人が何回来ているか（来店頻度）**、会員別・属性別の購買傾向 |

> **POSデータとの決定的な違い**
> `【Typical】` 通常のPOS売上情報は「何が売れたか」は分かりますが、
> **「誰が買ったか」は分かりません。** 同じ人が10回買ったのか、10人が1回ずつ買ったのかを
> 区別できないのです。
> 会員管理の仕組みがあると、この2つを区別できるようになります。
> `【Varies】` ただし、会員制度を持つかどうか、どこまで活用するかは企業により大きく異なります。

## 11-10 会計ソフト（財務会計）

| 項目 | 内容 |
|---|---|
| **何を管理するものか** | 仕訳（会計上の記録）、売上・仕入・経費、買掛金、現金・預金、棚卸資産、決算書の作成 |
| **誰が使うか** | ④ 経理・財務機能、社長、顧問税理士 `【Varies】` |
| **どの業務で使うか** | `A-12 レジ締め`以降の売上計上、`B-3 仕入計上`、`B-6 買掛金計上`、`B-7 支払`、`A-14 棚卸`、月次決算・年次決算 |
| **どんな情報が入るか** | POSからの売上情報（日次）、仕入計上データ、経費の支払、給与、棚卸情報、銀行の入出金 |
| **どんな情報が出るか** | 試算表、損益計算書、貸借対照表、**部門別の損益** `【Varies】`、買掛金残高一覧、消費税の計算資料 |

> **なぜ棚卸が終わらないと利益が出ないのか（再掲）**
> `08_money.md` 8-4 のとおり、**売上原価 ＝ 期首在庫 ＋ 仕入 − 期末在庫**。
> 会計ソフトは日々の売上と仕入を記録できますが、**期末在庫は棚卸の結果を入力するまで分かりません。**
> このため、棚卸の数字が入って初めて売上原価が確定し、粗利と利益が計算できます。

> **インボイス制度との関係**
> `【Fact】` 2023年10月1日から、消費税の仕入税額控除の方式として
> **適格請求書等保存方式（インボイス制度）**が開始されています（出典：国税庁）。
> 小売業など不特定多数の者に販売する事業では、記載事項を簡略化した
> **適格簡易請求書**（レシート）を交付することができます（出典：国税庁 インボイス制度Q&A）。
> このため、POSが印字するレシートの記載事項と、会計上の処理が結びついています。
> 詳細は `15_rules-customs.md` を参照してください。

## 11-11 勤怠管理・シフト管理

| 項目 | 内容 |
|---|---|
| **何を管理するものか** | 出退勤の時刻、実労働時間、時間外・深夜労働、休憩、有給休暇、シフトの予定と実績 |
| **誰が使うか** | 全従業員（打刻する人）／⑦ 店舗運営統括機能（シフトを組む人）／⑤ 人事・労務機能（集計・給与計算） |
| **どの業務で使うか** | 常時（打刻）、週次・月次（シフト作成）、月次（勤怠締め・給与計算） |
| **どんな情報が入るか** | 打刻（出勤・退勤・休憩）、シフトの予定、休暇の申請、時給・手当の設定 |
| **どんな情報が出るか** | 個人別の労働時間、**部門別・時間帯別の人時**、時間外労働の時間、給与計算の基礎データ、**人件費の実績** |

> **小売業で勤怠が重い理由**
> `03_company-structure.md` のとおり、X社（架空）は**正社員約60名＋パート・アルバイト約140名**。
> `【Fact】` 食品スーパーの店舗勤務者に占めるパート・アルバイト比率は71.2％（2024年、
> 出典：2024年スーパーマーケット年次統計調査報告書）。
> `【Typical】` 勤務時間が人ごとにバラバラで、日によってメンバーも変わるため、
> **「今月、誰が何時間働いたか」を集計するだけで相当な作業量**になります。
> また `14_kpi.md` で扱う**人時売上高**は、売上とこの労働時間を突き合わせて計算するため、
> 勤怠のデータは人事の書類であると同時に**経営数字の材料**でもあります。

## 11-13 EC・ネットスーパー `【Varies】`

| 項目 | 内容 |
|---|---|
| **何を管理するものか** | オンラインの受注、在庫の引き当て、配送またはお客さまの受け取り、オンライン決済 |
| **誰が使うか** | `【Varies】` 専任の担当者を置く場合と、⑧ 売場担当機能・⑩ バックヤード機能が兼務する場合がある |
| **どの業務で使うか** | 店頭販売とは別の流れ：**受注 → ピッキング（店内または倉庫で商品を集める）→ 梱包 → 配送または受け渡し → 決済** |
| **どんな情報が入るか** | 注文情報（商品・数量・希望日時・届け先）、決済情報、在庫情報 |

EC・通販では**注文が入ってから商品を渡すまでに時間があり**、
オンライン決済の入金にもタイムラグがあります。
つまり `04_end-to-end-process.md` の**サイクルA（数日で一周する速い流れ）に
「受注」という工程が追加される**構造になります。

## 11-15 情報が機械の間をどう流れるか（まとめ図）

`【Typical】` これまでのカテゴリを、情報の流れでつなぐと次のようになります。

```
  商品マスタ・売価マスタ（本部）
        │ 商品名・売価・バーコード
        ▼
  ┌──────────┐   売価           ┌──────────┐
  │   POS     │◀──────────────│ 売価マスタ  │
  │（レジ）    │                 └──────────┘
  └──────────┘                        ▲
        │ POS売上情報                    │ 売価変更
        ▼                                │
  ┌──────────┐   販売実績        ┌──────────┐
  │ 在庫の記録  │──────────────▶│ 発注システム │──▶ 仕入先
  └──────────┘                  └──────────┘
        ▲ 検収情報                       │ 発注データ
        │                                ▼
  ┌──────────┐                   （納品）
  │ 検品・検収  │◀────────────────────┘
  └──────────┘
        │ 仕入計上
        ▼
  ┌──────────┐   棚卸情報        ┌──────────┐
  │  会計ソフト │◀──────────────│   棚卸     │
  └──────────┘                  └──────────┘
        │ 損益
        ▼
    経営の数字（14_kpi.md へ）

  ［並行して］
  勤怠・シフト ──▶ 人件費・人時 ──▶ 人時売上高（14_kpi.md）
  決済端末     ──▶ 決済手段別売上 ──▶ 入金予定（08_money.md）
```

`【Inference】` この図の要点は、**どの機械も単独では完結していない**ことです。
売価マスタが間違っていればPOSが違う金額を打ち、
検収が記録されなければ在庫も仕入も合わず、
棚卸が入らなければ会計ソフトは利益を出せません。
`09_information.md` 9-7 で扱った「情報が止まりやすい・ずれやすい場所」は、
そのまま**この図の矢印の部分**にあたります。

## この章のまとめ（後続ファイルへの引き継ぎ事項）

1. **POSは「レジ」であると同時に「何が・いつ・いくつ売れたか」を記録する装置。**
   小売業のシステムの中心にあり、ここから出る情報が発注・人員配置・売価の判断を支えている。
2. **発注はEOS・Web・FAX・電話・対面と伝達手段に幅がある `【Varies】`。**
   商品分野・仕入先ごとに手段が違うのが実態。
3. **生鮮・惣菜には電子秤・値付け機が不可欠。** 量って初めて価格が決まるため。
   `【Fact】` 計量法上の**特定商品**にあたり、量目公差とはかりの定期検査（2年）が定められている。
4. **キャッシュレス決済端末は「入金のタイムラグ」と「手数料」を生む**（`08_money.md` 8-1）。
5. **会計ソフトは棚卸の数字が入って初めて利益を出せる**（`08_money.md` 8-4）。
6. **勤怠・シフトのデータは、人事の書類であると同時に人時売上高の材料**（`14_kpi.md`）。
7. `【Varies】` **セルフレジ・会員管理・EC・発注推奨機能の有無は企業により大きく異なる。**
8. **どの機械も単独では完結せず、マスタ・検収・棚卸でつながっている。**
9. `【Varies】` **中小小売業では紙・表計算ソフト・システムが併用されている。
   本資料はこれを事実として記述し、良し悪しを評価しない。**

次は `12_business-model.md` で、**小売業はどうやって儲けているのか**を扱います。

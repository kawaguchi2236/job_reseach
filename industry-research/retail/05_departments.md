| **F** | 業務頻度 | `common/methodology.md` §5 の語彙のみを使用 |
| **G** | インプット | 業務を始めるために必要なもの |
| **H** | アウトプット | 業務の結果できあがるもの |
| **I** | 関係部署 | 前工程・後工程を含む社内の相手 |

| **N** | 使用設備・道具 | 業界理解に必要な範囲で |
| **O** | 見ている数字・KPI | その機能が日常的に追っている数値 |

### 0-2 【最重要】「機能がある」＝「部署がある」ではありません

`【Typical】` X社規模（4店舗・年商30億円）の小売業では、
**本部機能はほぼすべて社長と事務担当3〜4名に集約されています。**
以降で「商品調達機能」「販促・販売企画機能」と分けて書くのは、
**仕事の種類を分けて理解するため**であって、そういう部署が実在するという意味ではありません。

```
  大手チェーンでの姿                    X社での実態 【Example】/【Typical】
  ─────────────────────         ─────────────────────────────
  商品部（バイヤー10名）      ┐
  販促部（5名）              ├──▶   社長（1名）が全部を兼ねる
  店舗開発部（3名）           ┘
  経理部（8名）              ┐
  人事部（5名）              ├──▶   事務担当（2〜3名）＋外部の税理士・社労士 【Varies】
  情報システム部（4名）       ┘        ＋システムベンダーの保守
```

> **本資料で繰り返し出てくる言い方**
> ✕「小売業には商品部がある」
> ○「**商品を決めて仕入れる仕事（商品調達機能）は必ず存在する**。
>   大手では商品部の専任バイヤーが、中小では社長や部門チーフが担っている」

### 0-3 Level 2（業態差）の扱い

`【Varies】` 本ファイルの本体は **食品スーパー**（X社）を基準に書いています。
専門店・ドラッグストア・EC・飲食併設型で業務が大きく異なる箇所は、
各機能の中に **「▼ Level 2：業態による違い」** として明示します。
食品スーパーの姿を「小売業一般の姿」と読まないでください。

### 0-4 頻度の表記について

`common/methodology.md` §5 の語彙のみを使います。

```
常時 / 日次 / 週次 / 月次 / 四半期 / 半期 / 年次
案件発生時 / 問い合わせ時 / 受注時 / 発注時 / 納品時 / 請求時 / 入金時
トラブル発生時 / 法定・契約上のタイミング / その他
```

`【Varies】` 「毎週月曜」「毎月25日」といった曜日・日付レベルの記述は、
法定期限など根拠のあるもの以外は書きません。実際の曜日・時刻は企業・仕入先により異なります。

## ① 商品調達機能（バイヤー）

> **この機能を一言でいうと：「何を・どこから・いくらで仕入れ、いくらで売るかを決める仕事」**
> 小売業の粗利は、ここでの決定でおおよその枠が決まります。

### A. 部署・機能名

| 項目 | 内容 |
|---|---|
| **本資料での正式名称** | **商品調達機能** |
| **一般的に使われる部署名・役職名** | 商品部、仕入部、購買部、**バイヤー**、仕入担当、マーチャンダイザー（MD） |
| **層** | 本部 |

> **バイヤー**
> → 店に置く商品を選び、仕入先と価格を決め、売価を決める人のこと。「買う人」という意味の英語から。
> → 実務例：「今年のお中元コーナーに何を並べるか」「この醤油を棚から外して別の商品を入れるか」を
>   決めるのがバイヤーの仕事です。**買う仕事に見えて、実際は「何を売るかを決める仕事」**です。

> **MD（エムディー／マーチャンダイジング：商品政策）**
> → どんな商品を・どれだけ・いくらで・どこに置いて売るかという、商品まわりの計画全体のこと。
> → 実務例：「夏は麺類とアイスを売場の前面に出し、鍋物の材料は縮小する」といった
>   季節ごとの商品構成の組み替えは、MDの仕事です。

### B. 存在目的

小売業は**自分で商品を作りません**。したがって「何を置くか」を決めた時点で、
その店が売れる商品の上限が決まります。
商品調達機能は、**商圏の客が買いたいものを、利益が出る条件で、必要な時期に確保する**ために存在します。

`【Inference】` この機能がないと次のことが起きます。
- 客が欲しい商品が棚にない（＝売上そのものが立たない）
- 仕入価格が高すぎて、売価を付けても粗利が残らない
- 同じような商品ばかりになり、棚が有効に使われない

### C. 担当者

| 区分 | 誰が担うか |
|---|---|
| **大手チェーンの一般的な姿** `【Typical】` | 商品部に所属するカテゴリー別の専任バイヤー（青果バイヤー、加工食品バイヤー等） |
| **X社での実態** `【Example】`／`【Typical】` | **社長が主要カテゴリーのバイヤーを兼務**。加工食品・日配・非食品の取引条件と定番売価は社長が決める |
| **生鮮の実態** `【Typical】` | **青果・水産・畜産は各店の部門チーフが市場・仲卸と直接やりとりする**ことが多い。相場が毎日動くため、本部で一括して決めきれない |
| **補助** | 事務担当（発注書・単価表の整理、マスタ登録の依頼） |

> `【Typical】` 中小小売で「バイヤー＝社長」になるのは、単に人が足りないからではありません。
> **仕入価格を決める交渉は、支払条件・取引継続の判断とセットである**ため、
> 会社としての約束ができる立場の人でないと決められないからです。

### E. 業務詳細

---

#### ①-1 商品選定（何を置くか）・新商品の導入判断

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 卸売業者・メーカーからの新商品案内を受けたとき／季節の切り替わり／棚に空きが出たとき／客からの要望が届いたとき／競合店で見かけたとき（＝案件発生時） |
| **誰が行うか** | 商品調達機能（X社では**社長**）。生鮮は部門チーフが提案し社長が承認 `【Typical】` |
| **何を確認するか** | ①自店の客層に合うか（価格帯・容量・調理の手間）②既存商品と重ならないか ③仕入価格と想定売価で狙う粗利が取れるか ④**棚のどこに置くか（場所があるか）** ⑤最低発注ロットは引き受けられる量か ⑥賞味期限・消費期限は自店の回転で売り切れる長さか |
| **何をするか** | 商談で商品説明・サンプル・販促計画を受ける。想定売価と値入を計算する。**置く場所を決める（＝何かを外す）**。試験的に少量導入する場合は数量と期間を決める |
| **何を判断するか** | **導入するか／しないか。導入するなら、代わりに何を外すか** |
| **誰と連携するか** | 仕入先（卸・メーカー営業）、店長、売場担当（部門チーフ）、情報システム機能（商品マスタ登録の依頼） |
| **最終的に何ができあがるか** | **取扱商品リスト（商品マスタへの登録依頼）**、定番売価、棚割の変更案 |
| **頻度** | 月次／季節の変わり目（＝その他）／案件発生時 `【Varies】` |

> **なぜこの業務が必要なのか**
> `【Inference】` 棚の面積は有限だからです。1つ増やすには1つ減らすしかありません。
> 「良い商品だから入れる」ではなく、**「今そこに置いてある商品よりも稼ぐか」**を比べる仕事です。
> 判断を誤ると、売れない商品が棚を占め続け、その分だけ売れる商品を置けなくなります。

> **死に筋（しにすじ）／売れ筋（うれすじ）**
> → **死に筋**＝ほとんど売れていない商品。**売れ筋**＝よく売れている商品。
> → 実務例：「この棚の下段の商品は1か月で3個しか売れていない」＝死に筋。
>   死に筋を放置すると、棚を占有するだけでなく、在庫として資金が寝ます。
>   だから小売業では**「何を入れるか」と同じ強さで「何を外すか」を議論します**。

#### ①-2 定番の見直し・カット（取扱中止）判断

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 定番の定期見直し時期／新商品を入れるため棚を空ける必要が出たとき／売れ行きが長期に落ちている商品を見つけたとき／メーカーの終売連絡を受けたとき |
| **誰が行うか** | 商品調達機能（社長）＋売場担当（部門チーフ）の意見 |
| **何を確認するか** | 一定期間の販売数量・売上・粗利／在庫の残り／代替商品があるか／**特定の客が指名買いしている商品でないか** |
| **何をするか** | 販売実績の低い順に並べて候補を出す。売場担当に確認する。**カットする商品の在庫を売り切る計画**（値下げして消化する等）を決める |
| **何を判断するか** | **外すか／残すか。外すなら、残った在庫をどう処理するか** |
| **誰と連携するか** | 売場担当、店長、仕入先（終売・返品の相談）、情報システム機能（マスタの取扱区分変更） |
| **最終的に何ができあがるか** | **カット商品リスト**、棚割の変更案、在庫処分の指示 |
| **頻度** | 月次〜四半期 `【Varies】` ／案件発生時 |

> **なぜこの業務が必要なのか**
> `【Inference】` 商品は勝手には減りません。意識して外さない限り、増え続けます。
> 品目が増えると、①1品目あたりの発注数が細かくなり、②在庫が分散し、③補充と期限管理の手間が増えます。
> カットは「品揃えを減らす後ろ向きの作業」ではなく、**棚と資金を売れる商品に振り向ける作業**です。

> `【Varies】` ただし、売れ行きが悪くても外せない商品があります。
> 「この店にはいつもある」と思われている商品、特定の客が毎回買っている商品、
> 他の商品と一緒に使われる商品（＝それがないと関連商品も売れない）などです。
> **数字だけでカットを決められない点が、この判断の難しさです** `【Typical】`。

#### ①-3 仕入先の選定と価格交渉

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 新商品の導入時／既存商品の仕入価格の見直し時／メーカーからの**価格改定の申し入れ**を受けたとき／新しい仕入先から取引の打診があったとき／既存の仕入先で欠品・納品遅れが続いたとき（＝案件発生時） |
| **誰が行うか** | 商品調達機能（X社では**社長**）。取引条件（締め日・支払サイト）の決定は社長のみ `【Typical】` |
| **何を確認するか** | 仕入単価／**最低発注ロット**／リードタイム（発注から納品までの日数）／納品便の時刻／欠品時の対応／返品の可否／**締め日と支払条件**／リベート（販売奨励金）の有無／物流費が仕入価格に含まれているか |
| **何をするか** | 複数の仕入先から条件を聞く。取引量をまとめる／発注単位を大きくする等の条件を示して単価を交渉する。**取引条件を文書（取引基本契約書・単価表）で確認する** |
| **何を判断するか** | **どの仕入先から、いくらで、どういう条件で仕入れるか。** 単価が安くても、ロットが大きすぎる・納品が遅い場合は採用しない |
| **誰と連携するか** | 卸売業者・メーカー・仲卸業者、経理・財務機能（支払条件の確認）、店長（納品時刻が店舗作業に影響するため） |
| **最終的に何ができあがるか** | **取引基本契約書／単価表（仕入価格表）**、発注ルート、支払条件 |
| **頻度** | 案件発生時／年次（年間の取引条件の見直し） `【Varies】` |

> **なぜこの業務が必要なのか**
> `【Inference】` 小売業の粗利率は2割台半ばです（`【Fact】` 食品スーパーで平均26.34％、2024年、
> 出典：2024年スーパーマーケット年次統計調査報告書）。
> **仕入単価が1％下がれば、粗利はそのまま増えます。**
> X社（年商30億円・原価約22億円）なら、原価が1％下がると年間2,200万円の差になります `【Example】`。
> 営業利益がほぼ±0の会社にとって、これは決定的な金額です。

> **支払サイト**
> → 商品を仕入れてから、実際に代金を払うまでの期間のこと。
> → 実務例：「月末締め・翌月末払い」なら、1日に仕入れた分は約2か月後、
>   末日に仕入れた分は約1か月後に払うことになります。
>   **サイトが長いほど、手元にお金が残っている期間が長くなります**（`08_money.md`）。

> **最低発注ロット（発注単位）**
> → 「これ以上小さい単位では売らない」と仕入先が決めている数量のこと。
> → 実務例：「1ケース＝24本単位でしか買えない」場合、6本しか売れない商品でも24本仕入れることになります。
>   **単価が安くても、ロットが自店の売れ行きに合わなければ在庫になります。**

#### ①-4 売価設定（値入の決定）★小売業固有の中心業務★

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 新商品の導入時／**仕入価格が変わったとき**／競合店が売価を変えたとき／定番売価の定期見直し時／特売企画の決定時 |
| **誰が行うか** | 商品調達機能（X社では**社長**）。生鮮は相場に応じて部門チーフが当日の売価を決める `【Typical】` |
| **何を確認するか** | 仕入原価／**狙う値入率**／**競合店の売価**／その商品が客にとって価格の比較対象になっているか／部門全体の粗利計画／端数（98円・198円など）の付け方のルール／**消費税の総額表示** |
| **何をするか** | 原価に値入を乗せて売価を計算する。競合店の価格を見て調整する。**売価マスタに登録する（情報システム機能へ依頼）**。プライスカードを手配する |
| **何を判断するか** | **いくらで売るか。** 値入を厚くすれば粗利は増えるが売れ数が落ちる。薄くすれば売れるが粗利が減る |
| **誰と連携するか** | 情報システム機能（売価マスタ登録）、店長・売場担当（売場への反映）、販促・販売企画機能（チラシ掲載価格との整合） |
| **最終的に何ができあがるか** | **定番売価（売価マスタ）**、プライスカード、値入率 |
| **頻度** | 月次／案件発生時（仕入価格の変動時）／生鮮は**日次** `【Varies】` |

> **値入（ねいれ）の計算**（`01_overview.md` 1-5 の再掲）
> ```
> 値入額 ＝ 予定売価 − 原価
> 値入率 ＝ 値入額 ÷ 予定売価
> ```
> `【Example】`（説明用の架空例）原価120円の豆腐に売価168円を付ける。
> 値入額48円、値入率28.6％。**この時点ではまだ「予定」です。**
> 実際には値下げ・廃棄が出るため、最終的な粗利率はこれより低くなります。

> **なぜこの業務が必要なのか**
> `【Inference】` 売価は「原価＋利益」で機械的に決まりません。
> 客は**同じ商品の他店の値段を知っている**からです。
> 特に卵・牛乳・食パン・豆腐など日々買われる商品は、客が価格をよく覚えているため、
> 原価に関係なく**近隣店と同水準にせざるを得ない**ことがあります。
> そのぶん他の商品で粗利を取る、という**部門全体・店全体での帳尻合わせ**が必要になります。

> **価格訴求商品（プライスライン商品／目玉商品）と粗利確保商品**
> `【Typical】` 小売業では、すべての商品で同じ値入率を取るわけではありません。
>
> | 種類 | 役割 | 値入の考え方 |
> |---|---|---|
> | **価格訴求商品**（卵・牛乳・特売の目玉） | **客を店に呼ぶ**ための商品 | 値入を薄くする。場合によっては原価割れに近い水準 `【Varies】` |
> | **粗利確保商品**（惣菜、こだわり商品、非食品） | **粗利を稼ぐ**商品 | 値入を通常どおり、または厚めに取る |
>
> 「1品ごとに儲けるのではなく、**買物カゴ全体で儲ける**」という考え方が小売業の値付けの基本です `【Typical】`。

> `【Fact】` 消費者に対して商品の価格を表示する場合、
> **消費税額を含めた支払総額の表示（総額表示）が義務づけられています**
> （出典：総額表示に関する主な質問／財務省）。
> したがって値札・チラシ・POPに載せる価格は、税込の支払額を明示する形にする必要があります。

#### ①-5 特売・チラシ商品の決定

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 販促カレンダーで決めた特売期間が近づいたとき／メーカー・卸からの**特売提案（特別価格の提示）**を受けたとき／季節行事の接近／競合店の動きを見たとき |
| **誰が行うか** | 商品調達機能（社長）＋販促・販売企画機能。**店長も意見を出す** `【Typical】` |
| **何を確認するか** | 特売原価（通常より安い仕入価格が出るか）／**確保できる数量**／納品日と店舗の作業負荷／売価をいくらにすれば客が反応するか／**その特売で部門の粗利がどれだけ落ちるか**／チラシの締切に間に合うか |
| **何をするか** | 仕入先に特売原価と数量を確認する。目玉商品と売価を決める。**必要数量を先に押さえる（特売発注）**。チラシ原稿に載せる商品・価格・写真を確定する |
| **何を判断するか** | **何を・いくらで・何個、特売にするか。** 安くしすぎれば粗利を失い、数量が足りなければ「チラシに載っているのに売り切れ」という事態になる |
| **誰と連携するか** | 仕入先、販促・販売企画機能（チラシ制作）、店長・売場担当（売場の確保と作業手配）、情報システム機能（売価の期間設定） |
| **最終的に何ができあがるか** | **特売計画（特売商品・売価・数量・期間）**、チラシ掲載内容、特売発注データ |
| **頻度** | 週次（特売の切り替え）／月次（販促カレンダーの確定） `【Varies】` |

> **なぜこの業務が必要なのか**
> `【Inference】` 特売は「安く売ること」が目的ではなく、**客に来てもらうこと**が目的です。
> 特売品そのものは粗利が薄くても、来店した客が他の商品も一緒に買えば、店全体の粗利は増えます。
> 逆に、特売品だけを買って帰る客が多ければ、**売上は増えたのに粗利は減る**という結果になります。

> **【重要】チラシ特売には「必ず売れる量を確保する」責任が伴う**
> `【Typical】` チラシに載せた商品が初日の早い時間に売り切れると、
> わざわざ来店した客の信頼を損ないます。
> そのため特売発注は「売れた分を補充する」定番発注とは考え方が逆で、
> **「これだけ売ると決めて、先に確保する」**という読み切りの発注になります（`04_end-to-end-process.md` A-2）。

#### ①-6 棚割の作成・見直し

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 新商品の導入／カット商品の発生／季節の切り替わり／売場の改装／販売実績を見た定期見直し |
| **誰が行うか** | 商品調達機能（社長）。**実際の棚の作り込みは売場担当**。メーカーの営業担当が棚割案を提案してくることもある `【Typical】` |
| **何を確認するか** | 棚の段数・幅・高さ／各商品の販売数量／**どの商品に何フェイス割り当てるか**／関連する商品が近くに並んでいるか／補充のしやすさ／重い商品が下段にあるか |
| **何をするか** | 棚の図面（棚割表）に商品を配置する。フェイス数を決める。売場担当に展開を指示する |
| **何を判断するか** | **どの商品をどこに何フェイス置くか。** よく売れる商品のフェイスを増やせば補充回数が減り欠品しにくくなるが、その分ほかの商品の場所がなくなる |
| **誰と連携するか** | 売場担当、店長、メーカー営業（提案を受ける場合）、販促・販売企画機能（エンド・平台の使い方との整合） |
| **最終的に何ができあがるか** | **棚割表（たなわりひょう）**、売場変更の指示 |
| **頻度** | 季節の変わり目（＝その他）／四半期〜半期 `【Varies】` ／案件発生時 |

> **棚割（たなわり）**（`04_end-to-end-process.md` A-1 の再掲）
> → 棚のどこに、どの商品を、何フェイス並べるかを決めた設計図のこと。
> → 実務例：「3段目の左からしょうゆA・B・C」と決めておけば、誰が補充しても同じ売場が再現されます。

> **なぜこの業務が必要なのか**
> `【Inference】` 棚割がないと、次の3つが起きます。
> 1. **人が替わるたびに売場が変わる。** 客が商品を見つけられなくなる
> 2. **補充の場所が分からない。** パート・アルバイトが自分で置き場所を判断することになる
> 3. **欠品に気づけない。** 「ここに何があるべきか」が決まっていないと、空いていても異常と分からない
>
> 棚割は「見た目を整える設計図」ではなく、**多人数で同じ売場を維持するための共通のルール**です。

#### ①-7 季節商品の仕込み（事前確保）

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 季節行事・商戦の接近（年末年始、節分、ひな祭り、春の行楽、土用、お盆、クリスマス等）／仕入先からの**予約受付の案内**（商戦の数か月前に始まることが多い `【Typical】`） |
| **誰が行うか** | 商品調達機能（社長）＋売場担当（部門チーフ）。数量の最終判断は社長 |
| **何を確認するか** | **前年同時期の販売実績**／今年の曜日の並び・行事の日取り／気温の見通し／仕入先の供給量と締切／確保に必要な資金／**売れ残ったときにどう処理するか** |
| **何をするか** | 予約数量を決めて仕入先に提出する。売場の確保と展開時期を決める。予約販売を行う場合は受付の仕組みを整える `【Varies】` |
| **何を判断するか** | **いくつ仕込むか。** 季節商品は**その期間を過ぎるとほぼ売れなくなる**ため、過剰は直接損失になる |
| **誰と連携するか** | 仕入先（メーカー・卸・産地）、店長、売場担当、販促・販売企画機能（チラシ・予約チラシ） |
| **最終的に何ができあがるか** | **季節商品の発注（確保）データ**、売場展開計画、予約受付の案内 |
| **頻度** | 発注時（商戦ごと）／年次（年間の商戦カレンダーの作成） |

> **なぜこの業務が必要なのか**
> `【Inference】` 季節商品は「売れてから追加発注する」ことができません。
> 商戦が始まってから作っても間に合わず、商戦が終われば売れ残りは値下げか廃棄になります。
> つまり**商戦の数週間〜数か月前の判断だけで、その商戦の結果が決まります**。
> 定番商品の発注（補充型）とは、判断の性質がまったく違う仕事です。

> `【Example】`（説明用の架空例）X社が年末に向けて数の子を仕込む。
> 11月の時点で「今年は○kg」と決めて確保する。
> 年末に売れ行きが鈍っても追加の仕入先は見つからず、余れば1月には売れない。
> **11月の判断が、12月末の粗利をほぼ決めてしまいます。**

#### ①-8 リベート・販売奨励金の交渉と確認

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 年間の取引条件を決めるとき／特売・大量仕入を行うとき／**請求書の照合で奨励金の反映を確認するとき**（＝請求時） |
| **誰が行うか** | 商品調達機能（社長）。金額の確認は経理・財務機能 |
| **何を確認するか** | 支払条件（どういう条件を満たせばいくら戻るのか）／対象期間／計算根拠となる数量・金額／**請求書や支払通知に正しく反映されているか** |
| **何をするか** | 仕入先と条件を取り決める。取り決めの内容を文書で残す。期間終了後に実績を突き合わせる |
| **何を判断するか** | 提示された条件を受けるか／条件を満たすために仕入量を増やすか（**増やした分が売れるかどうかとセットで判断する**） |
| **誰と連携するか** | 仕入先（メーカー・卸）、経理・財務機能 |
| **最終的に何ができあがるか** | **リベート（販売奨励金）の取り決め内容**、受取額の確認記録 |
| **頻度** | 年次（条件の取り決め）／月次・請求時（反映の確認） `【Varies】` |

> **リベート（販売奨励金・報奨金）**
> → 一定期間に一定量以上を仕入れた場合などに、仕入先から小売業者へ支払われる金銭のこと。
>   仕入代金の一部が後から戻ってくるような形になります。
> → 実務例：「年間で○ケース以上仕入れたら、1ケースあたり○円を支払う」といった取り決め。
>   この金額は**仕入原価を実質的に引き下げる**働きをします。
> `【Varies】` 名称・計算方法・支払方法（値引・現金・商品現物等）は取引先により大きく異なります。

> **なぜこの業務が必要なのか**
> `【Inference】` リベートは**帳簿上の仕入単価には現れないお金**です。
> 単価表だけを見て「A社のほうが安い」と判断すると、奨励金を含めた実質原価では逆だった、
> ということが起こり得ます。
> したがって仕入先の比較は、**単価と奨励金をセットで**見る必要があります。

#### ①-9 産地・メーカーとの関係構築

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 継続的な活動（＝常時）／産地の切り替わり時期／新しい産直の話が来たとき／品質・欠品のトラブルが起きたとき |
| **誰が行うか** | 商品調達機能（社長）、生鮮の部門チーフ |
| **何を確認するか** | 供給できる量と時期／品質・規格／価格の考え方／**天候不順時に優先的に回してもらえるか**／配送方法と費用／表示に必要な情報（産地・生産者名等） |
| **何をするか** | 産地・市場・メーカーを訪問する。商談する。産直商品の取り扱いを決める。トラブル時の連絡・調整を行う |
| **何を判断するか** | 継続的に取引するか／どの程度の量を任せるか |
| **誰と連携するか** | 産地（農協・生産者・漁協）、卸売市場の卸売業者・仲卸業者、メーカー、店長・売場担当 |
| **最終的に何ができあがるか** | **仕入ルートの確保**、産直商品の取扱い、相場・作柄の情報 |
| **頻度** | 常時（継続的な関係維持）／案件発生時 |

> **なぜこの業務が必要なのか**
> `【Typical】` 生鮮品は、**価格が事前に決まっていない**取引です（`02_industry-structure.md` 11-2）。
> その日の入荷量と引き合いで値が決まるため、
> 「どの小売店に優先的に良い品を回すか」は仕入先の裁量に左右される部分があります `【Inference】`。
> また台風・不作などで供給が絞られたとき、**普段の取引関係が量の確保に影響します**。
> この機能は、契約書には現れない部分の仕入力を支えています。

### ▼ Level 2：業態による商品調達機能の違い `【Varies】`

| 業態 | 商品調達の特徴 |
|---|---|
| **食品スーパー** | **生鮮の相場対応が日次で発生する**。加工食品は卸経由の定番管理が中心。品目数が多く、部門別に担当が分かれる |
| **専門店（衣料・雑貨・書籍等）** | **シーズン単位でまとめて仕入れる**。展示会・見本市での発注が中心になることがある `【Typical】`。仕入れた時点でそのシーズンの売上の上限が決まる。書籍は取次経由で、返品できる仕組みが使われてきた `【Typical】` |
| **ドラッグストア** | 医薬品・化粧品・日用品・食品の混在。**医薬品は取扱いに資格者の配置が必要**（`15_rules-customs.md`）。食品は集客のために価格を抑え、医薬品・化粧品で粗利を取る構成になりやすい `【Inference】` |
| **EC・通販** | **棚の物理的制約がないため品目数を多く持てる**。仕入れずに受注後に取り寄せる形態もある `【Varies】`。商品ページの情報（写真・説明文）を作る作業が商品調達とセットで発生する |
| **飲食併設型** | 商品ではなく**原材料**を仕入れる。レシピ（配合）に基づいて必要量を計算する。当日消化が前提のため在庫を持たない |

| **販売管理（POS）システム** | レジを通った商品・数量・金額を記録し、商品別の売上と在庫を把握するための仕組み |
| **商品マスタ管理／売価管理の仕組み** | 「何を扱っていて、いくらで売るか」を1か所に登録し、レジ・発注端末・プライスカードに反映させるための仕組み |
| **発注システム（EOS／Web発注）** | 仕入先へ発注内容を送るための仕組み |
| **表計算ソフト** | 値入の計算、特売計画、仕入先ごとの条件比較などに使われる `【Typical】` |

> **EOS（イーオーエス／Electronic Ordering System：電子発注システム）**
> → 発注の内容を、電話やFAXではなくデータで仕入先に送る仕組みのこと。
> → 実務例：発注端末で「この商品を3ケース」と入力すると、締め時刻に仕入先へ送信されます。

`【Varies】` X社規模では専用のMD（商品計画）システムを持たず、
POSの売上データと表計算ソフトで判断していることが多くあります `【Typical】`。

### N. 使用設備・道具

発注端末（ハンディターミナル）、パソコン、電話・FAX、
サンプル・試食用の設備（商談時）、卸売市場での買い付けに使う道具 `【Varies】`

### O. 見ている数字・KPI

| 数字 | 意味 | なぜ見るか |
|---|---|---|
| **値入率** | 売価に対する予定の利益幅 | 売価設定の妥当性を見る。粗利の出発点 |
| **粗利率（荒利率）** | 実際に残った利益幅 | 値入との差＝ロスがどれだけ出たかが分かる |
| **売上構成比（部門別・商品別）** | 何がどれだけ売れているか | 棚の配分が売上の配分と合っているかを見る |
| **販売数量（PI値）** | 客1,000人あたりの販売数 | 店の規模が違っても比較できる形で売れ行きを見る |
| **在庫金額・在庫日数** | 何日分の在庫を持っているか | 仕入れすぎていないかを見る |
| **欠品率** | 棚にあるべき商品が切れている割合 | 発注・納品が需要に追いついているかを見る |
| **導入品目数／カット品目数** | 出入りした商品数 | 品揃えが入れ替わっているかを見る |

> **PI値（ピーアイち／Purchase Index）**
> → **客1,000人あたり、その商品が何個売れたか**を表す数値のこと。
> → 実務例：ある日の客数が1,000人で、豆腐が80個売れたらPI値は80。
>   客数が1,500人の日に豆腐が100個売れた場合、個数は増えていますがPI値は約67に下がっています。
>   **客数の違いを取り除いて「売れ方そのもの」を比べられる**ため、発注や棚割の判断に使われます。

## ② 販促・販売企画機能

> **この機能を一言でいうと：「客に来てもらい、買ってもらうための仕掛けを作る仕事」**

### A. 部署・機能名

| 項目 | 内容 |
|---|---|
| **本資料での正式名称** | **販促・販売企画機能** |
| **一般的に使われる部署名・役職名** | 販促、販売促進、営業企画、チラシ担当、販促担当 |
| **層** | 本部 |

> **販促（はんそく／販売促進）**
> → 商品を売るために行う、価格以外も含めたさまざまな働きかけのこと。
> → 実務例：チラシを配る、店内にPOPを貼る、ポイントを付ける、試食を出す、
>   店頭にのぼりを立てる——これらはすべて販促です。

### B. 存在目的

小売業の売上は次の式で分解できます（`14_kpi.md`）。

```
売上 ＝ 客数 × 客単価
客単価 ＝ 1人あたり買上点数 × 1点あたり単価
```

販促・販売企画機能は、**このうち「客数」と「買上点数」を動かすため**に存在します。
どれだけ良い商品を揃えても、**その存在が客に伝わらなければ売上になりません**。

### C. 担当者

| 区分 | 誰が担うか |
|---|---|
| **大手チェーンの一般的な姿** `【Typical】` | 販促部が全店共通の年間販促計画とチラシを制作する |
| **X社での実態** `【Example】`／`【Typical】` | **社長＋事務担当1名**でチラシ内容と特売品を決める。**店長も意見を出す**。デザイン・印刷は外部の印刷会社に委託 `【Varies】` |
| **店内POP** | **売場担当が自分で手書きまたは簡易印刷で作る**ことが多い `【Typical】` |
| **SNS・Web発信** | `【Varies】` 行っている場合、社長・事務担当・店長のいずれかが兼務で担当する。専任者は置かないことが多い |

#### ②-1 販促カレンダーの作成

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 年度・シーズンの始まり／翌月の計画を立てる時期／行事カレンダーの確認時 |
| **誰が行うか** | 販促・販売企画機能（X社では**社長＋事務担当**）。店長が意見を出す |
| **何を確認するか** | 季節行事（正月、節分、ひな祭り、入学、行楽、土用、お盆、敬老、クリスマス等）／**地域の行事・学校行事**／前年同時期の売上と客数／給料日・年金支給日など客数が動く時期 `【Typical】`／競合店の販促パターン |
| **何をするか** | いつ・どういうテーマで・どの部門を主役にするかを月単位・週単位で決める。チラシの発行タイミングと枚数を決める |
| **何を判断するか** | **どの時期に販促を集中させるか。** 販促は費用がかかるため、効きやすい時期に寄せる |
| **誰と連携するか** | 商品調達機能（特売商品の手配が間に合うか）、店長（店舗の作業負荷）、印刷会社・折込業者 |
| **最終的に何ができあがるか** | **販促カレンダー（年間・月間）**、チラシ発行計画 |
| **頻度** | 年次（年間計画）／月次（翌月の確定） `【Varies】` |

> **なぜこの業務が必要なのか**
> `【Inference】` 販促には**準備期間**が必要だからです。
> チラシは原稿の締切から配布まで日数がかかり、特売商品は事前に数量を確保する必要があります。
> 「来週から特売をやろう」と思いついても、商品が手配できなければ実行できません。
> 販促カレンダーは、**商品の手配・チラシの制作・売場の準備・人員の配置を
> 同じタイミングに合わせるための時間割**です。

#### ②-2 チラシの企画・作成・配布 ★中小小売の主要な集客手段★

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 販促カレンダーで決めたチラシ発行日の接近／特売商品の決定／印刷会社の入稿締切 |
| **誰が行うか** | 販促・販売企画機能（社長＋事務担当）。デザイン・印刷は外部委託 `【Varies】` |
| **何を確認するか** | **掲載する商品と売価**（商品調達機能の決定と一致しているか）／**売価の税込表示**／写真の有無／掲載できる点数と紙面の配分／配布エリアと枚数／**商品の入荷日がチラシ期間に間に合うか**／景品表示法上の表示に問題がないか（`15_rules-customs.md`） |
| **何をするか** | 紙面のレイアウトを決める。目玉商品を大きく配置する。原稿を印刷会社に入稿する。**校正（誤字・価格の間違いの確認）**を行う。折込・ポスティングを手配する |
| **何を判断するか** | どの商品をどの大きさで載せるか／配布エリアと枚数をどうするか／**価格の誤りがないか（最終責任）** |
| **誰と連携するか** | 商品調達機能、店長・売場担当（売場の準備）、印刷会社、新聞折込業者・ポスティング業者 |
| **最終的に何ができあがるか** | **チラシ（完成原稿・印刷物）**、配布手配、店舗への事前連絡 |
| **頻度** | 週次 `【Varies】`（発行頻度は企業により異なる） |

> **なぜこの業務が必要なのか**
> `【Typical】` 食品スーパーの商圏は徒歩・自転車・車で来られる範囲に限られます。
> その範囲の世帯に**「今週この店に来る理由」**を伝える手段として、
> 新聞折込チラシ・ポスティングが広く使われてきました。
> チラシは単なる広告ではなく、**「客数を動かすためのスイッチ」**として運用されます。

> **【重要】チラシの価格ミスは重大な事故になる**
> `【Inference】` チラシに誤った安い価格を載せてしまうと、
> ①その価格で売らざるを得ない（信用のため）、②数量が想定を超えて欠品する、
> ③粗利が大きく削られる、という3つが同時に起きます。
> このため**校正は複数人で行うのが一般的**です `【Typical】`。

> **チラシ後の売場は「チラシと一致していること」が前提**
> `【Typical】` チラシに載っている商品が、
> - 売場にない（＝欠品）
> - 売場にあるが値段が違う（＝POSの売価設定漏れ）
>
> という状態は、クレームに直結します。
> したがってチラシを出すことは、**店舗に「その日までに売場を作る」作業を発生させる**ことでもあります。
> 販促と店舗運営が切り離せない理由がここにあります。

#### ②-3 店内POP・売場装飾のルール作りと手配

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 特売の開始／新商品の投入／季節売場の立ち上げ／売場の見直し |
| **誰が行うか** | 販促・販売企画機能（全店共通のもの）＋**売場担当（個別の手書きPOP）** `【Typical】` |
| **何を確認するか** | 表示している価格が**POSの売価と一致しているか**／表示内容に事実と異なる点がないか／**食品表示・景品表示のルールに反していないか**／取り外し忘れがないか |
| **何をするか** | 特売用のプライスカード・のぼり・売場装飾を手配し店舗へ送る。売場担当は商品の特徴や食べ方を書いたPOPを作る |
| **何を判断するか** | どの商品にPOPを付けるか／どういう言葉で伝えるか／期間終了後にいつ外すか |
| **誰と連携するか** | 売場担当、店長、商品調達機能（売価の確認）、POP・販促物の業者 `【Varies】` |
| **最終的に何ができあがるか** | **店内POP・プライスカード・のぼり等の販促物**、装飾された売場 |
| **頻度** | 週次（特売の切り替え）／日次（売場担当による個別POP） `【Varies】` |

> **POP（ポップ／Point of Purchase advertising：購買時点広告）**
> → 売場に置く小さな広告表示のこと。値札・手書きカード・のぼり・天井からの吊り下げなど。
> → 実務例：鮮魚売場に「今日入った○○。煮付けがおすすめ」と手書きで書いて貼る。
>   **店員が全員の客に説明することはできないため、POPが説明役を務めます。**

> **なぜこの業務が必要なのか**
> `【Inference】` 客は商品の前に立った数秒で買うかどうかを決めます。
> その場に「これは何か」「どう使うか」「なぜ今なのか」を伝える表示がなければ、
> 知らない商品は選ばれません。
> 特に生鮮品は、**調理法が分からないという理由で買われない**ことがあるため、
> 食べ方を書いたPOPが売れ行きを左右します `【Typical】`。

> **【重要】POPの外し忘れは価格トラブルになる**
> `【Typical】` 特売期間が終わったのに「○○円」のPOPが残っていると、
> レジで通常価格が表示され、客との間で認識の食い違いが生じます。
> **「付ける作業」と同じ重さで「外す作業」が管理される**のが売場の実務です。

#### ②-4 ポイント・会員施策の運用

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 制度の設計・変更時／ポイント倍付けなどの企画実施時／会員向け案内の発行時 |
| **誰が行うか** | 販促・販売企画機能（社長＋事務担当）。レジでの運用は**レジ・接客機能** |
| **何を確認するか** | ポイント付与率と**その原資（費用）**／有効期限／ポイント利用時のレジ処理／会員データの取扱い（個人情報の管理）／**会計上のポイント引当の扱い** `【Varies】` |
| **何をするか** | ポイント制度を設計・変更する。倍付けなどの企画を決める。レジ担当への説明資料を作る。会員向けの案内を出す `【Varies】` |
| **何を判断するか** | 付与率をどうするか／いつ倍付けをするか／**費用に見合う来店・購入の増加があるか** |
| **誰と連携するか** | レジ・接客機能、情報システム機能（POSの設定）、経理・財務機能（費用計上）、ポイントシステムの事業者 `【Varies】` |
| **最終的に何ができあがるか** | **ポイント制度のルール**、企画内容、会員データ |
| **頻度** | 年次（制度設計）／月次〜週次（企画の実施） `【Varies】` |

> **なぜこの業務が必要なのか**
> `【Typical】` 小売業の客は「誰が買ったか分からない」のが基本です（`01_overview.md` 1-4）。
> ポイントカード・会員制度は、**匿名の客を識別できるようにする仕組み**でもあります。
> ただし `【Varies】` 中小小売でそのデータを詳細に分析しているとは限らず、
> 「来店の動機付け」として運用されている場合も多くあります。

> `【Inference】` ポイントは実質的な値引きです。
> 付与率1％なら、売上100円につき1円の費用が将来発生します。
> X社（年商30億円）なら**年間3,000万円規模の話**になるため `【Example】`、
> 付与率の設定は粗利率の設計と一体で考える必要があります。

#### ②-6 販促効果の確認

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 特売・チラシ期間の終了／月次の締め |
| **誰が行うか** | 販促・販売企画機能（社長）＋店長 |
| **何を確認するか** | **チラシ期間の客数・売上・客単価**／前年同時期・直前週との比較／**掲載商品がどれだけ売れたか**／掲載商品以外も売れたか（ついで買いがあったか）／**部門の粗利がどれだけ落ちたか**／欠品が出なかったか |
| **何をするか** | 期間の数字を集計し、計画と比べる。次の販促の内容に反映する |
| **何を判断するか** | その販促を次も行うか／売価・数量・掲載の仕方を変えるか |
| **誰と連携するか** | 店長、売場担当、商品調達機能、経理・財務機能（数字の集計） |
| **最終的に何ができあがるか** | **販促結果の確認記録**、次回への申し送り |
| **頻度** | 週次（チラシ期間ごと）／月次 `【Varies】` |

> **なぜこの業務が必要なのか**
> `【Inference】` 販促は費用が先に出て、効果は後から現れます。
> チラシの印刷・折込費、値入を削った分の粗利、ポイント費用——これらはすべて先に発生します。
> **効果を確認しないと、同じ内容を繰り返すことになります。**
> 特に「売上は増えたが粗利は減った」というケースは、売上だけを見ていると気づけません。

#### ②-7 地域イベント・共同販促への参加 `【Varies】`

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 商店街組合・商工会議所・自治体からの案内／ショッピングセンター入居の場合は館の共通販促の案内（＝案件発生時） |
| **誰が行うか** | 社長、店長 |
| **何を確認するか** | 参加費・負担金／自店に必要な準備（商品・人員・売場）／開催日と店舗の営業への影響 |
| **何をするか** | 参加の可否を決め、必要な商品・人員・販促物を手配する |
| **何を判断するか** | 参加するか／どの程度の規模で関わるか |
| **誰と連携するか** | 商店街組合、商工会議所、自治体、ショッピングセンター運営者、店長 |

## ③ 店舗開発機能

> **この機能を一言でいうと：「どこに・どういう形の店を持つかを決め、店という器を維持する仕事」**

### A. 部署・機能名

| 項目 | 内容 |
|---|---|
| **本資料での正式名称** | **店舗開発機能** |
| **一般的に使われる部署名・役職名** | 店舗開発、開発、施設、営繕（えいぜん）、設備担当 |
| **層** | 本部 |

### B. 存在目的

`【Typical】` 小売業、特に食品スーパーでは、**立地がほぼ売上を決めます**（`01_overview.md` 1-6）。
商圏内の世帯数・通行量・競合店の配置が、その店の売上の上限を作ります。
店舗開発機能は、**「どこに、どのくらいの大きさで、いくらの費用で店を持つか」を決め、
決めた後はその建物・設備を売れる状態に保つため**に存在します。

`【Inference】` また小売業では、店舗の賃料・減価償却費・設備の保守費が**売上がゼロでも発生する固定費**です。
この固定費の水準は出店時にほぼ決まるため、**出店の判断は取り返しがつきにくい**という性質があります。

### C. 担当者

| 区分 | 誰が担うか |
|---|---|
| **大手チェーンの一般的な姿** `【Typical】` | 店舗開発部が候補地を継続的に調査し、出店計画を立てる |
| **X社での実態** `【Example】`／`【Typical】` | **常設の機能ではない。** 出店・改装の案件が発生したときに**社長が直接対応**する |
| **日常の設備管理** | **店長**が日常点検と一次対応を行い、修理は保守業者に依頼する `【Typical】` |
| **外部の関与** | 不動産業者、設計事務所・工事会社、什器・冷凍冷蔵設備のメーカー、金融機関 `【Varies】` |

> `【Typical】` 中小小売業では、出店は「数年に一度あるかないか」の出来事です。
> したがって専任者を置かず、**案件が起きたときに社長が外部の専門家と組んで進める**のが一般的です。
> 一方、**設備の故障対応は日常的に発生する**ため、そちらは店長の仕事として常設化しています。

#### ③-1 出店候補地の調査（商圏調査）

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 不動産業者・金融機関からの物件情報の持ち込み／既存店の建替え・移転の検討／競合店の撤退で空白地ができたとき（＝案件発生時） |
| **誰が行うか** | 社長（X社では店舗開発機能＝社長本人） |
| **何を確認するか** | **商圏内の世帯数・人口構成**／前面道路の通行量／**駐車場が確保できるか**（`【Fact】` 食品スーパーの専用駐車場は平均130.9台、売場1,000㎡あたり平均93.5台。2024年、出典：2024年スーパーマーケット年次統計調査報告書）／**競合店の位置と規模**／賃料・保証金の水準／建物の構造（電気容量・給排水・搬入口・荷受スペース）／**大規模小売店舗立地法の対象になるか** `【Fact】`（出典：大規模小売店舗立地法／e-Gov法令検索）／営業許可が取れる施設にできるか |
| **何をするか** | 現地を複数回・複数時間帯に見る。周辺を歩いて客層を確認する。売上の見込みを立てる。必要な投資額と回収の見通しを試算する |
| **何を判断するか** | **出店するか／しないか。** 見込み売上と、賃料・人件費・投資額の回収が見合うか |
| **誰と連携するか** | 不動産業者、家主、金融機関、設計事務所、自治体（都市計画・用途地域の確認）、保健所（営業許可の事前相談） |
| **最終的に何ができあがるか** | **出店可否の判断**、売上見込みと投資計画 |
| **頻度** | 案件発生時 `【Varies】` |

> **商圏（しょうけん）**
> → その店に客が来てくれる地理的な範囲のこと。
> → 実務例：食品スーパーなら「徒歩・自転車で10分以内」「車で5分以内」といった範囲を指します。
>   この範囲にどれだけの世帯が住んでいるかが、その店の売上の上限を作ります。
>   **商圏の外に住む人は、原則としてその店の客にはなりません。**

> **なぜこの業務が必要なのか**
> `【Inference】` 出店してしまった後では、立地は変えられないからです。
> 商品は入れ替えられ、売価は変えられ、人は配置し直せますが、**店の場所だけは動かせません**。
> したがって小売業では、出店の判断が事業の成否に対して極めて大きな比重を占めます。

#### ③-2 賃貸借契約・出店条件の決定

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 出店を決めたとき／既存店の契約更新時（＝法定・契約上のタイミング） |
| **誰が行うか** | 社長。契約内容の確認に専門家（弁護士・不動産業者）が関わることがある `【Varies】` |
| **何を確認するか** | **賃料（固定賃料か、売上歩合か、併用か）** `【Varies】`／保証金・敷金の額と返還条件／契約期間と更新条件／中途解約の条件と違約金／**原状回復の範囲**／営業時間・休業日の制限／共益費・看板使用料（ショッピングセンター入居の場合） |
| **何をするか** | 条件を交渉する。契約書の内容を確認する。契約を締結する。保証金・敷金を支払う |
| **何を判断するか** | その条件で契約するか／**賃料が見込み売上に対して重すぎないか** |
| **誰と連携するか** | 家主・ショッピングセンター運営者、不動産業者、金融機関、経理・財務機能（資金手当て） |
| **最終的に何ができあがるか** | **賃貸借契約書**、出店条件（賃料・期間・営業時間） |
| **頻度** | 案件発生時／法定・契約上のタイミング（更新） |

> **売上歩合賃料（うりあげぶあいちんりょう）**
> → 賃料の一部または全部を、**その店の売上の一定割合**として払う方式のこと。
> → 実務例：「売上の○％を賃料として払う」という契約。売上が下がれば賃料も下がる一方、
>   売上が伸びれば賃料も増えます。ショッピングセンターに入居する場合に使われることがあります `【Varies】`。
>   この方式では、**ショッピングセンター運営者に日々の売上を報告する業務**が発生します。

> **なぜこの業務が必要なのか**
> `【Inference】` 賃料は、売上がゼロの日でも発生します。
> 天候不良で客数が半分になった日も、賃料は満額です。
> したがって賃料の水準は、**その店が耐えられる売上の下限**を決めることになります。
> 契約時の数％の差が、契約期間全体では大きな金額になります。

#### ③-3 店舗レイアウト・什器計画

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 新規出店／改装の決定／部門構成の変更（惣菜売場の拡大など） |
| **誰が行うか** | 社長＋設計事務所・什器メーカー。**店長・売場担当が現場の意見を出す** `【Typical】` |
| **何を確認するか** | **売場とバックヤードの面積配分**（`【Fact】` 食品スーパーのバックヤード比率は平均30.5％。2024年、同調査）／入口から出口までの客の動線／**部門の配置順**／レジの台数と位置（`【Fact】` 売場1,000㎡あたり平均6.4台。2024年、同調査）／冷蔵・冷凍ケースの配置と電気容量／搬入口からバックヤード、売場への商品の動線／加工場（鮮魚・精肉・惣菜）の位置と衛生区分／**保健所の施設基準を満たすか** `【Fact】`（食品衛生法に基づく営業許可。出典：食品衛生法／e-Gov法令検索） |
| **何をするか** | レイアウト図を作る。什器（ゴンドラ・冷蔵ケース・平台）を選定・発注する。工事を発注する |
| **何を判断するか** | どの部門をどこに置くか／何にいくら投資するか／**バックヤードをどれだけ取るか**（売場を広げれば売上は増えやすいが、作業スペースが足りなくなる） |
| **誰と連携するか** | 設計事務所・工事会社、什器・冷凍冷蔵設備メーカー、保健所、消防署、店長・売場担当、商品調達機能（棚割との整合） |
| **最終的に何ができあがるか** | **店舗レイアウト図**、什器計画、工事の発注内容 |
| **頻度** | 案件発生時 |

> **動線（どうせん）**
> → 人やモノが移動する経路のこと。**客動線**と**作業動線**の2つがあります。
> → 実務例：入口に青果を置き、奥に鮮魚・精肉を置き、レジ前に日配を置く、という配置は
>   客に売場を広く歩いてもらうための客動線の設計です。
>   一方、荷受場から冷蔵庫までが遠いと、**冷蔵品を運ぶ時間が長くなって鮮度が落ちる**——
>   これは作業動線の問題です。

> **なぜこの業務が必要なのか**
> `【Inference】` レイアウトは、日々の作業時間（＝人件費）を長期にわたって固定します。
> バックヤードから売場までの距離が10m長いだけで、
> 品出しのたびに余分な歩行が発生し、それが毎日・全員分・何年も積み重なります。
> **レイアウトは「見た目の設計」ではなく、日々の人時を決める設計**です。

|---|---|
| **何をきっかけに始まるか** | 什器・設備の老朽化／部門構成の変更／競合店の出店・改装／契約更新のタイミング（＝案件発生時） |

| **何を判断するか** | どこまで改装するか／**休業日数をどう取るか**（休業日数だけ売上がゼロになる） |

> **なぜこの業務が必要なのか**
> `【Inference】` 什器・設備は使い続ければ劣化します。
> 冷蔵ケースの冷えが甘くなれば商品の鮮度が落ち、照明が暗くなれば売場が古びて見えます。
> ただし改装には**工事費と休業による売上減**という二重の負担が伴うため、
> 「いつ・どこまでやるか」の判断が重くなります。

| **何を確認するか** | 冷蔵・冷凍ケースの**庫内温度**／空調・照明の状態／給排水／電気設備／消防設備／POSレジ・決済端末の稼働／**故障時にどの商品に影響が出るか** |
| **何をするか** | 日常点検を行い記録する。異常があれば保守業者を呼ぶ。故障時は**商品の退避（他のケースや冷蔵庫へ移す）**を指示する。更新時期が来た設備の入れ替えを計画する |
| **何を判断するか** | 修理するか／入れ替えるか／**商品を退避させるか、廃棄するか** |
| **誰と連携するか** | 保守業者（冷凍冷蔵・空調・POS・決済端末）、店長・売場担当、経理・財務機能（修繕費・設備投資の支払）、保健所（食品に影響が出た場合） |

> **なぜこの業務が必要なのか**
> `【Inference】` 小売業では、**設備が止まると商品が失われます**。
> 冷凍ケースが一晩止まれば、そこにある商品はすべて廃棄になる可能性があります。
> 停電・冷媒漏れ・ファンの故障は予告なく起きるため、
> **温度の日常確認と、異常時に商品をどこへ移すかの段取り**が実務上の要点になります。
>
> `【Typical】` また、食品を扱う営業では衛生管理の一環として温度の記録が求められます。
> これは「記録のための記録」ではなく、**異常が起きたときに、いつからおかしかったのかを
> 追跡できるようにするため**の記録です。

## ④ 経理・財務機能

> **この機能を一言でいうと：「入ってきたお金と出ていくお金を、正しく記録し、確実に回す仕事」**
> 小売業の経理は、**毎日多額の現金が物理的に存在する**点で他業界と決定的に違います。

### A. 部署・機能名

| 項目 | 内容 |
|---|---|
| **本資料での正式名称** | **経理・財務機能** |
| **一般的に使われる部署名・役職名** | 経理、財務、管理部、総務経理、事務 |
| **層** | 本部 |

### B. 存在目的

小売業は、**1日に何百〜何千件の販売**と、**多数の仕入先からの毎日の納品**が並行して起きる業種です。
経理・財務機能は、

1. **売れたお金（現金・キャッシュレス）を1円単位で確定させ、確実に会社の口座に収める**
2. **仕入代金を正しい金額だけ、期日に支払う**
3. **会社が今いくら持っていて、いくら払う必要があるかを把握する**

ために存在します。

`【Inference】` 営業利益率がほぼ±0の業種（`【Fact】` 売上高30億円未満の食品スーパーで平均▲0.32％、2024年）では、
**現金の差異やロスの把握漏れが、そのまま赤字の原因**になります。
経理の精度は、この業界では直接的に損益に効きます。

### C. 担当者

| 区分 | 誰が担うか |
|---|---|
| **大手チェーンの一般的な姿** `【Typical】` | 経理部・財務部が分かれ、売上管理・買掛管理・資金管理を担当者ごとに分ける |
| **X社での実態** `【Example】`／`【Typical】` | **事務担当2名**が、売上金の確認・請求書照合・支払・給与計算まで一手に行う |
| **決算・税務** | **税理士に依頼する**ことが多い `【Varies】` |
| **資金繰りの最終判断** | **社長** |
| **店舗側の分担** | **レジ締め・現金の実査・銀行入金は店長**が行う（本部は報告を受けて照合する） |

> `【Typical】` 中小小売業の経理は「本部で完結する仕事」ではありません。
> **現金が実際にあるのは店舗**なので、店舗と本部が毎日データと現金でつながっています。

#### ④-1 日々の売上金管理

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 各店舗からの**日報（売上報告）**の到着（＝日次） |
| **誰が行うか** | 経理・財務機能（事務担当）。店舗側の実行者は店長 |
| **何を確認するか** | **POSが示す売上金額と、日報の金額が一致しているか**／決済手段別の内訳（現金・カード・コード決済・電子マネー・商品券）／**現金過不足の有無と金額**／返品・取消の件数と内容／釣銭準備金の残高／**銀行への入金額と日報の現金売上が一致しているか** |
| **何をするか** | 全店の日報を集計する。POSデータと突き合わせる。銀行の入金記録と照合する。差異があれば店長に確認する |
| **何を判断するか** | 差異を許容できる範囲か／調査が必要か／**会計上どう処理するか（現金過不足の計上）** |
| **誰と連携するか** | 店長、レジ・接客機能、金融機関 |
| **最終的に何ができあがるか** | **日次の売上集計**、入金の確認記録、現金過不足の記録 |
| **頻度** | **日次** |

> **なぜこの業務が必要なのか**
> `【Inference】` 小売業の売上は、**請求書のような証拠書類から生まれません**。
> レジを通った記録（POSデータ）と、実際の現金・決済記録だけが根拠です。
> この2つが一致していることを毎日確認しない限り、
> **「いくら売れたか」を会社として確定できません**。
>
> また現金は、誰が触ったかの記録が残らない資産です。
> 日をまたぐと差異の原因を追えなくなるため（`04_end-to-end-process.md` A-12）、
> **その日のうちに突き合わせる**必要があります。

> **初心者が間違えやすい点：売上 ≠ 入金**
> 小売業は「その場で代金を受け取る」ため、売上＝入金だと思われがちです。
> しかし**キャッシュレス決済の分は、売上は今日立ちますが、入金は後日**です（④-3）。
> 「今日の売上100万円」のうち、今日現金として手元に入るのは一部だけ、という状態が常態です。

#### ④-2 レジ現金の照合・現金過不足の処理

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | レジ締めの報告／**現金過不足が発生したとき**（＝日次／トラブル発生時） |
| **誰が行うか** | 店舗側：レジ担当＋店長。本部側：経理・財務機能 |
| **何を確認するか** | **レジごとの過不足額**／発生したレジ・時間帯・担当者／POSの取消・返品の記録／釣銭の受け渡しに関する記録／高額紙幣の授受 |
| **何をするか** | レジ単位で現金を数え直す。POSの記録を遡って確認する。**原因が特定できない場合は現金過不足として記録**する |
| **何を判断するか** | 原因が特定できるか／再発防止のために何を店舗に伝えるか／**金額が大きい場合の扱い** |
| **誰と連携するか** | 店長、レジ・接客機能 |
| **最終的に何ができあがるか** | **現金過不足の記録**、原因の確認結果 |
| **頻度** | **日次**（照合）／トラブル発生時（原因調査） |

> **現金過不足（げんきんかふそく）**
> → 帳簿上あるべき現金の額と、実際に数えた現金の額が食い違っている状態、およびその差額のこと。
> → 実務例：POSが「本日の現金売上85万円」と示しているのに、
>   レジの中身から釣銭準備金を引いた額が84万9,000円だった。この1,000円が現金過不足（不足）です。

> **なぜこの業務が必要なのか**
> `【Inference】` 現金過不足の多くは、釣銭の渡し間違いやレジ操作の誤りといった単純な原因です。
> しかし放置すると、**それが単純な誤りなのか、別の問題なのかが区別できなくなります**。
> 金額の大小よりも、**「毎日必ず確認している状態」を保つこと自体**に意味があります。

#### ④-3 キャッシュレス決済の入金管理 ★小売業固有★

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 決済事業者からの**入金（＝入金時）**／締め日の到来（＝法定・契約上のタイミング）／入金明細・精算書の受領 |
| **誰が行うか** | 経理・財務機能（事務担当） |
| **何を確認するか** | **決済手段ごとの売上高**（POS側の記録）と、**決済事業者からの入金額が一致しているか**／**差し引かれている決済手数料の額と率**／入金サイクル（締めから何日後に入るか）／**チャージバック・取消の反映**／複数の決済事業者ごとの明細 |
| **何をするか** | 決済事業者ごとの売上と入金を突き合わせる。手数料を費用として計上する。入金予定を資金繰り表に反映する |
| **何を判断するか** | 差異があった場合に決済事業者へ問い合わせるか／入金の遅れが資金繰りに影響しないか |
| **誰と連携するか** | 決済事業者（カード会社・決済代行会社・コード決済事業者）、金融機関、店長、社長（資金繰り） |
| **最終的に何ができあがるか** | **決済手段別の入金確認記録**、決済手数料の計上、資金繰り表への反映 |
| **頻度** | **月次**（締め・精算）／**日次**（売上データの送信・確認） `【Varies】` |

> **なぜこの業務が必要なのか**
> `【Fact】` 食品スーパーの現金以外の決済手段の導入率は95.6％（2024年、業界推計値。
> 出典：2024年スーパーマーケット年次統計調査報告書）。
> `【Fact】` 日本のキャッシュレス決済比率は2023年に39.3％
> （出典：キャッシュレス・ロードマップ2024／一般社団法人キャッシュレス推進協議会）。
>
> `【Inference】` つまり売上の相当部分が「今日は現金にならない売上」です。
> この部分は、
> 1. **入金が後日になる**（＝資金繰りに影響する）
> 2. **決済手数料が引かれる**（＝入金額は売上額より少ない）
> 3. **決済事業者が複数ある**（＝それぞれ締め日・入金日・手数料率が違う）
>
> という3つの理由から、**現金とはまったく別の管理が必要**になります。
> `【Varies】` 入金サイクルと手数料率は契約により大きく異なるため、一般化した数値は示しません。

> **【重要】「即時決済」と「即時入金」は違う**
> レジでの支払いが完了することと、会社の口座にお金が入ることは別の出来事です。
> 小売業の資金繰りを理解するうえで、ここが最初の分かれ目になります（`08_money.md`）。

#### ④-4 仕入計上

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 店舗での**検収の完了**（A-5／＝納品時） |
| **誰が行うか** | 店舗（検収データの登録）→ 経理・財務機能（会計上の計上） |
| **何を確認するか** | 品目・数量・単価・金額／仕入先ごとの計上区分／**買取仕入か、委託・消化仕入か**（消化仕入は売れた時点で計上するため、納品時には計上しない）／返品・値引が反映されているか／店舗別の区分 |
| **何をするか** | 検収データを仕入として会計上記録する。仕入先別・店舗別・部門別に積み上げる |
| **何を判断するか** | 取引形態に応じた計上のタイミング／締め日をまたぐ取引の帰属 |
| **誰と連携するか** | 店舗（バックヤード機能・店長）、仕入先 |
| **最終的に何ができあがるか** | **仕入データ（仕入先別・日別・店舗別）** |
| **頻度** | **日次**（納品時） |

> **なぜこの業務が必要なのか**
> `【Inference】` 仕入を日々記録していないと、月末になって「今月いくら仕入れたか」が分かりません。
> 仕入額が分からなければ、**粗利も、払うべき金額も計算できません**。
> また、仕入先から届く請求書が正しいかどうかを判断する材料（自社側の記録）が存在しなくなります。

> **初心者が間違えやすい点：発注 ≠ 仕入計上**（`04_end-to-end-process.md` A-5 の再掲）
> 注文しただけでは仕入になりません。**モノを受け取って検収した時点**で仕入が立ちます。

#### ④-5 請求書照合（買掛照合）★小売業で最も件数の多い経理業務★

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 仕入先からの**請求書の到着**（＝請求時）。締め日の後、仕入先ごとに順次届く |
| **誰が行うか** | 経理・財務機能（X社では事務担当） |
| **何を確認するか** | **請求金額と自社の仕入計上額が一致しているか**／単価は取り決めどおりか／**返品・値引・リベート（販売奨励金）が反映されているか**／締め期間は合っているか／店舗別の内訳／**適格請求書（インボイス）の記載事項が揃っているか** `【Fact】`（消費税の仕入税額控除には、原則として適格請求書等の保存が必要。出典：適格請求書等保存方式（インボイス制度）／国税庁） |
| **何をするか** | 請求書と自社の仕入データを1件ずつ突き合わせる。差異があれば店舗に検収内容を確認し、仕入先に問い合わせる |
| **何を判断するか** | **この金額で支払ってよいか／保留して確認するか** |
| **誰と連携するか** | 仕入先、店舗（バックヤード機能・店長／検収内容の確認）、商品調達機能（単価・リベートの取り決めの確認） |
| **最終的に何ができあがるか** | **照合済みの請求書**、差異の問い合わせ記録 |
| **頻度** | **月次**（請求時） |

> **なぜこの業務が必要なのか**（`04_end-to-end-process.md` B-5 の再掲と補足）
> `【Inference】` 請求書の金額が常に正しいとは限りません。
> 返品したはずの商品が請求に含まれている、特売で下げたはずの単価が通常単価で計算されている、
> 別の店舗の納品分が混ざっている——これらは実務上起こり得ます。
>
> **A-4の検品が「モノの正しさ」を守る工程なら、この照合は「金額の正しさ」を守る工程**です。
> 検品と照合の両方があって初めて、払うべき金額だけを払うことができます。

> **【重要】小売業の請求書照合は件数が多い**
> `【Inference】` 小売業は取扱品目が多く（X社で1店舗あたり約1万5,000品目 `【Example】`）、
> 仕入先も多数あり、納品は毎日複数便あります。
> したがって1か月分の請求書は、**仕入先の数だけ届き、その中身は数百〜数千行**になります。
> この照合作業が、中小小売の経理業務の中で大きな比重を占めます。

#### ④-6 買掛金計上と支払

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 請求書の照合完了（B-6）／**支払期日の到来**（B-7／＝法定・契約上のタイミング） |
| **誰が行うか** | 経理・財務機能。**支払実行の承認は社長** |
| **何を確認するか** | 支払期日／支払方法（振込・手形等） `【Varies】`／振込先口座／**口座に十分な残高があるか**／相殺すべきもの（返品・リベート）があるか |
| **何をするか** | 買掛金として記録し、支払予定表に載せる。期日に振込等で支払う。支払後に買掛金を消し込む |
| **何を判断するか** | **資金が不足する場合の手当て**（借入、支払時期の相談、入金の前倒し） |
| **誰と連携するか** | 社長（承認・資金繰り）、仕入先、金融機関 |
| **最終的に何ができあがるか** | **買掛金残高**、**支払予定表**、支払記録、買掛金の消込 |
| **頻度** | **月次**（法定・契約上のタイミング） |

> **買掛金（かいかけきん）**（`04_end-to-end-process.md` B-6 の再掲）
> → 商品を仕入れたが、まだ代金を払っていない金額のこと。
> → 実務例：11月中に1,800万円分を仕入れ、支払いは12月末という場合、
>   11月末時点で1,800万円の買掛金があります。
>   **「商品はもう店にあり、売れているのに、まだ払っていないお金」**です。

> **なぜこの業務が必要なのか**
> `【Inference】` 支払は、遅れると取引関係そのものに影響します。
> 小売業は**毎日商品を納めてもらわないと営業できない**業種なので、
> 仕入先との関係が止まることは、そのまま店が回らなくなることを意味します。
> したがって支払は「事務作業」ではなく、**事業継続の前提条件**として扱われます。

> **消込（けしこみ）**
> → 支払や入金があったときに、「この請求のこの分が払われた」と対応づけて、
>   残高から消していく作業のこと。
> → 実務例：買掛金1,850,000円のうち1,850,000円を振り込んだので、その分の残高をゼロにする。
>   これをしないと、**払ったのに未払いのまま残っている**状態になり、二重払いの原因になります。

#### ④-7 経費の処理と支払

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 請求書・領収書の到着（＝請求時）／店舗からの小口現金の精算報告／支払期日の到来 |
| **誰が行うか** | 経理・財務機能（事務担当） |
| **何を確認するか** | 費用の内容と金額／**どの店舗・どの費目のものか**／契約どおりの金額か（賃料・保守費・リース料など）／領収書・請求書が揃っているか／**小口現金の残高と使途** |
| **何をするか** | 費目別・店舗別に記録する。支払う。小口現金を補充する |
| **何を判断するか** | 費目の分類／店舗への配賦／金額に疑問があれば確認するか |
| **誰と連携するか** | 店長（店舗で発生した経費）、家主、保守業者、印刷会社、廃棄物処理業者、金融機関 |
| **最終的に何ができあがるか** | **経費の記録（費目別・店舗別）**、支払記録、小口現金出納帳 |
| **頻度** | **月次**（多くの支払）／日次（小口現金） `【Varies】` |

> **小口現金（こぐちげんきん）**
> → 日常のこまごまとした支払いのために、店舗や事務所に置いておく少額の現金のこと。
> → 実務例：消耗品の買い足し、切手代、急な修理の支払いなどに使います。
>   **小売業では売上金と小口現金が同じ店舗内にある**ため、
>   「どちらのお金か」を区別して管理する必要があります。

> **なぜこの業務が必要なのか**
> `【Inference】` 小売業の営業利益はほぼ±0の水準です（`【Fact】` 売上高30億円未満で平均▲0.32％、2024年）。
> 粗利7.8億円から人件費約4.0億円を引き、残りで家賃・水道光熱費・消耗品・広告販促費・
> 配送費・保守費を払うと、ほとんど残りません `【Example】`（`03_company-structure.md`）。
> **どの費用が、どの店で、いくら発生しているかを把握できなければ、
> 赤字の店がどこなのかも分かりません。**

#### ④-8 月次決算（試算表の作成）

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 月末の到来（＝月次） |
| **誰が行うか** | 経理・財務機能。**税理士の確認を受けることが多い** `【Varies】` |
| **何を確認するか** | 月の売上（店舗別・部門別）／**仕入と在庫の増減**／人件費／その他の経費／**粗利率が計画と比べてどうか**／前年同月との比較／店舗別の損益 |
| **何をするか** | 月の取引をすべて記録し終え、試算表を作る。売上原価を計算する（在庫の変動を反映）。社長へ報告する |
| **何を判断するか** | 数字に異常がないか／**粗利率が落ちている場合、原因はどこか**（値入か、ロスか、商品構成か） |
| **誰と連携するか** | 社長、店長、税理士 `【Varies】`、金融機関（報告を求められる場合） `【Varies】` |
| **最終的に何ができあがるか** | **月次試算表**、店舗別・部門別の損益、社長への報告資料 |
| **頻度** | **月次** |

> **試算表（しさんひょう）**
> → その時点までの取引をすべて集計した、決算書の途中経過にあたる表のこと。
> → 実務例：「今月の売上は2億5,000万円、仕入は1億8,500万円、粗利率は25.8％」
>   といった数字が並びます。**1年待たずに、毎月経営の状態を確認するための道具**です。

> **なぜこの業務が必要なのか**
> `【Inference】` 年に1回の決算だけでは、問題に気づくのが遅すぎます。
> 粗利率が1ポイント落ちていることに11か月気づかなければ、
> X社の規模なら年間3,000万円規模の差になります `【Example】`（`03_company-structure.md`）。
> **月次で見るからこそ、発注・値入・ロスのどこがずれているのかを追える**ようになります。

> **【重要】月次の粗利は「在庫をどう見るか」で変わる**
> `【Inference】` 売上原価は「期首在庫 ＋ 期中の仕入 − 期末在庫」で計算します（A-14）。
> 毎月棚卸をしない場合、月次の在庫は推計値になります `【Varies】`。
> そのため**月次の粗利率は目安であり、確定するのは棚卸を行ったとき**です。
> 小売業の数字を読むときは、この違いを押さえておく必要があります。

#### ④-9 資金繰り

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 月次・週次の資金確認／大きな支払の前／季節商戦前の仕入増加時／出店・改装の計画時／借入の返済期日 |
| **誰が行うか** | 経理・財務機能（資金繰り表の作成）＋**社長（最終判断）** |
| **何を確認するか** | **口座残高**／今後の入金予定（現金売上・キャッシュレスの入金・法人売掛金の回収 `【Varies】`）／今後の支払予定（買掛金・人件費・賃料・税金・借入返済）／**入金と支払のタイミングのずれ** |
| **何をするか** | 資金繰り表を作る。不足が見込まれる時期を特定する。金融機関と借入・返済の相談をする |
| **何を判断するか** | **資金が足りるか／足りない場合どう手当てするか** |
| **誰と連携するか** | 社長、金融機関、仕入先（支払時期の相談が必要な場合）、商品調達機能（大量仕入の時期） |
| **最終的に何ができあがるか** | **資金繰り表**、借入・返済の計画 |
| **頻度** | **月次**（資金繰り表）／週次〜日次（口座残高の確認） `【Varies】` |

> **資金繰り表（しきんぐりひょう）**
> → いつ・いくら入って、いつ・いくら出ていくかを時系列に並べた表のこと。
> → 実務例：「12月末に仕入代金1,850万円、給与3,300万円、賞与、賃料の支払いが重なる。
>   一方でクリスマス・年末商戦の売上が入る」——この重なりを事前に見るための表です。

> **なぜこの業務が必要なのか**
> `【Inference】` 小売業は「先に入って、後から出ていく」構造のため、
> 通常時は比較的資金が回りやすい業種です（`04_end-to-end-process.md` 4-3）。
> しかし次の場合、この関係は逆転します。
> - **季節商戦の前倒し仕入**（売れる前に支払期日が来る）
> - **新店の開店**（大量の初期在庫を仕入れてから売上が立つ）
> - **在庫が増えたとき**（払う義務だけが先に立つ）
> - **キャッシュレス比率の上昇**（入金が後ろにずれる）
>
> つまり資金繰りは「現金商売だから安心」ではなく、
> **入金と支払のタイミングを合わせ続ける仕事**です。

#### ④-10 棚卸に基づく売上原価の確定 ★小売業の粗利はここで決まる★

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | **棚卸の実施**（A-14／決算期末は必須。月次・四半期に行う企業もある `【Varies】`） |
| **誰が行うか** | 店舗（カウント）→ 経理・財務機能（集計・評価）。税理士の確認を受けることがある `【Varies】` |
| **何を確認するか** | 店舗・部門ごとの**実在庫の数量と金額**／帳簿上の在庫（理論在庫）との差／**不明ロスの金額**／評価の方法（原価法・売価還元法など） `【Varies】`／販売できない在庫（期限切れ・傷み・シーズン落ち）が含まれていないか |
| **何をするか** | 棚卸表を集計する。在庫金額を確定する。**売上原価 ＝ 期首在庫 ＋ 期中の仕入 − 期末在庫** で原価を計算する。粗利を確定する。不明ロスを把握する |
| **何を判断するか** | 差異の原因（記録漏れか、不明ロスか）／在庫の評価をどうするか／店舗・部門への報告内容 |
| **誰と連携するか** | 店長、売場担当、社長、税理士 `【Varies】` |
| **最終的に何ができあがるか** | **確定した在庫金額**、**確定した売上原価と粗利**、**不明ロスの金額** |
| **頻度** | **年次**（決算時は必須）／月次・四半期 `【Varies】` |

> **なぜこの業務が必要なのか**（`04_end-to-end-process.md` A-14 の再掲と補足）
> `【Inference】` 小売業では、**在庫金額が確定しない限り粗利が確定しません**。
> 日々のPOSデータで見ている粗利は、値下げ・廃棄を反映した「理論値」であり、
> **万引きや記録漏れによる不明ロスは含まれていません**。
> 棚卸をして初めて、その差が金額として現れます。

> **不明ロス（棚卸ロス）**（`01_overview.md` 1-5 の再掲）
> → 帳簿上あるはずの在庫が、実際には存在しない分のこと。
> → 実務例：帳簿100個に対し実在庫97個。この3個が不明ロス。
>   万引き・計量ミス・レジの登録ミス・廃棄の登録漏れ・納品数量の誤りなどが原因ですが、
>   **原因を特定できないからこそ「不明」ロス**と呼ばれます。
> `【Fact】` 食品スーパーの万引き防止策実施率は92.1％（2024年、同調査）。

#### ④-11 税務（申告・納付）

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | **法定の申告・納付期限の到来**（＝法定・契約上のタイミング） |
| **誰が行うか** | 経理・財務機能＋**税理士** `【Varies】` |
| **何を確認するか** | 決算数値／消費税の計算（**軽減税率が適用される商品と標準税率の商品が混在する**）／**適格請求書（インボイス）の保存**／源泉所得税の計算／固定資産税・事業所税の対象資産 |
| **何をするか** | 決算を組む。法人税・消費税の申告書を作成し申告・納付する。源泉所得税を納付する。各種税金を納付する |
| **何を判断するか** | 処理の判断が必要な項目は税理士に相談する |
| **誰と連携するか** | 税理士、税務署、自治体、社長 |
| **最終的に何ができあがるか** | **決算書**、申告書、納付記録 |
| **頻度** | **年次**（決算・申告）／**月次**（源泉所得税の納付など。法定・契約上のタイミング） |

> `【Fact】` 消費税の仕入税額控除を受けるには、原則として
> **適格請求書発行事業者が交付する適格請求書（インボイス）等の保存が必要**です
> （出典：No.6498 適格請求書等保存方式（インボイス制度）／国税庁）。
>
> `【Typical】` 食品小売では、**飲食料品（酒類・外食を除く）に軽減税率が適用される**ため、
> 同じレジの中に税率の異なる商品が混在します。
> したがってレシート・請求書・帳簿のいずれにおいても、**税率ごとに区分した記録**が必要になります。

> `【Fact】` また、消費者に対する価格表示は**総額表示（税込の支払総額を明示する）が義務**です
> （出典：総額表示に関する主な質問／財務省）。値札・チラシ・POPはこの前提で作られます。

### ▼ Level 2：業態による経理・財務機能の違い `【Varies】`

| 業態 | 経理の特徴 |
|---|---|
| **食品スーパー** | **現金の取扱量が多く、日次の現金照合が必須**。軽減税率の区分が常時発生する。仕入先が多数で請求書照合の件数が多い |
| **専門店** | 現金比率は業種により異なる。**シーズン末の値下げが売上原価に大きく影響する**ため、在庫評価の判断が重い `【Typical】` |
| **ドラッグストア** | 調剤を行う場合、**健康保険からの後日入金（調剤報酬）が混在**する `【Fact】`。即時決済と後日入金の二重管理になる |
| **EC・通販** | 現金の取扱いがほぼない代わりに、**決済事業者・モールからの入金と手数料の精算**が中心になる。**送料が原価に影響する** `【Typical】` |

## ⑤ 人事・労務機能

> **この機能を一言でいうと：「必要な時間帯に、必要な人数を、法律を守って働ける状態にする仕事」**
> 小売業の人件費は粗利の約半分を占めます（`【Fact】` 労働分配率 売上高30億円未満で50.81％、2024年）。
> **人の管理は、そのまま損益の管理です。**

### A. 部署・機能名

| 項目 | 内容 |
|---|---|
| **本資料での正式名称** | **人事・労務機能** |
| **一般的に使われる部署名・役職名** | 人事、総務、労務、人事総務、事務 |
| **層** | 本部（ただし**採用とシフトは店舗が担う部分が大きい**） |

### B. 存在目的

小売業の店舗は、**営業時間中ずっと人がいないと成立しません**。
レジが1台も開いていなければ客は買えず、品出しが止まれば棚は空になります。
一方で、人を多く置けばその分だけ人件費が増え、利益が消えます。

人事・労務機能は、
**「必要な人を集め、法律を守った条件で働いてもらい、正しく給与を払い、辞めないようにする」**
ために存在します。

`【Fact】` 食品スーパーの店舗勤務者の**71.2％がパート・アルバイト**（2024年、業界推計値。
出典：2024年スーパーマーケット年次統計調査報告書）。
`【Inference】` したがって小売業の人事・労務は、**正社員の人事制度より、
パート・アルバイトの採用・シフト・勤怠・給与が業務の中心**になります。

### C. 担当者

| 区分 | 誰が担うか |
|---|---|
| **大手チェーンの一般的な姿** `【Typical】` | 人事部が採用・教育・評価・労務を担当し、制度を全社共通で設計する |
| **X社での実態** `【Example】`／`【Typical】` | **採用は各店長が行い**、社会保険・雇用保険等の手続は**事務担当**が行う |
| **シフト作成** | **店長・部門チーフ**（店舗側の業務。人事・労務機能はルールと人時枠を示す） |
| **給与計算** | 事務担当（経理と同じ人が兼務することが多い） `【Typical】` |
| **外部の関与** | 社会保険労務士に手続を依頼する場合がある `【Varies】` |

> `【Typical】` 採用が店舗単位になるのは、**パート・アルバイトの通勤圏が限られる**からです
> （`03_company-structure.md` 3-4）。
> 本部でまとめて募集しても、その人が働けるのは自宅近くの店だけです。

#### ⑤-1 採用（パート・アルバイトが中心）★小売業固有★

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 退職者が出たとき／新店の開店／繁忙期（年末年始など）に向けた増員／**部門の技能者が不足したとき**（＝案件発生時） |
| **誰が行うか** | **店長**（募集・面接・採否の判断）。手続は事務担当。正社員の採用は社長 `【Typical】` |
| **何を確認するか** | **どの時間帯に何人足りないのか**（人数ではなく時間帯で見る）／必要な技能（鮮魚の加工、惣菜の調理など）／**勤務可能な曜日・時間**／通勤手段と時間／労働条件（時給・勤務時間・社会保険の適用）／**扶養の範囲内で働きたいという希望があるか** `【Typical】` |
| **何をするか** | 求人を出す（店頭の張り紙、求人サイト、ハローワーク、折込求人など `【Varies】`）。面接する。**労働条件を書面で示して雇用契約を結ぶ**。初日の受け入れと教育の段取りをする |
| **何を判断するか** | **採用するか。** 技能よりも「**その時間帯に入れるか**」が決め手になることが多い `【Typical】` |
| **誰と連携するか** | 店長、部門チーフ、事務担当（雇用契約・社会保険手続）、ハローワーク、求人媒体 |
| **最終的に何ができあがるか** | **雇用契約書（労働条件通知書）**、新しい人員、シフトへの組み込み |
| **頻度** | 案件発生時／年次（新卒・繁忙期の計画） `【Varies】` |

> **なぜこの業務が必要なのか**
> `【Inference】` 小売業では、**辞める人が出ると即座に売場が回らなくなります**。
> 1店舗の正社員は平均14.0人（`【Fact】` 2024年、同調査）しかおらず、
> パート・アルバイトの1人が抜けると、その時間帯の仕事を誰かが引き受けるしかありません。
> したがって採用は「制度としての人事」ではなく、**日々の営業を維持するための補充作業**の性質を持ちます。

> **【重要】小売業の採用は「人数」ではなく「時間帯」で考える**
> `【Typical】` 「3人足りない」ではなく、
> 「**夕方17時〜20時のレジが2人足りない**」「**早朝の品出しが1人足りない**」という形で不足が現れます。
> 同じ3人でも、全員が午前中しか働けなければ夕方の穴は埋まりません。
> これが `03_company-structure.md` で説明した**「人数ではなく人時で管理する」**ということの実務上の意味です。

> **【重要】部門の技能は代替が難しい**
> `【Typical】` 鮮魚の三枚おろし、精肉のスライス、惣菜の調理は、
> 採用してすぐにできる仕事ではありません。
> **部門の技能者が辞めると、その部門の売場が作れなくなる**という構造的な特徴があります
> （`03_company-structure.md` 3-4）。
> したがって生鮮部門の採用は、レジ・品出しの採用とは難易度がまったく違います。

#### ⑤-2 シフト作成のルール設定と人時枠の管理

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 翌月のシフト作成時期（＝月次）／週の予定の確定（＝週次）／**当日の欠勤・客数の変動**（＝日次） |
| **誰が行うか** | **人事・労務機能はルールと人時枠を示す。実際のシフト作成は店長・部門チーフ** |
| **何を確認するか** | 各人の勤務可能日・時間の希望／**予想客数**（曜日・天候・特売・行事）／**時間帯ごとに必要な人時**／法令上の制約（労働時間、休憩、割増賃金の発生、年次有給休暇 等）／扶養の範囲内で働く希望がある人の労働時間の上限 `【Typical】`／**部門の技能者が各時間帯にいるか** |
| **何をするか** | 人時枠（その店・その月に使える総労働時間の目安）を示す。シフト作成のルール（休憩の取り方、最低配置人数など）を定める。店長が作成したシフトを確認する |
| **何を判断するか** | **人時枠をどこに置くか。** 減らせば人件費は下がるが、レジの行列・品出しの遅れ・売場の乱れにつながり売上が落ちる |
| **誰と連携するか** | 店長、部門チーフ、経理・財務機能（人件費の予算）、社長 |
| **最終的に何ができあがるか** | **シフト作成のルール**、**人時枠**、（店舗側で）シフト表 |
| **頻度** | 月次（人時枠の設定）／週次・日次（店舗側の調整） `【Varies】` |

> **人時（にんじ／マンアワー）**（`03_company-structure.md` 3-1 の再掲）
> → 「1人が1時間働く」を1単位として数えた労働量のこと。
> → 実務例：パート4人が4時間ずつ働けば16人時。
>   **小売業では「何人いるか」より「何人時を投入したか」で人員を管理します。**

> **人時売上高（にんじうりあげだか）**
> → 1人時あたりいくら売れたかを表す数値。売上高 ÷ 総投入人時 で計算します。
> → 実務例：1日の売上210万円を、投入人時120人時で割ると、人時売上高は17,500円。
>   **同じ売上でも、少ない人時で達成したほうが人件費は少なくて済みます。**
>   ただし人を減らしすぎれば売上自体が落ちるため、単純に高ければよいとは言えません `【Inference】`。

> **なぜこの業務が必要なのか**
> `【Inference】` 人件費は売上総利益の約半分です（`【Fact】` 労働分配率 売上高30億円未満で50.81％、2024年）。
> **シフトを1時間多く／少なく組むことが、そのまま利益に直結します。**
> 一方、人を減らしすぎればレジに行列ができ、品出しが間に合わず、売場が荒れて売上が落ちます。
> **「人を減らすと経費は下がるが、売上も下がる」**という板挟みの中で毎日判断する——
> これが小売業の店舗運営の中心的な難しさです（`03_company-structure.md` 3-4）。

| **何をきっかけに始まるか** | 日々の出退勤（＝日次）／月次の集計時期 |
| **誰が行うか** | 各従業員（打刻）→ 店長（確認）→ 事務担当（集計） |
| **何を確認するか** | 実際の出退勤時刻／**打刻漏れ・修正の理由**／休憩が取れているか／時間外労働の有無／深夜労働の有無（22時以降） `【Varies】`／**年次有給休暇の取得状況**／シフトと実績のずれ |
| **何をするか** | 打刻データを集計する。修正があれば理由を記録する。時間外・深夜の時間を区分して集計する。給与計算へ渡す |
| **何を判断するか** | 打刻の修正を認めるか／時間外労働が続いている場合の配置の見直し |
| **誰と連携するか** | 店長、部門チーフ、経理・財務機能（給与計算）、社会保険労務士 `【Varies】` |
| **最終的に何ができあがるか** | **勤怠集計データ（人別・月別）**、実績人時 |
| **頻度** | **日次**（打刻・確認）／**月次**（集計） |

> **なぜこの業務が必要なのか**
> `【Inference】` 2つの理由があります。
> 1. **給与を正しく計算するため。** 時給制の従業員が大半を占めるため、
>    **勤怠の記録がそのまま給与額**になります。1分の記録漏れが賃金の未払いにつながります。
> 2. **実際にいくらの人時を使ったかを知るため。** 計画（シフト）と実績（勤怠）を比べることで、
>    人時枠どおりに運営できたかが分かります。

#### ⑤-4 給与計算・支払

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 給与の締め日の到来（＝法定・契約上のタイミング／月次） |
| **誰が行うか** | 事務担当（経理と兼務）。社会保険労務士に委託する場合がある `【Varies】` |
| **何を確認するか** | 勤怠集計（労働時間・時間外・深夜）／時給・月給の単価／**割増賃金の計算**／通勤手当／**社会保険料・雇用保険料の控除**／**源泉所得税の控除**／住民税の控除／支給日と振込手続の期限 |
| **何をするか** | 支給額を計算する。控除額を計算する。給与明細を作る。振込を手配する。**源泉所得税を納付する** |
| **何を判断するか** | 計算に誤りがないか／控除の適用に疑問があれば確認する |
| **誰と連携するか** | 店長（勤怠の確認）、経理・財務機能（資金繰り・振込）、金融機関、税務署、年金事務所、社会保険労務士 `【Varies】` |
| **最終的に何ができあがるか** | **給与明細**、**給与の支払**、**源泉所得税の納付**、賃金台帳 |
| **頻度** | **月次**（法定・契約上のタイミング） |

> `【Fact】` 源泉徴収した所得税は、原則として**支払った月の翌月10日まで**に納付します
> （＝法定・契約上のタイミング）。

> **なぜこの業務が必要なのか**
> `【Inference】` X社では約200名（正社員約60名＋パート・アルバイト約140名）に給与を払います `【Example】`。
> パート・アルバイトは**それぞれ勤務時間が違う**ため、1人ずつ計算する必要があります。
> しかも支払額は年間約4.0億円 `【Example】`——粗利の約半分です。
> **金額の大きさと計算件数の多さの両方**が、小売業の給与計算の特徴です。

#### ⑤-5 社会保険・労働保険の手続

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 入社・退職（＝案件発生時）／労働時間の変更により加入要件を満たす／満たさなくなったとき／**年度更新・算定基礎届などの法定の時期**（＝法定・契約上のタイミング） |
| **誰が行うか** | 事務担当。社会保険労務士に委託する場合がある `【Varies】` |
| **何を確認するか** | **各人の労働時間・労働日数が社会保険・雇用保険の加入要件を満たすか**／扶養の状況／退職時の手続（離職票等）／労働保険料の算定に必要な賃金総額 |
| **何をするか** | 加入・喪失の届出をする。年度更新・算定基礎届を提出する。保険料を納付する |
| **何を判断するか** | 加入対象になるか／本人への説明内容 |
| **誰と連携するか** | 年金事務所、ハローワーク、労働基準監督署、健康保険組合 `【Varies】`、社会保険労務士 `【Varies】`、店長、本人 |
| **最終的に何ができあがるか** | 各種届出、保険料の納付、被保険者資格の記録 |
| **頻度** | 案件発生時（入退社）／年次・法定・契約上のタイミング（年度更新等） |

> **なぜこの業務が必要なのか**
> `【Typical】` 小売業はパート・アルバイトの比率が高く、
> **1人ひとりの労働時間が違い、しかも変動します**。
> 労働時間が変われば社会保険の加入要件を満たしたり満たさなくなったりするため、
> **入退社のとき以外にも手続が発生します**。
> 従業員数が多く、出入りも多い小売業では、この手続の件数自体が業務量になります。

#### ⑤-6 教育訓練（衛生・接客・作業手順）

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 新しい人が入ったとき／**衛生に関する定期教育の時期**／作業手順の変更時／事故・クレームが起きたとき（＝トラブル発生時）／新しい機器・システムの導入時 |
| **誰が行うか** | **店長・部門チーフ（現場でのOJT）**。全社共通のルールは人事・労務機能が整理する |
| **何を確認するか** | 何を教える必要があるか（**衛生管理、手洗い、温度管理、期限表示、アレルゲンの取扱い**、レジ操作、接客の基本、包丁・スライサー等の機械の安全な扱い方、緊急時の対応）／理解できているか／記録を残しているか |
| **何をするか** | 現場で手順を見せて、やらせて、確認する。手順書・チェックリストを使う `【Varies】`。衛生に関する教育を定期的に行う |
| **何を判断するか** | 1人で任せてよいか／追加の指導が必要か |
| **誰と連携するか** | 店長、部門チーフ、保健所（講習・指導） `【Varies】`、機器メーカー（機械の取扱い説明） |
| **最終的に何ができあがるか** | 作業ができる人員、**教育の記録** `【Varies】`、手順書 |
| **頻度** | 案件発生時（入社時）／**日次**（日々のOJT）／年次（定期的な衛生教育） `【Varies】` |

> **OJT（オージェーティー／On the Job Training：職場内訓練）**
> → 実際の仕事をしながら、先輩が横について教える教育のこと。
> → 実務例：「今日は品出しを一緒にやりましょう。この商品は必ず古いものを手前に出します」
>   というように、作業そのものが教育の場になります。
>   **小売業では研修室で教えるより、売場で教えるほうが圧倒的に多い** `【Typical】`。

> **なぜこの業務が必要なのか**
> `【Inference】` 小売業の作業は、**一つひとつは単純でも、間違えると損失や事故になる**ものが多くあります。
> - 先入先出をしない → 期限切れ＝廃棄ロス
> - 冷蔵品を荷受後に放置する → 品質低下＝廃棄ロス
> - 期限表示を誤る → **食品事故・回収につながる**
> - レジの登録を間違える → 現金過不足・不明ロス
>
> しかも作業を行うのは**大半がパート・アルバイト**です（`【Fact】` 71.2％、2024年）。
> したがって「誰がやっても同じ結果になる」状態を作る教育が、
> 小売業の品質とロス率を支えています。

#### ⑤-7 衛生管理者・食品衛生責任者等の選任 `【Fact】`

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 新規出店・営業許可の取得時／選任者の退職・異動時／**事業場の労働者数が要件に達したとき**（＝法定・契約上のタイミング） |
| **誰が行うか** | 事務担当＋店長。最終的な選任は会社（社長） |
| **何を確認するか** | **店舗（施設）ごとに食品衛生責任者が置かれているか**／**事業場の常時使用労働者数**／必要な資格の保有者がいるか／講習の受講が必要か／届出・報告の要否 |
| **何をするか** | 有資格者を選任する。必要な講習を受講させる。行政への届出・報告を行う。選任者の氏名を掲示する `【Varies】` |
| **何を判断するか** | 誰を選任するか／新たに資格を取得させるか |
| **誰と連携するか** | 保健所、労働基準監督署、食品衛生協会 `【Varies】`、店長、対象者本人 |
| **最終的に何ができあがるか** | **選任の記録・届出**、掲示、有資格者の配置 |
| **頻度** | 案件発生時／法定・契約上のタイミング |

> `【Fact】` **食品衛生責任者**
> 食品衛生法および同法施行規則に基づく「公衆衛生上必要な措置」の基準の一つとして、
> 営業者は**施設または部門ごとに食品衛生責任者を定める**こととされています
> （食品衛生法第51条第1項、食品衛生法施行規則第66条の2・別表第17。
> 出典：食品衛生法／e-Gov法令検索、食品衛生責任者に関する自治体の案内）。
> `【Typical】` 実務上は、店長や生鮮・惣菜の部門チーフが所定の講習を受けて就任することが多くあります。

> `【Fact】` **衛生管理者（労働安全衛生法）**
> 労働安全衛生法第12条により、**常時50人以上の労働者を使用する事業場**では、
> 事業場の規模・業種の区分に応じて衛生管理者を選任する必要があります。
> 小売業は、**第二種衛生管理者免許**を有する者を衛生管理者として選任できる業種に含まれます
> （出典：労働安全衛生法関係の公的解説）。
> `【Inference】` 食品スーパーの1店舗はパート・アルバイトを含めると50人を超えることがあるため、
> **店舗が1つの事業場として選任義務の対象になり得ます**。
> `【Varies】` 具体的な要否は事業場ごとの人数によります。

> `【Typical】` このほか、取り扱う商品に応じて次のような許可・免許・資格が必要になります
> （詳細は `15_rules-customs.md`）。
> - **酒類**：販売場ごとに所轄税務署長の**酒類販売業免許** `【Fact】`（酒税法第9条。出典：国税庁）
> - **たばこ**：**製造たばこ小売販売業の許可** `【Fact】`（たばこ事業法第22条。出典：財務省）
> - **医薬品**：薬剤師・登録販売者の配置（ドラッグストア等） `【Fact】`
> - **食品の調理・加工**：食品衛生法に基づく営業許可・届出 `【Fact】`

> **なぜこの業務が必要なのか**
> `【Inference】` これらは「守っていれば得をする」ものではなく、
> **満たしていなければ営業そのものができない**要件です。
> 選任者が退職した場合、後任を立てなければ法令上の状態を満たせなくなるため、
> 人事・労務機能は**「今、誰が何の資格で選任されているか」を常に把握しておく**必要があります。

#### ⑤-8 労働安全衛生・労務トラブルへの対応

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | **労働災害の発生**（包丁・スライサーによる負傷、転倒、腰痛、やけど 等）／体調不良者の発生／ハラスメント等の相談／労働条件に関する申し出（＝トラブル発生時） |
| **誰が行うか** | 店長（一次対応）＋事務担当＋社長。社会保険労務士に相談する場合がある `【Varies】` |
| **何を確認するか** | 事実関係／**負傷者の状態と応急処置**／発生状況（いつ・どこで・何をしていて）／再発を防ぐために何が必要か／**労災保険の手続が必要か** |
| **何をするか** | 応急処置・受診の手配をする。発生状況を記録する。労災の手続を行う。作業手順・設備の見直しを検討する。相談に対応する |
| **何を判断するか** | 労災として扱うか／作業方法を変えるか／当面の人員配置をどうするか |
| **誰と連携するか** | 医療機関、労働基準監督署、社会保険労務士 `【Varies】`、店長、本人 |
| **最終的に何ができあがるか** | 記録、必要な届出、再発防止の指示 |
| **頻度** | トラブル発生時 |

> **なぜこの業務が必要なのか**
> `【Typical】` 小売業の現場には、**刃物・機械・重量物・水濡れした床・高温の調理器具**があります。
> 鮮魚の包丁、精肉のスライサー、惣菜のフライヤー、荷受のカゴ車、青果の重い段ボール——
> いずれも負傷につながり得る要素です。
> `【Inference】` そして作業する人の多くは**短時間勤務のパート・アルバイト**であり、
> 作業に慣れる前の時期が最も危険です。
> したがって安全衛生は、教育（⑤-6）と切り離せない業務になります。

### ▼ Level 2：業態による人事・労務機能の違い `【Varies】`

| 業態 | 人事・労務の特徴 |
|---|---|
| **食品スーパー** | **パート・アルバイト中心**（`【Fact】` 71.2％、2024年）。部門ごとの技能者の確保が難しい。食品衛生責任者の選任が必須 |
| **専門店** | **正社員比率が相対的に高くなりやすい** `【Typical】`。商品知識・接客技術の教育の比重が大きい |
| **ドラッグストア** | **薬剤師・登録販売者という資格者の配置が営業の前提** `【Fact】`。資格者がいない時間帯は該当商品を販売できないため、**シフトが資格者の勤務に制約される** `【Inference】` |
| **EC・通販** | 店頭人員の代わりに**受注処理・梱包・出荷・問い合わせ対応**の人員が必要。**注文の波に合わせた人員調整**が課題になる `【Typical】` |
| **飲食併設型** | **調理担当が必要**で、仕込み時間帯に人が偏る。食品衛生責任者に加え、調理に関する衛生管理の教育が重い |

## ⑥ 情報システム機能

> **この機能を一言でいうと：「売る・仕入れる・記録するための道具を、動き続ける状態に保つ仕事」**
> `【Varies】` **中小小売業では専任者を置かないことが多く**、事務担当がベンダーの窓口を務めます。

### A. 部署・機能名

| 項目 | 内容 |
|---|---|
| **本資料での正式名称** | **情報システム機能** |
| **一般的に使われる部署名・役職名** | 情報システム、システム担当、事務（兼務） |
| **層** | 本部 |

### B. 存在目的

小売業では、**レジが止まれば売上が立ちません。発注端末が止まれば明日の商品が来ません。**
情報システム機能は、

1. **POS・発注端末・決済端末が動き続ける状態を保つ**
2. **商品マスタ・売価マスタを正しく登録し、レジと売場の表示を一致させる**
3. **売上・在庫のデータを、判断できる形にして関係者に渡す**

ために存在します。

`【Inference】` 小売業のシステムは「効率化の道具」である以前に、
**営業を止めないための設備**という性格を持ちます。

### C. 担当者

| 区分 | 誰が担うか |
|---|---|
| **大手チェーンの一般的な姿** `【Typical】` | 情報システム部がPOS・発注・マスタ・データ分析の仕組みを運用する |
| **X社での実態** `【Example】`／`【Varies】` | **専任者なし。** ベンダーの保守に依存し、社内では**事務担当が窓口**になる |
| **マスタ登録** | 事務担当が行う。生鮮の売価など日々変わるものは**店舗側（部門チーフ・店長）が端末で登録**することもある `【Varies】` |
| **障害時** | 店長が一次対応（再起動・切替）し、**ベンダーの保守窓口へ連絡**する `【Typical】` |
| **データの集計** | `【Varies】` 社長・経理が兼務して行う。専門の分析担当は置かないことが多い |

> `【Varies】` **注意：** 「大量のPOSデータを分析する専門部署がある」というのは
> 大手チェーンの姿であり、中小小売の一般的な姿ではありません（`01_overview.md` 1-7）。
> 中小では**日々の売上確認が中心**で、担当者の経験と現場の観察が判断の軸になります `【Typical】`。

#### ⑥-1 POSレジの運用

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 日々の開店準備（＝日次）／レジの増設・入替／設定の変更（税率・ポイント・クーポン）／**障害の発生**（＝トラブル発生時） |
| **誰が行うか** | 店舗（日常の起動・点検）＋事務担当（設定変更の依頼）＋ベンダー（保守） |
| **何を確認するか** | 全レジが正常に起動するか／**売価が正しく表示されるか**／レシートのプリンタ・用紙／決済端末との連動／**日次の売上データが本部に届いているか**／バックアップの状態 `【Varies】` |
| **何をするか** | 起動・点検する。設定変更を手配する。売上データを回収・集計する。障害時はベンダーに連絡する |
| **何を判断するか** | 使用を続けてよいか／レジを閉じるか／ベンダーを呼ぶか |
| **誰と連携するか** | 店長、レジ・接客機能、POSベンダーの保守窓口、決済事業者 |
| **最終的に何ができあがるか** | 稼働するレジ、**日次の売上データ**、点検記録 |
| **頻度** | **日次**（起動・点検・データ回収）／トラブル発生時 |

> **なぜこの業務が必要なのか**
> `【Inference】` POSは「レジ」であると同時に「**売上と在庫の記録装置**」です
> （`04_end-to-end-process.md` A-8）。
> レジが止まると、
> 1. **会計ができない**（＝売れない）
> 2. **売上が記録されない**（＝経理が数字を確定できない）
> 3. **在庫が減らない**（＝発注の判断材料が狂う）
>
> という3つが同時に起きます。だからレジの稼働維持は、店舗の最優先事項の一つになります。

#### ⑥-2 発注端末（EOS）の運用

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 日々の発注業務（＝日次）／仕入先の追加・変更／**発注データの送信エラー**（＝トラブル発生時） |
| **誰が行うか** | 店舗（売場担当が使用）＋事務担当（設定）＋ベンダー |
| **何を確認するか** | 端末が通信できるか／**仕入先ごとの発注締め時刻の設定**／送信した発注データが仕入先に届いたか／商品マスタが端末に反映されているか／端末のバッテリー・故障の有無 |
| **何をするか** | 端末を配備・設定する。マスタを更新する。送信エラーがあれば原因を確認し、**電話・FAXなど別の方法で発注できるようにする** `【Typical】` |
| **何を判断するか** | 端末で送るか／別の手段に切り替えるか |
| **誰と連携するか** | 売場担当、店長、仕入先、EOSベンダー |
| **最終的に何ができあがるか** | 稼働する発注環境、**送信済みの発注データ** |
| **頻度** | **日次**／トラブル発生時 |

> **なぜこの業務が必要なのか**
> `【Inference】` 発注は締め時刻を過ぎると翌日の納品に間に合いません（`02_industry-structure.md` 11-4）。
> 端末が使えなかった日は、**その日の発注が丸ごと飛ぶ**か、
> 電話・FAXで手作業に切り替えるかのどちらかになります。
> したがって「代わりの手段を用意しておく」ことが運用の一部になります `【Typical】`。

#### ⑥-3 商品マスタの登録・メンテナンス

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | **新商品の導入決定**（①-1）／商品のカット（①-2）／規格・容量・JANコードの変更／仕入先の変更／**軽減税率の区分の設定** |
| **誰が行うか** | 事務担当（登録）。内容は商品調達機能が決める |
| **何を確認するか** | **JANコード**／商品名（レシート・プライスカードに出る名称）／規格・容量／**部門（どの売場の商品か）**／仕入先／仕入価格／**消費税の税率区分（軽減税率か標準税率か）**／発注の単位（入数・ケース） |
| **何をするか** | 商品マスタに登録する。POS・発注端末・プライスカードに反映させる。不要になった商品を取扱終了にする |
| **何を判断するか** | 登録内容に誤りがないか／既存商品と重複していないか |
| **誰と連携するか** | 商品調達機能、売場担当、店長、POS・EOSベンダー |
| **最終的に何ができあがるか** | **商品マスタ（登録済み）**、レジで読めるバーコード、発注できる状態 |
| **頻度** | 案件発生時／週次〜月次（まとめて登録） `【Varies】` |

> **マスタ（マスタデータ）**
> → 業務の土台になる、あらかじめ登録しておく基本情報のこと。
> → 実務例：商品マスタには「JANコード・商品名・部門・仕入先・売価・税率区分」が登録されています。
>   レジでバーコードを読むと、**このマスタから情報が呼び出されます**。
>   マスタに登録されていない商品は、**レジを通すことすらできません**。

> **なぜこの業務が必要なのか**
> `【Inference】` マスタは、**すべての業務の前提**になっています。
> - 登録されていない商品 → **レジで読めない**（会計できない）
> - 部門の登録が誤っている → **部門別の売上・粗利が狂う**
> - 税率区分が誤っている → **消費税の計算が誤る**
> - 発注単位が誤っている → **意図しない数量が届く**
>
> つまりマスタ登録の誤りは、売場・レジ・経理のすべてに波及します。
> 地味な作業に見えますが、**誤りの影響範囲が最も広い業務の一つ**です。

#### ⑥-4 売価マスタの登録（定番売価・特売売価）

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | **定番売価の決定・変更**（①-4）／**特売の売価と期間の決定**（①-5）／仕入価格の変動による売価見直し／値下げ（見切り）の一括設定 `【Varies】` |
| **誰が行うか** | 事務担当（本部一括のもの）＋**店舗（生鮮・日々の見切りなど店舗で決めるもの）** `【Varies】` |
| **何を確認するか** | **売価の金額**／**適用期間（いつからいつまで）**／対象店舗／**税込表示との整合**／プライスカードの手配ができているか／チラシの掲載価格と一致しているか |
| **何をするか** | 売価マスタに登録する。特売は期間を指定して登録する。プライスカードを出力する。期間終了後に定番売価へ戻ることを確認する |
| **何を判断するか** | 登録内容に誤りがないか／**チラシ・POPと一致しているか** |
| **誰と連携するか** | 商品調達機能、販促・販売企画機能、店長、売場担当、レジ・接客機能 |
| **最終的に何ができあがるか** | **売価マスタ（登録済み）**、プライスカード、レジに反映された売価 |
| **頻度** | **日次**（生鮮・見切り）／週次（特売の切り替え）／案件発生時 |

> **【最重要】売場の表示とレジの売価が食い違うと、必ずトラブルになる**
> `【Typical】` 小売業で最も起きやすく、かつ客の信頼に直結する事故がこれです。
>
> | 食い違いのパターン | 何が起きるか |
> |---|---|
> | **売場は特売価格、レジは通常価格** | 客が「安いと思って買ったのに高い」となる。**苦情に直結** |
> | **売場は通常価格、レジは特売価格** | 気づかれないまま**粗利が失われる** |
> | **特売期間が終わったのにPOPが残っている** | 上と同じ問題が起きる |
>
> `【Inference】` だから売価の登録は、
> **「登録する」「プライスカードを出す」「売場に貼る」「期間終了後に外す」**の
> 4つがセットで管理されます。1つでも抜けると食い違いが生じます。

#### ⑥-5 データの集計と店舗への共有 `【Varies】`

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 日次の売上確認／週次・月次の締め／特売の結果確認／棚割・発注の見直し時 |
| **誰が行うか** | `【Varies】` **専任者を置かないことが多く、社長・経理・店長が兼務**して行う |
| **何を確認するか** | 店舗別・部門別・日別の売上／客数・客単価・買上点数／**商品別の販売数量**／粗利率／値下げ・廃棄の金額／在庫数 |
| **何をするか** | POSからデータを取り出し、表計算ソフト等で集計する。店舗・部門へ渡す |
| **何を判断するか** | どの数字を、どの単位で、誰に渡すか |
| **誰と連携するか** | 社長、店長、売場担当、商品調達機能、経理・財務機能 |
| **最終的に何ができあがるか** | **売上・粗利・ロスの集計資料**、部門別の実績 |
| **頻度** | **日次**（売上の確認）／週次・月次（集計） `【Varies】` |

> **分析は「日々の売上確認」が中心**で、担当者の経験と売場の観察が判断の軸になります
> （`01_overview.md` 1-7）。
> 「大量のPOSデータを分析する」姿を中小小売の一般像として書くことはできません。

#### ⑥-6 障害対応・ベンダー窓口

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | **レジ・発注端末・決済端末・ネットワークの障害**（＝トラブル発生時）／システムの更新・切替の連絡を受けたとき |
| **誰が行うか** | 店舗（一次対応）→ 事務担当（ベンダーへの連絡）→ ベンダー（保守） |
| **何を確認するか** | **どの機器が・いつから・どういう状態か**／営業への影響（会計ができるか、発注ができるか）／**代替手段があるか**（別のレジを使う、手書き伝票、電話発注）／保守契約の範囲と連絡先 |
| **何をするか** | 一次対応（再起動・切替）を行う。ベンダーに連絡する。**営業を続けるための代替手段に切り替える**。復旧後にデータを確認する |
| **何を判断するか** | 営業を続けられるか／どのレジ・どの機能を止めるか／客への案内をどうするか |
| **誰と連携するか** | POS・EOSベンダー、決済事業者、通信事業者、店長、レジ・接客機能、売場担当 |
| **最終的に何ができあがるか** | 復旧、**障害の記録**、影響した取引の確認 |
| **頻度** | トラブル発生時 |

> **なぜこの業務が必要なのか**
> `【Inference】` 小売業のシステム障害は、**営業の停止に直結します**。
> レジが全台止まれば、その間の売上はゼロです。客は待たずに帰ります。
> したがって重要なのは「復旧すること」だけでなく、
> **「復旧までの間、どうやって営業を続けるか」**を決めておくことです。
> `【Typical】` 手書きの伝票で会計する、現金のみで対応する、といった手段が
> 実務上の備えとして用意されていることがあります。

#### ⑥-7 決済端末・ネットワーク・周辺機器の管理

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 決済手段の追加・変更／端末の入替／通信障害（＝トラブル発生時）／決済事業者からの仕様変更の連絡 |
| **誰が行うか** | 事務担当＋決済事業者・決済代行会社＋店長 |
| **何を確認するか** | 対応している決済手段／端末が正常に通信するか／**決済データがPOSと一致するか**／手数料率と入金サイクル／端末の設置場所とレジとの接続 |
| **何をするか** | 端末を設置・設定する。決済事業者と契約・変更手続をする。レジ担当に操作を説明する |
| **何を判断するか** | どの決済手段に対応するか／端末を入れ替えるか |
| **誰と連携するか** | 決済事業者・決済代行会社、通信事業者、POSベンダー、レジ・接客機能、経理・財務機能 |
| **最終的に何ができあがるか** | 稼働する決済環境、**決済手段別の売上記録** |
| **頻度** | 案件発生時／日次（稼働確認）／トラブル発生時 |

> **なぜこの業務が必要なのか**
> `【Fact】` 食品スーパーの現金以外の決済手段の導入率は95.6％（2024年、同調査）。
> `【Inference】` つまり決済端末が使えないことは、**売上の相当部分が受け取れない**ことを意味します。
> また決済手段ごとに事業者・手数料・入金サイクルが異なるため、
> **端末の管理は経理の入金管理（④-3）と一体**で運用されます。

### ▼ Level 2：業態による情報システム機能の違い `【Varies】`

| **EC・通販** | **受注管理・在庫連携・出荷指示・配送追跡**が業務の中心。店舗のPOSに相当するものが受注システムになる。モール出店の場合はモール側の仕組みに合わせる `【Typical】` |
| **飲食併設型** | 注文の受付（オーダー）と調理指示、原材料の在庫管理が必要になる `【Varies】` |

# 【店舗機能】

> ここからは、実際に商品を売る現場である**店舗**の機能です。
> `03_company-structure.md` の二層構造でいう**第2層**にあたります。
> X社では**同じ構成の店舗が4つ**あり、それぞれが独立した現場として毎日動いています `【Example】`。

---

## ⑦ 店舗運営統括機能（店長）

> **この機能を一言でいうと：「その店の売上・粗利・人・安全のすべてに責任を持つ仕事」**
> 本部と店舗をつなぐ唯一の結節点でもあります。

### A. 部署・機能名

| 項目 | 内容 |
|---|---|
| **本資料での正式名称** | **店舗運営統括機能** |
| **一般的に使われる部署名・役職名** | **店長**、店舗責任者、マネージャー、副店長（店長代行） |
| **層** | 店舗 |

### B. 存在目的

店舗には、売場担当・レジ担当・バックヤード担当・清掃担当がいます。
それぞれが自分の持ち場の仕事をしますが、**「店全体としてどうか」を見る人がいなければ**、
次のことが起きます。

- 部門ごとには回っているが、レジに行列ができている
- 売場は作られたが、人時を使いすぎて人件費が膨らんでいる
- 値下げは減ったが、その分廃棄が増えている
- 本部の決めた特売が、売場に反映されていない

店舗運営統括機能は、**部門ごとの最適ではなく「店としての結果」に責任を持つため**に存在します。

`【Fact】` 1店舗あたりの正社員数は平均14.0人、うち管理職者数は平均2.9人（2024年、同調査）。
`【Inference】` この人数では、店長は「管理だけをする人」ではいられません。
**判断する人であると同時に、現場で作業する人**でもあります（`03_company-structure.md` 3-4）。

### C. 担当者

| 区分 | 誰が担うか |
|---|---|
| **一般的な役職名** | 店長。規模により副店長・店長代行が置かれる `【Varies】` |
| **X社での実態** `【Example】`／`【Typical】` | 4店舗それぞれに店長（正社員）。**本店は社長が実質的に店長を兼ねる**こともある |
| **兼務の実態** `【Typical】` | 店長は**特定部門のチーフを兼ねる**ことがある。レジが混めばレジに入り、品出しも行う |
| **不在時** | 副店長・部門チーフの中の責任者が代行する `【Varies】` |

> `【Typical】` 中小小売業の店長は、
> **「本部の意思決定を実行する人」であると同時に「その店の経営者に近い立場」**です。
> 大手チェーンでは本部が決めることの多くを、中小では店長の裁量で決めます
> （`01_overview.md` 1-7 の比較表）。

### E. 業務詳細

---

#### ⑦-1 売上・粗利の管理（日々の数字の確認）

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 開店前（前日実績の確認）／営業時間中（進捗の確認）／閉店後（当日実績の確定）／週次・月次の締め（＝日次／週次／月次） |
| **誰が行うか** | **店長** |
| **何を確認するか** | **当日・前日の売上と客数**／計画・前年同日との差／**部門別の売上と粗利率**／客単価・買上点数／**時間帯別の売上の出方**／値下げ・廃棄の金額／欠品の状況／天候・曜日・行事の影響 |
| **何をするか** | POSの数字を確認する。部門チーフと共有する。**遅れている部門に手を打つ**（売場の作り直し、追加の品出し、値下げのタイミングの調整、人の配置換え）。本部へ報告する |
| **何を判断するか** | **今日の残り時間で何をするか。** 売上が計画に届いていない場合、追加で売り込むか／ロスを抑える方向に切り替えるか |
| **誰と連携するか** | 売場担当（部門チーフ）、レジ・接客機能、社長・本部（商品調達機能・経理・財務機能） |
| **最終的に何ができあがるか** | **日々の実績の把握**、部門への指示、本部への報告 |
| **頻度** | **日次**（複数回）／週次／月次 |

> **なぜこの業務が必要なのか**
> `【Inference】` 小売業の売上は、**その日が終われば取り返せません**。
> 製造業なら「今月遅れた分を来月作る」ことができますが、
> 小売業の「今日来なかった客」は戻ってきません。
> したがって店長は、**閉店後に結果を知るのではなく、営業時間中に手を打つ**ために数字を見ます。
>
> `【Example】`（説明用の架空例）午後3時の時点で売上が前年同日の85％。
> 客数は同水準なのに客単価が下がっている → 買上点数が減っている
> → 夕方の惣菜の品揃えを厚くする、関連商品を並べる、といった手を打つ。
> **同じ「売上が悪い」でも、客数が原因か客単価が原因かで、打つ手がまったく違います。**

> **【重要】売上と粗利は必ずセットで見る**
> `【Inference】` 値下げを多くすれば売上は伸びますが、粗利は減ります。
> 「売上は計画を超えたが、粗利率が2ポイント落ちた」という日は、
> 金額でみれば粗利が減っている可能性があります。
> 店長が見ているのは**売上そのものではなく、売上と粗利の両方**です。

#### ⑦-2 人員配置・シフトの最終確認

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 翌月のシフト作成時期（＝月次）／週の確認（＝週次）／**当日の欠勤・客数の変動**（＝日次） |
| **誰が行うか** | **店長**（部門チーフが部門内の案を作る場合もある `【Varies】`） |
| **何を確認するか** | 各人の勤務希望／**人時枠**（人事・労務機能が示した枠）／予想客数（曜日・天候・特売・行事）／**時間帯ごとの必要人数**（レジ・品出し・加工・清掃）／部門の技能者が各時間帯にいるか／法令上の制約（労働時間・休憩） |
| **何をするか** | シフト表を作成・確定する。当日の欠勤があれば配置を組み替える。**ピーク時にレジを何台開けるかを決める**。作業の優先順位を指示する |
| **何を判断するか** | **どの時間帯に何人置くか。** 増やせば人件費が増え、減らせばレジの行列・品出しの遅れ・売場の乱れにつながる |
| **誰と連携するか** | 部門チーフ、レジ・接客機能、人事・労務機能（人時枠・勤怠）、本人（勤務希望） |
| **最終的に何ができあがるか** | **確定したシフト表**、当日の配置指示 |
| **頻度** | **月次**（作成）／**週次**（確認）／**日次**（当日調整） |

> **なぜこの業務が必要なのか**
> `【Inference】` 小売業では**仕事量が時間帯によって何倍も変わります**
> （`03_company-structure.md` 3-4）。
> 開店直後と夕方のピークでは必要な人手がまったく違い、
> かつ天候で客数が変わるため、**前もって決めたシフトをそのまま実行できるとは限りません**。
>
> 店長の仕事は「シフト表を作ること」ではなく、
> **「その日の実際の忙しさに合わせて人を動かすこと」**です。

> `【Example】`（説明用の架空例）雨で客数が想定の7割。
> → レジを6台から3台に絞り、余った人を品出しと売場整理に回す。
> → 一方で客が少ないため売れ行きも落ちる。惣菜の追加仕込みを止め、見切りの開始を早める。
> **人の配置の変更が、そのまま商品の扱い方の変更につながります。**

---

#### ⑦-3 部門への指示と売場全体のチェック

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 開店前の売場チェック／営業時間中の巡回／**特売の初日**／本部からの指示を受けたとき（＝日次） |
| **誰が行うか** | **店長** |
| **何を確認するか** | **棚割どおりに商品が並んでいるか**／欠品はないか／**プライスカードと商品が一致しているか**／**特売品が計画どおりの場所・数量で展開されているか**／POPの貼り忘れ・外し忘れ／鮮度・期限の状態／売場が乱れていないか／床・通路が安全か |
| **何をするか** | 開店前に売場を一周する。気づいた点を部門チーフに伝える。**その場で直せるものは自分で直す** `【Typical】`。部門間の連携（惣菜と青果の関連陳列など）を調整する |
| **何を判断するか** | 何を優先して直すか／どの部門に人を回すか／売場の変更を指示するか |
| **誰と連携するか** | 売場担当（部門チーフ）、バックヤード機能、清掃・保安機能、販促・販売企画機能（本部の意図の確認） |
| **最終的に何ができあがるか** | **整った売場**、部門への指示、本部への現場からのフィードバック |
| **頻度** | **日次**（開店前・随時） |

> **なぜこの業務が必要なのか**
> `【Inference】` 売場は放っておくと必ず崩れます。
> 客が商品を手に取り、戻し、別の場所に置く。補充が追いつかない。POPが落ちる。
> **「作った売場」と「今の売場」は常にずれていきます。**
>
> 部門チーフは自分の部門しか見ていないため、
> 「青果は完璧だがレジ前が乱れている」という状態は、店長でなければ気づけません。
> 店長の巡回は、**部門の視点では見えない部分を埋める作業**です。

> **【重要】特売初日の売場は必ず確認される**
> `【Typical】` チラシに載っている商品が売場にない・価格が違う、という状態は
> 最も起きやすく、最も苦情になりやすい事故です（⑥-4）。
> そのため店長は、**特売初日の開店前に、チラシと売場を突き合わせる**のが一般的です。

---

#### ⑦-4 ロス管理（値下げ・廃棄・不明ロス）★小売業固有の中心業務★

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 日々の値下げ・廃棄の集計（＝日次）／部門の粗利率が計画を下回ったとき／**棚卸で不明ロスが判明したとき**（＝年次・月次） |
| **誰が行うか** | **店長**＋売場担当（部門チーフ） |
| **何を確認するか** | **部門別・日別の値下げ金額と廃棄金額**／ロス率（`【Fact】` 食品スーパーの部門別ロス率は惣菜10.6％、水産8.6％、畜産6.6％、日配品4.0％、青果3.2％、一般食品1.7％、非食品1.5％。2024年、同調査）／**発注量と売れ行きのずれ**／見切りの開始時刻と値下げ幅／先入先出ができているか／**不明ロスの金額** |
| **何をするか** | ロスの金額と発生源を確認する。部門チーフと原因を話す（発注が多すぎたのか、見切りが遅かったのか、鮮度管理の問題か）。**翌日以降の発注量と見切りのタイミングを調整する**よう指示する |
| **何を判断するか** | **どこまでのロスを許容するか。** ロスをゼロにしようとすれば欠品が増え、売上が落ちる。**ロスと欠品はトレードオフの関係にある** |
| **誰と連携するか** | 売場担当（部門チーフ）、経理・財務機能（金額の集計）、商品調達機能（発注方針）、社長 |
| **最終的に何ができあがるか** | **ロスの把握と原因の特定**、翌日以降の発注・見切りの指示 |
| **頻度** | **日次**（値下げ・廃棄）／月次（集計）／年次（不明ロスの確定） |

> **なぜこの業務が必要なのか**（`01_overview.md` 1-5 の再掲と補足）
> ```
> 粗利 ＝ 値入 − ロス（値下げ・廃棄・不明ロス）
> ```
> `【Inference】` 値入（売価の設定）は本部（商品調達機能）が決める部分が大きく、
> 店舗では変えられません。
> **つまり店舗が粗利を動かせる余地は、ほぼ「ロス」の部分だけです。**
> だから店長の仕事の中心に、ロス管理が来ます。

> **【最重要】ロスと欠品はトレードオフである**
> `【Inference】`
> ```
>   発注を減らす → ロスは減る → しかし欠品が増え、売上が落ちる
>   発注を増やす → 欠品は減る → しかしロスが増え、粗利が落ちる
> ```
> **どちらか一方を完全になくすことはできません。**
> 「今日のロスがゼロだった」ことは、必ずしも良い状態を意味しません。
> **売り切ったのか、そもそも並べていなかったのか**を区別して見る必要があります。
>
> この判断を毎日行うのが、小売業の店長と部門チーフの仕事の核心部分です。

> **3種類のロスは、対処する場所が違う**
>
> | ロスの種類 | 主な発生源 | 誰がどこで手を打つか |
> |---|---|---|
> | **廃棄ロス** | 発注が多すぎた／鮮度管理ができていない／見切りが遅い | 売場担当の**発注量**と**見切りのタイミング** |
> | **値下げロス** | 見切りの幅が大きい／見切りの開始が早すぎる | 売場担当の**値下げ幅と開始時刻の判断** |
> | **不明ロス** | 万引き／レジの登録ミス／計量ミス／廃棄の登録漏れ／納品数量の誤り | **清掃・保安機能（万引き対策）**、レジ教育、**検品の精度**、廃棄登録の徹底 |
>
> `【Fact】` 食品スーパーの万引き防止策実施率は92.1％（2024年、同調査）。

#### ⑦-5 発注の確認と大口・特売発注の判断

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 日々の発注（＝日次）／**特売・季節商戦の発注**（＝発注時）／新人が発注を担当するとき／発注ミスが続いたとき |
| **誰が行うか** | **店長**（確認・承認）。実際の発注は売場担当（部門チーフ） |
| **何を確認するか** | **発注数量が売れ行きに対して妥当か**／特売の数量が計画と合っているか／**在庫が積み上がっていないか**／期限内に売り切れる量か／売場に置ける量か／大口発注の資金への影響 |
| **何をするか** | 発注内容を確認する。大きすぎる／小さすぎる発注に指摘する。特売・季節商品の数量を本部（商品調達機能）と調整する |
| **何を判断するか** | **その数量で発注してよいか。** 特に特売・季節品は「読み切り」の発注なので、外すと損失が大きい |
| **誰と連携するか** | 売場担当（部門チーフ）、商品調達機能（社長）、仕入先（大口の場合） |
| **最終的に何ができあがるか** | 確認済みの発注、特売・季節商品の数量決定 |
| **頻度** | **日次**（定番）／発注時（特売・季節品） |

> **なぜこの業務が必要なのか**
> `【Inference】` 発注は小売業で最も重要な工程です（`04_end-to-end-process.md` A-2）。
> 粗利は発注した瞬間にほぼ決まってしまい、陳列や接客では取り返せません。
>
> 定番発注は売場担当が実績に基づいて行うので、店長は基本的に任せます。
> しかし**特売・季節品の発注は「計画ベースの読み切り」**であり、
> 外したときの金額が大きいため、店長（および本部）が関与します。
> `【Typical】` これが「定番は売場担当、特売は店長＋本部」という役割分担の理由です。

#### ⑦-6 現金・売上金の管理責任

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 開店前（釣銭準備金の用意）／レジ担当の交替時／閉店時（レジ締め）／翌朝（銀行への入金）（＝日次） |
| **誰が行うか** | **店長**（責任者としての確認）＋レジ・接客機能（実際のレジ精算） |
| **何を確認するか** | **釣銭準備金の額と金種**／**POSが示す現金売上と、レジ内の実際の現金が一致するか**／決済手段別の内訳／返品・取消の内容／**現金過不足の金額と原因**／金庫の保管状況／銀行への入金額 |
| **何をするか** | 釣銭を準備する（銀行で両替する `【Varies】`）。レジ締めに立ち会い、金額を確認する。売上金を金庫に保管する。**銀行へ入金する**（または夜間金庫・集金サービスを使う `【Varies】`）。日報を作成し本部へ報告する |
| **何を判断するか** | 差異の原因／差異が大きい場合の調査の要否／手元に残す釣銭の額 |
| **誰と連携するか** | レジ・接客機能、経理・財務機能、金融機関 |
| **最終的に何ができあがるか** | **日報（売上報告）**、**現金過不足の記録**、銀行への入金、金庫の売上金 |
| **頻度** | **日次** |

> **なぜこの業務が必要なのか**（`04_end-to-end-process.md` A-12 の再掲と補足）
> `【Typical】` 小売業は**毎日、多額の現金が物理的に店舗に存在する**業種です。
> BtoBの業界では代金は振込で入るため、現物の現金を扱う場面はほとんどありません。
>
> `【Inference】` 現金は、誰の手を経たか記録が残らない資産です。
> だからこそ、
> 1. **毎日必ず数える**（日をまたぐと原因を追えなくなる）
> 2. **責任者が確認する**（担当者1人で完結させない）
> 3. **速やかに銀行へ入れる**（店に置く時間を短くする）
>
> という運用が必要になります。これは店長の責任として設計されているのが一般的です `【Typical】`。

#### ⑦-7 クレーム対応（最終窓口）

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 客からの申し出（＝問い合わせ時）／レジ・売場担当が対応しきれなかったとき／**商品の品質に関する申し出**（異物・傷み・表示の誤り）（＝トラブル発生時） |
| **誰が行うか** | 一次対応は**レジ・接客機能／売場担当**。判断を要するものは**店長** |
| **何を確認するか** | **事実関係**（いつ・どこで・どの商品を・どういう状態で）／レシート・現物があるか／**同じロットの商品が売場に残っていないか**／過去に同様の事例がないか／仕入先・メーカーに確認が必要か／**健康被害の有無**（食品の場合） |
| **何をするか** | 話を聞く。事実を確認する。**必要に応じて売場から該当商品を撤去する**。返金・交換等の対応を決める。記録する。仕入先・メーカーへ連絡する。**健康被害のおそれがある場合は保健所へ相談する** `【Typical】` |
| **何を判断するか** | どう対応するか／**商品を回収・撤去するか**／本部・社長に報告すべき事案か／行政に相談すべきか |
| **誰と連携するか** | レジ・接客機能、売場担当、社長・本部、仕入先・メーカー、保健所（食品事故の場合） |
| **最終的に何ができあがるか** | 対応の完了、**クレームの記録**、再発防止の指示、（必要な場合）商品の撤去・回収 |
| **頻度** | 問い合わせ時／トラブル発生時 |

> **なぜこの業務が必要なのか**
> `【Inference】` 小売業のクレームは、**単なる接客の問題ではないものが混ざっています**。
> 「レジの対応が悪い」は接客の問題ですが、
> 「買った惣菜に異物が入っていた」は**食品事故の可能性**であり、
> **同じ商品が売場に並んだままかもしれない**という緊急性を持ちます。
>
> したがって店長は、申し出を聞いた時点で
> **「これは1人の客の問題か、それとも店全体の問題か」**を見分ける必要があります。
> これは判断を伴う仕事なので、パート・アルバイトに任せられません。

> **【重要】食品を扱う小売業では、クレームが行政対応につながることがある**
> `【Fact】` 食品衛生法は、公衆衛生に与える影響が著しい営業について都道府県知事の許可を求めており、
> 食中毒等が発生した場合には保健所の調査の対象になります
> （出典：食品衛生法／e-Gov法令検索）。
> `【Typical】` 実務上は、健康被害のおそれがある申し出を受けた場合、
> 店内での判断だけで済ませず、社長・保健所と連携して対応することになります。

#### ⑦-8 店舗の安全衛生管理

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 日々の店内点検（＝日次）／設備の異常（＝トラブル発生時）／労働災害の発生／定期的な衛生確認（＝月次・年次） `【Varies】` |
| **誰が行うか** | **店長**（店舗の責任者として）＋清掃・保安機能＋各部門 |
| **何を確認するか** | **冷蔵・冷凍ケースの温度**／加工場・調理場の衛生状態／**手洗い・服装・体調確認ができているか**／床の水濡れ・段差（転倒の危険）／刃物・機械の安全な使用／**消費期限・賞味期限の表示に誤りがないか**／消防設備・避難経路／防犯カメラ・非常時の連絡体制 |
| **何をするか** | 点検し記録する。異常があれば是正を指示する。従業員に注意喚起する。**食品衛生責任者としての職務を果たす**（店長が就任している場合 `【Typical】`）。事故が起きた場合は応急処置と報告を行う |
| **何を判断するか** | **商品を販売してよいか（品質・温度に問題がないか）**／設備を使い続けてよいか／営業に影響が出る場合の対応 |
| **誰と連携するか** | 清掃・保安機能、売場担当（特に生鮮・惣菜）、人事・労務機能（労災対応）、保健所、保守業者、消防署 |
| **最終的に何ができあがるか** | **点検記録（温度記録を含む）**、是正の指示、（事故時）記録と報告 |
| **頻度** | **日次**（温度・衛生の確認）／月次・年次（定期の確認）／トラブル発生時 |

> **なぜこの業務が必要なのか**
> `【Inference】` 食品を扱う小売業では、衛生管理の失敗が**商品事故＝健康被害**に直結します。
> これは損失の問題ではなく、**営業を続けられるかどうかの問題**です。
>
> また小売業の現場には、刃物・機械・重量物・水濡れした床があり（⑤-8）、
> 働く人の多くは短時間勤務のパート・アルバイトです。
> **設備と人の両方について、日々確認する人が必要**になります。

> `【Typical】` X社規模では、**店長が食品衛生責任者を兼ねている**ことが多く、
> 衛生管理は「別の誰かの仕事」ではなく店長自身の職務として組み込まれています。

#### ⑦-9 本部との情報のやりとり

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 日次の報告（日報）／本部からの指示・連絡（特売、価格変更、商品の切替）／店舗からの要望・相談（＝日次／週次） |
| **誰が行うか** | **店長**（店舗側の唯一の窓口） |
| **何を確認するか** | 本部の指示の内容と実行できるか（商品・売場・人員の準備が間に合うか）／店舗の実績（売上・粗利・ロス・客数）／**現場で起きていること**（客の反応、競合の動き、商品の売れ行き、設備の不具合） |
| **何をするか** | 日報を送る。本部の指示を部門へ落とし込む。**現場の状況を本部へ伝える**（この商品は売れない、この特売は数量が足りない、この価格では競合に負けている 等） |
| **何を判断するか** | 本部の指示をそのまま実行するか、店舗の事情を伝えて調整するか |
| **誰と連携するか** | 社長、商品調達機能、販促・販売企画機能、経理・財務機能、人事・労務機能、情報システム機能 |
| **最終的に何ができあがるか** | **日報・報告**、本部指示の店舗での実行、現場情報の本部への還流 |
| **頻度** | **日次**（日報）／週次（打ち合わせ） `【Varies】` |

> **なぜこの業務が必要なのか**
> `【Inference】` 本部（社長）は、**売場に常時いるわけではありません**。
> X社は4店舗あるため、社長が1店舗にいられるのは1日のうち一部だけです。
> したがって本部が判断する材料は、**数字（POSデータ）と店長からの情報**しかありません。
>
> 数字だけでは分からないことがあります。
> - なぜその商品が売れなかったのか（欠品していた／場所が悪かった／競合が安かった）
> - 客が何を探していたのか
> - 設備の調子が悪く、作業が遅れていた
>
> **店長が伝えなければ、本部は誤った判断をします。**
> これが「本部↔店舗」の情報のやりとりが小売業で最重要である理由です（PART 3 で詳述）。

#### ⑦-10 競合店調査

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 定期的な確認（＝週次〜月次 `【Varies】`）／**競合店の出店・改装・大型セールの情報を得たとき**／自店の客数が落ちたとき |
| **誰が行うか** | **店長**、売場担当（部門チーフ） |
| **何を確認するか** | **主要商品の売価**（卵・牛乳・食パン・豆腐など客が価格を覚えている商品）／チラシの内容／売場の作り方・品揃え／**新しく扱い始めた商品**／客の入り具合／営業時間 |
| **何をするか** | 競合店を見て回る。価格を記録する。自店の売価・品揃えと比べる。**必要な情報を本部（商品調達機能）へ伝える** |
| **何を判断するか** | 自店の売価を変える必要があるか（判断は本部）／売場の作り方を変えるか |
| **誰と連携するか** | 商品調達機能（売価の判断）、販促・販売企画機能、売場担当 |
| **最終的に何ができあがるか** | **競合店の売価情報**、自店への反映の提案 |
| **頻度** | 週次〜月次 `【Varies】` ／案件発生時（競合の出店・セール時） |

> **なぜこの業務が必要なのか**
> `【Typical】` 小売業の商圏は限られており、その中で複数の店が同じ客を対象にしています。
> 特に食品スーパーでは、**客は日常的に買う商品の価格を記憶しています**。
> 卵・牛乳・食パンなどが競合店より明らかに高い状態が続くと、
> 「あの店は高い」という印象になり、**その商品だけでなく来店そのものが減ります** `【Inference】`。
>
> したがって競合店調査は、価格を合わせるためだけでなく、
> **自店がどう見えているかを知るため**の業務です。

#### ⑦-11 棚卸の実施責任

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | **決算期末**／月次・四半期の棚卸（＝年次／月次 `【Varies】`） |
| **誰が行うか** | **店長（実施責任）**＋売場担当・パート・アルバイト（全員で実施することが多い `【Typical】`） |
| **何を確認するか** | **数える範囲**（売場・バックヤード・冷蔵庫・冷凍庫・加工場）／数え方のルール（重複・数え漏れを防ぐ区分け）／**売り物にならない商品の扱い**／委託・消化仕入の商品を区別しているか（`02_industry-structure.md` 11-2）／理論在庫との差 |
| **何をするか** | 実施計画を立てる（時間帯・人員・分担）。カウントを行う。棚卸表を集計する。**理論在庫と突き合わせて差異を確認する**。経理・財務機能へ渡す |
| **何を判断するか** | 差異の原因（記録漏れか、不明ロスか）／再カウントが必要か |
| **誰と連携するか** | 売場担当、パート・アルバイト、経理・財務機能、税理士 `【Varies】` |
| **最終的に何ができあがるか** | **実在庫データ**、**在庫金額**、**不明ロスの金額** |
| **頻度** | **年次**（決算時は必須）／月次・四半期 `【Varies】` |

> **なぜこの業務が必要なのか**（`04_end-to-end-process.md` A-14 の再掲）
> `【Inference】` 2つの理由があります。
> **① 正しい粗利を計算するため。**
> ```
> 売上原価 ＝ 期首在庫 ＋ 期中の仕入 − 期末在庫
> ```
> 期末在庫の金額が分からなければ、売上原価も粗利も出せません。
> **② 不明ロスを把握するため。**
> 棚卸をしない限り、そもそも「帳簿と実物が合っていないこと」に気づけません。

> **【重要】棚卸は営業と両立させる必要がある**
> `【Typical】` 小売業の棚卸は、**商品が動いている状態で数える**という難しさがあります。
> 閉店後に行う、開店前に行う、区画ごとに分けて行う、といった方法が取られますが `【Varies】`、
> いずれにせよ**全従業員の時間を使う大がかりな業務**です。
> 店長は、営業への影響と人時の投入を同時に管理することになります。

## ⑧ 売場担当機能（部門別）

> **この機能を一言でいうと：「担当する売場の商品を、発注し、作り、並べ、売り切る仕事」**
> **小売業の粗利を日々作っているのは、この機能です。**
> ただし**部門（青果／水産／畜産／惣菜／日配／一般食品／非食品）によって仕事の中身が大きく違います。**
> 本節は「共通部分」を書いたうえで、**8-X で部門差を必ず明示**します。

### A. 部署・機能名

| 項目 | 内容 |
|---|---|
| **本資料での正式名称** | **売場担当機能（部門別）** |
| **一般的に使われる部署名・役職名** | **部門チーフ**、主任、青果チーフ、鮮魚チーフ、精肉チーフ、惣菜チーフ、日配担当、グロサリー担当、部門担当者 |
| **層** | 店舗 |

> **部門（ぶもん）**
> → 店の中で商品を分類した管理の単位のこと。
> → 実務例：食品スーパーでは一般に「青果・水産（鮮魚）・畜産（精肉）・惣菜・日配・一般食品（グロサリー）・
>   非食品」に分かれます。**売上も粗利もロスも、この部門単位で集計されます。**
>   `【Fact】` 部門別の売上構成比・目標利益率・ロス率は `03_company-structure.md` の表を参照。

### B. 存在目的

商品は、仕入れただけでは売れません。
箱のまま倉庫に積んであっても、客は買えません（`02_industry-structure.md` 11-3）。

売場担当機能は、
1. **必要な量を発注して確保し**（＝欠品させない、余らせない）
2. **売れる状態にして売場に並べ**（＝加工・値付け・陳列）
3. **鮮度を保ちながら売り切る**（＝先入先出・見切り・廃棄）

ために存在します。

`【Inference】` `04_end-to-end-process.md` の A-2〜A-11 のほとんどを、この機能が担当します。
**小売業の業務フローの中心にいるのが、売場担当です。**

### C. 担当者

| 区分 | 誰が担うか |
|---|---|
| **部門チーフ（正社員）** | **発注・加工・値付けの判断・見切りの判断**を担当。部門の粗利とロスに責任を持つ |
| **パート・アルバイト** | **品出し・前出し・陳列・簡易な加工・POP作成**などを担当 |
| **X社での実態** `【Example】`／`【Typical】` | 1店舗あたり正社員14.0人 `【Fact】` のうち、部門チーフが各部門に1名程度。残りはパート・アルバイト |
| **兼務の実態** `【Typical】` | 部門チーフが複数部門を兼ねることがある（例：日配とグロサリーを1人で見る）。**店長が特定部門のチーフを兼ねる**こともある |
| **技能の所在** | **生鮮（水産・畜産・惣菜）は加工技能が必要**で、担当者が抜けると売場が作れなくなる `【Typical】` |

> `【Typical】` **発注は正社員（部門チーフ）が担うのが一般的**です
> （`04_end-to-end-process.md` A-2）。
> 発注の誤りは陳列や接客では取り返せないため、責任を持てる立場の人が行います。

#### ⑧-1 発注（定番発注・特売発注）★小売業で最も重要な工程★

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | **仕入先ごとの発注締め時刻の到来**／在庫が補充点を下回ったとき／**特売の決定**／季節商戦の準備（＝日次／発注時） |
| **誰が行うか** | **売場担当（部門チーフ）**。特売・大量仕入は商品調達機能（社長）＋店長が判断 |
| **何を確認するか** | **現在の在庫数**（売場＋バックヤード）／直近の販売実績（何日で何個売れたか）／**天気予報**／曜日・行事／**特売計画（チラシ内容）**／仕入先の在庫・相場情報／**前年同時期の実績**／リードタイム（次の納品はいつか）／**賞味期限・消費期限**／売場に置ける量 |
| **何をするか** | 品目ごとに数量を決め、発注端末・電話・FAX・Web発注等で**締め時刻までに送信**する `【Varies】` |
| **何を判断するか** | **いくつ発注するか。** 多ければロス、少なければ欠品。どちらかの損失が必ず出る |
| **誰と連携するか** | 仕入先（卸売業者・メーカー・仲卸業者）、店長（大口・特売の場合）、商品調達機能、バックヤード機能（納品量の事前共有） |
| **最終的に何ができあがるか** | **発注データ（発注情報）／発注書** |
| **頻度** | **日次**（生鮮・日配）／週次（グロサリー等）／発注時（季節品） `【Varies】` |

> **なぜこの業務が必要なのか**（`04_end-to-end-process.md` A-2 の再掲と補足）
> `【Inference】` 小売業の粗利は、**発注した瞬間にほぼ決まります**。
> - 発注が多すぎた → 値下げして売るか、捨てる → **粗利が減る**
> - 発注が少なすぎた → 売る商品がない → **売上そのものが立たない**
>
> 陳列や接客をどれだけ工夫しても、**発注量の誤りは取り返せません**。

> **定番発注と特売発注は考え方が逆**（`04_end-to-end-process.md` A-2 の再掲）
>
> | | **定番発注** | **特売発注** |
> |---|---|---|
> | 目的 | 棚を切らさない（欠品させない） | 特売期間中に売る量を確保する |
> | 数量の決め方 | **売れた分を補充する**（実績ベース） | **これだけ売ると決めて確保する**（計画ベース） |
> | 判断者 | 売場担当 | 商品調達機能（社長）＋店長 |
> | 誤ったときのリスク | 欠品または棚の在庫過多 | **大量の売れ残り** |
> | 頻度 | 日次〜週次 | 特売企画ごと（＝発注時） |

> **発注担当が実際に見ているもの** `【Typical】`
> 発注は「システムが示す数字を入力する作業」ではありません。次のような要素を重ねて判断します。
>
> | 見るもの | なぜ見るか |
> |---|---|
> | 在庫数 | 次の納品まで持つかを判断するため |
> | 直近の販売数 | 何日で売れるかの目安を得るため |
> | **天気予報** | 雨なら客数が減る。暑ければ冷たいもの、寒ければ鍋物が売れる `【Typical】` |
> | 曜日・給料日・行事 | 客数と買い方が変わる |
> | **特売の予定** | 特売品の周辺商品も一緒に売れることがある |
> | 競合店の動き | 競合が同じ商品を特売していれば自店の売れ行きは落ちる |
> | 期限 | 期限内に売り切れる量しか発注できない |
>
> `【Inference】` **これらを総合して数字を決めるため、発注は経験の蓄積が効く仕事**になります。
> 中小小売で「発注は担当者の経験と勘が軸になる」と言われるのは、この構造によります `【Varies】`。

> **補充点（発注点）**
> → 「在庫がこの数を下回ったら発注する」と決めておく基準の数のこと。
> → 実務例：リードタイムが1日で、1日に平均10個売れる商品なら、
>   在庫が15個を切ったら発注する、というように決めます。
>   **余裕分（安全在庫）を含めておかないと、売れ行きが伸びた日に欠品します。**

#### ⑧-2 入荷品の受け取りと売場への展開

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | バックヤードでの荷受・検品・検収の完了（A-3〜A-5／＝納品時） |
| **誰が行うか** | 売場担当（部門チーフ・パート・アルバイト）。小規模店では**売場担当が荷受・検品も兼ねる** `【Typical】` |
| **何を確認するか** | **自部門宛の商品がすべて届いているか**／数量が発注と合っているか／**品質（傷み・変色・破損）**／**賞味期限・消費期限が十分か**／規格（サイズ・等級）／**冷蔵・冷凍品の温度** |
| **何をするか** | 商品を受け取る。**冷蔵・冷凍品は速やかに適切な温度帯へ移す**。加工が必要なものは加工場へ、そのまま並べるものは売場へ運ぶ。バックヤードに置くものは保管場所へ入れる |
| **何を判断するか** | すぐ売場に出すか／バックヤードに置くか／**品質に問題があれば返品するか** |
| **誰と連携するか** | バックヤード機能、店長、仕入先（差異・品質の問題があった場合） |
| **最終的に何ができあがるか** | 売場・加工場・保管場所に配置された商品 |
| **頻度** | **日次**（納品の都度＝納品時） |

> **なぜこの業務が必要なのか**
> `【Typical】` 冷蔵・冷凍品は、**荷受から保管までの時間が品質に直結します**
> （`04_end-to-end-process.md` A-3）。
> 「トラックが着いたらすぐ冷蔵庫へ入れる」という単純な作業が、
> **鮮度の維持＝ロスの削減**に直結します。
>
> `【Inference】` 逆にいえば、納品時間帯に人が足りないと、
> 商品が常温のバックヤードに置かれたままになり、その日のうちに品質が落ちます。
> **だから納品時間帯の人員配置は、シフトを組むうえで外せない要素**になります（⑦-2）。

#### ⑧-3 加工（生鮮・惣菜）★部門により大きく異なる★

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 入荷（＝納品時）／**その日の売場計画に基づく仕込み**／売場の減り具合を見た追加加工（＝日次） |
| **誰が行うか** | **水産・畜産・惣菜の部門チーフと加工担当**（技能が必要）。青果は簡易な調製・パック詰め `【Varies】` |
| **何を確認するか** | **原料の状態（鮮度・品質）**／その日の売れ行きの見込み／**何をどれだけ作るか（仕込み量）**／作業場の衛生状態（手洗い・服装・器具の洗浄）／**加熱・冷却の温度と時間**（惣菜）／**アレルゲン・原材料の表示に必要な情報**／歩留まり（原料から商品になる割合） |
| **何をするか** | 【水産】魚をおろす・切り身にする・刺身にする・パック詰めする 【畜産】ブロック肉をスライス・ミンチにする・パック詰めする 【惣菜】調理する・盛り付ける・パック詰めする 【青果】カット野菜・果物の袋詰め・盛り合わせ `【Varies】` |
| **何を判断するか** | **何をどれだけ作るか**（作りすぎれば当日廃棄、少なすぎれば売り逃し）／1パックあたりの分量と価格帯／追加で作るか・作るのをやめるか |
| **誰と連携するか** | 店長、他部門（関連陳列）、仕入先（原料の相談）、清掃・保安機能（作業場の衛生） |
| **最終的に何ができあがるか** | **パック詰めされ、ラベルが貼られた商品** |
| **頻度** | **日次**（1日に複数回） |

> **なぜこの業務が必要なのか**
> `【Inference】` 生鮮品は、**仕入れた形のままでは売れません**。
> 魚1匹、肉のブロック、原材料——これらは家庭で使える単位に分けて初めて商品になります。
> つまり生鮮部門では、**小売業でありながら「加工」という製造に近い工程を持っている**ことになります。
>
> これが生鮮部門の粗利率が高く（`【Fact】` 畜産28.4％、水産28.2％、惣菜38.5％、2024年）、
> 同時にロス率も高い（`【Fact】` 惣菜10.6％、水産8.6％、畜産6.6％、2024年）理由です。
> **手間をかけた分だけ粗利が乗るが、その日のうちに売り切らなければならない。**

> **歩留まり（ぶどまり）**
> → 仕入れた原料のうち、実際に商品として売れる部分の割合のこと。
> → 実務例：魚1匹3,000gを三枚におろすと、頭・骨・内臓が除かれて切り身は1,800gになる。
>   このとき歩留まりは60％。
>   **原価計算は「1匹いくら」ではなく「売れる部分1gあたりいくら」で考える必要があります。**
>   歩留まりを読み違えると、値付けが狂い、粗利が出ません。

> **【重要】仕込み量の判断が惣菜の粗利を決める**
> `【Example】`（説明用の架空例。`04_end-to-end-process.md` 4-4 の例と同じ構造）
> 弁当を20個仕込む。原価400円・売価600円（値入率33.3％）。
> 14個が定価で売れ、4個が3割引、1個が半額、1個が廃棄。
> → 売上10,380円・原価8,000円 → 粗利2,380円（粗利率22.9％）。
> **値入率33.3％の計画に対し、実際は22.9％。**
>
> `【Inference】` もし15個しか仕込まなければ廃棄はゼロになりますが、
> 売り逃しが出ていた可能性があります。
> **「何個作るか」の判断が、そのまま粗利になります。**

#### ⑧-4 値付け（プライスカード・計量ラベル）

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 検収の完了／**加工の完了**／売価の変更決定／特売の開始（＝日次） |
| **誰が行うか** | 売場担当（部門チーフ・パート・アルバイト）。**生鮮・惣菜は加工とセット** |
| **何を確認するか** | **売価は決められたとおりか**（定番売価・特売売価）／**仕入価格が変わっていないか**／競合店の売価／**計量が正しいか**／**表示事項が揃っているか**（名称・原産地・内容量・消費期限／賞味期限・保存方法・アレルゲン等） |
| **何をするか** | プライスカード・値札を作成し、商品または棚に付ける。生鮮・惣菜は**計量してラベル（重量・単価・売価・期限）を発行し貼付する** |
| **何を判断するか** | 定番売価のままでよいか／仕入価格の変動を売価に反映するか（判断は本部と相談） |
| **誰と連携するか** | 商品調達機能（売価変更が必要な場合）、店長、情報システム機能（売価マスタ）、レジ・接客機能（レジと売場の一致） |
| **最終的に何ができあがるか** | **値札・ラベル付きの商品**、売場のプライスカード |
| **頻度** | **日次** |

> **なぜこの業務が必要なのか**
> `【Inference】` 値付けには2つの意味があります。
> 1. **客に価格を伝える**（伝わらなければ買われない）
> 2. **レジで正しい金額を通す**（売場とレジが食い違えばトラブルになる）
>
> 特に生鮮・惣菜は、**1パックごとに重量が違うため、1枚ずつラベルを発行**します。
> ここで単価や計量を誤れば、そのまま粗利がずれます（`04_end-to-end-process.md` A-6）。

> `【Fact】` **計量に関するルール**
> 計量法の商品量目制度では、政令で定める**特定商品**（食肉、魚介類、野菜など）を
> 法定計量単位で示して販売するとき、**政令で定める誤差（量目公差）を超えないように計量する**
> ことが求められています（出典：計量法における商品量目制度の概要／経済産業省）。
> `【Typical】` 食品スーパーの青果・精肉・鮮魚・惣菜は、この制度に基づく立入検査の対象になり得ます。

> `【Fact】` **表示に関するルール**
> 食品表示基準では、**生鮮食品は「名称」と「原産地」の表示が義務**とされ、
> 加工食品では原材料・添加物・アレルゲン等の表示が求められます
> （出典：食品表示基準に関する消費者庁・農林水産省の解説）。
> `【Typical】` 店内で加工・パック詰めした商品にも表示が必要になるため、
> **計量ラベルの印字内容そのものが法令上の表示**を兼ねている場合があります。

> **消費期限と賞味期限の違い**（初心者が最も混同する点）
>
> | | **消費期限** | **賞味期限** |
> |---|---|---|
> | やさしい説明 | **これを過ぎたら食べないほうがよい**期限 | **おいしく食べられる**期限 |
> | 主な対象 | 弁当、惣菜、生肉、生鮮加工品など**傷みやすいもの** | 缶詰、調味料、菓子など**日持ちするもの** |
> | 売場での扱い | **期限を過ぎたら販売できない。廃棄になる** | 期限が近いものは値下げ対象になることがある `【Varies】` |
>
> `【Inference】` **惣菜・生鮮のロス率が高いのは、消費期限が短いためです。**
> 一般食品（グロサリー）のロス率が1.7％と低いのは、賞味期限が長く、
> 売れ残っても翌週・翌月に売れるからです `【Fact】`（部門別ロス率、2024年）。

#### ⑧-5 品出し・陳列・売場づくり（エンド・平台）

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 開店前の売場作り／入荷後／**特売初日の売場切り替え**／季節の切り替わり／売場が減ったとき（＝日次） |
| **誰が行うか** | 売場担当（部門チーフ）＋パート・アルバイト |
| **何を確認するか** | **棚割どおりの位置か**／**先入先出になっているか**／前面に商品が並んでいるか／**POPと売価が一致しているか**／エンド・平台に何を積むか／重い商品が下段にあるか／通路が塞がれていないか |
| **何をするか** | 定番棚・エンド・平台に商品を並べる。POPを付ける。**前出し**をする。特売の売場を作る。季節売場を立ち上げる |
| **何を判断するか** | **どこにどれだけ積むか**／売れ行きを見て場所を変えるか／関連する商品を近くに置くか |
| **誰と連携するか** | 店長、バックヤード機能（在庫の取り出し）、販促・販売企画機能（売場計画）、他部門（関連陳列） |
| **最終的に何ができあがるか** | **販売可能な売場** |
| **頻度** | **日次**（開店前・随時）／特売の切り替え時 |

> **エンド**（`03_company-structure.md` 3-5 の再掲）
> → 棚（ゴンドラ）の端にある、通路に面した売場のこと。
> → 実務例：通路を歩く客の目に入りやすいため、特売品や売り込みたい商品を置きます。
>   **同じ商品でも、定番の棚に置くかエンドに置くかで売れ方が大きく変わります。**

> **平台（ひらだい）・ワゴン**
> → 商品を平らに積み上げて売る台のこと。
> → 実務例：特売の野菜や菓子を山積みにして「安い・たくさんある」という印象を作ります。
>   **積み方が少なくなると「売れ残り」に見えてしまう**ため、
>   減ってきたら詰め直す（山を作り直す）作業が発生します `【Typical】`。

> **関連陳列（かんれんちんれつ）**
> → **一緒に使われる商品を近くに並べる**こと。
> → 実務例：鍋の材料の近くに鍋つゆを置く。刺身の近くにわさび・つまを置く。
>   焼肉用の肉の近речにタレを置く。
>   **客が思い出す前に目に入れば、買上点数（1人あたりの購入点数）が増えます** `【Inference】`。
>   これは部門をまたぐため、**部門チーフ同士または店長の調整が必要**になります。

> **なぜこの業務が必要なのか**
> `【Inference】` 陳列は「並べること」ではなく、**客が選べる状態を作ること**です。
> - 商品が奥に引っ込んでいる → 品薄に見えて手に取られない
> - 棚割と違う場所にある → 客が見つけられない
> - 期限の新しいものが手前にある → 古いものが売れ残って廃棄になる
> - POPと値段が違う → レジでトラブルになる
>
> どれも「並んではいる」のに売れない・損が出る状態です。

#### ⑧-6 フェイス管理・前出し

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 開店前／営業時間中の巡回／**ピーク時間帯の後**／棚割の変更時（＝常時／日次） |
| **誰が行うか** | 売場担当、パート・アルバイト |
| **何を確認するか** | **各商品のフェイス数が棚割どおりか**／商品が前面に出ているか／**欠品・品薄になっていないか**／商品の向き（正面が見えているか）／別の場所に紛れ込んだ商品がないか |
| **何をするか** | **前出し**（商品を棚の手前に引き出す）を行う。乱れた商品を整える。売れ行きに応じてフェイス数を変える（判断は部門チーフ） |
| **何を判断するか** | フェイスを増やすか減らすか／**売れていない商品の場所を変えるか** |
| **誰と連携するか** | 店長、商品調達機能（棚割の変更が必要な場合） |
| **最終的に何ができあがるか** | **整った売場**、フェイスの調整結果 |
| **頻度** | **常時／日次**（1日に複数回） |

> **フェイス**（`03_company-structure.md` 3-5 の再掲）
> → 売場で商品が正面を向いて並んでいる、その「面」の数のこと。
> → 実務例：ある醤油を棚で横に3本並べれば「3フェイス」。
>   フェイスを増やせば目立ち、補充の頻度を減らせますが、その分ほかの商品の場所がなくなります。

> **前出し（まえだし）／フェイスアップ**
> → 棚の奥に下がった商品を、手前に引き出して並べ直す作業のこと。
> → 実務例：客が手前の商品を取ると、棚は奥だけに商品が残った状態になります。
>   このままだと「売り切れ」「品薄」に見え、**実際には在庫があるのに売れなくなります**。
>   だから前出しは、**在庫を増やさずに売場を回復させる作業**です。

> **なぜこの業務が必要なのか**
> `【Inference】` 前出しは、小売業で最も地味で、最も頻繁に行われる作業の一つです。
> 一見「見た目を整えているだけ」に見えますが、実際には
> 1. **欠品に見える状態を防ぐ**（売上を守る）
> 2. **在庫が奥に残っていることを発見する**（不要な発注を防ぐ）
> 3. **期限の古い商品を見つける**（廃棄を防ぐ）
>
> という3つの効果を同時に持ちます。
> `【Typical】` だからこそ、パート・アルバイトの基本作業として最初に教えられます。

#### ⑧-7 在庫補充（品出し）

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 売場の商品が減ったとき／開店前／**ピーク前の準備**（＝常時／日次） |
| **誰が行うか** | 売場担当、パート・アルバイト |
| **何を確認するか** | どの商品が減っているか／**バックヤードに在庫があるか**／期限の古いものが手前にあるか／売場が乱れていないか／**補充してもまだ足りない＝欠品情報**か |
| **何をするか** | バックヤードから商品を出して棚に補充する。**先入先出で並べる**。段ボール・トレー等の資材を片付ける。前出し・整頓をする |
| **何を判断するか** | 補充するか／売れていないので場所を変えるか／**在庫がないので発注に反映するか** |
| **誰と連携するか** | バックヤード機能、部門チーフ（発注へのフィードバック）、店長 |
| **最終的に何ができあがるか** | 補充された売場、**欠品情報**（次の発注に使う） |
| **頻度** | **常時／日次** |

> **なぜこの業務が必要なのか**
> `【Inference】` 補充は「売場を埋める作業」であると同時に、**発注のための情報収集**でもあります。
> 「補充しようとしたらバックヤードにもなかった」＝欠品。
> 「バックヤードに山ほど残っている」＝発注しすぎ。
> **品出しをする人が、在庫の実態を最初に知る立場にいます。**
> だからこの情報が部門チーフ（発注担当）に伝わるかどうかが、翌日の発注精度を左右します。

#### ⑧-8 鮮度チェック・先入先出 ★食品小売の中心業務★

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 開店前／営業時間中の巡回／補充の都度／閉店前（＝常時／日次） |
| **誰が行うか** | 売場担当、パート・アルバイト。**判断（撤去・値下げ）は部門チーフ** |
| **何を確認するか** | **消費期限・賞味期限**／見た目の状態（変色・傷み・しなび・ドリップ）／**冷蔵・冷凍ケースの温度**／包装の破れ／**期限の古いものが手前にあるか（先入先出ができているか）** |
| **何をするか** | 期限を1つずつ確認する。**期限の近いものを手前に出す**。状態が落ちた商品を撤去する。値下げ対象を部門チーフに報告する |
| **何を判断するか** | そのまま売るか／**値下げするか**／**撤去・廃棄するか** |
| **誰と連携するか** | 部門チーフ、店長、清掃・保安機能（廃棄物の処理） |
| **最終的に何ができあがるか** | 鮮度の保たれた売場、**値下げ・廃棄の候補リスト** |
| **頻度** | **常時／日次**（1日に複数回） |

> **先入先出（さきいれさきだし）**（`04_end-to-end-process.md` A-7 の再掲）
> → **先に入荷した（期限が近い）商品から先に売る**ように並べること。
> → 実務例：牛乳を補充するとき、新しい商品を奥に入れ、古い商品を手前に出します。
>   逆にすると古い商品が奥に残り続け、**期限切れ＝廃棄ロス**になります。

> **なぜこの業務が必要なのか**
> `【Inference】` 先入先出は、**やらなくても当日は何も起きない作業**です。
> だからこそ徹底が難しく、徹底されているかどうかでロス率が変わります。
>
> `【Example】`（説明用の架空例）新しい牛乳を手前に置いた。
> → 客は手前から取るので、新しいものから売れる。
> → 奥の古い牛乳は取られないまま期限を迎える。
> → **廃棄。しかも「よく売れているのに廃棄が出る」という分かりにくい形で損失が出る。**
>
> 1日1本でも、年間365本分の原価が失われます。
> **この単純な作業の徹底が、部門のロス率に直結します。**

#### ⑧-9 値下げ・見切りの判断 ★粗利を日々左右する判断★

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | **期限が迫ったとき**／**閉店が近づいたとき**／売れ行きが計画を下回ったとき／シーズンが終わるとき／仕入価格が変わったとき（＝日次） |
| **誰が行うか** | **売場担当（部門チーフ）**。値下げ幅の大きい判断は店長 `【Typical】` |
| **何を確認するか** | **残り在庫数**／消費期限・賞味期限／**残りの営業時間**／当日の客数の出方／**部門の粗利の進捗**／過去の同じ時間帯の売れ方／競合店の状況 |
| **何をするか** | **値下げシールを貼る**／POSの売価を変更する／売場の表示を変える／値下げ品を集めて目立つ場所に置く `【Varies】` |
| **何を判断するか** | **「今いくら下げれば売り切れるか」。** 下げすぎれば粗利を失い、下げ足りなければ廃棄になる |
| **誰と連携するか** | 店長、レジ・接客機能（変更後の売価が正しく通るか）、情報システム機能（売価の変更） |
| **最終的に何ができあがるか** | **売価変更情報**、**値下げロスの記録** |
| **頻度** | **日次**（惣菜・生鮮）／シーズン末（衣料・季節品）＝その他 |

> **見切り（みきり）**（`04_end-to-end-process.md` A-10 の再掲）
> → 売れ残りそうな商品を、**期限内に売り切るために値下げする**こと。
> → 実務例：閉店2時間前に惣菜を3割引、1時間前に半額にする。

> **なぜこの業務が必要なのか — 廃棄との比較**（`04_end-to-end-process.md` A-10 の再掲）
> `【Example】`（説明用の架空例）原価400円・売価600円の弁当が1個残っている。
> - 半額300円で売る → **300円は回収できる**（粗利は▲100円だが、現金は入る）
> - 捨てる → **原価400円がまるごと損失**
>
> つまり見切りは「損を確定させる行為」ではなく、**「損を小さくする行為」**です。

> **【最重要】見切りのタイミングが難しい理由**
> `【Inference】`
> ```
>   見切りを早く始める → 確実に売り切れる → しかし定価で買うはずだった客まで
>                                          値下げ品を買い、全体の粗利が下がる
>   見切りを遅らせる   → 定価で売れる分が増える → しかし売り切れずに廃棄が出る
> ```
> さらに、**客が「この店は○時になると半額になる」と学習する**と、
> その時間まで買い控えが起きます `【Typical】`。
> **つまり見切りは、その日の判断であると同時に、客の買い方を作ってしまう判断**でもあります。
>
> これが「いつから、いくら下げるか」が惣菜・生鮮の粗利を左右する日々の判断である理由です。

#### ⑧-10 廃棄処理（ロス計上）

| 観点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | **消費期限・賞味期限の到来**／品質の劣化／破損／見切っても売れ残ったとき（＝日次） |
| **誰が行うか** | 売場担当、パート・アルバイト |
| **何を確認するか** | **本当に販売できないか**（値下げで売り切れないか）／**廃棄する数量と金額**／どの商品・どの部門か／廃棄物の分別 |
| **何をするか** | 売場から撤去する。**廃棄として登録する（ロス計上）**。廃棄物として分別し、所定の場所へ出す |
| **何を判断するか** | 廃棄するか／値下げで売り切るか（⑧-9 に戻す判断） |
| **誰と連携するか** | 店長、経理・財務機能（ロス金額の集計）、清掃・保安機能、廃棄物処理業者 |
| **最終的に何ができあがるか** | **廃棄ロスの記録（ロス情報）**、廃棄物 |
| **頻度** | **日次** |

> **なぜ廃棄を「登録」するのか**（`04_end-to-end-process.md` A-11 の再掲）
> `【Inference】` 捨てるだけなら記録は要らないように見えますが、記録しないと次の3つができません。
> 1. **在庫数が合わなくなる**（帳簿上は残っているのに現物がない → **不明ロスに化ける**）
> 2. **粗利が正しく計算できない**（なぜ粗利率が計画より低いのか分からなくなる）
> 3. **次の発注を直せない**（どの商品がいくつ余っているのか分からない）
>
> `【Fact】` 食品スーパーの商品カテゴリー別廃棄率（金額ベース、2024年）は
> 惣菜2.4％、水産2.2％、青果1.3％、畜産1.2％、日配品1.0％、一般食品0.6％、非食品0.4％
> （出典：2024年スーパーマーケット年次統計調査報告書）。

> `【Inference】` 部門チーフは、**その部門の小さな経営者**にあたります。

> 「店全体で粗利率26％」ではなく「惣菜は目標38.5％に対して実績いくつか」という見方をします。

#### この表から読み取るべきこと

> **① 「生鮮」と「グロサリー」では、仕事の性質が根本的に違う**
> `【Inference】`
> ```
>   生鮮3部門（青果・水産・畜産）＋惣菜
>     → 仕入価格が毎日変わる／加工が必要／期限が短い／毎日値下げが発生する
>     → 「毎日ゼロから売場を作り直す」仕事
>
>   一般食品（グロサリー）・非食品
>     → 仕入価格が安定／加工なし／期限が長い／値下げはまれ
>     → 「棚を切らさず、整った状態を維持する」仕事
> ```
> **同じ店の中で、この2種類の仕事が並行して動いています。**

> **② 粗利率が高い部門ほど、ロス率も高い**
> `【Fact】` 惣菜：目標利益率38.5％／ロス率10.6％
> `【Fact】` 一般食品：目標利益率19.9％／ロス率1.7％
>
> `【Inference】` これは偶然ではありません。
> **粗利率が高いのは、加工という手間をかけているからです。**
> そして加工した商品は日持ちしないため、その日のうちに売り切れなければロスになります。
> **「手間をかけて粗利を乗せる」ことと「売れ残りリスクを負う」ことは、同じことの裏表**です
> （`01_overview.md` 1-5）。

> **③ 技能の代替可能性が部門で違う**
> `【Typical】`
> - **グロサリー・非食品**：発注のコツは要るが、品出し・陳列は短期間で習得できる
> - **水産・畜産・惣菜**：**包丁技能・スライス技能・調理技能が必要**。習得に時間がかかる
>
> `【Inference】` だから生鮮部門の担当者が退職すると、その部門の売場が作れなくなります。
> 採用（⑤-1）とシフト（⑦-2）の難しさが、部門によってまったく違う理由がここにあります。

> **④ 1日の仕事の流れが部門で違う** `【Typical】`
>
> | 部門 | 1日の流れのイメージ |
> |---|---|
> | **水産・畜産** | 早朝または午前に入荷 → **加工・パック詰め** → 売場展開 → 補充 → 夕方から見切り開始 → 閉店前に廃棄判断 |
> | **惣菜** | 朝の仕込み → 昼のピークに向けた品出し → **午後に追加仕込み（量の判断）** → 夕方のピーク → **時間を追って段階的に見切り** → 閉店時に廃棄 |
> | **青果** | 早朝の入荷（相場確認） → 調製・袋詰め → 売場展開 → 補充・鮮度チェック → 傷んだものの撤去・見切り |
> | **日配** | 複数便の入荷に応じた補充 → **期限のチェック（先入先出）** → 期限接近品の見切り |
> | **グロサリー** | 入荷 → 検品 → 定番棚への補充 → **棚割どおりの整頓・前出し** → 特売の売場作り |
> | **非食品** | 入荷 → 補充 → 陳列の整頓 → 季節商品の入れ替え |
>
> `【Inference】` **加工がある部門は「作る時間」が必要**なので、
> 入荷の時間帯に人を集中させる必要があります。
> 一方グロサリーは加工がないため、時間帯の制約が相対的にゆるやかです。
> **シフトを組むとき、部門ごとに必要な時間帯が違う**のはこのためです。

### O. 見ている数字・KPI

| 数字 | 意味 | なぜ見るか |
|---|---|---|
| **部門売上・売上構成比** | その部門がどれだけ売ったか | 部門が店に占める位置を見る（`【Fact】` 例：グロサリー24.3％、2024年） |
| **部門粗利率** | 実際に残った利益幅 | 目標利益率との差を見る（`【Fact】` 例：惣菜の目標38.5％、2024年） |
| **値入率** | 予定した利益幅 | 粗利率との差＝ロスの大きさが分かる |
| **ロス率（値下げ＋廃棄＋不明）** | 失われた粗利の割合 | `【Fact】` 部門差が大きい（惣菜10.6％〜非食品1.5％、2024年） |
| **廃棄率（金額ベース）** | 捨てた分の割合 | `【Fact】` 惣菜2.4％、一般食品0.6％など（2024年） |
| **販売数量・PI値** | 客1,000人あたり何個売れたか | 客数の違いを除いて売れ方を比べるため |
| **欠品率** | 棚が切れている割合 | 発注が需要に追いついているかを見る |
| **在庫数・在庫日数** | 何日分持っているか | 発注しすぎ・少なすぎを見る |
| **歩留まり** | 原料のうち商品になった割合 | 生鮮・惣菜の原価計算の前提 |
| **仕込み量と消化率** | 作った量のうち売れた割合 | 惣菜の粗利を直接決める |

## 4-0 【最初に】宿泊業のフローは「受注→製造→納品→請求→入金」ではない

### 他業界との決定的な違い

製造業や卸売業では、仕事は次の順に進みます。

```
  引き合い → 見積 → 受注 → 製造/仕入 → 納品 → 検収 → 請求 → 入金
```

宿泊業は違います。宿泊業の基本サイクルは次のとおりです。

```
  【価格を決めて在庫を出す】 → 【予約】 → 【滞在】 → 【精算】 → 【清掃】 → 【再び在庫へ】
```

### 3つの構造的な違い

#### ① 「作ってから売る」のでも「売ってから作る」のでもない — **商品は先に存在している**

`【Inference】` 客室は建物が建った時点ですでに存在しています。
宿泊業がしているのは「作ること」ではなく、
**「すでにある部屋を、日付ごとに区切って、値段を付けて出すこと」**です。

したがって、製造業でいう「受注してから生産する」という工程がありません。
代わりに、**「今日の分の商品（＝今日の70室）を、今日中に売り切る」**という
毎日くり返される販売行為があります。

#### ② 商品は売れなくても消える — **時間切れがある**

`01_overview.md` 1-1 のとおり、**今日売れなかった部屋は明日には消えます。**
製造業の在庫は明日も売れますが、宿泊業の在庫は日付とともに消滅します。

`【Inference】` このため、宿泊業のフローには
**「締め切りが毎日訪れる」**という他業界にない緊張があります。

#### ③ 代金の受け取り方が客ごとに違う — **チャネルによってカネの入り方が違う**

`02_industry-structure.md` 11-2 のとおり、同じ1泊でも
**直販か、OTA経由か、代理店経由か、法人契約か**で
「誰が集金するか」「いつ宿に入るか」「いくら引かれるか」がすべて違います。

**これが宿泊業のカネの流れを理解するうえで最も重要な点**なので、
本ファイルでは A（1予約のライフサイクル）と B（チャネル別の入金）に分けて説明します。

### 宿泊業では3つのサイクルが同時に走っている

```
【サイクルA】1件の予約のライフサイクル
   価格設定 → 在庫配分 → 予約受付 → 予約管理 → 決済 → 到着前準備
   → チェックイン → 滞在中対応 → チェックアウト・精算 → 客室清掃 → 次の販売へ
   （1件あたり：数か月〜数分で始まり、滞在翌日に終わる）

【サイクルB】チャネル別の入金サイクル
   売上の発生 → チャネルごとの集計 → 精算・請求 → 入金 → 消込
   （月次が中心。チャネルにより1週間〜2か月のずれ）

【サイクルC】毎日の運営サイクル（オペレーション）
   前日：翌日の到着リスト確定 → 食材発注 → シフト確認
   当日：朝の情報共有 → チェックアウト → 清掃 → チェックイン → 夜間対応 → 日次締め
   （毎日・例外なく回る）
```

**本ファイルでは A と B を扱います。C は `13_periodic-work.md` で詳述します。**

#### A-1 販売価格の設定

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 日次の業務として（多くは朝または夕方）。また大型イベントの発表時 |
| **誰が行うか** | ① 予約・販売管理機能。`【Varies】` 専任者／支配人／女将 |
| **何を確認するか** | ・今日から先、日付ごとの予約の入り具合（何室埋まっているか）<br>・過去の同時期の実績<br>・曜日、連休、地域のイベント（祭り・大会・学会・工事）<br>・周辺の宿の状況 `【Varies】` |
| **何をするか** | 日付ごと・部屋タイプごとに販売価格を決める。プラン（素泊まり・朝食付き等）ごとの価格も決める |
| **何を判断するか** | 「この価格で残りが売り切れるか」「上げてよいか」「下げるべきか」「安いプランを閉じるか」 |
| **誰と連携するか** | ② フロント（問い合わせの手応え）、⑦ 営業（法人・団体の動き）、⑤ 調理（食事の数の見込み） |
| **何が出来上がるか** | **日付別・部屋タイプ別・プラン別の販売価格** |
| **頻度** | **日次**（繁忙期）／**週次**（閑散期）`【Varies】` |

**なぜするのか**
`【Inference】` `01_overview.md` のとおり**部屋は売れ残ると消える**ため、
「定価を決めたら終わり」にはできません。
需要が読めない日は、予約の入り方を見ながら価格を動かすことになります。
これが `02_industry-structure.md` で説明した**レベニューマネジメント**です。

> **繁忙期の価格変動について**
> `【Typical】` 需要が集中する日（連休・地域の大型イベント・年末年始）は、
> 平常時より高い価格が設定されることが一般的です。
> `【Inference】` これは `01_overview.md` Level 1 ② のとおり
> **部屋数を増やせないため、需要が供給を超えると価格で調整するしかない**からです。
> **本資料はこの現象を説明するもので、価格設定の是非を論じるものではありません。**

#### A-2 在庫（部屋）の各チャネルへの配分

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | A-1 で価格が決まったとき。また予約状況が動いたとき |
| **誰が行うか** | ① 予約・販売管理機能 |
| **何を確認するか** | ・全体の販売可能室数（修繕中・従業員用等を除く）<br>・チャネルごとの現在の販売状況<br>・法人契約で確保している枠<br>・団体の仮予約で押さえている枠 |
| **何をするか** | 「直販に何室、OTA各社に何室、代理店に何室」を決め、**サイトコントローラー**で各チャネルに一括反映する |
| **何を判断するか** | 「どのチャネルに厚く出すか」「団体枠をいつ解放するか」 |
| **誰と連携するか** | PMS事業者・サイトコントローラー（システム）、⑦ 営業（団体枠の判断） |
| **何が出来上がるか** | **各チャネルに表示される空室数と価格** |
| **頻度** | **日次**／価格変更時 |

**なぜするのか**
`【Inference】` 複数のチャネルで同じ部屋を売っているため、
**どこかで1室売れたら、他のすべてのチャネルで在庫を1つ減らさなければなりません。**
これを手作業で行うと反映が遅れ、**オーバーブッキング**（後述）が発生します。

> **団体枠（ブロック）について**
> `【Typical】` 旅行代理店や団体客のために「○月○日、20室を押さえておいてほしい」と
> 依頼されることがあります。これを**ブロック**と呼びます。
> `【Typical】` ブロックには「いつまでに確定するか」の期限が設けられ、
> 期限までに確定しなければ枠を解放して一般販売に戻します。
> `【Inference】` 押さえたまま期限を過ぎると、その部屋は売る機会を失ったまま消えるためです。

#### A-3 予約受付

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 客からの予約申込（電話・自社サイト・OTA・代理店・法人からの依頼） |
| **誰が行うか** | ② フロント機能。OTA経由は**システムが自動で受信**し、人は内容を確認する |
| **何を確認するか** | ・宿泊日と泊数／人数（大人・子供）／部屋タイプ・室数<br>・プラン（素泊まり・朝食付き・2食付き）<br>・氏名・連絡先<br>・決済方法（事前決済か現地決済か）<br>・特記事項（到着予定時刻、アレルギー、駐車場、連泊時の清掃要否）<br>・**空室があるか**（最重要） |
| **何をするか** | 予約内容をPMSに登録し、在庫を1つ減らし、客へ**予約確認**を返す |
| **何を判断するか** | ・受けられるか（空室・人数・条件）<br>・**宿泊を断るべき事由に該当しないか**（後述 4-3 ①） |
| **誰と連携するか** | ① 予約・販売管理（在庫の減少を反映）、⑤ 調理（食事の数が変わる）、⑦ 営業（法人・団体の場合） |
| **何が出来上がるか** | **予約記録**（PMS上）、**予約確認書**（メール・書面）`【Varies】` |
| **頻度** | **常時**（OTAは24時間入る） |

**なぜするのか**
`【Inference】` 予約とは、**「その日その部屋を使う権利を客に渡し、
その分の在庫を市場から引き上げる」**という行為です。
記録が正確でないと、二重販売、到着日の食い違い、人数違いによる食事不足が起きます。

> **初心者がつまずく点：予約 ≠ 売上**
> `【Typical】` 予約を受けた時点では、**まだ売上にはなりません。**
> 売上が確定するのは、原則として**宿泊のサービスを提供したとき**（A-9 の精算時）です。
> 予約は「将来の売上の見込み」であり、キャンセルされれば消えます。

#### A-4 予約管理（到着日まで）

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 予約登録後、到着日までの間に発生する変更・問い合わせ |
| **誰が行うか** | ② フロント機能／① 予約・販売管理機能 |
| **何を確認するか** | ・変更内容（日程変更・人数変更・部屋タイプ変更・プラン変更）<br>・キャンセル（キャンセル料の発生有無）<br>・**同一人物の重複予約がないか**<br>・団体の人数確定期限が来ていないか |
| **何をするか** | PMSの予約内容を修正し、在庫を増減させ、各チャネルに反映する。<br>団体には確定人数の連絡を依頼する |
| **何を判断するか** | ・キャンセル料を請求するか（キャンセルポリシーに照らす。後述 4-3 ②）<br>・団体枠をいつ解放するか |
| **誰と連携するか** | ⑤ 調理（人数が変われば食材発注が変わる）、③ 清掃（室数が変われば清掃量が変わる）、⑧ 経理（キャンセル料の請求） |
| **何が出来上がるか** | **最新の予約状態**、**キャンセル料の請求データ**（発生した場合） |
| **頻度** | **常時**（変更は随時発生）／団体の確定は**契約上のタイミング** |

**なぜするのか**
`【Inference】` 予約は「入れたら終わり」ではありません。
到着までの間に変わり続けます。この反映が遅れると、
**在庫が実態と合わなくなり、売れるはずの部屋を売り逃すか、二重に売ってしまいます。**

#### A-5 事前決済 または 現地決済の確定

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 予約時（決済方法の選択）／到着時（現地決済の実行） |
| **誰が行うか** | ② フロント機能。集計は ⑧ 経理・財務機能 |
| **何を確認するか** | ・**誰が集金するか**（宿／OTA／代理店／企業）<br>・**いつ集金するか**（予約時／到着時／出発時／後日請求）<br>・支払手段（現金・カード・コード決済・請求書払い） |
| **何をするか** | 決済区分を予約記録に明記する。事前決済であれば入金済みの印を付ける |
| **何を判断するか** | 法人の場合、**掛売（後払い）を認めるか**（契約の有無・与信）`【Varies】` |
| **誰と連携するか** | ⑧ 経理・財務（入金の管理）、⑦ 営業（法人契約の条件） |
| **何が出来上がるか** | **決済区分が確定した予約記録** |
| **頻度** | **予約時**／**到着時**／**請求時** |

**なぜするのか**
`【Inference】` 宿泊業では、**同じ日に、同じ内容で泊まる客が、
まったく違うお金の流れを持っています。**
チェックアウト時に「この客からいくら受け取るのか、それともゼロか」を
即座に判断できなければ、二重請求や取りこぼしが起きます。

> `【Example】`（説明用の架空例）同じ日にチェックアウトする3人。
> - 客あ：OTAで事前決済済み → **フロントでは1円も受け取らない**
> - 客い：直販・現地決済 → **フロントで全額を受け取る**
> - 客う：A社の法人契約 → **フロントでは受け取らず、月末にA社へ請求**
>
> **見た目は同じ「1泊の客」ですが、精算の仕方は3通りです。**

#### A-6 到着前準備

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 前日または当日朝（施設の運用による `【Varies】`） |
| **誰が行うか** | ② フロント機能が中心。③ 清掃、④⑤ 料飲・調理、⑥ 設備管理が連動 |
| **何を確認するか** | ・当日の到着予定件数・人数<br>・当日のチェックアウト件数（＝清掃すべき室数）<br>・部屋タイプ別の内訳<br>・特記事項（アレルギー、記念日、高齢の客、団体、車椅子の利用、早着・遅着）<br>・清掃が間に合うか、修繕中の部屋がないか |
| **何をするか** | ・**当日到着リスト**を出す<br>・**客室の割り当て（アサイン）**を行う<br>・清掃業者へ当日の清掃室数を連絡する<br>・調理へ当日の食事数と特記事項を伝える<br>・朝の情報共有（申し送り） |
| **何を判断するか** | ・どの部屋を誰に割り当てるか（高層階の希望、静かな部屋、隣同士にする団体）<br>・清掃の順番（早くチェックインする客の部屋を先に） |
| **誰と連携するか** | ③ 清掃、④⑤ 料飲・調理、⑥ 設備管理、⑦ 営業（団体の場合） |
| **何が出来上がるか** | **当日到着リスト**、**客室アサイン表**、**清掃指示（室数・優先順）**、**食事の数** |
| **頻度** | **日次** |

- **アサイン（客室の割り当て）**
  → 予約に対して「実際にどの部屋番号を使うか」を決めること。
  → 実務例：3名の家族連れにはツインにエキストラベッドを入れた部屋を、
    早朝出発の客にはエレベーター近くの部屋を、団体には同じ階の連番の部屋を割り当てる。
  → **なぜするのか**：予約の時点では「シングル1室」としか決まっていないためです。
    部屋によって眺望・広さ・静かさ・エレベーターからの距離が違い、
    また清掃の進み具合も部屋ごとに違います。

#### A-7 チェックイン ★法令上の義務が集中する工程★

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 客の到着 |
| **誰が行うか** | ② フロント機能 |
| **何を確認するか** | ・予約の有無と内容（氏名・日付・泊数・人数・プラン）<br>・**本人確認**<br>・**宿泊者名簿に記載すべき事項**<br>・決済区分（事前決済済みか、現地で受け取るか）<br>・**宿泊を拒む事由に該当しないか**（4-3 ①） |
| **何をするか** | ・宿泊者名簿への記載（または記入依頼）<br>・鍵の受渡し<br>・館内の案内（食事の時刻と場所、浴場、Wi-Fi、避難経路）<br>・（現地事前収受の場合）宿泊料の受領 |
| **何を判断するか** | ・予約と実際の人数・構成が合っているか<br>・部屋を変更する必要がないか |
| **誰と連携するか** | ③ 清掃（部屋が仕上がっているか）、④ 料飲（食事時刻の確定）、⑥ 設備（不具合の有無） |
| **何が出来上がるか** | **宿泊者名簿（法定帳簿）**、**在館情報**、（受領した場合）**入金記録** |
| **頻度** | **常時**（到着時） |

##### 宿泊者名簿 — 法律で義務づけられた帳簿

`【Fact】` 営業者は、厚生労働省令で定めるところにより、
**旅館業の施設その他の厚生労働省令で定める場所に宿泊者名簿を備え**、
これに**宿泊者の氏名、住所、連絡先**その他の厚生労働省令で定める事項を記載し、
**都道府県知事の要求があったときは、これを提出**しなければなりません
（旅館業法第6条第1項）。

`【Fact】` 省令が定める詳細は次のとおりです（旅館業法施行規則第4条の2）。

| 項目 | 内容 |
|---|---|
| **備える場所** | ① 旅館業の施設、② 営業者の事務所（第2項） |
| **保存期間** | **作成の日から3年間**（第1項） |
| **作成の要件** | 正確な記載を確保するための措置を講じた上で作成すること（第1項） |
| **記載事項** | 宿泊者の**氏名・住所・連絡先**（法第6条第1項）<br>＋ 宿泊者が**日本国内に住所を有しない外国人**であるときは、**その国籍及び旅券番号**（第3項第1号）<br>＋ その他**都道府県知事が必要と認める事項**（第3項第2号） |

`【Fact】` また、**宿泊者の側にも義務があります。**
宿泊者は、営業者から請求があったときは上記の事項を告げなければなりません（旅館業法第6条第2項）。
`【Fact】` これに違反して**偽って告げた者は、拘留または科料**に処せられます（同法第12条）。

`【Fact】` 営業者が第6条第1項に違反した場合は、**50万円以下の罰金**です（同法第11条第1号）。

**なぜするのか**
`【Inference】` 宿泊者名簿は、**感染症が発生したときに誰がその施設に泊まっていたかを
追跡できるようにするため**、また**事件・事故が起きたときの手がかりとするため**の
仕組みです。旅館業法の目的（第1条）が「公衆衛生及び国民生活の向上」であることと対応しています。

> **初心者がつまずく点：「面倒な書類」ではなく「法定帳簿」です。**
> 宿泊者名簿は、宿が自主的に作っている顧客リストではありません。
> **法律で記載事項・保存期間・提出義務が決まっている帳簿**であり、
> 不備には罰則があります。

##### 本人確認

`【Fact】` 旅館業法施行規則第4条の3第2号は、玄関帳場等の設備の基準として
**「宿泊者名簿の正確な記載、宿泊者との間の客室の鍵の適切な受渡し及び
宿泊者以外の出入りの状況の確認を可能とする設備を備えていること」**を求めています。

`【Inference】` つまり法令は、**「名簿を正しく書けること」と「誰が出入りしているか分かること」**を
設備面から担保しようとしています。フロントでの本人確認は、この要請に応える実務です。

`【Varies】` 具体的にどこまで確認するか（身分証の提示を求めるか等）は
施設の運用・自治体の指導により異なります。
`【Typical】` 日本国内に住所を有しない外国人については、**国籍と旅券番号の記載が
法令上必要**なため、旅券（パスポート）の提示を受けるのが一般的です。

##### 鍵の受渡し

`【Typical】` 客室の鍵（物理キー・カードキー・暗証番号）を渡す工程です。
`【Fact】` これも上記のとおり、法令が「適切な受渡しを可能とする設備」を求めている事項です。
`【Inference】` 鍵を渡すとは、**その部屋への立入権限を客に移す**ことであり、
渡す相手を取り違えれば重大な問題になります。

#### A-8 滞在中対応

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | チェックイン後、客からの依頼・時刻の到来・トラブルの発生 |
| **誰が行うか** | ② フロント、④ 料飲（食事）、⑤ 調理、⑥ 設備管理 |
| **何を確認するか** | ・食事の時刻と人数、アレルギー等の特記事項<br>・館内設備の稼働状況<br>・客からの要望・苦情 |
| **何をするか** | ・食事の提供（`【Varies】` 施設による）<br>・要望への対応（アメニティ追加、タオル交換、荷物預かり、タクシー手配）<br>・設備トラブルへの対応（部屋の振替を含む）<br>・**追加利用の記録**（売店・自動販売機・ルームサービス・コインランドリー・駐車場） |
| **何を判断するか** | ・部屋を替える必要があるか<br>・追加料金をもらうか、サービスとするか `【Varies】` |
| **誰と連携するか** | 全機能。設備の故障時は ⑥ から外部業者へ |
| **何が出来上がるか** | **客ごとの利用明細**（宿泊料に加算されていく） |
| **頻度** | **常時**／食事は**日次**（決まった時刻）／トラブルは**トラブル発生時** |

**なぜするのか**
`【Inference】` 滞在中に発生した利用（飲食・売店・追加サービス）は、
**チェックアウト時にまとめて精算される**のが一般的です。
その場で記録しなければ、請求漏れが起きます。
また、宿泊業の商品は「泊まる時間そのもの」なので、
滞在中の対応の質が、そのまま商品の質になります。

#### A-9 チェックアウト・精算 ★売上が確定する瞬間★

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 客の出発（チェックアウト時刻まで、または客が申し出たとき） |
| **誰が行うか** | ② フロント機能 |
| **何を確認するか** | ・宿泊料（泊数×単価）<br>・追加利用分（飲食・売店・その他）<br>・**決済区分**（事前決済済みか、現地で受け取るか、法人へ請求か）<br>・適用すべき税（消費税、入湯税、宿泊税がある地域はそれも）<br>・忘れ物・客室の破損等の有無 |
| **何をするか** | 明細を確定し、支払を受け、領収書を発行し、鍵を回収して見送る |
| **何を判断するか** | ・追加請求すべきものがあるか（破損・持ち出し）`【Varies】`<br>・領収書の宛名・但し書き |
| **誰と連携するか** | ⑧ 経理・財務（売上計上）、③ 清掃（チェックアウト済み＝清掃可能の連絡） |
| **何が出来上がるか** | **売上（確定）**、**領収書**、（法人の場合）**請求対象データ**、**清掃対象の部屋** |
| **頻度** | **常時**（出発時） |

**なぜするのか**
`【Inference】` ここが**「サービスの提供が完了し、代金が確定する」点**です。
製造業でいえば納品・検収にあたります。
以降は「代金を受け取る」または「請求して受け取る」段階に移ります。

##### 精算時に上乗せされることがある税

| 税 | 内容 | 根拠 |
|---|---|---|
| **消費税** | 宿泊料・飲食代等に課される | 消費税法 |
| **入湯税** | `【Fact】` **鉱泉浴場所在の市町村**が、鉱泉浴場における入湯に対し**入湯客**に課する目的税。`【Fact】` 税率は**入湯客1人1日につき150円を標準**とする。`【Fact】` 徴収は**特別徴収**の方法によらなければならず、`【Fact】` **浴場の経営者その他徴収の便宜を有する者**が市町村の条例で特別徴収義務者として指定され、徴収して市町村に納入する | 地方税法第701条、第701条の2、第701条の3、第701条の4 |
| **宿泊税** | `【Fact】` 地方税法に定めのある税ではなく、地方団体が**条例で定める特定の費用に充てるため**に課することができる**法定外目的税**（第731条第1項）。`【Fact】` 新設・変更には**あらかじめ総務大臣に協議し、その同意を得る**必要がある（同条第2項）。`【Varies】` **課税の有無・対象・税率・免税点は地方団体ごとに条例で異なる** | 地方税法第731条以下 |

> **重要**：`【Varies】` **宿泊税は全国一律の制度ではありません。**
> 導入している自治体・していない自治体があり、税率も一律ではありません。
> 本資料では特定の自治体の税率を示しません。
> **押さえるべきは「宿が客から預かって、自治体に納める立場になる」という構造**です。

- **特別徴収（とくべつちょうしゅう）**
  → 税金の徴収に便宜を持つ者に代わりに徴収させ、納入させる方式のこと
    （地方税法第1条第1項第9号）。
  → 実務例：温泉旅館が、宿泊料とは別に入湯税を客から受け取り、
    月ごとにまとめて市町村へ納める。
  → **なぜこうするのか**：`【Inference】` 市町村が入湯客一人ひとりから直接徴収するのは
    現実的でないため、現場で接している宿が代わりに預かる仕組みになっています。
  → **注意**：`【Inference】` **これは宿の売上ではありません。**
    客から預かって行政に渡すだけのお金です。売上と混ぜてはいけません。

##### 初心者がつまずく点：売上 ≠ 入金

`【Typical】` A-9 で売上は確定しますが、**現金が宿に入るとは限りません。**

| 決済区分 | A-9 時点で現金は入るか |
|---|---|
| 現地・現金 | **入る**（即時） |
| 現地・クレジットカード | **入らない**。決済会社の締め後、後日入金 |
| OTA事前決済 | **入らない**。OTAが集金済み。精算日に手数料を引かれて入金 |
| 旅行代理店経由 | **入らない**。代理店の精算日に手数料を引かれて入金 |
| 法人契約（掛売） | **入らない**。締めて請求し、翌月以降に入金 |

**これが次の B 節のテーマです。**

#### A-10 客室清掃 ★商品を作り直す工程★

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | チェックアウトの確認（フロントからの連絡、または退室の確認） |
| **誰が行うか** | ③ 客室清掃機能（`【Varies】` 自社／外部委託） |
| **何を確認するか** | ・清掃すべき部屋の一覧と優先順<br>・当日の到着予定（早着があるか）<br>・連泊の部屋（清掃の要否・程度）<br>・備品の欠損・破損・忘れ物 |
| **何をするか** | ゴミの回収、リネンの交換、浴室・トイレの清掃、床・家具の清掃、アメニティの補充、備品の点検、換気 |
| **何を判断するか** | ・そのまま売れる状態か、修繕が必要か<br>・忘れ物をどう扱うか |
| **誰と連携するか** | ② フロント（完了報告）、⑥ 設備管理（不具合の報告）、リネンサプライ（汚れ物の引渡し） |
| **何が出来上がるか** | **販売可能な状態に戻った客室**、**清掃完了報告**、**不具合報告**、**忘れ物の記録** |
| **頻度** | **日次** |

##### 客室清掃の回転 — チェックアウトからチェックインまでが勝負

```
   10:00                    15:00                 （施設により異なる【Varies】）
     │                        │
  チェックアウト時刻       チェックイン開始時刻
     │◀──── この間に清掃を終わらせる ────▶│
     │                        │
     ├─ 客が退室              ├─ 清掃完了の部屋から順にアサイン可能
     ├─ フロントが清掃へ連絡   ├─ 早着の客への対応
     ├─ 清掃開始              │
     └─ リネン回収・交換       │
```

`【Varies】` チェックアウト時刻・チェックイン開始時刻は施設によって異なります。
`【Typical】` この**数時間の間に、その日にチェックアウトした全室を仕上げる**必要があります。

`【Inference】` ここから次の関係が導かれます。

> **その日に清掃できる部屋数 ＝ その日に受け入れられる客の数の上限**

清掃が間に合わなければ、部屋が空いていても客を入れられません。
逆に、清掃の人員は「その日のチェックアウト数」で決まるため、
**前日の予約状況が翌日の清掃人員を決めます**。

> `【Example】`（説明用の架空例）Xホテル（70室）で、今日のチェックアウトが55室。
> 清掃は1人あたり1時間に2室のペースだとすると、
> 55室 ÷ 2室 ＝ 27.5人時。5時間で仕上げるには約5.5人が必要です。
> 明日のチェックアウトが30室しかなければ、必要な人数は約3人になります。
> **毎日、必要な人数が変わります。** これが `01_overview.md` で述べた繁閑差の実務面です。

##### 連泊の場合

`【Varies】` 連泊中の客室を毎日清掃するか、ゴミ回収とタオル交換のみとするか、
客の希望で清掃を省略するかは施設により異なります。
`【Typical】` 連泊が多い日は清掃の総量が減り、清掃人員を抑えられます。

## 4-2 【サイクルB】販売チャネル別の入金の流れ

### この節が宿泊業のカネの理解の核心です

`02_industry-structure.md` 11-2 で示したとおり、
**同じ1泊でも、チャネルによって「誰が集金し、いつ宿に入り、いくら引かれるか」が違います。**
ここを理解しないと、宿泊業の資金繰りは理解できません。

### 全体図

```
                  【客が払う】              【誰が集金するか】        【宿に入るまで】
─────────────────────────────────────────────────────────────────────────────────
① 直販・現金      チェックアウト時 ──────▶ 宿が直接 ──────────────▶ 即時（その場）
                                                                     日次でレジ締め
                                                                     → 銀行へ入金

② 直販・カード    チェックアウト時 ──────▶ カード会社／決済代行 ───▶ 締め日後、後日
                                            （手数料を差し引く）       宿の口座へ

③ OTA・現地決済   チェックアウト時 ──────▶ 宿が直接 ──────────────▶ 即時
                                            （後日OTAへ手数料を支払）  ※手数料は逆に
                                                                        宿から出ていく

④ OTA・事前決済   予約時／宿泊前 ────────▶ OTAが集金 ─────────────▶ OTAの精算日に
                                            （手数料を差し引く）       後日入金

⑤ 旅行代理店      代理店の店頭等で ───────▶ 代理店が集金 ───────────▶ 代理店の精算日に
                                            （送客手数料を差し引く）   後日入金

⑥ 法人契約        企業が後日支払 ─────────▶ 宿が請求 ───────────────▶ 締め日 → 請求書
                                                                        → 翌月以降に入金
─────────────────────────────────────────────────────────────────────────────────
```

### 各チャネルの詳細

#### ① 直販・現金

| 項目 | 内容 |
|---|---|
| 集金する人 | 宿（フロント） |
| タイミング | **チェックアウト時（または到着時）** |
| 差し引かれるもの | なし |
| 宿に現金が入る時点 | **即時** |
| その後の処理 | `【Typical】` 日次でレジを締め、売上金を金庫へ。定期的に銀行へ入金 |
| 頻度 | **日次**（レジ締め） |

`【Inference】` **最も早く現金になるチャネル**です。
一方で、現金を扱う分、`【Typical】` 釣銭の準備、レジ差異の確認、
金庫での保管、銀行への搬送といった管理業務が発生します。

#### ② 直販・クレジットカード／コード決済

| 項目 | 内容 |
|---|---|
| 集金する人 | 決済会社（カード会社・決済代行会社） |
| タイミング | チェックアウト時に**決済データが成立** |
| 差し引かれるもの | **決済手数料** `【Varies】` |
| 宿に入る時点 | `【Varies】` **決済会社の締め日の後、後日**（数日〜1か月程度） |
| その後の処理 | ⑧ 経理が入金額と売上データを突合（消込） |
| 頻度 | 入金は**月次または月2回** `【Varies】` |

#### ③ OTA経由・現地決済

| 項目 | 内容 |
|---|---|
| 集金する人 | **宿**（フロントで受け取る） |
| タイミング | チェックアウト時 |
| 差し引かれるもの | **その場では差し引かれない** |
| 宿に入る時点 | **即時**（全額） |
| **その後に何が起きるか** | `【Typical】` **OTAが後日、販売手数料を宿に請求する**（または宿がOTAへ支払う） |
| 頻度 | 手数料の精算は**月次** `【Varies】` |

> **ここが分かりにくい点です。**
> `【Inference】` 現地決済のOTA予約では、**お金は一度全額宿に入り、
> 後から手数料が出ていきます。** 見かけ上は現金が潤沢に見えても、
> 翌月に手数料の支払が控えている、という状態になります。

#### ④ OTA経由・事前決済

| 項目 | 内容 |
|---|---|
| 集金する人 | **OTA** |
| タイミング | `【Varies】` 予約時／宿泊日の一定期間前 |
| 差し引かれるもの | **販売手数料** `【Varies】` |
| 宿に入る時点 | `【Varies】` **OTAの精算サイクルに従って後日**（翌月等） |
| その後の処理 | ⑧ 経理がOTAの精算明細と自社の売上データを突合 |
| 頻度 | **月次** `【Varies】` |

`【Inference】` このパターンでは、**宿は客からは1円も受け取りません。**
チェックアウト時にフロントが誤って請求しないよう、
A-5 の決済区分の記録が決定的に重要になります。

#### ⑤ 旅行代理店経由

| 項目 | 内容 |
|---|---|
| 集金する人 | **旅行代理店** |
| タイミング | `【Varies】` 申込時／出発前 |
| 差し引かれるもの | **送客手数料** `【Varies】` |
| 宿に入る時点 | `【Varies】` **代理店の精算サイクルに従って後日** |
| 実務上の特徴 | `【Typical】` 宿は代理店へ**宿泊の実績（誰が何泊したか）を報告**し、それに基づいて精算される |
| 頻度 | **月次** `【Varies】` |

`【Typical】` 団体旅行では、代理店が発行する**クーポン（宿泊券）**を客が持参し、
宿はそれを回収して代理店に請求する、という形が取られることがあります `【Varies】`。

#### ⑥ 法人契約（掛売）

| 項目 | 内容 |
|---|---|
| 集金する人 | **宿**（ただし後日） |
| タイミング | 締め日ごとに請求 → 支払期日に入金 |
| 差し引かれるもの | なし（`【Varies】` 振込手数料の負担は契約による） |
| 宿に入る時点 | `【Typical】` **締め日の翌月以降** |
| その後の処理 | 請求書発行 → 入金確認 → 消込。未入金があれば督促 |
| 頻度 | 請求は**月次**、入金は**月次** |

- **締め日（しめび）**
  → 一定期間の取引をまとめて集計する区切りの日のこと。
  → 実務例：「月末締め翌月末払い」＝ その月の1日から末日までの利用分を集計し、
    翌月に請求書を出し、翌月末に振り込んでもらう。
  → **なぜするのか**：1泊ごとに請求書を出していては双方の事務が回らないためです。

- **売掛金（うりかけきん）**
  → 売上は立ったがまだ入金されていない代金のこと。
  → 実務例：3月に法人が20泊利用し、4月末に入金される場合、
    3月末時点でその代金は売掛金として残っています。

> **初心者がつまずく点：「売上が立つ」と「お金が入る」は別**
> `【Inference】` 法人契約の場合、3月10日に泊まった客の代金が宿の口座に入るのは
> 早くても4月末、契約によっては5月になります。
> **その間、宿は代金を受け取らないまま、リネン代・清掃費・人件費・食材費を払い続けます。**
> （この時間差の詳細は `08_money.md` / `12_business-model.md` で扱います。）

### まとめ表：カネの入り方のチャネル差

| チャネル | 客が払う相手 | 差し引かれるもの | 宿に入るタイミング | 宿の事務作業 |
|---|---|---|---|---|
| 直販・現金 | 宿 | なし | **即時** | レジ締め・入金 |
| 直販・カード | 決済会社 | 決済手数料 `【Varies】` | 後日 | 入金消込 |
| OTA・現地決済 | 宿 | （後から手数料を支払） | **即時**（手数料は後日出金） | 手数料の請求確認・支払 |
| OTA・事前決済 | OTA | 販売手数料 `【Varies】` | 後日 | 精算明細の突合 |
| 旅行代理店 | 代理店 | 送客手数料 `【Varies】` | 後日 | 実績報告・請求・突合 |
| 法人契約 | 企業（後日） | なし | **締め後、翌月以降** | 請求書発行・督促・消込 |

`【Inference】` この表から読み取るべきこと：

1. **同じ売上でも、現金化されるまでの日数が最大2か月近く違う。**
2. **チャネルごとに、経理の事務作業の中身が違う。**
   現金はレジ締め、カードは消込、OTAは精算明細の突合、法人は請求と督促。
3. したがって **「どのチャネルで何割売れているか」は、資金繰りの形そのものを決める。**

## 4-3 宿泊業に固有の重要論点

### ① 宿泊拒否の制限 — 原則として断れない

`【Fact】` 営業者は、**次の各号のいずれかに該当する場合を除いては、宿泊を拒んではなりません**
（旅館業法第5条第1項）。

| 号 | 拒否できる事由 |
|---|---|
| 一 | 宿泊しようとする者が**特定感染症の患者等**であるとき |
| 二 | 宿泊しようとする者が**賭博その他の違法行為又は風紀を乱す行為をするおそれがある**と認められるとき |
| 三 | 宿泊しようとする者が、営業者に対し、**その実施に伴う負担が過重であって他の宿泊者に対する宿泊に関するサービスの提供を著しく阻害するおそれのある要求**として厚生労働省令で定めるものを**繰り返した**とき |
| 四 | **宿泊施設に余裕がないとき**その他**都道府県が条例で定める事由**があるとき |

`【Fact】` 第三号の「厚生労働省令で定めるもの」は次のとおりです
（旅館業法施行規則第5条の6。いずれも**他の宿泊者へのサービス提供を著しく阻害するおそれのあるもの**に限る）。

| 号 | 内容 |
|---|---|
| 一 | **宿泊料の減額**その他その内容の実現が容易でない事項の要求（**障害者差別解消法第2条第2号に規定する社会的障壁の除去を求める場合を除く**） |
| 二 | **粗野又は乱暴な言動**その他の従業者の心身に負担を与える言動を交えた要求であって、当該要求をした者の接遇に**通常必要とされる以上の労力を要することとなるもの**（営業者が障害を理由とする不当な差別的取扱いを行ったことに起因するもの等を除く） |

`【Fact】` また同条第2項は、営業者に対し、
**旅館業の公共性を踏まえ、宿泊しようとする者の状況等に配慮して、みだりに宿泊を拒むことがないよう**にするとともに、
**拒む場合には各号のいずれかに該当するかどうかを客観的な事実に基づいて判断**し、
**求めに応じてその理由を丁寧に説明できるようにする**ことを定めています。

`【Fact】` 第5条第1項に違反した場合の罰則は**50万円以下の罰金**です（同法第11条第1号）。

> **実務上の意味**
> `【Inference】` フロント担当者は、**「断れる場合」が法律で限定列挙されている**ことを
> 理解している必要があります。
> 特に、**障害を理由とする差別的取扱いは明確に除外規定が置かれている**点、
> また**「宿泊料の減額要求」や「乱暴な言動を交えた過重な要求」は、
> それが繰り返された場合に限って拒否事由になり得る**点に注意が必要です。
> 本資料は法令の内容を説明するものであり、個別事案の判断を示すものではありません。

### ② オーバーブッキング（二重予約）

- **オーバーブッキング**
  → 実際に用意できる部屋数を超えて予約を受けてしまっている状態のこと。
  → 実務例：シングル50室しかないのに、3月10日のシングルの予約が52件入っている。
  → **なぜ起きるのか**：`【Inference】` 宿泊業は `02_industry-structure.md` のとおり
    **複数のチャネルで同じ在庫を同時に売っています**。
    どこかで売れたときに他のチャネルの在庫を減らす処理が遅れると、
    その隙に別のチャネルで売れてしまいます。
    また、手作業での在庫更新、設備故障による客室の使用不能、
    連泊の延長申出なども原因になります。

`【Typical】` 主な発生原因

| 原因 | 内容 |
|---|---|
| 在庫反映の遅れ | 複数チャネルへの在庫更新にタイムラグがある |
| 手入力の誤り | 電話予約の入力漏れ・日付の入力誤り |
| 客室の使用不能 | 設備故障・水漏れ・破損で急に部屋が使えなくなる |
| 滞在延長 | 連泊中の客が急に延泊を申し出る |
| 団体枠の管理ミス | ブロックを解放し忘れる／二重に解放する |

`【Typical】` 対応としては、**別の客室タイプへの振替**、**他施設への振替（送客）と
その費用の負担**などが行われます `【Varies】`。

> **なぜこれが重大か**
> `【Inference】` 客は「今夜寝る場所」を確保したつもりで来ています。
> 部屋がないことは、他の商品の欠品とは意味が違います。
> だから宿泊業では**在庫の正確性が最優先**であり、
> サイトコントローラーのような仕組みが使われます
> （`02_industry-structure.md` 11-1 ⑨）。

### ③ キャンセル と ノーショー

- **キャンセル**
  → 予約が取り消されること。
  → `【Typical】` 取り消された時点で、その部屋は再び在庫に戻り、販売できる状態になります。
    ただし**直前であるほど、再販売できる時間が短くなります**。

- **ノーショー（No Show）**
  → 予約があるのに、連絡なく来ないこと。
  → 実務例：3月10日に予約が入っていたが、チェックイン時刻を過ぎても現れず、
    連絡も取れない。
  → **なぜ問題か**：`【Inference】` キャンセルの連絡があれば他の客に売り直せますが、
    ノーショーは**当日その時刻まで部屋を押さえ続けた末に売れない**ため、
    再販売の機会が完全に失われます。

`【Typical】` 実務上、ノーショーの場合も**宿泊料相当額を請求する**旨を
あらかじめ定めておくのが一般的です `【Varies】`。

### ④ キャンセルポリシー

- **キャンセルポリシー**
  → 「いつキャンセルしたら、いくらのキャンセル料がかかるか」をあらかじめ定めたもの。
  → 実務例：「7日前まで無料／3日前50％／前日80％／当日・不泊100％」のように、
    **宿泊日に近づくほど料率が上がる**形が一般的です `【Varies】`。
  → **なぜ必要か**：`【Inference】` `01_overview.md` のとおり部屋は売れ残ると消えます。
    直前のキャンセルは**再販売する時間がない**ため、
    その分の損失を誰が負担するかをあらかじめ決めておく必要があります。

`【Varies】` **料率・無料期限は施設・プラン・チャネルによって異なります。**
本資料では特定の料率を示しません。

> **業態による違い（重要）**
> `【Inference】` `01_overview.md` 1-5 で述べたとおり、
> **食事付きの宿は、キャンセルで失うものが多い**（部屋の売上＋仕入済みの食材）ため、
> 素泊まり中心の宿より早い段階からキャンセル料が発生する設定になりやすい傾向があります。
> また、団体予約は**人数が多く、代わりの客を見つけにくい**ため、
> 個人予約とは別のキャンセル規定を設けることが一般的です `【Varies】`。

> **OTA経由のキャンセルについて**
> `【Varies】` OTA経由の予約では、**キャンセルポリシーはプランごとに
> OTA上で設定されている**ことが一般的で、キャンセル料の徴収方法も
> OTAの仕組みに従います。宿が独自に請求できるとは限りません。

### ⑤ 飛び込み（ウォークイン）

- **ウォークイン（飛び込み客）**
  → 予約なしで直接来館して宿泊を申し込む客のこと。
  → **なぜ重要か**：`【Inference】` 当日の残室は放っておけば消えます。
    ウォークインは、その残室を最後に売る機会です。
  → `【Typical】` フロントはその場で空室・価格を判断し、
    宿泊者名簿への記載と本人確認を行って受け入れます。
  → `【Fact】` ただし、宿泊施設に余裕がないときは宿泊を拒むことができます
    （旅館業法第5条第1項第4号）。

## 4-4 【Example】1つの予約を最初から最後まで追跡する

> `【Example】` **以下はすべて説明用の架空の例です。**
> 金額・日付・手数料率は説明のための仮置きであり、実在の取引でも業界の代表値でもありません。

### 登場人物

| 3月31日 | ⑧ 経理 | 3月分のA商事の利用（Sさんを含め計18泊）を集計。**請求書を作成して送付** | **請求書**、売掛金の計上 |
| 4月30日 | ⑧ 経理 | A商事から振込入金。請求額と照合し、消込 | **入金の確定** |

#### このケースから読み取ること

`【Inference】`

1. **Sさんが泊まったのは3月10日。宿にお金が入ったのは4月30日。約50日の差があります。**
2. **その間、Xホテルは C清掃・Dリネン・朝食のパートに支払いを続けています。**
   支払いのほうが先に出ていきます。
3. **3月10日の Xホテルの動きの大半は「Sさん1人のため」ではありません。**
   52室の清掃、58名分の朝食、55件の到着——
   **同じ工程が同時並行で何十件も走っています。**
4. **設備の不具合で1室が売れなくなった瞬間、その日の在庫は70室ではなく69室になります。**
   宿泊業の在庫は毎日変動します。

### タイムライン — ケース2：同じ日の別の客（OTA事前決済）

| 日付 | 誰が | 何をしたか |
|---|---|---|
| 1月15日 | Tさん | Bトラベル（OTA）のサイトでXホテルを見つけ、3月10日1泊を予約。**その場でクレジットカード決済** |
| 1月15日 | Bトラベル → Xホテル | 予約情報がPMSへ自動連携。**決済区分は「Bトラベル事前決済済み」** |

#### ケース1とケース2の比較（同じ3月10日・同じシングル1泊）

| | ケース1（法人契約） | ケース2（OTA事前決済） |
|---|---|---|
| 客が払った相手 | A商事が後日Xホテルへ | Tさんが1月15日にBトラベルへ |
| 客が払った時期 | 4月30日（会社が） | **1月15日**（宿泊の約2か月前） |
| フロントでの受領 | なし | なし |
| 宿に入る時期 | 4月30日 | 4月（OTAの精算日） |

> しかしお金の動き方はまったく違います。**
> `【Inference】` これが宿泊業の経理が複雑になる理由であり、
> `03_company-structure.md` で ⑧ 経理・財務機能を独立した機能として立てた理由です。

### タイムライン — ケース3：直前キャンセルが起きた場合

| 日付 | 何が起きたか | 宿はどうなるか |
|---|---|---|
| 2月10日 | Uさんが3月10日1泊を直販で予約（現地決済） | 在庫が1減る |
| 3月9日 22:00 | Uさんから「行けなくなった」と電話 | 在庫が1戻る。**ただし前日夜のため、売り直せる時間はほとんどない** |
| 3月9日 22:00 | ② フロント | キャンセルポリシーに照らし、前日キャンセルの料率を適用してキャンセル料を案内 `【Varies】` |
| 3月10日 | — | 結局この部屋は売れず。**3月10日の406号室という商品は消滅** |

`【Inference】` **キャンセル料は「罰金」ではありません。**
再販売の機会を失った分の損失を、あらかじめ決めた基準で分担する仕組みです。
だから**宿泊日に近いほど料率が上がる**という形になります。

> **もしこれがY旅館（1泊2食付き）だったら**
> `【Example】` Y旅館で同じことが起きた場合、失われるのは部屋の売上だけではありません。
> **すでに仕入れた食材**も無駄になります。
> `【Inference】` だから食事付きの宿では、キャンセル料の発生時期が早めに設定されやすく、
> また団体については別建ての規定が置かれやすくなります `【Varies】`。

### 押さえるべき6点

1. **宿泊業のフローは「価格設定 → 在庫配分 → 予約 → 滞在 → 精算 → 清掃 → 再販売」の円環。**
   毎日締め切りが来て、売れ残りは消える。
2. **売上が確定するのは A-9（チェックアウト・精算）。入金はチャネルによって最大2か月後。**
3. **A-7（チェックイン）に法令上の義務が集中する。**
   宿泊者名簿（第6条・3年保存・罰則あり）、本人確認、鍵の受渡し、宿泊拒否の制限（第5条）。
4. **A-10（客室清掃）は製造工程。** 清掃が終わった部屋数がその日の受入能力の上限。
5. **オーバーブッキング／キャンセル／ノーショーは、
   「在庫が消滅する」という性質から必然的に生じる論点。**
6. **入湯税・宿泊税は宿の売上ではなく、客から預かって行政に納めるお金。**
   入湯税は地方税法上の目的税（150円標準・特別徴収）、
   宿泊税は法定外目的税で自治体により異なる `【Varies】`。

### `【Varies】` として数値を置かなかった論点（後続フェーズで扱う場合は出典を要する）

- OTA・旅行代理店の手数料率
- 決済手数料率
- キャンセルポリシーの料率と無料期限
- チェックイン／チェックアウトの時刻
- 客室単価（ADR）の水準
- 清掃1室あたりの所要時間・委託単価
- 宿泊税の税率・課税対象（自治体ごとに条例で異なる）
- OTA各社の精算サイクル

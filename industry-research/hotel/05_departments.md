## 1-① 予約・販売管理機能（レベニューマネジメント）

### A. 部署・機能名

| 項目 | 内容 |
|---|---|
| **正式名称（本資料での呼称）** | **予約・販売管理機能（レベニューマネジメント）** |
| **一般的な別名称** | 予約課、予約センター、レベニュー担当、レベニューマネージャー、販売企画、営業企画、支配人直轄 |
| **旅館での呼ばれ方** | `【Typical】` 「予約」「帳場」。家族経営では役職名がなく「女将が見ている」と表現される |
| **必ず存在するか** | **必ず存在する**（`03_company-structure.md` まとめ表） |

- **レベニューマネジメント**
  → 日付ごとに価格と販売する部屋数を動かして、**その日の売上をできるだけ大きくしようとする一連の仕事**のこと。
  → 実務例：3月10日（火）の残室が多ければ価格を下げて売り切り、逆に地元で大きな大会がある
    3月20日は早めに安いプランを閉じて価格を上げる。
  → **なぜこの仕事があるのか**：`01_overview.md` 1-1 のとおり、**今夜売れ残った部屋は二度と売れない**からです。
    「定価を決めたら終わり」にできる商売ではありません。

### B. 存在目的

**その日その日の70室を、日付が過ぎる前に、できるだけ良い条件で売り切るために存在します。**
部屋は形のある在庫と違って翌日に持ち越せず、売れ残った瞬間に消滅します。
だから**誰かが毎日、日付ごとの売れ行きを見て、価格と出し方に手を入れ続けなければならない**——
その役割を担うのがこの機能です。

### C. 担当者

| 会社 | 誰が担っているか |
|---|---|
| **Xホテル** `【Example】` | **支配人（全面）**。専任者は置いていない |
| **Y旅館** `【Example】` | **女将**＋長男の配偶者 |
| 一定規模以上 `【Varies】` | レベニューマネージャー、予約課長、販売企画担当を専任で置くことがある |

> **★支配人の関与（Xホテル）**
> `【Typical】` 支配人が**単独で担当**しています。価格を決めるのも、OTAの画面に入って
> 在庫を直すのも、清掃業者に室数を伝えるのも同じ人です。
> `【Inference】` 予約状況 → 清掃の室数 → 朝食の食数 → シフトの人数 が1本につながっているため、
> 分けて別の人が持つとかえって連絡の手間が増える、という事情があります
> （`03_company-structure.md` 3-3）。

#### E-①-1 販売価格の決定（レベニューマネジメント） ★この機能の中心★

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 日次の業務として（`【Varies】` 多くは朝または夕方）。加えて、地域の大型イベントの発表時、競合施設の価格が大きく動いたとき、予約の入り方が想定と食い違ったとき |
| **誰が行うか** | ① 予約・販売管理機能。**Xホテルでは支配人**／Y旅館では女将 |
| **何を確認するか** | ① **今日から先、日付ごとに何室埋まっているか**（30日後・14日後・7日後と近づくにつれての入り方）<br>② 過去の同じ曜日・同じ時期の実績（昨年の同日は何室売れ、単価はいくらだったか）<br>③ 曜日、連休、地域のイベント（祭り・スポーツ大会・学会・工事・工場の定期修理）<br>④ **同じ日付を、周辺の宿がいくらで売り出しているか** `【Varies】`<br>⑤ 法人契約の契約単価（すでに決まっている価格は動かせない）<br>⑥ 修繕・故障で売れない部屋がないか（＝分母が70室ではない日がある） |
| **何をするか** | 日付ごと・部屋タイプごと・プランごとに販売価格を決め直す。<br>**このままでは空室が残ると判断すれば価格を下げ、埋まりが早ければ上げる。**<br>決めた価格を、次の業務（①-2）で各チャネルへ反映する |
| **何を判断するか** | ・「この価格で残りが売り切れるか」<br>・「上げてよいか、下げるべきか、据え置くか」<br>・「安いプランを閉じるか（＝高い価格帯だけ残すか）」<br>・「下げて客数を取るか、価格を守って空室を許容するか」（`02_industry-structure.md` ② のとおり **OCC と ADR はしばしば逆に動く**） |
| **誰と連携するか** | ② フロント（電話・問い合わせの手応え、「今日は問い合わせが多い」という肌感）／⑦ 営業（法人・団体の動き、大口が入りそうか）／⑤ 調理（食事付きプランの価格は食材原価と関係する `【Varies】`）／③ 客室清掃（大量に売った日は清掃が回るか） |
| **最終的に何が出来上がるか** | **日付別・部屋タイプ別・プラン別の販売価格** |

**なぜこの業務が必要なのか**

`【Inference】` **今夜売れ残った部屋は、二度と売れないからです。**
製造業の在庫は明日も明後日も売れますが、「3月10日のシングル406号室」という商品は
3月11日になった瞬間に消滅します。売れ残りの損失を後から取り戻す手段がありません。

だから、放っておいて売れるのを待つのではなく、
**日付が近づくにつれて「このままだと残る／このままだと足りない」を読み、価格で調整し続ける**
必要があります。

> `【Example】`（説明用の架空例）Xホテル・3月10日（火）のシングル50室
>
> | 時点 | 予約済 | 支配人が見たこと | 打った手 |
> |---|---:|---|---|
> | 30日前 | 12室 | 平日で法人需要が見込める。昨年の同時期も終盤に伸びた | 何もしない（据え置き） |
> | 14日前 | 26室 | 想定よりやや遅い。近隣で大きなイベントの予定なし | OTAの一部プランを少し下げる |
> | 7日前 | 38室 | 伸びてきた。周辺の宿も埋まりつつある | **安いプランを閉じ、価格を戻す** |
> | 前日 | 47室 | 残り3室。当日の飛び込みも見込める | **据え置き**。当日朝に再判断 |
>
> **同じ3月10日という商品の値段が、日を追って何度も変わっています。**
> これがレベニューマネジメントの実際の姿です。
> `【Varies】` 実際に何日前にどう動かすかは施設・時期・立地によって大きく異なります。

> **本資料の立場**
> `common/methodology.md` §0 のとおり、本資料は**現象を説明するもの**であり、
> 価格設定の是非を論じるものでも、やり方を提案するものでもありません。

#### E-①-2 在庫（部屋）の各チャネルへの配分

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | E-①-1 で価格が決まったとき。予約が入って在庫が動いたとき。故障で部屋が使えなくなったとき |
| **誰が行うか** | ① 予約・販売管理機能（Xホテルでは支配人） |
| **何を確認するか** | ・**今日実際に売れる部屋数**（70室 − 修繕中 − 故障中 − 従業員用 − 団体ブロック分）<br>・チャネルごとの現在の販売状況（どのOTAでよく売れているか）<br>・法人契約で確保している枠<br>・団体の仮予約（ブロック）で押さえている枠と、その確定期限 |
| **何をするか** | 「直販に何室、OTA各社に何室、旅行代理店に何室」を決め、**サイトコントローラー**で各チャネルへ一括反映する |
| **何を判断するか** | ・どのチャネルに厚く出すか<br>・団体枠をいつ解放するか<br>・特定チャネルの販売を止めるか（→ E-①-5） |
| **誰と連携するか** | ⑦ 営業（団体枠・法人枠の判断）／② フロント（電話予約で在庫を直接触るため、認識を合わせる必要がある）／PMS・サイトコントローラー事業者（システム） |
| **最終的に何が出来上がるか** | **各チャネルの画面に表示される「空室数」と「価格」** |

**なぜこの業務が必要なのか**

`【Inference】` `02_industry-structure.md` 11-2 のとおり、
**宿泊業は同じ1つの部屋を、複数の売り場で同時に売っています。**
自社サイトでもA社のOTAでもB社のOTAでも、同じ406号室が並んでいます。

したがって、**どこかで1室売れた瞬間に、他のすべてのチャネルで在庫を1つ減らさなければなりません。**
この反映が遅れると、その隙に別のチャネルで同じ部屋が売れてしまいます。
これが**オーバーブッキング**（→ E-①-6）です。

- **サイトコントローラー**
  → 複数のOTAと自社サイトに対して、**空室数と料金を一括で反映させる**ための仕組み。
  → 実務例：フロントが電話予約を1件入れたら、A社・B社・C社のOTAの表示在庫がすべて1つ減る。
  → **なぜあるのか**：手作業で各OTAの管理画面に入って1つずつ直していては、
    反映までの数分〜数十分の間に二重に売れてしまうためです。

- **アロットメント**
  → 特定の販売先（旅行代理店・OTA等）に対して、**あらかじめ「この日はこの数まで売ってよい」と
    割り当てておく部屋数**のこと。
  → 実務例：「3月の平日は毎日、A旅行社に5室」と決めておき、その範囲で代理店が自由に売る。
  → `【Varies】` アロットメントを設定するか、都度照会にするかは取引条件によって異なります。

#### E-①-3 販売プランの設計とOTA掲載内容の管理

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 季節の変わり目、新しい需要が見えたとき（大会の誘致が決まった等）、写真や説明文が実態と合わなくなったとき、OTAから新しい販促の案内が来たとき `【Varies】` |
| **誰が行うか** | ① 予約・販売管理機能（Xホテルでは支配人）。写真・文章は ⑦ 営業や社長が関わることもある `【Varies】` |
| **何を確認するか** | ・今あるプランのどれが売れていて、どれが売れていないか<br>・掲載している写真・説明文が現在の設備と合っているか（改装した、大浴場の時間を変えた等）<br>・プランに含めている条件（食事の有無、チェックイン時刻、駐車場、キャンセル規定）<br>・客の口コミに書かれている内容 `【Varies】` |
| **何をするか** | プランを作る・直す・やめる。プラン名・説明文・写真・含まれるもの・キャンセル規定を各チャネルに登録する |
| **何を判断するか** | ・どの客層向けのプランを増やすか（連泊、朝食付き、早期予約、直前）<br>・プランを整理するか（多すぎると管理しきれない `【Varies】`） |
| **誰と連携するか** | ② フロント（プランの条件は現場が運用する。フロントが理解していないプランは事故のもと）／④⑤ 料飲・調理（食事付きプランは提供体制が要る）／⑦ 営業 |
| **最終的に何が出来上がるか** | **各チャネルに掲載される商品（プラン）とその内容** |

**なぜこの業務が必要なのか**

`【Inference】` 客は部屋そのものを見て買っているのではなく、
**画面に出ている写真・プラン名・説明文・条件を見て買っています。**
掲載内容が実態と違えば、到着したときに「聞いていた話と違う」という事態になり、
その対応はフロント（②）が負うことになります。

`【Typical】` また、プランごとにキャンセル規定・食事の有無・チェックイン可能時刻が違うため、
**プランの数が増えるほど、フロントが当日確認すべきことが増えます。**

#### E-①-4 予約状況（ブッキングカーブ）の日次確認

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 日次の業務として |
| **誰が行うか** | ① 予約・販売管理機能（Xホテルでは支配人） |
| **何を確認するか** | ・**今日から先30日〜90日程度の、日付ごとの予約室数**<br>・昨年の同じ時期と比べて早いか遅いか<br>・チャネル別の内訳（どこから入っているか）<br>・団体・法人の大口が入っているか<br>・キャンセルが集中していないか |
| **何をするか** | PMSの予約一覧・日別集計を見て、**「入り方が想定と違う日」を見つける**。見つけた日について E-①-1（価格）と E-①-2（配分）に戻る |
| **何を判断するか** | ・手を打つべき日はどれか<br>・まだ様子を見てよい日はどれか |
| **誰と連携するか** | ⑦ 営業（大口の見込みを聞く）／② フロント（問い合わせの状況）／③ 客室清掃（大量に売れそうな日の清掃体制）／⑨ 人事・総務（繁忙が見えた日のシフト） |
| **最終的に何が出来上がるか** | **「どの日に手を打つか」という判断の材料**（日別予約状況表・稼働予測） |

**なぜこの業務が必要なのか**

- **ブッキングカーブ**
  → 宿泊日までの日数の経過とともに、予約がどう積み上がっていくかを表した線のこと。
  → 実務例：「30日前12室 → 14日前26室 → 7日前38室 → 前日47室」という積み上がり方。
  → **なぜ見るのか**：`【Inference】` **今の予約室数だけを見ても、多いのか少ないのか分からない**からです。
    「7日前で38室」は、昨年の同時期が7日前で30室だったなら順調ですが、45室だったなら遅れています。
    **過去との比較があって初めて「手を打つべきか」が判断できます。**

`【Inference】` この確認をしないと、気づいたときには手を打つ時間が残っていません。
価格を下げても、**下げてから客が予約するまでには時間がかかります。**
前日に気づいても間に合わないため、日々の確認が必要になります。

#### E-①-5 売止め・販売再開の判断

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 満室が見えたとき／団体で大半が埋まったとき／設備故障で部屋が使えなくなったとき／清掃体制が足りないと判断したとき／逆に、止めていた日を再開するとき |
| **誰が行うか** | ① 予約・販売管理機能（Xホテルでは支配人） |
| **何を確認するか** | ・実際に販売できる部屋数（故障・修繕を差し引いた数）<br>・その日のチェックアウト数と清掃の見込み（清掃が間に合う室数か）<br>・すでに入っている予約の内訳<br>・止めるチャネルと残すチャネル |
| **何をするか** | **売止め**を行う。特定の日付・部屋タイプ・プラン・チャネルについて、販売を停止する。<br>状況が変われば**解除して販売を再開する** |
| **何を判断するか** | ・全チャネルを止めるか、一部だけ止めるか<br>・直販だけ残すか（`【Varies】` 手数料の差を考慮する場合がある）<br>・いつ再開するか |
| **誰と連携するか** | ② フロント（電話予約を受けてしまわないよう共有が必須）／③ 客室清掃（清掃能力が理由の場合）／⑥ 設備管理（故障が理由の場合） |
| **最終的に何が出来上がるか** | **販売停止・再開が反映された各チャネルの表示** |

**なぜこの業務が必要なのか**

- **売止め（うりどめ／ストップセール）**
  → その日付・その部屋タイプの販売を止めること。
  → 実務例：3月20日のシングルが残り2室になったので、OTAでの販売を止め、
    直販の電話予約と当日の飛び込み用に残す。
  → **なぜするのか**：`【Inference】` 理由は主に2つです。
    ① **これ以上売ると受け入れられない**（部屋が無い、清掃が回らない）ため。
    ② **オーバーブッキングを防ぐ**ため。残室が1〜2室まで減ると、
      複数チャネルの反映が数十秒でも遅れれば二重に売れる危険が高まります。

`【Fact】` なお、**宿泊施設に余裕がないときは宿泊を拒むことができます**
（旅館業法第5条第1項第4号）。売止めはこれを事前に行う実務的な手段にあたります
`【Inference】`。

#### E-①-6 オーバーブッキングの予防と発生時の調整

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | **予防**：日次の在庫確認のなかで。**発生時**：予約室数が実際の部屋数を超えていることが判明したとき（多くは到着前日〜当日） |
| **誰が行うか** | ① 予約・販売管理機能が中心。当日の現場対応は ② フロント。**Xホテルでは同じ支配人とフロントが動く** |
| **何を確認するか** | ・部屋タイプごとの「実際の室数」と「予約件数」の突き合わせ<br>・重複予約（同じ客が2件入れている）がないか<br>・故障・修繕で使えない部屋が反映されているか<br>・連泊延長の申出が入っていないか<br>・団体ブロックの二重解放がないか |
| **何をするか** | **予防**：在庫の実数を毎日突き合わせ、ずれていれば直す。残室が少ない日は早めに売止めする。<br>**発生時**：`【Typical】` 別の客室タイプへの振替、他施設への振替（送客）とその費用の負担などを行う `【Varies】` |
| **何を判断するか** | ・誰をどう振り替えるか（到着が遅い客か、連泊の客か、当日予約の客か）<br>・どこまで宿が負担するか `【Varies】` |
| **誰と連携するか** | ② フロント（客への説明と実際の対応）／③ 客室清掃（振替先の部屋を優先して仕上げる）／⑥ 設備管理（故障が原因なら復旧の見込み）／⑧ 経理（振替費用の負担が発生した場合）／OTA・旅行代理店（そのチャネル経由の予約の場合） |
| **最終的に何が出来上がるか** | **実態と一致した在庫**（予防）／**振替先が決まった予約と、その記録**（発生時） |

**なぜこの業務が必要なのか**

`【Inference】` **客は「今夜寝る場所」を確保したつもりで来ています。**
他の商品の欠品とは意味が違います。夜21時に到着した客に「部屋がありません」と言うことは、
その客にその晩の行き場が無くなることを意味します。

だから宿泊業では**在庫の正確性が最優先**であり、サイトコントローラーのような仕組みが使われます
（`02_industry-structure.md` 11-1 ⑨、`04_end-to-end-process.md` 4-3 ②）。

`【Typical】` 主な発生原因（`04_end-to-end-process.md` 4-3 ② より）

| 原因 | 内容 |
|---|---|
| 在庫反映の遅れ | 複数チャネルへの在庫更新にタイムラグがある |
| 手入力の誤り | 電話予約の入力漏れ・日付の入力誤り |
| 客室の使用不能 | 設備故障・水漏れ・破損で急に部屋が使えなくなる |
| 滞在延長 | 連泊中の客が急に延泊を申し出る |
| 団体枠の管理ミス | ブロックを解放し忘れる／二重に解放する |

#### E-①-7 団体・法人枠（ブロック）の管理と解放

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 旅行代理店・団体主催者・法人からの「○月○日に○室を押さえてほしい」という依頼（⑦ 営業経由が多い）／確定期限の到来 |
| **誰が行うか** | ① 予約・販売管理機能。依頼の受付・条件交渉は ⑦ 営業 |
| **何を確認するか** | ・押さえる日付・室数・部屋タイプ<br>・**いつまでに確定するか（確定期限）**<br>・その日の他の需要の見込み（押さえてよい規模か）<br>・単価・キャンセル規定（団体は個人と別建てになることが多い `【Varies】`） |
| **何をするか** | **ブロック**として在庫から抜き、一般販売に出さない状態にする。期限が近づけば相手に人数の確定を督促し、確定しなければ**解放して一般販売に戻す** |
| **何を判断するか** | ・押さえる室数と期限をどう設定するか<br>・期限を延ばすか、解放するか<br>・一部だけ確定した場合、残りをいつ戻すか |
| **誰と連携するか** | ⑦ 営業（相手との交渉窓口）／② フロント（当日の受入体制、同じ階に固める等）／④⑤ 料飲・調理（団体の食事は人数と時刻が集中する）／③ 客室清掃（団体は同日に大量のチェックアウトが発生する） |
| **最終的に何が出来上がるか** | **確定した団体予約**、または**一般販売に戻った在庫** |

**なぜこの業務が必要なのか**

- **ブロック**
  → 団体や代理店のために、一般販売に出さずに押さえておく部屋の枠のこと。
  → 実務例：「5月の大会で20室、3月末までに人数を確定します」という依頼を受け、
    20室を抜いておく。3月末に「15室で確定」と連絡が来たら、残る5室を一般販売に戻す。
  → **なぜ期限を設けるのか**：`【Inference】` **押さえたまま期限を過ぎると、
    その部屋は売る機会を失ったまま消えるから**です。
    団体が来なかった場合、その日の20室は空室のまま日付が過ぎます。

#### E-①-8 キャンセル・ノーショーの処理方針の適用

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 客・法人・代理店からのキャンセル連絡／チェックイン時刻を過ぎても現れず連絡も取れないとき（ノーショー） |
| **誰が行うか** | 実際の受付は ② フロント。**方針の適用と例外判断は ① 予約・販売管理**（Xホテルでは同じ支配人） |
| **何を確認するか** | ・予約の内容と、適用されるキャンセルポリシー（プラン・チャネルによって異なる `【Varies】`）<br>・キャンセルの時点（何日前か）<br>・チャネル（OTA経由か直販か法人か）<br>・食事付きの予約か（食材をすでに仕入れているか）<br>・団体か個人か |
| **何をするか** | 在庫を戻し、各チャネルへ反映する。キャンセル料が発生する場合はその金額を算定し、⑧ 経理へ渡す。ノーショーの場合は、あらかじめ定めた取扱いに従う |
| **何を判断するか** | ・キャンセル料を請求するか（キャンセルポリシーに照らす）<br>・**戻った在庫を売り直せる時間があるか**（あるなら価格を下げてでも売るか）<br>・OTA経由の場合、宿が独自に請求できるか（`【Varies】` OTAの仕組みに従う） |
| **誰と連携するか** | ② フロント（受付と客への案内）／⑤ 調理（食数の修正。`【Varies】` 食事付きの施設）／③ 客室清掃（清掃室数の修正）／⑧ 経理（キャンセル料の請求）／OTA・旅行代理店 |
| **最終的に何が出来上がるか** | **在庫に戻った部屋**、**キャンセル料の請求データ**（発生した場合）、**修正された食数・清掃室数** |

**なぜこの業務が必要なのか**

- **ノーショー（No Show）**
  → 予約があるのに、連絡なく来ないこと。
  → 実務例：3月10日に予約が入っていたが、チェックイン時刻を過ぎても現れず、連絡も取れない。
  → **なぜキャンセルより問題か**：`【Inference】` キャンセルの連絡があれば他の客に売り直せますが、
    ノーショーは**当日その時刻まで部屋を押さえ続けた末に売れない**ため、
    再販売の機会が完全に失われます。

`【Typical】` 実務上、ノーショーの場合も宿泊料相当額を請求する旨をあらかじめ定めておくのが
一般的です `【Varies】`。

`【Inference】` **キャンセル料は「罰金」ではありません。**
再販売の機会を失った分の損失を、あらかじめ決めた基準で分担する仕組みです
（`04_end-to-end-process.md` 4-4 ケース3）。だから宿泊日に近いほど料率が上がります。

> **業態による違い**
> `【Inference】` Y旅館のような1泊2食付きの施設では、キャンセルで失うものが
> **部屋の売上＋すでに仕入れた食材**の2つになります（`02_industry-structure.md` 11-4）。
> このため、素泊まり中心の宿より早い段階からキャンセル料が発生する設定になりやすい傾向があります
> `【Varies】`。

#### E-①-9 当日残室の最終処理と翌日以降への反映

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 清掃完了の報告（A-10 → A-11）／当日の一定時刻（`【Varies】` 夕方等） |
| **誰が行うか** | ① 予約・販売管理機能（Xホテルでは支配人） |
| **何を確認するか** | ・清掃が完了して**販売可能な状態に戻った部屋**の数<br>・故障・修繕で今日は売れない部屋<br>・当日の残室数と、まだ入りうる予約（直前予約・飛び込み） |
| **何をするか** | 空いた部屋を在庫に戻し、当日の残室をどう売るか決める。翌日以降の価格・配分を見直す（→ E-①-1 へ戻る） |
| **何を判断するか** | ・当日中に売り切るために価格を下げるか<br>・直前プランをOTAに出すか<br>・飛び込み客用に何室残すか `【Varies】` |
| **誰と連携するか** | ② フロント（飛び込み客の対応、当日の価格を共有）／③ 客室清掃（完了報告）／⑥ 設備管理（故障室の復旧見込み） |
| **最終的に何が出来上がるか** | **再び販売可能になった在庫** → **A-1 へ戻る** |

**なぜこの業務が必要なのか**

`【Inference】` `04_end-to-end-process.md` 4-1 のとおり、宿泊業のフローは**円環**です。
清掃が終わった部屋は「新しい商品」として再び市場に出ます。
**この戻し作業をしないと、空いているのに売れる状態になっていない部屋が発生します。**

#### E-①-10 実績の集計（OCC・ADR・RevPAR）

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 日次の締め（日報）／月次の締め |
| **誰が行うか** | ① 予約・販売管理機能。数字の確定は ⑧ 経理・財務と突き合わせる |
| **何を確認するか** | ・販売した客室数と販売可能客室数<br>・客室売上（食事・その他の売上と分けて把握する必要がある `【Varies】`）<br>・チャネル別の内訳<br>・前年同月・前月との比較 |
| **何をするか** | OCC・ADR・RevPAR を計算し、日別・月別に記録する。想定と大きく違う日があれば原因を確認する |
| **何を判断するか** | ・翌月以降の価格・配分の方針をどうするか<br>・特定チャネルの出し方を変えるか |
| **誰と連携するか** | ⑧ 経理・財務（売上の確定値）／② フロント（日次の売上データ）／⑦ 営業（法人・団体の寄与） |
| **最終的に何が出来上がるか** | **OCC・ADR・RevPAR の実績値**（日次・月次） |

**なぜこの業務が必要なのか**

`02_industry-structure.md` ② のとおり、この3つは**宿泊業の共通言語**です。
`【Inference】` 稼働率だけを見ていると「たくさん売ったが安すぎた」を見逃し、
単価だけを見ていると「高く売れたが空室だらけだった」を見逃します。
両方を掛け合わせた RevPAR を見ることで、**その日の客室が結局いくら稼いだか**が分かります。

| 指標 | 計算式（`02_industry-structure.md` ② より） |
|---|---|
| **OCC**（客室稼働率） | `販売した客室数 ÷ 販売可能な客室数 × 100` |
| **ADR**（平均客室単価） | `客室売上 ÷ 販売した客室数` |
| **RevPAR** | `客室売上 ÷ 販売可能な客室数`、または `OCC × ADR` |
| **定員稼働率**（旅館で重視） | `延べ宿泊者数 ÷ 収容定員（人）× 営業日数 × 100` |

### F. 業務頻度

| 業務 | 頻度 |
|---|---|
| ①-1 販売価格の決定 | **日次**（繁忙期）／**週次**（閑散期）`【Varies】` |
| ①-2 在庫のチャネル配分 | **日次**／価格変更時／トラブル発生時 |
| ①-3 プラン設計・掲載内容管理 | **月次**〜**四半期** `【Varies】`／その他（改装・設備変更時） |
| ①-4 予約状況の日次確認 | **日次** |
| ①-5 売止め・販売再開 | **その他**（満室が見えたとき）／トラブル発生時 |
| ①-6 オーバーブッキング予防 | **日次**（予防）／**トラブル発生時**（対応） |
| ①-7 ブロックの管理と解放 | **案件発生時**／**契約上のタイミング**（確定期限） |
| ①-8 キャンセル・ノーショー処理 | **常時**（連絡は随時入る） |
| ①-9 当日残室の最終処理 | **日次** |
| ①-10 OCC・ADR・RevPAR の集計 | **日次**（速報）／**月次**（確定）／**年次**（通期） |

## 1-② フロント機能

### A. 部署・機能名

| 項目 | 内容 |
|---|---|
| **正式名称（本資料での呼称）** | **フロント機能** |
| **一般的な別名称** | フロント、フロントオフィス、受付、レセプション、**帳場（ちょうば／旅館）**、宿泊部、フロントデスク |
| **時間帯による呼び分け** | `【Typical】` 夜間帯を担当する人を「ナイトフロント」「夜勤」と呼ぶことがある |
| **必ず存在するか** | **必ず存在する。法令上も要求される**（後述） |

`【Fact】` 旅館・ホテル営業の施設は、
**「宿泊しようとする者との面接に適する玄関帳場その他当該者の確認を適切に行うための設備」**として
厚生労働省令で定める基準に適合するものを有しなければなりません（旅館業法施行令第1条第1項第2号）。
`【Fact】` その設備は、**「宿泊者名簿の正確な記載、宿泊者との間の客室の鍵の適切な受渡し及び
宿泊者以外の出入りの状況の確認を可能とする設備を備えていること」**が求められます
（旅館業法施行規則第4条の3第2号）。

`【Inference】` つまりフロント機能は、宿が任意に置いている窓口ではなく、
**法令が想定している機能**です。

### B. 存在目的

**客を迎え入れ、泊められる状態にし、滞在中の要望に応え、代金を精算して送り出すために存在します。**
同時に、**「誰が泊まっているか」を法律の求めるとおりに記録し、鍵を正しい相手に渡す**という、
法令上の義務を実際に果たす場所でもあります。
`【Inference】` 客から見れば「宿そのもの」がフロントです。
予約・清掃・調理・設備のすべての結果が、最後にフロントの窓口に集まってきます。

### E. 業務詳細

---

#### E-②-1 予約受付（電話・メール・自社サイト）と予約内容の登録

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 客・法人・代理店からの予約申込（電話・メール・自社サイト）。**OTA経由はシステムが自動受信し、人は内容を確認する** |
| **誰が行うか** | ② フロント機能。`【Varies】` 夜間の電話予約は夜勤担当が受ける |
| **何を確認するか** | ① **空室があるか（最重要）**<br>② 宿泊日と泊数／人数（大人・子供）／部屋タイプ・室数<br>③ プラン（素泊まり・朝食付き・2食付き）と、そのプランの条件<br>④ 氏名・連絡先<br>⑤ **決済方法（事前決済か現地決済か、法人請求か）**<br>⑥ 特記事項（到着予定時刻、アレルギー、駐車場の要否、連泊時の清掃要否、喫煙／禁煙）<br>⑦ **宿泊を拒むべき事由に該当しないか**（→ E-②-12） |
| **何をするか** | 予約内容を **PMS に登録**し、在庫を1つ減らし、客へ**予約確認**を返す（メール・口頭・書面 `【Varies】`）。法人予約であれば契約単価を適用する |
| **何を判断するか** | ・受けられるか（空室・人数・条件）<br>・その日のその価格で出してよいか（売止め中でないか、① と共有している価格か）<br>・法人の掛売（後払い）を認めてよい相手か（契約の有無） |
| **誰と連携するか** | ① 予約・販売管理（在庫と価格。売止めの有無）／⑤ 調理（食事付きなら食数が増える `【Varies】`）／⑦ 営業（法人・団体の場合の条件確認）／⑧ 経理（決済区分） |
| **最終的に何が出来上がるか** | **予約記録（PMS上）**、**予約確認書**（メール・書面）`【Varies】`、**1つ減った在庫** |

**なぜこの業務が必要なのか**

`【Inference】` 予約とは、**「その日その部屋を使う権利を客に渡し、その分の在庫を市場から引き上げる」**
という行為です。記録が正確でないと、二重販売、到着日の食い違い、
人数違いによる食事不足が起きます。

> **初心者がつまずく点：予約 ≠ 売上**
> `【Typical】` 予約を受けた時点では、**まだ売上にはなりません。**
> 売上が確定するのは、原則として宿泊のサービスを提供したとき（A-9 の精算時）です。
> 予約は「将来の売上の見込み」であり、キャンセルされれば消えます。

#### E-②-2 予約の変更・取消の受付と反映

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 客・法人・代理店・OTAからの変更・取消の連絡（到着日までの間、随時） |
| **誰が行うか** | ② フロント機能。方針の判断は ① 予約・販売管理（Xホテルでは支配人） |
| **何を確認するか** | ・変更内容（日程・人数・部屋タイプ・プラン・泊数）<br>・キャンセルの場合、**適用されるキャンセルポリシー**（プラン・チャネルにより異なる `【Varies】`）<br>・**同一人物の重複予約がないか**<br>・団体の人数確定期限が来ていないか |
| **何をするか** | PMSの予約内容を修正し、**在庫を増減させ、各チャネルへ反映する**。キャンセル料が発生する場合は金額を案内し、記録する |
| **何を判断するか** | ・キャンセル料を請求するか<br>・変更後の条件で受けられるか（部屋タイプの空きがあるか） |
| **誰と連携するか** | ① 予約・販売管理（在庫反映）／⑤ 調理（人数が変われば食材発注が変わる）／③ 客室清掃（室数が変われば清掃量が変わる）／⑧ 経理（キャンセル料の請求） |
| **最終的に何が出来上がるか** | **最新の予約状態**、**修正された在庫**、**キャンセル料の請求データ**（発生した場合） |

**なぜこの業務が必要なのか**

`【Inference】` 予約は「入れたら終わり」ではありません。到着までの間に変わり続けます。
この反映が遅れると、**在庫が実態と合わなくなり、
売れるはずの部屋を売り逃すか、二重に売ってしまいます。**

#### E-②-3 到着前準備（当日到着リストの作成・客室のアサイン）

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 前日または当日朝（`【Varies】` 施設の運用による） |
| **誰が行うか** | ② フロント機能が中心。③ 客室清掃、④⑤ 料飲・調理、⑥ 設備管理が連動する |
| **何を確認するか** | ・当日の**到着予定件数・人数**<br>・当日の**チェックアウト件数（＝清掃すべき室数）**<br>・部屋タイプ別の内訳<br>・特記事項（アレルギー、記念日、高齢の客、団体、車椅子の利用、早着・遅着）<br>・**清掃が間に合うか**、修繕中・故障中の部屋がないか<br>・連泊中の部屋（動かせない部屋） |
| **何をするか** | ・**当日到着リスト**を出す<br>・**客室の割り当て（アサイン）**を行う<br>・③ 清掃業者へ当日の清掃室数と優先順を連絡する<br>・④⑤ 調理へ当日の食事数と特記事項を伝える<br>・朝の情報共有（申し送り） |
| **何を判断するか** | ・どの部屋を誰に割り当てるか（高層階の希望、静かな部屋、隣同士にする団体、エレベーター近く）<br>・清掃の順番（早くチェックインする客の部屋を先に）<br>・早着の客をどう扱うか（荷物だけ預かるか、部屋が出来ていれば入れるか） |
| **誰と連携するか** | ③ 客室清掃、④⑤ 料飲・調理、⑥ 設備管理、⑦ 営業（団体の場合）、① 予約・販売管理（当日の残室の売り方） |
| **最終的に何が出来上がるか** | **当日到着リスト**、**客室アサイン表**、**清掃指示（室数・優先順）**、**食事の数** |

**なぜこの業務が必要なのか**

- **アサイン（客室の割り当て）**
  → 予約に対して「実際にどの部屋番号を使うか」を決めること。
  → 実務例：3名の家族連れにはツインにエキストラベッドを入れた部屋を、
    早朝出発の客にはエレベーター近くの部屋を、団体には同じ階の連番の部屋を割り当てる。
  → **なぜ必要か**：`【Inference】` 予約の時点では「シングル1室」としか決まっていないためです。
    部屋によって眺望・広さ・静かさ・エレベーターからの距離が違い、
    また**清掃の進み具合も部屋ごとに違います。**
    「空いている部屋」と「今すぐ客を入れられる部屋」は別物です。

`【Inference】` この業務が、**フロントと客室清掃をつなぐ結節点**です。
アサインを決めなければ清掃の優先順が決まらず、
清掃が終わらなければアサインした部屋に客を入れられません（→ PART 3 の 3-2 で詳述）。

#### E-②-4 チェックイン（本人確認・宿泊者名簿への記載） ★法令上の義務が集中する工程★

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 客の到着 |
| **誰が行うか** | ② フロント機能 |
| **何を確認するか** | ・予約の有無と内容（氏名・日付・泊数・人数・プラン）<br>・**本人確認**<br>・**宿泊者名簿に記載すべき事項**（氏名・住所・連絡先。日本国内に住所を有しない外国人は国籍及び旅券番号）<br>・**決済区分**（事前決済済みか、現地で受け取るか、法人へ請求か）<br>・**宿泊を拒む事由に該当しないか**（→ E-②-12）<br>・割り当てた部屋が仕上がっているか（③ 清掃の完了報告） |
| **何をするか** | ・宿泊者名簿への記載（または客への記入依頼）<br>・鍵の受渡し（→ E-②-5）<br>・館内の案内（食事の時刻と場所、大浴場、Wi-Fi、朝食会場、**避難経路**）<br>・（現地事前収受の場合）宿泊料の受領 |
| **何を判断するか** | ・予約と実際の人数・構成が合っているか（2名予約で3名来ていないか＝定員と料金に関わる）<br>・部屋を変更する必要がないか<br>・記載事項に不足がないか |
| **誰と連携するか** | ③ 客室清掃（部屋が仕上がっているか）／④ 料飲（食事時刻の確定）／⑥ 設備管理（不具合の有無）／① 予約・販売管理（当日の飛び込み対応） |
| **最終的に何が出来上がるか** | **宿泊者名簿（法定帳簿）**、**在館情報**、（受領した場合）**入金記録**、鍵を持った宿泊者 |

**なぜこの業務が必要なのか — 宿泊者名簿は法律で義務づけられた帳簿です**

`【Fact】` 営業者は、厚生労働省令で定めるところにより、
**旅館業の施設その他の厚生労働省令で定める場所に宿泊者名簿を備え**、
これに**宿泊者の氏名、住所、連絡先**その他の厚生労働省令で定める事項を記載し、
**都道府県知事の要求があったときは、これを提出**しなければなりません（旅館業法第6条第1項）。

`【Fact】` 省令が定める詳細（旅館業法施行規則第4条の2）。

| 項目 | 内容 |
|---|---|
| **備える場所** | ① 旅館業の施設、② 営業者の事務所（第2項） |
| **保存期間** | **作成の日から3年間**（第1項） |
| **作成の要件** | 正確な記載を確保するための措置を講じた上で作成すること（第1項） |
| **記載事項** | 宿泊者の**氏名・住所・連絡先**（法第6条第1項）<br>＋ 宿泊者が**日本国内に住所を有しない外国人**であるときは、**その国籍及び旅券番号**（第3項第1号）<br>＋ その他**都道府県知事が必要と認める事項**（第3項第2号） |

`【Fact】` **宿泊者の側にも義務があります。** 宿泊者は、営業者から請求があったときは
上記の事項を告げなければなりません（旅館業法第6条第2項）。
`【Fact】` これに違反して**偽って告げた者は、拘留または科料**に処せられます（同法第12条）。
`【Fact】` 営業者が第6条第1項に違反した場合は、**50万円以下の罰金**です（同法第11条第1号）。

`【Inference】` 宿泊者名簿は、**感染症が発生したときに誰がその施設に泊まっていたかを
追跡できるようにするため**、また**事件・事故が起きたときの手がかりとするため**の仕組みです。
旅館業法の目的（第1条）が「公衆衛生及び国民生活の向上」であることと対応しています。

> **初心者がつまずく点：「面倒な書類」ではなく「法定帳簿」です。**
> 宿泊者名簿は、宿が自主的に作っている顧客リストではありません。
> **法律で記載事項・保存期間・提出義務が決まっている帳簿**であり、不備には罰則があります。

**本人確認について**

`【Fact】` 旅館業法施行規則第4条の3第2号は、玄関帳場等の設備の基準として
**「宿泊者名簿の正確な記載、宿泊者との間の客室の鍵の適切な受渡し及び
宿泊者以外の出入りの状況の確認を可能とする設備を備えていること」**を求めています。

`【Inference】` つまり法令は、**「名簿を正しく書けること」と「誰が出入りしているか分かること」**を
設備面から担保しようとしています。フロントでの本人確認は、この要請に応える実務です。

`【Varies】` 具体的にどこまで確認するか（身分証の提示を求めるか等）は
施設の運用・自治体の指導により異なります。
`【Typical】` 日本国内に住所を有しない外国人については、**国籍と旅券番号の記載が法令上必要**なため、
旅券（パスポート）の提示を受けるのが一般的です。

#### E-②-5 鍵の受渡しと鍵の管理

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | チェックイン時（渡す）／チェックアウト時（回収する）／滞在中の紛失・忘れの申出（トラブル発生時） |
| **誰が行うか** | ② フロント機能 |
| **何を確認するか** | ・**渡す相手が、その部屋の宿泊者本人か**<br>・部屋番号と鍵が一致しているか<br>・同室に複数名いる場合、何本渡すか<br>・回収時、全数が戻っているか<br>・（カードキーの場合）有効期限が宿泊日数と合っているか |
| **何をするか** | 鍵（物理キー・カードキー・暗証番号 `【Varies】`）を渡し、記録する。チェックアウト時に回収し、次の客に渡せる状態にする。紛失時は所定の手続をとる `【Varies】` |
| **何を判断するか** | ・本人確認が取れない相手に渡してよいか（**渡してはならない**）<br>・鍵を紛失された場合、錠の交換が必要か `【Varies】` |
| **誰と連携するか** | ③ 客室清掃（清掃用のマスターキーの受渡しと返却）／⑥ 設備管理（錠の故障・電池切れ・交換） |
| **最終的に何が出来上がるか** | **正しい相手に渡された鍵**、**鍵の受渡し記録**、回収された鍵 |

**なぜこの業務が必要なのか**

`【Fact】` 法令は、玄関帳場等の設備について
**「宿泊者との間の客室の鍵の適切な受渡し」を可能とする設備**を求めています
（旅館業法施行規則第4条の3第2号）。

`【Inference】` 鍵を渡すとは、**その部屋への立入権限を客に移すこと**です。
渡す相手を取り違えれば、別人が他人の泊まっている部屋に入れてしまいます。
**宿泊者は、その部屋の中で眠り、荷物を置き、無防備になります。**
だから鍵の受渡しは、単なる物の受渡しではなく、法令が名指しで要求する管理事項になっています。

#### E-②-6 滞在中の各種対応（要望・館内案内・手配）

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | チェックイン後、客からの依頼・時刻の到来・不具合の申出 |
| **誰が行うか** | ② フロント機能が窓口。内容により ④ 料飲、⑤ 調理、⑥ 設備管理、③ 客室清掃へ引き継ぐ |
| **何を確認するか** | ・要望の内容（アメニティ追加、タオル交換、枕の変更、部屋の温度、荷物預かり、タクシー手配、宅配便、モーニングコール、延泊）<br>・不具合の内容と場所（部屋番号）<br>・**追加利用の内容**（売店・自動販売機・ルームサービス `【Varies】`・コインランドリー・駐車場）<br>・館内設備の稼働状況（大浴場の湯温、Wi-Fi、エレベーター） |
| **何をするか** | 要望に応じて自ら対応するか、担当機能へ引き継ぐ。**追加利用をその場で記録し、客の明細に積み上げる**。設備トラブルは ⑥ へ回し、必要なら部屋を振り替える |
| **何を判断するか** | ・部屋を替える必要があるか<br>・追加料金をもらうか、サービスとするか `【Varies】`<br>・他の宿泊者に影響が及ぶ事態か（騒音・迷惑行為） |
| **誰と連携するか** | 全機能。設備の故障時は ⑥ から外部業者へ。食事は ④⑤ へ |
| **最終的に何が出来上がるか** | **客ごとの利用明細**（宿泊料に加算されていく）、対応記録、（設備の場合）**不具合報告** |

**なぜこの業務が必要なのか**

`【Inference】` 理由は2つあります。

1. **請求漏れを防ぐため。** 滞在中に発生した利用（飲食・売店・追加サービス）は、
   チェックアウト時にまとめて精算されるのが一般的です。
   その場で記録しなければ、翌朝には誰が何を使ったか分からなくなります。
2. **商品の質そのものだから。** 宿泊業の商品は「泊まる時間そのもの」です。
   滞在中の対応の質が、そのまま商品の質になります。

#### E-②-7 チェックアウト・精算・領収書発行 ★売上が確定する瞬間★

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 客の出発（チェックアウト時刻まで、または客が申し出たとき） |
| **誰が行うか** | ② フロント機能 |
| **何を確認するか** | ・宿泊料（泊数×単価）<br>・追加利用分（飲食・売店・コインランドリー・駐車場・その他）<br>・**決済区分**（事前決済済みか、現地で受け取るか、法人へ請求か）← **最重要**<br>・適用すべき税（消費税、**入湯税**、**宿泊税**がある地域はそれも）<br>・忘れ物・客室の破損等の有無<br>・鍵が返却されたか |
| **何をするか** | 明細を確定し、支払を受け、**領収書を発行**し、鍵を回収して見送る。<br>**チェックアウト済みであることを ③ 客室清掃へ伝える** |
| **何を判断するか** | ・追加請求すべきものがあるか（破損・持ち出し）`【Varies】`<br>・領収書の宛名・但し書き<br>・支払方法（現金・カード・コード決済・法人請求） |
| **誰と連携するか** | ⑧ 経理・財務（売上計上、現金の締め）／③ 客室清掃（**チェックアウト済み＝清掃可能の連絡**）／① 予約・販売管理（当日の在庫に戻る） |
| **最終的に何が出来上がるか** | **売上（この時点で確定）**、**領収書**、（法人の場合）**請求対象データ**、**清掃対象の部屋**、回収された鍵 |

**なぜこの業務が必要なのか**

`【Inference】` ここが**「サービスの提供が完了し、代金が確定する」点**です。
製造業でいえば納品・検収にあたります。以降は「代金を受け取る」または
「請求して受け取る」段階（サイクルB）に移ります。

**決済区分の確認が最重要である理由**

> `【Example】`（説明用の架空例。`04_end-to-end-process.md` A-5 より）
> 同じ日にチェックアウトする3人。
> - 客あ：OTAで事前決済済み → **フロントでは1円も受け取らない**
> - 客い：直販・現地決済 → **フロントで全額を受け取る**
> - 客う：A社の法人契約 → **フロントでは受け取らず、月末にA社へ請求**
>
> **見た目は同じ「1泊の客」ですが、精算の仕方は3通りです。**
> 間違えれば、二重請求（すでにOTAに払った客からもう一度取る）か、
> 取りこぼし（受け取るべき客から受け取らない）になります。

**精算時に上乗せされることがある税**

| 税 | 内容 | 根拠 |
|---|---|---|
| **消費税** | 宿泊料・飲食代等に課される | 消費税法 |
| **入湯税** | `【Fact】` **鉱泉浴場所在の市町村**が、鉱泉浴場における入湯に対し**入湯客**に課する目的税。`【Fact】` 税率は**入湯客1人1日につき150円を標準**とする。`【Fact】` 徴収は**特別徴収**の方法によらなければならず、**浴場の経営者その他徴収の便宜を有する者**が市町村の条例で特別徴収義務者として指定され、徴収して市町村に納入する | 地方税法第701条、第701条の2、第701条の3、第701条の4 |
| **宿泊税** | `【Fact】` 地方税法に定めのある税ではなく、地方団体が**条例で定める特定の費用に充てるため**に課することができる**法定外目的税**（第731条第1項）。`【Fact】` 新設・変更には**あらかじめ総務大臣に協議し、その同意を得る**必要がある（同条第2項）。`【Varies】` **課税の有無・対象・税率・免税点は地方団体ごとに条例で異なる** | 地方税法第731条以下 |

> `【Varies】` **宿泊税は全国一律の制度ではありません。** 本資料では特定の自治体の税率を示しません。
> 押さえるべきは **「宿が客から預かって、自治体に納める立場になる」** という構造です。
> `【Inference】` **これは宿の売上ではありません。** 売上と混ぜてはいけません。

> **初心者がつまずく点：売上 ≠ 入金**
> `【Typical】` ここで売上は確定しますが、**現金が宿に入るとは限りません。**
> 現地・現金なら即時入りますが、カード・OTA事前決済・代理店・法人契約では入りません
> （`04_end-to-end-process.md` 4-2 の B-①〜⑥）。

#### E-②-9 貴重品・手荷物の預かりと遺失物（忘れ物）の管理

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 客からの預かり依頼（貴重品・手荷物・チェックイン前後の荷物）／清掃中に忘れ物が発見されたとき（③ 客室清掃からの報告）／客からの「忘れ物をした」という連絡 |
| **誰が行うか** | ② フロント機能。発見は ③ 客室清掃が多い |
| **何を確認するか** | **預かり時**：預かる物の内容、預ける人の氏名・部屋番号、返却の予定<br>**忘れ物**：発見された部屋番号・日時・物の種類と特徴、その部屋の宿泊者が誰か（宿泊者名簿・予約記録で照合） |
| **何をするか** | **預かり**：預かり証を渡し `【Varies】`、保管し、本人確認のうえ返却する。<br>**忘れ物**：記録し、保管する。宿泊者が判明すれば連絡する。**法令に従って処理する**（後述） |
| **何を判断するか** | ・**高価品を預かるか**（種類と価額の通知を受けるか）<br>・保管しておく期間と、その後の扱い<br>・警察署長へ提出するもの |
| **誰と連携するか** | ③ 客室清掃（発見と引渡し）／⑨ 人事・総務（記録の管理）／**警察署**（社外） |
| **最終的に何が出来上がるか** | **預かり記録・預かり証**、**遺失物の記録**、返却された物、**警察署長へ提出された物件** |

**なぜこの業務が必要なのか — ① 預かった物への責任は法律で定まっています**

`【Fact】` 商法第596条第1項は、**旅館、飲食店、浴場その他の客の来集を目的とする場屋における
取引をすることを業とする者**（同節において「場屋営業者」）は、
**客から寄託を受けた物品の滅失又は損傷については、不可抗力によるものであったことを
証明しなければ、損害賠償の責任を免れることができない**と定めています。

`【Fact】` 同条第2項は、**客が寄託していない物品であっても、場屋の中に携帯した物品が、
場屋営業者が注意を怠ったことによって滅失し、又は損傷したときは、
場屋営業者は、損害賠償の責任を負う**と定めています。

`【Fact】` 同条第3項は、**客が場屋の中に携帯した物品につき責任を負わない旨を表示したときであっても、
場屋営業者は、前二項の責任を免れることができない**と定めています。

`【Fact】` 一方、商法第597条（高価品の特則）は、
**貨幣、有価証券その他の高価品については、客がその種類及び価額を通知して
これを場屋営業者に寄託した場合を除き、場屋営業者は、
その滅失又は損傷によって生じた損害を賠償する責任を負わない**と定めています。

`【Inference】` 以上の条文から、実務上は次のことが読み取れます。

- 宿は、**客から預かった物について重い責任を負う立場**にあります。
- 「責任を負いません」という掲示をしても、それだけで責任を免れる構造にはなっていません（第596条第3項）。
- **高価品については、客が種類と価額を通知して預けた場合に責任の対象となります**（第597条）。
  フロントが貴重品の預かり時に中身を確認・記録する実務は、この条文と対応しています `【Inference】`。

**なぜこの業務が必要なのか — ② 忘れ物（遺失物）の扱いも法律で定まっています**

`【Fact】` 遺失物法第2条第5項は、**「施設」**とは
**建築物その他の施設（車両、船舶、航空機その他の移動施設を含む。）であって、
その管理に当たる者が常駐するもの**をいうと定義し、
同条第6項は**「施設占有者」**とは**施設の占有者**をいうと定義しています。

`【Fact】` 遺失物法第4条第2項は、**施設において物件（埋蔵物を除く。）の拾得をした拾得者
（当該施設の施設占有者を除く。）は、速やかに、当該物件を当該施設の施設占有者に
交付しなければならない**と定めています。

`【Fact】` 遺失物法第13条第1項は、**第4条第2項の規定による交付を受けた施設占有者は、速やかに、
当該交付を受けた物件を遺失者に返還し、又は警察署長に提出しなければならない**と定めています
（ただし書として、法令の規定によりその所持が禁止されている物に該当する物件及び
犯罪の犯人が占有していたと認められる物件は、速やかに、これを警察署長に提出しなければならない）。

`【Fact】` 遺失物法第15条は、施設占有者は、交付を受けた物件については、
第13条第1項の規定により遺失者に返還し、又は警察署長に提出するまでの間、
**これを善良な管理者の注意をもって取り扱わなければならない**と定めています。

`【Inference】` 実務に置き換えると、次のようになります。

```
  客室清掃のスタッフが部屋で忘れ物を見つける
        │  （＝施設において物件の拾得をした拾得者）
        ▼
  速やかに施設占有者（＝宿）へ交付する   ← 遺失物法第4条第2項
        │
        ▼
  フロントが受け取り、記録して保管する   ← 善良な管理者の注意（同法第15条）
        │
        ├─▶ 遺失者に返還する            ← 同法第13条第1項
        └─▶ または警察署長に提出する      ← 同法第13条第1項
```

`【Typical】` フロントが遺失物の記録（発見日時・場所・物の種類と特徴・宿泊者名）を
残すのは、後から遺失者を特定し、返還または提出を行うためです `【Inference】`。

#### E-②-10 夜間対応（ナイトフロント） `【Varies】`

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 夜間帯の勤務開始（`【Varies】` 施設により時刻・体制が異なる） |
| **誰が行うか** | ② フロント機能の夜勤担当。**Xホテルではパート・夜勤アルバイト4名がこの帯を中心に担う**。`【Varies】` 小規模施設では夜間無人・自動チェックイン機・呼出ボタン等の運用もある |
| **何を確認するか** | ・**まだ到着していない予約（未着）** と、その連絡先<br>・在館者の状況（何室・何名が在館しているか）<br>・館内の安全（施錠、消灯、不審な出入り、火気）<br>・翌朝の到着・出発の予定<br>・当日の売上データ（未確定のもの） |
| **何をするか** | ・遅着の客のチェックイン<br>・夜間の電話・要望対応<br>・館内の巡回 `【Varies】`<br>・**ナイトオーディット（夜間監査）＝その日の売上の締めと確認**（→ E-②-13、⑧ 経理と共通）<br>・翌日の到着リストの準備<br>・**ノーショーの確認と記録** |
| **何を判断するか** | ・未着の客に連絡を取るか、ノーショーとするか（`【Varies】` 判断時刻は施設の定めによる）<br>・夜間に発生した事態を支配人に連絡すべきか |
| **誰と連携するか** | ① 予約・販売管理（翌日の在庫・当日残室）／⑧ 経理（売上の締め）／⑥ 設備管理（夜間の設備トラブル）／支配人（判断が要る事態）／**警察・消防・救急**（緊急時） |
| **最終的に何が出来上がるか** | **日次の売上の締め（ナイトオーディット）**、**日報**、翌日の到着リスト、夜間の記録・申し送り |

**なぜこの業務が必要なのか**

`【Inference】` `01_overview.md` 1-7 (6) のとおり、**宿泊業は24時間の事業です。**
客は夜中に到着し、夜中に体調を崩し、夜中に設備の不具合に気づきます。
**客が施設内で就寝している以上、誰かが起きて対応できる状態を保つ必要があります。**

- **ナイトオーディット（Night Audit。夜間監査）**
  → その日1日の売上・客室の状況を、日付が変わる前後に締めて確認する作業のこと。
  → 実務例：その日の宿泊料・飲食・売店の売上を集計し、
    現金の残高と帳簿上の金額が合っているかを確認し、
    在館している部屋・空室・清掃待ちの部屋の数を確定させて、日報にまとめる。
  → **なぜ夜にするのか**：`【Inference】` 宿泊業は24時間動いているため、
    **「1日の終わり」を人為的に決めないと売上が締まらない**からです。
    昼間はチェックイン・チェックアウトが同時に動いていて数字が確定しません。
    客の動きが止まる夜間が、その日の数字を固定できる唯一の時間帯です。

`【Varies】` **夜間の体制は施設によって大きく異なります。**
24時間有人のホテル、夜間は自動精算機・自動チェックイン機で運用する施設、
一定時刻で玄関を施錠し呼出対応とする旅館など、形はさまざまです。
**「すべての宿が夜勤者を置いている」とは限りません。**

#### E-②-11 緊急時対応（急病・火災・地震・設備故障・迷惑行為）

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 客・従業員からの通報、警報の作動、設備の停止、外部からの連絡（**トラブル発生時**） |
| **誰が行うか** | ② フロント機能が一次対応。**防火管理者（Xホテルでは支配人）**、⑥ 設備管理、⑨ 人事・総務が連動 |
| **何を確認するか** | ・何が起きているか、どこで起きているか、けが人・体調不良者がいるか<br>・在館者の人数と部屋（**収容人員の把握**）<br>・避難が必要な事態か<br>・外部（消防・救急・警察）へ連絡すべき事態か |
| **何をするか** | ・救急・消防・警察への通報<br>・在館者への周知・避難誘導<br>・設備の停止・復旧の手配（⑥ へ）<br>・客室の振替（部屋が使えなくなった場合）<br>・記録を残す |
| **何を判断するか** | ・通報するか、館内で対応できるか<br>・避難させるか<br>・営業を継続できるか（→ ① へ連絡して売止め） |
| **誰と連携するか** | ⑥ 設備管理／支配人（防火管理者）／⑨ 人事・総務（記録・報告）／**消防署・救急・警察・保健所**（社外）／設備メンテナンス業者 |
| **最終的に何が出来上がるか** | **事態の収束**、**記録（事故・苦情・設備故障の記録）**、必要に応じた行政への報告 |

**なぜこの業務が必要なのか**

`【Fact】` 消防法第8条第1項は、**学校、病院、工場、事業場、興行場、百貨店…その他多数の者が出入し、
勤務し、又は居住する防火対象物で政令で定めるものの管理について権原を有する者**は、
政令で定める資格を有する者のうちから**防火管理者**を定め、政令で定めるところにより、
当該防火対象物について**消防計画の作成、当該消防計画に基づく消火、通報及び避難の訓練の実施、
消防の用に供する設備、消防用水又は消火活動上必要な施設の点検及び整備、
火気の使用又は取扱いに関する監督、避難又は防火上必要な構造及び設備の維持管理
並びに収容人員の管理その他防火管理上必要な業務**を行わせなければならないと定めています。

`【Fact】` 旅館、ホテル、宿泊所その他これらに類するものは、
消防法施行令別表第一**（五）項イ**に掲げられており、
`【Fact】` 収容人員が**30人以上**のものは防火管理者の選任が必要です
（消防法施行令第1条の2第3項第1号ロ）。

`【Inference】` 上の条文に**「収容人員の管理」**が含まれている点が、フロント業務と直結します。
**「今、館内に何人いるのか」を把握しているのはフロントだけ**だからです。
火災が起きたとき、客は建物の構造も避難経路も知りません。

#### E-②-12 宿泊を拒む事由への該当判断

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 予約申込時（A-3）／チェックイン時（A-7）／滞在中に事態が生じたとき |
| **誰が行うか** | ② フロント機能。**判断は支配人に上げるのが一般的** `【Typical】` |
| **何を確認するか** | ・**旅館業法第5条第1項各号のいずれかに該当するか**（下表）<br>・該当すると判断する**客観的な事実**があるか |
| **何をするか** | 該当しなければ受け入れる。該当する場合、法令の枠組みに従って対応し、**求めに応じて理由を丁寧に説明できるようにする** |
| **何を判断するか** | 各号への該当の有無。**これは限定列挙であり、宿の裁量で自由に断れるものではない** |
| **誰と連携するか** | 支配人・社長／⑨ 人事・総務（記録）／必要に応じて**警察**／**保健所** |
| **最終的に何が出来上がるか** | 受入れ、または法令に基づく対応と**その記録** |

**なぜこの業務が必要なのか — 宿泊業は原則として宿泊を拒めません**

`【Fact】` 営業者は、**次の各号のいずれかに該当する場合を除いては、宿泊を拒んではなりません**
（旅館業法第5条第1項）。

| 号 | 拒否できる事由 |
|---|---|
| 一 | 宿泊しようとする者が**特定感染症の患者等**であるとき |
| 二 | 宿泊しようとする者が**賭博その他の違法行為又は風紀を乱す行為をするおそれがある**と認められるとき |
| 三 | 宿泊しようとする者が、営業者に対し、**その実施に伴う負担が過重であって他の宿泊者に対する宿泊に関するサービスの提供を著しく阻害するおそれのある要求**として厚生労働省令で定めるものを**繰り返した**とき |
| 四 | **宿泊施設に余裕がないとき**その他**都道府県が条例で定める事由**があるとき |

`【Fact】` 第三号の「厚生労働省令で定めるもの」は次のとおりです（旅館業法施行規則第5条の6。
いずれも**他の宿泊者へのサービス提供を著しく阻害するおそれのあるもの**に限る）。

| 号 | 内容 |
|---|---|
| 一 | **宿泊料の減額**その他その内容の実現が容易でない事項の要求（**障害者差別解消法第2条第2号に規定する社会的障壁の除去を求める場合を除く**） |
| 二 | **粗野又は乱暴な言動**その他の従業者の心身に負担を与える言動を交えた要求であって、当該要求をした者の接遇に**通常必要とされる以上の労力を要することとなるもの**（営業者が障害を理由とする不当な差別的取扱いを行ったことに起因するもの等を除く） |

`【Fact】` また同条第2項は、営業者に対し、**旅館業の公共性を踏まえ、
宿泊しようとする者の状況等に配慮して、みだりに宿泊を拒むことがないよう**にするとともに、
**拒む場合には各号のいずれかに該当するかどうかを客観的な事実に基づいて判断**し、
**求めに応じてその理由を丁寧に説明できるようにする**ことを定めています。

`【Fact】` 第5条第1項に違反した場合の罰則は**50万円以下の罰金**です（同法第11条第1号）。

> **実務上の意味**
> `【Inference】` フロント担当者は、**「断れる場合」が法律で限定列挙されている**ことを
> 理解している必要があります。
> 特に、**障害を理由とする差別的取扱いは明確に除外規定が置かれている**点、
> また**「宿泊料の減額要求」や「乱暴な言動を交えた過重な要求」は、
> それが繰り返された場合に限って拒否事由になり得る**点に注意が必要です。
> 本資料は法令の内容を説明するものであり、個別事案の判断を示すものではありません。

`【Fact】` なお、営業者は、旅館業の施設において**特定感染症のまん延の防止に必要な対策を
適切に講じ、及び高齢者、障害者その他の特に配慮を要する宿泊者に対して
その特性に応じた適切な宿泊に関するサービスを提供するため、その従業者に対して
必要な研修の機会を与えるよう努めなければならない**とされています
（旅館業法第3条の5第2項。努力義務）。

#### E-②-13 レジ締め・日次の売上の締め（⑧ 経理と共同）

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 日次（`【Varies】` 夜間または勤務交代時） |
| **誰が行うか** | ② フロント機能（夜勤担当が行うことが多い `【Typical】`）。確認は ⑧ 経理・財務、支配人 |
| **何を確認するか** | ・その日の宿泊売上・飲食売上・売店売上・その他売上<br>・**支払方法別の内訳**（現金・カード・コード決済・OTA事前決済・法人請求）<br>・**レジの現金残高と帳簿上の金額が合っているか**<br>・釣銭の準備金<br>・当日の在館室数・空室数・清掃待ち室数<br>・入湯税・宿泊税の預り分 `【Varies】` |
| **何をするか** | 売上を集計し、現金を数え、差異があれば原因を探す。売上金を金庫へ入れる。**日報**を作成する |
| **何を判断するか** | ・レジ差異が出た場合の原因（釣銭の渡し間違い、記録漏れ、入力誤り）<br>・支配人に報告すべき事項か |
| **誰と連携するか** | ⑧ 経理・財務（日次の売上データの引継ぎ、銀行への入金）／① 予約・販売管理（OCC・ADRの速報値）／支配人 |
| **最終的に何が出来上がるか** | **日報（日次売上報告書）**、**確定した当日売上**、金庫に収まった売上金、**レジ差異の記録** |

**なぜこの業務が必要なのか**

`【Inference】` `04_end-to-end-process.md` 4-2 のとおり、
**宿泊業の売上はチャネルごとにお金の入り方が違います。**
「今日いくら売れたか」と「今日いくら現金が入ったか」は一致しません。

だから日次の締めでは、**「売上の合計」と「支払方法別の内訳」の2つを別々に出す**必要があります。
この2つが分かれていないと、翌月にOTAや法人から入金があったときに、
どの売上に対する入金なのかを突き合わせられません（→ ⑧ 経理の E-⑧-4）。

#### E-②-14 清掃完了状況の確認と客室の販売可否の管理

| 7つの視点 | 内容 |
|---|---|
| **何をきっかけに始まるか** | チェックアウト（部屋が空く）／清掃の進行中／清掃完了報告の受領 |
| **誰が行うか** | ② フロント機能。報告するのは ③ 客室清掃 |
| **何を確認するか** | ・**各部屋が今どの状態にあるか**（在室中／チェックアウト済・清掃前／清掃中／清掃済・点検前／清掃済・販売可／使用不可）<br>・当日のチェックイン予定と、その部屋が仕上がっているか<br>・早着の客がいるか<br>・不具合の報告があった部屋 |
| **何をするか** | 清掃完了の報告を受け、**PMS上の客室状態を「販売可」に更新する**。仕上がった部屋から順にチェックインに使う |
| **何を判断するか** | ・今チェックインできる部屋があるか<br>・早着の客を待たせるか、別の部屋に変えるか<br>・不具合のある部屋を売ってよいか（→ ⑥ 設備管理、① へ連絡） |
| **誰と連携するか** | ③ 客室清掃（完了報告・不具合報告）／⑥ 設備管理（修理の要否）／① 予約・販売管理（使用不可の部屋を在庫から外す） |
| **最終的に何が出来上がるか** | **最新の客室状態（ルームステータス）**、チェックインに使える部屋の一覧 |

**なぜこの業務が必要なのか**

- **ルームステータス（客室状態）**
  → 1つ1つの部屋が今どういう状態にあるかを表す区分のこと。
  → 実務例：`【Typical】` 「在室中」「チェックアウト済・清掃前（＝汚れている）」「清掃中」
    「清掃済・点検前」「清掃済・販売可」「使用不可（故障・修繕）」などに分けて管理する
    `【Varies】` 呼び方は施設・システムにより異なります。
  → **なぜ必要か**：`【Inference】` **「空いている部屋」と「今すぐ売れる部屋」は違う**からです。
    客がチェックアウトした直後の部屋は、空いてはいますが、そのままでは次の客に渡せません。
    **清掃が終わって初めて商品に戻ります。**

`【Inference】` **この情報が正確でないと、宿は部屋を売れません。**
清掃が終わっている部屋をフロントが知らなければ、待合スペースに客を待たせ続けることになります。
逆に、終わっていない部屋に客を通してしまえば、前の客のゴミが残っている部屋に案内することになります。
**この連携が宿泊業の心臓部です（→ PART 3 の 3-2 で独立して扱います）。**

### F. 業務頻度

| 業務 | 頻度 |

### L. 使用データ

予約情報（日付・泊数・人数・部屋タイプ・プラン・氏名・連絡先・特記事項）／
**決済区分情報**（誰がいつ集金するか）／**宿泊者情報**（氏名・住所・連絡先・国籍・旅券番号）／
**客室状態情報（ルームステータス）**／在館情報（今誰が何室に泊まっているか）／
利用明細情報（宿泊料・飲食・売店・その他）／売上情報（支払方法別）／
鍵の受渡し情報／遺失物情報／苦情・事故情報／シフト情報

> `【Inference】` 宿泊者名簿の情報は、**法令が記載・保存・提出を義務づけている情報**であると同時に、
> 氏名・住所・連絡先という個人に関する情報でもあります。
> 取扱いには法令上の要請が重なっている点を押さえてください。

### O. 見ている数字・KPI

| 数字 | 意味 | なぜ見るか |
|---|---|---|
| **当日の到着件数・出発件数** | 今日何人来て何人出るか | 人員配置と清掃室数が決まる |
| **在館室数・在館人数** | 今館内に何室・何人いるか | **収容人員の管理**（消防法第8条第1項）と緊急時対応の前提 |
| **清掃完了室数／清掃待ち室数** | 今すぐ売れる部屋がいくつあるか | 部屋を渡せるかどうかが決まる |
| **残室数** | 今日あと何室売れるか | 飛び込み対応と当日の価格判断（① へ） |
| **日次売上（支払方法別）** | いくら売れて、いくら現金で入ったか | 売上と入金は別物のため（`04_end-to-end-process.md` 4-2） |
| **レジ差異** | 現金の実数と帳簿の差 | 記録漏れ・渡し間違いの発見 |
| **ノーショー件数** | 連絡なく来なかった件数 | 再販売の機会が完全に失われた件数 |
| **平均チェックイン所要時間** `【Varies】` | 1組あたりの手続時間 | 到着が集中する時間帯の待ち時間に影響する |
| **苦情件数・内容** | どんな指摘が出ているか | どの機能に問題が生じているかの手がかり |
| **稼働率（OCC）・ADR** | 当日の速報値 | ① と共有する共通言語 |

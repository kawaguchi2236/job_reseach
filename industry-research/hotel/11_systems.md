# 11_systems.md — 宿泊業で使われるシステム

> 本ファイルは、中小宿泊業で**現在一般的に使われているシステムの種類**を、
> **「それは何のための道具か」**という観点だけで説明します。
>
> `common/methodology.md` §0 のとおり、本資料は業界・業務を理解するための教科書です。
> **したがって本ファイルでは、次のことを一切書きません。**
> - DX施策・デジタル化の評価・IT導入の提案
> - 「このシステムを入れるべき」「この作業は自動化できる」といった提案
> - 特定ベンダー・製品の推奨、製品比較
> - 「紙は非効率」「アナログである」といった価値判断
>
> **書くのは、「その道具は何を管理するものか」「誰が何の業務で使うか」「何が入って何が出るか」だけです。**
>
> 機能の番号（①〜⑨）は `03_company-structure.md` 3-2、
> ステップ名（A-1〜A-11、B-①〜⑥）は `04_end-to-end-process.md` の定義に従います。
> 情報の名前は `09_information.md`、帳票は `10_documents.md` を参照してください。

## 11-0 この章の読み方

### 各システムを5点で説明する

| 見出し | 何を書くか |
|---|---|
| **何を管理するものか** | その道具が抱えている対象 |
| **誰が使うか** | どの機能の、どの担当者が触るか |
| **どの業務で使うか** | A-1〜A-11／B-①〜⑥ のどのステップか |
| **どんな情報が入るか** | インプット（`09_information.md` の情報名で示す） |
| **どんな情報が出るか** | アウトプット |

### 宿泊業のシステムの全体像

`【Inference】` 宿泊業のシステムは、**中心にPMSがあり、その周りに「売る側」と「支える側」が付く**形です。

```
                【売る側】
  ┌──────────────────────────────────────────────────────┐
  │  OTAの管理画面        自社サイトの予約エンジン         │
  │（エクストラネット）                                    │
  │       │                        │                      │
  │       └──────────┬─────────────┘                      │
  │                  ▼                                    │
  │        **サイトコントローラー**                        │
  │        （各チャネルの在庫・料金を同期）                │
  └──────────────────────┬───────────────────────────────┘
                         │ 予約情報・在庫情報
                         ▼
  ┌──────────────────────────────────────────────────────┐
  │          ★ **PMS（宿泊管理システム）** ★              │
  │  予約・客室・宿泊者・売上・客室ステータスの中心         │
  └───┬──────────┬──────────┬──────────┬────────────────┘
      │          │          │          │
      ▼          ▼          ▼          ▼
  決済端末   清掃管理    鍵システム   会計ソフト
              の仕組み  （カードキー）    │
                                          ▼
                                    勤怠管理／給与

  【レベニューマネジメントの道具】`【Varies】` … 価格判断の材料を見るために使われる
  【電話交換・客室電話】`【Varies】` … 館内の通話
```

`【Varies】` **これらがすべて別々の仕組みである施設と、1つにまとまっている施設があります。**
`【Varies】` **そもそもPMSを使っていない施設もあり、紙の台帳で運用されている施設もあります**（11-12）。

## 11-1 PMS（宿泊管理システム）

- **PMS（Property Management System。宿泊管理システム）**
  → 宿泊施設の**予約・客室・宿泊者・売上**を一元的に記録し、日々の運営に使う仕組みのこと。
  → 実務例：フロントが電話予約を受けてPMSに登録すると、在庫が1つ減り、
    当日の到着リストに載り、チェックイン時に宿泊者名簿の材料になり、
    チェックアウト時に明細が確定し、その日の売上に集計される。
  → **なぜ必要か**：`【Inference】` `09_information.md` 9-0 のとおり、
    宿泊業の情報は**1件の予約を軸に鎖のようにつながっています。**
    予約台帳・到着リスト・客室状況・売上を別々に持つと、
    同じ内容を何度も書き写すことになり、どこかで食い違います。

| 項目 | 内容 |
|---|---|
| **何を管理するものか** | **予約**（誰が・いつ・何室・何人・いくらで）／**客室**（部屋番号・タイプ・**ステータス**）／**宿泊者**（氏名・住所・連絡先）／**売上**（宿泊料・料飲・その他・税）／**決済区分** |
| **誰が使うか** | **② フロント（最も使う）**／① 予約・販売管理（支配人）／③ 客室清掃（`【Varies】` ステータス更新）／⑧ 経理（売上データ） |
| **どの業務で使うか** | A-2（在庫）・**A-3（予約受付）**・A-4（予約管理）・A-5（決済区分）・**A-6（到着前準備）**・**A-7（チェックイン）**・A-8（滞在中）・**A-9（精算）**・A-10（客室ステータス）・A-11（在庫へ戻す） |
| **どんな情報が入るか** | 予約情報（電話・メール・自社サイト・**サイトコントローラー経由でOTAから自動**）／宿泊者の情報（チェックイン時）／滞在中の利用（飲食・売店）／清掃状況情報 `【Varies】`／販売価格情報・配分情報 |
| **どんな情報が出るか** | **当日到着リスト**／**ルームアサイン表**／**客室ステータス一覧**／**宿泊者名簿**（`【Varies】` PMSから出力する場合）／**利用明細・領収書**／**ナイトオーディットの日計表**／OCC・ADR・RevPAR |

**PMSが担っている役割（`09_information.md` との対応）**

| PMSの中にある情報 | `09_information.md` での名前 |
|---|---|
| 予約一覧 | **予約情報** |
| 空室状況 | **在庫（残室）情報** |
| 決済方法の欄 | **決済区分情報** |
| 到着リスト・アサイン | **到着前情報** |
| 宿泊者の登録 | **チェックイン情報（宿泊者名簿）** |
| 客室ステータス | **清掃状況情報** |
| 明細・日計 | **精算情報／売上確定情報** |

> **宿泊者名簿とPMSの関係について**
> `【Fact】` 旅館業法施行規則第4条の2第1項は、宿泊者名簿を
> **正確な記載を確保するための措置を講じた上で作成**し、**作成の日から3年間保存**することを求めています。
> `【Fact】` 同条第2項は備える場所を**旅館業の施設**および**営業者の事務所**と定めています。
> `【Varies】` **PMSの記録をもって名簿とするか、宿泊カードを綴じて保存するかは施設の運用により異なります。**
> 本資料では特定の運用が適法であると断定しません（`10_documents.md` 10-2-1／10-2-2）。

## 11-2 サイトコントローラー

- **サイトコントローラー**
  → 複数の販売チャネル（自社サイト・OTA各社・旅行代理店）の
    **在庫と料金を一括で同期させる仕組み**のこと。
  → 実務例：OTA①で1室売れると、その情報を受けて自社サイト・OTA②・OTA③の在庫も自動で1室減らす。
    価格を変えるときも、1か所で変えれば全チャネルに反映される。
  → **なぜ必要か**：`【Inference】` `09_information.md` 9-3 のとおり、
    宿泊業は**同じ1つの在庫を複数の売り場に同時に並べています。**
    どこかで1室売れたら、他のすべての売り場の在庫を即座に減らさなければなりません。
    人が5か所の画面を1つずつ更新していては、その作業の間に別のチャネルで売れてしまいます。

| 項目 | 内容 |
|---|---|
| **何を管理するものか** | **チャネル横断の在庫（残室）と料金**／各チャネルへの**配分** |
| **誰が使うか** | **① 予約・販売管理機能**（`【Example】` Xホテルでは支配人） |
| **どの業務で使うか** | **A-2（在庫の各チャネルへの配分）**／A-1（価格の反映）／A-11（在庫へ戻す） |
| **どんな情報が入るか** | **販売価格情報**（日付別・部屋タイプ別・プラン別）／**各チャネルへの配分情報**／PMSからの在庫の増減 |
| **どんな情報が出るか** | 各チャネルに表示される**空室数と価格**／各チャネルから受けた**予約情報**（PMSへ渡す） |

**この道具が解決している構造**

```
  【サイトコントローラーが無い場合】
    1室売れる → 人が 自社サイト・OTA①・OTA②・OTA③・代理店 の5か所を順に更新
                  ▲
                  この作業中に別のチャネルで売れると **オーバーブッキング**

  【サイトコントローラーがある場合】
    1室売れる → サイトコントローラーが全チャネルの在庫を同期
```

`【Inference】` つまりサイトコントローラーは、
**「在庫情報を1つに保つ」ためだけに存在する仕組み**です。

`【Varies】` **PMSとサイトコントローラーが一体になっている場合と、別々の場合があります。**

## 11-3 OTAの管理画面（エクストラネット）

- **OTA（Online Travel Agent。オンライン旅行会社）**
  → インターネット上で宿泊施設の予約を受け付ける事業者のこと（`02_industry-structure.md` 11-1 ①）。

- **エクストラネット（OTAの管理画面）**
  → OTAが宿泊施設向けに用意している管理画面のこと。
    宿がそのOTA上の掲載内容・在庫・料金・予約・精算を確認・操作する場所です。
  → 実務例：掲載写真を差し替える、プラン名と説明文を書き直す、
    特定の日の販売を止める（クローズアウト）、予約とキャンセルの一覧を見る、
    今月の精算明細を確認する、口コミに返信する `【Varies】`。
  → **なぜ必要か**：`【Inference】` OTAは宿の売り場であり、
    **そこに何をどう並べるかは宿が決めます。** その操作をする場所が要ります。

| 項目 | 内容 |
|---|---|
| **何を管理するものか** | **そのOTA上の掲載内容**（写真・プラン名・説明文・施設情報）／そのOTAの**在庫と料金**／そのOTA経由の**予約とキャンセル**／そのOTAの**精算明細** |
| **誰が使うか** | ① 予約・販売管理（支配人）／⑦ 営業（取引条件・掲載交渉）／⑧ 経理（精算明細の取得） |
| **どの業務で使うか** | A-1（価格）／A-2（在庫配分）／A-3（予約の受信）／A-4（変更・キャンセル）／**B-③・B-④（入金と手数料）** |
| **どんな情報が入るか** | 掲載内容（写真・文章）／販売価格情報／配分情報（`【Varies】` サイトコントローラー経由で自動反映される場合もある） |
| **どんな情報が出るか** | **予約情報**（サイトコントローラー経由でPMSへ）／**OTAの精算明細**（`10_documents.md` 10-4-3）／口コミ `【Varies】`／販売実績 |

`【Varies】` **OTAは複数社と取引するのが一般的であり、その場合は管理画面もOTAごとに別々です。**
`【Inference】` したがって「OTAの管理画面を見る」という作業は、**取引しているOTAの数だけ発生します。**

## 11-4 予約エンジン（自社サイトの予約機能）

- **予約エンジン（予約受付システム）**
  → 宿の自社サイト上で、客が直接、空室を見て予約・決済まで行えるようにする仕組みのこと。
  → 実務例：客が自社サイトの「空室検索」で3月10日を選び、
    シングル・朝食付きのプランを選び、氏名と連絡先を入力し、
    クレジットカードで事前決済するか「現地決済」を選んで予約を完了する。
  → **なぜ必要か**：`【Inference】` 自社サイトに「電話番号」だけを載せている場合、
    予約は営業時間内の電話に限られます。予約エンジンがあれば、
    **客がOTAを経由せずに、24時間いつでも予約できます**（＝直販。B-①／B-②）。

| 項目 | 内容 |
|---|---|
| **何を管理するものか** | **自社サイト経由の予約**／自社サイトに表示する在庫と料金・プラン |
| **誰が使うか** | 客（予約する側）／① 予約・販売管理（掲載内容と価格の設定）／② フロント（入った予約の確認） |
| **どの業務で使うか** | A-2（配分）／**A-3（予約受付）**／A-5（決済区分）／B-①・B-②（直販の入金） |
| **どんな情報が入るか** | 販売価格情報／配分情報（`【Varies】` サイトコントローラー経由）／客が入力した予約情報 |
| **どんな情報が出るか** | **予約情報**（PMSへ）／**予約確認書**（客へのメール）／事前決済の場合は決済データ |

`【Varies】` 自社サイトに予約エンジンを置いているかどうかは施設により異なります。
`【Typical】` 電話とメールのみで予約を受けている施設もあります。

## 11-5 レベニューマネジメントの道具 `【Varies】`

- **レベニューマネジメント（収益管理）**
  → 「いつ・どのチャネルに・いくらで・何室出すか」を、予約の入り具合を見ながら
    決め直していく仕事のこと（`02_industry-structure.md` 11-2）。

`【Varies】` **この仕事のために何を使うかは、施設によって大きく異なります。**

| 使われているもの `【Varies】` | 何を見るか |
|---|---|
| **PMSの予約状況の画面** | 日付ごとの予約の入り具合（残室数） |
| **表計算ソフトで作った表** | 過去の同時期の実績、今年の入り方との比較、日付別の残室と価格 |
| **OTAの管理画面の販売実績** | そのOTAでどれだけ売れているか |
| **専用の仕組み** `【Varies】` | `【Varies】` 需要の予測や価格の提案を行うものがあるが、導入の有無は施設により異なる |
| **紙のノート・手書きの表** | `【Typical】` 日付ごとの残室と価格を書き込む |

`【Inference】` 共通しているのは、**見ている情報が同じ**ことです。

```
  ・日付ごとの残室数（＝在庫情報）
  ・日付ごとの予約の入り方の推移（＝ブッキングカーブ）
  ・過去の同時期の実績（＝売上確定情報の蓄積）
  ・曜日・連休・地域のイベント
  ・周辺の宿の状況 `【Varies】`
```

- **ブッキングカーブ**
  → ある宿泊日について、**予約が日を追ってどう積み上がってきたか**を表した線のこと。
  → 実務例：3月10日の予約が、2か月前・1か月前・1週間前・前日にそれぞれ何室入っていたかを並べる。
    去年の同じ曜日の線と比べ、今年が早いか遅いかを見る。
  → **なぜ見るのか**：`【Inference】` 「今20室空いている」という事実だけでは、
    高いのか安いのか判断できません。
    **去年の同じ時期より早く埋まっているなら価格を上げられ、遅いなら手を打つ**という判断になります。

> `【Varies】` **中小宿泊業では、専任者を置かず支配人や女将が兼務するのが一般的です**
> （`02_industry-structure.md` 11-2、`03_company-structure.md` 3-2 ①）。
> **本資料は、どの道具を使うべきかを述べるものではありません。**

## 11-6 客室管理・清掃管理の仕組み

`【Varies】` **清掃状況情報の受け渡しに何を使うかは、施設により大きく異なります。**
`05_departments.md` PART 3 3-2-4 および `09_information.md` 9-4-4 の表と同じ内容です。

| 使われているもの `【Varies】` | どういうものか | 記録は残るか |
|---|---|---|
| **内線電話・無線機** | 仕上がるたびに ② フロントへ口頭で伝える | `【Inference】` 残らない |
| **清掃状況表（紙）** | 紙の表に部屋番号と状態を書き、② が見に行く／受け取る | 残る |
| **PMSの客室ステータス** | 清掃側が直接システムの状態を変え、② の画面に反映される | 残る |
| **清掃管理の仕組み** `【Varies】` | 清掃側の端末から状態を送る | 残る |

### PMSの客室ステータス機能として使う場合

| 項目 | 内容 |
|---|---|
| **何を管理するものか** | **部屋番号ごとの状態**（使用済み／清掃中／清掃済・点検前／**販売可**／使用不可） |
| **誰が使うか** | ③ 客室清掃（状態を変える）／**② フロント（状態を見る）**／① 予約・販売管理（売れる在庫の把握）／⑥ 設備管理（使用不可の設定） |
| **どの業務で使うか** | **A-10（客室清掃）**／A-6（アサイン）／A-7（鍵の受渡し）／A-11（在庫へ戻す） |
| **どんな情報が入るか** | チェックアウトの確認（② から）／清掃の完了（③ から）／点検の結果（③ から）／不具合（③・⑥ から） |
| **どんな情報が出るか** | **「今、渡せる部屋」の一覧**（② が使う）／**「今、売れる在庫」**（① が使う） |

`【Inference】` **どの道具を使っても、受け渡される中身は同じです**（`09_information.md` 9-4-4）。
・どの部屋が、今、販売可になったか
・まだ終わっていない部屋はどれで、いつ終わる見込みか
・売ってはいけない部屋はどれか

> **外部委託の場合について**
> `【Example】` Xホテルは客室清掃を外部委託しています。
> `【Varies】` **委託先がPMSを直接操作するか、責任者が電話・紙で報告するかは契約・運用により異なります。**
> `【Inference】` 社外との受け渡しになる分、経路が1段増えます（`06_people.md` 6-6-1）。

## 11-7 会計ソフト

| 項目 | 内容 |
|---|---|
| **何を管理するものか** | **仕訳と帳簿**（売上・仕入・経費・売掛金・買掛金・預り金）／**月次の試算表**／年次の決算 |
| **誰が使うか** | ⑧ 経理・財務機能（`【Example】` Xホテルでは事務パート）／**顧問税理士**／社長 |
| **どの業務で使うか** | B-①〜⑥（入金の消込）／月次決算／年次決算・税務申告／資金繰りの把握 |
| **どんな情報が入るか** | **ナイトオーディットの日計表**（売上）／仕入・経費の請求書／**OTA・代理店の精算明細**／入出金の記録（通帳）／給与の情報／**預り金**（入湯税・宿泊税・源泉所得税・社会保険料） |
| **どんな情報が出るか** | **月次試算表**／貸借対照表・損益計算書／売掛金・買掛金の残高一覧／消費税・法人税の申告の材料 |

**宿泊業で会計ソフトが扱う、他業界と違う項目**

`【Inference】`

| 項目 | なぜ宿泊業で特別か |
|---|---|
| **チャネル別の売掛金** | `08_money.md` 8-1 のとおり、**入金の形がチャネルごとに違う**。OTA・代理店・法人・カード会社がそれぞれ別の相手先になる |
| **OTA・代理店への手数料** | `【Varies】` 入金から控除される場合と、請求を受けて支払う場合がある |
| **預り金（入湯税・宿泊税）** | `【Inference】` **売上ではない。** 客から預かって自治体に納めるもの（`08_money.md` 8-4） |
| **前受金** `【Varies】` | `【Inference】` 事前決済を受けた分は、宿泊の提供前に受け取っている |

`【Varies】` **会計ソフトを宿が直接使うか、顧問税理士に記帳を任せるかは施設により異なります。**
`【Typical】` 中小宿泊業では、**日々の売上・現金は宿が管理し、仕訳と決算は税理士が行う**という
分担が見られます（`03_company-structure.md` 3-2 ⑧）。

## 11-8 勤怠管理

| 項目 | 内容 |
|---|---|
| **何を管理するものか** | 従業者ごとの**出退勤の時刻**／休憩／時間外労働／**深夜（午後10時〜午前5時）の労働時間**／休日労働／有給休暇 `【Varies】` |
| **誰が使うか** | 従業者本人（打刻）／⑨ 人事・総務（集計・給与計算）／⑧ 経理（人件費） |
| **どの業務で使うか** | シフトの作成・調整／勤怠の管理／**給与計算（深夜割増を含む）**／社会保険・労働保険の手続 |
| **どんな情報が入るか** | 打刻（出勤・退勤）／**勤務シフト表**／申請（休暇・時間外） |
| **どんな情報が出るか** | 月ごとの勤務時間の集計／**深夜労働時間**／時間外労働時間／給与計算の材料／人時の把握（`14_kpi.md` の人時生産性） |

**宿泊業で深夜労働時間の記録が避けられない理由**

`【Fact】` **労働基準法第37条第4項**
> 使用者が、**午後十時から午前五時まで**（…）の間において労働させた場合においては、
> その時間の労働については、通常の労働時間の賃金の計算額の**二割五分以上の率**で計算した
> **割増賃金**を支払わなければならない。

`【Inference】` `01_overview.md` 1-7(6) のとおり、宿泊業は**24時間の事業**です。
`【Example】` Xホテルは年中無休・24時間フロントであり、夜勤のシフトが常に存在します。
したがって**深夜帯の労働時間を、従業者ごとに把握する必要があります。**

`【Varies】` 打刻の手段（タイムカード・システム・手書きの出勤簿）は施設により異なります。

## 11-9 決済端末

| 項目 | 内容 |
|---|---|
| **何を管理するものか** | **現地での決済**（クレジットカード・コード決済・電子マネー `【Varies】`） |
| **誰が使うか** | ② フロント／④ 料飲（`【Varies】` レストラン・売店） |
| **どの業務で使うか** | **A-9（チェックアウト・精算）**／A-7（`【Varies】` 到着時に収受する場合）／**B-②（直販・カード）／B-③（OTA・現地決済）** |
| **どんな情報が入るか** | 精算する金額（**利用明細の確定額**）／カード・コードの読み取り |
| **どんな情報が出るか** | 決済データ（決済会社へ）／控え（客へ・宿へ）／`【Varies】` PMSへの連携 |

**なぜ「決済端末」を独立して挙げるのか**

`【Inference】` `08_money.md` 8-1 のとおり、**カード決済ではチェックアウト時にお金は動きません。**
動くのは決済データであり、**現金が宿に入るのは決済会社の締め日の後です**（B-②）。
`【Inference】` つまり決済端末は「お金を受け取る道具」ではなく、
**「後日お金が入ることを確定させる道具」**です。

`【Varies】` レジと決済端末が一体か別か、PMSと連携しているかは施設により異なります。
`【Typical】` 中小宿泊業では、**レジ（現金）と決済端末（カード等）が別々**で、
それぞれの締めを行う運用が見られます。

## 11-10 鍵システム（カードキー） `【Varies】`

`【Varies】` **鍵の形式は施設により異なります。**

| 形式 | どういうものか | 誰が管理するか |
|---|---|---|
| **物理キー** | 金属の鍵。`【Typical】` フロントのキーボックスで管理 | ② フロント |
| **カードキー** | カードに客室と有効期間の情報を書き込んで渡す `【Varies】` | ② フロント／⑥ 設備管理（機器の維持） |
| **暗証番号** `【Varies】` | 客室の入口で番号を入力する | ② フロント |

### カードキーの仕組みを使う場合

| 項目 | 内容 |
|---|---|
| **何を管理するものか** | **どのカードが、どの客室に、いつまで入れるか** |
| **誰が使うか** | ② フロント（発行・回収）／③ 客室清掃（`【Varies】` 清掃用のカード）／⑥ 設備管理（機器の維持・電池交換） |
| **どの業務で使うか** | **A-7（鍵の受渡し）**／A-8（滞在中の再発行 `【Varies】`）／A-9（回収）／A-10（清掃時の入室） |
| **どんな情報が入るか** | アサイン情報（どの部屋か）／宿泊期間（いつまで有効か） |
| **どんな情報が出るか** | 有効なカード／`【Varies】` 入室の記録（機器により異なる） |

**なぜ鍵が「システム」として扱われるのか**

`【Fact】` **旅館業法施行規則第4条の3第2号**は、玄関帳場その他の設備の基準として、
**宿泊者名簿の正確な記載、宿泊者との間の客室の鍵の適切な受渡し及び
宿泊者以外の出入りの状況の確認を可能とする設備を備えていること**を定めています。

`【Inference】` つまり**鍵の受渡しは、法令が設備面から担保しようとしている事項**です。
`【Inference】` 鍵を渡すとは、**その部屋への立入権限を客に移す**ことであり、
渡す相手を取り違えれば重大な問題になります（`04_end-to-end-process.md` A-7）。

`【Varies】` **鍵の形式と法令上の要求の関係について、本資料では特定の形式が要求されているとは述べません。**
条文は「適切な受渡し」と「宿泊者以外の出入りの状況の確認」を可能とする設備を求めています。

### なぜ併用されるのか（理由の記述。評価ではありません）

`【Inference】`

1. **客の前で使えるかどうかが違う。**
   電話を受けながら画面を操作するより、手元のメモに書き取ってから入力するほうが、
   通話を止めずに済む場面があります。
2. **持ち歩けるかどうかが違う。**
   清掃スタッフは客室を回ります。館内の別の階で、印刷した表に書き込むという形になります。
3. **同時に複数の人が見られるかどうかが違う。**
   紙の清掃表は、通りかかった人が誰でも見られます。
4. **社外の相手と共有できるかどうかが違う。**
   `【Example】` Xホテルの清掃は委託先（C清掃）です。
   `【Varies】` 委託先がPMSを操作する権限を持つとは限らず、紙・電話での受け渡しになる場合があります。
5. **記録として残す必要のあるものがある。**
   `【Fact】` 宿泊者名簿は**作成の日から3年間の保存**が必要です（旅館業法施行規則第4条の2第1項）。
   `【Varies】` 宿泊カードを綴じて保存する運用があります（`10_documents.md` 10-2-2）。

> **繰り返しますが、本資料はこの併用の是非を述べません。**
> `common/methodology.md` §0 のとおり、本資料は**今の仕事を理解するための資料**です。
> 「紙をやめるべき」「システムを入れるべき」といった記述は、本プロジェクトの範囲外です。

## この章のまとめ（後続ファイルへの引き継ぎ事項）

### 押さえるべき6点

1. **中心はPMS（宿泊管理システム）。** 予約・客室・宿泊者・売上・客室ステータスを一元的に記録する。
   `09_information.md` の情報の名前と、PMSの中の項目が対応している。
2. **サイトコントローラーは「在庫情報を1つに保つ」ためだけの仕組み。**
   同じ在庫を複数の売り場に並べているという宿泊業の商流（`02_industry-structure.md` 11-2）から必然的に生まれた道具。
3. **OTAの管理画面（エクストラネット）は、取引しているOTAの数だけ存在する。**
   掲載内容の管理と、精算明細の取得の場所。
4. **決済端末は「お金を受け取る道具」ではなく「後日お金が入ることを確定させる道具」。**
   カード決済ではチェックアウト時に現金は動かない（B-②）。
5. **鍵は法令が設備面から求めている事項に関わる。**
   `【Fact】` 旅館業法施行規則第4条の3第2号（宿泊者名簿の正確な記載、**客室の鍵の適切な受渡し**、
   宿泊者以外の出入りの状況の確認を可能とする設備）。
6. **中小宿泊業では紙の帳票とシステムが併用されている。**
   電話予約のメモ、紙の予約台帳、手書きの清掃表、申し送りノート、忘れ物管理台帳、手書きの出勤簿。
   **本資料はこれを事実として記述し、評価しない。**

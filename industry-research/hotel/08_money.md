## 8-0 【最初に】宿泊業のカネは「1本の流れ」ではない

### 製造業・卸売業との違い

多くの業界では、カネの流れは1本です。

```
  見積 → 受注 → 納品 → 請求 → 入金
                         （締め日 → 支払期日）
```

宿泊業は違います。**同じ日に、同じ部屋に、同じ料金で泊まった客でも、
カネの入り方が最大6通りに分かれます。**

```
  ① 直販・現地現金      → 宿が受け取る。**即時**
  ② 直販・現地カード    → 決済会社が集金。手数料を引いて後日
  ③ OTA・現地決済      → 宿が受け取る（即時）。**後から手数料が出ていく**
  ④ OTA・事前決済      → OTAが集金。手数料を引いて後日
  ⑤ 旅行代理店         → 代理店が集金。送客手数料を引いて後日
  ⑥ 法人契約（掛売）    → 宿が締めて請求。翌月以降に入金
```

`04_end-to-end-process.md` 4-2 で **B-①〜⑥** として整理した6つです。
**本ファイルはこれを起点に、カネの全体像（入り・出・時間差）を組み立てます。**

### この章で押さえる3つの論点

| 論点 | 内容 | 節 |
|---|---|---|
| **① チャネルによって入金の仕方が違う** | 誰が集金し、いつ入り、いくら引かれるか | 8-1 |
| **② 売上をどうやって確定させるか** | ナイトオーディット（日次の売上確定） | 8-2 |
| **③ 固定費が極めて重い** | 客が来なくても出ていくカネ | 8-5 |

## 8-1 入ってくるカネ — チャネルによって入金の仕方が違う

### 8-1-1 「誰が集金するか」で4つに分かれる

`【Inference】` まず整理すべきは、**客が誰にお金を払うか**です。

```
                 客が払う相手
  ┌──────────────┬──────────────┬──────────────┬──────────────┐
  │  宿に払う     │ 決済会社に払う│  OTAに払う    │ 代理店に払う  │
  │（現金）       │（カード等）   │（事前決済）   │              │
  └──────┬───────┴──────┬───────┴──────┬───────┴──────┬───────┘
         │              │              │              │
    **即時に宿へ**   締め後、後日   OTAの精算日   代理店の精算日
    （手数料なし）  （決済手数料） （販売手数料） （送客手数料）
                                   を引いて後日   を引いて後日

  ※これらとは別に、**法人契約**（客も企業も当日は払わない。宿が後から請求する）がある
```

### 8-1-2 6つのチャネルの詳細（B-①〜⑥）

`04_end-to-end-process.md` 4-2 に各チャネルの詳細表があります。
**ここでは「カネとしてどう見えるか」に絞って整理します。**

#### B-① 直販・現地現金

| 項目 | 内容 |
|---|---|
| 客が払う相手 | **宿** |
| 差し引かれるもの | **なし** |
| 宿に入る時点 | **即時**（チェックアウト時または到着時） |
| その後の事務 | `【Typical】` **日次**でレジを締め、売上金を金庫へ。定期的に銀行へ入金 |
| 経理が見るもの | レジの現金有高、レジ差異、釣銭の残 |

`【Inference】` **最も早く現金になるチャネル**です。
一方で、現金そのものを扱う分の管理業務（釣銭の準備、差異の確認、金庫での保管、銀行への搬送）が
必ず発生します（`05_departments.md` E-⑧-2）。

#### B-② 直販・クレジットカード／コード決済

| 項目 | 内容 |
|---|---|
| 客が払う相手 | **決済会社**（カード会社・決済代行会社） |
| 差し引かれるもの | **決済手数料** `【Varies】` |
| 宿に入る時点 | `【Varies】` **決済会社の締め日の後、後日**（数日〜1か月程度） |
| その後の事務 | 入金額と自社の売上データの突合（消込） |

`【Inference】` **チェックアウト時にお金は動きません。** 動くのは「決済データ」です。
客の側では支払が済んでいますが、宿の口座に入るのは後日です。

#### B-③ OTA経由・現地決済 ★最も分かりにくい形★

| 項目 | 内容 |
|---|---|
| 客が払う相手 | **宿**（フロントで受け取る） |
| その場で差し引かれるもの | **なし**（全額が宿に入る） |
| 宿に入る時点 | **即時** |
| **その後に何が起きるか** | `【Typical】` **OTAが後日、販売手数料を宿に請求する**（または宿がOTAへ支払う） |
| その後の事務 | 手数料の請求内容の確認と支払 |

> **★ここが分かりにくい点です★**
> `【Inference】` このチャネルでは、**お金が一度全額宿に入り、翌月に手数料が出ていきます。**
> 手元の現金だけを見ていると、実際の手取りより多く見えます。
> **「入ってきたお金の一部は、来月出ていく約束が付いている」**という状態です。

#### B-④ OTA経由・事前決済

| 項目 | 内容 |
|---|---|
| 客が払う相手 | **OTA** |
| いつ払うか | `【Varies】` 予約時／宿泊日の一定期間前 |
| 差し引かれるもの | **販売手数料** `【Varies】` |
| 宿に入る時点 | `【Varies】` **OTAの精算サイクルに従って後日** |
| その後の事務 | **OTAの精算明細と自社の売上データの突合** |

`【Inference】` **宿は客から1円も受け取りません。**
だから A-5（決済区分の確定）で「事前決済済み」と記録しておくことが決定的に重要です。
記録が無ければ、フロントが誤って客に請求してしまいます。

#### B-⑤ 旅行代理店経由

| 項目 | 内容 |
|---|---|
| 客が払う相手 | **旅行代理店** |
| いつ払うか | `【Varies】` 申込時／出発前 |
| 差し引かれるもの | **送客手数料** `【Varies】` |
| 宿に入る時点 | `【Varies】` **代理店の精算サイクルに従って後日** |
| その後の事務 | `【Typical】` 宿が代理店へ**宿泊の実績（誰が何泊したか）を報告**し、それに基づいて精算される |

`【Typical】` 団体旅行では、代理店が発行する**クーポン（宿泊券）**を客が持参し、
宿がそれを回収して代理店に請求する形が取られることがあります `【Varies】`。

- **送客手数料**
  → 旅行代理店が客を宿に送ったことに対して、宿が代理店に払う手数料のこと。
  → **なぜ払うのか**：`【Inference】` 代理店は、宿が自力では届かない客
    （店頭に来る客、団体、パッケージ旅行の客）を連れてきています。
    その対価として、売上から一定の割合が引かれます `【Varies】`。

#### B-⑥ 法人契約（掛売）

| 項目 | 内容 |
|---|---|
| 客が払う相手 | **企業**（後日、宿へ） |
| いつ払うか | 締め日ごとに宿が請求 → 支払期日に振込 |
| 差し引かれるもの | なし（`【Varies】` 振込手数料の負担は契約による） |
| 宿に入る時点 | `【Typical】` **締め日の翌月以降** |
| その後の事務 | 請求書発行 → 入金確認 → 消込。未入金があれば督促 |

- **掛売（かけうり）**
  → 代金をその場で受け取らず、後日まとめて請求して受け取る売り方のこと。
  → 実務例：A商事の社員が3月中に18泊利用 → 3月31日に18泊分をまとめて請求 → 4月30日に入金。
  → **なぜするのか**：`【Inference】` 出張のたびに社員が立て替え、
    1泊ごとに請求書を出していては、宿も企業も事務が回らないためです。

- **締め日（しめび）**
  → 一定期間の取引をまとめて集計する区切りの日のこと。
  → 実務例：「月末締め翌月末払い」＝ その月の1日から末日までの利用分を集計し、
    翌月に請求書を出し、翌月末に振り込んでもらう。

- **売掛金（うりかけきん）**
  → 売上は立ったが、まだ入金されていない代金のこと。
  → 実務例：3月に法人が18泊利用し、4月末に入金される場合、
    3月末時点でその代金は**売掛金**として帳簿に残っています。

### 8-1-3 まとめ表：カネの入り方のチャネル差

| チャネル | 客が払う相手 | 差し引かれるもの | 宿に入るタイミング | 経理の事務作業 |
|---|---|---|---|---|
| **B-① 直販・現金** | 宿 | なし | **即時** | レジ締め・銀行入金 |
| **B-② 直販・カード** | 決済会社 | 決済手数料 `【Varies】` | 後日 | 入金消込 |
| **B-③ OTA・現地決済** | 宿 | （後から手数料を支払） | **即時**（手数料は後日出金） | 手数料の確認・支払 |
| **B-④ OTA・事前決済** | OTA | 販売手数料 `【Varies】` | 後日 | **精算明細の突合** |
| **B-⑤ 旅行代理店** | 代理店 | 送客手数料 `【Varies】` | 後日 | 実績報告・請求・突合 |
| **B-⑥ 法人契約** | 企業（後日） | なし | **締め後、翌月以降** | 請求書発行・督促・消込 |

`【Varies】` **手数料率・精算サイクルは事業者と契約により異なるため、本資料では示しません。**

### 8-1-4 この表から読み取ること

`【Inference】`

1. **同じ売上でも、現金化されるまでの日数が最大2か月近く違う。**
2. **チャネルごとに、経理の事務作業の中身が違う。**
   現金はレジ締め、カードは消込、OTAは精算明細の突合、代理店は実績報告、法人は請求と督促。
   **「経理」と一言で言っても、やっていることが5通りあります。**
3. **「どのチャネルで何割売れているか」が、資金繰りの形そのものを決める。**
   この構成比を**チャネルミックス**と呼びます（`12_business-model.md`／`14_kpi.md`）。
4. **表示価格が同じでも、宿の手取りは違う。**
   `02_industry-structure.md` 11-2 の「同じ1泊1万円でも手取りが違う」を参照してください。

## 8-2 ナイトオーディット — 日次の売上確定

### 8-2-1 ナイトオーディットとは

- **ナイトオーディット（Night Audit。夜間監査／日次の売上締め）**
  → 1日の営業が一区切りついた時点で、**その日の売上をすべて締めて確定させる**作業のこと。
    「オーディット（audit）」は監査・照合という意味です。
  → 実務例：夜勤者が、その日のチェックイン・チェックアウト・宿泊料・飲食・売店・
    自動販売機・入湯税等をすべて集計し、現金・カード・請求の内訳と突き合わせ、
    ずれがないことを確認したうえで、その日の帳簿を閉じる。
  → **なぜするのか**：下記 8-2-2。

`【Varies】` 呼び方は施設により「日次締め」「日締め」「レジ締め」等さまざまです。
`【Varies】` 誰が行うか（夜勤者／早番／支配人／経理）も施設により異なります。
`【Example】` Xホテルでは夜勤者が行い、翌朝に支配人が確認します。

### 8-2-2 なぜ毎日締めるのか

`【Inference】` 理由は3つあります。

**理由1：宿泊業は「毎日、商品が入れ替わる」から**

`01_overview.md` 1-1 のとおり、**在庫（客室×日付）は消滅します。**
3月10日の70室という商品は、3月11日には存在しません。
`【Inference】` したがって**「3月10日にいくら売れたか」は、その日のうちに確定させる**必要があります。
後からまとめて計算しようとすると、どの日の売上か分からなくなります。

**理由2：24時間営業なので、「1日」の区切りを人が決めなければならない**

`【Inference】` 店舗であれば閉店時刻が1日の区切りです。
しかし宿泊施設は**閉まりません。** 深夜3時にチェックインする客もいます。
`【Varies】` **どの時刻を「1日の区切り」とするかは施設が決めており、施設により異なります。**
ナイトオーディットは、この**区切りを実際に入れる作業**です。

**理由3：在館中の客の利用が積み上がり続けるから**

`04_end-to-end-process.md` A-8 のとおり、滞在中の客は飲食・売店・
コインランドリー・駐車場などを利用し、**その分が明細に積み上がっていきます。**
`【Inference】` 連泊の客は、まだチェックアウトしていないので精算されていません。
それでも「その日までにいくら発生したか」は確定させる必要があります。

### 8-2-3 ナイトオーディットで何をするか

`05_departments.md` E-⑧-1 に詳細があります。要点を示します。

| すること | なぜか |
|---|---|
| **その日の宿泊料を確定する** | `【Inference】` 何室・何人が実際に泊まったかを確定する |
| **滞在中の客の利用分を加算する** | 連泊客はまだ精算していないため |
| **現金・カード・請求の内訳に分ける** | `【Inference】` **B-①〜⑥のどれに当たるかで、その後の処理が全部違う** |
| **レジの現金有高と突き合わせる** | `【Inference】` 差異があればその日のうちに原因を探す |
| **入湯税・宿泊税がある場合、その分を分けて集計する** | `【Inference】` **これは売上ではないため**（8-4） |
| **その日の稼働（OCC・ADR・RevPAR）を出す** | `【Inference】` 翌日以降の価格判断（A-1）の材料になる |
| **日報を作る** | 支配人・社長・翌日の担当者が読む |

### 8-2-4 ナイトオーディットの出口

```
  ナイトオーディット（日次）
        │
        ├──▶ ① 予約・販売管理 ：その日の OCC・ADR・RevPAR → 翌日以降の価格判断（A-1）
        ├──▶ ⑧ 経理・財務     ：売上データ → 月次の請求・消込・試算表
        ├──▶ ② フロント       ：翌日の担当者への申し送り
        └──▶ 支配人・社長      ：日報
```

`【Inference】` **ナイトオーディットは経理のためだけの作業ではありません。**
そこで出た数字が、**翌日の価格をいくらにするかの材料**になっています。

## 8-3 キャンセル料・ノーショーの扱い

### 8-3-1 何が起きているのか

`04_end-to-end-process.md` 4-3 ③④ のとおりです。**カネの側から見直します。**

- **キャンセル料**
  → 予約が取り消されたときに、あらかじめ定めた基準に従って収受する金額のこと。
  → **なぜ収受するのか**：`【Inference】` 部屋は売れ残ると消えます（`01_overview.md` 1-1）。
    直前のキャンセルは**再販売する時間がない**ため、
    その分の損失を誰が負担するかをあらかじめ決めておく必要があります。
  → **注意**：`【Inference】` **キャンセル料は「罰金」ではありません。**
    再販売の機会を失った分の損失を、あらかじめ決めた基準で分担する仕組みです。
    だから**宿泊日に近いほど料率が上がる**という形になります。

- **ノーショー（No Show）**
  → 予約があるのに、連絡なく来ないこと。
  → **なぜキャンセルより重いのか**：`【Inference】` キャンセルの連絡があれば他の客に売り直せますが、
    ノーショーは**当日その時刻まで部屋を押さえ続けた末に売れない**ため、
    再販売の機会が完全に失われます。
  → `【Typical】` 実務上、ノーショーの場合も**宿泊料相当額を請求する**旨を
    あらかじめ定めておくのが一般的です `【Varies】`。

`【Varies】` **キャンセル料の料率・無料期限は、施設・プラン・チャネルによって異なります。**
本資料では特定の料率を示しません。

### 8-3-2 カネとしてどう扱われるか

`【Inference】` キャンセル料は**宿泊のサービスを提供していないのに受け取る金額**です。
したがって、通常の宿泊売上とは性質が違います。

| 論点 | 内容 |
|---|---|
| **誰から取るか** | 直販なら**客から直接**。OTA経由なら `【Varies】` **OTAの仕組みに従う**（宿が独自に請求できるとは限らない） |
| **いつ取るか** | `【Varies】` キャンセル時／当日／後日請求 |
| **どうやって取るか** | `【Varies】` 事前決済済みであれば返金額から控除、カード情報を預かっていればその決済、法人なら請求に加算 |
| **消費税の扱い** | `【Varies】` **キャンセル料の性質（損害賠償金か、役務の対価か）によって取扱いが異なりうる**ため、本資料では断定しません。実務では顧問税理士に確認します |

> **OTA経由のキャンセルについて**
> `【Varies】` OTA経由の予約では、**キャンセルポリシーはプランごとにOTA上で設定されている**ことが一般的で、
> キャンセル料の徴収方法もOTAの仕組みに従います。
> `【Inference】` つまり**「宿が決めたキャンセル料を、宿が客から取る」とは限りません。**
> 同じ宿の同じ部屋でも、チャネルによってキャンセル時のカネの動きが違います。

### 8-3-3 業態によって「失うもの」が違う

`【Inference】` `01_overview.md` 1-5 および `02_industry-structure.md` 11-4 のとおりです。

| | Xホテル（素泊まり・朝食のみ） | Y旅館（1泊2食付き） |
|---|---|---|
| 直前キャンセルで失うもの | **部屋の売上** | **部屋の売上 ＋ すでに仕入れた食材の代金** |
| キャンセル料の設定 | `【Varies】` | `【Inference】` **早い段階から発生する設定になりやすい** |
| 団体の扱い | `【Varies】` | `【Typical】` **人数が多く代わりの客を見つけにくいため、個人とは別の規定を設けるのが一般的** `【Varies】` |

## 8-4 入湯税・宿泊税 — 預かって納めるカネ

### 8-4-1 なぜ節を分けるのか

`【Inference】` **この2つは宿の売上ではありません。**
客から預かって、そのまま自治体に渡すだけのお金です。
売上と混ぜると、売上が過大に見え、納めるべき税を使ってしまうことになります。

> **初心者が最も間違えやすい点です。**
> 「宿泊料 10,000円 ＋ 入湯税 150円 ＝ 10,150円」を受け取ったとき、
> **宿の売上は 10,000円であり、150円は預かり金です。**

### 8-4-2 入湯税（地方税法に定めのある税）

> `common/methodology.md` の鉄則に従い、**条文の語をそのまま引用します。**

`【Fact】` **地方税法第701条**
> 「**鉱泉浴場所在の市町村**は、環境衛生施設、鉱泉源の保護管理施設及び消防施設その他消防活動に必要な施設の
> 整備並びに観光の振興（観光施設の整備を含む。）に要する費用に充てるため、
> **鉱泉浴場における入湯に対し、入湯客に入湯税を課するものとする。**」

`【Fact】` **地方税法第701条の2**
> 「入湯税の税率は、**入湯客一人一日について、百五十円を標準とするものとする。**」

`【Fact】` **地方税法第701条の3**
> 「入湯税の徴収については、**特別徴収の方法によらなければならない。**」

`【Fact】` **地方税法第701条の4第1項**
> 「入湯税を特別徴収によつて徴収しようとする場合においては、
> **浴場の経営者その他徴収の便宜を有する者を当該市町村の条例によつて特別徴収義務者として指定し、
> これに徴収させなければならない。**」

`【Fact】` **地方税法第701条の4第2項**
> 「前項の特別徴収義務者は、**当該市町村の条例で定める納期限までに**その徴収すべき入湯税に係る
> 課税標準額、税額その他条例で定める事項を記載した**納入申告書を市町村に提出し、
> 及びその納入金を当該市町村に納入する義務を負う。**」

**用語の説明**

- **特別徴収（とくべつちょうしゅう）**
  → `【Fact】` 地方税法第1条第1項第9号に定義された方式で、
    税金の徴収に便宜を有する者に代わりに徴収させ、納入させる方式のこと。
  → 実務例：温泉旅館が、宿泊料とは別に入湯税を客から受け取り、条例で定める納期限までに市町村へ納める。
  → **なぜこうするのか**：`【Inference】` 市町村が入湯客一人ひとりから直接徴収するのは
    現実的でないため、現場で接している宿が代わりに預かる仕組みになっています。

- **標準税率**
  → `【Fact】` 地方税法第1条第1項第5号に定義された語で、
    地方団体が課税する場合に**通常よるべき税率**をいいます。
  → `【Varies】` したがって、**市町村の条例で異なる額を定めることもできます。**

> **★納期限は条例で定まります★**
> `【Fact】` 第701条の4第2項は「**当該市町村の条例で定める納期限までに**」と書いています。
> `【Varies】` **したがって、納期限を「月次」と一律に書くことはできません。**
> 実際の納期限は、その市町村の条例を確認する必要があります。

### 8-4-3 宿泊税（法定外目的税）

`【Fact】` **地方税法第731条第1項**
> 「道府県又は市町村は、**条例で定める特定の費用に充てるため**、
> **法定外目的税を課することができる。**」

`【Fact】` **地方税法第731条第2項**
> 「道府県又は市町村は、法定外目的税の**新設又は変更**をしようとする場合においては、
> **あらかじめ、総務大臣に協議し、その同意を得なければならない。**」

> **★宿泊税は地方税法に個別の定めがある税ではありません★**
> `【Fact】` 入湯税は地方税法第701条以下に直接規定がありますが、
> **宿泊税は法定外目的税として、各地方団体が条例で定めるものです。**
> `【Varies】` **したがって、課税の有無・課税対象・税率・免税点・納期限は、地方団体ごとに条例で異なります。**
> **本資料では特定の自治体の税率・納期限を示しません。**
> **一律に「月次で納める」と書くこともできません（納期限は条例による `【Varies】`）。**

### 8-4-4 カネの流れとして見ると

```
  【客】チェックアウト時に、宿泊料とは別に入湯税（または宿泊税）を払う
      │
      ▼
  【宿】② フロントが受け取る
      │  （ナイトオーディットで**売上とは分けて集計する**）
      ▼
  【宿】⑧ 経理・財務が**預り金**として管理する
      │
      │ **条例で定める納期限までに**
      │ 納入申告書を提出し、納入金を納入する  ← 地方税法第701条の4第2項（入湯税）
      ▼
  【市町村】
```

`【Inference】` **宿から見ると、これは「入って、出ていくだけ」のお金です。**
利益にも損失にもなりません。しかし、**預かっている間は宿の口座にある**ため、
資金繰り上は一時的に手元にあるように見えます。**使ってはいけないお金です。**

### 8-4-5 消費税との違い

`【Inference】` 初心者が混同しやすいので整理します。

| | **消費税** | **入湯税** | **宿泊税** |
|---|---|---|---|
| 根拠 | 消費税法 | **地方税法第701条以下**（個別の定めあり） | **地方税法第731条**（法定外目的税。**条例で定める**） |
| 納税者は誰か | `【Inference】` 制度上の納税義務者は事業者 | `【Fact】` **入湯客**（第701条） | `【Varies】` 条例による |
| 宿の立場 | 納税義務者 | `【Fact】` **特別徴収義務者**（第701条の4第1項） | `【Varies】` 条例による |
| 税率 | 消費税法による | `【Fact】` **1人1日150円を標準**（第701条の2）。`【Varies】` 条例で異なる額も可 | `【Varies】` 条例による |
| 全国一律か | — | `【Fact】` **鉱泉浴場所在の市町村**が課す | `【Varies】` **導入している自治体としていない自治体がある** |
| 宿の売上に入るか | — | **入らない**（預り金） | **入らない**（預り金） |

## 8-5 出ていくカネ — 固定費が極めて重い

### 8-5-1 まず全体像

`02_industry-structure.md` ★③ に固定費・変動費の区分があります。**カネがいつ出るかを加えて整理します。**

#### 客が来ても来なくても出ていくカネ（固定費）

| 費目 | いつ出るか | 内容 |
|---|---|---|
| **建物の減価償却費** | `【Inference】` **現金は出ない**（過去に払った建設費を期間配分する会計上の費用） | 自社所有の場合 |
| **賃料** `【Varies】` | **月次** | 賃借の場合 |
| **借入金の元本返済と利息** | **月次** `【Varies】` | `【Inference】` **元本返済は費用ではないが、現金は出ていく** |
| **固定資産税** | **法定・契約上のタイミング** | 土地・建物 |
| **正社員の人件費** | **月次** | フロント正社員・支配人など |
| **フロントを開けておくための人件費** | **月次** | `【Inference】` 24時間または長時間、必ず人がいる |
| **保守点検費** | **法定・契約上のタイミング**／**月次** `【Varies】` | 消防設備・エレベーター・ボイラー・空調 |
| **共用部の光熱費** | **月次** | 廊下・ロビー・大浴場の湯を張る費用 |
| **保険料** | **年次** `【Varies】` | 火災保険・施設賠償責任保険など `【Varies】` |
| **PMS等のシステム利用料** | **月次** `【Varies】` | `11_systems.md` 参照 |

#### 客数・客室数に連動して出ていくカネ（変動費）

| 費目 | いつ出るか | 何に連動するか |
|---|---|---|
| **客室清掃費**（外部委託の場合） | **月次** `【Varies】` | **清掃した室数** |
| **リネンの洗濯代** | **月次** `【Varies】` | **枚数** |
| **アメニティ・消耗品** | **月次** `【Varies】` | **販売室数・人数** |
| **客室の水道光熱費** | **月次** | 使った分 |
| **食材費** `【Varies】` | **月次** `【Varies】` | **人数**（`07_goods.md` 7-4） |
| **OTA・代理店への手数料** | **月次** `【Varies】` | **売上に対する率** `【Varies】` |
| **決済手数料** | `【Varies】` 入金時に控除 | **カード等の決済額** |

### 8-5-2 なぜ「固定費が重い」ことが宿泊業の輪郭を決めるのか

`【Inference】` 2つの帰結があります。

**帰結1：1室多く売ったときの追加費用が、売価に比べて小さい**

```
  1室追加で売ったときに増える費用
    ＝ 清掃費（1室分）＋ リネン（1室分）＋ アメニティ（1室分）＋ 客室の水道光熱費
      （食事があれば ＋ 食材費）
  一方で、建物・借入・正社員・フロントの人件費・共用部の光熱費は**1円も増えません**
```

`【Inference】` だから**「空室にするくらいなら安くても売る」という力が働きます。**
これが `02_industry-structure.md` ★① の「在庫が消滅する → だから価格を動かす」と合わさって、
**レベニューマネジメント**という仕事を生んでいます。

**帰結2：稼働が落ちても費用はあまり減らない**

`【Inference】` 建物を止めることも、フロントを閉めることも簡単ではありません。
`【Example】` Xホテルは年中無休・24時間フロントです。客が1人でも、フロントには人がいます。

> **この構造から「損益分岐点稼働率」という考え方が出てきます。**
> **詳細は `12_business-model.md` で扱います。**

> **本資料はこの構造を説明するだけで、「だからどうすべきか」は書きません**
> （`common/methodology.md` §0）。

### 8-5-3 出ていくカネの締めと支払

`【Typical】` 仕入先・委託先への支払は、**締めて、まとめて払う**のが一般的です `【Varies】`。

| 支払先 | 何に対して | 締めと支払 `【Varies】` |
|---|---|---|
| 清掃業者（C清掃） | 清掃した室数 | `【Typical】` **月次**で締めて請求を受け、支払 |
| リネンサプライ（Dリネン） | 洗濯した枚数 `【Varies】` | `【Typical】` **月次** |
| 食材卸・酒類卸 | 納品した食材 | `【Typical】` **月次** |
| アメニティ業者 | 納品した数量 | `【Typical】` **月次** |
| 設備メンテナンス業者 | 点検・修理 | **法定・契約上のタイミング**／案件発生時 |
| OTA | 販売手数料 | `【Varies】` **月次**。`【Inference】` 入金から控除される場合と、請求を受けて支払う場合がある |
| 従業者 | 給与 | **月次** |
| 税務署 | **源泉所得税** | `【Fact】` 下記 |

`【Fact】` **所得税法第183条第1項**
> 「居住者に対し国内において第二十八条第一項（給与所得）に規定する給与等（…）の支払をする者は、
> その支払の際、その給与等について所得税を徴収し、
> **その徴収の日の属する月の翌月十日までに、これを国に納付しなければならない。**」

`【Inference】` 給与から天引きした所得税は、**宿のお金ではありません。**
従業者から預かって国に納めるものであり、**入湯税・宿泊税と同じ「預かって納める」構造**です。

## 8-6 時間差 — カネが出るのが先、入るのが後

### 8-6-1 なぜ時間差が生まれるのか

`【Inference】` 宿泊業では、**サービスを提供した日と、現金が入る日がずれます。**
一方で、**そのサービスを提供するための費用は、提供の前後に出ていきます。**

```
  【出ていくカネ】
    建物・設備の投資 ──────────────────▶ 何年も前に出ている（借入の返済が続く）
    正社員の給与・光熱費 ──────────────▶ 毎月出ている
    食材の仕入 ───────────────────────▶ 宿泊の**前日**に出ている（発注済み）
    清掃費・リネン代 ─────────────────▶ 宿泊の**翌月**に出る

  【入ってくるカネ】
    直販現金 ─────────────────────────▶ 宿泊日に入る
    カード ───────────────────────────▶ 後日
    OTA事前決済 ──────────────────────▶ OTAの精算日（後日）
    代理店 ───────────────────────────▶ 代理店の精算日（後日）
    法人契約 ─────────────────────────▶ 締めて請求し、翌月以降
```

### 8-6-2 売上 ≠ 入金

> **初心者が最もつまずく点です。**

`【Typical】` A-9（チェックアウト・精算）で**売上は確定します**が、
**現金が宿に入るとは限りません。**

| 決済区分 | A-9 時点で現金は入るか |
|---|---|
| 直販・現金 | **入る**（即時） |
| 直販・クレジットカード | **入らない**。決済会社の締め後、後日入金 |
| OTA・現地決済 | **入る**（全額）。ただし**後日、手数料が出ていく** |
| OTA・事前決済 | **入らない**。OTAが集金済み。精算日に手数料を引かれて入金 |
| 旅行代理店経由 | **入らない**。代理店の精算日に手数料を引かれて入金 |
| 法人契約（掛売） | **入らない**。締めて請求し、翌月以降に入金 |

### 8-6-3 【Example】時間差を数えてみる

> `【Example】`（説明用の架空例。`04_end-to-end-process.md` 4-4 ケース1と同じ場面）
> A商事のSさんが3月10日にXホテルに1泊。法人契約（月末締め翌月末払い）。

| 日付 | 何が起きたか | 現金の動き |
|---|---|---|
| 3月9日 | 翌日の朝食用の食材を発注・納品 | `【Inference】` 3月分の仕入として**翌月に支払** |
| **3月10日** | **Sさんが宿泊** | **なし** |
| 3月11日 | Sさんがチェックアウト。**売上が確定** | **なし**（A商事へ請求するため） |
| 3月11日 | C清掃が406号室を清掃 | `【Inference】` 3月分の清掃費として**翌月に支払** |
| 3月25日 `【Varies】` | 従業者へ3月分の給与を支払 | **出る** |
| 3月31日 | 3月分のA商事の利用（18泊）を集計。**請求書を送付** | **なし**。売掛金として計上 |
| 4月10日 | 3月に支払った給与の源泉所得税を納付 | `【Fact】` **出る**（所得税法第183条第1項：徴収の日の属する月の翌月10日まで） |
| 4月 `【Varies】` | C清掃・Dリネン・食材卸へ3月分を支払 | **出る** |
| **4月30日** | **A商事から振込入金。請求額と照合し、消込** | **入る** |

`【Inference】` **Sさんが泊まったのは3月10日。宿にお金が入ったのは4月30日。約50日の差があります。**
**その間、Xホテルは C清掃・Dリネン・食材卸・従業者に支払いを続けています。**
**支払いのほうが先に出ていきます。**

### 8-6-4 この時間差を経理はどう管理するか

`05_departments.md` E-⑧-9（資金繰りの管理）に詳細があります。要点のみ。

| 見るもの | 何のためか |
|---|---|
| **売掛金の残高と回収予定** | `【Inference】` いつ・いくら入ってくるか |
| **買掛金・未払金の残高と支払予定** | `【Inference】` いつ・いくら出ていくか |
| **預金残高の見通し** | `【Inference】` 支払日に残高が足りるか |
| **借入金の返済予定** | `【Inference】` 費用ではないが、現金は出ていく |
| **預り金（入湯税・宿泊税・源泉所得税・社会保険料）** | `【Inference】` **手元にあるが宿のお金ではない** |

## 8-7 【Example】1予約のカネの動きを時系列で（直販とOTAの対比）

> `【Example】` **以下はすべて説明用の架空の例です。**
> 金額・日付・手数料は説明のための仮置きであり、実在の取引でも業界の代表値でもありません。
> `【Varies】` **手数料率は示しません。** 「手数料が引かれる」という構造だけを示します。

### 前提

- Xホテル、3月10日（火）、シングル1泊、表示価格 **10,000円**（税・サービス料込み）
- 同じ部屋・同じ日・同じ価格で、2人の客が泊まった
  - **Pさん**：自社サイトから予約し、**現地でクレジットカード決済**（B-②）
  - **Qさん**：Bトラベル（OTA）で予約し、**事前決済**（B-④）

### ケースA：直販・現地カード決済（Pさん／B-②）

| 日付 | 誰が | カネの動き | 宿の帳簿では |
|---|---|---|---|
| 2月20日 | Pさん | 自社サイトで予約。**この時点では支払わない** | **何も起きない**（予約は売上ではない） |
| 3月10日 | Pさん | チェックイン。支払はまだ | 何も起きない |
| **3月11日** | Pさん → 宿 | チェックアウト。**カードで10,000円を決済** | **売上 10,000円が確定**（A-9） |
| 3月11日 未明〜 | ② フロント／⑧ 経理 | **ナイトオーディット**で3月10日分の売上を締める | 売上が日次で確定 |
| `【Varies】` 3月末 | 決済会社 | 3月分の決済を締める | — |
| `【Varies】` 4月 | 決済会社 → 宿 | **決済手数料を差し引いた金額**を宿の口座へ振込 | **入金**。売上と照合して**消込** |

```
  客が払った日：3月11日
  宿に入った日：4月（決済会社の締め後）`【Varies】`
  手取り：10,000円 − 決済手数料 `【Varies】`
```

### ケースB：OTA・事前決済（Qさん／B-④）

| 日付 | 誰が | カネの動き | 宿の帳簿では |
|---|---|---|---|
| **1月15日** | Qさん → **Bトラベル** | OTAのサイトで予約し、**その場でカード決済（10,000円）** | **何も起きない**（宿には1円も入らない） |
| 1月15日 | Bトラベル → 宿 | 予約情報がPMSへ自動連携。**決済区分は「Bトラベル事前決済済み」** | 予約記録（売上ではない） |
| 3月10日 | Qさん | チェックイン。**支払いは受け取らない** | 何も起きない |
| **3月11日** | Qさん | チェックアウト。**この日も1円も受け取らない** | **売上 10,000円が確定**（A-9） |
| 3月11日 未明〜 | ② フロント／⑧ 経理 | **ナイトオーディット**で3月10日分の売上を締める。**現金・カードの受領はゼロ**と記録 | 売上が日次で確定 |
| `【Varies】` 4月 | Bトラベル → 宿 | 3月分の宿泊料から**販売手数料を差し引いた金額**を振込 | **入金**。**OTAの精算明細と自社の売上データを突合**して消込 |

```
  客が払った日：**1月15日**（宿泊の約2か月前）
  宿に入った日：4月（OTAの精算日）`【Varies】`
  手取り：10,000円 − 販売手数料 `【Varies】`
```

### 2つを並べる

| | **ケースA（直販・現地カード）** | **ケースB（OTA・事前決済）** |
|---|---|---|
| 客が払った相手 | **宿**（カード経由） | **Bトラベル（OTA）** |
| 客が払った日 | 3月11日 | **1月15日** |
| **フロントでの受領** | **カード決済（10,000円）** | **なし** |
| 売上が確定した日 | **3月11日（A-9）** | **3月11日（A-9）** ← **同じ** |
| 宿に現金が入った日 | 4月（決済会社の締め後）`【Varies】` | 4月（OTAの精算日）`【Varies】` |
| 差し引かれるもの | **決済手数料** `【Varies】` | **販売手数料** `【Varies】` |
| 経理の作業 | 入金額と売上の突合（消込） | **OTAの精算明細と自社の売上データの突合** |
| 客の情報を誰が持つか | **宿** | `【Varies】` **OTA**（宿へ渡る範囲は契約による） |

### 読み取ること

`【Inference】`

1. **表示価格が同じ10,000円でも、宿の手取りは違います。**
   引かれるものが「決済手数料」か「販売手数料」かで異なります `【Varies】`。
2. **売上が確定した日（3月11日）は同じです。**
   売上の計上は、**カネがどう動いたかではなく、サービスを提供したかどうか**で決まります。
3. **客が払った日は、1月15日と3月11日で2か月近く違います。**
   しかし**宿の帳簿では、どちらも3月の売上**です。
4. **ケースBでは、宿は一度も客からお金を受け取っていません。**
   だから A-5（決済区分の確定）が決定的に重要です。記録が無ければ二重請求になります。
5. **経理の作業が違います。** 消込か、精算明細の突合か。
   `【Inference】` **チャネルが増えるほど、経理の作業の種類が増えます。**

### もし直販・現地現金だったら（B-①との対比）

| | 直販・現金（B-①） | 直販・カード（B-②） | OTA事前決済（B-④） |
|---|---|---|---|
| 宿に現金が入る日 | **3月11日（即時）** | 4月 `【Varies】` | 4月 `【Varies】` |
| 差し引かれるもの | **なし** | 決済手数料 `【Varies】` | 販売手数料 `【Varies】` |
| 宿の事務 | レジ締め・銀行入金 | 消込 | 精算明細の突合 |

`【Inference】` **同じ部屋・同じ日・同じ価格でも、3通りのカネの動き方があります。**
どれが多いかで、宿の資金繰りの形が変わります。

## この章のまとめ（後続ファイルへの引き継ぎ事項）

### 押さえるべき8点

1. **チャネルによって、誰が集金し・いつ入り・いくら引かれるかがすべて違う**（B-①〜⑥）。
   同じ売上でも、現金化まで最大2か月近い差がある。
2. **OTA・現地決済（B-③）は、一度全額が宿に入り、後から手数料が出ていく。**
   手元の現金だけを見ると、実際の手取りより多く見える。
3. **ナイトオーディットは、24時間営業の施設に「1日の区切り」を入れる作業。**
   その日の売上を確定し、現金・カード・請求の内訳に分け、入湯税等を分け、
   OCC・ADR・RevPAR を出す。**出口は経理だけでなく、翌日の価格判断にも向かう。**
4. **キャンセル料は罰金ではなく、再販売の機会を失った分の損失を分担する仕組み。**
   だから宿泊日に近いほど料率が上がる `【Varies】`。
   **OTA経由では、キャンセル料の徴収方法もOTAの仕組みに従う** `【Varies】`。
5. **入湯税・宿泊税は宿の売上ではない。** 客から預かって自治体に納めるお金。
   入湯税は地方税法第701条以下（1人1日150円を標準・特別徴収）、
   **納入は「当該市町村の条例で定める納期限までに」**（第701条の4第2項）。
   宿泊税は**法定外目的税**（第731条第1項）であり、
   **課税の有無・対象・税率・納期限はすべて条例による** `【Varies】`。
   **一律に「月次」と書いてはいけない。**
6. **源泉所得税も預かって納めるお金。**
   `【Fact】` 所得税法第183条第1項：**徴収の日の属する月の翌月10日まで**に国に納付。
7. **固定費が極めて重い。** 客が来なくても、建物・借入・正社員・フロントの人件費・
   共用部の光熱費は出ていく。だから**1室多く売ったときの追加費用が売価に比べて小さく、
   稼働が落ちても費用が減りにくい**。
8. **カネは出るのが先、入るのが後。** 食材は宿泊の前日、清掃費・リネン代は翌月、
   入金は最大2か月後。**この間の資金を持ちこたえることが資金繰り。**

### `【Varies】` として数値を置かなかった論点（後続フェーズで扱う場合は出典を要する）

- OTA・旅行代理店の手数料率、決済手数料率
- 各社の精算サイクル・締め日・支払サイト
- キャンセルポリシーの料率と無料期限、キャンセル料の消費税の取扱い
- 宿泊税の税率・課税対象・納期限（自治体ごとの条例）、入湯税の実際の納期限
- 清掃委託単価、リネンの料金体系
- 賃料・借入条件・保険料

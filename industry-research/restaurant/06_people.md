## 6-0 飲食業の「ヒト」がなぜ独立した章になるのか

飲食業では、ヒトの流れが他の3つの流れ（モノ・カネ・情報）と比べて特別な意味を持ちます。
理由は3つあります。

| # | 理由 | どこに効いてくるか |
|---|---|---|
| 1 | **人手がそのまま提供能力である** | `【Typical】` 注文を受ける人・作る人・運ぶ人が足りなければ、席が空いていても客を入れられません。機械で置き換えて生産量を増やすことができない部分が大きい業種です |
| 2 | **必要な人数が時間帯で激しく変わる** | `【Typical】` ピークタイムに人が集中して必要になり、その前後は余ります（`02_industry-structure.md` 11-6(4)） |
| 3 | **「今日誰がいるか」が毎日変わる** | `【Typical】` パート・アルバイト中心のシフト運営のため、同じ店でも日によって顔ぶれが違います |

`【Fact】` 飲食店（中分類76）の従業者数は3,489,163人（2021年6月1日現在。出典：令和3年経済センサス‐活動調査／総務省・経済産業省）。
`【Fact】` 同調査で、飲食店の個人経営事業所の1か所あたり従業者数は約3.0人、法人の事業所は約13.7人です。

> `【Inference】` つまり飲食業の「ヒト」は、**数人で回している店**から
> **十数人が同時に動いている店**まで幅があり、
> 同じ仕事が「1人の中で完結する」場合と「複数人の間を渡り歩く」場合の両方が存在します。
> 本章では後者（複数人の場合）を基本として書き、
> 前者（1人が兼務する場合）を 6-7 で改めて扱います。

## 6-1 登場人物の一覧（誰がいるのか）

`【Example】` モデル企業「株式会社まるみダイニング」（3店舗・正社員9名・パート・アルバイト38名）を
前提に、登場人物を整理します。

### 社内の登場人物

| 立場 | 人数（モデル企業） | 主に担う機能 | 雇用の性格 |
|---|---|---|---|
| 代表取締役（オーナーシェフ） | 1名 | ①メニュー開発／②仕入・調達／③店舗開発／⑥販促／A店の⑨キッチン | `【Example】` 経営者。労働時間の管理対象ではない |
| 本部スタッフ | 1名 | ④経理・財務／⑤人事・労務 | `【Example】` 正社員（代表の配偶者） |
| 店長 | 3名 | ⑦店長（店舗運営）／⑫清掃・衛生の記録確認 | `【Example】` 正社員。各店1名 |
| 調理社員 | 4名 | ⑧仕込み／⑨キッチン | `【Example】` 正社員 |
| ホール担当 | 24名 | ⑩ホール／⑪レジ・会計 | `【Example】` パート・アルバイト |
| キッチン担当 | 14名 | ⑧仕込みの補助／⑨キッチンの補助／洗い場 | `【Example】` パート・アルバイト |

> `【Typical】` **飲食業では「正社員1人あたりのパート・アルバイト人数」が多くなりがち**です。
> `【Inference】` これは 6-8 で述べる山谷に対応するためで、
> 短時間だけ働く人を組み合わせないとピークに人を揃えられないからです。
> `【Varies】` 比率は業態・営業時間・店舗規模により大きく異なります。

### 社外の登場人物

| 相手 | 誰か | 店の誰とやりとりするか |
|---|---|---|
| 食材卸・酒類卸 | 営業担当者、配送担当者 | `【Typical】` 条件は②仕入・調達機能（代表）、日々の発注と受け取りは⑦店長機能・⑨キッチン機能 |
| 卸売市場の仲卸 | 仲卸業者 | `【Varies】` 店主が直接。早朝に出向く場合がある |
| 不動産オーナー・管理会社 | 貸主、管理担当者 | `【Typical】` ③店舗開発機能（代表）。家賃の支払は④経理・財務機能 |
| 保健所 | 食品衛生監視員 | `【Typical】` 許可申請は③店舗開発機能、監視指導の受け入れは⑦店長機能（＝食品衛生責任者） |
| 消防署 | 予防担当 | `【Typical】` 防火管理者（`【Example】` 各店長）が消防計画の届出・立入検査に対応 |
| 警察署（公安委員会） | 生活安全担当 | `【Fact】` 深夜における酒類提供飲食店営業の届出先（風営法第33条第1項） |
| グルメサイト・予約サイト | 営業担当者 | `【Typical】` 掲載内容は⑥販促機能、予約の受け方は⑩ホール機能 |
| デリバリープラットフォーム | 事業者担当者、配達員 | `【Typical】` 契約は⑥販促機能、日々の受け渡しは⑨キッチン機能・⑩ホール機能 |
| 決済事業者 | 契約担当 | `【Typical】` ④経理・財務機能（入金と手数料の確認） |
| 金融機関 | 融資担当 | `【Typical】` 代表取締役＋④経理・財務機能 |
| 税理士・社会保険労務士 | 顧問 | `【Typical】` ④経理・財務機能／⑤人事・労務機能 |
| 廃棄物収集運搬業者 | 収集担当 | `【Typical】` ⑫清掃・衛生機能 |
| リネン業者（おしぼり・マット） | 配送担当 | `【Typical】` ⑩ホール機能 |
| 厨房機器・設備の業者 | 修理担当 | `【Typical】` ⑦店長機能が呼び、費用の判断は代表取締役 |
| 客 | 一般消費者、法人の幹事 | `【Typical】` ⑩ホール機能・⑪レジ・会計機能。宴会の相談は⑦店長機能 |

## 6-2 社内の関係（1）本部 ↔ 店舗

### なぜ本部と店舗に分かれるのか

`【Typical】` 2店舗以上になると、「会社で1回決めればよいこと」と「店ごとに毎日やること」が分かれます
（`03_company-structure.md` 3-2）。
ヒトの関係で言えば、**代表取締役・本部スタッフと、各店の店長の間に縦の線が1本通る**ことになります。

```
        ┌──────────────────────────┐
        │  代表取締役（オーナーシェフ）  │
        │   ①②③⑥ ＋ A店の厨房       │
        └───────┬──────────┬────────┘
                │          │
      方針・レシピ・売価    │ 相談・承認
      仕入先・人件費枠     │
                │          │
        ┌───────┴──────┐   │
        │ 本部スタッフ1名  │   │
        │  ④経理 ⑤人事    │   │
        └───────┬──────┘   │
                │日報・勤怠・請求書
                ↓          ↓
   ┌────────┬────────┬────────┐
   │ A店 店長 │ B店 店長 │ C店 店長 │  ← ⑦店長機能
   └────────┴────────┴────────┘
```

### 本部と店舗の間で何が往復するか

`【Typical】` 受け渡される具体的な中身は `03_company-structure.md` 3-7 と
`05_departments.md` PART 3（3-2「本部 ↔ 店舗の連携」）に一覧があります。
ここでは**ヒトの関係として何が起きているか**を書きます。

| 方向 | 起きていること | なぜそうなるか |
|---|---|---|
| 本部 → 店舗 | **決めたことを伝える**（メニュー・売価・仕入先・単価・販促・人件費の枠・衛生管理の様式） | `【Typical】` 3店舗で同じメニューを出すなら、原価計算も売価決定も1回で足ります。店ごとに決めると同じ食材を違う値段で買うことになります |
| 店舗 → 本部 | **起きたことを報告する**（日報・売上データ・納品書・在庫・勤怠・廃棄・クレーム・設備不具合） | `【Inference】` 本部は店に常駐していないため、報告がなければ何も分かりません。日報と勤怠が遅れると、経理と給与計算が止まります |
| 店舗 → 本部（相談） | **判断を仰ぐ**（高額な修理、大口予約の受諾、重大なクレーム、値引きの例外） | `【Typical】` 金額が大きい判断・会社の看板に関わる判断は、店長の権限を超えます |

> `【Example】`（説明用の架空例）B店の製氷機が故障した場面。
> 店長は修理業者を呼ぶところまでは自分で決めますが、
> 「修理では直らないので買い替えが必要、金額は◯十万円」となった時点で代表取締役に上げます。
> **どこまでが店長の判断で、どこから上に上げるかの線引きが、本部↔店舗の関係の実体**です。
> `【Varies】` この線引き（決裁の範囲）は企業により異なります。

### 中小飲食企業では本部が「人」であって「部」ではない

`【Typical】` 中小飲食企業では、本部機能が独立した部署として存在するとは限りません。
`【Example】` モデル企業の本部は**代表取締役1名＋本部スタッフ1名の計2名**です。
`【Inference】` したがって店長から見た「本部」は、組織ではなく**特定の2人**です。
連絡手段も電話・メッセージアプリが中心になります（`【Typical】`）。

## 6-3 社内の関係（2）店長 ↔ 社員 ↔ アルバイト

### 3層の関係

```
   ⑦店長（正社員）
    ・その日の営業を成立させる責任を持つ
    ・発注を確定する／仕込み量を指示する／シフトを組む
    ・クレームの一次対応をする／レジを締める／日報を書く
        │
        ├─── 調理社員（正社員）
        │      ・⑧仕込み ⑨キッチンの中心
        │      ・レシピどおりの品質を出す
        │      ・キッチン担当に作業を割り振る
        │
        └─── パート・アルバイト（ホール／キッチン）
               ・⑩ホール ⑪レジ・会計 ⑧⑨の補助 ⑫清掃
               ・「その時間に、決められた作業をする」
```

### それぞれの関係で何が渡されるか

| 関係 | 渡されるもの | 頻度 |
|---|---|---|
| 店長 → 調理社員 | 当日の予約情報、仕込み量の指示、品切れ・数量限定の判断 | `日次` |
| 調理社員 → 店長 | 食材の残量、仕込みの進み具合、設備の不具合、廃棄の内容 | `日次`／`常時`（営業中） |
| 店長 → アルバイト | シフト、当日の重点（おすすめ・品切れ・予約）、作業の割り振り | `日次`（開店前の情報共有）／`週次`または`月次`（シフト） |
| アルバイト → 店長 | 出退勤の記録、客からの申し出、欠勤・遅刻の連絡、備品の不足 | `常時`／`トラブル発生時` |
| 調理社員 → キッチン担当 | 仕込みの手順、切り方・分量の指示 | `日次` |

> **なぜ開店前に情報共有をするのか**
> `【Inference】` ホールが品切れを知らずに注文を受けてしまうと、
> 客に謝って注文を取り直すことになります（`04_end-to-end-process.md` A-4）。
> **「今日は何が出せて、何が出せないのか」を営業前に全員の頭に入れておく**ことが、
> 営業中の手戻りを減らす唯一の手段です。
> 中小飲食企業では、これが朝礼・朝の声かけという形で行われます（`【Typical】`）。

### アルバイトの「習熟の差」が関係の形を決める

`【Typical】` パート・アルバイトは入退社が相対的に多く、同じ「ホール担当」でも
入って1週間の人と3年目の人が同じシフトに入ります。
`【Inference】` そのため、店長と調理社員は**その日いる人の習熟度に合わせて作業を割り振る**必要があります。

> `【Example】`（説明用の架空例）夜のピークに、ホールに3名入る日。
> 3年目の人に注文取りと会計を任せ、2か月目の人に配膳と下げ膳を任せ、
> 初日の人には水とおしぼりの提供とテーブル拭きだけを任せる、という割り振りになります。
> **同じ3名でも、誰が入るかで店の処理能力が変わります。**

`【Typical】` これを踏まえて、教育（誰が何をできるようになったか）の把握が⑤人事・労務機能と
⑦店長機能の仕事になります（`05_departments.md` ⑤ E-8、⑦ E-13）。

## 6-4 社内の関係（3）キッチン ↔ ホール

飲食業でもっとも密度の高いヒトの関係が、**キッチン（⑨）とホール（⑩）の間**です。
詳細な連携は `05_departments.md` PART 3（3-6）で扱っているため、ここでは関係の構造だけを示します。

### 関係の構造

```
  客 ──注文──→ ⑩ホール ──オーダーを「通す」──→ ⑨キッチン
                  ↑                                  │
                  └────── 完成の知らせ ─────────────┘
                              （デシャップ）
```

`【Typical】` 両者の間では、**一方向の依頼**と**逆方向の知らせ**が営業中ずっと往復します。

| 方向 | 何が渡るか | 渡らないと何が起きるか |
|---|---|---|
| ホール → キッチン | オーダー（注文伝票）／アレルギー等の特記事項／提供タイミングの希望／追加オーダー／「止め」の解除待ち | `【Inference】` 通し忘れ＝料理が作られず客が待ち続ける。二重通し＝作りすぎて廃棄になる |
| キッチン → ホール | 完成した料理／品切れ・数量限定の連絡／提供が遅れる旨／「止め」（一時的に注文を受けられない状態） | `【Inference】` 品切れが伝わらなければホールが注文を取ってしまう。遅延が伝わらなければ客への説明ができない |

> **用語：デシャップ**
> → キッチンとホールの受け渡し場所（カウンター・棚）のこと。
>   料理が置かれ、ホールがそれを取って運びます。「ディッシュアップ」に由来する呼び方です。
> → 実務例：「デシャップに3番テーブルの唐揚げが出ている」＝運ぶべき料理がそこにある状態。
> → **なぜ場所を決めるのか：** 完成した料理をどこに置くか決まっていないと、
>   **誰も気づかないまま料理が冷め、どのテーブルのものか分からなくなります。**
>   場所を固定し、テーブル番号を声で言い合うことで、渡し間違いと放置を防ぎます。

> **用語：止め（とめ）**
> → キッチンが一時的に注文を受けられない状態にすること。
> → 実務例：注文が一気に集中したとき、「揚げ物、5分止めます」とホールに伝える。
> → **なぜ必要か：** 受け続けると提供時間が延び、先に注文した客の料理も遅れます。
>   `【Inference】` 止めることは「売上を捨てる」判断ですが、
>   **止めないことで全テーブルの提供が遅れる**ほうが影響が大きい場面があります。
>   この判断は⑨キッチン機能が行い、⑦店長機能が全体を見て調整します。

### この関係が崩れると何が起きるか

`【Inference】` キッチンとホールの関係が崩れたときの影響は、次の順で連鎖します。

```
オーダーが正しく伝わらない
  → 違う料理が作られる（食材のロス）
  → 作り直しで時間がかかる（客を待たせる）
  → 客の不満（クレーム／口コミ）
  → 席が空かない（回転数が落ちる）
  → その日の売上が落ちる
```

`【Typical】` とくに**アレルギーの申し出の伝達**は、この連鎖とは別に扱われます。
`【Inference】` これは接客の丁寧さの問題ではなく、**客の生命に関わる情報伝達**です
（`03_company-structure.md` 3-4⑩）。
ホールは申し出を必ず厨房に伝え、厨房は使用食材と調理器具の使い回しを確認します。

## 6-5 簡易RACI ── 「誰が決めるのか」を整理する道具

### RACI とは何か（初心者向け）

**RACI（レイシー）**
→ 1つの仕事について、**関わる人の役割を4種類に分けて表にする整理の方法**です。
　英語の頭文字をとった呼び方です。

| 記号 | 英語 | 本資料での言い方 | 意味 |
|---|---|---|---|
| **R** | Responsible | **実行** | 実際に手を動かして作業する人 |
| **A** | Accountable | **承認（決定）** | 「それでよい」と決める人。**1つの仕事に1人**が原則 |
| **C** | Consulted | **相談** | 決める前に意見を聞かれる人 |
| **I** | Informed | **報告** | 決まった後に知らされる人 |

→ 実務例：「今日の発注」という仕事では、
　**実行＝店長**（発注書を作って卸に伝える）、
　**承認＝店長**（数量を決めるのも店長）、
　**相談＝調理社員**（在庫と使う量を聞く）、
　**報告＝本部の経理**（後で納品書が回ってくる）。

> **なぜこの整理をするのか**
> `【Inference】` 中小企業では役職と仕事が1対1で対応していないため、
> 「この仕事は誰の仕事か」が曖昧になりがちです。
> とくに**承認（A）が誰なのかが決まっていないと、判断が止まるか、
> 逆に複数の人が別々に決めてしまいます。**
> `【Typical】` 飲食業では判断の多くが「その場で」「その日のうちに」必要になるため、
> 誰が決めるのかがはっきりしていることの重要性が高くなります。

`【Varies】` **以下の表は、モデル企業（3店舗・正社員9名）を前提とした整理です。**
実際の分担は企業により大きく異なります。
とくに1店舗の個人経営店では 6-6 のとおり、ほぼすべてがオーナーシェフに集約されます。

---

### 主要な意思決定は誰が決めるのか（簡易RACI）

`【Example】` モデル企業の設定に基づく整理です。

#### (1) メニューと売価

| | 担当 | 内容 |
|---|---|---|
| **実行（R）** | 代表取締役（①メニュー開発機能） | 企画・試作・レシピ化・原価計算 |
| **承認（A）** | **代表取締役** | `【Example】` 何を出すか、いくらで売るかを最終決定 |
| **相談（C）** | 店長・調理社員 | 試作への参加、作れるかどうかの確認、客の反応 |
| **報告（I）** | 全店舗・④経理・財務機能 | レシピと売価の周知、POSへの商品登録 |
| 頻度 | `四半期`または`半期`（季節の入替）／`案件発生時` | |

> **なぜ売価を店が決めないのか**
> `【Inference】` 3店舗で同じメニューを違う値段で売ると、客から見て説明がつきません。
> また、原価計算は食材の単価に基づくため、会社で1回やれば足ります
> （`05_departments.md` ① E-4・E-5）。

#### (2) 仕入先の選定

| | 担当 | 内容 |
|---|---|---|
| **実行（R）** | 代表取締役（②仕入・調達機能） | 候補の探索、見積の取得、条件交渉 |
| **承認（A）** | **代表取締役** | `【Example】` どこから買うか、いくらで買うか、支払条件を決定 |
| **相談（C）** | 店長・調理社員 | 品質の評価、配送時間の都合 |
| **報告（I）** | 全店舗・④経理・財務機能 | 単価表の配布、買掛金の管理対象として登録 |
| 頻度 | `年次`または`案件発生時`（条件見直し）／`トラブル発生時`（欠品・相場変動） | |

#### (3) 発注量（日々の数量）

| | 担当 | 内容 |
|---|---|---|
| **実行（R）** | **店長**（⑦店長機能） | 品目ごとに数量を決め、仕入先へ伝える（A-1） |
| **承認（A）** | **店長** | `【Example】` 数量の決定は店長の権限内 |
| **相談（C）** | 調理社員（在庫と使用量）／⑩ホール機能（予約状況） | |
| **報告（I）** | 仕入先（社外）／④経理・財務機能（納品書経由） | |
| 頻度 | `日次`（生鮮）／`週次`（乾物・調味料・消耗品 `【Varies】`）／`発注時` | |

> **なぜ発注は店が決めるのか**
> `【Typical】` 在庫も客数の見込みも店ごとに違うため、本部では決められません。
> `【Typical】` モデル企業では**「取引先と単価は本部、日々の数量は店舗」**という分担です
> （`03_company-structure.md` 3-3②）。
> `【Varies】` 本部で一括発注する企業もあります。

#### (4) 仕込み量

| | 担当 | 内容 |
|---|---|---|
| **実行（R）** | 調理社員（⑧仕込み機能） | 仕込み作業そのもの（A-3） |
| **承認（A）** | **店長または調理責任者** | `【Example】` 何をどれだけ仕込むかの決定 |
| **相談（C）** | ⑩ホール機能（当日の予約・客の動き） | |
| **報告（I）** | ⑨キッチン機能（営業中に使う側） | |
| 頻度 | `日次`（品目により`週次` `【Varies】`） | |

> **この判断がなぜ難しいのか**
> `【Inference】` 多く仕込めば廃棄（ロス）になり、少なく仕込めば品切れで売る機会を失います。
> しかも判断材料が不確実です（天気は変わる、予約はキャンセルされる、団体が飛び込みで来る）。
> `【Typical】` 実務では、前週の同曜日の実績、当日の予約件数、天気予報を見比べて決めます
> （`03_company-structure.md` 3-4⑧、`05_departments.md` ⑧ E-1）。

#### (5) 値引き・廃棄の判断

| | 担当 | 内容 |
|---|---|---|
| **実行（R）** | ⑩ホール機能・⑨キッチン機能 | 値引きの適用、廃棄と記録（A-L） |
| **承認（A）** | **店長** | `【Example】` その場の値引き・サービス・廃棄の可否を決定 |
| **相談（C）** | 調理社員（まだ使えるかの判断） | |
| **報告（I）** | ④経理・財務機能（日報経由。原価率の分析に使う） | |
| 頻度 | `日次`／`トラブル発生時` | |

> **なぜ「誰が決めるか」を決めておく必要があるのか**
> `【Inference】` 値引きも廃棄も、**その分だけ利益が減る判断**です。
> 誰でも自由にできる状態にすると、月末に原価率が上がった理由が分からなくなります。
> `【Typical】` 一方で、客の前で即断しなければならない場面（提供が遅れた、料理を落とした）もあるため、
> 「いくらまでは担当者の判断でよいか」という線が引かれることになります（`【Varies】`）。

#### (6) シフト

| | 担当 | 内容 |
|---|---|---|
| **実行（R）** | **店長**（⑦店長機能） | 希望の収集、シフト表の作成、当日の欠員対応 |
| **承認（A）** | **店長**（人件費の枠の中で） | `【Example】` 誰をいつ入れるかの決定 |
| **相談（C）** | ⑤人事・労務機能（人件費の枠、法定の制約）／本人（希望） | |
| **報告（I）** | 本人・⑤人事・労務機能（勤怠として集計される） | |
| 頻度 | `週次`または`月次`（作成 `【Varies】`）／`トラブル発生時`（当日の欠員） | |

`【Fact】` シフトを組む際には労働基準法の制約がかかります。
`【Fact】` 使用者は、労働者に、休憩時間を除き1週間について40時間を超えて労働させてはならず、
1週間の各日については、休憩時間を除き1日について8時間を超えて労働させてはなりません
（労働基準法第32条）。
`【Fact】` 使用者は、労働時間が6時間を超える場合においては少なくとも45分、
8時間を超える場合においては少なくとも1時間の休憩時間を労働時間の途中に与えなければなりません（同法第34条第1項）。
`【Fact】` 使用者は、労働者に対して、毎週少なくとも1回の休日を与えなければなりません（同法第35条第1項）。
`【Fact】` 使用者が、午後10時から午前5時まで（厚生労働大臣が必要であると認める場合においては、
その定める地域又は期間については午後11時から午前6時まで）の間において労働させた場合においては、
その時間の労働については、通常の労働時間の賃金の計算額の2割5分以上の率で計算した割増賃金を
支払わなければなりません（同法第37条第4項）。

> `【Inference】` 夜遅くまで営業する業態では、この割増がシフトの組み方と人件費に影響します。
> `【Example】` モデル企業のB店は翌1:00まで営業するため、深夜の時間帯に働く人が生じます。

#### (7) 採用

| | 担当 | 内容 |
|---|---|---|
| **実行（R）** | ⑤人事・労務機能（求人掲載・書類管理）＋店長（面接） | |
| **承認（A）** | **店長**（パート・アルバイト）／**代表取締役**（正社員） | `【Example】` 雇うかどうかの決定 |
| **相談（C）** | ⑤人事・労務機能（人件費の枠、労働条件） | |
| **報告（I）** | ⑤人事・労務機能（雇用契約・社会保険の手続へ） | |
| 頻度 | `案件発生時` | |

`【Fact】` 使用者は、労働契約の締結に際し、労働者に対して賃金、労働時間その他の労働条件を
明示しなければなりません。この場合において、賃金及び労働時間に関する事項その他の厚生労働省令で
定める事項については、厚生労働省令で定める方法により明示しなければなりません（労働基準法第15条第1項）。

> `【Inference】` つまり「来週から来て」という口頭のやりとりだけでは足りず、
> 明示が必要な事項が法律上定められています。
> 具体的な様式・実務は `05_departments.md` ⑤ E-3 を参照してください。

#### (8) クレームの最終対応

| | 担当 | 内容 |
|---|---|---|
| **実行（R）** | ⑩ホール機能（一次対応） | 事情を聞く、事実を確認する |
| **承認（A）** | **店長**（通常のクレーム）／**代表取締役**（重大な場合） | `【Example】` 返金・作り直し・謝罪の範囲を決定 |
| **相談（C）** | ⑨キッチン機能（原因の確認）／本部 | |
| **報告（I）** | 本部（記録）／①メニュー開発機能・⑫清掃・衛生機能（再発防止の情報） | |
| 頻度 | `トラブル発生時`／`問い合わせ時` | |

> **健康被害の訴えは別扱いになります**
> `【Typical】` 店長の判断で終わらせない、という扱いになります。
> `【Fact】` 保健所長は、食中毒患者等が発生したときは、中毒の原因となった食品等および
> 病因物質を追及するために必要な疫学的調査等を行います（食品衛生法第63条第2項、同法施行令第36条）。
> `【Fact】` また、都道府県知事は、営業者が同法の一定の規定に違反した場合においては、
> 第55条第1項の許可を取り消し、または営業の全部もしくは一部を禁止し、
> もしくは期間を定めて停止することができます（食品衛生法第60条第1項）。
> `【Inference】` したがって健康被害の訴えは、店の中で処理する「クレーム」ではなく、
> **事業の継続に直結する事象**として代表取締役まで上がります
> （`04_end-to-end-process.md` A-C）。

## 6-6 中小飲食業の実態 ── オーナーシェフが全部決める

### 1店舗の個人経営店では、RACI の列が1本になる

`【Fact】` 2021年6月1日現在、飲食店（中分類76）の民営事業所499,176のうち、
**個人経営は311,574事業所（62.4％）**、個人経営の事業所1か所あたりの従業者数は約3.0人です
（出典：令和3年経済センサス‐活動調査／総務省・経済産業省）。
`【Fact】` 同調査で、全産業（民営）の事業所のうち個人経営は31.8％です。

`【Inference】` つまり飲食業では、**「会社ではなく個人が営んでいる店」が多数**です。
この場合、6-5 の表は次のようになります。

| 意思決定 | オーナーシェフ | 家族 | アルバイト |
|---|---|---|---|
| メニューと売価 | **A**／R | — | — |
| 仕入先の選定 | **A**／R | — | — |
| 発注量 | **A**／R | — | — |
| 仕込み量 | **A**／R | R（補助） | R（補助） |
| 値引き・廃棄 | **A**／R | — | I |
| シフト | **A**／R | C | C（希望） |
| 採用 | **A**／R | C | — |
| クレームの最終対応 | **A**／R | — | R（一次対応） |

> `【Typical】` これは「機能が存在しない」のではなく、
> **機能はすべて存在するが、担当者が1人しかいない**状態です
> （`03_company-structure.md` 3-6）。
> 発注もするし、給与も計算するし、衛生記録もつけます。

### この状態で何が起きているか（価値判断ではなく構造の説明）

`【Inference】` 承認する人と実行する人が同一であることから、構造上、次のことが言えます。

| 構造 | どうなるか |
|---|---|
| **判断の伝達が要らない** | 「相談して、決めて、伝える」という工程がない。決めた瞬間に実行される |
| **判断が1人の手の空き具合に依存する** | `【Typical】` 調理中・接客中は、発注や経理の判断ができない。営業時間の外にそれらを行うことになる |
| **文書化の必要性が低い** | `【Typical】` レシピも手順も「自分の頭の中」で足りる。文書化が必要になるのは、人を増やすとき・店を増やすとき |
| **不在時に決まらない** | `【Inference】` オーナーが休むと、承認が必要な事柄が止まる |

`【Typical】` そして**店舗数が増えると、この形は維持できなくなります。**
`【Inference】` 2店舗目ができた時点で、オーナーは同時に2か所にいられません。
そこで「店長」という役割が生まれ、6-5 の二層構造（会社の決定と店の決定）に移ります。
`【Typical】` このとき初めて、レシピの文書化・売価の統一・シフトの枠・報告の様式が必要になります
（`01_overview.md` 1-6 軸A）。

> **大手外食チェーンとの違い（混同しないこと）**
> `【Varies】` 大手外食チェーンでは、本部に専門部署（商品部・人事部・店舗開発部等）が置かれ、
> セントラルキッチンで複数店舗分の仕込みをまとめて行う形が採られることがあります。
> **これは大手の姿であって、中小飲食企業一般の姿ではありません**
> （`01_overview.md` 1-6）。
> 本資料が想定するのは、代表取締役＋本部スタッフ数名という規模の本部です。

## 6-7 アルバイト中心のシフト運営 ── 「今日誰がいるか」が毎日変わる

### 構造

`【Example】` モデル企業のA店は、正社員3名（店長1＋調理社員2）とパート・アルバイト16名で
運営されています。ある日の営業に入るのは、そのうちの一部です。

```
【A店の登録メンバー】             【ある平日の夜営業に入る人】
  店長           1名      →       店長           1名
  調理社員       2名      →       調理社員       1名（もう1名は休み）
  ホール担当    10名      →       ホール担当     3名
  キッチン担当   6名      →       キッチン担当   2名
  ───────────────                ───────────────
  合計          19名               合計           7名
```

`【Typical】` 翌日は別の3名がホールに入ります。**同じ店でも、日によって顔ぶれが違います。**

### なぜこの形になるのか

`【Inference】` 理由は 6-8 の山谷です。
ピークの2〜3時間だけ人を多く必要とするため、
**1日8時間働く人だけで組むと、ピーク以外の時間に人が余ります。**
`【Typical】` そこで、**1日のうち数時間だけ働く人を組み合わせる**ことになります。
`【Varies】` 具体的な時間帯の区切り方は、業態・営業時間・店舗規模により大きく異なるため、
本資料では時刻を示しません。

### この形から生じる実務

| 起きること | 誰が対応するか | 頻度 |
|---|---|---|
| **希望シフトを集めて表を作る** | ⑦店長機能（枠は⑤人事・労務機能） | `週次`または`月次`（`【Varies】`） |
| **当日の欠員に対応する**（体調不良・学校の都合など） | ⑦店長機能 | `トラブル発生時` |
| **入ったばかりの人に作業を教える** | ⑦店長機能・調理社員・先輩の担当者 | `常時` |
| **その日いる人の習熟度に合わせて作業を割り振る** | ⑦店長機能・調理社員 | `日次` |
| **勤怠を集計して給与を計算する** | ⑤人事・労務機能 | `月次` |

> **当日の欠員がなぜ重い問題になるのか**
> `【Inference】` 製造業なら、今日作れなかった分を明日作れます。
> 飲食業では、**その日の営業はその日しかありません。**
> 人が1人足りない状態でピークを迎えると、提供が遅れ、席の回転が落ち、
> その日の売上がそのまま減ります。取り戻す機会がありません。
> `【Typical】` だから店長は、他のメンバーに連絡する／自分が現場に入る／
> 出せるメニューを絞る、といった対応をその場で判断します。

> `【Example】`（説明用の架空例）夜営業の1時間前に、ホール担当1名から欠勤の連絡が入った場面。
> 店長の選択肢は概ね次のとおりです。
> 1. 休みの人に連絡して入ってもらう
> 2. 店長自身がホールに入り、締め作業を閉店後に回す
> 3. 予約以外の席を一部使わない（受け入れ客数を減らす）
> 4. 調理社員をホールに回し、メニューの一部を数量限定にする
>
> **どれを選んでも何かを諦めることになります。** この判断が店長機能の中身です。

### 法令上の制約（シフトを組むときに必ず関わるもの）

`【Fact】` 賃金については、最低賃金法第4条第1項により、
**使用者は、最低賃金の適用を受ける労働者に対し、その最低賃金額以上の賃金を支払わなければなりません。**
`【Fact】` 労働時間・休憩・休日・深夜割増については、労働基準法第32条・第34条第1項・第35条第1項・
第37条第4項の定めがあります（条文は 6-5(6) に掲げたとおり）。
`【Fact】` また、使用者は、その雇入れの日から起算して6箇月間継続勤務し全労働日の8割以上出勤した労働者に対して、
継続し、または分割した10労働日の有給休暇を与えなければなりません（労働基準法第39条第1項）。
`【Fact】` 同条第3項により、1週間の所定労働日数が通常の労働者に比し相当程度少ない労働者等については、
有給休暇の日数は厚生労働省令で定める日数とされます。

> `【Inference】` **パート・アルバイトにも年次有給休暇の制度が適用されます。**
> 所定労働日数が少ない人については日数が別に定められる、という構造です。
> 具体的な日数の計算と手続は `05_departments.md` ⑤ を参照してください。

## 6-8 ピークタイムに人が集中して必要になる（山谷）

### 山谷の形

`【Typical】` 飲食業の忙しさは営業時間の中で均一ではありません
（`02_industry-structure.md` 11-6(4)）。
**必要な人数を縦軸、工程の順序を横軸にとると、山のような形になります。**

```
必要な
人数
 ▲
 │                    ┌───┐
 │                    │   │          ← ピーク（最大人数が必要）
 │              ┌─────┘   └─────┐
 │        ┌─────┘               └─────┐
 │  ┌─────┘                           └─────┐
 └──┴───────────────────────────────────────┴──▶ 工程の順序
   開店前   開店直後   ピーク   ピーク後   L.O.後   閉店後
  （仕込み） （ゆるやか）        （客が引く）（会計・片付け）（締め・清掃）
```

`【Fact】` 本資料では時刻表を作りません（`04_end-to-end-process.md`）。
開店時刻・ピーク時刻は業態と店舗により大きく異なります（`【Varies】`）。

### 山谷が生む二律背反

`【Inference】` 山谷があることから、次の2つが同時に成り立ちません。

| 選択 | 起きること |
|---|---|
| ピークに合わせて人を揃える | 暇な時間に人が余る（働く時間に対して仕事がない状態が生じる） |
| 暇な時間に合わせて人を揃える | ピークに回らない（客を待たせ、席の回転が落ちる） |

`【Typical】` そこで実務では、**短時間で働く人を重ねて、山の形に人数を合わせる**組み方になります。

```
【1人が通しで入る場合】        【短時間の人を重ねる場合】
  ■■■■■■■■  （8時間）         ■■■■■■■■     店長（通し）
  ■■■■■■■■  （8時間）         ■■■■■■■■     調理社員（通し）
                                   ■■■■         ホール（ピーク前後）
  → ピークで人手不足、               ■■■■■■       ホール（ピーク中心）
    暇な時間に余る                     ■■■■       キッチン（ピーク中心）
                                 → 山の形に人数が沿う
```

### 山谷が他の流れに与える影響

| 影響先 | 何が起きるか | 参照 |
|---|---|---|
| **カネ** | `【Typical】` 人件費（L）は、ピークに何人置くかで決まる。売上に対する人件費率に直結する | `08_money.md` `12_business-model.md` `14_kpi.md` |
| **モノ** | `【Inference】` ピークに調理が集中するため、仕込みを厚くしておかないと提供が間に合わない | `07_goods.md` |
| **情報** | `【Inference】` ピーク中はオーダー情報が一気に増える。伝達の誤りが起きやすい時間帯になる | `09_information.md` |
| **KPI** | `【Typical】` 「人時売上高」（働いた1時間あたりの売上）は、この山谷に人をどれだけ合わせられたかを見る数字 | `14_kpi.md` |

## 6-9 【Example】1日の営業で人がどう動くか（追跡）

> ### ⚠ 以下はすべて説明用の架空例です
> `【Example】` モデル企業「株式会社まるみダイニング」A店（本店・40席。昼：定食／夜：居酒屋）の
> ある1日を、**人の動き**に絞って追跡します。
> `03_company-structure.md` のモデル企業設定に基づく架空例であり、実在の店舗ではありません。
> `【Fact】` 時刻は示しません。**工程の順序**として読んでください
> （`04_end-to-end-process.md` の表記方針に従います）。
> 同じ1日を「工程」の側から追ったものが `04_end-to-end-process.md` 4-5 にあります。
> ここでは**誰が誰とやりとりしているか**を見てください。

### 登場する人（この日のメンバー）

| 記号 | 立場 | この日の役割 |
|---|---|---|
| **Sさん** | A店 店長（正社員・食品衛生責任者・防火管理者） | 店の全体を見る。発注・締め・日報 |
| **Kさん** | 調理社員（正社員） | 仕込みとキッチンの中心 |
| **Tさん** | キッチン担当（アルバイト・3年目） | 仕込みの補助、洗い場、揚げ場 |
| **Hさん** | ホール担当（アルバイト・2年目） | 注文取り・配膳・会計 |
| **Nさん** | ホール担当（アルバイト・2か月目） | 配膳・下げ膳・テーブルセット |
| **Yさん** | ホール担当（アルバイト・夜のみ） | 夜のピークに合わせて入る |
| （本部）**代表** | 代表取締役（オーナーシェフ） | この日はB店の厨房に入る予定 |
| （本部）**Mさん** | 本部スタッフ（経理・労務） | 店には来ない。日報と請求書を扱う |

---

### 【開店前】

**■ Sさん（店長）が最初に出勤する**

Sさんはまず**前日に発注した食材の受け取り**に立ちます（A-2 納品・検品）。

- 青果卸の**配送担当者**が到着。Sさんが納品書を受け取り、段ボールを開けて確認
- トマトに1つ傷みがあり、**その場で配送担当者に伝えて1個分を差し引いてもらう**
- レタスが1ケース不足。配送担当者から「市場の入荷が悪く、翌朝に追加分を届ける」と連絡を受ける

> `【Inference】` **ここが社外の人との最初の接点**です。
> 配送担当者は複数店を回るため、その場を離れると確認ができません
> （`04_end-to-end-process.md` A-2）。だから受け取りのときに必ず人が立ち会います。

続いて精肉卸の配送担当者が到着。Sさんは冷蔵で届いた鶏もも肉の**温度を確認**し、
衛生管理の記録用紙に記入してから冷蔵庫へ収納します。

**■ Kさん（調理社員）と Tさん（キッチン担当）が仕込みに入る**

SさんがKさんに当日の情報を渡します。

> Sさん「今夜は12名の予約が1件、4名の予約が2件。レタスが1ケース入らなかった」
> Kさん「じゃあサラダはキャベツに替えます。牛すじは前日の残りが3人前だから、15人前追加で仕込みます」

`→ ここで「仕込み量の承認（A）」が行われています（6-5(4)）。`
`　実行するのはKさんとTさんですが、量と内容を決める場面にSさんが関与しています。`

Kさんは、Tさんに作業を割り振ります。

> Kさん「Tさん、キャベツを千切りにしておいて。それが終わったら鶏の下処理、
> 　　　僕は牛すじを煮始めます」

`→ 調理社員が、その日いる人の習熟度に合わせて作業を割り振っています（6-3）。`
`　Tさんは3年目なので、手順の説明なしで任せられます。`

**■ Hさん・Nさん（ホール担当）が開店準備に入る**

- Nさん（2か月目）が客席とトイレの清掃を仕上げ、テーブルに箸と調味料をセット
- Hさん（2年目）がレジに釣銭準備金をセットし、POSと決済端末の動作を確認
- 12名の予約に合わせ、2人でテーブル3卓をつなげて席を作る

**■ 全員での情報共有（A-4）**

Sさんが全員に伝えます。

> 「今日のサラダはキャベツに変更。牛すじは在庫が多いのでおすすめして。
> 　夜の早い時間に12名、その後に4名ずつ予約が2件」

`→ この1回の共有が、営業中の手戻りを防ぎます（6-3）。`
`　ホールが品切れや変更を知らずに注文を取ると、客に謝って取り直すことになります。`

---

### 【営業中・昼】

**■ 客と Hさん の接点（A-5 → A-6）**

2名の客が来店。Hさんが2人掛けテーブルへ案内します。
（4人掛けに通すと、後から来る4名客を断ることになるため）

客が「日替わり定食2つ」と注文。Hさんが**復唱**し、さらに尋ねます。

> Hさん「日替わり定食お2つですね。本日の日替わりは鶏の唐揚げです。
> 　　　——アレルギーなど、召し上がれないものはございますか？」
> 客「卵がだめです」

Hさんはハンディ端末に「日替わり×2／うち1つ **卵除去**」と入力。
厨房のプリンタから伝票が出ます。

`→ ここで ⑩ホール から ⑨キッチン へ情報が渡っています（6-4）。`
`　アレルギーの申し出は、Hさんの丁寧さの問題ではなく、必ず伝える情報です。`

**■ Kさん（キッチン）の判断（A-7）**

Kさんが伝票を見て、「卵除去」の表示を確認します。
その1つだけ小鉢のだし巻き玉子を煮物に差し替えると判断。
同時に入っている他のテーブルの注文と合わせ、**調理時間の長い唐揚げから先に揚げ始めます。**

`→ 揚げ場はTさんが担当しているため、KさんはTさんに「唐揚げ3つ、先に入れて」と声をかけます。`

**■ 提供と会計（A-8 → A-9）**

Nさん（2か月目）が料理を運びます。
卵除去のほうを該当する客の前に置くよう、Hさんが口頭で確認しながら渡します。

> Hさん「Nさん、こっちが卵除去。窓側の右の方に」

`→ 習熟の浅い担当者に運ばせる場合、先輩が「どちらを誰に」を明示します。`
`　ここを省くと、アレルギー対応品が別の客に渡る可能性が生じます。`

食事が終わり、客が会計へ。Hさんが伝票を確認し、コード決済で処理してレシートを渡します。

**■ 片付け（A-10）**

外で待っている客がいるため、NさんとHさんが手分けして食器を下げ、
テーブルを拭き、箸と調味料をセットし直します。

`→ この作業の速さが、そのまま次の客の来店（＝売上）になります。`

---

### 【営業中・夜 ＝ ピーク】

**■ 人が増える**

昼のピークが過ぎ、Nさんが上がります（退勤）。
夕方から**Yさん（夜のみのホール担当）**が入り、Hさんと2人体制になります。
キッチンはKさんとTさんのまま。Sさんは全体を見ながら、必要に応じてどちらにも入ります。

`→ これが 6-8 の山谷への対応です。同じ店の同じ日でも、時間帯で人の構成が変わります。`

**■ 予約客12名の来店（A-P → A-5）**

Sさんが予約台帳で名前と人数を確認し、準備した席へ案内します。
コース料理の予約のため、Kさんは既に人数分の準備を進めています。

> `【Inference】` 予約がなければ、この12名分の食材は用意されていません。
> **予約は、来る人数・食べるもの・時間が確定している唯一の情報**です
> （`04_end-to-end-process.md` A-P）。

**■ ピークで起きること**

同時に複数のテーブルから注文が入り、キッチンに伝票がたまります。
Kさんが判断します。

> Kさん「Sさん、揚げ物5分止めます」
> Sさん「了解。Hさん、Yさん、揚げ物のオーダーは5分待って。
> 　　　先に刺身と冷菜をすすめて」

`→ 「止め」というキッチン側の判断が、店長を通じてホール全員に伝わっています（6-4）。`
`　止めないことを選ぶと、全テーブルの提供が遅れます。`

**■ 追加オーダー（A-6 に戻る）**

コースの途中で「生ビールを5杯追加」の注文。Yさんがハンディ端末に入力します。

`→ 追加オーダーは客単価を押し上げる要素です（01_overview.md 1-5）。`
`　これを取りに行くかどうかは、ホールがテーブルを見ているかで決まります。`

**■ クレームが1件発生（A-C）**

別のテーブルから「注文した料理が来ていない」という申し出。
Hさんが一次対応し、伝票を確認すると、**通し忘れ**が見つかります。

> Hさん「大変申し訳ございません。すぐにお作りします」
> → Sさんに報告 → Sさんがキッチンに優先で作るよう依頼
> → Sさんが「ドリンク1杯をサービスにする」と判断

`→ 値引き・サービスの承認（A）は店長（6-5(5)）。`
`　Hさんの判断で勝手にサービスにはしません。`
`　健康被害の訴えではないため、代表取締役には上げず、日報に記載して共有します。`

**■ ラストオーダー（A-8.5）**

HさんとYさんが全テーブルを回り、最後の注文を尋ねます。
受け終わったら、Kさんに「ラストオーダー終了」を伝えます。
Kさんは残りを作り終えたら、片付けと翌日の仕込みの準備に移れます。

---

### 【閉店後】

**■ 人が減っていく**

- Yさんが上がる（退勤）
- Tさんが洗い場を仕上げて上がる
- Hさんがテーブルセットを戻して上がる
- **残るのは Sさん と Kさん**

`→ 閉店後は少人数になります。締め・清掃・記録は、この2人の仕事になります（6-8 の山谷の右端）。`

**■ 締め作業（A-11）**

Sさんがレジを締めます。POSの現金売上とレジの現金が合わず、
レシートと伝票を確認して、**夜の団体客が現金で払った分を別の保管袋に入れたまま**だったことを見つけます。
合算して照合が取れ、記録に経緯を残します。

`→ Sさん1人で完結する仕事ですが、内容は Mさん（本部スタッフ）へ渡ります。`

**■ 清掃・衛生記録（A-12）**

Kさんが厨房を洗浄し、冷蔵庫・冷凍庫の温度を測って記録用紙に記入。
Sさんが記録を確認します。

`【Fact】` Sさんは食品衛生責任者として、衛生管理の措置の遵守のために必要な注意を行うとともに、
営業者に対し必要な意見を述べるよう努めることとされています
（食品衛生法施行規則別表第17第1号ホ）。
`【Fact】` 営業者は食品衛生責任者の意見を尊重しなければなりません（同ニ）。

`→ つまり Sさん が「この記録では足りない」と判断したとき、`
`　それを代表取締役（営業者）に伝える立場にあることが、制度として定められています。`

**■ 日報（A-13）**

Sさんが日報を作成し、本部の Mさん へ送ります。
売上・客数・客単価・現金過不足・廃棄の内容・特記事項（レタス未着、通し忘れの1件）を記載。

`→ ここで初めて、店の1日が本部の人の手に渡ります。`
`　Mさん はこの日報を使って、月次の店別損益と仕入計上・支払（B系列）を進めます。`

---

### この1日で、人は何回「社外」と接したか

| 場面 | 相手 | 店の担当 |
|---|---|---|
| 納品・検品 | 青果卸の配送担当者 | Sさん（店長） |
| 納品・検品 | 精肉卸の配送担当者 | Sさん（店長） |
| 欠品の連絡 | 青果卸の配送担当者 | Sさん（店長） |
| 来店・注文・会計 | 客（昼：2名） | Hさん・Nさん |
| 予約の来店 | 客（夜：12名の幹事） | Sさん・Hさん・Yさん |
| クレームの申し出 | 客（夜） | Hさん → Sさん |
| 決済 | 決済事業者（端末経由） | Hさん・Yさん |
| 日報の送付 | （社内）本部 | Sさん → Mさん |

> `【Inference】` **飲食業のヒトの流れの特徴は、「社外との接点が現場の担当者にある」ことです。**
> 卸との窓口は店長、客との窓口はアルバイトのホール担当。
> 営業部門が社外を担当し、現場は社内だけを見る、という形にはなりません。
> だから飲食業では、**現場の一人ひとりの対応が、そのまま会社の対外的な顔になります。**

# 14_kpi.md — 飲食業のKPI・数字

> このファイルは、飲食店の現場と本部で実際に見られている数字を整理したものです。
> 各指標について「**名称／意味／計算方法／誰が見るか／なぜ重要か**」を示します。
> `common/methodology.md` §3 に従い、**数値目安は出典があるもののみ記載し、
> 根拠のないものは `【Varies】` として質的に記述します。**
> 指標の背後にある収益構造は `12_business-model.md`、
> 数字の元になる情報は `09_information.md`、帳票は `10_documents.md` を参照してください。
> 出典の詳細は `19_sources.md` を参照してください。

---

## 14-0 この章の読み方

### ★ 数値目安を書かない理由

> `【Varies】` **本資料では、原価率・FL比率・人件費率・回転率などの「目安」を示しません。**
> 理由は次のとおりです。
>
> 1. `【Fact】` 業態別の水準を示す公的統計が、本資料の調査範囲では確認できていません
>    （`19_sources.md` §D-4）。
> 2. `【Typical】` 業態・立地・価格帯・提供形態によって前提がまったく異なります。
>    居酒屋とカフェ、立ち食いそばと高級すしでは、同じ指標でも意味が変わります。
> 3. `【Inference】` 根拠のない目安を示すと、
>    **それが「正しい水準」であるかのように読まれてしまいます。**
>
> **一般に語られる目安の数値を見かけた場合は、
> 「どの業態の、いつの、誰が出した数字か」を確認してください。**

### 指標の4つのグループ

```
【売上をつくる数字】     売上高／客数／客単価／回転率／席稼働率／
                        ドリンク比率／予約件数／リピート率

【コストを見る数字】     原価率（F）／人件費率（L）／FL比率／FLR比率／ロス率

【効率を見る数字】       人時売上高／坪売上

【利益の構造を見る数字】 限界利益率／損益分岐点売上高
```

### どの数字を、どの頻度で見るか

| 頻度 | 誰が | 主に見る数字 | どこから取るか |
|---|---|---|---|
| `日次` | ⑦店長機能 | 売上高／客数・組数／客単価／現金過不足／廃棄の内容／予約件数 | POSのレジ精算票、日報 |
| `週次` | ⑦店長機能 | 曜日別の売上・客数／シフトに対する人件費 | 日報の集計 |
| `月次` | ④経理・財務機能・代表取締役 | **原価率／人件費率／FL比率／FLR比率**／店別損益／ロス率 | 棚卸＋会計ソフト |
| `月次`〜`年次` | 代表取締役 | 坪売上／限界利益率／損益分岐点売上高 | 店別損益 |

> `【Inference】` **日次で見える数字と、月次でしか出ない数字があります。**
> 売上・客数・客単価はPOSからその日のうちに出ますが、
> **原価率は棚卸をしないと出ません**（`12_business-model.md` 12-4）。
> この差が、飲食業の数字の見方の基本にあります。

# グループ1：売上をつくる数字

---

## 14-1 売上高

| 項目 | 内容 |
|---|---|
| **名称** | 売上高（うりあげだか） |
| **意味** | その期間に、提供した料理・飲み物の代金として確定した金額の合計 |
| **計算方法** | `売上高 ＝ 席数 × 回転数 × 客単価`（店内飲食）<br>`＋ テイクアウト ＋ デリバリー ＋ 法人向け（仕出し・宴会・貸切）` |
| **誰が見るか** | ⑦店長機能（`日次`）／④経理・財務機能（`月次`）／代表取締役 |
| **どこから取るか** | POSのレジ精算票／日報／会計ソフト |
| **なぜ重要か** | `【Typical】` すべての比率（原価率・人件費率・FL比率）の**分母**になります。売上が分からなければ、費用が多いか少ないかも判断できません |

### 売上高を分けて見る

`【Typical】` 売上高は、次のように分解して見られます。

| 分け方 | 何が分かるか |
|---|---|
| **昼／夜** | `【Inference】` 同じ店でも客単価・原価率・人件費の構造が違います（`12_business-model.md` 12-11(3)） |
| **フード／ドリンク** | `【Inference】` 原価率の水準が違うため、構成比が変わると全体の原価率が動きます（14-8） |
| **現金／キャッシュレス** | `【Inference】` 現金が手元に来るタイミングが違います（`08_money.md` 8-2） |
| **店内／テイクアウト／デリバリー** | `【Inference】` 席を使うかどうか、容器代・手数料がかかるかどうかが違います |
| **曜日別／時間帯別** | `【Typical】` 発注・仕込み・シフトの判断材料になります |
| **店別**（多店舗の場合） | `【Inference】` 合算した数字では、どの店がどう効いているか見えません |

> **前年同月比・前月比**
> `【Typical】` 売上高は、単月の金額だけでなく、前年の同じ月と比べて見られます。
> `【Inference】` 飲食業は季節性があるため、**前月と比べても季節の違いが混ざります。**
> 前年の同じ月と比べることで、季節の影響を除いた変化が見えます。

## 14-2 客数・組数

| 項目 | 内容 |
|---|---|
| **名称** | 客数（きゃくすう）／組数（くみすう） |
| **意味** | **客数**＝その期間に来店した人の延べ人数。**組数**＝来店したグループの数 |
| **計算方法** | POSで会計のたびに入力された人数の合計（`【Typical】`）<br>`1組あたりの人数 ＝ 客数 ÷ 組数` |
| **誰が見るか** | ⑦店長機能（`日次`）／④経理・財務機能（`月次`）／①メニュー開発機能 |
| **どこから取るか** | POS（A-5 来店・案内、A-9 会計で入力される）／日報 |
| **なぜ重要か** | `【Typical】` **客単価を計算するための分母**です。また、売上が増えた／減ったときに、**客が増えたのか、1人あたりの支払額が増えたのか**を分けて見るために必要です |

> **なぜ客数と組数を分けるのか**
> `【Inference】`
> - **客数**は、料理を作る量・提供の手間に対応します
> - **組数**は、**席の使われ方**に対応します
>
> `【Example】`（説明用の架空例）40席の店に、
> 「2名の組が20組（客数40名）」来る日と、「8名の組が5組（客数40名）」来る日では、
> 客数は同じですが、席の使い方も接客の手間も違います。
> 前者は40席を20組で使い、後者は5組で使っています。

> **初心者がつまずく点：客数 ≠ 組数**
> `【Inference】` 「今日は50組来た」と「今日は50人来た」はまったく違う情報です。
> 資料や会話で「客数」と言われたとき、**人数のことか組数のことか**を確認する必要があります。

## 14-3 客単価

| 項目 | 内容 |
|---|---|
| **名称** | 客単価（きゃくたんか） |
| **意味** | 客1人あたりの平均支払額 |
| **計算方法** | `客単価 ＝ 売上高 ÷ 客数`<br>（組単価を見る場合は `組単価 ＝ 売上高 ÷ 組数`） |
| **誰が見るか** | ⑦店長機能（`日次`）／①メニュー開発機能（`月次`）／代表取締役 |
| **どこから取るか** | POS／日報 |
| **なぜ重要か** | `【Typical】` 売上＝席数×回転数×客単価 の3要素の1つです。**席数は増やせず、回転数にも限界があるため、客単価は売上を動かせる数少ない要素**です |

### 客単価の分解

```
客単価 ＝ （フードの1品単価 × フードの注文点数）
        ＋（ドリンクの1杯単価 × ドリンクの杯数）
```

`【Inference】` 客単価が変わる原因は、次のどれかです。

| 原因 | 内容 |
|---|---|
| **注文点数が変わった** | `【Typical】` 追加オーダーが増えた／減った |
| **ドリンクの杯数が変わった** | `【Typical】` 酒類を飲む客が増えた／減った |
| **頼まれるメニューが変わった** | `【Typical】` 高いメニューが出た／安いメニューに偏った |
| **売価を変えた** | `【Typical】` メニューの価格を改定した |
| **客層・利用目的が変わった** | `【Varies】` 宴会が増えた／1人客が増えた |

> **初心者がつまずく点：客単価 ≠ 1品単価**
> `【Inference】` メニューの一番人気が900円でも、客単価が900円になるわけではありません。
> 客が2品頼めば客単価は上がり、複数人で1品を分ければ下がります。
> **客単価は「1人あたりいくら支払ったか」であり、メニューの価格そのものではありません**
> （`12_business-model.md` 12-2）。

> `【Example】`（説明用の架空例）モデル企業「株式会社まるみダイニング」A店の客単価は、
> 昼 約900円／夜 約3,200円という設定です（`03_company-structure.md` 3-1）。
> `【Inference】` 同じ店・同じ厨房でも、昼と夜で客単価が3倍以上違います。
> **昼は「食事」、夜は「食事＋酒＋滞在」に対する支払だから**です。

## 14-4 回転率（回転数）

| 項目 | 内容 |
|---|---|
| **名称** | 回転率（かいてんりつ）／回転数（かいてんすう） |
| **意味** | 1つの席が、その営業で**何回使われたか** |
| **計算方法** | `回転率 ＝ 客数 ÷ 席数`（1営業あたり）<br>`【Varies】` 組数で計算する場合もあります |
| **誰が見るか** | ⑦店長機能／代表取締役／③店舗開発機能（出店時の試算） |
| **どこから取るか** | POSの客数 ÷ 席数（席数は店の設定値） |
| **なぜ重要か** | `【Typical】` 売上＝席数×回転数×客単価 の3要素の1つ。**席数が固定である以上、回転率は売上の天井を決める要素**です |

### 回転率を決めるもの

```
回転率 ＝ 営業時間 ÷（1組あたりの滞在時間 ＋ 片付けにかかる時間）
                     ※ ただし客が途切れなく来ることが前提
```

`【Inference】` 回転率が上がらない理由は、次のどれかです。

| 理由 | 内容 | 関係する工程 |
|---|---|---|
| **客が来ていない** | そもそも席が埋まっていない | — |
| **1組の滞在が長い** | `【Typical】` 業態によっては滞在が長いことが前提（居酒屋・長居型のカフェ） | — |
| **提供が遅い** | 料理が出るまで待たせている | A-7 調理 |
| **片付けが遅い** | `【Inference】` **席が空かなければ、次の客は入れません** | A-10 片付け |
| **席の割り当てが合っていない** | `【Inference】` 2名客を6人掛けに通すと、後から来る6名客を断ることになります | A-5 来店・案内 |
| **会計に時間がかかる** | 客が帰るまでの時間が延びる | A-9 会計 |

> **片付けが「生産工程」である理由**
> `【Inference】` 売上 ＝ 席数 × 回転数 × 客単価 の「回転数」は、
> **片付けの速さで決まる**部分があります。
> ピーク時に片付けが遅れると、外で待っている客がいるのに席に案内できない状態が生じます
> （`04_end-to-end-process.md` A-10）。

`【Varies】` **回転率の目安は業態により大きく異なります。**
`【Typical】` 居酒屋のように滞在が長い業態では低く、立ち食いそばのような業態では高くなります。
**「高いほどよい」という指標ではありません。**

## 14-5 席稼働率

| 項目 | 内容 |
|---|---|
| **名称** | 席稼働率（せきかどうりつ）／座席稼働率 |
| **意味** | 席が**どれだけ埋まっていたか**の割合 |
| **計算方法** | `【Varies】` 定義が複数あります。代表的なものは<br>`席稼働率 ＝ 実際に使われた席数 ÷ 全席数 × 100`<br>`【Varies】` 時間の要素を入れる場合は `（使われた席 × 時間）÷（全席 × 営業時間）` |
| **誰が見るか** | ⑦店長機能／代表取締役 |
| **どこから取るか** | `【Varies】` POSの客数・テーブル情報から算出する／手で数える |
| **なぜ重要か** | `【Inference】` **回転率だけでは、「席が空いたまま使われていない」状態が見えません。**席稼働率は、店の面積がどれだけ使われているかを示します |

### ★ 回転率と席稼働率は違う

> **初心者がつまずく点：回転率 ≠ 席稼働率**
>
> | | **回転率** | **席稼働率** |
> |---|---|---|
> | 何を見るか | **1席が何回使われたか**（時間方向） | **何席が埋まっているか**（空間方向） |
> | 計算 | 客数 ÷ 席数 | 使われた席 ÷ 全席 |
> | 高いとき | 客が次々入れ替わっている | 席が埋まっている |
> | 低いとき | 1組の滞在が長い／客が来ていない | 席が空いている |
>
> `【Example】`（説明用の架空例）40席の店で、
> - **ケース1**：4人掛けテーブル10卓に、2名ずつ入っている
>   → **席稼働率は50％**（40席のうち20席が使用）だが、**テーブルは全部埋まっている**
> - **ケース2**：4人掛けテーブル5卓に4名ずつ入っている
>   → 席稼働率も50％だが、**5卓が空いている**
>
> `【Inference】` ケース1では、席稼働率は低いのに**新しい客を案内できません。**
> 「席が空いているのに入れない」という状態が、飲食業では普通に起こります。
> **だから席稼働率だけを見ても、店が満席かどうかは分かりません。**

`【Varies】` 席稼働率は定義が一定ではないため、
**企業内で「どう計算するか」を決めて使う指標**です。

## 14-6 予約件数・予約人数

| 項目 | 内容 |
|---|---|
| **名称** | 予約件数／予約人数 |
| **意味** | その日（またはその期間）に予約が入っている件数と人数 |
| **計算方法** | 予約台帳・予約管理システムの集計 |
| **誰が見るか** | ⑦店長機能（`日次`）／⑧仕込み機能／⑤人事・労務機能（シフト）／⑥販促機能 |
| **どこから取るか** | 予約台帳／予約管理システム／予約サイトの管理画面 |
| **なぜ重要か** | `【Inference】` **飲食業で唯一、「これから来る客」が確定している情報**だからです |

> **予約が計画の起点になる理由（再掲）**
> `【Inference】` 飲食業は「何人来るか分からない」商売です。
> しかし予約が入っている分だけは、**来る人数・食べるもの・時間が確定します。**
> つまり予約は、**仕入量・仕込み量・シフト人数を決めるための唯一の確定情報**です
> （`04_end-to-end-process.md` A-P、`09_information.md` 9-2）。

`【Typical】` 予約に関して見られる数字には、次のものもあります（`【Varies】`）。

| 数字 | 内容 |
|---|---|
| 予約経路別の件数 | `【Varies】` 電話／予約サイト／自社サイト／店頭 |
| 予約人数が売上に占める割合 | `【Inference】` 予約への依存度が分かる |
| 無断キャンセルの件数 | `【Inference】` 仕込みと席の両方を失うため、影響を把握する |

## 14-7 リピート率

| 項目 | 内容 |
|---|---|
| **名称** | リピート率／再来店率 |
| **意味** | 一度来た客が、また来る割合 |
| **計算方法** | `【Varies】` **定義も計算方法も一定ではありません**（後述） |
| **誰が見るか** | ⑥販促機能／代表取締役 |
| **どこから取るか** | `【Varies】` 会員登録・ポイント・予約情報など、客を識別できる仕組みがある場合に限られます |
| **なぜ重要か** | `【Typical】` 新しい客を呼ぶための販促費をかけずに来てくれる客の割合を示します |

> **★ 飲食業では、この数字を出すこと自体が難しい**
> `【Inference】` `01_overview.md` 1-4 のとおり、飲食業の客の多くは**一見客**で、
> 氏名・住所を知らないまま取引が終わります。
> **つまり「同じ人が2回来た」ことを店が知る手段が、そもそもありません。**
>
> `【Varies】` リピート率を数字として出せるのは、次のような仕組みがある場合に限られます。
> - 会員登録・ポイントカード・アプリ
> - 予約時に氏名・連絡先を記録している（宴会・コース予約など）
> - デリバリープラットフォーム経由（`【Varies】` 事業者側のデータ）
>
> `【Typical】` 仕組みがない店では、**店の人が顔を覚えている**という形で把握されます。
> `【Fact】` 本資料では、リピート率の目安となる数値を示しません。

# グループ2：コストを見る数字

---

## 14-8 原価率（F）

| 項目 | 内容 |
|---|---|
| **名称** | 原価率（げんかりつ）／F比率 |
| **意味** | 売上高に対して、**食材費が何％を占めるか** |
| **計算方法** | `原価率 ＝ 食材費 ÷ 売上高 × 100`<br>**ここが重要：** `食材費 ＝ 月初の在庫 ＋ 当月の仕入 − 月末の在庫` |
| **誰が見るか** | ④経理・財務機能（`月次`）／代表取締役／①メニュー開発機能／⑦店長機能 |
| **どこから取るか** | 棚卸表＋仕入の記録（納品書・レシート）＋売上高 |
| **なぜ重要か** | `【Typical】` 飲食業の費用のうち、金額が大きく、日々の運営で動く2つのうちの1つ（もう1つは人件費）です |

### ★ 原価率は棚卸をしないと出ない

> `【Example】`（説明用の架空例。数値は説明のための仮置きです）
> 月初在庫60万円、当月仕入180万円、月末在庫70万円なら、
> 当月の食材費＝60＋180−70＝**170万円**。
> 売上が500万円なら原価率は34.0％。
> **仕入額180万円で計算すると36.0％となり、2ポイントずれます**
> （`04_end-to-end-process.md` A-I）。

> **初心者がつまずく点：仕入 ≠ 売上原価**
> `【Inference】` 月末に大量に仕入れて在庫が積み上がっていれば、
> 「仕入額」は大きくても「使った額」は小さいはずです。
> **月末の在庫を数えなければ、この区別ができません。**

### 原価率が上がったとき、どこを見るか

```
原価率が上がった
   │
   ├─ 仕入単価が上がった？          → 納品書の単価・相場（②仕入・調達機能）
   ├─ 捨てた量が増えた？            → 廃棄（ロス）記録（14-11）
   │     ├─ 仕入ロス   → 発注量（A-1）
   │     ├─ 仕込みロス → 仕込み量（A-3）
   │     └─ 提供ロス   → オーダーの伝達（A-6）
   ├─ 売れるメニューの構成が変わった？ → メニュー別の出数（POS）
   ├─ ドリンク比率が下がった？       → 14-10
   ├─ 分量が増えている？（計量のばらつき）→ レシピどおりに作られているか
   └─ 棚卸の数え漏れ・記録漏れ？     → 棚卸表・納品書の管理
```

> `【Inference】` **記録がなければ、原価率という結果の数字だけが残り、原因が分かりません。**
> A-L の廃棄記録で「なぜ捨てたのか」まで記録する理由がここにあります
> （`07_goods.md` 7-9）。

### 標準原価と実際原価

`【Typical】` メニュー別原価計算表が示すのは「**レシピどおりに作った場合の原価**」です
（`10_documents.md` 10-4）。
`【Inference】` 実際には、仕込みの歩留まり、廃棄、計量の誤差、盛り付けのばらつきによって、
実際の原価はこれより高くなるのが通常です。

```
標準原価（レシピから計算した原価）
    ↓ この差はどこから出たのか？
実際原価（棚卸から計算した原価）
```

`【Typical】` 実務では、この2つを比較して差の原因を見る、という使い方をします。

> `【Varies】` **原価率の目安は業態・提供形態により大きく異なります。**
> 酒類の比率が高い店と食事中心の店ではまったく違うため、
> 本資料では具体的な水準を示しません（`01_overview.md` 1-5）。

## 14-9 人件費率（L）

| 項目 | 内容 |
|---|---|
| **名称** | 人件費率（じんけんひりつ）／L比率 |
| **意味** | 売上高に対して、**人件費が何％を占めるか** |
| **計算方法** | `人件費率 ＝ 人件費 ÷ 売上高 × 100`<br>`【Varies】` 人件費に何を含めるか（役員報酬、社会保険料の会社負担分、賞与）は企業により異なります |
| **誰が見るか** | ④経理・財務機能（`月次`）／⑤人事・労務機能／⑦店長機能／代表取締役 |
| **どこから取るか** | 勤怠の集計＋給与計算＋売上高 |
| **なぜ重要か** | `【Typical】` 食材費と並ぶ2大費目です。**シフト（誰が何時間入るか）で日々動く**点が特徴です |

### 人件費率が動く理由

| 理由 | 内容 |
|---|---|
| **シフトを厚くした／薄くした** | `【Typical】` 直接的に人件費が増減します |
| **売上が変わった**（人員は同じ） | `【Inference】` 人件費が同じでも、売上が減れば人件費率は上がります |
| **深夜の時間が増えた** | `【Fact】` 深夜（午後10時から午前5時まで）の労働には通常の賃金の2割5分以上の割増賃金（労働基準法第37条第4項） |
| **時間外労働が増えた** | `【Fact】` 労働時間を延長した場合、通常の労働時間の賃金の計算額の2割5分以上5割以下の範囲内でそれぞれ政令で定める率以上の率で計算した割増賃金の支払いが必要です（労働基準法第37条第1項） |
| **正社員の比率が変わった** | `【Inference】` 正社員の給与は固定費に近いため、売上が減ったときに率が跳ね上がります |
| **最低賃金が改定された** | `【Fact】` 使用者は、最低賃金の適用を受ける労働者に対し、その最低賃金額以上の賃金を支払わなければなりません（最低賃金法第4条第1項） |

> **人件費率だけを見ると判断を誤る**
> `【Inference】` 人件費率が高いとき、原因は2つあります。
> - **人を入れすぎた**（分子が大きい）
> - **売上が足りなかった**（分母が小さい）
>
> `【Typical】` この2つを分けるために、**人時売上高**（14-13）という別の指標が使われます。

`【Varies】` **人件費率の目安は業態・営業時間・店舗規模により大きく異なるため、
本資料では具体的な水準を示しません。**

## 14-10 ドリンク比率（酒類比率）

| 項目 | 内容 |
|---|---|
| **名称** | ドリンク比率／酒類比率 |
| **意味** | 売上高のうち、**ドリンク（または酒類）が占める割合** |
| **計算方法** | `ドリンク比率 ＝ ドリンクの売上 ÷ 売上高 × 100`<br>`【Varies】` 「ドリンク全体」で見るか「酒類のみ」で見るかは企業により異なります |
| **誰が見るか** | ⑦店長機能／①メニュー開発機能／代表取締役 |
| **どこから取るか** | POSのメニュー別売上（カテゴリ別集計） |
| **なぜ重要か** | `【Typical】` **ドリンクの原価率はフードより低いことが一般的**なため、**同じ売上でもドリンクの比率が高いほど、全体の原価率（F）は下がります** |

> `【Example】`（説明用の架空例。数値は説明のための仮置きであり実データではありません）
> 売上100万円の店で、フードの原価率が35％、ドリンクの原価率が20％だとします。
>
> | | ドリンク比率20％ | ドリンク比率40％ |
> |---|---|---|
> | フードの原価 | 28万円 | 21万円 |
> | ドリンクの原価 | 4万円 | 8万円 |
> | **食材費（F）合計** | **32万円** | **29万円** |
> | **全体の原価率** | **32.0％** | **29.0％** |
>
> `【Inference】` 売上はどちらも100万円ですが、**全体の原価率が3ポイント違います。**
> **メニューの価格を変えなくても、ドリンクが出るかどうかで原価率が変わる**という構造です
> （`12_business-model.md` 12-2）。

> **なぜドリンクの原価率が低いのか（構造の説明）**
> `【Inference】` 飲食業の売価は「食材費＋手間＋場所の対価」で構成されます。
> ドリンクは食材の加工がほとんど不要ですが、
> **「席に座って飲める」という場所の対価は料理と同じようにかかっています。**
> 結果として、売価に対する食材費の割合は低くなります。

`【Varies】` **具体的な原価率の水準は業態・商品により大きく異なるため、
本資料では数値を示しません。**

## 14-11 ロス率（廃棄率）

| 項目 | 内容 |
|---|---|
| **名称** | ロス率／廃棄率 |
| **意味** | 仕入れた食材のうち、**売上にならずに捨てられた分**の割合 |
| **計算方法** | `【Varies】` 定義が複数あります。代表的なものは<br>`ロス率 ＝ 廃棄した食材の金額 ÷ 売上高 × 100`<br>または `廃棄した食材の金額 ÷ 食材費 × 100` |
| **誰が見るか** | ⑦店長機能（`日次`）／④経理・財務機能（`月次`）／代表取締役 |
| **どこから取るか** | 廃棄（ロス）記録（A-L） |
| **なぜ重要か** | `【Inference】` **廃棄は原価率を押し上げる形で現れます。**ロス率を分けて見ないと、原価率が上がった原因が「仕入値」なのか「捨てた量」なのか分かりません |

### ロスの理由別の分類

`【Typical】` 廃棄の理由は主に次に分類されます（`04_end-to-end-process.md` A-L）。

| 理由の分類 | 内容 | どの工程に原因があるか |
|---|---|---|
| **仕入ロス** | 仕入れすぎて使い切れなかった | A-1 発注 |
| **仕込みロス** | 仕込みすぎて残った | A-3 仕込み |
| **提供ロス** | 作ったが客に出せなかった（オーダーミス、作り直し） | A-6 注文／A-7 調理 |
| **食べ残し** | 客が残した | メニュー設計（量）／A-6 での助言 |
| **期限切れ・品質劣化** | 使う前に使えなくなった | 保管方法／先入先出 |

> **なぜ理由まで記録するのか**
> `【Inference】` 原価率が上がったとき、理由の分類があれば
> **発注・仕込み・オーダーのどこに原因があったか**まで遡れます。
> **記録しないと、原価率という結果の数字だけが残り、原因が分からなくなります**
> （`07_goods.md` 7-9）。

> **初心者がつまずく点：廃棄ロス ≠ 食べ残し**
> `【Inference】` 食べ残しは廃棄ロスの**一種**ですが、原因がまったく違います。
> - **廃棄ロス（仕込みロス・仕入ロス）**＝**店が作りすぎた／仕入れすぎた**
> - **食べ残し**＝**客が食べ切れなかった**（メニューの分量・注文時の助言に関わる）
>
> `【Typical】` 前者は発注・仕込みの判断の問題、後者はメニュー設計と接客の問題です。
> **同じ「捨てた」でも、見るべき場所が違います。**

### ★ 記録されないロスがある

> `【Inference】` **品切れによる機会の損失は、帳簿に現れません。**
> 「今日、牛すじ煮込みを頼もうとした客が5人いたが、品切れで断った」という事実は、
> POSにも原価計算にも残りません。
> `【Typical】` だから実務では、品切れを起こしたメニューと時刻を記録したり、
> 日報の特記事項に書いたりします（`07_goods.md` 7-6）。
>
> **つまりロス率が低いことは、必ずしもよい状態を意味しません。**
> 仕込みを絞りすぎて品切れを連発している場合も、ロス率は低く出ます。

`【Varies】` **ロス率の目安は業態・メニュー構成により大きく異なるため、
本資料では具体的な水準を示しません。**

## 14-12 FL比率・FLR比率

### FL比率

| 項目 | 内容 |
|---|---|
| **名称** | FL比率（エフエルひりつ／Food & Labor ratio） |
| **意味** | **F（食材費）とL（人件費）の合計**が、売上に対して何％を占めるか |
| **計算方法** | `FL比率 ＝（食材費 ＋ 人件費）÷ 売上高 × 100` |
| **誰が見るか** | ④経理・財務機能（`月次`）／代表取締役／⑦店長機能 |
| **どこから取るか** | 店別損益表（棚卸＋勤怠集計＋売上高） |
| **なぜ重要か** | 下記の2つの理由 |

**理由1：金額が大きく、かつ日々の運営で動かせるのがこの2つだから**

`【Typical】` 家賃は契約で決まっていて今月だけ下げることはできません。
一方、食材費は仕入量や廃棄量で変わり、人件費はシフトで変わります。

**理由2：この2つは互いに置き換えが効くから**

> `【Example】`（説明用の架空例）
> - 野菜を丸ごと仕入れて店で切る → 食材費は安いが、切る人の**人件費**がかかる（F↓ L↑）
> - カット済み野菜を仕入れる → **食材費**は高いが、切る手間はゼロ（F↑ L↓）
>
> **片方だけ見ていると判断を誤る**ので、合計（FL）で見る、という発想です
> （`01_overview.md` 1-5、`12_business-model.md` 12-4）。

> **初心者がつまずく点：原価率 ≠ FL比率**
> `【Inference】` 原価率は**食材費だけ**の比率、FL比率は**食材費＋人件費**の比率です。
> 「原価率が30％だから、残り70％がもうけ」というのは誤りです。
> **FL比率で見ると、すでに60％前後が消えていることがある**、という関係になります
> （`【Varies】` 実際の水準は企業により異なります）。

### FLR比率

| 項目 | 内容 |
|---|---|
| **名称** | FLR比率 |
| **意味** | FL に **R（家賃）** を加えた割合 |
| **計算方法** | `FLR比率 ＝（食材費 ＋ 人件費 ＋ 家賃）÷ 売上高 × 100` |
| **誰が見るか** | 代表取締役／④経理・財務機能／③店舗開発機能（出店時の試算） |
| **どこから取るか** | 店別損益表 |
| **なぜ重要か** | `【Inference】` FL だけを見ていると、**家賃の重さが視界に入りません。**家賃は動かせない費用であるため、FLR で見ることで「動かせない部分を含めて、どれだけ残るか」が見えます |

> `【Example】`（説明用の架空例）
>
> | | X店 | Y店 |
> |---|---|---|
> | 月商 | 500万円 | 500万円 |
> | FL比率 | 65％（325万円） | 65％（325万円） |
> | 家賃 | 40万円（8％） | 90万円（18％） |
> | **FLR比率** | **73％** | **83％** |
> | FLR を引いた残り | 135万円 | 85万円 |
>
> `【Inference】` FL は同じでも、残る金額が50万円違います。
> この残りから水道光熱費・販促費・その他経費・借入返済を払い、最後に利益になります。

> `【Varies】` **FL比率・FLR比率の目安**として一般に語られる数値がありますが、
> 業態・立地・提供形態によって前提がまったく異なり、
> 公的統計に基づく確定値ではないため、本資料では具体的な目標値・標準値を示しません。

## 14-13 人時売上高

| 項目 | 内容 |
|---|---|
| **名称** | 人時売上高（にんじうりあげだか） |
| **意味** | **働いた1時間あたり、いくらの売上があったか** |
| **計算方法** | `人時売上高 ＝ 売上高 ÷ 総労働時間`<br>（総労働時間＝その期間に働いた全員の労働時間の合計） |
| **誰が見るか** | ⑦店長機能／⑤人事・労務機能／代表取締役 |
| **どこから取るか** | 勤怠の集計＋売上高 |
| **なぜ重要か** | `【Inference】` **人件費率だけでは「人を入れすぎた」のか「売上が足りなかった」のかが分かりません。**人時売上高は、投入した時間あたりの成果を直接示します |

> `【Example】`（説明用の架空例。数値は説明のための仮置きです）
> ある日の売上が412,600円、その日の総労働時間が52時間だったとします。
> 人時売上高＝412,600 ÷ 52 ＝ **約7,935円／時間**
>
> `【Inference】` 翌日、同じ売上で総労働時間が60時間だった場合、
> 人時売上高は約6,877円／時間に下がります。
> **同じ売上を、より多くの時間で作ったことになります。**

### 人時売上高が飲食業で意味を持つ理由

`【Inference】` 飲食業には**ピークタイムに人が集中して必要になる山谷**があります
（`02_industry-structure.md` 11-6(4)、`06_people.md` 6-8）。

```
 ピークに合わせて人を揃える  → 暇な時間に人が余る → 人時売上高が下がる
 暇な時間に合わせて人を揃える → ピークに回らない   → 売上が落ちる
```

> `【Inference】` つまり人時売上高は、
> **「山谷にどれだけ人数を合わせられたか」を示す数字**として読めます。
> `【Typical】` 短時間で働くパート・アルバイトを組み合わせてシフトを作るのは、
> この山の形に人数を沿わせるためです。

### 関連する指標

| 指標 | 計算方法 | 何を見るか |
|---|---|---|
| **人時売上高** | 売上高 ÷ 総労働時間 | 1時間あたりの売上 |
| **人時生産性**（`【Varies】`） | `【Varies】` 粗利 ÷ 総労働時間 など | 1時間あたりの粗利 |
| **1人あたり客数**（`【Varies】`） | 客数 ÷ 総労働時間 | 1時間あたり何人の客に対応したか |

`【Varies】` **人時売上高の目安は業態により大きく異なります**
（`【Inference】` セルフサービスの業態とフルサービスの業態では、前提がまったく違います）。
本資料では具体的な水準を示しません。

## 14-14 坪売上

| 項目 | 内容 |
|---|---|
| **名称** | 坪売上（つぼうりあげ）／坪効率 |
| **意味** | **店の面積1坪あたり、いくらの売上があったか** |
| **計算方法** | `坪売上 ＝ 売上高 ÷ 店舗面積（坪）`<br>`【Varies】` 全体の面積で計算するか、客席部分の面積で計算するかは企業により異なります |
| **誰が見るか** | 代表取締役／③店舗開発機能（出店時の試算） |
| **どこから取るか** | 売上高＋物件の面積 |
| **なぜ重要か** | `【Inference】` **家賃は面積に応じて決まる**ことが多いため、面積あたりの売上を見ることで、**その家賃に見合う売上が取れているか**が分かります |

> **なぜ坪で見るのか**
> `【Typical】` 飲食店の売上には席数×回転数×客単価という天井があり、
> **席数は面積で決まります**（`12_business-model.md` 12-1）。
> `【Inference】` つまり坪売上は、**店が持っている「器」をどれだけ使えているか**を示します。
> `【Typical】` 立地のよい場所ほど家賃が高いため、
> 家賃の高い店は、より高い坪売上が必要になる、という関係があります
> （`02_industry-structure.md` 11-6(2)）。

> **1坪 ＝ 約3.3平方メートル**
> `【Typical】` 不動産と飲食業の実務では、面積を「坪」で表すことが広く行われています。

`【Varies】` **坪売上の目安は業態・立地により大きく異なります。**
本資料では具体的な水準を示しません。

## 14-15 限界利益率

| 項目 | 内容 |
|---|---|
| **名称** | 限界利益率（げんかいりえきりつ） |
| **意味** | **売上が1単位増えたときに、そのうち何％が利益の増加になるか** |
| **計算方法** | `限界利益 ＝ 売上高 − 変動費`<br>`限界利益率 ＝ 限界利益 ÷ 売上高 × 100 ＝ 1 − 変動費率` |
| **誰が見るか** | 代表取締役／④経理・財務機能 |
| **どこから取るか** | 店別損益表（費目を固定費と変動費に分けて集計する） |
| **なぜ重要か** | `【Inference】` **客が1人増えても、家賃は増えません。正社員の給与も増えません。**増えた売上のうち変動費を引いた分が、そのまま利益の増加になります |

> `【Example】`（説明用の架空例。数値はすべて説明のための仮置きであり実データではありません）
> 客単価3,200円の客が1人増えた場合、その客のために増える変動費を次のように置きます。
>
> | 費目 | 売上に対する割合 | 金額 |
> |---|---|---|
> | 食材費 | 32％ | 1,024円 |
> | パート・アルバイト賃金（増えた分） | 18％ | 576円 |
> | 消耗品費 | 2％ | 64円 |
> | 決済手数料 | 2％ | 64円 |
> | **変動費 合計** | **54％** | **1,728円** |
> | **限界利益** | **46％** | **1,472円** |
>
> `【Inference】` この客1人から、**1,472円が利益の増加として残ります。**
> 客が10人増えれば14,720円、**逆に10人減れば14,720円の利益が消えます。**

> **なぜこの考え方が飲食業で重要なのか**
> `【Inference】` 固定費が大きいということは、
> **売上が少し増減しただけで、利益が大きく動く**ということです。
> `【Typical】` だから飲食業では、天候・曜日・季節による客数の変動が
> そのまま利益の変動として現れます（14-17）。

## 14-16 損益分岐点売上高

| 項目 | 内容 |
|---|---|
| **名称** | 損益分岐点（そんえきぶんきてん）売上高 |
| **意味** | **利益がちょうどゼロになる売上高。**これを超えた分から利益が出ます |
| **計算方法** | `損益分岐点売上高 ＝ 固定費 ÷ 限界利益率` |
| **誰が見るか** | 代表取締役／④経理・財務機能／③店舗開発機能（出店時の試算） |
| **どこから取るか** | 店別損益表（固定費と変動費に分けた集計） |
| **なぜ重要か** | `【Typical】` 飲食業には、客が来なくても発生する費用（家賃・正社員の給与・リース料・借入返済）がまとまって存在します。**売上がゼロでも毎月一定額が出ていく**ため、「いくら売れば赤字にならないか」を把握する必要があります |

> `【Example】`（説明用の架空例。`08_money.md` 8-8、`12_business-model.md` 12-6 と同じ設定です）
> 固定費170万円、限界利益率46％の店の場合、
> 損益分岐点売上高 ＝ 170万円 ÷ 0.46 ＝ **約369.6万円**
>
> | 月商 | 変動費（54％） | 固定費 | 利益 |
> |---|---|---|---|
> | 300万円 | 162万円 | 170万円 | **−32万円** |
> | 369.6万円 | 199.6万円 | 170万円 | **0円**（損益分岐点） |
> | 400万円 | 216万円 | 170万円 | **+14万円** |
> | 500万円 | 270万円 | 170万円 | **+60万円** |
>
> `【Example】` **上の比率（32％、18％、54％など）は、計算のしかたを示すために置いた架空の数値です。**
> `【Varies】` 実際の水準は業態・立地・提供形態により大きく異なるため、
> **この数値を業界の目安として引用しないでください。**

### 関連する見方

| 指標 | 計算方法 | 何を見るか |
|---|---|---|
| **損益分岐点比率** | 損益分岐点売上高 ÷ 実際の売上高 × 100 | `【Inference】` 100％に近いほど、余裕が小さい |
| **損益分岐点の客数** | 損益分岐点売上高 ÷ 客単価 | `【Inference】` 1日に何人来れば赤字にならないか |
| **1日あたりの必要売上** | 損益分岐点売上高 ÷ 月の営業日数 | `【Inference】` 日次の目標として使える形にする |

> `【Example】`（説明用の架空例）損益分岐点売上高が約370万円、
> 月の営業日数が26日、客単価が2,400円なら、
> 1日あたり約14.2万円、客数にして約59名が必要、という計算になります。
> `【Inference】` **この形にすると、日次の日報の数字と直接比べられます。**

## 14-17 客数の変動（曜日・天候・季節）

| 項目 | 内容 |
|---|---|
| **名称** | 曜日別客数／天候別客数／季節変動 |
| **意味** | 客数が、曜日・天候・季節によってどれだけ変わるか |
| **計算方法** | `【Typical】` 日報・POSの日次データを、曜日別・天候別に並べて比較する |
| **誰が見るか** | ⑦店長機能（`日次`〜`週次`）／⑧仕込み機能 |
| **どこから取るか** | POSの日次集計／日報（天候は特記事項欄に記録されていることがある `【Varies】`） |
| **なぜ重要か** | `【Inference】` **発注量・仕込み量・シフト人数を決める材料**になるからです。飲食業の日次業務は、毎回条件が違う中で判断する業務です（`13_periodic-work.md` 13-8） |

### 変動の要因

| 要因 | `【Typical】` 傾向 | どの判断に影響するか |
|---|---|---|
| **曜日** | `【Varies】` 業態・立地により異なる（`【Typical】` 居酒屋は週末に向けて増えることが多い） | A-1 発注／A-3 仕込み／シフト |
| **天候** | `【Typical】` 雨・雪・台風で来店が減ることがある | 同上。`【Inference】` 仕込みを終えた後に天候が変わると、廃棄が発生し得る |
| **季節・行事** | `【Typical】` 歓送迎会・忘年会シーズンに予約が集中する業態がある | 繁忙期の準備（`13_periodic-work.md` 13-8） |
| **近隣のイベント** | `【Varies】` 増える場合と減る場合がある | 同上 |
| **給料日の前後** | `【Varies】` | 同上 |

> **なぜこの変動が利益に強く効くのか**
> `【Inference】` 14-15 のとおり、飲食業では**増えた売上の一定割合がそのまま利益になり、
> 減った売上の一定割合がそのまま利益から消えます。**
> 固定費（家賃・正社員の給与）は客が来なくても発生するためです。
>
> `【Example】`（説明用の架空例）限界利益率が46％の店で、
> 台風により1日の客数が通常の半分（売上が7万円減）になった場合、
> その日の利益は約3.2万円減ります。
> **家賃も正社員の給与も、その日の分だけ減らすことはできません。**

`【Fact】` 本資料では、曜日別・天候別の変動幅について数値目安を示しません
（`【Varies】` 業態・立地により大きく異なるため）。

## 14-19 数字を見るときの注意（初心者向け）

### (1) 1つの指標だけでは判断できない

> `【Inference】` 飲食業の指標は、**互いに打ち消し合う**関係にあるものが多くあります。

| 指標が改善したように見えるとき | 裏で起きているかもしれないこと |
|---|---|
| 原価率が下がった | `【Inference】` 仕込みを絞りすぎて品切れが増えている（機会の損失は記録されない） |
| 人件費率が下がった | `【Inference】` 人を減らしすぎて提供が遅れ、回転率が落ちている |
| 回転率が上がった | `【Inference】` 客単価が下がっている（滞在が短い＝注文が少ない） |
| 客単価が上がった | `【Inference】` 客数が減っている（単価の高い客だけが残った） |
| ロス率が下がった | `【Inference】` 品切れが増えている（14-11） |
| 売上が増えた | `【Inference】` 手数料の高い販路が増えて、残る金額は増えていない（`12_business-model.md` 12-11） |

> `【Typical】` だから実務では、**FL比率のように複数の要素を合わせた指標**や、
> **店別損益のように費目をすべて並べた表**が使われます。

### (2) 日次で見える数字と、月次でしか出ない数字がある

```
【日次で出る】   売上高／客数／客単価／現金過不足／廃棄の内容／予約件数
                 → POSと日報から、その日のうちに出る

【月次で出る】   原価率／人件費率／FL比率／FLR比率／限界利益率／損益分岐点
                 → 棚卸と締めが終わらないと出ない
```

> `【Inference】` **この時間差があるため、「今月の原価率が高かった」と分かるのは翌月です。**
> `【Typical】` だから日次では、廃棄記録・仕込み表・品切れの記録といった
> **原価率の「原因」にあたる情報**を残しておく、という運用になります
> （`09_information.md` 9-12）。

### (3) 数値目安を鵜呑みにしない

> `【Varies】` 飲食業では「原価率は◯％」「FL比率は◯％以下」といった目安が語られることがあります。
> `【Fact】` **本資料ではこれらの数値を示しません。**
> 業態別の水準を示す公的統計が、本資料の調査範囲では確認できていないためです。
>
> `【Inference】` 目安の数値を見かけた場合は、次を確認してください。
> - **どの業態の数字か**（居酒屋とカフェでは前提が違う）
> - **いつの数字か**（食材の相場・最低賃金は年によって変わる）
> - **誰が出した数字か**（公的統計か、調査会社か、経験則か）
> - **何を分子・分母にしているか**（人件費に役員報酬・社会保険料を含むか 等）

# 13_periodic-work.md — 飲食業の定期業務

> ### このファイルの方針（必ずお読みください）
> `【Fact】` **本ファイルでは「1日のタイムスケジュール」を作りません。**
> 開店時刻・ピーク時刻・閉店時刻は業態と店舗により大きく異なるためです（`【Varies】`）。
> 代わりに、`common/methodology.md` §5 の共通語彙に従って、
> **頻度の分類ごとに「何が起きるか」**を整理します。
>
> ```
> 常時 / 日次 / 週次 / 月次 / 四半期 / 半期 / 年次
> 案件発生時 / 問い合わせ時 / 受注時 / 発注時 / 納品時 / 請求時 / 入金時
> トラブル発生時 / 法定・契約上のタイミング / その他
> ```
>
> `【Fact】` 曜日・日付レベルの具体化は、**法定期限など根拠がある場合のみ**記載します。
> 機能番号（①〜⑫）は `03_company-structure.md` 3-2、
> 工程番号（A-1〜A-13、B-1〜B-6 ほか）は `04_end-to-end-process.md` に対応します。
> 出典の詳細は `19_sources.md` を参照してください。

## 13-0 飲食業の定期業務の特徴

| # | 特徴 | 内容 |
|---|---|---|
| 1 | **日次の業務が非常に多い** | `【Typical】` 発注・仕込み・レジ締め・日報・衛生管理の記録が、毎営業日発生します |
| 2 | **「その日のうちに終わらせる」業務がある** | `【Inference】` レジ締めは翌日に回せません。毎日確認しないと、どの日にずれたか分からなくなるためです（`08_money.md` 8-9） |
| 3 | **月次で数字が確定する** | `【Typical】` 棚卸をして初めて原価が確定します。日々の数字だけでは利益が出せません |
| 4 | **季節による繁閑がある** | `【Typical】` 歓送迎会・忘年会シーズンなど、予約が集中する時期があります |
| 5 | **法定期限のある手続がある** | `【Fact】` 源泉所得税の納付、健康診断、防火管理など、法令に基づく期限があります |

### 定期業務の全体マップ

```
【常時】   営業中の業務（接客・調理・会計・片付け）／予約の受付／クレーム対応
   │
【日次】   発注・納品検品・仕込み・開店準備・レジ締め・日報・清掃・衛生管理記録・廃棄記録
   │
【週次】   シフト作成（`【Varies】`）／棚卸（`【Varies】`）／乾物・消耗品の発注／販促の確認
   │
【月次】   棚卸／仕入の締め・請求書照合・支払／勤怠集計・給与計算／店別損益／資金繰り
   │
【四半期】 季節メニューの入替（`【Varies】`）／販促企画の見直し
   │
【半期】   `【Varies】` メニュー全体の見直し／人事の評価
   │
【年次】   決算・申告／棚卸（年次の企業）／健康診断／消防訓練／営業許可の更新（有効期間による）
   │
【イベント起点】 出店・改装／採用／設備の故障／食中毒の疑い／繁忙期の準備／台風・災害
```

## 13-1 常時（営業中に随時発生する業務）

`【Typical】` 「常時」とは、営業している間ずっと、決まった周期ではなく発生する業務です。

| 業務 | 誰が | 工程 | 内容 |
|---|---|---|---|
| 来店・案内 | ⑩ホール機能 | A-5 | 客が来るたび。席の割り当てを判断する |
| 注文（オーダー）を受ける・通す | ⑩ホール機能 | A-6 | `受注時`。復唱して確認し、厨房へ通す |
| 調理 | ⑨キッチン機能 | A-7 | オーダーが通るたび。提供順序を組み立てる |
| 提供 | ⑩ホール機能 | A-8 | 料理が完成するたび |
| 会計 | ⑪レジ・会計機能 | A-9 | `入金時`。客が会計を求めるたび |
| 片付け（下げ膳・テーブルセット） | ⑩ホール機能・⑫清掃・衛生機能 | A-10 | 客が席を立つたび |
| 食器・器具の洗浄 | ⑫清掃・衛生機能 | — | 使用済みが出るたび |
| 在庫の残量の把握 | ⑨キッチン機能 | — | 使いながら確認し、品切れを店長・ホールに連絡する |
| 予約の受付 | ⑩ホール機能・⑦店長機能 | A-P | `問い合わせ時`。電話・サイト・店頭 |
| クレームへの一次対応 | ⑩ホール機能→⑦店長機能 | A-C | `トラブル発生時` |
| 廃棄の発生と記録 | ⑧仕込み機能・⑨キッチン機能 | A-L | 発生の都度 |
| 手洗い | 全員 | — | `【Fact】` 一般的な衛生管理の基準に関わる（食品衛生法施行規則第66条の2第1項、別表第17） |
| 先入先出（古いものから使う） | ⑧仕込み機能・⑨キッチン機能 | — | 食材を取り出すたび |

## 13-2 日次（毎営業日に行う業務）

### 開店前

| 業務 | 誰が | 工程 | なぜ毎日行うのか |
|---|---|---|---|
| **発注** | ⑦店長機能 | A-1 | `【Typical】` **生鮮食材は数日しか持たないため、まとめ買いができません。**「今日使う分を昨日発注する」というサイクルが基本形になります（`07_goods.md` 7-2） |
| **納品・検品** | ⑦店長機能・⑨キッチン機能 | A-2 | `【Typical】` 配送担当者はその場を離れると確認ができません。`【Inference】` 傷んだ食材を受け取ってしまうと、後から「元々傷んでいたのか、店で傷めたのか」が分からなくなります |
| **納品時の温度の確認と記録** | ⑦店長機能・⑨キッチン機能 | A-2 | `【Fact】` 衛生管理の実施状況を記録し、保存すること（食品衛生法施行規則第66条の2第3項第3号） |
| **仕込み** | ⑧仕込み機能 | A-3 | `【Typical】` 注文を受けてから全部を一から作っていては間に合いません。**時間のかかる工程を営業時間の外へ出す**必要があります（`07_goods.md` 7-5） |
| **仕込み品へのラベル貼り（日付・品名）** | ⑧仕込み機能 | A-3 | `【Inference】` 日付がないと、その容器がいつ作られたものか分からず、**使うか捨てるかの判断ができなくなります**（`07_goods.md` 7-10） |
| **開店準備** | ⑩ホール機能・⑦店長機能・⑫清掃・衛生機能 | A-4 | 清掃の仕上げ／テーブルセッティング／POS・決済端末の動作確認 |
| **釣銭準備金のセット** | ⑦店長機能 | A-4 | `【Inference】` 毎日同じ額から始めないと、締めの計算の基準がぶれます（`08_money.md` 8-9） |
| **冷蔵庫・冷凍庫の温度の確認と記録** | ⑫清掃・衛生機能 | A-4 | `【Fact】` 同上（施行規則第66条の2第3項第3号） |
| **従業員の健康状態の確認と記録** | ⑦店長機能 | A-4 | `【Fact】` 同上 |
| **情報共有（品切れ・予約・その日の重点）** | ⑦店長機能 | A-4 | `【Inference】` ホールが品切れを知らずに注文を受けると、**客に謝って注文を取り直す**ことになります（`06_people.md` 6-3） |

### 閉店後

| 業務 | 誰が | 工程 | なぜ毎日行うのか |
|---|---|---|---|
| **レジ締め（現金の照合）** | ⑦店長機能・⑪レジ・会計機能 | A-11 | `【Inference】` **毎日確認すれば「今日ずれた」と分かりますが、月末にまとめて確認すると、どの日に何が起きたのかを追えなくなります**（`08_money.md` 8-9） |
| **決済端末の集計とPOSの照合** | ⑦店長機能 | A-11 | `【Inference】` 決済手段の入力誤りを見つけるため |
| **翌日の釣銭準備金の用意** | ⑦店長機能 | A-11 | 翌朝の開店に間に合わせるため |
| **売上金の保管または入金** | ⑦店長機能 | A-11 | `【Varies】` 方法は企業により異なる |
| **清掃（厨房・客席・トイレ）** | ⑫清掃・衛生機能 | A-12 | `【Fact】` 施設の清掃は一般的な衛生管理の基準に含まれます（施行規則第66条の2第1項、別表第17） |
| **調理器具・食器の洗浄と消毒** | ⑫清掃・衛生機能 | A-12 | `【Fact】` 機械器具の洗浄・消毒は同基準に含まれます |
| **ごみの分別と搬出** | ⑫清掃・衛生機能 | A-12 | `【Fact】` 事業者は、その事業活動に伴って生じた廃棄物を自らの責任において適正に処理しなければなりません（廃棄物の処理及び清掃に関する法律第3条第1項） |
| **衛生管理の記録の作成と確認** | ⑫清掃・衛生機能／確認は⑦店長機能 | A-12 | `【Fact】` 施行規則第66条の2第3項第3号 |
| **廃棄（ロス）の記録** | ⑧仕込み機能・⑨キッチン機能 | A-L | `【Inference】` 記録しないと、原価率が上がった原因を追えません（`07_goods.md` 7-9） |
| **火元・ガス・電源の確認、戸締り** | ⑫清掃・衛生機能・⑦店長機能 | A-12 | — |
| **日報の作成と本部への送信** | ⑦店長機能 | A-13 | `【Inference】` 日報が遅れると、本部は売上を把握できず、資金繰りの判断も遅れます。**本部の仕事の入力データ**です |

### 日次業務の依存関係

```
 A-1 発注（前日）
      ↓
 A-2 納品・検品 ──→ 検品結果が A-3 の内容を変えることがある
      ↓
 A-3 仕込み ──→ 仕込み量が足りないと、営業中に提供が滞る
      ↓
 A-4 開店準備 ──→ 情報共有がないと、営業中に手戻りが起きる
      ↓
 【営業】
      ↓
 A-11 締め ──→ ここで差異を残すと、翌日以降に原因を追えなくなる
      ↓
 A-12 清掃・衛生記録 ──→ 翌日の営業を始められる状態を作る
      ↓
 A-13 日報 ──→ 本部の月次業務（B系列・給与・店別損益）の入力になる
```

> `【Inference】` **日次業務は直列につながっています。**
> どこか1つが遅れると、その後がすべて遅れます。
> 発注が締切に間に合わなければ翌日の食材が届かず、
> 仕込みが遅れれば開店できず、
> 日報が届かなければ本部の月次業務が進みません。

## 13-3 週次

`【Varies】` 週次で行う業務は、企業により異なります。以下は`【Typical】`な例です。

| 業務 | 誰が | 内容 | なぜこの頻度か |
|---|---|---|---|
| **シフトの作成** | ⑦店長機能 | 希望を集め、必要な人数と時間帯に合わせて組む | `【Varies】` `週次`または`月次`。`【Inference】` 短い周期のほうが客数の見込みに合わせやすく、長い周期のほうが働く人が予定を立てやすい、という関係があります |
| **乾物・調味料・消耗品の発注** | ⑦店長機能 | 生鮮以外の品目 | `【Typical】` 日持ちするためまとめて発注できます（`07_goods.md` 7-2） |
| **酒類の発注** | ⑦店長機能 | `【Varies】` | `【Typical】` 重量物のため配達が前提になりやすい |
| **棚卸**（`【Varies】`） | ⑦店長機能・⑨キッチン機能 | 在庫を数える | `【Varies】` `週次`で行う企業と`月次`のみの企業があります。`【Inference】` 頻度が高いほど、原価のずれに早く気づけます |
| **リネンの交換** | ⑩ホール機能 | おしぼり・マットの回収と受け取り | `【Varies】` `日次`または`週次` |
| **販促の確認** | ⑥販促機能・⑦店長機能 | 掲載内容・口コミ・SNSの確認 | `【Varies】` |
| **売上・客数の週次の確認** | ⑦店長機能 | 日報の集計を週単位で見る | `【Inference】` 曜日ごとの傾向を見るには、週単位で並べる必要があります |
| **設備の点検**（`【Varies】`） | ⑫清掃・衛生機能 | `【Varies】` グリストラップの清掃など | `【Varies】` 店の設備と使用量によります |

## 13-4 月次

### 数字を確定させる業務

| 業務 | 誰が | 工程 | 内容 |
|---|---|---|---|
| **棚卸** | ⑦店長機能・⑨キッチン機能 | A-I | 冷蔵庫・冷凍庫・常温倉庫・**酒類**・仕込み品の実際の在庫を数え、金額に換算する |
| **仕入の締め** | ④経理・財務機能 | B-4 | 仕入先ごとに、締め期間分の仕入金額を集計する |
| **請求書照合** | ④経理・財務機能 | B-5 | 納品書を1枚ずつ請求明細と突き合わせる |
| **支払** | ④経理・財務機能 | B-6 | 振込手続／口座振替の残高確保 |
| **原価の確定** | ④経理・財務機能 | — | 月初在庫＋当月仕入−月末在庫＝当月の食材費 |
| **店別損益の作成** | ④経理・財務機能 | — | 店ごとに売上・F・L・R・その他経費を集計し、**FL比率・FLR比率**を出す |
| **資金繰りの把握** | ④経理・財務機能 | — | 口座の残高が支払の日に足りるかを先読みする |

> **なぜ棚卸が月次業務の起点になるのか**
> `【Typical】` その月の食材費（売上原価）は、**仕入れた金額そのものではありません。**
>
> ```
> 当月の食材費 ＝ 月初の在庫 ＋ 当月の仕入 − 月末の在庫
> ```
>
> `【Inference】` **月末の在庫を数えなければ、この区別ができません。**
> 棚卸が終わらないと原価が確定せず、原価が確定しないと店別損益も出せません
> （`04_end-to-end-process.md` A-I、`12_business-model.md` 12-4）。

`【Varies】` 棚卸の頻度は企業により異なります（`週次`／`月次`／`年次`）。

| **社会保険料の納付** | ④経理・財務機能 | 会社負担分と本人負担分を納める | `【Varies】` `法定・契約上のタイミング` |

## 13-5 四半期・半期

`【Varies】` この周期の業務は企業により大きく異なります。

| 周期 | 業務 | 誰が | 内容 |
|---|---|---|---|
| `四半期` | **季節メニューの入替** | ①メニュー開発機能 | `【Typical】` 旬の食材に合わせてメニューを変える。企画→試作→レシピ化→原価計算→売価決定→店舗への周知 |
| `四半期` | 販促企画の立案・見直し | ⑥販促機能 | `【Typical】` 季節の企画、クーポンの設計 |
| `四半期` | `【Varies】` 消費税の中間申告・納付 | ④経理・財務機能 | `【Varies】` 事業者の状況により回数と時期が異なる。`法定・契約上のタイミング` |
| `半期` | `【Varies】` メニュー全体の見直し | ①メニュー開発機能 | 売れ行きと粗利の両面から見直す |
| `半期` | `【Varies】` 人事の評価・面談 | ⑤人事・労務機能・⑦店長機能 | `【Varies】` 実施の有無・周期は企業により異なる |
| `半期` | `【Varies】` 労働保険の申告・納付 | ⑤人事・労務機能 | `【Varies】` `法定・契約上のタイミング` |

> **季節メニューの入替が四半期になる理由**
> `【Typical】` 食材に旬があるためです。
> `【Inference】` 旬の食材は品質がよく、相場も動きます。
> また、客の側にも季節に応じた期待があります。
> `【Varies】` ただし、入替の周期は業態により異なります
> （`【Typical】` 定番のみで通年同じメニューの店もあります）。

> 施設の整備改善を命じ、または許可の取消し・営業の禁止・停止をすることができます（同法第61条）。
> `【Inference】` したがって、健康被害の訴えは「クレーム対応」ではなく
> **事業の継続に直結する事象**として扱われます（`04_end-to-end-process.md` A-C）。

## 13-8 季節・繁忙期に関する業務

### 飲食業の売上には季節性がある

`【Typical】` 飲食業の売上は、季節・曜日・天候によって変動します。
`【Varies】` 変動の大きさと時期は、業態・立地・客層により異なります。

| 時期 | `【Typical】` 何が起きるか | 影響を受けやすい業態 |
|---|---|---|
| **年末（忘年会シーズン）** | 宴会の予約が集中する | `【Typical】` 居酒屋・宴会対応のある店 |
| **年始（新年会）** | 同上 | 同上 |
| **年度替わり（歓送迎会シーズン）** | 宴会の予約が集中する | 同上 |
| 大型連休 | `【Varies】` 立地により増減が分かれる（`【Inference】` 繁華街・オフィス街では減り、観光地・住宅地では増えることがある） | `【Varies】` |
| 夏 | `【Varies】` 業態により大きく異なる | `【Varies】` |
| 法事・慶事の時期 | `【Varies】` 仕出し・個室利用の需要 | `【Typical】` 料理店・仕出しを行う店 |

### 繁忙期に向けて発生する業務

`【Typical】` 予約が集中する時期には、通常の定期業務とは別に次が発生します。

| 業務 | 誰が | 内容 | 頻度の分類 |
|---|---|---|---|
| **宴会コースの設計** | ①メニュー開発機能 | 人数・予算に応じたコースと飲み放題の内容・価格を決める | `年次`または`案件発生時` |
| **予約の受付体制の準備** | ⑥販促機能・⑦店長機能 | 予約サイトの受付枠の設定／コースの掲載 | `年次` |
| **仕入の事前調整** | ②仕入・調達機能・⑦店長機能 | `【Inference】` 量が増えるため、仕入先に見込みを伝えておく | `案件発生時` |
| **シフトの確保（人数を厚くする）** | ⑦店長機能・⑤人事・労務機能 | `【Inference】` 予約が集中する時間帯に人を揃える | `案件発生時` |
| **`【Varies】` 短期の採用** | ⑤人事・労務機能 | `【Varies】` 繁忙期に合わせて人を増やす企業がある | `案件発生時` |
| **仕込みの前倒し** | ⑧仕込み機能 | `【Inference】` 予約人数が確定している分だけは、先に準備できる | `日次` |
| **無断キャンセルへの備え** | ⑦店長機能 | `【Varies】` キャンセル料の取扱い、予約時の確認 | `案件発生時` |

> **なぜ繁忙期の準備が「前倒しの業務」になるのか**
> `【Inference】` 飲食業の売上には席数×回転数×客単価という天井があります
> （`12_business-model.md` 12-1）。
> 繁忙期に予約が集中しても、**席数は増えません。**
> したがって、増やせるのは
> ①客単価（コースの設計）、②回転（時間帯を分けた予約枠）、
> ③席を使わない売上（仕出し・テイクアウト）の3つです。
> `【Typical】` これらは当日に決められないため、**前もって準備する業務**になります。

### 曜日・天候による変動

`【Typical】` 季節より短い周期でも、売上は変動します。

| 要因 | `【Typical】` 傾向 | どの業務に影響するか |
|---|---|---|
| **曜日** | `【Varies】` 業態・立地により異なる（`【Typical】` 居酒屋は週末に向けて増えることが多い） | ②客数見込み情報→A-1 発注、A-3 仕込み、シフト |
| **天候** | `【Typical】` 雨・雪・台風で来店が減ることがある | 同上。`【Inference】` 仕込みを終えた後に天候が変わると、廃棄が発生し得る |
| **近隣のイベント** | `【Varies】` 増える場合と減る場合がある | 同上 |
| **給料日の前後** | `【Varies】` | `【Varies】` |

> `【Inference】` **これらの変動は、日次の発注・仕込み・シフトの判断に直接影響します。**
> つまり「定期業務」といっても、飲食業の日次業務は
> **毎回同じことを繰り返すのではなく、毎回条件が違う中で判断する業務**です
> （`09_information.md` 9-3）。

`【Varies】` これ以外にも、税務・社会保険に関する期限が存在します。

|---|---|---|

| **定期健康診断** | `【Fact】` **1年以内ごとに1回、定期に** | 労働安全衛生規則第44条第1項 |
| **雇入時の健康診断** | `【Fact】` 常時使用する労働者を**雇い入れるとき** | 労働安全衛生規則第43条 |
| **賃金台帳への記入** | `【Fact】` **賃金支払の都度遅滞なく** | 労働基準法第108条 |
| **労働条件の明示** | `【Fact】` **労働契約の締結に際し** | 労働基準法第15条第1項 |
| **防火管理者の選任・解任の届出** | `【Fact】` 定めたとき（解任したとき）、**遅滞なく** | 消防法第8条第2項 |
| **消防計画の届出** | `【Fact】` 防火管理者が作成し、所轄消防長または消防署長に届け出る | 消防法施行令第3条の2第1項 |
| **衛生管理の実施状況の記録・保存** | `【Fact】` 記録し、保存する（**保存期間は、取り扱う食品が使用・消費されるまでの期間を踏まえ合理的に設定する**） | 食品衛生法施行規則第66条の2第3項第3号 |
| **衛生管理計画・手順書の検証と見直し** | `【Fact】` 効果を検証し、**必要に応じて**内容を見直す | 食品衛生法施行規則第66条の2第3項第4号 |
| **食品衛生責任者の講習会の受講** | `【Fact】` **定期的に受講**し、新たな知見の習得に努める（許可を要する営業に限る） | 食品衛生法施行規則別表第17第1号ハ |
| **労働者名簿・賃金台帳等の保存** | `【Fact】` **5年間**（ただし附則第143条第1項により、**当分の間「3年間」**） | 労働基準法第109条、同法附則第143条第1項 |
| **飲食店営業の許可の更新** | `【Fact】` 許可には有効期間が付される（`【Varies】` 期間は一律ではない） | 食品衛生法第55条 |

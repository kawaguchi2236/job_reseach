# 03_company-structure.md — 典型的な中小飲食企業の姿と組織・機能

> このファイルでは、以降のすべてのファイルで使う**説明用モデル企業**を設定し、
> その中にどんな機能（仕事）があるのかを整理します。
> 部署名ではなく**機能**で整理するのは、中小企業では一人が複数の仕事を兼務するのが普通だからです。
> 出典の詳細は `19_sources.md` を参照してください。

---

## 3-1 説明用モデル企業の設定

> ### ⚠ 必ずお読みください
> `【Example】` **以下のモデル企業「株式会社まるみダイニング」は、本資料を理解するために作った架空の企業です。**
> **実在企業ではなく、また業界の統計的な平均値でもありません。**
> 席数・客単価・従業員数・売上などの数値は、説明を具体的にするために置いた**仮の値**です。
> 実際の企業の姿は、業態・立地・規模により大きく異なります（`【Varies】`）。
> **このモデルの数値を、業界の標準値として引用しないでください。**

### 会社の概要

`【Example】`

| 項目 | 設定 |
|---|---|
| 商号 | 株式会社まるみダイニング |
| 所在地 | 地方中核市（人口30万人規模）の市街地 |
| 事業内容 | 飲食店の経営（居酒屋業態2店舗、カフェ・ランチ業態1店舗） |
| 創業 | 個人商店として創業し、その後法人化。現在は創業から約20年 |
| 資本金 | 1,000万円 |
| 代表者 | 代表取締役（**オーナーシェフ**。調理人としてのキャリアから独立し創業） |
| 店舗数 | **3店舗**（すべて同一市内。車で15〜25分の範囲） |
| 従業員 | 正社員9名／パート・アルバイト38名（合計47名） |
| 年商 | 約3億円 |

`【Fact】` 中小企業基本法（昭和38年法律第154号）第2条において、サービス業の中小企業者は
「資本金5,000万円以下 **または** 常時使用する従業員100人以下」と定義されます
（出典：中小企業基本法／e-Gov法令検索）。
`【Inference】` 上記モデル企業は資本金・従業員数のいずれの基準でも中小企業者に該当します。

### 3店舗の設定

`【Example】`

| | **A店（本店）** | **B店（駅前店）** | **C店（郊外店）** |
|---|---|---|---|
| 業態 | 昼：定食／夜：居酒屋 | 夜：居酒屋中心 | 昼：カフェ・ランチ中心 |
| 席数 | 40席（うち個室8席） | 32席（カウンター10席含む） | 24席 |
| 営業時間 | 11:00–14:30／17:00–23:00 | 17:00–翌1:00 | 8:00–18:00 |
| ラストオーダー | 昼14:00／夜22:15 | 翌0:30 | 17:15 |
| 定休日 | 週1日 | 週1日 | 不定（`【Varies】`） |
| 客単価 | 昼 約900円／夜 約3,200円 | 夜 約3,500円 | 約1,100円 |
| 酒類の比率 | 夜営業では売上の相当部分 | 高い | 低い（提供はするが注文は少ない） |
| テイクアウト | 昼の弁当のみ | なし | あり（ドリンク・焼菓子） |
| デリバリー | プラットフォーム経由（昼のみ） | なし | プラットフォーム経由 |
| 常駐する正社員 | 店長1＋調理社員2 | 店長1＋調理社員1 | 店長1＋調理社員1 |
| パート・アルバイト | 16名 | 13名 | 9名 |

### 従業員の構成

`【Example】`

```
【正社員 9名】
  代表取締役（オーナーシェフ）      1名  ← 本部全般＋A店の厨房にも立つ
  本部スタッフ（経理・総務・労務兼務）1名  ← 代表の配偶者が担当
  店長                            3名  （A店・B店・C店に各1名）
  調理社員                        4名  （A店2名・B店1名・C店1名）

【パート・アルバイト 38名】
  ホール（接客）担当              24名
  キッチン（調理補助・洗い場）担当  14名
```

`【Typical】` 飲食業では、**正社員1人あたりのパート・アルバイト人数が他業種に比べて多い**構成になりがちです。
`【Inference】` これは `02_industry-structure.md` 11-6(4) で説明した「ピークタイムに人が集中して要る」という
構造から来ています。短時間だけ働く人を組み合わせないと、山谷に対応できないためです。

`【Varies】` 正社員とパート・アルバイトの比率は、業態・営業時間・店舗規模により大きく異なります。

## 3-2 組織・機能の全体像（本部機能と店舗機能の二層）

### なぜ「二層」で整理するのか

`【Typical】` 1店舗だけの個人店では、すべての仕事が1つの店の中で完結します。
しかし**2店舗以上になると、「店ごとにやること」と「会社全体で1回だけやればよいこと」が分かれます。**

> `【Example】`（説明用の架空例）
> - メニューの原価計算は、**会社で1回**やればよい（3店舗で同じメニューを出すなら）
> - 今日のホウレンソウの発注は、**店ごと**にやらなければならない（店ごとに在庫も客数も違うため）
>
> 前者が**本部機能**、後者が**店舗機能**です。

`【Varies】` ただし、どこまでを本部に集めるかは企業により異なります。
仕入を本部でまとめる企業もあれば、店長の裁量に任せる企業もあります。
モデル企業では「メニューと仕入先の選定は本部、日々の発注は店舗」という分担にしています（`【Example】`）。

## 3-3 本部機能の詳細

> 以下、各機能について「何のために存在するのか」「誰が担うのか」「何をするのか」を示します。
> `【Varies】` 部署名は企業により異なります。モデル企業では独立した「部」は存在せず、
> **代表取締役と本部スタッフ1名がこれらの機能をすべて分担しています。**

### ① メニュー開発機能

| 項目 | 内容 |
|---|---|
| 一般的な名称 | 商品部、メニュー開発、（中小では）社長直轄・オーナー担当 |
| 存在目的 | `【Typical】` **何を、いくらで売るかを決めるため。** これが決まらなければ、仕入るものも、必要な設備も、必要な人の数も決まりません |
| 誰が担うか | `【Example】` モデル企業では代表取締役（オーナーシェフ）。店長と調理社員が試作に参加 |
| 主な仕事 | 新メニューの企画・試作／**レシピ（分量と手順）の文書化**／**原価計算**／売価の決定／季節メニューの入替／既存メニューの見直し |
| 頻度 | `【Varies】` 季節の入替は`四半期`または`半期`、単発の入替は`案件発生時` |
| なぜ必要か | `【Typical】` レシピを文書化しないと、**作る人が変わると味が変わり、原価も変わります。** 多店舗になるほど文書化が不可欠になります |

> **用語：原価計算（メニューごとの）**
> → 1皿を作るのに、食材がいくらかかるかを計算すること。
> → 実務例：「ハンバーグ定食＝合いびき肉120g×◯円＋玉ねぎ30g×◯円＋米150g×◯円＋…＝合計◯円」。
> → **なぜするのか：** これを計算せずに売価を決めると、**売れば売るほど損をするメニュー**が生まれます。
>   また、実際の原価率が上がったとき、どのメニューが原因かを追えなくなります。

### ② 仕入・調達機能

| 項目 | 内容 |
|---|---|
| 一般的な名称 | 購買、調達、仕入、（中小では）社長直轄 |
| 存在目的 | `【Typical】` **必要な品質の食材を、必要なときに、納得できる価格で手に入る状態を作るため。** |
| 誰が担うか | `【Example】` モデル企業では代表取締役。日々の発注は各店の店長が行う |
| 主な仕事 | 仕入先の選定／価格・配送条件・支払条件の取り決め／新しい食材の探索／相場変動時の対応／仕入先の切替判断 |
| 頻度 | 仕入先の選定・条件見直しは`年次`または`案件発生時`、相場対応は`トラブル発生時` |
| なぜ必要か | `【Typical】` 発注そのものは店でできますが、**「どこから買うか」「いくらで買うか」は会社として決める**必要があります。店ごとにバラバラだと、同じ食材を違う値段で買うことになります |

`【Varies】` 中小飲食企業では、本部で一括発注する形と、店舗が各自で発注する形の両方があります。
`【Typical】` モデル企業では、**取引先と単価は本部が決め、日々の数量は店舗が決める**形をとっています（`【Example】`）。

### ③ 店舗開発機能

| 項目 | 内容 |
|---|---|
| 一般的な名称 | 店舗開発、開発、（中小では）社長直轄 |
| 存在目的 | `【Typical】` **どこに、どんな店を出すかを決めるため。** `02_industry-structure.md` 11-6(2) のとおり、立地は売上をほぼ決めます |
| 誰が担うか | `【Example】` モデル企業では代表取締役が不動産仲介業者・工事業者と直接やりとり |
| 主な仕事 | 物件の情報収集／立地の確認（通行量・周辺人口・競合）／賃料と想定売上の突き合わせ／内装・厨房設備の仕様決定／工事業者の選定／**許可取得のための施設要件の確認**／既存店の改装判断／退店の判断 |
| 頻度 | `案件発生時` |
| なぜ必要か | `【Fact】` 飲食店営業の許可は、都道府県の条例で定める施設基準に適合していなければ受けられません（食品衛生法第54条・第55条）。**設計段階で基準を満たしていないと、工事後にやり直しになります** |

### ④ 経理・財務機能

| 項目 | 内容 |
|---|---|
| 一般的な名称 | 経理部、管理部、（中小では）総務経理・社長の配偶者が担当 |
| 存在目的 | `【Typical】` **お金の出入りを記録し、支払うべきものを支払い、資金が尽きないようにするため。** |
| 誰が担うか | `【Example】` モデル企業では本部スタッフ1名（代表の配偶者）。決算・申告は税理士に委託 |
| 主な仕事 | 各店の日報・売上データの集計／現金の照合／仕入請求書と納品書の突合／**買掛金の管理と支払**／家賃・水道光熱費等の支払／給与支払の準備／**店別損益の作成**／資金繰りの把握／税理士への資料提供 |
| 頻度 | 売上集計は`日次`、請求書照合と支払は`月次`、店別損益は`月次`、決算は`年次` |
| なぜ必要か | `【Typical】` 飲食業は現金の出入りが多く、**現金が合っているかを日々確認しないと、どこでずれたか分からなくなります。** また、支払は月にまとまって発生するため、**入ってくるお金と出ていくお金の時間差**を見ておく必要があります（`08_money.md`） |

### ⑤ 人事・労務機能

| 項目 | 内容 |
|---|---|
| 一般的な名称 | 人事部、総務部、管理部、（中小では）総務経理が兼務 |
| 存在目的 | `【Typical】` **必要な時間に、必要な人数が店にいる状態を作り、その対価を正しく払うため。** |
| 誰が担うか | `【Example】` モデル企業では本部スタッフ1名。採用面接は店長も行う |
| 主な仕事 | 求人の掲載／面接・採用／**雇用契約書の作成**／勤怠の集計／**給与計算（深夜割増・残業割増を含む）**／社会保険・雇用保険の手続／年末調整の準備／教育の枠組み作り |
| 頻度 | 採用は`案件発生時`、勤怠集計と給与計算は`月次`、社会保険手続は`法定・契約上のタイミング` |
| なぜ必要か | `【Fact】` 深夜（午後10時から午前5時まで）に労働させた場合、通常の賃金の2割5分以上の割増賃金の支払いが必要です（労働基準法第37条第4項）。`【Inference】` 夜営業のある飲食業では、この計算が毎月発生します |

### ⑥ 販促機能

| 項目 | 内容 |
|---|---|
| 一般的な名称 | 販売促進、マーケティング、（中小では）社長・店長が兼務 |
| 存在目的 | `【Typical】` **店の存在と内容を客に知らせ、来店・予約につなげるため。** |
| 誰が担うか | `【Example】` モデル企業では代表取締役と各店の店長が分担 |
| 主な仕事 | グルメサイト・予約サイトの掲載内容の管理／SNS・自社サイトの更新／店頭の看板・のぼりの管理／季節の販促企画／クーポンの設計／予約導線の確認／口コミへの対応 |
| 頻度 | 掲載内容の更新は`月次`または`案件発生時`、販促企画は`四半期`（季節の切り替わりに合わせる `【Typical】`）、口コミ対応は`問い合わせ時` |
| なぜ必要か | `【Typical】` `02_industry-structure.md` 11-1(3) のとおり、客が店を探す入口はグルメサイト・地図アプリ・SNSに移っています。**掲載情報（営業時間・定休日・メニュー・写真）が古いままだと、来店の機会を失います** |

## 3-4 店舗機能の詳細

### ⑦ 店長（店舗運営）機能

| 項目 | 内容 |
|---|---|
| 一般的な名称 | 店長、店舗責任者、マネージャー |
| 存在目的 | `【Typical】` **その店の1営業日を成立させ、目標とする売上と利益を出すため。** 本部の方針を、その店の実情に合わせて実行に落とす役割です |
| 誰が担うか | `【Example】` モデル企業では各店に正社員の店長1名 |
| 主な仕事 | 当日の売上目標と人員配置の確認／**発注の確定**／在庫の確認／仕込み量の指示／シフトの作成と当日の欠員対応／クレームの一次対応／**レジ締め・現金の確認**／日報の作成／衛生管理の記録の確認／本部への報告 |
| 頻度 | 発注は`日次`（`【Varies】` 品目により週次のものもある）、シフト作成は`週次`または`月次`、締めと日報は`日次` |
| なぜ必要か | `【Typical】` 店の中では、キッチンとホールと会計が同時に動いています。**誰か1人が全体を見て判断しないと、どこかが詰まったときに止まります。** 店長はその「全体を見る人」です |

> **店長機能が扱う判断の例**
> `【Example】`（説明用の架空例）
> - 「予約が急にキャンセルされた。仕込んだ分をどうするか」→ 当日のおすすめとして出す判断
> - 「アルバイトが1人来られなくなった」→ 他の人に連絡する／自分が入る判断
> - 「野菜の入荷が悪く、いつもの品が入らない」→ メニューを差し替える／数量限定にする判断
>
> これらはマニュアルに書ききれないため、**その場で判断できる人が店にいる必要があります。**

### ⑧ 仕込み機能

| 項目 | 内容 |
|---|---|
| 一般的な名称 | 仕込み、下ごしらえ、プレップ |
| 存在目的 | `【Typical】` **注文が入ってから提供するまでの時間を短くするため。** 時間のかかる工程を営業時間の外へ出しておく仕事です |
| 誰が担うか | `【Example】` モデル企業では調理社員が中心。キッチン担当のアルバイトが補助 |
| 主な仕事 | 野菜の洗浄・カット／肉・魚の下処理／だし・スープ・タレ・ソースの作成／煮込み／揚げ物の下ごしらえ／ご飯の炊飯／**仕込み量の決定**／仕込み品の保管とラベル貼り |
| 頻度 | `日次`（開店前が中心。品目により`週次`のものもある `【Varies】`） |
| インプット | 納品された食材／前日の売上実績／当日の予約状況／天候・曜日の情報 |
| アウトプット | 使える状態になった食材（仕込み品）／仕込み記録 |
| なぜ必要か | `【Typical】` 煮込みに2時間かかる料理を、注文後に作り始めることはできません。**仕込みは「時間を前倒しで買う」工程**です |

> **仕込み量の判断がなぜ難しいのか**
> `【Inference】` 多く仕込めば廃棄（ロス）になり、少なく仕込めば品切れで売る機会を失います。
> しかも判断材料は不確実です（天気は変わる、予約はキャンセルされる、団体が飛び込みで来る）。
> `【Typical】` だから実務では、前年の同時期・前週の同曜日の実績、当日の予約件数、天気予報を
> 見比べて決めます。この判断は店長または調理責任者が行います。

### ⑨ キッチン（調理）機能

| 項目 | 内容 |
|---|---|
| 一般的な名称 | 厨房、キッチン、調理場 |
| 存在目的 | `【Typical】` **注文を受けた料理を、決められた品質で、できるだけ早く仕上げて出すため。** |
| 誰が担うか | `【Example】` モデル企業では調理社員とキッチン担当アルバイト |
| 主な仕事 | オーダー（注文伝票）の確認／調理／盛り付け／**提供順序の管理**／仕上がりの品質確認／食材の残量把握と店長への連絡／調理器具の洗浄 |
| 頻度 | `常時`（営業中） |
| なぜ必要か | — |

> **「提供順序の管理」がなぜ重要か**
> `【Typical】` 同じテーブルの料理は、**できるだけ同時に出す**必要があります。
> また、先に注文した客より後から来た客に先に出すわけにはいきません。
> ところが、料理によって調理時間はバラバラです（刺身は数分、煮込みは長い、揚げ物は中程度）。
> `【Inference】` そこでキッチンは、**複数のオーダーを同時に見ながら、
> 逆算して作り始める順番を決めています。** これが飲食業の調理の難しさの中心です。

### ⑩ ホール（接客）機能

| 項目 | 内容 |
|---|---|
| 一般的な名称 | ホール、フロア、サービス |
| 存在目的 | `【Typical】` **客が席に着いてから帰るまでの体験をつくり、注文を正確に厨房へ伝えるため。** |
| 誰が担うか | `【Example】` モデル企業ではホール担当アルバイトが中心。店長が全体を見る |
| 主な仕事 | 出迎え・席への案内／おしぼり・水の提供／メニューの説明／**注文（オーダー）を受けて厨房へ通す**／料理・飲み物の提供／追加注文の確認／下膳（食器を下げる）／テーブルの清掃と席の準備／見送り |
| 頻度 | `常時`（営業中） |
| なぜ必要か | `【Typical】` 客が直接接するのはホールの担当者です。**料理がよくても接客で評価が決まることがあります。** また、注文の聞き間違い・伝え間違いは、そのまま食材のロスと客の不満になります |

> **用語：オーダーを「通す」**
> → 客から受けた注文を、厨房が作業できる形で伝えること。
> → 実務例：ハンディ端末（注文を入力する小型の機械）でキッチンのプリンタに伝票を出す／
>   伝票を厨房に持って行く／口頭で復唱して伝える。
> → **なぜ「通す」という言い方をするのか：** 注文はホールから厨房へ**一方向に流れて確定する**ためです。
>   通し忘れ・二重通しは、提供漏れや作りすぎに直結します。

> **アレルギー・苦手な食材への対応**
> `【Typical】` 客からアレルギーの申し出があった場合、ホールは必ず厨房に伝え、
> 厨房は使用食材と調理器具の使い回しを確認します。
> `【Inference】` これは接客の丁寧さの問題ではなく、**客の生命に関わる情報伝達**です。
> 伝達経路が曖昧な店では事故が起こり得ます。

### ⑪ レジ・会計機能

| 項目 | 内容 |
|---|---|
| 一般的な名称 | レジ、会計、キャッシャー |
| 存在目的 | `【Typical】` **提供した料理・飲み物の代金を、正確にその場で回収するため。** |
| 誰が担うか | `【Example】` モデル企業ではホール担当者または店長 |
| 主な仕事 | 伝票内容の確認と合計／**決済手段への対応**（現金・クレジットカード・電子マネー・コード決済）／釣銭の受渡し／レシート・領収書の発行／割引・クーポンの適用／**釣銭準備金の管理**／レジ締め |
| 頻度 | 会計は`常時`（営業中）、レジ締めは`日次` |
| なぜ必要か | `【Typical】` 飲食業は**その場で代金を回収する**（`01_overview.md` 1-4）ため、ここで取り損ねると回収の機会がありません |

> **用語：レジ締め**
> → 営業終了後に、**レジの中の現金と、システム上の売上記録が一致するかを確認する**こと。
> → 実務例：POSが「本日の現金売上118,400円」と表示しているとき、
>   レジの中の現金から釣銭準備金を引いた額が118,400円になるかを数えて確認する。
> → **なぜするのか：** 一致しない場合、釣銭の渡し間違い・打ち間違い・記録漏れのいずれかが起きています。
>   **毎日確認しないと、どの日にずれたのか分からなくなります。**

### ⑫ 清掃・衛生機能

| 項目 | 内容 |
|---|---|
| 一般的な名称 | 清掃、衛生管理 |
| 存在目的 | `【Fact】` **食品衛生法が定める衛生管理の基準を守り、食中毒・異物混入を防ぐため。** これは店の判断で省略できる仕事ではありません |
| 誰が担うか | `【Example】` モデル企業では全従業員が分担。記録の確認は店長（食品衛生責任者）が行う |
| 主な仕事 | 厨房・客席・トイレの清掃／調理器具・食器の洗浄と消毒／手洗い／**冷蔵庫・冷凍庫の温度確認と記録**／**害虫・害獣の対策**／ごみの分別と搬出／グリストラップの清掃／ダクトの清掃（業者委託 `【Varies】`）／**衛生管理の記録の作成と保存** |
| 頻度 | 清掃・手洗い・温度確認は`日次`または`常時`、ダクト清掃等は`【Varies】` |

`【Fact】` 食品衛生法第51条第1項は、営業施設の衛生的な管理その他公衆衛生上必要な措置について、
厚生労働省令で基準を定めることとしています。
`【Fact】` その基準は食品衛生法施行規則の**別表第17**（一般的な衛生管理）に定められ、
施設の清掃、内壁・天井・床の清潔維持、採光・照明・換気、便所の清掃と消毒、
手洗設備に石けん・ペーパータオル等および消毒剤を備えること、
機械器具の洗浄・消毒などが列挙されています
（食品衛生法施行規則第66条の2第1項、別表第17）。
`【Fact】` 同法第51条第2項により、**営業者はこの基準に従い、公衆衛生上必要な措置を定め、遵守しなければなりません。**

## 3-5 必置ポジション（置かないと営業できない役割）

飲食店には、**法令により置くことが義務づけられている役割**があります。
これは「機能」ではなく「特定の人を指名する義務」です。

---

### (1) 食品衛生責任者

| 項目 | 内容 |
|---|---|
| 何か | `【Fact】` 営業者が、その施設ごとに定めなければならない衛生管理の責任者 |
| 根拠 | `【Fact】` 食品衛生法第51条第1項第1号・第2項／食品衛生法施行規則第66条の2第1項・**別表第17第1号イ**（出典：e-Gov法令検索） |
| 誰がなれるか | `【Fact】` 別表第17第1号ロにより、次のいずれかに該当する者<br>(1) 食品衛生監視員または食品衛生管理者の資格要件を満たす者<br>(2) **調理師、製菓衛生師、栄養士、管理栄養士、船舶料理士**、と畜場法に規定する衛生管理責任者・作業衛生責任者、食鳥処理衛生管理者<br>(3) **都道府県知事等が行う講習会、または都道府県知事等が適正と認める講習会を受講した者** |
| 何をするか | `【Fact】` 別表第17第1号ハ・ホにより、①都道府県知事等が行う（または認める）講習会を定期的に受講し、食品衛生に関する新たな知見の習得に努めること（許可を要する営業に限る）、②営業者の指示に従い衛生管理に当たること、③衛生管理の措置の遵守のために必要な注意を行い、営業者に対し必要な意見を述べるよう努めること |
| 営業者側の義務 | `【Fact】` 別表第17第1号ニにより、**営業者は食品衛生責任者の意見を尊重**しなければなりません |
| 申請書への記載 | `【Fact】` 営業許可の申請書には、食品衛生管理者または**食品衛生責任者の氏名、資格の種類、受講した講習会**を記載します（食品衛生法施行規則第67条第4号） |

> **初心者が誤解しやすい点**
> `【Fact】` 「食品衛生**責任者**」と「食品衛生**管理者**」は別の制度です。
> 食品衛生管理者は、食肉製品・乳製品など特定の食品を製造・加工する施設に置く専門職（食品衛生法第48条）で、
> 一般の飲食店に求められるのは**食品衛生責任者**のほうです。
> `【Fact】` なお、食品衛生管理者は食品衛生責任者を兼ねることができます（別表第17第1号イ）。

> `【Typical】` 実務上は、**店舗ごとに1名**、店長または調理責任者が食品衛生責任者になっていることが多くみられます。
> `【Example】` モデル企業では、A店・B店・C店それぞれの店長が食品衛生責任者を務め、
> 代表取締役も調理師免許を持つため資格要件を満たしている、という設定にしています。

### (2) 防火管理者

| 項目 | 内容 |
|---|---|
| 何か | `【Fact】` 一定規模以上の防火対象物について、管理権原者が定めなければならない防火管理の責任者 |
| 根拠 | `【Fact】` 消防法第8条第1項（出典：e-Gov法令検索） |
| 対象となる飲食店 | `【Fact】` 消防法施行令別表第一**（三）項ロが「飲食店」**にあたり、同令第1条の2第3項第1号ロにより、<br>**（一）項から（四）項までの防火対象物で、収容人員が30人以上のもの**が防火管理者の選任対象です<br>（収容人員＝当該防火対象物に出入し、勤務し、または居住する者の数。算定方法は総務省令で定める：同条第4項） |
| 資格の区分 | `【Fact】` 消防法施行令第3条第1項により、<br>・**乙種**：（一）〜（四）項等の防火対象物で**延べ面積300平方メートル未満**のもの（乙種防火管理講習の課程を修了した者ほか）<br>・**甲種**：それ以外（甲種防火管理講習の課程を修了した者、所定の学科を修めて卒業し1年以上の実務経験を有する者ほか）<br>いずれも、当該防火対象物において防火管理上必要な業務を適切に遂行できる**管理的または監督的な地位にある者**であることが必要 |
| 何をするか | `【Fact】` 消防法第8条第1項により、**消防計画の作成**、消防計画に基づく**消火・通報・避難の訓練の実施**、消防用設備等の**点検・整備**、火気の使用・取扱いに関する**監督**、避難・防火上必要な構造・設備の維持管理、**収容人員の管理**その他防火管理上必要な業務 |
| 届出 | `【Fact】` 管理権原者は、防火管理者を定めたとき（および解任したとき）、遅滞なくその旨を所轄消防長または消防署長に**届け出**なければなりません（消防法第8条第2項）<br>`【Fact】` 防火管理者は、消防計画を作成し所轄消防長または消防署長に**届け出**なければなりません（消防法施行令第3条の2第1項） |

> `【Example】` モデル企業では、席数40席のA店と32席のB店は収容人員30人以上に該当するものとし、
> 各店長が防火管理者となる設定にしています。
> `【Varies】` C店（24席）については、収容人員の算定結果により該当・非該当が分かれるため、
> 実際には所轄消防署に確認することになります。
> **収容人員は席数と同じではなく、従業員を含めて総務省令の算定方法により求めます。**

### (3) その他、業態により必要になる手続

| 手続 | 誰に | いつ必要か | 根拠 |
|---|---|---|---|
| **飲食店営業の許可** | 都道府県知事等（保健所） | `【Fact】` 飲食店営業を営もうとするとき（食品衛生法施行令第35条第1号が許可対象業種として飲食店営業を掲げる） | `【Fact】` 食品衛生法第54条・第55条 |
| **深夜における酒類提供飲食店営業の届出** | 公安委員会（警察署経由） | `【Fact】` 酒類提供飲食店営業を**深夜（午前0時から午前6時まで）**に営もうとするとき | `【Fact】` 風俗営業等の規制及び業務の適正化等に関する法律第33条第1項（深夜の定義は同法第13条第1項） |
| **酒類の販売業免許** | 所轄税務署長 | `【Fact】` 酒類の**販売業**をしようとするとき。ただし**「酒場、料理店その他酒類をもつぱら自己の営業場において飲用に供する業」については免許を要しない** | `【Fact】` 酒税法第9条第1項ただし書 |

> **初心者が最もつまずく点：店で酒を出すのに免許は要るのか？**
> `【Fact】` **店内で客に飲ませるだけなら、酒類販売業免許は要りません**（酒税法第9条第1項ただし書）。
> `【Inference】` 一方、**未開栓の酒を持ち帰り用に売る**行為は「販売業」にあたるため、
> 販売業免許が必要になります。
> **「店内で飲ませる」と「容器のまま売る」は、酒税法上まったく別の行為**です。
> `【Example】` モデル企業のB店（居酒屋）は店内提供のみのため免許不要、
> C店で瓶ワインを持ち帰り販売する場合には免許の取得が必要になる、という整理になります。

> **深夜営業の注意**
> `【Fact】` 風営法上の「深夜」は**午前0時から午前6時まで**です（同法第13条第1項）。
> `【Example】` モデル企業のB店は翌1:00まで営業し酒類を提供するため、第33条第1項の届出が必要です。
> A店（23:00閉店）とC店（18:00閉店）は該当しません。
> `【Fact】` また、同法第33条第4項により、都道府県は条例で地域を定めて、深夜の酒類提供飲食店営業を
> 禁止することができます。**営業できるかどうかは所在地の条例によります。**

## 3-6 中小飲食企業の実態：機能はあるが、担当者は分かれていない

ここまで12の機能に分けて説明しましたが、**これは「12の部署がある」という意味ではありません。**

`【Typical】` 実際の中小飲食企業、とくに個人経営の店では、次のような状態がごく普通です。

```
【1店舗の個人経営店（オーナーシェフ）の場合】

  ① メニュー開発  ─┐
  ② 仕入・調達    ─┤
  ③ 店舗開発      ─┤
  ④ 経理・財務    ─┤
  ⑤ 人事・労務    ─┼──→  すべて オーナーシェフ 1人
  ⑥ 販促          ─┤      （＋家族が④⑤を手伝う）
  ⑦ 店舗運営      ─┤
  ⑧ 仕込み        ─┤
  ⑨ 調理          ─┘
  ⑩ ホール        ──→  アルバイト（＋オーナー）
  ⑪ レジ・会計    ──→  オーナーまたはアルバイト
  ⑫ 清掃・衛生    ──→  全員で分担、記録はオーナー
```

`【Fact】` `01_overview.md` 1-7 のとおり、2021年6月1日現在、飲食店（中分類76）の民営事業所499,176のうち
**個人経営は311,574事業所（62.4％）**、個人経営の事業所1か所あたりの従業者数は約3.0人です
（出典：令和3年経済センサス‐活動調査／総務省・経済産業省）。

`【Inference】` 3人しかいない店に、12の部署は作れません。
**しかし12の仕事はすべて発生します。** 発注もするし、給与も計算するし、衛生記録もつけます。

> **だから本資料は「機能」で整理しています。**
> 「営業部がある」ではなく「顧客対応という機能が必ず存在する」と考えるのと同じで、
> 飲食業でも「メニュー開発部がある」ではなく
> **「何をいくらで売るかを決める仕事が必ず存在し、誰かがやっている」**と読んでください。

`【Typical】` モデル企業（3店舗・正社員9名）は、この「全部1人」の状態から少し進み、
**本部に2名（代表＋本部スタッフ）を置いて、店から本部機能を切り出した段階**にあたります。
それでも、代表取締役は①②③⑥を1人で担い、さらにA店の厨房にも立ちます（`【Example】`）。

## 3-7 店舗間・本部間で受け渡されるもの（概要）

`【Typical】` 詳細は `05_departments.md` `09_information.md` で扱いますが、
本部と店舗の間で日常的に往復する情報は次のとおりです。

```
【本部 → 店舗】
  ・メニューとレシピ（何を、どう作るか）
  ・売価（いくらで売るか）
  ・仕入先と単価（どこから、いくらで買うか）
  ・販促の内容（今月の企画、クーポン）
  ・人件費の枠（今月のシフトに使える時間の目安）
  ・衛生管理の様式（記録する用紙・項目）

【店舗 → 本部】
  ・日報（売上、客数、客単価、現金の過不足）
  ・売上データ（POSの集計）
  ・発注・納品の情報（何をいくら仕入れたか）
  ・在庫・棚卸の結果
  ・勤怠（誰が何時間働いたか）
  ・廃棄（ロス）の記録
  ・クレーム・客の声
  ・設備の不具合（冷蔵庫の異音、水漏れ など）
```

`【Inference】` このうち**日報と勤怠は、遅れると後工程（経理・給与計算）が止まります。**
`【Typical】` そのため、日報は`日次`、勤怠は`月次`の締めに合わせて提出されるのが一般的です。

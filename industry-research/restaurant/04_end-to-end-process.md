## 4-0 前提：飲食業のフローは「受注→納品→請求→入金」ではない

### 他業界との決定的な違い

多くの業界（製造業・卸売業・建設業など）の業務フローは、次の形で説明されます。

```
【一般的な BtoB のフロー】
  引合 → 見積 → 受注 → 生産/手配 → 納品 → 検収 → 請求 → 入金
                                                      ↑
                                        ここまで1〜3か月かかることも
```

**飲食業のフローはこの形になりません。** 飲食業では次のようになります。

```
【飲食業のフロー】
  仕入 → 仕込み → （客が来る）→ 注文 → 調理 → 提供 → 即時決済
                                                      ↑
                                          注文から数分〜数十分で完結
```

### 何が違うのか（5つの違い）

| | 一般的なBtoBのフロー | 飲食業のフロー |
|---|---|---|
| **順番** | 注文を受けてから材料を手配する | **注文を受ける前に食材を仕入れ、仕込んでおく**（`【Typical】`） |
| **見積** | 見積を出し、合意してから始まる | **メニューに価格が書いてある**。都度の見積はない（宴会・仕出し等を除く `【Varies】`） |
| **受注の確定** | 注文書・契約書で確定する | **口頭の注文で確定する**。書面の契約はない |
| **代金の回収** | 納品後に請求書を出し、後日入金 | **その場で回収する**（売掛金が発生しない） |
| **所要時間** | 数日〜数か月 | **数分〜数十分** |

> **だから飲食業には「売掛金」がほとんどありません。**
> `【Typical】` 売掛金とは「売上は立ったが、まだ入金されていないお金」のことです。
> 飲食業では料理を出したその場で代金を受け取るため、この状態がほとんど生じません。
> `【Varies】` ただし、法人向けの宴会・仕出しで請求書払いにする場合や、
> クレジットカード・コード決済（決済事業者から後日入金される）では、
> **入金までの時間差が生じます**（`08_money.md` で扱います）。

### だから2本のサイクルを並べて見る必要がある

`【Inference】` 飲食業では、**代金を「受け取る」流れと「払う」流れの速度がまったく違います。**

```
【A. 営業サイクル】客からお金を受け取るまで  ─── 速い（当日で完結）
   発注 → 納品 → 仕込み → 提供 → 即時決済

【B. 支払サイクル】仕入先にお金を払うまで    ─── 遅い（翌月以降）
   発注 → 納品 → 仕入計上 → 締め → 請求書照合 → 支払
```

この2本を**別々に理解してから重ねる**のが、飲食業のお金の流れを掴む近道です。
以下、A と B を順に見ていきます。

### 本ファイルの表記について

`【Fact】` 本プロジェクトでは業務頻度の語彙を共通化しています（`common/methodology.md` §5）。
飲食業固有のタイミングは、次のように共通語彙に対応させて表記します。

| 飲食業での言い方 | 本資料での表記 |
|---|---|
| 客が来店したとき | `常時`（営業中に随時発生するため） |
| 客から注文を受けたとき | `受注時` |
| 代金を受け取るとき | `入金時` |
| 食材が届いたとき | `納品時` |
| 仕入先に発注するとき | `発注時` |

> `【Fact】` また、本ファイルでは**「何時に何をする」という時刻表は作りません。**
> 開店時刻・ピーク時刻・閉店時刻は業態と店舗により大きく異なるためです（`【Varies】`）。
> 代わりに **「開店前 → 営業中 → 閉店後」という工程の順序**として記述します。

### A-1 発注

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | `【Typical】` 在庫の残量と、翌日以降の見込み客数（予約状況・曜日・天候）を確認したとき |
| **誰が行うか** | ⑦店長機能（`【Varies】` 中小では店主・調理責任者が行う場合もある） |
| **何を受け取るか** | 在庫の状況／前日までの売上実績／予約情報／天気予報／本部が決めた仕入先と単価（②仕入・調達機能から） |
| **何を確認するか** | ①今ある在庫量　②翌日以降に必要な量　③仕入先ごとの発注締切時刻　④相場や欠品の情報 |
| **何をするか** | 品目ごとに発注数量を決め、仕入先へ伝える（電話・FAX・発注システム・営業担当への口頭 `【Varies】`） |
| **何を判断するか** | **どれだけ持つか。** 多く持てば廃棄になり、少なく持てば品切れになる（`02_industry-structure.md` 11-6(3)） |
| **誰と連携するか** | 社内：⑧仕込み機能・⑨キッチン機能（在庫と使用量の情報）／社外：食材卸・酒類卸・産地 |
| **何が出来上がるか** | **発注情報**（何を・いくつ・いつ届けてもらうか） |
| **次に誰へ渡すか** | 仕入先（社外）→ 翌日の A-2 納品・検品へ |
| **頻度** | `日次`（生鮮）／`週次`（乾物・調味料・消耗品 `【Varies】`）／`発注時` |

> **なぜ毎日発注するのか**
> `【Typical】` 生鮮食材は数日しか持たないため、まとめ買いができません（`02_industry-structure.md` 11-4）。
> 「今日使う分を昨日発注する」というサイクルが、飲食業の基本形になります。

> `【Example】`（説明用の架空例）モデル企業A店の店長が、翌日の発注を決める場面。
> 「明日は金曜で、夜の早い時間に12名の予約が1件入っている。先週の同曜日の客数は夜だけで68名。
>  天気は晴れ。鶏もも肉は在庫が3kgあるので追加は5kg。生ビールの樽は残り1本なので2本。
>  刺身用の魚は、市場の入荷を見てから決めるので、卸の担当者に朝連絡する」

### A-2 納品・検品

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 仕入先が食材を届けたとき |
| **誰が行うか** | ⑦店長機能または⑨キッチン機能（`【Varies】` 開店前に店にいる人が受ける） |
| **何を受け取るか** | **食材（モノ）** と **納品書（書類）** |
| **何を確認するか** | ①**品目と数量が発注どおりか**　②**鮮度・状態に問題がないか**（傷み・変色・臭い・パッケージの破損）　③**温度**（冷蔵・冷凍品が適切な温度で届いたか）　④賞味期限・消費期限　⑤納品書の単価・金額 |
| **何をするか** | 現物と納品書を突き合わせ、問題があればその場で仕入先に伝える。問題がなければ受け取り、**すぐに適切な温度帯へ収納する**（冷蔵・冷凍・常温） |
| **何を判断するか** | **受け取るか、返品・交換を求めるか。** 受け取った後では言えないため、その場で判断する |
| **誰と連携するか** | 社外：仕入先の配送担当／社内：④経理・財務機能（納品書を回す） |
| **何が出来上がるか** | 使える状態の在庫／**検品済みの納品書**／（必要に応じて）**温度の記録** |
| **次に誰へ渡すか** | 在庫 → A-3 仕込みへ。納品書 → B-3 仕入計上へ（④経理・財務機能） |
| **頻度** | `日次`（生鮮）／`納品時` |

> **なぜ「その場で」検品するのか**
> `【Typical】` 配送担当者は複数店を回るため、その場を離れると確認ができません。
> `【Inference】` また、傷んだ食材をそのまま受け取って冷蔵庫に入れてしまうと、
> **後から「元々傷んでいたのか、店で傷めたのか」が分からなくなります。**
> `【Fact】` 温度の確認と記録は、後述する衛生管理計画の中に位置づけられる場合があります。

> **初心者がつまずく点：納品書 ≠ 請求書**
> - **納品書**＝「これを届けました」という、モノに添えられる書類。**届いた都度**もらう
> - **請求書**＝「この期間分の合計はこれです」という、お金を請求する書類。**締めた後**にもらう
>
> `【Typical】` 飲食業では毎日納品があるため、納品書は毎日たまり、請求書は月に1枚来る、
> という形になるのが一般的です（`【Varies】` 締めのサイクルは取引先により異なる）。

### A-3 仕込み

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 食材の納品が済み、開店までに時間があるとき |
| **誰が行うか** | ⑧仕込み機能（調理社員が中心、キッチン担当が補助） |
| **何を受け取るか** | 検品済みの食材／前日の残った仕込み品／レシピ（①メニュー開発機能から）／当日の予約情報／店長からの仕込み量の指示 |
| **何を確認するか** | ①前日の仕込み品の残量と状態　②今日出す予定のメニュー　③予約の内容（コース・アレルギー対応の有無）　④先に使うべき食材（先入先出） |
| **何をするか** | 野菜の洗浄・カット／肉・魚の下処理／だし・スープ・タレ・ソースの作成／煮込み／揚げ物の下ごしらえ／炊飯／**仕込み品に日付を書いて保管** |
| **何を判断するか** | **どれだけ仕込むか。** 前週同曜日の実績・予約・天候から見込む |
| **誰と連携するか** | ⑦店長機能（仕込み量の判断）／⑨キッチン機能（営業中に使う） |
| **何が出来上がるか** | **仕込み品**（注文が来たらすぐ仕上げられる状態の半製品）／仕込みの記録 |
| **次に誰へ渡すか** | ⑨キッチン機能（A-7 調理） |
| **頻度** | `日次`（`【Varies】` 品目により`週次`のものもある） |

> **なぜ前もって作るのか（この工程が飲食業の中核である理由）**
> `【Typical】` 客は席に着いてから料理が出るまで、長くは待ちません。
> ところが実際の調理には時間がかかります。
>
> `【Example】`（説明用の架空例）「牛すじの煮込み」を注文後に一から作ると、
> 下茹で30分＋煮込み2時間＝2時間半かかります。客は待てません。
> そこで**開店前に煮込んでおき、注文時は温めて器に盛るだけ（2〜3分）**にします。
>
> `【Inference】` つまり仕込みとは、**営業時間内にできない作業を、営業時間外へ移す工程**です。
> 仕込みが不足すると営業中に提供が滞り、仕込みが過剰だと廃棄になります。
> **仕込み量の判断は、その日の利益を左右する判断**です。

> **先入先出（さきいれさきだし）**
> → 先に入ってきたものから先に使うこと。
> → 実務例：冷蔵庫の中で、古い日付のものを手前に、新しいものを奥に置く。
> → **なぜするのか：** 新しいものから使うと、**古いものがいつまでも残り、最後は廃棄になる**ためです。
>   仕込み品に日付を書くのは、これを目で判断できるようにするためです。

### A-4 開店準備

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 仕込みが一段落し、開店時刻が近づいたとき |
| **誰が行うか** | ⑩ホール機能・⑦店長機能・⑫清掃・衛生機能 |
| **何を受け取るか** | 当日の予約情報／当日のメニュー（品切れ・おすすめの情報）／釣銭準備金 |
| **何を確認するか** | ①客席・トイレの清掃状態　②テーブルセッティング（箸・調味料・おしぼり）　③**釣銭の額**　④POS・決済端末が動くか　⑤予約席の配置　⑥品切れ・本日のおすすめの共有　⑦**冷蔵庫・冷凍庫の温度**　⑧従業員の健康状態と手洗い |
| **何をするか** | 清掃の仕上げ／テーブルセッティング／レジに釣銭をセット／予約席に札を置く／**朝礼的な情報共有**（品切れ・予約・その日の重点） |
| **何を判断するか** | 開店できる状態になっているか。不備があれば開店を遅らせるか、対応しながら開けるか |
| **誰と連携するか** | ⑨キッチン機能（品切れ情報）／⑪レジ・会計機能（釣銭） |
| **何が出来上がるか** | **営業を開始できる状態の店**／衛生管理の記録（温度・健康状態など） |
| **次に誰へ渡すか** | A-5 以降、営業中の全機能 |
| **頻度** | `日次` |

> **なぜ品切れ情報を共有するのか**
> `【Inference】` ホールが品切れを知らずに注文を受けてしまうと、
> **客に謝って注文を取り直す**ことになり、客の満足度と提供の流れの両方が損なわれます。
> 開店前の共有は、この手戻りを防ぐための工程です。

### A-5 来店・案内

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 客が来店したとき（予約客・飛び込み客の両方） |
| **誰が行うか** | ⑩ホール機能 |
| **何を受け取るか** | 客の人数／予約の有無／席や時間の希望 |
| **何を確認するか** | ①人数　②予約かどうか（予約なら予約表と照合）　③喫煙・禁煙、個室・カウンター等の希望　④**満席のときの待ち時間** |
| **何をするか** | 出迎え／席へ案内／おしぼり・水を出す／メニューを渡す／（満席時）待ち客の記録と案内 |
| **何を判断するか** | **どの席に案内するか。** 人数と席の組み合わせ、次の予約の時間、回転の見込みを考える |
| **誰と連携するか** | ⑦店長機能（満席時・団体客の判断） |
| **何が出来上がるか** | **着席した客**／テーブル番号と客数の記録（POS入力） |
| **次に誰へ渡すか** | A-6 注文へ |
| **頻度** | `常時`（営業中） |

> **席への案内が売上に直結する理由**
> `【Inference】` 2名客を6人掛けテーブルに案内すると、その後に来る6名客を断ることになります。
> `【Typical】` ホールは、**今いる客・待っている客・これから来る予約客**を同時に考えながら
> 席を割り当てています。これが `01_overview.md` 1-5 の「回転数」を作る実務です。

### A-6 注文（オーダー）

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 客が注文を決め、呼ばれたとき |
| **誰が行うか** | ⑩ホール機能（`【Varies】` セルフ業態では券売機・タブレット・モバイルオーダーが担う） |
| **何を受け取るか** | 客からの注文内容／アレルギー・苦手食材の申し出／取り分けや提供タイミングの希望 |
| **何を確認するか** | ①品名と数量　②**アレルギー・食材の除去の有無**　③焼き加減・辛さ等の指定　④**提供のタイミングの希望**（「まずドリンクだけ」「料理は後で」）　⑤品切れでないか |
| **何をするか** | 注文を聞き、**復唱して確認**し、厨房へ**通す** |
| **何を判断するか** | 提供の順序をどうするか。人数に対して量が多すぎないか（必要なら助言する） |
| **誰と連携するか** | ⑨キッチン機能（オーダーを渡す）／⑪レジ・会計機能（伝票に記録される） |
| **何が出来上がるか** | **オーダー（注文伝票）**／POS上の売上予定データ |
| **次に誰へ渡すか** | ⑨キッチン機能（A-7 調理） |
| **頻度** | `受注時`（営業中に随時） |

#### ★ オーダーの通し方（飲食業固有の作法）

`【Typical】` 注文をホールから厨房へ伝えることを「**オーダーを通す**」と言います。
伝え方には主に次の形があります（`【Varies】` 店により異なる）。

| 方式 | どう伝わるか | 特徴 |
|---|---|---|
| **口頭＋復唱** | ホールが厨房に声で伝え、厨房が復唱する | `【Typical】` 小規模店で使われる。確実だが、忙しいと聞き漏らしが起きうる |
| **手書き伝票** | 伝票に書き、厨房に差す | `【Typical】` 紙が残るため後から確認できる |
| **ハンディ端末＋キッチンプリンタ** | ホールが端末に入力→厨房のプリンタから伝票が出る | `【Typical】` 入力と同時にPOSに記録される |
| **タブレット／モバイルオーダー** | 客が自分で入力する | `【Typical】` ホールの作業が減る。聞き間違いが起きない |

> **なぜ「復唱」するのか**
> `【Inference】` 注文の聞き間違い・伝え間違いは、
> ①違う料理を作る（食材のロス）、②客を待たせる（作り直し）、③客の不満、を同時に引き起こします。
> **アレルギーの聞き漏らしは、客の健康に直接影響します。**
> 復唱は、この誤りを提供前に発見するための工程です。

> **「通し」に関する飲食業の用語**
> - **一括（いっかつ）で通す**＝注文をまとめて厨房へ渡すこと
> - **追加オーダー**＝食事の途中で追加される注文。**客単価を押し上げる要素**
> - **止め（とめ）**＝厨房が一時的に注文を受けられない状態にすること（作業が詰まったとき）
> - **番手（ばんて）**＝提供の順番

### A-7 調理

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | オーダーが厨房に通ったとき |
| **誰が行うか** | ⑨キッチン機能 |
| **何を受け取るか** | オーダー（注文伝票）／仕込み品／レシピ |
| **何を確認するか** | ①注文内容（品名・数量・指定）　②**アレルギー等の特記事項**　③**同じテーブルの他の料理との出すタイミング**　④在庫の残り |
| **何をするか** | 仕込み品を使って仕上げる／加熱する／盛り付ける／**提供の順序を組み立てる**／完成を⑩ホール機能に知らせる |
| **何を判断するか** | **どの順で作るか。** 調理時間の違う複数のオーダーを、同時に完成させるための逆算 |
| **誰と連携するか** | ⑩ホール機能（提供・特記事項）／⑦店長機能（在庫切れ・遅延の報告） |
| **何が出来上がるか** | **完成した料理**／使用した食材の減少（在庫の減少） |
| **次に誰へ渡すか** | ⑩ホール機能（A-8 提供） |
| **頻度** | `常時`（営業中） |

> `【Example】`（説明用の架空例）4名のテーブルから
> 「刺身盛り（3分）／だし巻き玉子（8分）／唐揚げ（10分）／牛すじ煮込み（3分）」が一括で通った場合。
> 同時に出すなら、唐揚げを最初に、次にだし巻き、最後に刺身と煮込みを仕上げる、
> という逆算になります。**注文順に作ると、料理がバラバラに出てしまいます。**

### A-8 提供

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 厨房で料理が完成したとき |
| **誰が行うか** | ⑩ホール機能 |
| **何を受け取るか** | 完成した料理／テーブル番号／特記事項 |
| **何を確認するか** | ①**どのテーブルの料理か**　②盛り付け・温度に問題がないか　③アレルギー対応品が正しい客に届くか　④取り皿・カトラリーが必要か |
| **何をするか** | 料理を運び、テーブルに置き、料理名を伝える／必要な取り皿を出す／食べ終わった皿を下げる（下膳）／追加注文を確認する |
| **何を判断するか** | 下げてよい皿か（まだ食べているか）。追加注文を尋ねるタイミング |
| **誰と連携するか** | ⑨キッチン機能／⑪レジ・会計機能（追加注文の記録） |
| **何が出来上がるか** | 客が食事をしている状態／追加オーダー（→ A-6 に戻る） |
| **次に誰へ渡すか** | 追加注文があれば A-6 へ。なければ A-9 会計へ |
| **頻度** | `常時`（営業中） |

#### ★ A-8.5 ラストオーダー

`【Typical】` **ラストオーダー（L.O.）**とは、**その日の注文を受け付ける最終時刻**のことです。

| 項目 | 内容 |
|---|---|
| **なぜ必要か** | `【Inference】` 閉店時刻ぎりぎりに注文を受けると、調理・提供・客の食事・片付けが閉店後にずれ込みます。従業員の退勤時刻が守れず、清掃と締め作業の時間も確保できません |
| **誰が行うか** | ⑩ホール機能（店長の指示による） |
| **何をするか** | 全テーブルを回り、最後の注文を尋ねる／注文がなければ以後は受け付けない／厨房に「ラストオーダー終了」を伝える |
| **何が起きるか** | 厨房は残りの注文を作り終えたら、片付けと翌日の仕込みの準備に移れる |
| **頻度** | `日次` |

`【Varies】` ラストオーダーを閉店の何分前に設定するかは、業態・メニューの調理時間により異なります。
`【Typical】` 料理とドリンクで別々の時刻を設定する店もあります（料理のほうを早く締める）。

### A-9 会計（即時決済）

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 客が会計を求めたとき |
| **誰が行うか** | ⑪レジ・会計機能（ホール担当または店長） |
| **何を受け取るか** | 伝票（そのテーブルの注文内容）／客からの支払 |
| **何を確認するか** | ①**伝票の内容が実際の注文と合っているか**（提供していないものが入っていないか、追加注文が漏れていないか）　②割引・クーポンの適用　③**支払方法**（現金／クレジットカード／電子マネー／コード決済）　④金額と釣銭 |
| **何をするか** | 合計金額を伝える／決済を処理する／釣銭を渡す／レシート（求められれば領収書）を発行する／POSに会計を確定させる |
| **何を判断するか** | 伝票に疑義がある場合、客に確認するか、店側の負担とするか |
| **誰と連携するか** | ⑩ホール機能（提供内容の確認）／④経理・財務機能（売上データ） |
| **何が出来上がるか** | **売上の確定**／現金またはカード等の債権／レシート／POSの会計データ |
| **次に誰へ渡すか** | A-10 片付けへ。売上データ → A-11 締め作業、A-13 日報へ |
| **頻度** | `入金時`（営業中に随時） |

> **ここが飲食業の最大の特徴です。**
> `【Typical】` 他業界なら「納品 → 請求書発行 → 1〜2か月後に入金」となるところが、
> 飲食業では**この1ステップで完了**します。
> `【Inference】` そのため飲食業では、**売掛金の回収管理という仕事がほとんど発生しません。**
> 代わりに、**現金を毎日正確に扱う**という別の負担が生じます（A-11）。

> **決済手段による違い**
> | 決済手段 | 店にお金が入るタイミング | 手数料 |
> |---|---|---|
> | 現金 | `【Typical】` その場（レジに入る） | なし |
> | クレジットカード | `【Typical】` カード会社の締め日・入金日に応じて後日 | `【Varies】` あり |
> | 電子マネー・コード決済 | `【Typical】` 決済事業者の入金サイクルに応じて後日 | `【Varies】` あり |
> | デリバリープラットフォーム | `【Typical】` プラットフォームの送金サイクルに応じて後日 | `【Varies】` あり |
>
> `【Inference】` **売上が立った日と、現金が手元に来る日は同じとは限りません。**
> キャッシュレス比率が上がるほど、この時間差が資金繰りに効いてきます（`08_money.md`）。

### A-10 片付け

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 客が席を立ったとき |
| **誰が行うか** | ⑩ホール機能・⑫清掃・衛生機能 |
| **何を受け取るか** | 使用済みの食器・グラス・おしぼり／汚れたテーブル |
| **何を確認するか** | ①忘れ物がないか　②食器の破損　③テーブル・椅子・床の汚れ　④**残った料理の量**（廃棄量の把握につながる） |
| **何をするか** | 食器を下げて洗浄へ回す／テーブルと椅子を拭く／セッティングを戻す／**次の客を入れられる状態にする** |
| **何を判断するか** | すぐに次の客を案内できるか |
| **誰と連携するか** | ⑩ホール機能（次の案内）／⑫清掃・衛生機能（洗浄） |
| **何が出来上がるか** | **空席（次の客を迎えられる席）** |
| **次に誰へ渡すか** | A-5 来店・案内（次の客） |
| **頻度** | `常時`（営業中） |

> **片付けが「生産工程」である理由（再掲）**
> `【Inference】` 席が空かなければ、次の客は入れません。
> 売上 ＝ 席数 × 回転数 × 客単価 の「回転数」は、**片付けの速さで決まる**部分があります。
> ピーク時に片付けが遅れると、外で待っている客がいるのに席に案内できない状態が生じます。

### A-11 締め作業（レジ締め・現金管理）

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 最後の客が退店し、その日の会計が終わったとき |
| **誰が行うか** | ⑦店長機能・⑪レジ・会計機能 |
| **何を受け取るか** | レジの中の現金／POSの当日売上データ／決済端末の当日集計 |
| **何を確認するか** | ①**レジの現金 − 釣銭準備金 ＝ POSの現金売上額** になるか　②カード・コード決済の端末集計とPOSが一致するか　③割引・訂正・返金の内容　④売上の内訳（現金／キャッシュレス／客数／客単価） |
| **何をするか** | 現金を数える／POSの締め処理を行う／**差額があれば原因を探す**／翌日分の釣銭を準備する／売上金を保管または入金する |
| **何を判断するか** | 差額の原因が特定できるか。できない場合、過不足として記録する |
| **誰と連携するか** | ④経理・財務機能（売上データと現金の報告） |
| **何が出来上がるか** | **確定した当日売上**／**現金過不足の記録**／翌日の釣銭準備金 |
| **次に誰へ渡すか** | A-13 日報作成 → ④経理・財務機能 |
| **頻度** | `日次` |

> **なぜ毎日、現金を数えるのか**
> `【Inference】` 飲食業は1日に何十件も現金を扱います。
> 釣銭の渡し間違い、POSへの打ち間違い、レシートの発行漏れは、どうしても起こり得ます。
> **毎日確認すれば「今日ずれた」と分かりますが、月末にまとめて確認すると、
> どの日に何が起きたのかを追えなくなります。**
> `【Typical】` だから締め作業は、**その日のうちに、店を閉めてから行う**のが基本形になります。

> **用語：釣銭準備金（つりせんじゅんびきん）**
> → 開店時にレジに入れておく、釣銭用の現金のこと。**売上ではありません。**
> → 実務例：毎朝5万円を入れておき、締めのときはレジの現金から5万円を引いて売上と照合する。
> → **なぜ区別するのか：** これを売上と混ぜて数えると、毎日5万円多い計算になってしまうためです。

### A-12 清掃・衛生記録

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 営業終了後 |
| **誰が行うか** | ⑫清掃・衛生機能（全員で分担）／記録の確認は⑦店長機能（食品衛生責任者） |
| **何を受け取るか** | 使用後の厨房・客席・器具 |
| **何を確認するか** | ①厨房の清掃（床・シンク・調理台・フライヤー）　②客席・トイレの清掃　③**ごみの分別と搬出**　④**冷蔵庫・冷凍庫の温度**　⑤グリストラップの状態　⑥翌日の仕込み品の保管状態 |
| **何をするか** | 清掃・洗浄・消毒／ごみ出し／**衛生管理の記録を書く**／火元・ガス・電源の確認／戸締り |
| **何を判断するか** | 記録に異常値（温度など）があった場合、どう対応するか |
| **誰と連携するか** | ⑦店長機能（記録の確認）／社外：廃棄物収集運搬業者 |
| **何が出来上がるか** | **翌日の営業を始められる状態の店**／**衛生管理の記録** |
| **次に誰へ渡すか** | 翌日の A-3 仕込み・A-4 開店準備へ |
| **頻度** | `日次` |

#### ★ HACCPに沿った衛生管理（制度の根拠）

`【Fact】` 食品衛生法第51条第1項は、営業施設の衛生的な管理その他公衆衛生上必要な措置について、
厚生労働省令で次の2つの事項に関する基準を定めることとしています。

| 号 | 基準の内容 | 省令上の定め |
|---|---|---|
| 第1号 | 施設の内外の清潔保持、**ねずみ及び昆虫の駆除**その他**一般的な衛生管理**に関すること | `【Fact】` 食品衛生法施行規則第66条の2第1項・**別表第17** |
| 第2号 | 食品衛生上の危害の発生を防止するために特に重要な工程を管理するための取組（**小規模な営業者その他の政令で定める営業者**にあっては、その**取り扱う食品の特性に応じた取組**）に関すること | `【Fact】` 食品衛生法施行規則第66条の2第2項・**別表第18** |

`【Fact】` 同条第2項により、**営業者はこれらの基準に従い、公衆衛生上必要な措置を定め、これを遵守しなければなりません。**

`【Fact】` 別表第18は、①危害要因の分析、②重要管理点の決定、③管理基準の設定、
④モニタリング方法の設定、⑤改善措置の設定、⑥検証方法の設定、⑦記録の作成、
の7項目を定めています。これが一般に「HACCPに沿った衛生管理」と呼ばれるものです。

`【Fact】` そして**飲食店営業は「取り扱う食品の特性に応じた取組」でよい営業者に含まれます。**
食品衛生法施行令第34条の2第2号は、**飲食店営業**（食品を調理し、または設備を設けて客に飲食させる営業）を行う者等を
第51条第1項第2号の政令で定める営業者として掲げ、
食品衛生法施行規則第66条の3第1号は、飲食店営業（喫茶店営業を含む）を行う者をこれに該当するものとしています。
`【Typical】` これが一般に「**HACCPの考え方を取り入れた衛生管理**」と呼ばれるものです。

`【Fact】` 営業者が具体的に行うべきこととして、食品衛生法施行規則第66条の2第3項は次の4点を定めています。

1. 食品衛生上の危害の発生の防止のため、施設の衛生管理及び食品の取扱い等に関する計画
   （**衛生管理計画**）を作成し、食品を取り扱う者及び関係者に**周知徹底**を図ること
2. 施設設備、機械器具の構造・材質、食品の製造・加工・調理・運搬・貯蔵・販売の工程を考慮し、
   公衆衛生上必要な措置を適切に行うための**手順書**を必要に応じて作成すること
3. **衛生管理の実施状況を記録し、保存すること**
   （保存期間は、取り扱う食品が使用・消費されるまでの期間を踏まえ合理的に設定する）
4. 衛生管理計画及び手順書の**効果を検証し、必要に応じて内容を見直すこと**

> **初心者向けのまとめ**
> `【Inference】` 制度をひとことで言うと、
> **「どこで危険が起きうるかをあらかじめ考えて、その場所を決めた方法で毎日チェックし、
> チェックしたことを記録に残し、ときどき方法を見直す」**という仕組みです。
> `【Typical】` 飲食店の現場では、「冷蔵庫の温度を記録する」「加熱の中心温度を確認する」
> 「従業員の健康状態と手洗いを記録する」といった形で日々の作業に組み込まれています。
> `【Fact】` これは努力目標ではなく、**食品衛生法第51条第2項に基づく遵守事項**です。
> `【Varies】` 具体的にどの工程を重点にするかは、店が扱う食品と調理方法によって異なります。

> **食品衛生責任者との関係**
> `【Fact】` 食品衛生責任者は、**上記の措置の遵守のために必要な注意を行うとともに、
> 営業者に対し必要な意見を述べるよう努める**こととされ（施行規則別表第17第1号ホ）、
> **営業者は食品衛生責任者の意見を尊重**しなければなりません（同ニ）。

### A-13 日報作成・本部への報告

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 締め作業が終わったとき |
| **誰が行うか** | ⑦店長機能 |
| **何を受け取るか** | POSの当日集計／現金の照合結果／当日の出来事（クレーム・設備不具合・欠員など） |
| **何を確認するか** | ①売上（現金／キャッシュレス別）　②客数・組数　③客単価　④**廃棄（ロス）の内容**　⑤予約の状況　⑥**現金の過不足**　⑦特記事項 |
| **何をするか** | 日報を作成し、本部（④経理・財務機能）へ送る |
| **何を判断するか** | 本部に即時に伝えるべき事項があるか（設備故障・重大なクレーム・食品事故の疑い） |
| **誰と連携するか** | ④経理・財務機能／⑤人事・労務機能（欠員・勤怠）／①メニュー開発機能（売れ行き） |
| **何が出来上がるか** | **日報**（店の1日を数値と事実で残したもの） |
| **次に誰へ渡すか** | 本部 → `月次`の店別損益、`月次`の仕入計上、`月次`の給与計算へ |
| **頻度** | `日次` |

> **日報が後工程を動かす**
> `【Inference】` 日報が遅れると、本部は売上を把握できず、資金繰りの判断も遅れます。
> 「日報を書く」は店の自己満足ではなく、**本部の仕事の入力データ**です。

## 4-2 【A補足】営業サイクルと並行して常時動いているもの

### A-P 予約管理

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 客からの予約の申し込み（電話／予約サイト／店頭／自社サイト） |
| **誰が行うか** | ⑩ホール機能・⑦店長機能 |
| **何を受け取るか** | 日時／人数／連絡先／コース・飲み放題の希望／席の希望／アレルギー等の要望 |
| **何を確認するか** | ①その日時に**席が空いているか**　②人数に対応できる席の組み合わせがあるか　③厨房が対応できる量か　④コース内容と料金　⑤**アレルギー・苦手食材** |
| **何をするか** | 予約台帳（紙／予約システム）に記入する／確認の連絡をする／当日の席割りに反映する／**厨房に仕込み量として伝える** |
| **何を判断するか** | **受けるか、断るか。** 同じ時間帯に予約が重なりすぎると提供が回らなくなる |
| **誰と連携するか** | ⑧仕込み機能（仕込み量）／⑨キッチン機能（コース内容）／⑥販促機能（予約サイトの掲載内容） |
| **何が出来上がるか** | **予約情報**（日時・人数・内容） |
| **次に誰へ渡すか** | A-1 発注（数量の根拠）／A-3 仕込み（仕込み量）／A-4 開店準備（席割り）／A-5 来店・案内 |
| **頻度** | `常時`／`問い合わせ時` |

> **予約が飲食業の計画の土台になる理由**
> `【Inference】` 飲食業は「何人来るか分からない」商売です。
> しかし予約が入っている分だけは、**来る人数・食べるもの・時間が確定します。**
> つまり予約は、仕入量・仕込み量・シフト人数を決めるための**唯一の確定情報**です。
> 予約が多い日は仕込みを厚くし、人を多く入れる。これが計画の起点になります。

`【Typical】` 予約に関して発生する実務上の論点として、**無断キャンセル（予約したのに連絡なく来ない）**があります。
`【Inference】` 予約分の食材を仕込んでいた場合、その分が廃棄になり、
さらにその時間帯は他の客を断っている可能性があります。
`【Varies】` キャンセル料の設定と徴収の有無は企業により異なります。

### A-C クレーム対応

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 客からの申し出（店内／電話／予約サイトの口コミ／SNS） |
| **誰が行うか** | ⑩ホール機能（一次対応）→ ⑦店長機能（判断）→ 重大な場合は本部・代表 |
| **何を受け取るか** | 客の申し出の内容 |
| **何を確認するか** | ①**何が起きたのか**（事実の確認）　②いつ・どのテーブル・どの料理か　③**健康被害の有無**　④再現性があるか（他の客にも起きうるか） |
| **何をするか** | 事情を聞く／事実を確認する／対応する（作り直し・返金・謝罪など `【Varies】`）／**記録に残す**／必要に応じて本部へ報告 |
| **何を判断するか** | **その場で完結させてよいか、上位に上げるべきか。** とくに健康被害の訴えは店長の判断で終わらせない |
| **誰と連携するか** | ⑨キッチン機能（原因の確認）／⑦店長機能／本部／`【Fact】` 食中毒の疑いがある場合は保健所 |
| **何が出来上がるか** | 対応の記録／再発防止のための情報 |
| **次に誰へ渡すか** | ①メニュー開発機能（レシピ・品質）／⑫清掃・衛生機能（衛生）／⑤人事・労務機能（接客教育） |
| **頻度** | `トラブル発生時`／`問い合わせ時` |

> **健康被害の訴えは別扱いになります**
> `【Fact】` 保健所長は、食中毒患者等が発生したときは、中毒の原因となった食品等および
> 病因物質を追及するために必要な疫学的調査等を行います（食品衛生法第63条第2項、同法施行令第36条）。
> `【Fact】` また、都道府県知事は、営業者が同法の一定の規定（**第51条第2項＝衛生管理の基準に従った措置の遵守義務を含む**）に
> 違反した場合においては、**第55条第1項の許可を取り消し、または営業の全部もしくは一部を禁止し、
> もしくは期間を定めて停止することができます**（食品衛生法第60条第1項）。
> `【Fact】` さらに、営業の施設が第54条による施設の基準に違反した場合は、
> 施設の整備改善を命じ、または許可の取消し・営業の禁止・停止をすることができます（同法第61条）。
> `【Inference】` したがって、健康被害の訴えは「クレーム対応」ではなく
> **事業の継続に直結する事象**として扱われます。

### A-L 廃棄（ロス）の記録

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 食材・仕込み品・調理済みの料理が、売上にならずに捨てられたとき |
| **誰が行うか** | ⑧仕込み機能・⑨キッチン機能（発生した人が記録）／確認は⑦店長機能 |
| **何を確認するか** | ①何を　②どれだけ　③**なぜ捨てたのか** |
| **何をするか** | 廃棄記録に書く／廃棄物として分別・保管・搬出する |
| **何が出来上がるか** | **廃棄（ロス）の記録** |
| **次に誰へ渡すか** | ⑦店長機能 → A-13 日報 → ④経理・財務機能（原価率の分析） |
| **頻度** | `日次`（発生の都度） |

`【Typical】` 廃棄の理由は主に次に分類されます。

| 理由の分類 | 内容 | どの工程に原因があるか |
|---|---|---|
| **仕入ロス** | 仕入れすぎて使い切れなかった | A-1 発注 |
| **仕込みロス** | 仕込みすぎて残った | A-3 仕込み |
| **提供ロス** | 作ったが客に出せなかった（オーダーミス、作り直し） | A-6 注文／A-7 調理 |
| **食べ残し** | 客が残した | メニュー設計（量）／A-6 での助言 |
| **期限切れ・品質劣化** | 使う前に使えなくなった | 保管方法／先入先出 |

> **なぜ理由まで記録するのか**
> `【Inference】` 原価率が上がったとき、「仕入値が上がった」のか「捨てた量が増えた」のかで
> 見るべき場所がまったく変わります。
> さらに捨てた理由が分かれば、**発注・仕込み・オーダーのどこに原因があったか**まで遡れます。
> **記録しないと、原価率という結果の数字だけが残り、原因が分からなくなります。**

### A-I 棚卸（たなおろし）

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 定められた締めのタイミング |
| **誰が行うか** | ⑦店長機能・⑨キッチン機能（`【Varies】` 本部が立ち会う場合もある） |
| **何を受け取るか** | 帳簿・システム上の在庫データ／前回の棚卸結果 |
| **何を確認するか** | ①冷蔵庫・冷凍庫・常温倉庫・酒類の**実際の在庫量**　②仕込み品の残量　③帳簿上の在庫との差 |
| **何をするか** | 現物を数え、金額に換算し、記録する／帳簿との差を確認する |
| **何を判断するか** | 差が出た原因（記録漏れ、廃棄の未記録、計量の誤差、盗難など） |
| **誰と連携するか** | ④経理・財務機能（原価の確定） |
| **何が出来上がるか** | **期末（月末）在庫高** |
| **次に誰へ渡すか** | ④経理・財務機能 → **原価の計算へ** |
| **頻度** | `月次`（`【Varies】` 頻度は企業により異なる。`年次`の企業もある） |

> **なぜ棚卸が必要なのか（原価の計算に必須だから）**
> `【Typical】` その月の食材費（売上原価）は、**仕入れた金額そのものではありません。**
>
> ```
> 当月の食材費 ＝ 月初の在庫 ＋ 当月の仕入 − 月末の在庫
> ```
>
> `【Inference】` 月末に大量に仕入れて在庫が積み上がっていれば、
> 「仕入額」は大きくても「使った額」は小さいはずです。
> **月末の在庫を数えなければ、この区別ができません。**
> だから棚卸をしないと、その月の本当の原価率が分からないのです。
>
> `【Example】`（説明用の架空例。数値は説明のための仮置きです）
> 月初在庫60万円、当月仕入180万円、月末在庫70万円なら、
> 当月の食材費＝60＋180−70＝**170万円**。
> 売上が500万円なら原価率は34.0％。仕入額180万円で計算すると36.0％となり、2ポイントずれます。

## 4-3 【B】仕入先へ支払うまでのサイクル

`【Typical】` A系列（客からお金を受け取る）が当日で完結するのに対し、
B系列（仕入先にお金を払う）は**月単位でゆっくり進みます。**

### B系列の全体像

```
  B-1 発注      B-2 納品・検品     B-3 仕入計上     B-4 締め
  （店舗）  →   （店舗）      →   （店舗/本部） →  （本部）
   日次          日次              日次〜月次        月次
     │              │                   │              │
     │           納品書              納品書を         期間分を
  発注情報       を受領              記録             合計
                                                        ↓
                                     B-6 支払   ←   B-5 請求書照合
                                     （本部）        （本部）
                                      月次             月次
                                        │                │
                                   振込/引落        請求書と納品書
                                                    を突き合わせる
```

> **注意：B-1 と B-2 は、A-1 と A-2 と同じ行為です。**
> 同じ「発注」「納品」という行為が、
> **モノの流れ（A系列）とお金の流れ（B系列）の両方の出発点**になっています。
> 現場では1回の行為ですが、追いかける先が2つに分かれる、と理解してください。

---

### B-3 仕入計上

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 納品・検品が済み、納品書が手元にあるとき |
| **誰が行うか** | ④経理・財務機能（`【Varies】` 店舗で一次記録し本部で集約する形もある） |
| **何を受け取るか** | 検品済みの納品書／現金で買った分のレシート |
| **何を確認するか** | ①納品書の仕入先・日付・品目・数量・単価・金額　②検品で問題がなかったか　③**掛仕入か現金仕入か** |
| **何をするか** | 仕入として記録する（掛仕入なら**買掛金**が増える。現金仕入なら現金が減る） |
| **何を判断するか** | 返品・値引きがあった分をどう処理するか |
| **誰と連携するか** | ⑦店長機能（納品書の受け渡し） |
| **何が出来上がるか** | **仕入の記録**／**買掛金の残高** |
| **次に誰へ渡すか** | B-4 締めへ |
| **頻度** | `日次`〜`月次`（`【Varies】` 企業により異なる）／`納品時` |

> **用語：買掛金（かいかけきん）**
> → 商品・食材を受け取ったが、**まだ支払っていない代金**のこと。会社にとっての「払う義務」。
> → 実務例：「今月、卸から届いた食材の代金180万円は、翌月末に払う」→ この180万円が買掛金。
> → **なぜ記録するのか：** 買掛金を把握していないと、
>   **翌月にいくら払わなければならないのかが分からず、資金が足りなくなる**ためです。

> **初心者がつまずく点：発注 ≠ 仕入計上**
> `【Typical】` 注文（発注）しただけでは仕入にはなりません。
> **モノが届いて検品が済んだ時点**で、はじめて仕入として記録します。
> 発注したが届かなかったもの、届いたが返品したものは、仕入になりません。

### B-4 締め

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 仕入先との取り決めによる締め日が到来したとき |
| **誰が行うか** | ④経理・財務機能 |
| **何を受け取るか** | 締め期間中の納品書一式／仕入の記録 |
| **何を確認するか** | 締め期間中の納品がすべて記録されているか（記録漏れがないか） |
| **何をするか** | 仕入先ごとに、締め期間分の仕入金額を集計する |
| **何が出来上がるか** | 仕入先ごとの**当期間の仕入合計額** |
| **次に誰へ渡すか** | B-5 請求書照合へ |
| **頻度** | `月次`（`【Varies】` 締め日は取引先との取り決めによる） |

### B-5 請求書照合

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 仕入先から請求書が届いたとき |
| **誰が行うか** | ④経理・財務機能 |
| **何を受け取るか** | **請求書**（仕入先から） |
| **何を確認するか** | ①請求書の合計額と、店で集計した仕入合計額が**一致するか**　②単価が取り決めどおりか　③返品・値引きが反映されているか　④届いていないものが請求されていないか |
| **何をするか** | 納品書を1枚ずつ請求明細と突き合わせる／差異があれば仕入先に問い合わせる |
| **何を判断するか** | 支払ってよいか、金額の訂正を求めるか |
| **誰と連携するか** | 社外：仕入先／社内：⑦店長機能（納品の事実確認） |
| **何が出来上がるか** | **支払確定額** |
| **次に誰へ渡すか** | B-6 支払へ |
| **頻度** | `月次`／`請求時` |

> **なぜ照合するのか**
> `【Inference】` 請求書の金額をそのまま払うと、
> **届いていないものの代金、返品したものの代金、取り決めと違う単価**を払ってしまう可能性があります。
> `【Typical】` 飲食業は毎日納品があり、品目数も多いため、
> **納品書を日々きちんと保管しておくこと**が照合の前提になります。
> 納品書を捨ててしまうと、照合ができません。

### B-6 支払

| 項目 | 内容 |
|---|---|
| **何をきっかけに始まるか** | 支払期日が到来したとき |
| **誰が行うか** | ④経理・財務機能（承認は代表取締役 `【Varies】`） |
| **何を受け取るか** | 支払確定額のリスト／口座残高の情報 |
| **何を確認するか** | ①**支払総額**　②口座残高が足りるか　③支払方法（振込・口座振替・手形 `【Varies】`）　④支払期日 |
| **何をするか** | 振込手続をする／口座振替の残高を確保する／支払記録を残す |
| **何を判断するか** | **資金が足りるか。** 足りない場合の対応（入金予定の確認、借入の検討など） |
| **誰と連携するか** | 社外：金融機関、仕入先／社内：代表取締役 |
| **何が出来上がるか** | 支払の完了／**買掛金の減少** |
| **次に誰へ渡すか** | 資金繰りの記録へ |
| **頻度** | `月次`／`法定・契約上のタイミング` |

> **A系列とB系列を重ねると何が見えるか**
> `【Inference】`
> - **入ってくるお金**：ほぼ毎日入る（現金はその日、カード等は後日）
> - **出ていくお金**：月に何度か、まとまって出る（仕入代金・家賃・給与）
>
> つまり飲食業は、**入金は細かく毎日、支払はまとめて月に数回**という形になります。
> `【Typical】` この形は、**日々の売上をそのまま使ってしまうと、月末の支払で資金が足りなくなる**
> という事態を生みます。だから経理・財務機能は、
> 「今月末にいくら払うのか」を常に把握しておく必要があります（`08_money.md` で詳述）。

## 4-5 【Example】1日の営業を追跡する

> ### ⚠ 以下はすべて説明用の架空例です
> `【Example】` `03_company-structure.md` のモデル企業「株式会社まるみダイニング」A店（本店・40席）の
> ある1日を追跡します。**実在の店舗ではなく、数値も説明のための仮置きです。**
> `【Fact】` 本資料では時刻表は作りません。以下は**工程の順序**として読んでください。

---

### 【開店前】

**■ 前日の発注が届く（A-2 納品・検品）**

店長のSさんが出勤すると、青果卸のトラックが到着しています。
納品書を受け取り、段ボールを開けて中身を確認します。

- キャベツ10玉 → 発注どおり。葉の状態も問題なし
- トマト3kg → **1つに傷みがある**。配送担当にその場で伝え、1個分を差し引いてもらう
- レタス → 発注は2ケースだったが**1ケースしか入っていない**。市場の入荷が悪く、明日の朝に追加分を届けると連絡を受ける

Sさんは納品書に「トマト1個返品」「レタス1ケース未着」とメモし、事務所の納品書ファイルに入れます。
`→ この納品書が、月末の B-5 請求書照合で使われます。`

次に精肉卸が到着。冷蔵で届いた鶏もも肉5kgの**温度を確認**し、
衛生管理の記録用紙に記入してから、冷蔵庫へ収納します。

**■ 仕込みを始める（A-3 仕込み）**

調理社員のKさんが仕込みに入ります。
店長から「今夜は12名の予約が1件、ほかに4名予約が2件」と伝えられています。

- 牛すじの煮込み：前日の残りが3人前。今日は予約が多いので**追加で15人前**を仕込む
- だし：毎日引く。今日はいつもの量
- レタスが足りないため、**サラダのメニューを「本日はキャベツのサラダ」に変更**することを店長と決める
- 仕込んだ容器には**「9/17 牛すじ」**とラベルを貼り、冷蔵庫の手前（先に使う側）に置く

`→ 「レタスが入らなかったのでメニューを変える」という判断が、A-2 の検品から A-3 に伝わっています。`

**■ 開店準備（A-4）**

ホール担当のアルバイト2名が出勤。

- 客席とトイレの清掃を仕上げ、テーブルに箸・調味料をセット
- 12名の予約に合わせ、**テーブル3卓をつなげて席を作る**
- レジに釣銭準備金5万円をセット。POSと決済端末の動作を確認
- 全員に情報共有：「今日のサラダはキャベツに変更」「牛すじは在庫が多いのでおすすめして」
  「夜の早い時間に12名、その後の時間帯に4名ずつ予約あり」

---

### 【営業中・昼】

**■ 来店・案内（A-5）**

近隣のオフィスから2名の客が来店。
「2名です」と言われ、ホール担当が**2人掛けテーブル**へ案内します。
（4人掛けに通してしまうと、後から来る4名客を断ることになるため）

**■ 注文（A-6）**

客が「日替わり定食2つ」と注文。ホール担当が**復唱**します。
「日替わり定食お2つですね。本日の日替わりは鶏の唐揚げです。
 ——アレルギーなど、召し上がれないものはございますか？」
客の1人が「卵がだめです」と答えます。

ホール担当はハンディ端末に「日替わり×2／**うち1つ 卵除去**」と入力。
厨房のプリンタから伝票が出ます。

**■ 調理（A-7）**

キッチンのKさんが伝票を見ます。
「卵除去」の表示を確認し、**その1つだけ小鉢のだし巻き玉子を煮物に差し替える**と判断。
同時に入っていた他のテーブルの注文（そば2つ、定食1つ）と合わせ、
**調理時間の長い唐揚げから先に揚げ始めます。**

**■ 提供（A-8）**

ホール担当が料理を運びます。
卵除去のほうを**必ず該当する客の前に置く**よう、口頭で確認しながら提供します。

**■ 会計（A-9）**

食事が終わり、客が会計へ。
伝票は「日替わり定食×2＝1,800円」。POSで金額を確認し、客はコード決済を選択。
決済端末で処理し、レシートを渡します。
`→ この1,800円は、現金としては今日レジに入りません。決済事業者から後日入金されます。`

**■ 片付け（A-10）**

ホール担当が食器を下げ、テーブルを拭き、箸と調味料をセットし直します。
外で待っている客がいるため、**この作業の速さがそのまま次の売上になります。**

---

### 【営業中・夜】

**■ 予約客の来店（A-P → A-5）**

予約の12名が来店。予約台帳で名前と人数を確認し、準備した席へ案内します。
コース料理の予約のため、**厨房は既に人数分の準備を進めています。**
（予約がなければ、この12名分の食材は用意されていません）

**■ 追加オーダーが入る（A-6 に戻る）**

コースの途中で「生ビールを5杯追加」の注文。
これが `01_overview.md` 1-5 の**客単価を押し上げる要素**です。

**■ ラストオーダー（A-8.5）**

閉店の一定時間前、ホール担当が全テーブルを回ります。
「まもなくラストオーダーのお時間です。ご注文はございますか」
最後の注文を受け終えたら、厨房に「ラストオーダー終了」を伝えます。
厨房は残りを作り終えたら、**片付けと翌日の仕込みの準備に移れます。**

---

### 【閉店後】

**■ 締め作業（A-11）**

最後の客が退店。店長のSさんがレジを締めます。

- POSの当日集計：売上合計 **412,600円**（現金 148,200円／カード・コード決済 264,400円）
- レジの現金を数える：**153,200円**
- 釣銭準備金 50,000円を引く → **103,200円**
- POSの現金売上は148,200円。**45,000円合わない**

Sさんはレシートと伝票を確認し、
**夜の団体客が現金で払った45,000円を、別の保管袋に入れたまま**だったことを見つけます。
合算して照合が取れました。記録に「保管袋への入れ忘れを確認済み」と残します。

`→ 毎日締めるからこそ、その日のうちに原因が分かります。`

**■ 清掃・衛生記録（A-12）**

- 厨房の床・シンク・調理台を洗浄
- 冷蔵庫・冷凍庫の温度を測り、記録用紙に記入
- ごみを分別し、翌朝の回収に出せる場所へ
- 火元・ガス・電源を確認し、戸締り

**■ 廃棄の記録（A-L）**

この日の廃棄を記録します。
- 「揚げ置きの唐揚げ 8個（昼の作りすぎ）」
- 「キャベツ 半玉（外葉の傷み）」

`→ 「昼の作りすぎ」という理由が残ることで、翌週の仕込み量の判断材料になります。`

**■ 日報（A-13）**

Sさんが日報を作成し、本部へ送ります。

| 項目 | 当日 |
|---|---|
| 売上 | 412,600円（昼 96,400円／夜 316,200円） |
| 客数 | 昼 72名／夜 68名 |
| 客単価 | 昼 約1,339円／夜 約4,650円 |
| 現金過不足 | 0円（保管袋の件を確認済み） |
| 廃棄 | 唐揚げ8個、キャベツ半玉 |
| 特記事項 | レタス1ケース未着。メニューを差し替え。明日追加納品予定 |

`→ この日報が、本部の ④経理・財務機能 に渡り、`
`  月次の店別損益、月次の仕入計上・支払（B系列）につながっていきます。`
